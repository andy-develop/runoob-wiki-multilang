Node.js Domain モジュール

Node.js 組み込みモジュール

Domain モジュールは、Node.js で非同期コードのエラー処理を簡素化するためのツールです。複数の非同期操作を1つの「ドメイン」にグループ化し、そのドメイン内でエラーを一元的にキャッチして処理することができます。

簡単に言うと、Domain はエラー処理の「コンテナ」のようなもので、関連する非同期操作をこのコンテナに入れて、それらの操作で発生する可能性のあるエラーを一元的に管理できます。

domain モジュールの使用は Node.js 14 で非推奨（deprecated）になりました。Node.js コミュニティは、async/await やより包括的なエラー監視・処理ロジックなど、より現代的な方法でエラーを処理することを推奨しているためです。

なぜ Domain モジュールが必要なのか？

Node.js の非同期プログラミングでは、エラー処理が複雑になることがあります：

  1. 非同期エラーはキャッチしにくい：従来の try-catch では非同期コールバック内のエラーをキャッチできません
  2. エラーの伝播が困難：エラーはどの非同期操作でも発生する可能性があり、発生源の追跡が困難です
  3. リソースクリーンアップの問題：エラー発生後、リソースを適切に解放することを保証する必要があります

Domain モジュールは、これらの問題を解決するために設計されました。

Domain モジュールの核となる概念

1. Domain の作成

例

const domain = require('domain');
const myDomain = domain.create();

2. Domain のライフサイクル

  1. 作成：使用domain.create()
  2. 進入：使用domain.enter()または暗黙的に進入
  3. 実行：ドメイン内のコードを実行する
  4. 退出：使用domain.exit()
  5. 破棄：参照がなくなったときに自動的に破棄される

3. 暗黙的バインド

Domain は以下のオブジェクトに暗黙的にバインドできます：

  • setTimeout/setIntervalコールバック
  • EventEmitter イベント
  • ストリーム(Stream)操作

Domain の主要なメソッド

1. domain.run(fn)

ドメインコンテキストで関数を実行する：

例

myDomain.run(() => {
  // ここでの非同期操作は domain にキャッチされる
  setTimeout(() => {
    throw new Error('Async error');
  }, 100);
});

2. domain.add(emitter)

EventEmitter インスタンスをドメインに明示的に追加する：

例

const server = require('http').createServer();
myDomain.add(server);

3. domain.remove(emitter)

ドメインから EventEmitter インスタンスを削除します。

4. domain.bind(callback)

ドメインにバインドされた新しい関数を返します：

例

const boundFn = myDomain.bind((err, data) => {
  if (err) throw err;
  console.log(data);
});

5. domain.intercept(callback)

bind に似ていますが、エラーファーストコールバックを特別に処理します：

例

const interceptedFn = myDomain.intercept((err, data) => {
  console.log(data);
});

エラー処理

Domain はerrorイベントを通じてキャッチしたエラーを処理します：

例

myDomain.on('error', (err) => {
  console.error('Domain caught error:', err);
  // リソースをクリーンアップ
  server.close();
});

実際の応用例

1. HTTP サーバーのエラー処理

例

const http = require('http');
const domain = require('domain');

const server = http.createServer((req, res) => {
  const d = domain.create();
 
  d.on('error', (err) => {
    res.statusCode = 500;
    res.end(`Server error: ${err.message}`);
    // プロセスのクラッシュを防ぐ
    server.close();
  });
 
  d.run(() => {
    // リクエストを処理
    process.nextTick(() => {
      // 非同期エラーをシミュレート
      if (req.url === '/error') {
        throw new Error('Intentional error');
      }
      res.end('OK');
    });
  });
});

server.listen(3000);

2. データベース接続管理

例

const domain = require('domain');
const db = require('some-db-library');

function queryDatabase(callback) {
  const d = domain.create();
 
  d.on('error', (err) => {
    console.error('Database error:', err);
    db.releaseConnection();
  });
 
  d.run(() => {
    db.getConnection((err, connection) => {
      if (err) throw err;
     
      connection.query('SELECT * FROM users', (err, results) => {
        if (err) throw err;
        callback(null, results);
        db.releaseConnection();
      });
    });
  });
}

Domain の限界

  1. 非推奨：Node.js 公式が domain モジュールを非推奨にしており、async_hooks や他の方法を使用することを推奨しています
  2. メモリリーク：不適切な使用はメモリリークを引き起こす可能性があります
  3. パフォーマンスオーバーヘッド：domain の作成と管理には一定のパフォーマンスオーバーヘッドがあります

代替案

domain モジュールは非推奨となっているため、以下の代替案を検討できます：

  1. async/await + try-catch：現代の JavaScript の非同期処理方式を使用する
  2. Promise エラー処理：使用.catch()Promise チェーン内のエラーを処理する
  3. async_hooks：Node.js が提供するより低レベルの非同期コンテキスト追跡 API

メソッドとプロパティ

メソッド/プロパティ説明
domain.create()新規のdomainインスタンスを作成して返します。
domain.run(callback)ドメイン内で指定されたコールバック関数を実行し、そのコールバック内のエラーを自動的にキャッチします。
domain.bind(callback)新しい関数を作成し、その新しい関数内で元の関数を呼び出し、スローされたエラーをキャッチします。
domain.intercept(callback)類似：bind()ただし、エラーを最初の引数としてコールバック関数に渡します。
domain.add(emitter)EventEmitter または Timer オブジェクトを明示的に追加して、そのエラーが現在のドメインでキャッチされるようにします。
domain.remove(emitter)ドメインから指定された EventEmitter または Timer オブジェクトを削除します。
domain.on('error', callback)ドメイン内のerrorイベントをリッスンし、未処理のエラーをすべてキャッチします。

例

1. ドメインを作成し、domain.run() を使用してエラーをキャッチする

domain.run() は非同期操作をドメイン内に配置でき、操作でエラーが発生した場合、そのエラーは現在のドメインによってキャッチされ処理されます。

例

const domain = require('domain');
const d = domain.create();

d.on('error', (err) => {
  console.log('エラーをキャッチ:', err);
});

d.run(() => {
  setTimeout(() => {
    throw new Error('非同期エラー');
  }, 100);
});

上記の例では、setTimeout 内のエラーは d ドメインの error イベントによってキャッチされ、プロセスのクラッシュは発生しません。

2. domain.bind() を使用してコールバック内のエラーをキャッチする

domain.bind() はラッパー関数を作成し、コールバック関数内のエラーを現在のドメインにキャッチさせることができます。

例

const domain = require('domain');
const d = domain.create();

d.on('error', (err) => {
  console.log('エラーをキャッチ:', err);
});

const asyncFunction = d.bind((callback) => {
  setTimeout(() => {
    callback(new Error('コールバック内のエラー'));
  }, 100);
});

asyncFunction((err) => {
  if (err) throw err;
});

ここでは、asyncFunction 内のエラーは domain によってキャッチされ処理されます。

3. domain.add() を使用してイベントを明示的に追加する

domain.add() を使用して特定の EventEmitter をドメインに追加できます。これにより、そのエラーもそのドメインによってキャッチされます。

例

const domain = require('domain');
const EventEmitter = require('events');
const d = domain.create();

const emitter = new EventEmitter();

d.on('error', (err) => {
  console.log('EventEmitter エラーをキャッチ:', err);
});

// emitter をドメインに追加
d.add(emitter);

emitter.on('data', () => {
  throw new Error('EventEmitter 内のエラー');
});

emitter.emit('data');

data イベントがエラーをスローしたとき、domain はこのエラーをキャッチし、プログラムはクラッシュしません。

domain の注意点と制限

  • パフォーマンスへの影響：domainパフォーマンスに一定の影響を与える可能性があり、特に高並行のシナリオでは影響が出るため、頻繁な使用は推奨されません。
  • 新規プロジェクトでの使用は推奨されない：Node.js 4.0 以降、domainは非推奨モジュールとしてマークされています。新しいプロジェクトでは、次のようなより現代的なエラー処理方式を使用することを推奨します。async/await、try/catchやイベント監視など。
  • すべてのシナリオに適しているわけではない：domainすべてのタイプのエラー（構文エラーなど）をキャッチできるわけではなく、非同期操作やコールバック関数内の実行時エラーの処理にのみ適用されます。

代替案

はdomain非推奨となっているため、非同期操作のエラーを処理するには以下の方法を使用することを推奨します：

  • 使用async/await 和 try/catch：async/await をサポートする関数では、try/catchを使用してエラーをキャッチできます。
  • グローバルエラー処理：以下を使用してprocess.on('uncaughtException') 和 process.on('unhandledRejection')未キャッチの例外や未処理の Promise 拒否を監視できます。
  • イベントリスナーのエラー処理：各 EventEmitter のerrorイベントにリスナーを追加します。

ただしdomainモジュールは非同期操作のエラーを捕捉する簡便な方法を提供しますが、パフォーマンスと信頼性の問題があるため、Node.js 公式は新規プロジェクトでの使用を推奨していません。例外処理には、より現代的な方法、例えばasync/awaitやイベントリスナーなどを使用して、エラーがアプリケーション内で効果的に処理されることを保証します。
