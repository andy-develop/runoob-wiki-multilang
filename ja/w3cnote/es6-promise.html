5.1 ES6 Promise オブジェクト

カテゴリ ES6 チュートリアル

概要

非同期プログラミングの一つの解決策です。

構文上、Promise はオブジェクトであり、そこから非同期操作のメッセージを取得できます。

Promise 状態

状態の特徴

Promise の非同期操作には3つの状態があります: pending（進行中）、fulfilled（成功済み）と rejected（失敗済み）です。非同期操作の結果以外に、他のどの操作もこの状態を変更することはできません。

Promise オブジェクトの状態変化は、pending から fulfilled への変化と、pending から rejected への変化のみです。fulfilled または rejected の状態にある限り、状態はそれ以上変わらず、すなわち resolved（確定済み）となります。

const p1 = new Promise(function(resolve,reject){ resolve('success1'); resolve('success2'); }); const p2 = new Promise(function(resolve,reject){ resolve('success3'); reject('reject'); }); p1.then(function(value){ console.log(value); // success1 }); p2.then(function(value){ console.log(value); // success3 });

状態の欠点

Promise はキャンセルできません。一度作成するとすぐに実行され、途中でキャンセルすることはできません。

コールバック関数を設定しない場合、Promise 内部で発生したエラーは外部に反映されません。

pending 状態のときは、現在どの段階（開始直後か完了間近か）にあるのかを知ることはできません。

then メソッド

then メソッドは2つの関数を引数として受け取ります。最初の引数は Promise の実行が成功したときのコールバック、2番目の引数は Promise の実行が失敗したときのコールバックです。2つの関数のうち、呼び出されるのは1つだけです。

then メソッドの特徴

JavaScript のイベントキューの現在の実行が完了するまで、コールバック関数が呼び出されることはありません。

const p = new Promise(function(resolve,reject){ resolve('success'); }); p.then(function(value){ console.log(value); }); console.log('first'); // first // success

を通じて.then形式で追加されたコールバック関数は、いつでも呼び出されます。

複数回呼び出すことによって

.then
、複数のコールバック関数を追加でき、それらは挿入順に従って、独立して実行されます。

const p = new Promise(function(resolve,reject){ resolve(1); }).then(function(value){ //1つ目のthen // 1 console.log(value); return value * 2; }).then(function(value){ //2つ目のthen // 2 console.log(value); }).then(function(value){ //3つ目のthen // undefined console.log(value); return Promise.resolve('resolve'); }).then(function(value){ //4つ目のthen // resolve console.log(value); return Promise.reject('reject'); }).then(function(value){ //5つ目のthen //reject:reject console.log('resolve:' + value); }, function(err) { console.log('reject:' + err); });

then メソッドはチェーン呼び出しのために resolved または rejected 状態の Promise オブジェクトを返します。また、その Promise オブジェクトの値はこの戻り値です。

then メソッドの注意点

Promise チェーンを簡潔にプログラミングするには、フラットな状態を保ち、Promise を入れ子にしないようにするのが最善です。

常に Promise チェーンを返すか終了させるように注意してください。

const p1 = new Promise(function(resolve,reject){ resolve(1); }).then(function(result) {   p2(result).then(newResult => p3(newResult)); }).then(() => p4());

新しい Promise を作成したがそれを返すのを忘れた場合、対応するチェーンが壊れ、p4 が p2 と p3 と同時に実行されることになります。

ほとんどのブラウザでは、終了できない Promise チェーン内の rejection には、後ろに続けて処理を追加することをお勧めします。.catch(error => console.log(error));
