はじめに

最初に皆さんに紹介するのは、非常に有名な画像読み込み・キャッシュフレームワークである Picasso です。強力なフレームワークは往々にして使い方は非常に簡単ですが、その背後には見逃せない機能やテクニックがたくさんあります。Picasso も同様です。

Picasso入門

依存関係への追加

まず、依存関係を追加する必要があります。現在は最新バージョンを使用します。2.5.2依存関係の追加には、よく知られている2つの方法があります。

Gradle

compile 'com.squareup.picasso:picasso:2.5.2'

Maven

<dependency>  
    <groupId>com.squareup.picasso</groupId>
    <artifactId>picasso</artifactId>
    <version>2.5.2</version>
</dependency>

基本的な画像の読み込み

Picassoはチェーン式プログラミングを使用します。基本的な画像リクエストを完了するには、少なくとも3つのパラメータが必要です。

  • with(Context context)- 多くAndrod APIが呼び出しを行いますが、ここでも違いはありません。
  • load(String imageUrl)- ここでは、どの画像を読み込むべきかを示します。ほとんどの場合、String を使用してURL画像を表します。
  • into(ImageView targetImageView)- 表示先のImageView

簡単な例を見てみましょう。

ImageView targetImageView = (ImageView) findViewById(R.id.imageView);  
String internetUrl = "http://i.imgur.com/DvpvklR.png";

Picasso  
    .with(context)
    .load(internetUrl)
    .into(targetImageView);

ここまでで、URL内の画像に問題がなければ、しばらく待てば目的の画像が見られます。画像が存在しない場合、Picassoはエラーコールバックを返します。エラーコールバックの処理方法については後ほど説明します。たった3つの文で画像リクエストが完了しましたが、これは氷山の一角にすぎません。

Picasso上級

単純な使い方以外にも、loadメソッドがオーバーロードされたメソッドであることに気づくでしょう。実は、基本的なString型の読み込み以外にも、さまざまなソースから望みの画像を読み込むことができます。

リソースの読み込み

int resourceId = R.mipmap.ic_launcher;

Picasso  
    .with(context)
    .load(resourceId)
    .into(imageViewResource);

ファイルの読み込み

File file = new File(Environment.getExternalStoragePublicDirectory(Environment.DIRECTORY_PICTURES), "Running.jpg");

Picasso  
    .with(context)
    .load(file)
    .into(imageViewFile);

Uriの読み込み

Uri uri = resourceIdToUri(context, R.mipmap.future_studio_launcher);

Picasso  
    .with(context)
    .load(uri)
    .into(imageViewUri);

public static final String ANDROID_RESOURCE = "android.resource://";  
public static final String FOREWARD_SLASH = "/";

private static Uri resourceIdToUri(Context context, int resourceId) {  
    return Uri.parse(ANDROID_RESOURCE + context.getPackageName() + FOREWARD_SLASH + resourceId);
}

public class UsageExampleAdapter extends ActionBarActivity {

次に、Adapterのレイアウトファイルを忘れてはいけません。非常にシンプルで、それは私たちが表示したいもの（ImageView）です。ImageView

<?xml version="1.0" encoding="utf-8"?>  
  <ImageView xmlns:android="http://schemas.android.com/apk/res/android"  
         android:layout_width="match_parent"
         android:layout_height="200dp"/>

最後に、実装する必要があります。ImageListAdapter 。

public class ImageListAdapter extends ArrayAdapter {  
    private Context context;
    private LayoutInflater inflater;

    private String[] imageUrls;

    public ImageListAdapter(Context context, String[] imageUrls) {
        super(context, R.layout.listview_item_image, imageUrls);

        this.context = context;
        this.imageUrls = imageUrls;

        inflater = LayoutInflater.from(context);
    }

    @Override
    public View getView(int position, View convertView, ViewGroup parent) {
        if (null == convertView) {
            convertView = inflater.inflate(R.layout.listview_item_image, parent, false);
        }

        Picasso
            .with(context)
            .load(imageUrls[position])
            .fit() // 稍后解释
            .into((ImageView) convertView);

        return convertView;
    }
}

重要な点はgetView()このメソッドの中にあります。もちろん、Picassoの使い方に大きな変化はないことに気づくでしょう。このためにわざわざこの記事を使うのは価値がないように見えるかもしれませんが、実は、Picassoはスクロール時に自動的に画像リクエストをキャンセルし、画像をクリアして、正しい画像を（次の要素に）読み込みます。ImageView。

注後ほど、アダプターの最適化された使用法についてさらに説明します。fit() と tags()。

Picassoの力：キャッシュ

上下に繰り返しスクロールすると、画像が以前よりもはるかに速く表示されるのがわかります。おそらくお気づきでしょうが、これらの画像はキャッシュからのものであり、ネットワークから再読み込みする必要はありません。Picassoの画像読み込みは主に3つのソースから行われます：メモリ -> ディスク -> ネットワーク最後に、あなたが何かをする必要はありません。Picassoがすべてやってくれています！キャッシュのサイズを変更することもできますが、これらは後ほど説明します。

リスト内でのnull/空値の処理

Picassoを使用していると、おそらく2つの問題に遭遇します：IllegalArgumentException: Path must not be empty1つはnull/空値の処理、もう1つは不完全な画像のマッピングです。プログラムが正常に動作することを確認するために、問題を解決する2つの方法を紹介します。

Picassoの画像リクエストのキャンセル

読み込むつもりがない場合は、このリクエストをキャンセルする必要があります。使用するのはcancelRequest()これにより、このImageViewにリクエストコールバックがないことを確認できます。ユーザーが高速でスクロールすると、ListViewとImageViewの再利用が発生する可能性があります。リクエストをキャンセルすることで、誤った画像の表示を防ぐことができます。

プレースホルダーの使用

もう1つの方法はプレースホルダーを使用することです。簡単に言うと、デフォルト画像を使用することです。

コード例

@Override
public View getView(int position, View convertView, ViewGroup parent) {  
    if (null == convertView) {
        convertView = inflater.inflate(R.layout.listview_item_image, parent, false);
    }

    ImageView imageView = (ImageView) convertView;

    if (TextUtils.isEmpty(imageUrls[position])) {
        // option 1: 取消Picasso的图片请求
        Picasso
                .with(context)
                .cancelRequest(imageView);

        imageView.setImageDrawable(null);

        // option 2: 使用占位符
        /*
        Picasso
                .with(context)
                .load(R.drawable.floorplan)
                .into(imageView);
        */
    }
    else {
        Picasso
                .with(context)
                .load(imageUrls[position])
                .fit() // will explain later
                .into(imageView);
    }

    return convertView;
}

placeholder(), error(), フェードイン/フェードアウト

.placeholder() プレースホルダー

1つの問題を考慮するのを忘れるところでした：空のImageViewは非常に不親切な体験です。Picassoでネットワークから画像を読み込む場合、ネットワーク環境によっては画像をすぐに読み込めないことがあります。そのようなときにプレースホルダーを使用します。.placeholder()これは、ネットワーク画像の読み込みが成功するまで、あらかじめ1枚の画像（もちろんローカル画像）を読み込みます。

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .placeholder(R.mipmap.ic_launcher)
    .into(imageViewPlaceholder);

.error() エラープレースホルダー

読み込もうとしている画像リンクがすでに無効になっている場合、Picassoのエラーコールバックを通じて適切な操作を選択できますが、それでは複雑すぎます。ほとんどの場合、呼び出すだけで十分です：error()それだけで十分です。

Picasso  
    .with(context)
    .load("http://futurestud.io/non_existing_image.png")
    .placeholder(R.mipmap.ic_launcher) 
    .error(R.mipmap.future_studio_launcher) 
    .into(imageViewError);

noFade() の使用

フェードイン/フェードアウトのエフェクトを使わずに画像を直接表示したい場合は、noFade() を使用できます。

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .placeholder(R.mipmap.ic_launcher) 
    .error(R.mipmap.future_studio_launcher) 
    .noFade()
    .into(imageViewFade);

noPlaceholder() の使用

次のような状況を考えてみましょう。ImageViewに画像を1枚読み込んだ後、しばらくして同じImageViewに別の画像を読み込みたいとします。デフォルト設定では、Picassoを再度呼び出すと、ImageViewは以前に設定したplaceholderの画像を読み込みます。このImageViewがUIにとって重要な場合、数秒以内にImageViewの画像を素早く変更すると見た目が不適切になることがあります。良い解決策の1つは、次のメソッドを呼び出すことです：.noPlaceholder()このメソッドです。2枚目の画像が読み込まれるまで、ImageViewは1枚目の画像を表示し続けます。これはユーザーにとって親切です。

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .placeholder(R.mipmap.ic_launcher) 
    .into(imageViewnoPlaceholder, new Callback() {
        @Override
        public void onSuccess() {
            Picasso
                .with(context)
               .load(UsageExampleListViewAdapter.eatFoodyImages[1])
               .noPlaceholder() 
               .into(imageViewNoPlaceholder);
        }
        @Override
        public void onError() {
        }
    });

画像のスケーリングとサイズ調整

resize(x, y) によるサイズ変更

通常、サーバーの画像が目的の画像サイズと完全に一致していれば、帯域幅、メモリ消費、画質のバランスは良好です。しかし、それは常に期待どおりとは限りません。取得した画像が期待するサイズでない場合は、次を使用できます：resize(horizontalSize, verticalSize)画像のサイズを変更します。

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .resize(600, 200) 
    .into(imageViewResize);

scaleDown() の使用

もし私たちがresize(x,y)メソッドを呼び出した場合、Picassoは通常、画像の読み込み品質を変更するために再計算を行います。たとえば、小さな画像を大きな画像として表示する場合です。しかし、元の画像がresizeした新しい画像の仕様（サイズ）よりも大きい場合は、onlyScaleDown() を呼び出して再計算せずに直接表示できます。

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .resize(6000, 2000)
    .onlyScaleDown() //如果它大于6000x2000像素，将仅对图像进行调整大小。
    .into(imageViewResizeScaleDown);

画像のスケーリングとストレッチを避ける

画像を操作するとき、元画像とターゲットのサイズ比が異なると歪みが生じることがあります。これを防ぐために、Picassoは2つの解決方法を提供しています。呼び出すのは：centerCrop() または centerInside()。 centerCrop()centerCrop() はトリミング技術を使用して画像をスケーリングし、ImageViewの境界を埋めてから、余分な部分を切り取ります。このメソッドを使用すると、ImageViewは適切に埋められますが、画像が完全に表示されない場合があります。

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .resize(600, 200) // resizes the image to these dimensions (in pixel)
    .centerCrop() 
    .into(imageViewResizeCenterCrop);

CenterInside()

centerInside() もトリミング技術の1つです。スケーリング時に、画像の幅と高さは同時に、設定されたImageViewの境界と等しいか、それ以下になります。画像は完全に表示されますが、ImageViewを完全に埋められない場合があります。

Picasso
    .with(this)
    .load(eatFoodyImages[0])
    .resize(600, 200)
    .centerInside()
    .into(imageView);

fit()

前述の機能で基本的なスケーリングのニーズをほぼ解決できます。ここにもう1つ非常に便利な機能があります：fit() です。

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .fit()
    // call .centerInside() or .centerCrop() to avoid a stretched image
    .into(imageViewFit);

fit() はImageViewの幅と高さを測定し、内部で resize() を使用して、ImageViewに合わせて画像サイズを縮小します。fit()について知っておくべき点が2つあります。まず、fit()を呼び出すと画像リクエストが遅延します。PicassoはImageViewのサイズが測定されるまで待つ必要があるからです。次に、fit()のターゲットとして使用できるのはImageViewだけです（後ほど他のターゲットも見ていきます）。 利点は、画像が最低限の解像度を使用することであり、画質に影響を与えません。解像度が低いほど、キャッシュの使用量が少なくなります。
