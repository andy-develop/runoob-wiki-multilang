3.5 Verilog 遅延逆注釈

カテゴリ Verilog チュートリアル 上級編

キーワード： 遅延逆注釈， SDF

遅延逆注釈とは、設計者がセルライブラリのプロセス、ゲートレベルのネットリスト、レイアウト内の容量や抵抗などの情報に基づき、デジタル設計ツールを利用して遅延情報をゲートレベルのネットリストに注釈付けするプロセスである。遅延逆注釈後のネットリストを使用することで、正確なタイミングシミュレーションが可能になり、実際に動作するデジタル回路に近いシミュレーションができる。

遅延逆注釈のプロセス

前述のチュートリアルでのシミュレーションは、ほとんどが機能シミュレーションです。IC設計であれFPGA開発であれ、タイミングシミュレーションは必須です。『Verilog チュートリアル』の『1.4 Verilog 設計手法』の章でも、完全なデジタル設計開発フローが説明されています。

以下では、遅延逆注釈がこのフローでどのように使用されるかを説明します。復習と定着を兼ねてです。

  • (1) ハードウェア記述言語を使用してRTLレベルでの記述を完了し、機能シミュレーションを行います。
  • (2) クロック、リセット、出力ポートなどの信号に対して、クロック周波数、タイミングチェック、遅延などの情報設定を含む一定のタイミング制約を設定し、論理合成に使用します。
  • (3) 合成されたゲートレベルネットリストには、様々な概算の遅延情報が含まれます。この時点で、hold、recovery、removal、interconnect（配線）などの遅延情報を除いて、初期のタイミングシミュレーションと静的タイミング解析（STA）を行うことができ、setupなどのタイミングがタイミング要件を満たしているかを初期検証します。多くの企業や個人もこの段階のシミュレーションを省略します。
  • (4) ゲートレベルネットリストに対して配置配線を行い、レイアウトレベルのネットリストに変換します。部品の幾何学的形状や製造プロセスなどの情報に基づいて、レイアウト回路内の容量と抵抗情報を抽出でき、この情報に基づいてレイアウト内の遅延値を計算できます。
  • (5) 配置配線後のレイアウト内の遅延情報をレイアウトレベルのネットリストに逆注釈することで、ネットリスト内の遅延値を正確に修正できます。この時点で再度タイミングシミュレーションとSTAを行い、タイミングが満たされているかを検証します。
  • (6) すべての検証が成功した場合は、ダウンロードまたは実装、製造を行うことができます。タイミングに違反（violation）がある場合、まず遅延パラメータ、クロック周波数、信号関係などの設定に問題がないかタイミング制約設定を確認し、再配置配線を行って違反を解消できるか検証します。上記の対策でも違反を解消できない場合は、設計の初期に戻り、RTLの記述を最適化する必要があります。

このプロセスの概念図は以下の通りです。黄色でマークされた部分は、デジタル設計フローに追加できる操作の説明を示しています。

SDF ファイル

SDF（Standard Delay Format）は、標準遅延フォーマットファイルであり、遅延逆注釈によく使用されます。このファイルには、シミュレーションで使用されるすべてのIOPATH、INTERCONNECT、TIMING CHECKなどの遅延時間およびタイミング制約のパラメータが含まれています。以下ではSDFファイルについて簡単に紹介します。

ファイル形式

SDFファイルはキーワードDELAYFILEで宣言され、DESIGN、DATEなどのキーワード情報を含みます。

遅延時間とタイミング制約のパラメータはすべてCELL内で説明されます。

SDFファイルは、ファイル宣言情報と多数の異なるCELLで構成されています。形式は以下の通りです。

(DELAYFILE
(DESIGN "top")
(DATE "Love Sep 7 11:11:11 2017")
......
(TIMESCALE 1ns)
(CELL
  ......
)
(CELL
  ......
)
......
)

遅延タイプ

SDFファイル内の遅延タイプには、セル遅延（cell delay）と配線遅延（wire delay）があります。セル遅延は論理ゲートセルデバイス内部の遅延を指し、配線遅延はデバイス間をwireで相互接続する際の遅延を指します。

セル遅延の記述は以下の通りです。モジュール "and_gate" における入力ポート（A/B）と出力ポート（Z）の立ち上がり遅延および立ち下がり遅延を定義し、最小値と最大値を指定しています。

(CELL
  (CELLTYPE "and_gate")  //モジュール名
  (INSTANCE u_and)       //インスタンス名。複数階層にアクセスする場合は、アクセス階層を指定する必要があります
  (DELAY
    (ABSOLUTE
    (IOPATH A Z (1.5::1.8) (1.3::1.7))  //立ち上がり遅延 最小値1.5、最大値1.8
    (IOPATH B Z (1.5::1.8) (1.3::1.7))  //立ち下がり遅延 最小値1.3、最大値1.7
    )
  )
)

配線遅延の記述は以下の通りです。モジュール "top" 内で、u_andの出力端からu_dtの入力端までの立ち上がり遅延と立ち下がり遅延を定義し、最小値と最大値を指定しています。

一般的に、RTLレベルシミュレーションや合成後のゲートレベルネットリストでは、バックエンドで再配置配線が必要なため、配線遅延（wire delay）は無視できます。配置配線後のネットリストは実際の回路に近くなるため、この時点で配線遅延を考慮する必要があります。

(CELL
  (CELLTYPE "top") //モジュール名
  (INSTANCE)       //トップレベル設計モジュールの場合は、インスタンス名を省略できます
  (DELAY
    (ABSOLUTE
    (INTERCONNECT u_and.Z u_dt.D (0.500::0.751) (0.400::0.551))
    //(INTERCONNECT u_and/Z u_dt/D (0.500::0.751) (0.400::0.551))
    //階層アクセス記号。一部のコンパイラは"."をサポートし、一部は"/"をサポートします。ここに注意が必要です
    )
  )
)

条件付き遅延とタイミングチェック

CELL内では、キーワードCONDを使用して条件付き遅延を指定することもできます。

同時に、CELL内でタイミングチェックを行うこともできます。

Dフリップフロップの遅延説明とタイミングチェックの例は以下の通りです。

(CELL
  (CELLTYPE "d_gate")
  (INSTANCE u_dt)
  (DELAY
    (ABSOLUTE
    // D=1の時、立ち上がり遅延は1.3-2.3、立ち下がり遅延は1.5-2.2
    (COND D==1'b1 (IOPATH CP Q (1.3::2.3) (1.5::2.2)))
    // D=0の時、立ち上がり遅延は1.2-2.1、立ち下がり遅延は1.4-2.0
    //ここではCONDの使い方を説明するためだけであり、D=1の時に立ち下がり遅延パラメータが使用されることはありません
    // D=0の時に立ち上がり遅延パラメータが使用されることもありません
    (COND D==1'b0 (IOPATH CP Q (1.2::2.1) (1.4::2.0)))
    )
  )
  (TIMINGCHECK
  (SETUP D (posedge CP) (0.8::1))
  //setup check、D-CP時間が0.8または1より小さい場合、violationを出力します
  )
)

使用方法

Verilogは、システム関数 $sdf_annotate を提供し、SDFファイルを呼び出して遅延逆注釈のプロセスを完了します。

使用形式は以下の通りです：

$sdf_annotate ('sdf_file'[, module_instance] [,'sdf_configfile'][,'sdf_logfile'][,'mtm_spec'] [,'scale_factors'][,'scale_type']);

ここで、sdf_file は必須であり、その他のパラメータは省略可能です。

ここでは、最初のいくつかの一般的なパラメータのみを説明します。

  • sdf_file: SDFファイル名。パス情報を含みます。
  • module_instance: インスタンス化された設計モジュール名。通常はtestbench内でインスタンス化されたデジタル設計モジュール名です。SDFファイル内容内の宣言と階層が一致するように注意してください。
  • log_file: コンパイル時のSDFに関するログで、参照を容易にします。
  • mtm_spec: 使用する遅延タイプを指定します。オプションにはMAXIMUM、MINIMUM、TYPICALがあり、それぞれSDFファイルで注釈された最大値、最小値、典型値を使用することを示します。もちろん、上記のSDFファイルの例には典型値はありません。

specify を使用したシミュレーション

以下では、specify を使用して簡単なタイミングシミュレーションを行い、SDFファイルを使用したタイミングシミュレーションと比較できるようにします。

specify で遅延を指定したANDゲートの論理記述は以下の通りです：

module and_gate(
   output  Z,
   input   A, B);

   assign Z = A & B ;

   specify
      specparam t_rise = 1.3:1.5:1.7 ;
      specparam t_fall = 1.1:1.3:1.6 ;
      (A, B  *> Z) = (t_rise, t_fall) ;
   endspecify

 endmodule

specify で遅延を指定したDフリップフロップの記述は以下の通りです：

例

module d_gate(
            output      Q ,
            input       D, CP);

   reg                  Q_r ;
   always @(posedge CP)
     Q_r <= D ;
   assign       Q = Q_r ;

   specify
      if (D == 1'b1)
        (posedge CP => (Q +: D)) = (1.3:1.5:1.7, 1.1:1.4:1.9) ;
      if (D == 1'b0)
        (posedge CP => (Q +: D)) = (1.2:1.4:1.6, 1.0:1.3:1.8) ;
      $setup(D, posedge CP, 1);
   endspecify

endmodule

トップレベルモジュールの記述は以下の通りです。主な機能は、AND論理の出力結果をDフリップフロップに入力してバッファリングすることです。

例

module top(
   output  and_out,
   input   in1, in2, clk);

   wire    res_tmp ;
   and_gate u_and(res_tmp, in1, in2);
   d_gate   u_dt(and_out, res_tmp, clk);

endmodule

testbenchの記述は以下の通りです。シミュレーション時に "+maxdelays" を設定し、最大遅延値を使用します。

例

`timescale 1ns/1ps
module test ;
   wire         and_out ;
   reg          in1, in2 ;
   reg          clk ;

   initial begin
      clk = 0 ;
      forever begin
          #(10/2) clk = ~clk ;
      end
   end

   initial begin
      in1 = 0 ; in2 = 0 ;
      # 32 ;
      in1 = 1 ; in2 = 1 ;
      # 13 ;
      in1 = 1 ; in2 = 0 ;
   end

   top   u_top(
               .and_out (and_out),
               .in1     (in1),
               .in2     (in2),
               .clk     (clk));

   initial begin
      forever begin
         #100;
         if ($time >= 1000)  $finish ;
      end
   end

endmodule // test

シミュレーションのタイミングは以下の通りです。図から分かること：

  • (1) ANDゲートの入力端A/Bから出力端Zへの立ち上がり遅延は 33.7-32=1.7nsです；
  • (2) ANDゲートの出力端Zからフリップフロップの入力端Dへの相互接続遅延は0です；
  • (3) フリップフロップのD端からCP端までの時間差は 35-33.7=1.3nsであり、setup check時に設定した1nsより大きいため、タイミングは要件を満たしており、violationは存在しません。
  • (4) フリップフロップのCP端から出力端Qへの立ち上がり遅延は 36.7-35=1.7nsです；

以上より、シミュレーション結果は設計パラメータと一致しています。

SDF を使用したシミュレーション

SDFファイルの例で使用されたパラメータを変更せずに、複数のCELL記述をまとめて完全なSDFファイルとし、"simple_test.sdf"という名前を付けます。

testbenchに以下の文を追加し、SDFファイル内の遅延情報を設計のモジュールtopに逆注釈して、再度タイミングシミュレーションを行います。

   initial begin
      $sdf_annotate("../rtl/simple_test.sdf", u_top, , "sdf.log", "MAXIMUM", ,);
   end

シミュレーションのタイミングとlog出力情報は以下の通りです。図から分かること：

  • (1) ANDゲートの入力端A/Bから出力端Zへの立ち上がり遅延は 33.8-32=1.8nsです；
  • (2) ANDゲートの出力端Zからフリップフロップの入力端Dへの相互接続遅延は 34.551-33.8=0.751nsであり、もはや0ではありません；
  • (3) フリップフロップのD端子からCP端子までの時間差は35-34.551=0.449nsであり、setup check時に設定した1nsより小さいため、タイミング要件を満たさず、violationが存在するという情報が出力されます。
  • (4) フリップフロップのCP端子から出力端子Qまでの立ち上がり遅延は37.3-35=2.3nsです。

以上のことから、シミュレーション結果は設計パラメータに適合していますが、タイミングにviolationが存在します。主な原因は、ANDゲートの入力端のデータとフリップフロップのクロックが非同期で無関係であるためです。このような非同期の問題を解決するには、次の章「第4章：同期と非同期」を参照してください。

説明が必要なのは以下のとおりです。

specifyブロック文と比較して、SDFファイルはモジュール間のwire delayも指定できます。

一般的に、SDFファイルを使用してレイアウトレベルのネットリストのタイミング情報を指定すると、実際のデジタル回路に最も近くなります。RTLや論理合成後のゲートレベルネットリストと比較して、このバージョンのタイミングが最も悪いです。

SDFファイルでモジュール内のパス遅延を指定する場合、元のモジュールのspecifyブロックを保持する必要があります。また、specifyブロックとSDFファイルで指定する遅延の条件やタイプなどはすべて一致している必要がありますが、遅延値は異なっていても構いません。例えば、specifyブロックで無条件に遅延を指定した場合：

(A => Z) = (1.3, 1.7) ;

SDFファイルで条件付き遅延を指定した場合：

(COND A==1'b1&&B==1'b1 (IOPATH A Z (1.5::1.8) (1.3::1.7)))

コンパイル段階で「IOPATH from A to Z is not found.」というSDF Warningが報告されます。SDFファイルで設定した遅延は無効です。この場合、SDFファイルでも無条件の方法でパス遅延を指定する必要があります。

今回はSDFファイルとその使用方法を紹介するために手動で作成したSDFファイルです。実際には、SDFファイルは設計者がIC設計ツール（例：PrimeTime）を使って生成するものであり、前述の注意事項についてもあまり心配する必要はなく、デバッグ時に注意すればよいです。一般的なデジタル設計のゲートレベルネットリストは膨大な量になるため、人がSDFファイルを書くことは現実的ではありません。
