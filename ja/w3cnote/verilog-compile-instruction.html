2.5 Verilog コンパイル指令

分類 Verilog チュートリアル

バッククォートで始まる`一部の識別子は Verilog システムコンパイル指令です。

コンパイル指令は、Verilog コードの作成、コンパイル、デバッグなどに非常に便利です。

以下では、完全な8つのコンパイル指令を紹介します。このうち、最初の4つは使用頻度が高くなっています。

`define, `undef

コンパイル段階で、`defineテキスト置換に使用され、C言語の...に類似しています。#define。

いったん`define指令がコンパイルされると、その指令はコンパイルプロセス全体で有効になります。たとえば、あるファイルで次のように定義した場合：

`define    DATA_DW     32

別のファイルでも DATA_DW を直接使用できます。

`define    S     $stop;   
//用`S来代替系统函数$stop; (包括分号)
`define    WORD_DEF   reg [31:0]       
//可以用`WORD_DEF来声明32bit寄存器变量

`undef以前のマクロ定義を取り消すために使用されます。例：

`define    DATA_DW     32
……
reg  [DATA_DW-1:0]    data_in   ;
……
`undef DATA_DW

`ifdef, `ifndef, `elsif, `else, `endif

これらは条件付きコンパイル指令に属します。次の例では、MCU51 が定義されている場合は1番目のパラメータ説明を使用します。MCU が定義されておらず、WINDOW が定義されている場合は2番目のパラメータ説明を使用します。両方とも定義されていない場合は3番目のパラメータ説明を使用します。

`ifdef       MCU51
    parameter DATA_DW = 8   ;
`elsif       WINDOW
    parameter DATA_DW = 64  ;
`else
    parameter DATA_DW = 32  ;
`endif

`elsif, `elseコンパイル指令にとって`ifdef指令はオプションであり、つまり...のみでも`ifdef 和 `endif1つの条件付きコンパイル指令ブロックを構成できます。

もちろん、...を使用して`ifndef条件付きコンパイルを設定することもできます。これは、関連するマクロ定義がない場合に関連する文を実行することを示します。

次の例では、WINDOW が定義されている場合は2番目のパラメータ説明を使用します。WINDOW が定義されていない場合は1番目のパラメータ説明を使用します。

例

`ifndef     WINDOW
    parameter DATA_DW = 32 ;  
 `else
    parameter DATA_DW = 64 ;
 `endif

`include

使用すると`includeコンパイル時に Verilog ファイルを別の Verilog ファイルに埋め込むことができ、C言語の #include 構造に似た働きをします。この指令は通常、グローバルまたは共通のヘッダーファイルを設計ファイルに含めるために使用されます。

ファイルパスは相対パスでも絶対パスでも使用できます。

`include         "../../param.v"
`include         "header.v"

`timescale

Verilog モデルでは、遅延は具体的な単位時間で表され、`timescaleコンパイル指令によって時間単位が実際の時間に関連付けられます。

この指令は、遅延とシミュレーションの単位および精度を定義するために使用されます。形式は次のとおりです。

`timescale      time_unit / time_precision

time_unit は時間単位を表し、time_precision は時間精度を表します。これらはどちらも数字と単位 s（秒）、ms（ミリ秒）、us（マイクロ秒）、ns（ナノ秒）、ps（ピコ秒）、fs（フェムト秒）で構成されます。時間精度は時間単位と同じにできますが、時間精度の大きさは時間単位の大きさを超えることはできません。たとえば、次の例では、出力端 Z は A&B の結果を 5.21ns 遅延して出力します。

例

`timescale 1ns/100ps    //時間単位は1ns、精度は100ps、有効
//`timescale 100ps/1ns //無効
module AndFunc(Z, A, B);
    output Z;
    input A, B ;
    assign #5.207 Z = A & B
endmodule

コンパイルプロセス中に、`timescale指令は、別の...に遭遇するまで、後続のすべてのモジュールの遅延値に影響を与えます。`timescale指令または`resetall指令。

Verilog にはデフォルトの...がないため、`timescale、指定されていない場合、`timescaleVerilog モジュールは前にコンパイルされたモジュールの...を継承することになります。`timescaleパラメータ。設計エラーが発生する可能性があります。

設計内の複数のモジュールがすべて...を持つ`timescale場合、シミュレータは常にすべてのモジュールの最小遅延精度に合わせられ、すべての遅延はそれに応じて最小遅延精度に換算され、遅延単位は影響を受けません。例：

例

`timescale 10ns/1ns      
module test;
    reg        A, B ;
    wire       OUTZ ;
 
    initial begin
        A     = 1;
        B     = 0;
        # 1.28    B = 1;
        # 3.1     A = 0;
    end
 
    AndFunc        u_and(OUTZ, A, B) ;
endmodule

モジュール AndFunc では、5.207 は 5.21ns に対応します。

モジュール test では、1.28 は 13ns に、3.1 は 31ns に対応します。

ただし、test をシミュレーションする場合、AndFunc の最小精度が 100ps であるため、test の遅延精度は再調整されます。13ns は 130*100ps に、31ns は 310*100ps に対応します。シミュレーション時も遅延精度は 100ps が使用されます。シミュレーション時間単位の大小は影響しません。

並列サブモジュールがある場合、サブモジュール間の `timescale は互いに影響しません。

たとえば、モジュール test 内でサブモジュール OrFunc をさらにインスタンス化した場合、test をシミュレーションするとき、OrFunc の #5.207 遅延は依然として 52ns に対応します。

例

//サブモジュール：
`timescale 10ns/1ns      //時間単位は1ns、精度は100ps、有効
module OrFunc(Z, A, B);
    output Z;
    input A, B ;
    assign #5.207 Z = A | B
endmodule
 
//トップレベルモジュール：
`timescale 10ns/1ns      
module test;
    reg        A, B ;
    wire       OUTZ ;
    wire       OUTX ;
 
    initial begin
        A     = 1;
        B     = 0;
        # 1.28    B = 1;
        # 3.1     A = 0;
    end
 
    AndFunc        u_and(OUTZ, A, B) ;
    OrFunc         u_and(OUTX, A, B) ;
 
endmodule

この例では、test をシミュレーションするとき、OrFunc の #5.207 遅延は依然として 52ns に対応します。

`timescaleの時間精度設定はシミュレーション時間に影響します。時間精度が小さいほど、シミュレーション時に消費するメモリが多くなり、実際に使用されるシミュレーション時間が長くなります。そのため、必要がない場合は、時間精度はできるだけ大きく設定するべきです。

`default_nettype

この指令は、暗黙的なネット変数にネットタイプを指定するために使用されます。つまり、宣言されていない接続をネットタイプとして定義します。

`default_nettype wand

この例で定義されたデフォルトのネットは wire-and タイプです。したがって、この指令の後にあるモジュール内の接続が宣言されていない場合、そのネットは wire-and タイプと見なされます。

`default_nettype none

この例が定義された後は、wire 型変数は自動的に生成されなくなります。

たとえば、次の1番目の書き方はコンパイル時に Error を報告しませんが、2番目の書き方はコンパイルに失敗します。

例

//Z1 は定義なしで使用され、システムはデフォルトで Z1 を wire 型変数とみなし、Warning はあるが Error はない
module test_and(
        input      A,
        input      B,
        output     Z);
    assign Z1 = A & B ;  
endmodule

例

//Z1 は定義なしで使用され、コンパイル指令が存在するため、システムは Error を報告し、これにより書き間違いを検出する
`default_nettype none
module test_and(
        input      A,
        input      B,
        output     Z);
    assign Z1 = A & B ;  
endmodule

`resetall

このコンパイラ指令は、すべてのコンパイル指令をデフォルト値に再設定します。

`resetallデフォルトの接続タイプをネットタイプに設定できます。

当 `resetallモジュールの最後に追加すると、現在の...を`timescaleキャンセルしてそれ以上の伝播を防ぎ、現在の...が`timescale局所的に有効であることを保証し、`timescale の誤った継承を回避します。

`celldefine, `endcelldefine

これら2つのプログラム指令は、モジュールをセルモジュールとしてマークするために使用され、モジュールの定義を含みます。たとえば、AND、OR、NOT ゲート、一部の PLL セル、PAD モデル、および一部の Analog IP などです。

例

`celldefine
module (
    input      clk,
    input      rst,
    output     clk_pll,
    output     flag);
        ……
endmodule
`endcelldefine

`unconnected_drive, `nounconnected_drive

モジュールのインスタンス化において、これら2つのコンパイル指令の間に現れる未接続の入力ポートは、順バイアス回路状態または逆バイアス回路状態になります。

`unconnected_drive pull1
. . .
 / *在这两个程序指令间的所有未连接的输入端口为正偏电路状态（连接到高电平） * /
`nounconnected_drive
`unconnected_drive pull0
. . .
 / *在这两个程序指令间的所有未连接的输入端口为反偏电路状态（连接到低电平） * /
`nounconnected_drive
