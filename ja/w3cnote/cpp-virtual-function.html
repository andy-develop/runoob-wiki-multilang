仮想関数と純粋仮想関数の違い

分類 プログラミング技術

まず：一つの概念を強調します

関数を仮想関数と定義しても、その関数が実装されない関数であることを意味するわけではありません。

仮想関数として定義するのは、基底クラスのポインタを使ってサブクラスのこの関数を呼び出せるようにするためです。

関数を純粋仮想関数と定義して初めて、関数が実装されていないことを意味します。

純粋仮想関数を定義するのはインターフェースを実現するためであり、規範としての役割を果たします。このクラスを継承するプログラマーはこの関数を必ず実装しなければならないという規範です。

1、はじめに

次のようなクラス階層があると仮定します：

class A
{
public:
    virtual void foo()
    {
        cout<<"A::foo() is called"<<endl;
    }
};
class B:public A
{
public:
    void foo()
    {
        cout<<"B::foo() is called"<<endl;
    }
};
int main(void)
{
    A *a = new B();
    a->foo();   // 在这里，a虽然是指向A的指针，但是被调用的函数(foo)却是B的!
    return 0;
}

この例は仮想関数の典型的な応用であり、この例を通じて仮想関数についてある程度の概念が得られるかもしれません。その「仮想」たる所以は、いわゆる「遅延結合」または「動的結合」にあります。クラス関数の呼び出しはコンパイル時に決定されるのではなく、実行時に決定されます。コードを書く時点では、呼び出されるのが基底クラスの関数なのか、どの派生クラスの関数なのかを確定できないため、「仮想」関数と呼ばれます。

仮想関数はポインタまたは参照を利用してのみ多態性の効果を達成できます。

C++純粋仮想関数

一、定義

純粋仮想関数は基底クラスで宣言される仮想関数であり、基底クラスでは定義されませんが、すべての派生クラスが自分自身の実装方法を定義することを要求します。基底クラスで純粋仮想関数を実装する方法は、関数プロトタイプの後に「=0」を付けることです。

virtual void funtion1()=0

二、導入の理由

  • 1、多態性の特性を便利に使用するために、基底クラスで仮想関数を定義する必要がよくあります。
  • 2、多くの場合、基底クラス自体がオブジェクトを生成することは不合理です。例えば、動物は基底クラスとして虎や孔雀などのサブクラスを派生させることができますが、動物自体がオブジェクトを生成するのは明らかに不自然です。

上記の問題を解決するために、純粋仮想関数の概念が導入されました。関数を純粋仮想関数として定義すると（方法：virtual ReturnType Function()= 0;）、コンパイラは派生クラスで多態性を実現するために必ずオーバーライドすることを要求します。同時に、純粋仮想関数を含むクラスは抽象クラスと呼ばれ、オブジェクトを生成できません。これにより上記の2つの問題をうまく解決できます。

純粋仮想関数を宣言したクラスは抽象クラスです。したがって、ユーザーはクラスのインスタンスを作成できず、その派生クラスのインスタンスのみを作成できます。

純粋仮想関数の最も顕著な特徴は、派生クラスで関数を再宣言しなければならないことです（後ろの「=0」を付けないと、その派生クラスもインスタンス化できません）。また、抽象クラスでは通常定義されません。

純粋仮想関数を定義する目的は、派生クラスに関数のインターフェースのみを継承させることにあります。

純粋仮想関数の意義は、すべてのクラスオブジェクト（主に派生クラスオブジェクト）に純粋仮想関数の動作を実行させることですが、クラスは純粋仮想関数に合理的なデフォルト実装を提供できません。したがって、クラスの純粋仮想関数の宣言は、サブクラスの設計者に「あなたは純粋仮想関数の実装を提供しなければなりませんが、私（クラス）はあなたがどのように実装するかは知りません」と伝えているのです。

抽象クラスの紹介

抽象クラスは特殊なクラスであり、抽象化と設計の目的のために作成され、継承階層構造の上位に位置します。

  • （1）抽象クラスの定義：純粋仮想関数を持つクラスを抽象クラスと呼びます。

  • （2）抽象クラスの役割：抽象クラスの主な役割は、関連する操作をインターフェースとして継承階層構造に組織化し、それによって派生クラスに共通のルートを提供することです。派生クラスは、基底クラスでインターフェースとして定義された操作を具体的に実装します。したがって、派生クラスは実際には一連のサブクラスの操作インターフェースの共通セマンティクスを描き出します。これらのセマンティクスはサブクラスにも伝えられ、サブクラスはこれらのセマンティクスを具体的に実装することも、さらに自分のサブクラスに伝えることもできます。

  • （3）抽象クラスを使用する際の注意：a、抽象クラスは基底クラスとしてのみ使用でき、その純粋仮想関数の実装は派生クラスによって提供されます。派生クラスが純粋仮想関数を再定義せず、基底クラスの純粋仮想関数を継承するだけの場合、その派生クラスは依然として抽象クラスです。派生クラスが基底クラスの純粋仮想関数の実装を提供する場合、その派生クラスはもはや抽象クラスではなく、オブジェクトを生成できる具体的なクラスになります。b、抽象クラスはオブジェクトを定義できません。

まとめ：

  • 1、純粋仮想関数の宣言は次のとおりです：virtual void funtion1()=0;純粋仮想関数は必ず定義がありません。純粋仮想関数は派生クラスの動作、すなわちインターフェースを規範化するために使用されます。純粋仮想関数を含むクラスは抽象クラスであり、抽象クラスはインスタンスを定義できませんが、その抽象クラスを実装する具象クラスを指すポインタまたは参照を宣言することはできます。

  • 2、仮想関数の宣言は次のとおりです：virtual ReturnType FunctionName(Parameter);仮想関数は必ず実装しなければなりません。実装しない場合、コンパイラはエラーを報告します。エラーメッセージは次のとおりです：

    error LNK****: unresolved external symbol "public: virtual void __thiscall ClassName::virtualFunctionName(void)"

  • 3、仮想関数の場合、親クラスとサブクラスはそれぞれ独自のバージョンを持ちます。多態的に呼び出される場合、動的にバインドされます。

  • 4、純粋仮想関数を実装したサブクラスでは、その純粋仮想関数はサブクラスにおいて仮想関数になります。サブクラスのサブクラス、すなわち孫クラスはその仮想関数をオーバーライドでき、多態的に呼び出される場合、動的にバインドされます。

  • 5、仮想関数はC++において多態性（polymorphism）を実現するためのメカニズムです。中核となる理念は、基底クラスを介して派生クラスで定義された関数にアクセスすることです。

  • 6、ヒープ上にメモリを動的に割り当てる場合、デストラクタは仮想関数でなければなりませんが、純粋仮想である必要はありません。

  • 7、フレンドはメンバ関数ではありません。メンバ関数のみが仮想にできるため、フレンドは仮想関数にできません。ただし、フレンド関数に仮想メンバ関数を呼び出させることで、フレンドの仮想問題を解決できます。

  • 8、デストラクタは仮想関数であるべきです。対応するオブジェクト型のデストラクタが呼び出されるため、ポインタがサブクラスオブジェクトを指している場合、サブクラスのデストラクタが呼び出され、その後自動的に基底クラスのデストラクタが呼び出されます。

純粋仮想関数を持つクラスは抽象クラスであり、オブジェクトを生成できず、派生のみ可能です。その派生クラスで純粋仮想関数が書き換えられていない場合、その派生クラスもまだ抽象クラスです。

純粋仮想関数を定義するのは、まさに基底クラスをインスタンス化できないようにするためです。

なぜなら、このような抽象データ構造をインスタンス化すること自体に意味がないからです。

あるいは、実装を提供しても意味がありません。

実際、私個人としては、純粋仮想関数の導入は2つの目的によるものだと考えています。

  • 1、安全性のためです。明確にすべきなのに不注意によって生じる未知の結果を避け、サブクラスに実行すべき実装を行うよう促します。

  • 2、効率のためです。プログラム実行の効率ではなく、コーディングの効率のためです。
