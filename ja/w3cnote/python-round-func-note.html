Pythonにおけるround関数の小さな落とし穴

カテゴリ プログラミング技術

これはずっと書きたいと思っていたが、このテーマが小さいので、ずっと書くのが面倒だった。でも、やはり書いておこう。このまま残しておくといつか災いになるから。

round関数はとても簡単で、浮動小数点数を近似して、小数桁を保持する。例えば：

>>> round(10.0/3, 2)
3.33
>>> round(20/7)
3

最初の引数は浮動小数点数、2番目の引数は保持する小数桁数で、オプションです。省略した場合、デフォルトで整数まで丸められます。

こんなに簡単な関数に、どんな落とし穴があるのだろうか？

1、roundの結果はpythonのバージョンに関係する

python2とpython3で何が違うのか見てみましょう：

$ python
Python 2.7.8 (default, Jun 18 2015, 18:54:19) 
[GCC 4.9.1] on linux2
Type "help", "copyright", "credits" or "license" for more information.
>>> round(0.5)
1.0

$ python3
Python 3.4.3 (default, Oct 14 2015, 20:28:29) 
[GCC 4.8.4] on linux
Type "help", "copyright", "credits" or "license" for more information.
>>> round(0.5)
0

面白いでしょう？

pythonのドキュメントを読むと、そこにはこう書かれています：

python2.7のdocでは、round()の最後にこう書かれています。「Values are rounded to the closest multiple of 10 to the power minus ndigits; if two multiples are equally close, rounding is done away from 0.」保持される値は、より近い上位の倍数に丸められます（四捨六入）。もし二つの倍数が同じくらい近い場合、0から遠い方に丸められます。したがって、round(0.5)は1に近似され、round(-0.5)は-1に近似されます。

しかし、python3.5のdocでは、ドキュメントは「values are rounded to the closest multiple of 10 to the power minus ndigits; if two multiples are equally close, rounding is done toward the even choice.」に変わっています。もし両辺までの距離が同じであれば、偶数の方に丸められます。例えば、round(0.5)とround(-0.5)はどちらも0に丸められ、round(1.5)は2に丸められます。

したがって、py2からpy3に移行するプロジェクトがある場合は、roundの箇所に注意してください（もちろん、/や//、print、そして少し変わったライブラリにも注意が必要です）。

>>> round(2.675, 2)
2.67

python2とpython3のdocはどちらも同じ例を挙げています。原文はこう言っています：

Note

The behavior of round() for floats can be surprising: for example, round(2.675, 2) gives 2.67 instead of the expected 2.68. This is not a bug: it’s a result of the fact that most decimal fractions can’t be represented exactly as a float. See Floating Point Arithmetic: Issues and Limitations for more information.

簡単に言うと、round(2.675, 2) の結果は、python2から見てもpython3から見ても、2.68になるはずなのに、結果はなぜか2.67になるのです。なぜでしょうか？これは浮動小数点数の精度に関係しています。ご存知のように、機械の中では浮動小数点数は必ずしも正確に表現できるわけではありません。なぜなら、1と0の列に変換すると無限桁になる可能性があり、機械はすでに切り捨て処理を行っているからです。そのため、機械の中に保存される2.675という数字は、実際の数字よりほんの少しだけ小さいのです。このわずかな差によって、2.67にほんの少しだけ近くなるため、小数第二位まで丸めると2.67に近似されるのです。

以上です。精度にそれほど要求がない場合を除き、できるだけround()関数は避けるようにしましょう。近似計算には他にも選択肢があります：

  • mathモジュールのいくつかの関数を使います。例えば、math.ceiling（天井除算）。
  • pythonには整除（整数除算）が組み込まれています。python2では /、python3では //、そしてdiv関数もあります。
  • 文字列フォーマットは切り捨てに使えます。例えば、"%.2f" % value（小数第二位まで保持して文字列にします……もし浮動小数点数として使いたいなら、float()の外衣を着せてください）。
  • もちろん、浮動小数点数の精度に対する要求が非常に高い場合は、「デシマル」を使ってください。いやいや、decimalモジュールを使ってください。

そんなところです。
