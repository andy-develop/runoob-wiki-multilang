基本構文

📋 Cron 時間形式

* * * * * コマンド
分 時 日 月 曜日 実行するコマンド

分 (0-59)

毎時の何分目に実行するか

時 (0-23)

毎日の何時目に実行するか

日 (1-31)

毎月の何日目に実行するか

月 (1-12)

毎年の何月目に実行するか

曜日 (0-7)

毎週の何日目に実行するか
(0と7はどちらも日曜日を表します)

🎯 特殊文字の説明

  • *任意の値を表し、すべての可能な値にマッチする
  • ,リストを表し、例: 1,3,5 は1時、3時、5時を表す
  • -範囲を表し、例: 1-5 は1から5まで
  • /間隔を表し、例: */5 は5単位ごと
  • ?日と曜日のフィールドに使用し、値を指定しないことを表す
よく使うコマンド

⏰ 最もよく使われるスケジュールタスク

🔄 毎分実行

* * * * * /path/to/script.sh
毎分1回実行され、テストによく使われる

🕐 毎時実行

0 * * * * /path/to/script.sh
毎時の0分に実行。例: 1:00, 2:00, 3:00

🌅 毎朝8時に実行

0 8 * * * /path/to/script.sh
毎日午前8:00に実行。日次タスクに適している

🌙 毎日深夜に実行

0 2 * * * /path/to/backup.sh
毎日午前2:00に実行。バックアップタスクに適している

📅 毎週月曜日に実行

0 9 * * 1 /path/to/weekly-report.sh
毎週月曜日午前9:00に実行。週次レポート生成に適している

📆 毎月1日に実行

0 0 1 * * /path/to/monthly-task.sh
毎月1日未明に実行。月次タスクに適している

⚡ 5分ごとに実行

*/5 * * * * /path/to/monitor.sh
5分ごとに1回実行。監視スクリプトに適している

🔄 30分ごとに実行

*/30 * * * * /path/to/sync.sh
30分ごとに1回実行。同期タスクに適している
上級の使い方

🚀 上級スケジュール設定

💼 営業日に毎時実行

0 * * * 1-5 /path/to/workday-task.sh
月曜から金曜まで毎時実行。オフィス自動化に適している

🎯 特定の時間に実行

30 9,14,18 * * * /path/to/reminder.sh
毎日9:30、14:30、18:30に実行

📈 営業時間内に15分ごと

*/15 9-17 * * 1-5 /path/to/status-check.sh
営業日の9時から17時まで15分ごとに実行

🌸 四半期タスク

0 0 1 1,4,7,10 * /path/to/quarterly.sh
各四半期の初日に実行（1月、4月、7月、10月）

🎉 年次タスク

0 0 1 1 * /path/to/yearly-cleanup.sh
毎年1月1日に年次クリーンアップを実行

⏰ 複雑な時間の組み合わせ

15,45 */2 * * * /path/to/complex-task.sh
2時間ごとの15分と45分に実行

🔧 出力リダイレクト付き

0 2 * * * /path/to/backup.sh >> /var/log/backup.log 2>&1
バックアップを実行し、エラー情報を含むログを記録

🌐 環境変数の設定

0 3 * * * cd /app && /usr/bin/python3 script.py
指定ディレクトリに移動してPythonスクリプトを実行
実践例

💡 実際の応用シーン

📊 データベースバックアップ

0 2 * * * mysqldump -u root -p database_name > /backup/db_$(date +\%Y\%m\%d).sql
毎日午前2時にMySQLデータベースをバックアップ

🧹 ログクリーンアップ

0 1 * * 0 find /var/log -name "*.log" -mtime +30 -delete
毎週日曜日午前1時に30日前のログファイルを削除

🔄 Git 自動同期

*/10 * * * * cd /path/to/repo && git pull origin main
10分ごとにGitリポジトリの更新を自動取得

📧 システムレポートメール

0 8 * * 1 df -h | mail -s "Weekly Disk Usage" admin@example.com
毎週月曜日にディスク使用状況のメールを送信

🌡️ システム監視

*/5 * * * * top -bn1 | grep "Cpu(s)" >> /var/log/cpu_usage.log
5分ごとにCPU使用率を記録

🔒 SSL証明書の確認

0 9 * * * openssl x509 -in /etc/ssl/cert.pem -noout -checkend 2592000
毎日SSL証明書が期限切れに近いかどうかを確認

📱 APIヘルスチェック

*/2 * * * * curl -f http://localhost:8080/health || echo "API Down" | mail -s "Alert" admin@example.com
2分ごとにAPIの状態を確認し、異常時にメールを送信

🔄 Dockerコンテナの再起動

0 4 * * * docker restart $(docker ps -q --filter "status=exited")
毎日午前4時に停止中のDockerコンテナを再起動
テクニックとヒント

💎 エキスパートのテクニックとベストプラクティス

📝 Cron管理コマンド

crontab -e # 現在のユーザーのcrontabを編集
crontab -l # 現在のcrontabを表示
crontab -r # 現在のcrontabを削除
基本的なcrontab管理コマンド

👤 ユーザーレベル管理

sudo crontab -u username -e # 指定したユーザーのcrontabを編集
sudo crontab -u username -l # 指定したユーザーのcrontabを表示
他のユーザーのスケジュールタスクを管理

📊 ログ記録のベストプラクティス

0 2 * * * /path/to/script.sh >> /var/log/cron_script.log 2>&1
標準出力とエラーを両方ともログファイルにリダイレクトする

🔧 環境変数の設定

SHELL=/bin/bash
PATH=/usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin
0 2 * * * /path/to/script.sh
crontab内で環境変数を設定する

⚠️ タスクの重複を防ぐ

0 * * * * flock -n /tmp/script.lock -c '/path/to/script.sh'
ファイルロックを使用してスクリプトの重複実行を防ぐ

🔍 cronタスクのデバッグ

# cronサービスの状態を確認
systemctl status cron
# cronログを確認
tail -f /var/log/cron
スケジュールタスクをデバッグする一般的な方法

📊 特殊な時間表現

@reboot /path/to/startup.sh # システム起動時に実行
@yearly /path/to/yearly.sh # 毎年実行
@monthly /path/to/monthly.sh # 毎月実行
@weekly /path/to/weekly.sh # 毎週実行
@daily /path/to/daily.sh # 毎日実行
@hourly /path/to/hourly.sh # 毎時実行
特殊文字列を使用して時間表現を簡素化する

⚡ パフォーマンス最適化のアドバイス

# システムが混雑する時間帯の実行を避ける
5 2 * * * /path/to/heavy-task.sh
# 実行時間を分散させ、複数のタスクが同時に実行されるのを避ける
7 3 * * * /path/to/task1.sh
13 3 * * * /path/to/task2.sh
タスクの実行時間を適切に計画する
