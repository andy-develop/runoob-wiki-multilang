1.1 Androidでおなじみの画面適応

カテゴリ Android 拡張チュートリアル

はじめに

Androidのオープンソースがもたらすネタは、さまざまな機種・バージョンのスマートフォンにおける互換性の問題に勝るものはなく、同時にすべてのAndroid開発者が直面する課題となっています。あるいは、さまざまな問題が何の前触れもなく発生します。本稿では、互換性の問題の中でも適応問題を中心に紹介します。

基本概念

  • 画面サイズ

    画面の対角線の長さで、通常「インチ」で表します。

  • 解像度

    スマホ画面のピクセル数のことです。

  • 画面ピクセル密度（Pixels Per Inch）

    1インチあたりのピクセル数です。詳しく言うと、対角線のピクセル数を画面サイズで割ったものです。

上記の画面の点を踏まえ、Androidシステムでは標準のDPI（PPI）値がいくつか定義されています。

解像度240X320320X480480X800720X12801080X1920

独立ピクセルdp

実にさまざまな画面密度の違いにより、同じピクセルサイズの長さが異なる画面では表示される長さが異なります。Androidシステムはmdpi、すなわち160dpiを標準とし、この画面では1px = 1dp、他の画面では比例換算します。hdpi（240dpi）では1dp = 1.5px...（すなわちldpi:mdpi:hdpi:xhdpi:xxhdpi = 3:4:6:8:12）

独立ピクセルsp

開発中、フォントサイズの設定にはspを単位として使用します。この単位で設定されたフォントはシステムのフォントサイズの影響を受けます。フォントサイズの設定には12sp、14sp、18sp、22spを使用することをお勧めします。

画面適応の解決

画面に関する基本概念を理解した後も、実際の開発では断片化の問題が次々と発生します。そこで、画面適応の旅に出かけましょう。

画像の適応

小猪（シャオズー）が以前の記事で使用すると書いたこと以外に.9画像より多くの場合、画像の劣化（歪み）の問題を解決する必要があります。

Android SDKの画像読み込みフロー

  1. Android SDKは画面密度に応じて対応するリソースファイルを自動的に選択してレンダリング・読み込みを行います。例えば、SDKがスマホの解像度がxhdpiであることを検出すると、優先的にxhdpiフォルダー内の対応する画像リソースを探します。
  2. xhdpiフォルダーに画像リソースがない場合は、より高解像度のフォルダー（例：xxhdpi）を検索し、同じ名前の画像リソースが見つかるまで探し、それを比例に応じて縮小してxhdpi画像にします。
  3. 上のフォルダーを検索しても画像が見つからない場合は、低解像度のフォルダー（例：hdpi）を検索し、同じ名前の画像リソースが見つかるまで探し、それを比例に応じて拡大してxhdpi画像にします。

これに対して、デザイナー（美工）と連携する場合、できるだけ大きな画像を選択し、同時に現在の主流解像度の画面に合わせます。

レイアウトの適応

まずlayout_weightから説明しましょう。layout_weightはandroid.widget.LinearLayoutの属性で、簡単に言うとLinearLayoutの子Viewでのみ使用可能です。もちろんwrap_contentとmatch_parentについても言うまでもありません。使用方法は皆さんご存知だと思いますが、layout_weightにはいくつか注意点があります。余計な話をすべきかどうか分かりませんが、もういい、スキップ！（逃げる）

修飾子

サイズ修飾子

  • 使用シーン

    タブレットとスマホを使ったことがある方ならご存知でしょうが、アプリにはこういう状況があります。スマホ（小さい画面）ではシングルパネルでそれぞれ内容を表示し、タブレットではデュアルパネルモードでより多くの内容を表示します。

  • 使用方法

    サイズ修飾子（layout-large）を使ってファイルを作成することで、ディレクトリはこのようになります。そして、そこに異なる内容を入れます。

    res/layout/activity_main.xml

    <LinearLayout xmlns:android="http://schemas.android.com/apk/res/android" android:orientation="vertical" android:layout_width="match_parent" android:layout_height="match_parent"> <fragment android:id="@+id/left_fragment" android:layout_height="match_parent" android:name="com.xlhgo.demo.LeftFragment" android:layout_width="match_parent" /> </LinearLayout>

    res/layout-large/activity_main.xml

    <LinearLayout xmlns:android="http://schemas.android.com/apk/res/android" android:layout_width="match_parent" android:layout_height="match_parent" android:orientation="horizontal"> <fragment android:id="@+id/left_fragment" android:layout_height="match_parent" android:layout_width="0dp" android:layout_weight="1" android:name="com.xlhgo.demo.LeftFragment" /> <fragment android:id="@+id/right_fragment" android:layout_height="match_parent" android:layout_width="0dp" android:layout_weight="1" android:name="com.xlhgo.demo.RightFragment /> </LinearLayout>

  • 注意事項

    この方法はAndroid 3.2より前のバージョンにのみ適しています。それ以降は、また新しい遊び道具があります。

最小幅修飾子

元のサイズ修飾子に基づくと、largeの存在はあまりにも曖昧です。そこでGoogleパパが新しい方法を提供してくれました。それが最小幅（Smallest-width）修飾子です。

  • 使用方法

    res/layout-sw600dp/activity_main.xml

    <LinearLayout xmlns:android="http://schemas.android.com/apk/res/android" android:layout_width="match_parent" android:layout_height="match_parent" android:orientation="horizontal"> <fragment android:id="@+id/left_fragment" android:layout_height="match_parent" android:layout_width="0dp" android:layout_weight="1" android:name="com.xlhgo.demo.LeftFragment" /> <fragment android:id="@+id/right_fragment" android:layout_height="match_parent" android:layout_width="0dp" android:layout_weight="1" android:name="com.xlhgo.demo.RightFragment /> </LinearLayout>

  • 分析

    つまり、最小幅が600dp以上のデバイスでは、システムは layout-sw600dp/main.xml（デュアルパネル）レイアウトを選択し、それ以外の場合は layout/activity_main.xml（シングルパネル）レイアウトを選択します。

    ただし、Androidバージョン3.2未満のデバイスはこの技術をサポートしていません。その理由は、これらのデバイスがsw600dpをサイズ修飾子として認識できないためです。したがって、依然としてlarge修飾子を使用する必要があります。これにより、res/layout-large/main.xml というファイル（res/layout-sw600dp/activity_main.xml と同じ）が存在することになります。へへ、Androidはこのすべてをとっくに見抜いています。

レイアウトエイリアスの使用

上記の問題を解決するために、レイアウトエイリアスを使用します。

  • 使用方法：

    元の res/layout-sw600dp/activity_main.xml レイアウトを res/layoout/ ディレクトリに移動し、activity_main_(xxx).xml という名前にします（xxxの命名規則はできるだけ統一した標準にしましょう）。

    次に、values-large と values-sw600dp のレイアウトを見てみましょう。

    <resources> <item name="main" type="layout">@layout/activity_main_(xxx)</item> </resources>

画面の向き（Orientation）修飾子

  • res/layout-land
  • res/layout-port
  • res/layout-sw600dp-land
  • res/layout-sw600dp-port

dimenの使用

dpを使用しても、実際には画面適応の問題を完全に解決することはできません。特に横向きレイアウトのときに気づきやすいです。というのも、スマホによって画面の幅と高さのdp値が異なるため、コントロールにどのようにdp値を割り当てても適応をうまく解決できないからです。

  • 解決策

    画面の幅を320に分割し、高さを480に分割して、実際のピクセルに従って各単位に値を割り当て、対応するvalues-widthxheightフォルダー内のlay_x.xmlとlay_y.xmlに配置します。

  • 具体的なコード

    import java.io.File; import java.io.FileNotFoundException; import java.io.FileOutputStream; import java.io.PrintWriter; /** * Created by xlh on 2016/12/4. */ public class MakeXml { private final static String rootPath = "F:\\layoutroot\\values-{0}x{1}\\"; //自分の状況に応じて変更できます。 private final static float dw = 320f; private final static float dh = 480f; private final static String WTemplate = "<dimen name=\"x{0}\">{1}px</dimen>\n"; private final static String HTemplate = "<dimen name=\"y{0}\">{1}px</dimen>\n"; public static void main(String[] args) { makeString(320, 480); makeString(480, 800); makeString(480, 854); makeString(540, 960); makeString(600, 1024); makeString(720, 1184); makeString(720, 1196); makeString(720, 1280); makeString(768, 1024); makeString(800, 1280); makeString(1080, 1812); makeString(1080, 1920); makeString(1440, 2560); } public static void makeString(int w, int h) { StringBuffer sb = new StringBuffer(); sb.append("<?xml version=\"1.0\" encoding=\"utf-8\"?>\n"); sb.append("<resources>"); float cellw = w / dw; for (int i = 1; i < 320; i++) { sb.append(WTemplate.replace("{0}", i + "").replace("{1}", change(cellw * i) + "")); } sb.append(WTemplate.replace("{0}", "320").replace("{1}", w + "")); sb.append("</resources>"); StringBuffer sb2 = new StringBuffer(); sb2.append("<?xml version=\"1.0\" encoding=\"utf-8\"?>\n"); sb2.append("<resources>"); float cellh = h / dh; for (int i = 1; i < 480; i++) { sb2.append(HTemplate.replace("{0}", i + "").replace("{1}", change(cellh * i) + "")); } sb2.append(HTemplate.replace("{0}", "480").replace("{1}", h + "")); sb2.append("</resources>"); String path = rootPath.replace("{0}", h + "").replace("{1}", w + ""); File rootFile = new File(path); if (!rootFile.exists()) { rootFile.mkdirs(); } File layxFile = new File(path + "lay_x.xml"); File layyFile = new File(path + "lay_y.xml"); try { PrintWriter pw = new PrintWriter(new FileOutputStream(layxFile)); pw.print(sb.toString()); pw.close(); pw = new PrintWriter(new FileOutputStream(layyFile)); pw.print(sb2.toString()); pw.close(); } catch (FileNotFoundException e) { e.printStackTrace(); } } public static float change(float a) { int temp = (int) (a * 100); return temp / 100f; } }

    対応する各ディレクトリにはlay_x.xmlとlay_y.xmlがあります。

    その中のコードも非常に規則的です。

  • 使用方法

    これらのファイルがあれば、使用は非常に便利です。例えば、デザイナーがくれた画像が320*480の場合、次のように直接呼び出せます。android:layout_xxx="@dimen/xxxx"

パーセントレイアウト

パーセントレイアウトについて、私の記憶が正しければ2015年初頭の新物です。Googleの実子（直系）なので、余計な話はせず、まず公式サイトのリンクを貼ります：android-percent-support-lib-sample

要するにパーセントレイアウトです。デザイナーと適切にコミュニケーションが取れれば、これはAndroid開発において良い選択肢となるでしょう。

<?xml version="1.0" encoding="utf-8"?> <android.support.percent.PercentRelativeLayout xmlns:android="http://schemas.android.com/apk/res/android" xmlns:app="http://schemas.android.com/apk/res-auto" android:layout_width="match_parent" android:layout_height="wrap_content"> <Button android:layout_width="0dp" android:layout_height="wrap_content" android:text="30%" app:layout_widthPercent="30%"/> <Button android:layout_width="0dp" android:layout_height="wrap_content" android:layout_alignParentRight="true" android:text="20%" app:layout_widthPercent="20%"/> </android.support.percent.PercentRelativeLayout>

その他のツールの使用

上記の従来の画面適応策に加えて、私はずいぶん前に外部委託プロジェクトを開発した際に、非常に面白いツールを使用しました。それは鸿神（ホンシェン）のAndroid画面自動適応。デザイナーがくれた画像はiOSサイズだったので、使用後は本当に爽快でした。もちろん、ブロガーは後の面接や社交の場でこの適応案について言及したところ、ある状況ではバグが発生すると言われたので、今は慎重な姿勢を取っています...。しかし全体的には比較的少ないはずです。少なくとも私は直接遭遇したことはありません（きっと私が未熟すぎるだけです）。
