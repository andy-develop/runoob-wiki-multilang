インターネット組織の未来：GitHub社員の奔放さの源泉を分析する

カテゴリ プログラミング技術

もしこんな奔放な会社があったとしたら、「マネージャー」という層がなく、人々はみんな自分の好きなことをして価値を生み出し、それ以外のことは自然に任せて進んでいく。ここで官僚主義による無駄をどれだけ節約できるだろうか？そんな会社はどれだけ速く動けるだろうか？どれだけ多くの無意味な対立が跡形もなく解消されるだろうか？どれほど驚くべきイノベーション文化を形成できるだろうか？

GitHubはまさに、この理想主義に限りなく近づこうとしている会社です！プログラマーの皆さんはGitHubをご存知でしょう。GitHubは開発者のコラボレーションプラットフォームであり、2014年の統計では340万人以上のユーザーがいて、急速に商業化が進んでいます。

GitHubはオープンソースソフトウェアの上に成り立つ民間の営利企業ですが、その運営プロセス全体でオープンソースコラボレーションの精神を実践しています——会社全体がボランティア活動を推奨しています。まだどういう仕組みか分からない？説明を聞いてください。

オープンな仕事の割り当て

ほとんどの企業では、仕事は次のように割り当てられます。会社の上層部がプロジェクトを思いつき、プロジェクト立ち上げ、財務予算、人員配置を経て、トップダウンでプロジェクトを各チームや事業部門に割り当てます。GitHubではそうではありません。彼らは「オープンな仕事の割り当て」方式を採用しています。つまり、自分自身でプロジェクト配分の問題を解決し、正式な申請や管理層の介入なしに、自分がやりたいプロジェクトに自分を割り当てるのです。

あなたはこう言うでしょう。GitHubの社員数はたった175人だから、こんなやり方が通用するのは当然だ、と。しかしValve社を見てください。社員は400人、売上総額は100億ドルに達します。Valveの組織形態はGitHubと非常に似ています。これで何かが説明できるのではないでしょうか。

なぜ会社の構造について話すのか？

古代、焼き畑農業をしていた人々は、自分の余剰生産力で何か第二次・第三次産業ができないかと考えていました。例えば、狩猟の合間に作物を育てたり、衣服を縫ったりして市場で売るなどです。研究によれば、そうした余剰生産力の中で最も影響を与える可能性が高いのは、人間の脳の中にある余剰の創造力です。

そこでGoogleの有名な「20%ルール」で余暇プロジェクトができるようになりました。クレイ・シャーキーという人物が『認知余剰 — ネット時代の創造と繁栄』という本を書きました。彼の考えでは、余暇時間は人々に価値あるものを生み出す機会を与えるというものです。

直感的には、これはまったくのナンセンスに思えます。人をそこに置いて、最初から最後まで自分のやりたいことをやらせれば、自然と価値を生み出すのか？心の中でこう思っているでしょう。あの誰それをここに置いたら、7×24時間淘宝（タオバオ）で買い物をしているだろう、と。

しかし、事実が示すように、そのような労働条件は、創造性のある人々にとって確かに魅力的です。例えば、Chrissie BrodiganというUXリサーチャーがいます。彼女は「Deprivationテスト」というテスト手法を持っており、以前はFirefoxのユーザーエクスペリエンス評価を担当していましたが、GitHubに入ることを決めました。

GitHubの社員は、オープンな仕事の割り当て方式に惹かれたのは、主にそれに境界がないからだと述べています。彼らは自分と気が合う人々と自由に選んで一緒にクールなものを作るのが好きなのです。彼らは一緒に自分たちのプログラマブルオフィスをデザインすることもできます。

イノベーションの4大難題

こう言う人もいるでしょう。こんなものは面倒だし、なぜこんなに混乱させるのか。そんなことに関わりたくない。会社がやるべきことを指示してくれれば、品質と量を保証してやり遂げるだけでいいではないか、と。

この主張が一部の業界ではもちろん成り立つことは言うべきでしょう。例えば、数年前、広東省や浙江省あたりには多くのアパレル工場がありました。アパレル業界の経験が深い人にとっては、明確な目標（例：ターゲット層、服のスタイル、販売地域）が決まれば、いくら投資する必要があるか、どの規模のラインを建設するか、どのような技能工を雇うべきか、さらには各工程の技能工が何をすべきかを伝えることができます。

残念ながら、今日、企業がかなり長期間生き残るためには、未知のイノベーションに直面する必要があります：どうやって革新するのか？どうやってそのような革新を繰り返し起こせるようにするのか？伝統的な企業は独立した「イノベーション部門」を設け、そこに属する人々が革新を担当し、他の人々はアパレル工場で働くようなものです。GitHubは異なります。会社全体をイノベーションを核とした働き方に置いています。これは、一団の人々が継続的に成功裏に革新し続けるための4大難題を考慮したものです：

  • 注意力の管理：一般的な組織の設計は、主に既存の成功に基づいており、一方でその成功を享受し、もう一方で既存の成功を守ることを目的としていて、新しいアイデアの開拓に集中することはありません。

  • 歩調を合わせること：一般的にイノベーションのアイデアは個人や小グループから生まれることが多いですが、実行は全社の力を尽くして行う必要があります。そして様々な理由（政治、社会的要因など）により、残りの大勢の人々に納得してもらうのは難しいのです。

  • 人々に一緒に働かせること：新製品やサービスが実を結び始めると、人、アイデア、取引が急速に増加するため、より多くの人を雇う必要があります。これにより、一方では人々が仕事に参加しやすくなりますが、同時に一部の人が木を見て森を見ず、ビジョンや現在の状況を全体的に把握できない事態を引き起こしやすくなります。

  • 硬直した管理：中には組織構造と管理方法の根本的な変更を本当に必要とするイノベーションがありますが、ほとんどの企業の基本構造はそれほど柔軟ではありません——これが組織構造がイノベーションと同期しにくい直接の原因です。

GitHubの構造は実際にはどのようなものなのか？

コミュニケーション！コミュニケーション！コミュニケーションこそがオープンな仕事の割り当ての中核要素です。言い換えれば、GitHubの会社構造は分散型の情報伝達ネットワークのようなもので、そのネットワーク上では会社の目標、会社がどのように働くか、そしてもちろん何をすべきかが伝達されます。

イノベーション企業の戦略は絶えず調整されており、ある期間のこれらの調整の増分について、全員の認識を同期させることが極めて重要です。そうでなければ、小さな調整が特定のユニットやチームに届きにくくなります。一部のチームが対応する調整を行わず、最終的にそれが蓄積されると、チーム間には深い溝のような認識ギャップが生まれます。あなたはこう言うでしょう。それは普通だ、自分が見てきた企業はみんなそうだ、と。例を挙げると、1980年代、ジョブズはチームを率いて比較的成功したMacintoshを作り上げましたが、もう一つのチームは必死になってApple IIIを作りました。Apple IIIがどういうものかは皆さんご存知でしょう。

良好なコミュニケーションは、チームが新しい、または関連するビジネスチャンスを発見するのにも役立ちます。例えば、このネットワークの中で、ある新プロジェクトが非常にクールだとすると、その情報がネットワークを通じて会社の上層部に伝わり、経営陣はその情報を利用して進路を修正できます。そして修正の結果は再びネットワークを通じて各ユニットに伝わり、「○○プロジェクト」が今や会社のビジネス実現に貢献し始めていることを彼らに理解させます。

これはどうやって機能するのか？

1. 人に自分が興味あることを選ばせる

GitHubはまず、自分たちが会社として何が最も重要かを明確にし、それを会社の戦略に反映させる必要があります。そして各チームも同様のことを行います。「これが会社の戦略、これが私たちの製品です。では私たちのチームにとって何が最も重要ですか？」と。営業、テクニカルサポート、運用などのチームはすべてこれを行い、自チームの目標を会社の戦略目標に合わせました。前述の情報ネットワークが、この組織形態をより効率的にしています。

チームが仕事の重点を見つけたら、個人も自分の興味ポイントを見つけ、自分の興味とこれらの戦略の適合点を探り、自分自身を貢献できる重要な仕事に割り当てます。したがって、個人にとっては、会社にとって重要であり、自分も強い興味を持っていることであれば、実行することを決められます。うまく機能すれば、全員が重要な仕事に取り組み、誰かが階層的に割り当てる必要はありません。これがいわゆるオープンな仕事の割り当て方式（Open Allocation Approach）。

GitHubの例を挙げましょう。しばらく前、3Dプリンターがとても人気でした。Mike Skalnikという人物が、会社が3Dプリンターを購入した後、それに興味を持ち始めました。彼は徐々に元のプロジェクトから時間を割いて3Dプリンターをいじるようになりました。最初は、3Dプリンターがオープンソースのコードコラボレーションプラットフォームと何の関係があるのか、誰にも分かりませんでした。しかしMikeは次第に3Dプリンターを理解するようになり、後には、3Dプリントのモデルファイルを他の人と協力して共同管理できることに気づきました。そしてこれはまさにGitHubの方向性と完全に一致していました。

Mikeはその後、3Dプリントにますます多くの時間を割くようになり、最終的には3Dプリントプロジェクトのリーダーになりました。

2. 問題に最も近い人に意思決定権を与える

GitHubは、実際の問題により近い人々に意思決定権を移そうとしています。GitHubのプロジェクトには、各プロジェクトに一人の主要な責任者がいます。

あなたはこう言うでしょう。もちろん、私たちのチームにも各チームにプロダクトオーナーがいますよ、と。問題は、どのようにしてそのような人やチームが生まれるのかです。一般的な企業には、中堅・上級マネージャーがいて、自分の部下を小さなチームに分け、各チームに担当エリアを任せます。そして各エリアには、人員配置を担当するラインマネージャーがいます。そのラインマネージャーが一人を指名して言います。「あなた、そうあなたです。プロダクトオーナーとしてこの製品を担当してください」。こうしてプロダクトオーナーは操り人形のようにその製品を担当します。ここには大きな問題があります。それは、頂点にいる意思決定者が、製品や会社の方向性をみんなに示すために、比較的成功するビジョンを予測しなければならないということです。

オープンな仕事の割り当て方式では、前述のプロセスは基本的に逆になります。GitHubは、解決すべき問題に最も近い人がその問題を最もよく理解しているはずであり、そのような問題をどのように解決するかを最もよく知っている可能性が高いと考えています。GitHubはそのような人々にこの意思決定権を与えています。

3. このやり方を好む人を採用する

分かっていますが、まだ疑問視する人もいます。これは混乱そのものではないか？毎日ただ淘宝（タオバオ）でネットショッピングをしている人をどう防ぐのか？先ほど話したことに戻ると、もし誰かがこうしたことを監視するために時間と労力を費やしたり、あるいは社内政治を行ったりする必要があるなら、それは組織か個人のどちらかに問題があることを示しています。

とても重要なのは、適切な人を選び、彼らをチームに引き入れることだ。適切な人とは何か？そうした人々は、本来積極的で、技術と自分のキャリアに対して情熱を持っている人である。こうした大人たちが行うことは、最終的に必ず会社に利益をもたらす。もちろん前提はある。一般的に、「よし、私は情熱がある。今日は一日かけて同僚にパンを焼いてあげよう」と言う人はいない（祝日には例外があるかもしれない）。誰もが、自分がやっていることが何らかの形で会社を前進させるはずだと確信している。

余談

世界は本当にフラットなのか？

ある時期、業界はみな、自社の組織をフラットな組織構造にしようと悩んでいた。実際には、どこまでフラットなら「フラット」と言えるのかを悩む必要はなく、組織内の各ポイントをネットワークでつなぎ、情報が自由に流れるようにすることが重要なのである。

オープンソースの精神

オープンソースの精神とは、ある人が他の人が作った何かがとてもクールだと気づき、その人たちにメッセージを送り、自分はそれに興味を持っており、力を貢献したいと伝えることだ。次に、プロジェクトの熱量がその熱心な観客に何が重要かを教え、後者は自分がどのように貢献するかを決める。GitHubの働き方もこれであり、前述のオープンな作業割り当てである。

透明性について

組織変革を行うときに透明性について悩む人もいるが、GitHubは透明性を提唱すると同時に、チームや個人に一定のプライベートな空間も残している。チームが現在行っていることを一時的に保留し、適切なタイミングで公開したいと望むなら、そのような決定も尊重される。

GitHubのこのやり方には限界があるのか？

ある！

1. 会社はやはり、重要だが退屈な仕事にも金を払わなければならない。例えば昇進やボーナスなど。2

2. 幹部の採用は非常に難しい。一般的に会社がCEOを採用する場合、それに応じてCEOに大きな権限を与える。しかし、ネットワーク型の組織では、CEOが他の人に命令して単に実行させることは難しい。CEOは業界について深い洞察を持つべきであり、少なくとも社内では、自分が思想家であることを証明しなければならない。

3. 人を解雇するのは難しい。通常、解雇されるのは、ひどくサボっているような人物だ。しかし、このようなオープンな作業割り当てモデルでは、その人がサボっていることを証明するのにも多くの時間がかかる。ただし、従来の作業割り当てモデルと比べれば、やはり利点はある。従来のモデルでは、より多くのサボっている人が生まれるからだ。

オープンなタスク割り当ては、あなたの会社や組織で機能するだろうか？

試してみるといいだろう。
