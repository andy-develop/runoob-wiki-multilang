1.2 カスタムView

カテゴリ Android拡張チュートリアル

はじめに

カスタムViewは、文字通り名前の通りのものですが、Android開発において、多いと言うほどでもなく、百度/Google向けの開発では気持ちよく使われています。少ないとも言えず、どんなAPPも自分のアプリを美しく華麗にしたいと思っています。

概要

カスタムViewの話題を始めるにあたり、まず簡単に紹介します。先輩の小猪氏が以前の問題でも触れていましたが（View と ViewGroup の概念）、しかし、少し粗い感じがします（これは先輩が1年以上前に書いたもので、その頃私はまだ素人でした！）。

Androidが私たちに限られたコントロールを提供する一方で、拡張の手段も提供しています。コントロールを継承することで、自由に私たちのAPP（コントロール）を豊かにすることができます。つまり、カスタムにより、Androidはjsなどの言語のように、githubや掘金など多くのコミュニティで大量のオープンソースがあり、優れた作品が絶えず学ばれ模倣されるようになります。そう考えると、このカスタムView(Group)は学ばざるを得ないように見えます。 ちょっと待って、もちろんカスタムだけを追求するのは実際の開発ではあまり良くありません。特に適応の問題に直面した場合です。上の言葉と少し矛盾しますが、皆さんの見方は人それぞれだと思います（実は、このブログ主はカスタムコントロールをあまり書きません。material designで個性的なデザインを十分に実現できるからです。もちろん言うべきことは言いますが、毎週のブログは自分への区切りでもあります）。

カスタムViewの継承とコンストラクタ

何事にも始まりはあります。継承について言えば、実際にはViewのサブクラスであればViewを含めて大丈夫です。もちろん、Viewのサブクラス（TextView、ImageViewなどはすでにいくつかの属性を備えています。どう選ぶかは各自で判断してください）もあります。カスタムについては、まずコンストラクタから話しましょう。

余計な話はせず、まずコードを出します

//これを方法1と呼びましょう public MyView(Context context) { super(context); } //これを方法2と呼びましょう public MyView(Context context, AttributeSet attrs) { super(context, attrs); }

このコントロールがJavaコードでnewされる場合は、方法1を必ず実装しなければなりません。コントロールがXMLで直接使用される場合は、方法2を実装する必要があります。少なくともどちらか一方を実装します。また、場合によっては、簡単に方法1の中のsuper(context)に変更するthis(context,null)。もちろん、どのような場合にこうできるかは説明しません。次にAttributeSerというパラメータについて紹介します。

AttributeSer - カスタム属性

すべてのコントロールには属性があります。カスタムコントロールなら、カスタム属性が欠かせません！ 1. 話を進めやすくするために、まず見本に従ってres/values/ディレクトリの下に1つ追加しますattrs.xmlこのファイルです。

attrs.xml

<?xml version="1.0" encoding="utf-8"?> <resources> <!-- ここには何を書くのでしょう！、もちろん私たちのカスタム属性です --> <declare-styleable name="MyViewStyle" > <declare-styleable name="MyViewStyle" > <attr name="content" format="string" /> <attr name="isShow" format="boolean"/> <attr name="background" format="color"/> <attr name="select" > <flag name="s1" value="１"/> <flag name="s2" value="2"/> <flag name="s3" value="3"/> </attr> </declare-styleable> </resources>

サポートされているカスタム属性

  • reference: リソース参照
  • string: 文字列
  • Color: 色
  • boolean: ブール値
  • dimension: 寸法値
  • float: 浮動小数点数型
  • integer: 整数型
  • fraction: 百分率
  • enum: 列挙型
  • flag: ビットOR演算

2. これらのカスタム属性があれば、次はもちろん必要なカスタムコントロールに付け加えます。まずXMLコードに書きましょう。

<com.xlhgo.viewdemo.MyView app:content="コンテンツが王様" app:is_show="false" app:view_background="@color/colorAccent" app:select="s1" android:layout_width="wrap_content" android:layout_height="wrap_content" />

上記の2つのステップを完了すると、急いでデモを実行したくなるかもしれません。すると、何も出てこないことに気づくかもしれません。

まだ始めたばかりです。少し時間をください。次が本番です。

3. カスタム属性とコントロールがあるので、次はJavaコードでこれらのカスタム属性を取得することです。

private String mContent; private Boolean mIsShow; private int mBackground; private int mSelect; public MyView(Context context, AttributeSet attrs) { super(context, attrs); TypedArray typedArray = context.obtainStyledAttributes(attrs,R.styleable.MyViewStyle); if(typedArray != null){ //ここで注意すべきは、String型にはデフォルト値がないので、必ず定義しておくことです。そうしないとまたNullPointerExceptionの大技が出ます。 mContent = typedArray.getString(R.styleable.MyViewStyle_content); mIsShow = typedArray.getBoolean(R.styleable.MyViewStyle_is_show, true); mBackground = typedArray.getColor(R.styleable.MyViewStyle_view_background, Color.RED); mSelect = typedArray.getInt(R.styleable.MyViewStyle_select, 0); } Log.d("viewStyle","content:"+mContent); Log.d("viewStyle","isShow:"+mIsShow); Log.d("viewStyle","background:"+mBackground); Log.d("viewStyle","select:"+mSelect); }

カスタムコントロール - View - onMeasure

コントロールである以上、何はともあれ、まずその幅と高さが必要です。しかし、私たちは明らかにXMLでコントロールのlayout_widght 与 layout_height、なぜわざわざカスタムコントロールの（onMeasure）を書き直す必要があるのでしょうか。その理由は以下のとおりです。

いくつかの概念

AndroidシステムはMeasureSpecクラスを提供しており、これを介してViewを測定するのに役立ちます。MeasureSpecは32ビットのint値で、上位2ビットが測定モード、下位30ビットが測定サイズです。これってまさにバイナリですか！ そうです。しかし、ご安心ください。Googleは数学が苦手な多くの人をかなり考慮してくれています。MeasureSpecのメソッドを使用すれば、必要な数値を取得できます。

次に測定モードについて説明します。測定モードは次の3つです：

  • EXACTLY:精密モード コントロールのlayout_width属性とlayout_height属性を具体的な数値に指定した場合（wrap_contentを除く）、システムはこのモードを使用します。（なお、ViewクラスのonMeasureはデフォルトでEXACTLYモードなので、onMeasureを書き換えない限り、デフォルトモードしか使用できません。)
  • AT_MOST:最大モード コントロールのlayout_width属性またはlayout_height属性がwrap_contentの場合、コントロールのサイズは通常、子コントロールや内容の変化に応じて変化します。このとき、コントロールのサイズは親コントロールが許可する最大サイズを超えなければ問題ありません。
  • UNSPECIFIED：このモードではサイズを指定できません。Viewは好きな大きさになれます。通常はカスタムViewを描画するときに使用します。

上記のいくつかの概念をなんとなく理解したら、このメソッドを書き換え始めましょう。もしかすると急いでいるかもしれません。というのも、以前にカスタムViewについての知識がなければ、私が最初に見たときのように、やはりさっぱり分からないでしょうから。

@Override protected void onMeasure(int widthMeasureSpec, int heightMeasureSpec) { super.onMeasure(widthMeasureSpec, heightMeasureSpec); //コントロールの幅と高さを設定します。ここではデフォルトがpxであることを覚えておいてください。解像度変換で適応を実現することを忘れずに。ここでは説明しません。 setMeasuredDimension(getSize(widthMeasureSpec),getSize(heightMeasureSpec)); } private int getSize(int measureSpec){ int result = 0; int specMode = MeasureSpec.getMode(measureSpec); int specSize = MeasureSpec.getSize(measureSpec); switch (specMode){ case MeasureSpec.EXACTLY: //layout_widthとlayout_heightがmatch_parentまたは固定数値の場合は、ここに来ます result = 200; break; case MeasureSpec.AT_MOST: //layout_widthとlayout_heightがwrap_contentと定義されている場合は、ここに来ます result = Math.min(１00,specSize); break; case MeasureSpec.UNSPECIFIED: //サイズが指定されていない場合 result = 400; break; } return result; }

これで大成功です。 これで皆さんもViewのonMeasureに馴染みがあるはずですが、話はまだ終わっていません。次にlayoutメソッドについて説明しましょう。

カスタムコントロール - View - layout

layoutは、名前の通り、このコントロールが位置するレイアウトを定義するものです。実際、onMeasureによってこのコントロールの幅と高さを決定しても、すべての幅と高さが表示できるわけではありません。layoutによって、このコントロールに使用可能なスペースを割り当てる必要があります。

layoutは難しくないので、理解すれば十分です。遠慮なくコードを直接出します。

@Override public void layout(int l, int t, int r, int b) { super.layout(l, t, r, b); Log.d("layout:","l:"+l); Log.d("layout:","t:"+t); Log.d("layout:","r:"+r); Log.d("layout:","b:"+b); }

現在のコントロールの幅と高さは200pxで、出力結果は次のとおりです： l:48 t:48 r:248 b:248

layoutの使用方法を理解した後、個人的にはlayoutはカスタムViewではあまり多く使われないと思います。しかし、あえて2つだけ言及します。もし私たちがsuper.layout(l,t,r±100,b±100)その後、コントロールも割り当てられた位置に応じて変更されたり、追加されたりしますが、他のコントロールの位置には影響しません。この点はonMeasureとは大きく異なります。 デモ：MyViewコントロールの下にコントロールを追加して、その位置がどのように表示されるか見てみましょう：

カスタムコントロール - View - onDraw

準備すべきものは準備し、言うべきでないことも言いました。次は私たちのonDrawメソッドを書き換えましょう。カスタムViewである以上、つまり'派手'に見えてカスタマイズ性が高いということです。それならonDrawメソッドを使わなければなりません。

Viewの描画にはCanvasが欠かせません。そのため、onDrawメソッドを書き換えるとき、システムはCanvasオブジェクトを渡してくれます。あとは自分で作成したPaintと組み合わせて、思い通りのインターフェースを描画するだけです。余計な話はせず、コードを出します duang!

@Override protected void onDraw(Canvas canvas) { super.onDraw(canvas); Paint paint = new Paint(); canvas.drawCircle(50, 50, 50, paint); }

このようにして、簡単に円を1つ描画しました。これでカスタムViewのこの記事は終わりだと感じましたか？ 違います！ 小さな実験をしてみましょう。super.onDraw(canvas); の下にログ Log.d("myView","onDraw"); を追加し、次にこのコントロールにイベントを追加して、どうなるか見てみましょう。

findViewById(R.id.myview).setOnClickListener(new View.OnClickListener() { @Override public void onClick(View view) { view.invalidate(); //このViewをリフレッシュする } });

invalidateメソッドはViewをリフレッシュするためのものです。このコントロールをクリックすると、onDrawが繰り返し呼び出されます（クリック以外でも、このメソッドはよく呼ばれます）。同時に、実際にonDrawコード内のPaintが複数回生成されることを意味します。へへ、何か気づきましたか？次に、最後にカスタムViewの最適化について説明します。
