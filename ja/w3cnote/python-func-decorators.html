Python 関数デコレータ

カテゴリ プログラミング技術

デコレータ(Decorators)は Python の重要な一部です。簡単に言うと、他の関数の機能を変更する関数です。コードをより短く、より Pythonic( Python らしく)にしてくれます。多くの初心者はどこで使えばよいか分かりません。そこで、デコレータがコードをより簡潔にできる領域を共有しようと思います。まず、独自のデコレータの書き方について説明しましょう。

これはおそらく最も習得が難しい概念の一つです。完全に理解できるように、一度にひとつのステップずつ説明します。

すべてがオブジェクト

まず Python における関数を理解しましょう。

def hi(name="yasoob"): return "hi " + name print(hi()) # output: 'hi yasoob' # 関数を変数に代入することもできます。たとえば greet = hi # ここでは括弧を使っていません。hi関数を呼び出しているのではなく # greet変数に格納しているだけです。これを実行してみましょう。 print(greet()) # output: 'hi yasoob' # 古いhi関数を削除すると、何が起こるか見てみましょう！ del hi print(hi()) #outputs: NameError print(greet()) #outputs: 'hi yasoob'

関数の中で関数を定義する

以上が関数の基本知識です。知識をさらに一歩進めましょう。Python では関数の中に別の関数を定義できます：

def hi(name="yasoob"): print("now you are inside the hi() function") def greet(): return "now you are in the greet() function" def welcome(): return "now you are in the welcome() function" print(greet()) print(welcome()) print("now you are back in the hi() function") hi() #output:now you are inside the hi() function # now you are in the greet() function # now you are in the welcome() function # now you are back in the hi() function # 上記は、いつでもhi()を呼び出すと、greet()とwelcome()が同時に呼び出されることを示しています。 # そして、greet()とwelcome()関数はhi()関数の外からはアクセスできません。たとえば： greet() #outputs: NameError: name 'greet' is not defined

これで、関数の中に別の関数を定義できることが分かりました。つまり、ネストされた関数を作成できるのです。次に学ぶ必要があるのは、関数も関数を返すことができるということです。

関数から関数を返す

実際には、ある関数の中で別の関数を実行する必要はなく、出力として返すこともできます：

def hi(name="yasoob"): def greet(): return "now you are in the greet() function" def welcome(): return "now you are in the welcome() function" if name == "yasoob": return greet else: return welcome a = hi() print(a) #outputs: <function greet at 0x7f2143c01500> # 上記は、`a`がhi()関数内のgreet()関数を指すようになったことを明確に示しています。 # これを試してみてください print(a()) #outputs: now you are in the greet() function

もう一度このコードを見てみましょう。if/else文ではgreet()やwelcome()ではなく、greetとwelcomeを返しています。なぜでしょうか？これは、後ろに括弧を付けると関数が実行されるからです。しかし、括弧を付けなければ、関数は実行されずにどこへでも渡したり、他の変数に代入したりできます。分かりましたか？もう少し詳しく説明します。

  • 私たちが次のように書くとa = hi()，hi()が実行され、name 引数のデフォルトが yasoob であるため、関数greet()が返されます。

  • さらに、次のものを出力することもできます。hi()()、これにより次のように出力されます：now you are in the greet() function。

  • もし文を次のように変更するとa = hi(name = "ali")、その場合welcome()関数が返されます。

関数を別の関数の引数として渡す

def hi(): return "hi yasoob!" def doSomethingBeforeHi(func): print("I am doing some boring work before executing hi()") print(func()) doSomethingBeforeHi(hi) #outputs:I am doing some boring work before executing hi() # hi yasoob!

これで、デコレータが実際に何であるかをさらに学ぶために必要な知識がすべて揃いました。デコレータを使うと、関数の前後でコードを実行できます。

あなたの最初のデコレータ

前の例で、実際にはすでにデコレータを作成していました！次に、前のデコレータを修正して、もう少し役立つプログラムを作成しましょう：

def a_new_decorator(a_func): def wrapTheFunction(): print("I am doing some boring work before executing a_func()") a_func() print("I am doing some boring work after executing a_func()") return wrapTheFunction def a_function_requiring_decoration(): print("I am the function which needs some decoration to remove my foul smell") a_function_requiring_decoration() #outputs: "I am the function which needs some decoration to remove my foul smell" a_function_requiring_decoration = a_new_decorator(a_function_requiring_decoration) #now a_function_requiring_decoration is wrapped by wrapTheFunction() a_function_requiring_decoration() #outputs:I am doing some boring work before executing a_func() # I am the function which needs some decoration to remove my foul smell # I am doing some boring work after executing a_func()

分かりましたか？私たちは今学んだ原理を適用しました。これこそがPythonのデコレータが行うことです！デコレータは関数をラップし、何らかの方法でその動作を変更します。さて、私たちはコードの中で特定の記号を使っていないことに疑問を感じているかもしれません。@その記号？それは、デコレートされた関数を生成するための短い方法です。ここで、私たちがどのように@それを使って前のコードを実行するかを示します：

@a_new_decorator def a_function_requiring_decoration(): """Hey you! Decorate me!""" print("I am the function which needs some decoration to " "remove my foul smell") a_function_requiring_decoration() #outputs: I am doing some boring work before executing a_func() # I am the function which needs some decoration to remove my foul smell # I am doing some boring work after executing a_func() #the @a_new_decorator is just a short way of saying: a_function_requiring_decoration = a_new_decorator(a_function_requiring_decoration)

これで Python デコレータの動作原理について基本的な理解が得られたことを願います。次のコードを実行すると、ひとつの問題が発生します：

print(a_function_requiring_decoration.__name__)
# Output: wrapTheFunction

これは私たちが望んでいるものではありません！出力(Ouput)は"a_function_requiring_decoration"であるべきです。ここでの関数はwarpTheFunctionに置き換えられています。それは私たちの関数の名前とドキュメント文字列(docstring)を書き換えてしまいます。幸いなことに、Python にはこの問題を解決する簡単な関数が用意されており、それはfunctools.wrapsです。前の例を修正して functools.wraps を使いましょう：

from functools import wraps def a_new_decorator(a_func): @wraps(a_func) def wrapTheFunction(): print("I am doing some boring work before executing a_func()") a_func() print("I am doing some boring work after executing a_func()") return wrapTheFunction @a_new_decorator def a_function_requiring_decoration(): """Hey yo! Decorate me!""" print("I am the function which needs some decoration to " "remove my foul smell") print(a_function_requiring_decoration.__name__) # Output: a_function_requiring_decoration

これでずっと良くなりました。次に、デコレータの一般的な使用シーンを学びましょう。

ブループリントの基本形：

from functools import wraps def decorator_name(f): @wraps(f) def decorated(*args, **kwargs): if not can_run: return "Function will not run" return f(*args, **kwargs) return decorated @decorator_name def func(): return("Function is running") can_run = True print(func()) # Output: Function is running can_run = False print(func()) # Output: Function will not run

注意：@wraps装飾する関数を受け取り、関数名、ドキュメント文字列、引数リストなどをコピーする機能を追加します。これにより、デコレータ内部で装飾前の関数の属性にアクセスできます。

使用シーン

ここでは、デコレータが特に優れている点と、それを使うことでいくつかのことをより簡単に管理できるようになる点を見てみましょう。

認可(Authorization)

デコレータは、誰かがWebアプリケーションのエンドポイントを使用する権限を持っているかを確認するのに役立ちます。Flask や Django の Web フレームワークで広く使われています。以下は、デコレータベースの認可を使用する例です：

from functools import wraps def requires_auth(f): @wraps(f) def decorated(*args, **kwargs): auth = request.authorization if not auth or not check_auth(auth.username, auth.password): authenticate() return f(*args, **kwargs) return decorated

ログ(Logging)

ログはデコレータが活躍するもうひとつの場面です。次に例を示します：

from functools import wraps def logit(func): @wraps(func) def with_logging(*args, **kwargs): print(func.__name__ + " was called") return func(*args, **kwargs) return with_logging @logit def addition_func(x): """Do some math.""" return x + x result = addition_func(4) # Output: addition_func was called

あなたはすでにデコレータの別の賢い使い方を考えているに違いありません。

引数を持つデコレータ

この問題を考えてみましょう。@wraps もデコレータではありませんか？しかし、@wraps は通常の関数ができるように、ひとつの引数を受け取ります。では、なぜ私たちも同じようにしないのでしょうか？それは、@my_decorator 構文を使用するとき、単一の関数を引数として受け取るラッパー関数を適用しているからです。Python ではすべてのものがオブジェクトであり、関数も含まれることを覚えておいてください。これを踏まえて、ラッパー関数を返す関数を作成できます。

関数内にデコレータを埋め込む

ログの例に戻り、出力先のログファイルを指定できるラッパー関数を作成しましょう。

from functools import wraps def logit(logfile='out.log'): def logging_decorator(func): @wraps(func) def wrapped_function(*args, **kwargs): log_string = func.__name__ + " was called" print(log_string) # logfileを開いて、内容を書き込みます with open(logfile, 'a') as opened_file: # 指定されたlogfileにログを書き込みます opened_file.write(log_string + '\n') return func(*args, **kwargs) return wrapped_function return logging_decorator @logit() def myfunc1(): pass myfunc1() # Output: myfunc1 was called # これで out.log というファイルが作成され、その中身は上記の文字列になります @logit(logfile='func2.log') def myfunc2(): pass myfunc2() # Output: myfunc2 was called # これで func2.log というファイルが作成され、その中身は上記の文字列になります

デコレータクラス

これで、本番環境で使用できる logit デコレータができました。しかし、アプリケーションの一部がまだ脆弱な場合、例外はより緊急な対応が必要になることがあります。たとえば、単にログをファイルに書き出したいだけのこともあれば、注意を引く問題をメールで送信しつつ、ログも残しておきたいこともあります。これは継承を使用する場面ですが、これまでにデコレータを構築するために使用する関数しか見てきませんでした。

幸いなことに、クラスを使用してデコレータを構築することもできます。では、関数ではなくクラスとして logit を再構築しましょう。

from functools import wraps class logit(object): def __init__(self, logfile='out.log'): self.logfile = logfile def __call__(self, func): @wraps(func) def wrapped_function(*args, **kwargs): log_string = func.__name__ + " was called" print(log_string) # logfileを開いて書き込みます with open(self.logfile, 'a') as opened_file: # 指定されたファイルにログを書き込みます opened_file.write(log_string + '\n') # 次に、通知を送信します self.notify() return func(*args, **kwargs) return wrapped_function def notify(self): # logitはログを取るだけで、他には何もしません pass

この実装には、ネストされた関数を使用する方法よりもすっきりしているという利点があります。また、関数をラップする際は以前と同じ構文を使用します：

@logit()
def myfunc1():
    pass

次に、logit のサブクラスを作成して、メールの機能を追加します（ただし、メールの話題はここでは扱いません）。

class email_logit(logit): '''関数呼び出し時に管理者へメールを送信できる logit の実装バージョン''' def __init__(self, email='admin@myproject.com', *args, **kwargs): self.email = email super(email_logit, self).__init__(*args, **kwargs) def notify(self): # self.emailにメールを送信します # ここでは実装しません pass

今後、@email_logit は @logit と同じ効果に加えて、ログに加えて管理者にメールも送信します。

    Pythonデコレータについて説明する前に、少し下品ですがデコレータというテーマに非常にぴったりな例を挙げたいと思います。

    誰もが身につけている下着の主な機能は恥部を隠すことですが、冬になると風や寒さを防ぐことはできません。どうすればいいでしょうか？私たちが考えた方法の一つは、下着を改造して、より厚く、より長くすることです。そうすれば、恥部を隠す機能だけでなく、保温も提供できます。ただし問題があります。この下着を長ズボンに改造した後も、恥部を隠す機能はありますが、本質的にはもはや本物の下着ではありません。そこで賢い人々は長ズボンを発明し、下着に影響を与えないまま、直接下着の外に長ズボンを穿きました。こうして下着はやはり下着のままであり、長ズボンがあれば赤ちゃんももう寒くありません。デコレータはここで言う長ズボンのようなもので、下着の役割に影響を与えないまま、私たちの体に防寒効果を提供します。

    デコレータについて語る前に、まず一つ理解しておく必要があります。Python の関数は Java や C++ とは少し異なり、Python の関数は普通の変数のように別の関数へパラメータとして渡すことができます。例えば：

    def foo():
    print("foo")

def bar(func):
    func()

bar(foo)

    正式にテーマに戻ります。デコレータは本質的に Python の関数またはクラスであり、他の関数やクラスがコードを一切変更することなく追加機能を実現できるようにします。デコレータの戻り値も関数/クラスオブジェクトです。デコレータはアスペクト指向のニーズがある場面でよく使われます。例えば、ログ挿入、パフォーマンステスト、トランザクション処理、キャッシュ、権限検証などの場面です。デコレータはこの種の問題を解決する絶好の設計です。デコレータがあれば、関数の機能自体とは無関係な大量の類似コードをデコレータに抽出して再利用し続けることができます。概括すると、デコレータの役割は既存のオブジェクトに追加機能を加えることです。

    まず簡単な例を見てみましょう。実際のコードはこれよりずっと複雑かもしれませんが。

    def foo():
    print('i am foo')

    ここで新しい要件があります。関数の実行ログを記録したい。そこでコードにログコードを追加します：

    def foo():
    print('i am foo')
    logging.info("foo is running")

    関数 bar()、bar2() にも同様の要件がある場合はどうすればいいでしょうか？bar 関数の中にまた logging を書くのでしょうか？それだと大量の類似コードが発生します。重複コードを減らすために、次のように新しい関数を定義することができます：ログ処理を専門に行い、ログ処理が完了した後に実際の業務コードを実行する関数です。

    def use_logging(func):
    logging.warn("%s is running" % func.__name__)
    func()

def foo():
    print('i am foo')

use_logging(foo)

    このやり方は論理的には問題なく、機能も実現されています。しかし、呼び出し時に実際の業務ロジックである foo 関数を呼び出すのではなく、use_logging 関数に置き換えてしまうため、既存のコード構造を壊してしまいます。毎回元の foo 関数をパラメータとして use_logging 関数に渡さなければならなくなります。もっと良い方法はないでしょうか？もちろんあります。その答えがデコレータです。

    簡単なデコレータ

    def use_logging(func):

    def wrapper():
        logging.warn("%s is running" % func.__name__)
        return func()   # 把 foo 当做参数传递进来时，执行func()就相当于执行foo()
    return wrapper

def foo():
    print('i am foo')

foo = use_logging(foo)  # 因为装饰器 use_logging(foo) 返回的时函数对象 wrapper，这条语句相当于  foo = wrapper
foo()                   # 执行foo()就相当于执行 wrapper()

    use_logging はデコレータであり、普通の関数です。実際の業務ロジックを実行する関数 func をその中に包み込みます。foo が use_logging に装飾されているように見えます。use_logging が返すのも関数で、その関数の名前は wrapper です。この例では、関数に入るときと出るときが横断的関心事と呼ばれ、このようなプログラミング方式はアスペクト指向プログラミングと呼ばれます。

    @ シンタックスシュガー

    Python にしばらく触れたことがあるなら、@ 記号に馴染みがないことはないでしょう。その通り、@ 記号はデコレータのシンタックスシュガーです。これは関数定義の先頭に置きます。そうすることで、最後の再代入操作を省略できます。

    def use_logging(func):

    def wrapper():
        logging.warn("%s is running" % func.__name__)
        return func()
    return wrapper

@use_logging
def foo():
    print("i am foo")

foo()

    上記のように、@ があれば foo = use_logging(foo) という一文を省けます。直接 foo() を呼び出すだけで望む結果が得られます。おわかりですか。foo() 関数は何も変更する必要がなく、定義箇所にデコレータを追加するだけです。呼び出し時は以前と同様です。他にも似たような関数があれば、デコレータを呼び出して関数を修飾し続けられます。関数を繰り返し変更したり、新しいラッパーを追加したりする必要はありません。こうしてプログラムの再利用性を高め、可読性も向上させました。

    デコレータが Python でこれほど便利に使えるのは、Python の関数が普通のオブジェクトのように他の関数へパラメータとして渡せること、他の変数に代入できること、戻り値にできること、別の関数内に定義できることに起因しています。

    *args、**kwargs

    もしかしたら、業務ロジック関数 foo がパラメータを必要とする場合はどうするのかと聞く人もいるかもしれません。例えば：

    def foo(name):
    print("i am %s" % name)

    wrapper 関数を定義するときにパラメータを指定できます：

    def wrapper(name):
        logging.warn("%s is running" % func.__name__)
        return func(name)
    return wrapper

    こうすることで、foo 関数で定義されたパラメータを wrapper 関数内に定義できます。ここでまた、「foo 関数が2つのパラメータを受け取る場合は？3つの場合は？さらに多くのパラメータを渡すかもしれない場合は？」と聞く人がいるでしょう。デコレータが foo のパラメータ数を把握できない場合、*args を使って対応できます：

    def wrapper(*args):
        logging.warn("%s is running" % func.__name__)
        return func(*args)
    return wrapper

    こうすれば、foo がいくつのパラメータを定義していても、すべて完全に func に渡すことができます。これで foo の業務ロジックに影響しません。ここでさらに、「foo 関数がキーワード引数も定義している場合はどうなるのか？」と疑問に思う読者もいるでしょう。例えば：

    def foo(name, age=None, height=None):
    print("I am %s, age %s, height %s" % (name, age, height))

    その場合は、wrapper 関数でキーワード引数を指定すればよいです：

    def wrapper(*args, **kwargs):
        # args是一个数组，kwargs一个字典
        logging.warn("%s is running" % func.__name__)
        return func(*args, **kwargs)
    return wrapper

    パラメータ付きデコレータ

    デコレータにはさらに大きな柔軟性があります。例えばパラメータ付きデコレータです。上記のデコレータ呼び出しでは、デコレータが受け取る唯一のパラメータは業務を実行する関数 foo です。デコレータの構文では、呼び出し時に他のパラメータを指定することもできます。例えば @decorator(a) のようにです。これにより、デコレータの作成と使用においてより大きな柔軟性が得られます。例えば、デコレータ内でログレベルを指定できます。なぜなら、業務関数によって必要なログレベルが異なる場合があるからです。

    def use_logging(level):
    def decorator(func):
        def wrapper(*args, **kwargs):
            if level == "warn":
                logging.warn("%s is running" % func.__name__)
            elif level == "info":
                logging.info("%s is running" % func.__name__)
            return func(*args)
        return wrapper

    return decorator

@use_logging(level="warn")
def foo(name='foo'):
    print("i am %s" % name)

foo()

    上記の use_logging はパラメータを許可するデコレータです。これは実際には元のデコレータに対する関数ラッパーであり、デコレータを返します。これはパラメータを含むクロージャと理解できます。@use_logging(level="warn") のように呼び出すと、Python はこのラッパー層を検出し、パラメータをデコレータの環境に渡します。

    @use_logging(level="warn")以下と等価です@decorator

    クラスデコレータ

    その通り、デコレータは関数だけでなくクラスにもできます。関数デコレータと比較すると、クラスデコレータは柔軟性が高く、高凝集性、カプセル化などの利点があります。クラスデコレータを使用する際は主にクラスの __call__ メソッドに依存します。@ 形式でデコレータを関数に付加すると、このメソッドが呼び出されます。

    class Foo(object):
    def __init__(self, func):
        self._func = func

    def __call__(self):
        print ('class decorator runing')
        self._func()
        print ('class decorator ending')

@Foo
def bar():
    print ('bar')

bar()
functools.wraps

    デコレータを使用するとコードを大幅に再利用できますが、欠点として元の関数のメタ情報が失われてしまうことがあります。例えば関数の docstring、__name__、パラメータリストなどです。まず例を見てみましょう：

    # 装饰器
def logged(func):
    def with_logging(*args, **kwargs):
        print func.__name__      # 输出 'with_logging'
        print func.__doc__       # 输出 None
        return func(*args, **kwargs)
    return with_logging

# 函数

    再論@wraps(func)デコレータの実装原理。

    上の投稿を訂正します。@DragonZ説明されている基本的なコードフレームワークは、おそらく以下のとおりです：

    def Wraps(fWrap):
    def TmpWraps(func):
        def WrapsDecorator(*args, **kwargs):
            return func(*args, **kwargs)
            WrapsDecorator.__name__=fWrap.__name__
            WrapsDecorator.__doc__=fWrap.__doc__
        return WrapsDecorator
    return TmpWraps

    さらに、そのデコレータは __name__ や __doc__ の関数メタ情報だけでなく、さらに多くの情報もコピーします。正しい実装コードは以下のとおりです：

    def mywraps(fwrap):
    def TmpWraps(func):
        def dec(**args):
            return func(**args)
        meta_info=['__module__', '__name__', '__qualname__', '__doc__', '__annotations__']
        for meta in meta_info:
            setattr(dec,meta,getattr(fwrap,meta))
        #逐个获取fwrap函数的元信息，并复制到dec函数上
        return dec
    return TmpWraps

    さらに、クラスデコレータに関しては、次のように説明すると初心者にとってより親切かもしれません：

    デコレータはクラスによっても実装できます。実際には主にクラスの以下の特徴を利用して、間接的に関数デコレータ機能を実装しています：

    関数呼び出し構文 f() はクラスのインスタンス化と同等です。つまり、クラスの __init__ 関数を呼び出してオブジェクトを作成することです。

    オブジェクトの呼び出し obj() は、オブジェクトの __call__ マジックメソッドを実行することと同等です。

    クラスでデコレータを実装すると、関数デコレータの2層を超えるネストを回避できます。3層ある場合、最外部の関数はクラスの __init__ 関数を呼び出しているとみなせるからです。これによりコードが読みやすく保守しやすくなります。

    本質的には、クラスの __init__ と __call__ マジックメソッドを実装し、__init__ 関数内でデコレータのパラメータを受け取り、__call__ 関数内で具体的なデコレータ構造を実装するだけでよいです。

    以下に例を示します。クラスを使ってパラメータ付きデコレータを実装します。違いを観察してみてください。

    from functools import wraps 
#定义一个装饰器名称的类
class  with_para_decorator: 
    #在类的__init__函数内接受装饰器参数，并赋值给类的实例参数，这样可以让其他函数随时使用
    #当然，如果装饰器没有参数，此处不转a,b即可，相当于类无参实例化
    def __init__(self,a,b):    
        self.a=a
        self.b=b
    #在类的__call__函数内接受被装饰函数，并具体定义装饰器
    def __call__(self,func):   
    @wraps(func)   
    def wrap_function(arg1,arg2):  
        print('装饰带参数的函数，函数传的参数为：{0}, {1}'.format(arg1,arg2))
        print('带参数的装饰器，装饰器传的参数为：{0}, {1}'.format(self.a,self.b))
        return func(arg1,arg2)   
    return wrap_function
#使用装饰器
@with_para_decorator(1,2)  
def need_decorate(a,b):   
pass
need_decorate(4,5)

    上記コードの具体的な原理の解析は以下のとおりです：

    • @with_para_decorator(1,2) は、クラス名であるため、(1,2) パラメータを使ってこのクラスのインスタンスオブジェクトを作成して返すことに相当します。例えば obj とします。
    • このとき、構文は @obj になり、need_decorate=obj(need_decorate) に相当します。このとき obj.__call__ マジックメソッドが呼び出され、そのマジックメソッド内で具体的にデコレータ機能を実装しています。
    • わかるように、その本質的な動作原理は関数デコレータと変わりません。3層の関数ネストを、__init__ 関数と __call__ 関数による2層のネストに変えただけです。
    • 比較すると、クラスデコレータの方がコードがより直感的であることがわかります。
