Application()

appオブジェクトは通常、Express アプリケーションを表します。Express モジュールからエクスポートされたトップレベルのexpress()メソッドを呼び出して作成します：

var express = require('express');
var app = express();

app.get('/', function(req, res) {
    res.send('hello world!');
});

app.listen(3000);

app オブジェクトには以下のメソッドがあります：

  • HTTP リクエストをルーティングします。詳細はapp.METHOD和app.paramこれらの2つの例を参照してください。
  • ミドルウェアを構成します。詳細はapp.route。
  • HTML ビューをレンダリングします。詳細はapp.render。
  • テンプレートエンジンを登録します。詳細はapp.engine。

また、アプリケーションの動作を変更できるプロパティ設定もいくつかあります。詳細については、[関連資料] を参照してください。Application settings。

Properties

app.locals

app.locals オブジェクトは JavaScript オブジェクトであり、そのプロパティはアプリケーションのローカル変数です。

app.locals.title
// => 'My App'
app.locals.email
// => 'me@myapp.com'

一度設定すると、app.localsの各プロパティ値はアプリケーションのライフサイクル全体にわたって有効です。これに対して、res.localsは、このリクエストのライフサイクル内でのみ有効です。

アプリケーション内では、テンプレートをレンダリングするときにこれらのローカル変数を使用できます。これらは非常に便利で、テンプレートに役立つメソッドや、appレベルのデータを提供できます。req.app.locals（詳細はreq.app）を参照してください。Locals はミドルウェアで使用できます。

app.locals.title = 'My App';
app.locals.strftime = require('strftime');
app.locals.email = 'me@myapp.com';

app.mountpath

app.mountpathプロパティは、サブアプリケーションがマウントされるパスパターンです。

サブアプリケーションはexpressのインスタンスであり、リクエストを処理するためのルートハンドラとして使用できます。

var express = require('express');
var app = express(); // the main app
var admin = express(); // the sub app
admin.get('/', function(req, res) {
    console.log(admin.mountpath); // /admin
    res.send('Admin Homepage');
});
app.use('/admin', admin); // mount the sub app

これは req オブジェクトのreq.baseUrl）プロパティに似ています。ただし、req.baseUrl はマッチした URL パスであり、マッチしたパターンではない点が異なります。サブアプリケーションが複数のパスパターンにマウントされている場合、app.mountpath はマウントパスパターンのリストになります。次の例のようになります。

var admin = express();

admin.get('/', function (req, res) {
  console.log(admin.mountpath); // [ '/adm*n', '/manager' ]
  res.send('Admin Homepage');
});

var secret = express();
secret.get('/', function (req, res) {
  console.log(secret.mountpath); // /secr*t
  res.send('Admin Secret');
});

admin.use('/secr*t', secret); // load the 'secret' router on '/secr*t', on the 'admin' sub app
app.use(['/adm*n', '/manager'], admin); // load the 'admin' router on '/adm*n' and '/manager', on the parent app

Events

app.on('mount', callback(parent))

サブアプリケーションが親アプリケーションにマウントされると、mount イベントが発行されます。親アプリケーションのオブジェクトが引数としてコールバックメソッドに渡されます。

var admin = express();
admin.on('mount', function(parent) {
    console.log('Admin Mounted');
    console.log(parent); // refers to the parent app
});
admin.get('/', function(req, res) {
    res.send('Admin Homepage');
});
app.use('/admin', admin);

app.all(path, callback[, callback ...]

app.allメソッドは標準のapp.METHOD()メソッドに似ていますが、すべての HTTP 動詞にマッチする点が異なります。 特定のプレフィックスにグローバルなロジック処理をマッピングしたり、無条件にマッチさせたりするのに非常に有効です。例えば、以下の内容を他のすべてのルート定義の前に置くと、この時点以降のすべてのルートで認証が必要になり、ユーザーが自動的にロードされます。これらのコールバックは必ずしも終端ではないことに注意してください:loadUserタスクを完了した後に、next()メソッドを呼び出して、後続のルートのマッチングを続行できます。

app.all('*', requireAuthentication, loadUser);

または、これと同等の形式です:

app.all('*', requireAuthentication);
app.all('*', loadUser);

もう1つの例は、グローバルなホワイトリスト方式です。この例は前のものと非常に似ていますが、単に/apiで始まるパスのみに制限しています。

app.all('/api/*', requireAuthentication);

app.engine(ext, callback)

指定されたエンジンのコールバックを登録して、ext ファイルのレンダリングを処理します。 デフォルトでは、Express はrequire()を使用して、ファイル拡張子に基づくエンジンをロードする必要があります。例えば、foo.jadeファイルをレンダリングしようとすると、Express は内部的に以下の内容を呼び出し、同時にrequire()結果をキャッシュして後続の呼び出しに備え、パフォーマンスを向上させます。

以下の方法は、すぐに使える.__expressメソッドを提供していないテンプレートや、別のテンプレートエンジン拡張子を使用したい場合に使用します。 例えば、EJS テンプレートエンジンを使用して.htmlファイルをレンダリングします：

var engines = require('consolidate');
app.engine('haml', engines.haml);
app.engine('html', engines.hogan);

app.param([name], callback)

ルートパラメータにコールバックトリガーを追加します。ここでのnameはパラメータ名またはパラメータの配列です。functionはコールバックメソッドです。コールバックメソッドの引数は順に、リクエストオブジェクト，レスポンスオブジェクト，次のミドルウェア，パラメータ値和パラメータ名です。nameが配列の場合、各パラメータが配列内で宣言された順序に従ってコールバックトリガーが登録されます。また、最後のパラメータ以外のパラメータについては、それらのコールバック内でnext()次の宣言されたパラメータのコールバックを呼び出します。最後のパラメータの場合、コールバック内で呼び出します。next()現在処理中のルートにある次のミドルウェアを呼び出します。もしname単なるstringそれと同じです（つまり、パラメータが1つだけの場合、それは最後のパラメータであり、配列の最後のパラメータと同じです）。:userルートパスに出現する場合、ユーザーの読み込み処理をマッピングして自動的に提供できます。req.userこのルートに提供したり、入力パラメータを検証したりします。

app.param('user', function(req, res, next, id) {
    User.find(id, function(error, user) {
        if (err) {
            next(err);
        }
        else if (user){
            req.user = user;
        } else {
            next(new Error('failed to load user'));
        }
    });
});

についてParamのコールバックで定義されたルートについては、それらはローカルです。マウントされたappやルートには継承されません。したがって、app上のParamコールバックは、app上のルートがこのルートパラメータを持っている場合にのみ機能します。

res.sendStatus(500); // equivalent to res.status(500).send('Internal Server Error')

サポートされていないステータスが指定された場合、このHTTPステータスは依然としてstatusCodeに設定され、このコードの文字列がBodyとして使用されます。

res.sendStatus(2000); // equivalent to res.status(2000).send('2000');

More about HTTP Status Codes

res.set(field [, value])

レスポンスオブジェクトのHTTPヘッダーを設定します。field为value複数の値を一度に設定するには、オブジェクトをパラメータとして渡すことができます。

res.set('Content-Type', 'text/plain');
res.set({
    'Content-Type':'text/plain',
    'Content-Length':'123',
    'ETag':'123456'
})

これはres.header(field [,value])と同じ効果です。

res.status(code)

このメソッドを使用して、レスポンスオブジェクトのHTTPステータスを設定します。これはNodeのresponse.statusCodeの一貫性のあるエイリアスです。

res.status(403).end();
res.status(400).send('Bad Request');
res.status(404).sendFile('/absolute/path/to/404.png');

res.type(type)

プログラムはContent-TypeHTTPヘッダーのMIMEタイプを設定します。もしこの設定されたtypeがmime.lookup正しいものに解析できるContent-Type。もしtypeに/文字が含まれている場合、プログラムは直接Content-Type为type。

res.type('.html');              // => 'text/html'
res.type('html');               // => 'text/html'
res.type('json');               // => 'application/json'
res.type('application/json');   // => 'application/json'
res.type('png');                // => image/png:

res.vary(field)

Varyレスポンスヘッダーがない場合は、Varyレスポンスヘッダーを追加します。

追記：varyの意味は、プロキシサーバー/キャッシュ/CDNに対して、リクエストが同じかどうかを判断する方法を伝えることです。vary内の組み合わせが、サーバー/キャッシュ/CDNが判断する際の基準になります。たとえば、VaryにUser-Agentがある場合、同じリクエストであっても、ユーザーがIEでページを開き、その後Firefoxで同じページを開いた場合、CDN/プロキシは異なるページと見なします。VaryにUser-Agentがない場合、CDN/プロキシは同じページと見なし、キャッシュされたページを直接ユーザーに返し、Webサーバーにそのページを再度リクエストしません。簡単に言うと、fieldキャッシュのkeyとして、キャッシュにヒットするかどうかを判断するために使用されます

res.vary('User-Agent').render('docs');

Router

1つのrouterオブジェクトは、ミドルウェアとルーティングに関する独立したインスタンスです。これは「mini-application」（ミニアプリケーション）と考えることができ、ミドルウェアとルートメソッドを操作する機能を持ちます。各Expressプログラムには組み込みのappルートがあります。app.use()メソッドのパラメータとして、または別のルートのuse()パラメータとして使用できます。expressオブジェクトにはRouter()メソッドがあり、Router()を使用して新しいrouterオブジェクトを作成できます。

res.vary('User-Agent').render('docs');

Router([options])

次のように、ルートを作成できます：

var router = express.Router([options]);

optionsパラメータはルートの動作を指定でき、次の選択肢があります：

プロパティ 説明 デフォルト値 利用可能性
caseSensitive 大文字と小文字を区別するかどうか デフォルトでは無効です。/Foo和/fooと同じように扱います。
mergeParams 親ルートのres.paramsを保存します。親ルートのパラメータと子ルートのパラメータが競合する場合、子ルートのパラメータが優先されます。 false 4.5.0+
strict 厳密ルーティングを有効にします。 デフォルトでは無効で、/foo和/foo/ルートと同じように扱われます  

あなたはrouterをプログラムとして扱い、その上にミドルウェアやHTTPルートメソッドを追加できます（例：get，put，postなど）。

// invoked for any requests passed to this router
router.use(function(req, res, next) {
  // .. some logic here .. like any other middleware
  next();
});
// will handle any request that ends in /events
// depends on where the router is "use()'d"
router.get('/events', function(req, res, next) {
  // ..
});

特別なルートURLにルートをマウントできます。これにより、各ルートを別々のファイルや、さらにミニプログラムに配置することができます。

// only requests to /calendar/* will be sent to our "router"
app.use('/calendar', router);

Methods

router.all(path, [callback, ...] callback)

このメソッドはrouter.METHOD()メソッドと同じですが、このメソッドはすべてのHTTPアクションにマッチする点が異なります。

このメソッドは、グローバルなロジック処理を特別なパスプレフィックスや任意のマッチングにマッピングしたい場合に非常に便利です。たとえば、次に示すルートを他のルートの前に置くと、そのポイント以降のすべてのルートで検証操作とユーザー情報の自動読み込みが要求されます。これらのグローバルなロジック操作は、リクエスト/レスポンスサイクルを終了する必要がないことに注意してください：loaduserタスクを実行してから、next()を呼び出して、実行フローを後続のルートに引き渡すことができます。

router.all('*', requireAuthentication, loadUser);

同等の形式:

router.all('*', requireAuthentication)
router.all('*', loadUser);

これはホワイトリストのグローバル機能の例です。この例は前のものとよく似ていますが、/apiで始まるパスのみに作用します:

router.all('/api/*', requireAuthentication);

router.METHOD(path, [callback, ...] callback)

router.METHOD()メソッドは、ルートメソッドをExpress内で提供します。ここでのMETHODはHTTPメソッドの1つで、たとえばGET，PUT，POSTなどです。ただし、router内のMETHODは小文字です。したがって、実際のメソッドはrouter.get()，router.put()，router.post()などです。

複数のコールバック関数を提供できます。それらはミドルウェアと同じように動作しますが、これらのコールバックはnext('router')を呼び出して残りのルートコールバックをバイパスできる点が異なります。このメカニズムを使用して、ルートにいくつかの前提条件を設定できます。リクエストが現在のルートの処理条件を満たしていない場合は、後続のルートに制御を渡します。

以下の断片は、最も簡単なルート定義を示しています。Expressはpath文字列を正規表現に変換し、受信リクエストを内部的にマッチングします。マッチングの際には、Query stringsは考慮されません。たとえば、"GET /"は以下のルートにマッチし、"GET /?name=tobi"も同様です。

router.get('/', function(req, res) {
    res.send('Hello World');
});

マッチングするpathに特別な制限がある場合は、正規表現を使用できます。たとえば、次は"GET /commits/71dbb9c"と"GET /commits/71bb92..4c084f9"にマッチします。

router.get(/^\/commits\/(\w+)(?:\.\.(\w+))?$/, function(req, res) {
    var from = req.params[0];
    var to = req.params[1];
    res.send('commit range ' + from + '..' + to);
});

router.param(name, callback)

ルートパラメータにコールバックトリガーを追加します。ここでのnameはパラメータ名、functionはコールバックメソッドです。コールバックメソッドのパラメータは、順にリクエストオブジェクト、レスポンスオブジェクト、次のミドルウェア、パラメータ値、パラメータ名です。nameは技術的にはオプションですが、Express V4.11.0以降のバージョンでは推奨されません（下記参照）。

とは異なり、app.param()，router.param()はルートパラメータとして配列を受け入れません。

たとえば、:userがルートパスに現れる場合、ユーザー読み込みのロジック処理をマッピングして、このルートにreq.userを自動的に提供したり、入力パラメータを検証したりできます。

router.param('user', function(req, res, next, id) {
    User.find(id, function(error, user) {
        if (err) {
            next(err);
        }
        else if (user){
            req.user = user;
        } else {
            next(new Error('failed to load user'));
        }
    });
});

に関しては、Paramのコールバックで定義されたルートはローカルです。それらはマウントされたappやルートには継承されません。したがって、router上で定義されたparamコールバックは、それがrouter上のルートがこのルートパラメータを持っている場合にのみ有効です。

が定義されたparamルート上では、paramコールバックはすべて最初に呼び出されます。それらはリクエスト-レスポンスサイクル内で一度だけ呼び出されます。複数のルートがマッチする場合でも同様です。以下の例のとおりです：

router.param('id', function(req, res, next, id) {
    console.log('CALLED ONLY ONCE');
    next();
});
router.get('/user/:id', function(req, res, next) {
    console.log('although this matches');
    next();
});
router.get('/user/:id', function(req, res) {
    console.log('and this mathces too');
    res.end();
});

GET /user/42 の場合、次の結果が得られます：

CALLED ONLY ONCE
although this matches
and this matches too

以下のセクションで説明するrouter.param(callback)は、v4.11.0以降で非推奨になりました。

コールバックパラメータを1つだけrouter.param(name, callback)メソッドに渡すと、router.param(naem, callback)メソッドの動作は完全に変わります。このコールバックパラメータは、router.param(name, callback)どのような動作を持つべきかを定義するカスタムメソッドです。このメソッドは2つのパラメータを受け取り、ミドルウェアを返す必要があります。

このコールバックの最初のパラメータは、キャプチャする必要があるURLのパラメータ名です。2番目のパラメータは任意のJavaScriptオブジェクトで、ミドルウェアを返す実装で使用される可能性があります。 このコールバックメソッドが返すミドルウェアは、URLにこのパラメータが含まれている場合に実行される動作を決定します。

以下の例では、router.param(name, callback)パラメータシグネチャはrouter.param(name, accessId)に変更されました。置き換え先はパラメータ名とコールバックを受け取り、router.param()現在はパラメータ名と数値を受け取ります。

var express = require('express');
var app = express();
var router = express.Router();
router.param(function(param, option){
    return function(req, res, next, val) {
        if (val == option) {
            next();
        }
        else {
            res.sendStatus(403);
        }
    }
});
router.param('id', 1337);
router.get('/user/:id', function(req, res) {
    res.send('Ok');
});
app.use(router);
app.listen(3000, function() {
    console.log('Ready');
});

この例では、router.param(name. callback) のパラメータシグネチャは元のままですが、ミドルウェアに置き換えられており、user idの型が正しいかどうかを検出するカスタムデータ型検出メソッドが定義されています。

router.param(function(param, validator) {
    return function(req, res, next, val) {
        if (validator(val)) {
            next();
        }
        else {
            res.sendStatus(403);
        }
    }
});
router.param('id', function(candidate) {
    return !isNaN(parseFloat(candidate)) && isFinite(candidate);
});

router.route(path)

シングルトンパターンのルートインスタンスを返します。その後、その上にさまざまなHTTPメソッドのミドルウェアを適用できます。router.route()を使用して、ルート名の重複（例：タイプミスによるエラー）を避けます。つまり、意図しているのはrouter.route()このシングルトンメソッドを使用して、同じパスに複数のルートインスタンスが存在するのを避けることです。

上記のrouter.param()例に基づいて、以下のコードは、router.route()を使用してさまざまなHTTPメソッドのハンドラを指定する方法を示しています。

var router = express.Router();
router.param('user_id', function(req, res, next, id) {
    // sample user, would actually fetch from DB, etc...
    req.user = {
        id:id,
        name:"TJ"
    };
    next();
});
router.route('/users/:user_id')
    .all(function(req, res, next) {
        // runs for all HTTP verbs first
        // think of it as route specific middleware!
        next();
    })
    .get(function(req, res, next) {
        res.json(req.user);
    })
    .put(function(req, res, next) {
        // just an example of maybe updating the user
        req.user.name = req.params.name;
        // save user ... etc
        res.json(req.user);
    })
    .post(function(req, res, next) {
        next(new Error('not implemented'));
    })
    .delete(function(req, res, next) {
        next(new Error('not implemented'));
    })

この方法では、単一の/usrs/:useridパスを再利用して、さまざまなHTTPメソッドを追加しています。

router.use([path], [function, ...] function)

オプションのpathパラメータで指定されたパスに、指定されたミドルウェアメソッドをマウントします。未指定のpathパラメータの場合、デフォルト値は/です。 このメソッドはapp.use()に似ています。簡単な例と使用例を以下に説明します。app.use()を参照して、詳細情報を得てください。

ミドルウェアは配管のようなものです。リクエストは、あなたが定義した最初のミドルウェアから始まり、ミドルウェアスタックを下っていきます。パスがマッチした場合、そのリクエストが処理されます。

var express = require('express');
var app = express();
var router = express.Router();
// simple logger for this router`s requests
// all requests to this router will first hit this middleware
router.use(function(req, res, next) {
    console.log('%s %s %s', req.method, req.url, req.path);
    next();
})
// this will only be invoked if the path starts with /bar form the mount ponit
router.use('/bar', function(req, res, next) {
    // ... maybe some additional /bar logging ...
    next();
})
// always be invoked
router.use(function(req, res, next) {
    res.send('hello world')；
})
app.use('/foo', router);
app.listen(3000);

ミドルウェアfunctionの場合、マウントされたパスは取り除かれ、見えなくなります。この特性の主な影響は、異なるパスに同じミドルウェアをマウントしても、プレフィックスが変更されていても、コードを変更する必要がないことです。

router.use()でミドルウェアを定義する順序は重要です。ミドルウェアは順番に呼び出されるため、順序がミドルウェアの優先順位を決定します。たとえば、通常ログは最初に使用するミドルウェアであり、すべてのリクエストが記録されるようにします。

var logger = require('morgan');
router.use(logger());
router.use(express.static(__dirname + '/public'));
router.use(function(req, res) {
    res.send('Hello');
});

さて、静的ファイルのリクエストを記録したくないが、[X]の後に定義されたlogger()ルートとミドルウェアは記録し続けたいとします。単純にstatic()を先頭に移動することで解決できます：

router.use(express.static(__dirname + '/public'));
router.use(logger());
router.use(function(req, res){
  res.send('Hello');
});

もう1つの確実な例は、異なるパスから静的ファイルをホストする場合です。[X]を./public先頭に置くことで、より高い優先順位を得られます：

app.use(express.static(__dirname + '/public'));
app.use(express.static(__dirname + '/files'));
app.use(express.static(__dirname + '/uploads'));

router.use()メソッドは名前付きパラメータもサポートしています。これにより、マウントポイントが他のルートに対して名前付きパラメータを使用してプリロードできるようになり、非常に有益です。
