1.3 カスタム ViewGroup

分類 Android 拡張チュートリアル

はじめに

前のセクションではカスタム View について説明しました。次はそれによく似たカスタム ViewGroup について説明します。実装のメソッド名はほぼ同じで、例えばコンストラクタや、測定・レイアウト・カスタム属性が必要な点も同じです。そのため、これらの説明は繰り返しません。デモを書いてみましょう。

View と ViewGroup の相違点のまとめ

  • 測定: ViewGroup はコンテナとして、子 View の幅と高さを測定し、それらの期待値としてまとめる必要があります。
  • レイアウト: ViewGroup は onLayout をオーバーライドして子をレイアウトし、子の layout メソッドを呼び出して、子の上下左右の位置を指定する必要があります。
  • 描画: ViewGroup は通常、自身を描画しません。

オーバーライドするメソッド

generateLayoutParams

@Override protected LayoutParams generateLayoutParams(LayoutParams p) { return super.generateLayoutParams(p); }

しかし、私はこれを最初に説明したいと思います。ここには非常に重要な概念があるからです。それはLayoutParams !

皆さんも思い出してみてください。例えばあるRelativeLayoutレイアウト内に View を追加すると、この View はandroid:layout_toXXXOf，android:layout_alignXX...これらの属性を定義できます。同様に、LinearLayoutその中の子 View には...が付加されます。android:layout_weightこの属性です。ソースコードを確認すると、その内部に LinearLayout.LayoutParams が定義されているのがわかります。このクラスの中に、使用している属性が存在していることがわかります。

onMeasure

ViewGroup の onMeasure メソッドは View の方法とは異なります。子 View を管理する必要があり、その一つとして子 View の表示サイズを担当します。

@Override protected void onMeasure(int widthMeasureSpec, int heightMeasureSpec) { super.onMeasure(widthMeasureSpec, heightMeasureSpec); int childCount = getChildCount(); //子 View の数を取得する //ループ（走査）を使用して子 View に自身の測定を通知する for (int i=0;i<childCount;i++){ View childView = getChildAt(i); measureChild(childView,widthMeasureSpec,heightMeasureSpec); } }

onLayout

カスタム ViewGroup を描画するときは、その onLayout をオーバーライドする必要があります。これは子 View の表示位置を管理するために使います。

@Override protected void onLayout(boolean b, int l, int i1, int i2, int i3) { //いくつかの変数を初期化する int count = getChildCount(); int width = 0; int height = 0; MarginLayoutParams params = null; //子 View をループし、それらの位置を定義する for (int i = 0; i < count; i++){ View childView = getChildAt(i); width = childView.getMeasuredWidth(); height = childView.getMeasuredHeight(); params = (MarginLayoutParams) getLayoutParams(); switch (i){ case 0: //最初のコンポーネント l = params.leftMargin; i1 = getHeight() - height - params.bottomMargin; break; case 1: //2 番目のコンポーネント l = getWidth() - width - params.leftMargin - params.rightMargin; i1 = getHeight() - height - params.bottomMargin; break; } i2 = l + width; i3 = height + i1; //子 View の layout を呼び出します。これは前回のカスタム View で説明した layout メソッドです。 childView.layout(l, i1, i2, i3); } }

コードはとても理解しやすいでしょう。最終的に驚くべきことに、ViewGroup が View の layout メソッドを積極的に呼び出してその位置を決定していることがわかります。これがコンテナとコンポーネントの違いです。

次に、レイアウト内でカスタム ViewGroup を使用してみましょう。レイアウトと効果を見てみます。

<?xml version="1.0" encoding="utf-8"?> <com.xlh.demo.MyViewGroup xmlns:android="http://schemas.android.com/apk/res/android" android:layout_width="match_parent" android:layout_height="match_parent"> <TextView android:background="@color/colorAccent" android:layout_width="100dp" android:layout_height="100dp"/> <TextView android:background="@color/colorPrimary" android:layout_width="100dp" android:layout_height="100dp" /> </com.example.xlh.demo.MyViewGroup>

これでカスタム ViewGroup について基本的な理解が得られました。さらなる学習には、実際のプロジェクトで使用したり、既存のコードを解析する（いわゆる「車輪の分解」）必要があります。しかし、この記事をこんなに早く終わらせたくはありません。あまりにも安易だと読者に申し訳ないので、小さなサンプルを作ってみましょう！

public class CustomScrollView extends ViewGroup { private int mScreenHeight; private int mStartY; private int mEnd; private Scroller mScroller; private int mLastY; private int childCount; public CustomScrollView(Context context) { this(context,null); } public CustomScrollView(Context context, AttributeSet attrs) { super(context,attrs); //必要な属性をいくつか初期化する WindowManager wm= (WindowManager) getContext().getSystemService(Context.WINDOW_SERVICE); mScreenHeight=wm.getDefaultDisplay().getHeight(); mScroller = new Scroller(getContext()); } //onMeasure で子 View を測定する @Override protected void onMeasure(int widthMeasureSpec, int heightMeasureSpec) { super.onMeasure(widthMeasureSpec, heightMeasureSpec); int childCount = getChildCount(); for (int i=0;i<childCount;i++){ View childView = getChildAt(i); measureChild(childView,widthMeasureSpec,heightMeasureSpec); } } //子 View の位置を決定する @Override protected void onLayout(boolean changed, int l, int t, int r, int b) { childCount = getChildCount(); //この ViewGroup の高さを設定する MarginLayoutParams lp = (MarginLayoutParams) getLayoutParams(); lp.height=mScreenHeight * childCount; setLayoutParams(lp); //子 View の位置をレイアウトする for (int i = 0; i< childCount; i++){ View childView = getChildAt(i); if(childView.getVisibility()!=View.GONE){ childView.layout(l,i*mScreenHeight,r,(i+1)*mScreenHeight); } } } //step3: 必要なタッチ応答イベントを追加します @Override public boolean onTouchEvent(MotionEvent event) { //このタッチイベントでは、2 つの距離を判断する必要があります。1 つは指が移動した距離、もう 1 つは View がスクロールした距離です。 //これは指の移動に伴って変化する量です。 int y = (int) event.getY(); switch (event.getAction()){ case MotionEvent.ACTION_DOWN: mLastY = y; mStartY = getScrollY(); break; case MotionEvent.ACTION_MOVE: //再び画面に触れたとき、以前のスクロールアニメーションがまだ停止していなければ、すぐに停止させます。 if(!mScroller.isFinished()){ mScroller.abortAnimation(); } int dY= mLastY -y; //スクロールが上端に達したときは、プルダウンでバウンドする効果を与えます。 if(getScrollY()<0){ dY/=3; } //スクロールの判定 if(getScrollY()>mScreenHeight*getChildCount()-mScreenHeight){ dY=0; } //View を対応する dy 距離だけスクロールさせます。 scrollBy(0,dY); mLastY=y; break; case MotionEvent.ACTION_UP: mEnd = getScrollY(); int dScrollY = mEnd - mStartY; if(dScrollY>0){//上にスクロールする場合 if(getScrollY()<0){ mScroller.startScroll(0,getScrollY(),0,-dScrollY); }else{ if (dScrollY<mScreenHeight/3){ mScroller.startScroll(0,getScrollY(),0,-dScrollY); }else{ mScroller.startScroll(0,getScrollY(),0,mScreenHeight-dScrollY); } } }else{//下にスクロールする場合 if(getScrollY()>mScreenHeight*getChildCount()-mScreenHeight){ mScroller.startScroll(0,getScrollY(),0,-dScrollY); }else{ if(-dScrollY<mScreenHeight/3){ mScroller.startScroll(0,getScrollY(),0,-dScrollY); }else { mScroller.startScroll(0, getScrollY(), 0, -mScreenHeight - dScrollY); } } } break; } //画面を再描画する postInvalidate(); return true; } //スワイプ操作の制御 @Override public void computeScroll() { super.computeScroll(); if(mScroller.computeScrollOffset()){ scrollTo(0,mScroller.getCurrY()); postInvalidate(); } } }
