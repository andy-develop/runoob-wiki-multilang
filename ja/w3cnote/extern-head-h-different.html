extern とヘッダーファイル(*.h)の違いと関連

分類

用 #include他のヘッダーファイル内の変数や関数の宣言を含めることができるのに、なぜ extern キーワードが必要なのでしょうか？

グローバル変数または関数 a を参照したい場合、ソースファイルに直接 #include<xxx.h> （xxx.h には a の宣言が含まれています）を含めるだけで十分ではないでしょうか。なぜ extern を使う必要があるのでしょうか？

この問題は、長い間、まさに似て非なるものとして私を悩ませてきました。実践と資料の調査を経て、以下のようなまとめになりました：

一、ヘッダーファイル

まずヘッダーファイルについて説明します。実はヘッダーファイルはコンピュータにとってほとんど意味がありません。それはプリコンパイル時に#include#include の場所で展開されるだけです。他に意味はありません。実はヘッダーファイルは主に他の人が読むためのものです。

私は実験をしたことがあります。ヘッダーファイルの拡張子を xxx.txt に変更し、そのヘッダーファイルを参照する場所で #include "xxx.txt" を使いました。コンパイルもリンクも問題なく通りました。これにより、ヘッダーファイルはコードを読むための役割だけであり、他に役割はないことがわかります！

C でも C++ でも、関数や変数、構造体、クラスなどを .c または .cpp ファイルに置きます。そして lib, dll, obj, .o などにコンパイルします。それを使うときは、基本的に gcc hisfile.cpp yourfile.o|obj|dll|lib などです。

しかしプログラマーにとって、あなたの lib, dll... の中に一体何が入っているのか、どうやって知るのでしょうか？ あなたのヘッダーファイルを見る必要があります。あなたのヘッダーファイルはユーザーへの説明です。関数、パラメータ、さまざまなインターフェースの説明です。

説明であるならば、ヘッダーファイルの中に入っているのは当然、関数、変数、クラスに関する「宣言」（関数にとっては関数プロトタイプとも呼ばれる）です。覚えておいてください、「宣言」であり、「定義」ではないということです。

さて、皆さんが宣言と定義の違いを知っていると仮定します。ですから、ヘッダーファイルの中で何かをうかつに定義しないほうがよいでしょう。例えばグローバル変数：

/*xx头文件*/
#ifndef _XX_头文件.H
#define _XX_头文件.H
int A;
#endif

非常に悪いことに、ここでの int A はグローバル変数の定義です。そのため、このヘッダーファイルが複数回参照されると、A は重複定義されてしまい、明らかに構文エラーになります。ただし、この #ifndef による条件付きコンパイルがあるおかげで、ヘッダーファイルが一度だけインクルードされることは保証されます。それでも問題は起きないかもしれませんが、複数の c ファイルがこのヘッダーファイルをインクルードすると、やはりエラーになります。なぜなら、マクロ名の有効範囲はその c ソースファイル内に限られるため、これらの複数の c ファイルをコンパイルする際にはエラーになりません。しかしリンク時に「同じ変数が複数の場所で定義されている」というエラーが報告されます：

Linking...
incl2.obj : error LNK2005: "int glb" (?glb@@3HA) already defined in incl1.obj
Debug/incl.exe : fatal error LNK1169: one or more multiply defined symbols found

二、extern

このキーワードは本当に厄介です。変数を定義するとき、この extern は意外にも省略できます（定義時にはデフォルトで省略されます）。変数を宣言するとき、この extern は変数の前に必ず付けなければなりません。そのため、宣言なのか定義なのかがわからなくなることがあります。言い換えると、変数の前に extern があっても必ずしも宣言とは限らず、変数の前に extern がなければ定義のみ可能です。注：定義は変数にメモリ領域を割り当てますが、宣言は変数にメモリ領域を割り当てる必要がありません。

以下、変数と関数の2つのカテゴリに分けて説明します：

（1）変数

特に変数については：

extern int a; // 声明一个全局变量 a
int a; // 定义一个全局变量 a
extern int a =0 ; // 定义一个全局变量 a 并给初值。
int a =0;    // 定义一个全局变量 a, 并给初值，

4番目は3番目と同じで、外部から使用できるグローバル変数を定義し、初期値を与えます。

混乱しましたか？ それらは本当によく似ています。しかし定義は一箇所にしか現れてはなりません。つまり、int a; でも extern int a=0; でも int a=0; でも、1回しか現れてはいけません。一方、extern int a; は何度現れてもかまいません。

グローバル変数を参照するときは、extern int a; と宣言する必要があります。このとき extern は省略できません。省略すると int a; になり、これは宣言ではなく定義になります。注：extern int a; の型 int は省略でき、extern a; となります。ただし、他の型は省略できません。

（2）関数

関数も同様で、定義と宣言があります。定義するときに extern を使うと、その関数が外部から参照できることを示します。宣言するときに extern を使うと、これが宣言であることを示します。しかし、関数の定義と宣言には違いがあります。関数の定義には関数本体が必要ですが、関数の宣言には関数本体がありません（そしてセミコロンで終わります）。そのため、関数の定義と宣言のどちらでも extern を省略できます。いずれにしても他のファイルはこの関数が他の場所で定義されていることを知っているので、extern を付けなくても問題ありません。このように両者は大きく異なるので、extern を省略しても問題は起きません。

例えば：

/*某cpp文件*/
int fun(void)
{
      return 0;
}

では、グローバル関数を定義しました：

/*另一cpp文件*/
int fun(void);

これに対して宣言を行えば、その後は使用できます。extern を付けても付けなくても同じです。また、fun の宣言をヘッダーファイルに入れることもできます。最終的に次のようになります：

/*fun.h*/
int fun(void);   //函数声明，所以省略了extern，完整些是extern int fun(void);
/*对应的fun.cpp文件*/
int fun(void)
{
     return 0;
}//一个完整的全局函数定义，因为有函数体，extern同样被省略了。

そして、あなたの fun を使いたいクライアントがこのヘッダーファイルをインクルードすれば、ok、グローバルな宣言になります。問題ありません。

しかし、逆に、このクライアントがグローバル変数を使いたい場合は、extern を付けてその変数を宣言する必要があります。そうしないと定義になってしまいます。

まとめ：

変数について言えば、自分のソースファイル（例えばファイル名A）内で別のソースファイル（例えばファイル名B）の変数を使いたい場合、方法は2つあります：(1) Aファイル内で、Bファイルで定義されている変数（もちろんグローバル変数）を extern で宣言する必要があります。(2) Aファイルに Bファイルに対応するヘッダーファイルを追加します。もちろん、このヘッダーファイルには Bファイル内の変数宣言が含まれます。つまり、このヘッダーファイル内で extern を使ってその変数を宣言する必要があります。そうしないと、その変数はもう一度定義されてしまいます。

関数について言えば、自分のソースファイル（例えばファイル名A）内で別のソースファイル（例えばファイル名B）の関数を使いたい場合、方法は2つあります：(1) Aファイル内で Bファイルで定義されている関数を extern で宣言します（実際には extern は省略してもよく、Aファイル内に Bファイルで定義されている関数のプロトタイプが現れればよいだけです）。(2) Aファイルに Bファイルに対応するヘッダーファイルを追加します。もちろん、このヘッダーファイルには Bファイル内の関数プロトタイプが含まれます。ヘッダーファイル内では関数に extern を付けなくてもかまいません。

上記のまとめを別の言い方にすると：

(a) あるファイルから別のファイルのグローバル変数を呼び出す場合、グローバル変数は通常、元の .c ファイルに定義されています。ソースファイルを #include でインクルードすることはできず、ヘッダーファイルのみをインクルードできます。そのため、一般的な方法は extern int a; を使って外部変数を宣言することです。もう1つの方法は、a.c ファイルでグローバル変数 int global_num; を定義した場合、対応する a.h ヘッダーファイルに extern int global_num; と書くことです。そうすれば、他のソースファイルは a.h をインクルードすることで、それが外部変数であると宣言できます。

（b）また、変数と関数の異なる例int fun(); 和 extern int fun();すべて宣言です（定義には実装本体が必要です）。extern を使うextern int fun()と、ただより明確にそれが宣言であることを示すだけです。一方、int a;定義です。extern int a;宣言です。

(3) さらに、extern 修飾子は C++ プログラムで C 関数を呼び出す際の仕様問題に使用できます。

例えば、C++ で C ライブラリ関数を呼び出す場合、C++ プログラム内で extern "C" を使って参照する関数を宣言する必要があります。これはリンカのためのもので、リンク時に C 関数の仕様に従ってリンクするようにリンカに指示します。主な理由は、C++ と C のプログラムは、コンパイル完了後のオブジェクトコードにおける命名規則が異なるからです。

C++ 言語はコンパイル時に多態性（ポリモーフィズム）の問題を解決するため、名前とパラメータを結合して中間の名前を生成します。一方 C 言語はそのようなことをしないため、リンク時に対応するものが見つからないという状況が発生します。この場合、C++ 側では extern "C" を使ってリンク指定を行う必要があります。これはコンパイラに「名前をそのまま維持してください。リンク用の中間名を生成しないでください」と伝えます。

三、extern とヘッダーファイルの関連

この関連性によって、最初に提起した2つの問題も解決されます：

(a) #include を使うことで他のヘッダーファイル内の変数や関数の宣言を含めることができるのに、なぜ extern キーワードがまだ必要なのでしょうか？

(b) グローバル変数または関数 a を参照したい場合、ソースファイルに直接 #include（xxx.h には a の宣言が含まれている）を含めればそれで十分ではないか？ なぜ extern を使う必要があるのか？

答え：あるファイル（仮にファイル名Aとします）が別のファイル（仮にファイル名Bとします）で定義された変数や関数を大量に参照する場合、ヘッダーファイルを使う方が効率が高く、プログラム構造もより規範的になります。他のファイル（例えばファイル名C、Dなど）がファイル名Bで定義された変数や関数を参照する場合は、ファイルBに対応するヘッダーファイルを #include でインクルードするだけで済みます（もちろん、このヘッダーファイルには変数や関数の宣言しかなく、定義を絶対に含めてはいけません）。

それは忘れ去られた時代です。コンパイラが .c（または .cpp）ファイルしか認識できず、.h が何であるかも知らなかった時代です。

当時の人々は多くの .c（または .cpp）ファイルを書きました。やがて、多くの .c（または .cpp）ファイルにおける変数宣言や関数プロトタイプが同じであることに気づきました。しかし彼らはその内容を一字一句、繰り返し各 .c（または .cpp）ファイルに打ち込まなければなりませんでした。さらに恐ろしいのは、そのうちの1つの宣言が変更されたとき、すべての .c（または .cpp）ファイルを調べて、その中の宣言を修正しなければならないことでした。ああ、まさに世界の終わりの到来です！

ついに、誰か（あるいは数人）がこのような苦痛に耐えられなくなりました。彼（ら）は重複する部分を取り出し、新しいファイルに置き、必要な .c（または .cpp）ファイルに #include XXXX という文を打ち込みました。こうして、ある宣言が変更されたとしても、あちこち探して修正する必要はもうありません---世界はやはり素晴らしいのです！

この新しいファイルは .c（または .cpp）ファイルの先頭に置かれることが多かったため、「ヘッダーファイル」と名付けられました。拡張子は .h です。

これ以降、コンパイラ（実際にはその中のプリプロセッサ）は、世の中に.c（または.cpp）ファイルのほかに、.hファイルというものが存在し、さらに#includeというコマンドがあることを知っている。
