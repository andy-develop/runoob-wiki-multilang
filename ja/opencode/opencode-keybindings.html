OpenCode ショートカットキー設定の詳細

OpenCode は、アプリケーション制御、セッション管理、メッセージ閲覧、モデル切り替え、入力編集などの各種操作を網羅した、完全なキーボードショートカットシステムを提供します。

すべてのショートカットキーは、tui.jsonファイルでカスタマイズできます。

設定ファイル

ショートカットキー設定は、tui.jsonファイルのkeybindsフィールドに記述します。各レコードのキー名は操作名、値は対応するショートカットキーです：

例

{
  "$schema": "https://opencode.ai/tui.json",
  "keybinds": {
"leader": "ctrl+x", // リーダーキー設定（下記参照）
"session_new": "<leader>n", // 新規セッション：リーダーキーを押してから n を押す
"model_list": "<leader>m", // モデルリストを開く：リーダーキーを押してから m を押す
"session_compact": "none" // 値を "none" に設定するとこのショートカットキーを無効化できます
  }
}

1つの操作に複数のショートカットキーをバインドでき、カンマで区切ります。いずれかを押すと操作が実行されます：

例

{
  "$schema": "https://opencode.ai/tui.json",
  "keybinds": {
// 以下の記述は、pageup または ctrl+alt+b を押すと、どちらでも上にページ送りできることを示します。
    "messages_page_up": "pageup,ctrl+alt+b"
  }
}

リーダーキー（Leader Key）

OpenCode のほとんどのショートカットキーはリーダーキー（Leader Key）メカニズムを採用しています。まずリーダーキーを押し、次に機能キーを押すと、2つのキーの組み合わせで対応する操作が実行されます。この設計の利点は、ターミナル自体のショートカットキーとの競合を避けられることです。

デフォルトのリーダーキーはctrl+xです。例えば、新規セッションのショートカットキーは<leader>n、実際の操作は：まずctrl+x、次にn。

リーダーキーは任意のコンビネーションキーに変更できます：

例

{
  "$schema": "https://opencode.ai/tui.json",
  "keybinds": {
"leader": "ctrl+x" // リーダーキーを他のキー（例: "ctrl+space"、"alt+x" など）に変更
// 設定内の <leader> プレースホルダーは、ここで設定したキーに自動的に置き換えられます。
  }
}

ショートカットキーを設定する際に必ずしもリーダーキーを使用する必要はありません。通常のキーやコンビネーションキーを直接バインドすることもできます。ただし、ターミナルのショートカットキーとの競合を避けるため、リーダーキーを優先的に使用することをお勧めします。

ショートカットキーの無効化

任意のショートカットキーの値を"none"に設定すると、その操作を無効化できます。無効化後は、どのキーを押しても実行されません：

例

{
  "$schema": "https://opencode.ai/tui.json",
  "keybinds": {
"session_compact": "none", // 「セッションを圧縮」ショートカットキーを無効化
"scrollbar_toggle": "none", // 「スクロールバー切り替え」ショートカットキーを無効化
"tips_toggle": "none" // 「ヒント切り替え」ショートカットキーを無効化
  }
}

デスクトップ版内蔵入力ショートカットキー

OpenCode デスクトップ版のプロンプト入力ボックスには、追加で一組のReadline / Emacs スタイルのテキスト編集ショートカットキーが内蔵されています。これらのショートカットキーは内蔵機能であり、tui.json変更または無効化することはできません：

ショートカットキー 操作
ctrl+a 現在の行の先頭に移動
ctrl+e 現在の行の末尾に移動
ctrl+b カーソルを後方に1文字移動
ctrl+f カーソルを前方に1文字移動
alt+b カーソルを後方に1単語移動
alt+f カーソルを前方に1単語移動
ctrl+d カーソル位置の文字を削除
ctrl+k カーソルから行末までの内容を削除
ctrl+u カーソルから行頭までの内容を削除
ctrl+w 前の単語を削除
alt+d 後の単語を削除
ctrl+t カーソルの前後2つの文字の位置を入れ替える
ctrl+g 現在のポップアップウィンドウをキャンセル、または実行中の応答を中止する

Shift+Enter での改行設定

一部のターミナルは、デフォルトで修飾キー付きの Enter（例：Shift+Enter）を独立したキーとして送信しないため、OpenCode で押すとShift+Enter改行されず、メッセージが直接送信されます。ターミナルでこのキーのエスケープシーケンスを手動で設定する必要があります。

Windows Terminal での設定方法

ステップ1：Windows Terminal のsettings.jsonファイルを開きます。パスは：

%LOCALAPPDATA%\Packages\Microsoft.WindowsTerminal_8wekyb3d8bbwe\LocalState\settings.json

ステップ2：配列に以下の設定を追加し、送信するactionsエスケープシーケンスのアクションを定義します：Shift+Enter例

例

"actions": [
  {
    "command": {
      "action": "sendInput",
ステップ3：
    },
    "id": "User.sendInput.ShiftEnterCustom"
  }
]

配列にキーバインドを追加し、を上記で定義したアクションにマッピングします：keybindings例Shift+Enterステップ4：

例

"keybindings": [
  {
    "keys": "shift+enter",
    "id": "User.sendInput.ShiftEnterCustom"
  }
]

ファイルを保存した後、Windows Terminal を再起動するか、新しいタブを開いて設定を有効にします。他のターミナル（iTerm2、Kitty、Alacritty など）を使用している場合は、対応するターミナルのドキュメントを参照し、「キーマッピング」または「Key bindings」関連の設定を見つけて、settings.json送信するように設定し、

エスケープシーケンスを送信すればOKです。Shift+Enterその他の拡張\u001b[13;2uAI 思考中...
