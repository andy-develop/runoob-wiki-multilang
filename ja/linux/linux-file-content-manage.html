Linux ファイルとディレクトリ管理

Linux のディレクトリ構造はツリー構造であり、最上位のディレクトリはルートディレクトリです。/。

他のディレクトリはマウントによってツリーに追加でき、マウント解除によって削除できます。

このチュートリアルを始める前に、絶対パスと相対パスとは何かを知っておく必要があります。

  • 絶対パス：
    パスの書き方は、ルートディレクトリ / から/書き始めます。例： /usr/share/doc というディレクトリ。

  • 相対パス：


    パスの書き方は、ルートディレクトリ / からではなく/書き始めます。例えば /usr/share/doc から /usr/share/man に行く場合、次のように書けます：cd ../manこれが相対パスの書き方です。

ディレクトリを操作する一般的なコマンド

次に、ディレクトリを操作するいくつかの一般的なコマンドを見てみましょう。

  • ls（英語の正式名称：list files）: ディレクトリとファイル名を一覧表示します
  • cd（英語の正式名称：change directory）：ディレクトリを切り替えます
  • pwd（英語の正式名称：print work directory）：現在のディレクトリを表示します
  • mkdir（英語の正式名称：make directory）：新しいディレクトリを作成します
  • rmdir（英語の正式名称：remove directory）：空のディレクトリを削除します
  • cp（英語の正式名称：copy file）: ファイルまたはディレクトリをコピーします
  • rm（英語の正式名称：remove）: ファイルまたはディレクトリを削除します
  • mv（英語の正式名称：move file）: ファイルとディレクトリを移動、またはファイルとディレクトリの名前を変更します

次のように使用できますman [コマンド]各コマンドの使用ドキュメントを確認できます。例：man cp。

ls (ディレクトリの一覧表示)

Linuxシステムでは、ls コマンドが最も頻繁に実行されるかもしれません。

構文：

[root@www ~]# ls [-aAdfFhilnrRSt] 目录名称
[root@www ~]# ls [--color={never,auto,always}] 目录名称
[root@www ~]# ls [--full-time] 目录名称

オプションとパラメータ：

  • -a ：すべてのファイルを、隠しファイル（. で始まるファイル）も含めて一覧表示します（よく使う）
  • -d ：ディレクトリ内のファイルデータではなく、ディレクトリ自体のみを一覧表示します（よく使う）
  • -l ：ファイルの属性や権限などのデータを含む長い形式で一覧表示します（よく使う）

ディレクトリ内のすべてのファイルを（属性と隠しファイルを含めて）一覧表示します

[root@www ~]# ls -al ~

cd (ディレクトリの切り替え)

cd は Change Directory の略で、作業ディレクトリを変更するためのコマンドです。

構文：

 cd [相对路径或绝对路径]

#使用 mkdir 命令创建 runoob 目录
[root@www ~]# mkdir runoob

#使用绝对路径切换到 runoob 目录
[root@www ~]# cd /root/runoob/

#使用相对路径切换到 runoob 目录
[root@www ~]# cd ./runoob/

# 表示回到自己的家目录，亦即是 /root 这个目录
[root@www runoob]# cd ~

# 表示去到目前的上一级目录，亦即是 /root 的上一级目录的意思；
[root@www ~]# cd ..

次に、何度か操作してみれば、cd コマンドをよく理解できるはずです。

pwd (現在のディレクトリを表示)

pwd はPrint Working Directoryの略で、つまり現在のディレクトリを表示するコマンドです。

[root@www ~]# pwd [-P]

オプションとパラメータ：

  • -P：リンク（link）パスではなく、実際のパスを表示します。

例：単に現在の作業ディレクトリを表示します：

[root@www ~]# pwd
/root   <== 显示出目录啦～

例：リンクファイル自体のディレクトリ名ではなく、実際の作業ディレクトリを表示します。

[root@www ~]# cd /var/mail   <==注意，/var/mail是一个链接档
[root@www mail]# pwd
/var/mail         <==列出目前的工作目录
[root@www mail]# pwd -P
/var/spool/mail   <==怎么回事？有没有加 -P 差很多～
[root@www mail]# ls -ld /var/mail
lrwxrwxrwx 1 root root 10 Sep  4 17:54 /var/mail -> spool/mail
# 看到这里应该知道为啥了吧？因为 /var/mail 是链接档，链接到 /var/spool/mail 
# 所以，加上 pwd -P 的选项后，会不以链接档的数据显示，而是显示正确的完整路径啊！

mkdir (新しいディレクトリの作成)

新しいディレクトリを作成したい場合は、mkdir (make directory) を使用しましょう。

構文：

mkdir [-mp] 目录名称

オプションとパラメータ：

  • -m ：ファイルの権限を設定します！直接設定するので、デフォルト権限（umask）を気にする必要はありません～
  • -p ：必要なディレクトリ（親ディレクトリも含めて）を再帰的に作成するのに役立ちます！

例：/tmp の下でいくつか新しいディレクトリを作成してみてください：

[root@www ~]# cd /tmp
[root@www tmp]# mkdir test    <==创建一名为 test 的新目录
[root@www tmp]# mkdir test1/test2/test3/test4
mkdir: cannot create directory `test1/test2/test3/test4': 
No such file or directory       <== 没办法直接创建此目录啊！
[root@www tmp]# mkdir -p test1/test2/test3/test4

この -p オプションを追加すると、複数階層のディレクトリを自動的に作成してくれます！

例：権限がrwx--x--xのディレクトリを作成します。

[root@www tmp]# mkdir -m 711 test2
[root@www tmp]# ls -l
drwxr-xr-x  3 root  root 4096 Jul 18 12:50 test
drwxr-xr-x  3 root  root 4096 Jul 18 12:53 test1
drwx--x--x  2 root  root 4096 Jul 18 12:54 test2

上記の権限部分で、-m を付けて属性を強制設定しない場合、システムはデフォルト属性を使用します。

-m を使用する場合、上記の例のように -m 711 を指定して、新しいディレクトリに drwx--x--x の権限を付与します。

rmdir (空のディレクトリの削除)

構文：

 rmdir [-p] 目录名称

オプションとパラメータ：

  • -p ：そのディレクトリから、複数階層の空ディレクトリを一度に削除します

runoob ディレクトリを削除します

[root@www tmp]# rmdir runoob/

mkdir の例で作成したディレクトリ（/tmp の下）を削除します！

[root@www tmp]# ls -l   <==看看有多少目录存在？
drwxr-xr-x  3 root  root 4096 Jul 18 12:50 test
drwxr-xr-x  3 root  root 4096 Jul 18 12:53 test1
drwx--x--x  2 root  root 4096 Jul 18 12:54 test2
[root@www tmp]# rmdir test   <==可直接删除掉，没问题
[root@www tmp]# rmdir test1  <==因为尚有内容，所以无法删除！
rmdir: `test1': Directory not empty
[root@www tmp]# rmdir -p test1/test2/test3/test4
[root@www tmp]# ls -l        <==您看看，底下的输出中test与test1不见了！
drwx--x--x  2 root  root 4096 Jul 18 12:54 test2

-p オプションを使用すると、test1/test2/test3/test4 を一度に削除できます。

ただし注意すべき点は、この rmdir は空のディレクトリしか削除できないことです。空でないディレクトリを削除するには rm コマンドを使用できます。

cp (ファイルまたはディレクトリのコピー)

cp はファイルとディレクトリをコピーします。

構文：

[root@www ~]# cp [-adfilprsu] 来源档(source) 目标档(destination)
[root@www ~]# cp [options] source1 source2 source3 .... directory

オプションとパラメータ：

  • -a：-pdr と同じ意味です。pdr については以下の説明を参照してください；（よく使う）

  • -d：ソースがリンクファイル（link file）の場合、ファイル自体ではなくリンクファイルをコピーします；

  • -f：強制（force）の意味で、対象ファイルがすでに存在し開けない場合は、削除してもう一度試みます；

  • -i：対象ファイル（destination）がすでに存在する場合、上書き時に実行を確認します（よく使う）

  • -l：ファイル自体をコピーするのではなく、ハードリンク（hard link）のリンクファイルを作成します；

  • -p：デフォルト属性ではなく、ファイルの属性も一緒にコピーします（バックアップでよく使う）；

  • -r：再帰的にコピーを続け、ディレクトリのコピーに使用します；（よく使う）

  • -s：シンボリックリンク（symbolic link）、つまり「ショートカット」ファイルとしてコピーします；

  • -u：destination が source より古い場合のみ destination を更新します！

root として、root ディレクトリの .bashrc を /tmp にコピーし、bashrc と名付けます

[root@www ~]# cp ~/.bashrc /tmp/bashrc
[root@www ~]# cp -i ~/.bashrc /tmp/bashrc
cp: overwrite `/tmp/bashrc'? n  <==n不覆盖，y为覆盖

rm (ファイルまたはディレクトリの削除)

構文：

 rm [-fir] 文件或目录

オプションとパラメータ：

  • -f ：force の意味で、存在しないファイルを無視し、警告メッセージは表示されません；
  • -i ：対話モードで、削除前にユーザーに実行するかどうかを確認します
  • -r ：再帰的に削除します！ディレクトリの削除に最もよく使います！これは非常に危険なオプションです！！！

先ほど cp の例で作成した bashrc を削除します！

[root@www tmp]# rm -i bashrc
rm: remove regular file `bashrc'? y

-i オプションを付けると、削除前に確認を求めてくるので、誤ったファイル名を削除するのを防げます！

mv (ファイルとディレクトリの移動、または名前の変更)

構文：

[root@www ~]# mv [-fiu] source destination
[root@www ~]# mv [options] source1 source2 source3 .... directory

オプションとパラメータ：

  • -f ：force 強制の意味で、対象ファイルがすでに存在する場合、確認せずに直接上書きします；
  • -i ：対象ファイル（destination）がすでに存在する場合、上書きするかどうかを確認します！
  • -u ：対象ファイルがすでに存在し、source の方が新しい場合のみ更新（update）します

ファイルをコピーし、ディレクトリを作成し、ファイルをそのディレクトリに移動します

[root@www ~]# cd /tmp
[root@www tmp]# cp ~/.bashrc bashrc
[root@www tmp]# mkdir mvtest
[root@www tmp]# mv bashrc mvtest

ファイルをディレクトリに移動するには、このようにします！

先ほどのディレクトリ名を mvtest2 に変更します

[root@www tmp]# mv mvtest mvtest2

Linux ファイル内容の表示

Linuxシステムでは、以下のコマンドを使用してファイルの内容を表示します：

  • cat 最初の行からファイルの内容を表示します
  • tac 最後の行から表示します。tac は cat を逆さに書いたものだとわかります！
  • nl 表示するときに行番号も出力します！
  • more ファイルの内容を1ページずつ表示します
  • less more に似ていますが、more より優れているのは、前にページをめくれることです！
  • head 最初の数行だけ表示します
  • tail 最後の数行だけ表示します

次のように使用できますman [コマンド]各コマンドの使用ドキュメントを確認できます。例：man cp。

cat

最初の行からファイルの内容を表示します

構文：

cat [-AbEnTv]

オプションとパラメータ：

  • -A ： -vET を統合したオプションで、空白だけでなく特殊文字も表示できます。
  • -b ： 行番号を表示しますが、空白行以外の行のみに行番号を付け、空白行には行番号を付けません！
  • -E ： 行末の改行バイト $ を表示します。
  • -n ： 行番号を表示します。空白行にも行番号が付きます。-b オプションとは異なります。
  • -T ： [tab] キーを ^I として表示します。
  • -v ： 判別しにくい特殊文字を表示します。

/etc/issue ファイルの内容を表示します。

[root@www ~]# cat /etc/issue
CentOS release 6.4 (Final)
Kernel \r on an \m

tac

tac コマンドは cat と正反対で、ファイルの内容を最後の行から表示します。tac は cat を逆に書いたものだと分かります。例：

[root@www ~]# tac /etc/issue

Kernel \r on an \m
CentOS release 6.4 (Final)

nl

行番号を表示

構文：

nl [-bnw] 文件

オプションとパラメータ：

  • -b ： 行番号の指定方法を指定します。主に2種類あります：
    -b a ： 空行かどうかに関係なく行番号を表示します（cat -n に似ています）。
    -b t ： 空行がある場合、その空行には行番号を表示しません（デフォルト）。
  • -n ： 行番号の表示方法を指定します。主に3種類あります：
    -n ln ： 行番号を画面の一番左に表示します。
    -n rn ： 行番号を自分のフィールドの一番右に表示し、0 を付けません。
    -n rz ： 行番号を自分のフィールドの一番右に表示し、0 を付けます。
  • -w ： 行番号フィールドの桁数を指定します。

例1： nl で /etc/issue の内容を表示する

[root@www ~]# nl /etc/issue
     1  CentOS release 6.4 (Final)
     2  Kernel \r on an \m

more

ページ単位でめくる

[root@www ~]# more /etc/man_db.config 
#
# Generated automatically from man.conf.in by the
# configure script.
#
# man.conf from man-1.6d
....(中间省略)....
--More--(28%)  <== 重点在这一行喔！你的光标也会在这里等待你的命令

more プログラムの実行中に、押せるキーがいくつかあります：

  • スペースキー： 下へ1ページめくります。
  • Enter ： 下へ「1行」めくります。
  • /文字列 ： 表示中の内容から下方向へ「文字列」というキーワードを検索します。
  • :f ： ファイル名と現在表示中の行数をすぐに表示します。
  • q ： more をすぐに終了し、そのファイルの内容を表示しなくなります。
  • b または [ctrl]-b ： 前のページに戻ります。ただし、この操作はファイルに対してのみ有効で、パイプラインには無効です。

less

ページ単位でめくる。以下の例では /etc/man.config ファイルの内容を出力します。

[root@www ~]# less /etc/man.config
#
# Generated automatically from man.conf.in by the
# configure script.
#
# man.conf from man-1.6d
....(中间省略)....
:   <== 这里可以等待你输入命令！

less 実行中に入力できるコマンドは次のとおりです：

  • スペースキー ： 下へ1ページめくります。
  • [pagedown] ： 下へ1ページめくります。
  • [pageup] ： 上へ1ページめくります。
  • /文字列 ： 下方向へ「文字列」を検索する機能。
  • ?文字列 ： 上方向へ「文字列」を検索する機能。
  • n ： 直前の検索を繰り返します（/ または ? に関連します！）
  • N ： 直前の検索を逆方向に繰り返します（/ または ? に関連します！）
  • q ： less プログラムを終了します。

head

ファイルの先頭の数行を表示する

構文：

head [-n number] 文件

オプションとパラメータ：

  • -n ： 後に数字を指定し、表示する行数を意味します。
[root@www ~]# head /etc/man.config

デフォルトでは先頭の10行を表示します！先頭の20行を表示するには、次のようにします：

[root@www ~]# head -n 20 /etc/man.config

tail

ファイルの末尾の数行を表示する

構文：

tail [-n number] 文件

オプションとパラメータ：

  • -n ： 後に数字を指定し、表示する行数を意味します。
  • -f ： 後に指定したファイル名を継続的に監視します。[ctrl]-c を押すまで tail の監視は終了しません。
[root@www ~]# tail /etc/man.config
# 默认的情况中，显示最后的十行！若要显示最后的 20 行，就得要这样：
[root@www ~]# tail -n 20 /etc/man.config

    1. Linux リンクの概念

    Linux のリンクには2種類あり、1つはハードリンク（Hard Link）、もう1つはシンボリックリンク（Symbolic Link）と呼ばれます。デフォルトでは、lnコマンドはハードリンクを作成します。

    ハードリンク

    ハードリンクは、インデックスノードを介して接続することを指します。Linux のファイルシステムでは、ディスクパーティションに保存されているファイルは、種類に関係なく番号が割り当てられ、インデックスノード番号（Inode Index）と呼ばれます。Linux では、複数のファイル名が同じインデックスノードを指すことができます。例えば、A が B のハードリンクである場合（A と B はどちらもファイル名）、A のディレクトリエントリ内の inode ノード番号と B のディレクトリエントリ内の inode ノード番号は同じです。つまり、1つの inode ノードが2つの異なるファイル名に対応し、2つのファイル名が同じファイルを指していることになります。A と B はファイルシステムに対して完全に平等です。どちらかを削除しても、もう一方のアクセスには影響しません。

    ハードリンクの役割は、1つのファイルが複数の有効なパス名を持つことを可能にすることです。これにより、ユーザーは重要なファイルへのハードリンクを作成して、「誤削除」を防ぐことができます。その理由は上記のとおりで、そのディレクトリに対応するインデックスノードには複数のリンクがあるためです。1つのリンクを削除しても、インデックスノード自体や他のリンクには影響しません。最後のリンクが削除されて初めて、ファイルのデータブロックとディレクトリのリンクが解放されます。つまり、ファイルが本当に削除される条件は、関連するすべてのハードリンクファイルが削除された場合です。

    ソフトリンク

    もう1つのリンクはシンボリックリンク（Symbolic Link）と呼ばれ、ソフトリンクとも呼ばれます。ソフトリンクファイルは Windows のショートカットに似ています。実際には特別なファイルです。シンボリックリンクでは、ファイルは実際にはテキストファイルであり、別のファイルの位置情報が含まれています。例えば、A が B のソフトリンクである場合（A と B はどちらもファイル名）、A のディレクトリエントリ内の inode ノード番号と B のディレクトリエントリ内の inode ノード番号は異なります。A と B は2つの異なる inode を指し、さらに2つの異なるデータブロックを指します。しかし、A のデータブロックには B のパス名だけが格納されています（これにより B のディレクトリエントリを見つけることができます）。A と B の間は「主従」関係にあり、B が削除されても A は存在します（2つは異なるファイルであるため）、ただし指しているのは無効なリンクです。

    2. 実験を通して理解を深める

    [oracle@Linux]$ touch f1          #创建一个测试文件f1
[oracle@Linux]$ ln f1 f2          #创建f1的一个硬连接文件f2
[oracle@Linux]$ ln -s f1 f3       #创建f1的一个符号连接文件f3
[oracle@Linux]$ ls -li            # -i参数显示文件的inode节点信息
total 0
9797648 -rw-r--r--  2 oracle oinstall 0 Apr 21 08:11 f1
9797648 -rw-r--r--  2 oracle oinstall 0 Apr 21 08:11 f2
9797649 lrwxrwxrwx  1 oracle oinstall 2 Apr 21 08:11 f3 -> f1

    上記の結果から、ハードリンクファイル f2 と元のファイル f1 の inode ノードは同じで、両方とも 9797648 ですが、シンボリックリンクファイルの inode ノードは異なることが分かります。

    [oracle@Linux]$ echo "I am f1 file" >>f1
[oracle@Linux]$ cat f1
I am f1 file
[oracle@Linux]$ cat f2
I am f1 file
[oracle@Linux]$ cat f3
I am f1 file
[oracle@Linux]$ rm -f f1
[oracle@Linux]$ cat f2
I am f1 file
[oracle@Linux]$ cat f3
cat: f3: No such file or directory

    上記のテストから、元のファイル f1 を削除しても、ハードリンク f2 は影響を受けませんが、シンボリックリンク f3 ファイルは無効になることが分かります。

    3. まとめ

    これに基づいて関連するテストを行うと、以下のすべての結論が得られます：

    • 1). シンボリックリンク f3 を削除しても、f1、f2 に影響はありません。
    • 2). ハードリンク f2 を削除しても、f1、f3 にも影響はありません。
    • 3). 元のファイル f1 を削除しても、ハードリンク f2 には影響がなく、シンボリックリンク f3 は無効になります。
    • 4). 元のファイル f1 とハードリンク f2 を同時に削除すると、ファイル全体が本当に削除されます。
