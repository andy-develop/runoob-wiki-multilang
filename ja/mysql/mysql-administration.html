MySQL 管理

MySQL サーバーの起動と停止

Windows システムの場合

MySQL サーバーを起動:

1、「サービス」管理ツールを使用:「ファイル名を指定して実行」ダイアログ（Win + R）を開き、入力services.msc「MySQL」サービスを見つけ、右クリックして「開始」を選択します。

2. コマンドプロンプトを使用:コマンドプロンプト（管理者として）を開き、次のコマンドを入力します:

net start mysql

MySQL サーバーを停止:

1、「サービス」管理ツールを使用:同様に「ファイル名を指定して実行」ダイアログを開き、services.msc と入力し、「MySQL」サービスを見つけて右クリックし「停止」を選択します。

2、コマンドプロンプトを使用:コマンドプロンプト（管理者として）を開き、次のコマンドを入力します:

net stop mysql

Linux システムの場合

1. MySQL サービスの起動:

使用systemdコマンド（Ubuntu、CentOS など、ほとんどの最新の Linux ディストリビューションに適用）:

sudo systemctl start mysql

使用serviceコマンド（一部の古いディストリビューション）:

sudo service mysql start

2. MySQL サービスの停止:

systemd を使用:

sudo systemctl stop mysql

service コマンドを使用:

sudo service mysql stop

3. MySQL サービスの再起動:

systemd を使用: 
sudo systemctl restart mysql

service コマンドを使用:

sudo service mysql restart

4. MySQL サービスの状態確認:

systemd コマンドを使用:

sudo systemctl status mysql

service コマンドを使用:

sudo service mysql status

Mac OS システム

MySQL サービスの起動:

コマンドラインを使用:

sudo /usr/local/mysql/support-files/mysql.server start

MySQL サービスの停止:

コマンドラインを使用:

sudo /usr/local/mysql/support-files/mysql.server stop

MySQL サービスの再起動:

コマンドラインを使用:

sudo /usr/local/mysql/support-files/mysql.server restart

MySQL サービスの状態確認:

コマンドラインを使用:

sudo /usr/local/mysql/support-files/mysql.server status

上記のコマンドでは、mysql はインストールパスやバージョンの違いによって異なる場合があります。

Mac OS では、MySQL のインストールパスは通常 /usr/local/mysql/ です。そのため、MySQL サービスの起動と停止には、このパスにある mysql.server スクリプトを使用する必要があります。

MySQL ユーザー設定

MySQL では、ユーザー設定にはユーザーの作成、権限の設定、ユーザーの管理などの操作が含まれます。以下は、ユーザーの作成、権限の設定、ユーザーの確認と削除などを含む、よく使われる MySQL ユーザー設定操作です。

ユーザーの作成

新しいユーザーを作成するには、次の SQL コマンドを使用できます:

CREATE USER 'username'@'host' IDENTIFIED BY 'password';
  • username: ユーザー名。
  • host: ユーザーがどのホストから接続できるかを指定します。例:localhostローカル接続のみ許可、%任意のホストからの接続を許可。
  • password: ユーザーのパスワード。

例

CREATE USER 'john'@'localhost' IDENTIFIED BY 'password123';

権限の付与

ユーザーを作成した後、アクセス権限を付与する必要があります。次のコマンドを使用してGRANTコマンドで権限を付与します:

GRANT privileges ON database_name.* TO 'username'@'host';

  • privileges: 必要な権限。例:ALL PRIVILEGES、SELECT、INSERT、UPDATE、DELETEなど。
  • database_name.*: 特定のデータベースまたはテーブルに対する権限を付与します。database_name.*データベース全体のすべてのテーブルに対する権限を付与することを示します。database_name.table_name指定されたテーブルに対する権限を付与することを示します。
  • TO 'username'@'host': 権限を付与するユーザーとホストを指定します。

例

GRANT ALL PRIVILEGES ON test_db.* TO 'john'@'localhost';

権限のリフレッシュ

権限を付与または取り消した後、変更を有効にするために権限をリフレッシュする必要があります:

FLUSH PRIVILEGES;

ユーザー権限の確認

特定のユーザーの権限を確認するには、次のコマンドを使用できます:

SHOW GRANTS FOR 'username'@'host';

例

SHOW GRANTS FOR 'john'@'localhost';

権限の取り消し

ユーザーの権限を取り消すには、REVOKE コマンドを使用します:

REVOKE privileges ON database_name.* FROM 'username'@'host';

例

REVOKE ALL PRIVILEGES ON test_db.* FROM 'john'@'localhost';

ユーザーの削除

ユーザーを削除する必要がある場合は、次のコマンドを使用できます:

DROP USER 'username'@'host';

例

DROP USER 'john'@'localhost';

ユーザーのパスワード変更

ユーザーのパスワードを変更するには、ALTER USER コマンドを使用できます:

ALTER USER 'username'@'host' IDENTIFIED BY 'new_password';

例

ALTER USER 'john'@'localhost' IDENTIFIED BY 'newpassword456';

ユーザーのホスト変更

ユーザーのホスト（つまり、どのホストからの接続を許可するか）を変更するには、ユーザーを削除してから新しいユーザーを作成し直すことができます。

例

-- 古いユーザーを削除
DROP USER 'john'@'localhost';

-- ユーザーを再作成し、新しいホストを指定
CREATE USER 'john'@'%' IDENTIFIED BY 'password123';

ユーザー作成時の権限指定

ユーザー作成時に、同時に権限を付与することもできます（MySQL 8.0.16 以降）:

例

CREATE USER 'john'@'localhost' IDENTIFIED BY 'password123' WITH GRANT OPTION;
GRANT ALL PRIVILEGES ON test_db.* TO 'john'@'localhost';

/etc/my.cnf ファイルの設定

/etc/my.cnf ファイルは MySQL の設定ファイルであり、MySQL サーバーのさまざまなパラメータとオプションを設定するために使用されます。

通常、この設定ファイルを変更する必要はありません。このファイルのデフォルト設定は次のとおりです:

[mysqld]
datadir=/var/lib/mysql
socket=/var/lib/mysql/mysql.sock

[mysql.server]
user=mysql
basedir=/var/lib

[safe_mysqld]
err-log=/var/log/mysqld.log
pid-file=/var/run/mysqld/mysqld.pid

設定ファイルでは、エラーログファイルを格納するディレクトリを指定できます。通常、これらの設定を変更する必要はありません。

/etc/my.cnf ファイルは、システムや MySQL のバージョンによって異なる場合がありますが、通常は次のセクションが含まれます:

1. 基本設定

  • basedir: MySQL サーバーの基本インストールディレクトリ。
  • datadir: MySQL データファイルを保存する場所。
  • socket: MySQL サーバーの Unix ソケットファイルのパス。
  • pid-file: 現在実行中の MySQL サーバープロセスの ID を保存するファイルのパス。
  • port: MySQL サーバーがリッスンするポート番号。デフォルトは 3306 です。

2. サーバーオプション

  • bind-address: MySQL サーバーがリッスンする IP アドレスを指定します。IP アドレスまたはホスト名を指定できます。
  • server-id: レプリケーション設定において、各 MySQL サーバーに一意の識別子を設定します。
  • default-storage-engine: デフォルトのストレージエンジン。例: InnoDB や MyISAM。
  • max_connections: サーバーが同時に維持できる最大接続数。
  • thread_cache_size: スレッドキャッシュのサイズ。新しい接続の起動速度を向上させるために使用されます。
  • query_cache_size: クエリキャッシュのサイズ。同じクエリの効率を向上させるために使用されます。
  • default-character-set: デフォルトの文字セット。
  • collation-server: サーバーのデフォルトの照合順序。

3. パフォーマンスチューニング

  • innodb_buffer_pool_size: InnoDB ストレージエンジンのバッファプールサイズ。これは InnoDB パフォーマンスチューニングにおいて最も重要なパラメータの一つです。
  • key_buffer_size: MyISAM ストレージエンジンのキーバッファサイズ。
  • table_open_cache: 同時に開くことができるテーブルのキャッシュ数。
  • thread_concurrency: 同時に実行できるスレッド数。

4. セキュリティ設定

  • skip-networking: MySQL サーバーがネットワーク接続をリッスンすることを禁止し、ローカル接続のみを許可します。
  • skip-grant-tables: パスワードなしで MySQL サーバーを起動します。通常、忘れた root パスワードを回復するために使用されますが、セキュリティリスクがあります。
  • auth_native_password=1: MySQL 5.7 以降のネイティブパスワード認証を有効にします。

5. ログ設定

  • log_error: エラーログファイルのパス。
  • general_log: すべてのクライアント接続とクエリを記録するログ。
  • slow_query_log: 実行時間が特定のしきい値を超えるスロークエリを記録します。
  • log_queries_not_using_indexes: インデックスを使用しないクエリを記録します。

6. レプリケーション設定

  • master_host 和 master_user: マスターサーバーのアドレスとレプリケーションユーザー。
  • master_password: レプリケーションユーザーのパスワード。
  • master_log_file 和 master_log_pos: レプリケーションに使用するログファイルと位置。

    このコマンドは、MySQLデータベース管理システムのパフォーマンスおよび統計情報を出力します。

    新規ユーザー追加には GRANT コマンドを推奨

    一、通常のデータユーザーに、データベース内のすべてのテーブルデータを照会・挿入・更新・削除する権限を付与します。

    grant select on testdb.* to common_user@'%'
grant insert on testdb.* to common_user@'%'
grant update on testdb.* to common_user@'%'
grant delete on testdb.* to common_user@'%'

    または、1つのMySQLコマンドで置き換えます：

    grant select, insert, update, delete on testdb.* to common_user@'%'

    二、データベース開発者に、テーブル、インデックス、ビュー、ストアドプロシージャ、関数などの作成権限を付与します。

    MySQLデータテーブル構造の作成・変更・削除権限を付与します。

    grant create on testdb.* to developer@'192.168.0.%';
grant alter on testdb.* to developer@'192.168.0.%';
grant drop on testdb.* to developer@'192.168.0.%';

    MySQL外部キー操作権限を付与します。

    grant references on testdb.* to developer@'192.168.0.%';

    MySQL一時テーブル操作権限を付与します。

    grant create temporary tables on testdb.* to developer@'192.168.0.%';

    MySQLインデックス操作権限を付与します。

    grant index on testdb.* to developer@'192.168.0.%';

    MySQLビューの操作、ビューソースコードの参照権限を付与します。

    grant create view on testdb.* to developer@'192.168.0.%';
grant show view on testdb.* to developer@'192.168.0.%';

    MySQLストアドプロシージャ・関数の操作権限を付与します。

    grant create routine on testdb.* to developer@'192.168.0.%'; -- now, can show procedure status
grant alter routine on testdb.* to developer@'192.168.0.%'; -- now, you can drop a procedure
grant execute on testdb.* to developer@'192.168.0.%';

    三、通常のDBAに、特定のMySQLデータベースを管理する権限を付与します。

    grant all privileges on testdb to dba@'localhost'

    その中で、キーワードprivileges省略可能です。

    四、上級DBAに、MySQL内のすべてのデータベースを管理する権限を付与します。

    grant all on *.* to dba@'localhost'

    五、MySQL grant 権限は、それぞれ複数の階層に作用することができます。

    1. grant が MySQLサーバー全体に作用する場合：

    grant select on *.* to dba@localhost; -- dba 可以查询 MySQL 中所有数据库中的表。
grant all on *.* to dba@localhost; -- dba 可以管理 MySQL 中的所有数据库

    2. grant が単一のデータベースに作用する場合：

    grant select on testdb.* to dba@localhost; -- dba 可以查询 testdb 中的表。

    3. grant が単一のデータテーブルに作用する場合：

    grant select, insert, update, delete on testdb.orders to dba@localhost;

    ここで1人のユーザーに複数のテーブルを許可する場合、上記のステートメントを複数回実行できます。例えば：

    grant select(user_id,username) on smp.users to mo_user@'%' identified by '123345';
grant select on smp.mo_sms to mo_user@'%' identified by '123345';

    4. grant がテーブル内の列に作用する場合：

    grant select(id, se, rank) on testdb.apache_log to dba@localhost;

    5. grant がストアドプロシージャ・関数に作用する場合：

    grant execute on procedure testdb.pr_add to 'dba'@'localhost'
grant execute on function testdb.fn_add to 'dba'@'localhost'

    六、MySQLユーザー権限を表示します。

    現在のユーザー（自分）の権限を表示：

    show grants;

    他のMySQLユーザーの権限を表示：

    show grants for dba@localhost;

    七、MySQLユーザーに付与済みの権限を剥奪します。

    revoke は grant と構文がほぼ同じで、キーワードの to を from に置き換えるだけです：

    grant all on *.* to dba@localhost;
revoke all on *.* from dba@localhost;

    八、MySQL grant・revoke ユーザー権限に関する注意事項

    1. grant, revoke でユーザー権限を変更した後、そのユーザーがMySQLデータベースに再接続して初めて権限が有効になります。

    2. 許可されたユーザーが、これらの権限を他のユーザーにも grant できるようにしたい場合は、オプションが必要です。 grant option 
    grant select on testdb.* to dba@localhost with grant option;

    この機能は通常あまり使いません。実際には、データベース権限はDBAが一元管理するのが最善です。

    注意：作成完了後、以下のステートメントを実行する必要があります。FLUSH PRIVILEGESステートメント。

    InnoDB ストレージエンジン

    InnoDBはトランザクション型データベースの首选エンジンであり、トランザクションセーフテーブル（ACID）、行ロック、外部キーをサポートします。MySQL 5.5.5以降、InnoDBはデフォルトのストレージエンジンです。InnoDBの主な特徴は次のとおりです：

    1. InnoDBは、コミット、ロールバック、クラッシュリカバリ機能を備えたトランザクションセーフ（ACID互換）ストレージエンジンをMySQLに提供します。InnoDBは行レベルでロックし、SELECTステートメントではOracleに似たノンロッキング読み取りも提供します。これらの機能により、マルチユーザー展開とパフォーマンスが向上します。SQLクエリでは、InnoDBタイプのテーブルを他のMySQLテーブルタイプと自由に混在させることができ、同じクエリ内でも混在可能です。
    2. InnoDBは、膨大なデータ量を処理するための最大パフォーマンスを実現するように設計されています。そのCPU効率は、他のどのディスクベースのリレーショナルデータベースエンジンにも匹敵しない可能性があります。
    3. InnoDBストレージエンジンはMySQLサーバーと完全に統合されており、メインメモリにデータとインデックスをキャッシュするために独自のバッファプールを維持します。InnoDBはテーブルとインデックスを論理テーブルスペースに格納します。テーブルスペースには複数のファイル（またはRAWディスクパーティション）を含めることができます。これはMyISAMテーブルとは異なります。例えば、MyISAMテーブルでは各テーブルが個別のファイルに格納されます。InnoDBテーブルは、ファイルサイズが2GBに制限されているオペレーティングシステム上でも、任意のサイズにすることができます。
    4. InnoDBは外部キー整合性制約（FOREIGN KEY）をサポートします。テーブル内のデータを格納する際、各テーブルのストレージは主キー順に格納されます。テーブル定義で主キーが明示的に指定されていない場合、InnoDBは各行に対して6BのROWIDを生成し、それを主キーとして使用します。
    5. InnoDBは、高いパフォーマンスを必要とする多くの大規模データベースサイトで使用されています。InnoDBはディレクトリを作成しません。InnoDBを使用する場合、MySQLはMySQLデータディレクトリの下に、ibdata1という10MBサイズの自動拡張データファイルと、ib_logfile() および ib_logfile1 という5MBサイズの2つのログファイルを作成します。

    MyISAM ストレージエンジン

    MyISAMはISAMベースのストレージエンジンであり、それを拡張したものです。Web、データストレージ、およびその他のアプリケーション環境で最も一般的に使用されるストレージエンジンの1つです。MyISAMは挿入・クエリの速度が高いですが、トランザクションをサポートしていません。MySQL 5.5.5より前のバージョンでは、MyISAMがデフォルトのストレージエンジンです。MyISAMの主な特徴は次のとおりです：

    1. 大容量ファイル（最大63ビットのファイル長）は、大容量ファイルをサポートするファイルシステムおよびオペレーティングシステムでサポートされます。
    2. 削除、更新、挿入操作を混合して使用する場合、動的サイズの行はフラグメントをより少なく生成します。これは、隣接する削除されたブロックをマージし、次のブロックが削除された場合には次のブロックに拡張することによって自動的に行われます。
    3. 各MyISAMテーブルの最大インデックス数は64で、これはコンパイルによって変更することもできます。キー長が250Bを超える場合、1024Bを超えるキーが使用されます。
    4. BLOBおよびTEXT列はインデックス化できます。
    5. NULL値はインデックス化された列で許可されます。この値は各キーにつき0〜1バイトを占めます。
    6. すべての数値キー値は、より高いインデックス圧縮を可能にするために、高バイト優先で格納されます。
    7. 各テーブルに1つのAUTO_INCREMENT列の内部処理。MyISAMはINSERTおよびUPDATE操作のためにこの列を自動的に更新します。AUTO_INCREMENT列をより高速にします（少なくとも10%）。シーケンスの先頭の値が削除された後は再利用できません。
    8. データファイルとインデックスファイルを別々のディレクトリに置くことができます。
    9. 各文字カラムは異なる文字セットを持つことができます。
    10. VARCHARを持つテーブルは、固定または動的なレコード長にできます。
    11. VARCHAR および CHAR 列は最大 64KB まで可能です。

    MyISAM エンジンを使用してデータベースを作成すると、3つのファイルが生成されます。ファイル名はテーブル名で始まり、拡張子がファイルタイプを示します：frm ファイルはテーブル定義を格納し、データファイルの拡張子は .MYD（MYData）、インデックスファイルの拡張子は .MYI（MYIndex）です。

    MEMORY ストレージエンジン

    MEMORY ストレージエンジンはテーブルのデータをメモリ内に格納し、クエリや他のテーブルデータの参照に対して高速アクセスを提供します。MEMORY の主な特徴は次のとおりです：

    1. MEMORY テーブルの各テーブルは、最大32個のインデックス、各インデックス16列、および最大500Bのキー長を持つことができます。
    2. MEMORY ストレージエンジンは HASH および BTREE インデックスをサポートします。
    3. 1つの MEMORY テーブルに非一意キーを持つことができます。
    4. MEMORY は BLOB または TEXT 列をサポートしていません。
    5. MEMORY テーブルは固定レコード長フォーマットを使用します。
    6. MEMORY は AUTO_INCREMENT 列と、NULL 値を含む列のインデックスをサポートします。
    7. MEMORY テーブルの内容はメモリに格納されます。メモリは、MEMORY テーブルと、クエリ処理中にサーバーが作成する内部テーブルで共有されます。
    8. MEMORY テーブルは、すべてのクライアント間で共有されます（他の非 TEMPORARY テーブルと同様です）。
    9. MEMORY テーブルの内容が不要になった場合、MEMORY テーブルが使用しているメモリを解放するには、DELETE FROM または TRUNCATE TABLE を実行するか、テーブル全体を削除（DROP TABLE を使用）します。

    ユーザーの追加：

    insert into mysql.user(Host,User,Password) values("localhost","test",password("1234"));

    次のエラーが報告されます: ERROR 1364 (HY000): Field 'ssl_cipher' doesn't have a default value エラー

    エラーの原因：

    mysql ユーザーテーブルの一部のフィールドは null を許容しておらず、デフォルト値もありません。実際には操作ミスであり、mysql でユーザーを追加する際にこのように直接 user テーブルに insert することはできません。

    解決方法：

    正しいユーザー追加方法：

    GRANT USAGE ON *.* TO 'user01'@'localhost' IDENTIFIED BY '123456' WITH GRANT OPTION;

    ユーザー：user01、パスワード：123456。これで新しいユーザーが追加され、上記のエラーは発生しません。

    character-set-server = utf8

    この行は [mysqld] の下に置きます。

    !includedir /etc/mysql/conf.d/
!includedir /etc/mysql/mysql.conf.d/


[client]
default-character-set = utf8

[mysqld]
default-storage-engine = INNODB
character-set-server = utf8
collation-server = utf8_general_ci
