MySQL データ型

MySQL でデータフィールドの型を定義することは、データベースの最適化にとって非常に重要です。

MySQL は多くの型をサポートしており、大まかに3つのカテゴリに分けられます：数値、日付/時刻、文字列(キャラクタ)型です。

数値型

MySQL はすべての標準 SQL 数値データ型をサポートしています。

これらの型には、厳密な数値データ型（INTEGER、SMALLINT、DECIMAL、NUMERIC）と、近似数値データ型（FLOAT、REAL、DOUBLE PRECISION）が含まれます。

キーワード INT は INTEGER の同義語であり、キーワード DEC は DECIMAL の同義語です。

BIT データ型はビットフィールド値を保存し、MyISAM、MEMORY、InnoDB、BDB テーブルをサポートします。

SQL 標準の拡張として、MySQL は整数型 TINYINT、MEDIUMINT、BIGINT もサポートしています。次の表は、各整数型に必要なストレージと範囲を示しています。

型 サイズ 範囲（符号付き） 範囲（符号なし） 用途

日付と時刻型

時刻値を表す日付と時刻の型は、DATETIME、DATE、TIMESTAMP、TIME、YEAR です。

各時刻型には有効な値の範囲と「ゼロ」値があり、MySQL が表現できない不正な値が指定された場合に「ゼロ」値が使用されます。

TIMESTAMP 型には独自の自動更新機能があり、後で説明します。

型 サイズ
( bytes) 		範囲 形式 用途

YEAR 1 1901/2155 YYYY 年値

文字列型

文字列型とは、CHAR、VARCHAR、BINARY、VARBINARY、BLOB、TEXT、ENUM、SET を指します。この節では、これらの型の仕組みと、クエリでの使用方法について説明します。

型 サイズ 用途
CHAR 0-255 bytes 固定長文字列
VARCHAR 0-65535 bytes 可変長文字列
TINYBLOB 0-255 bytes 255 文字を超えないバイナリ文字列
TINYTEXT 0-255 bytes 短いテキスト文字列
BLOB 0-65 535 bytes バイナリ形式の長いテキストデータ
TEXT 0-65 535 bytes 長いテキストデータ
MEDIUMBLOB 0-16 777 215 bytes バイナリ形式の中程度の長さのテキストデータ
MEDIUMTEXT 0-16 777 215 bytes 中程度の長さのテキストデータ
LONGBLOB 0-4 294 967 295 bytes バイナリ形式の非常に大きなテキストデータ
LONGTEXT 0-4 294 967 295 bytes 非常に大きなテキストデータ

注意：char(n) と varchar(n) の括弧内の n は文字数を表し、バイト数を表しません。たとえば CHAR(30) は 30 文字を保存できます。

CHAR と VARCHAR は似ていますが、保存と取得の方法が異なります。最大長や末尾のスペースが保持されるかどうかなども異なります。保存または取得の際に大文字小文字の変換は行われません。

BINARY と VARBINARY は CHAR と VARCHAR に似ていますが、非バイナリ文字列ではなくバイナリ文字列を含む点が異なります。つまり、文字列ではなくバイト文字列を含みます。これは、文字セットを持たず、照合と比較が列値のバイトの数値に基づくことを意味します。

BLOB はバイナリラージオブジェクトであり、可変量のデータを格納できます。BLOB 型には TINYBLOB、BLOB、MEDIUMBLOB、LONGBLOB の4種類があります。それらの違いは、格納できる範囲が異なることです。

TEXT 型には TINYTEXT、TEXT、MEDIUMTEXT、LONGTEXT の4種類があります。この4つの BLOB 型に対応して、格納できる最大長が異なるため、実際の状況に応じて選択できます。

列挙型と集合型（Enumeration and Set Types）

  • ENUM: 列挙型。単一の値を格納するために使用され、事前定義された集合から1つを選択できます。
  • SET: 集合型。複数の値を格納するために使用され、事前定義された集合から複数を選択できます。

空間データ型（Spatial Data Types）

GEOMETRY, POINT, LINESTRING, POLYGON, MULTIPOINT, MULTILINESTRING, MULTIPOLYGON, GEOMETRYCOLLECTION: 空間データ（地理情報、幾何図形など）を格納するために使用されます。

    char、varchar、text について普段あまり気にしていませんでした。一般的に、今はみんな varchar を使っているかもしれません。しかし、保存する内容が比較的大きい場合、varchar と text のどちらを選ぶべきでしょうか？

    この3つの型の比較：

    • （1）char: char は言うまでもなく、固定長形式ですが、長さの範囲は 0〜255 です。255 未満の長さの文字を保存したい場合、MySQL は残りの文字をスペースで埋めます。そのため、データを読み取るときは、char 型のデータを処理して末尾のスペースを削除する必要があります。
    • （2）varchar: varchar については、最大長は 255 という説もあれば、65535 という説もあります。多くの資料を調べた結果、次のようになりました：varchar 型は 5.0.3 未満のバージョンでは最大長が 255 に制限されていますが、5.0.3 以降のバージョンでは varchar データ型の長さは 65535 までサポートされています。つまり、65532 バイト（バイトであって文字ではないことに注意！！！）のデータを格納できます（先頭ビットと終了ビットが3バイトを占めます）。つまり、5.0.3 未満のバージョンでは固定の TEXT または BLOB 形式で格納する必要があったデータを、新しいバージョンでは可変長の varchar で格納できるため、データベースファイルのサイズを効果的に削減できます。
    • （3）text: char や varchar と異なり、text はデフォルト値を持つことができません。その最大長は 2 の 16 乗 - 1 です。

    まとめると、いくつかのポイントがあります：

    • 頻繁に変化するフィールドには varchar を使用
    • 固定長が分かっている場合は char を使用
    • できる限り varchar を使用
    • 255 文字を超える場合は varchar または text のみを使用
    • varchar を使える場所では text を使わない

    FLOAT と DOUBLE の違い（単精度と倍精度の違いは何か）

    最も本質的な違い：単精度、つまり float は、32ビットマシンでは4バイトで格納されます。一方、倍精度の double は8バイトで格納されます。格納ビットが異なるため、表現できる数値の範囲が異なり、すなわち正確に表現できる数の桁数も異なります。

    1、占有するメモリが異なる

    単精度浮動小数点数は4バイト（32ビット）の記憶域を使用して1つの浮動小数点数を格納します。符号部1ビット、指数部8ビット、仮数部23ビットを含みます。

    一方、倍精度浮動小数点数は8バイト（64ビット）の記憶域を使用して1つの浮動小数点数を格納します。符号部1ビット、指数部11ビット、仮数部52ビットを含みます。

    2、格納できる数値の範囲が異なる

    単精度浮動小数点数の数値範囲は -3.4E38 ～ 3.4E38 です。一方、倍精度浮動小数点数が表現できる数値の絶対値の範囲はおおよそ -2.23E308 ～ 1.79E308 です。Eは10の何乗かを表し、例えば3.4E38は3.4×10の38乗を指します。

    3、10進数での桁数が異なる

    単精度浮動小数点数は最大で10進の有効数字7桁です。ある数の有効数字が7桁を超える場合、それを単精度変数として定義すると、超えた部分は自動的に四捨五入されます。

    倍精度浮動小数点数は10進で15または16桁の有効数字を表現でき、超えた部分も自動的に四捨五入されます。
