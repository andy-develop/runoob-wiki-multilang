MySQL トランザクション

MySQL トランザクションは主に、操作量が多く、複雑度の高いデータを処理するために使用されます。例えば、人事管理システムで、ある従業員を削除する場合、その従業員の基本情報を削除するだけでなく、その従業員に関連する情報（メールボックス、記事など）も削除する必要があります。このように、一連のデータベース操作文が1つのトランザクションを構成します！

MySQL では、トランザクションは一連のSQL文の実行であり、それらは単一の作業単位として扱われます。

  • MySQL では、Innodb データベースエンジンを使用しているデータベースまたはテーブルのみがトランザクションをサポートします。
  • トランザクション処理はデータベースの整合性を維持するために使用でき、一連の SQL 文がすべて実行されるか、すべて実行されないことを保証します。
  • トランザクションは管理に使用されますinsert、update、deleteステートメント

一般的に、トランザクションは4つの条件（ACID）を満たす必要があります：：原子性（Atomicity（または不可分割性）、一貫性（Consistency）、分離性（Isolation（また独立性）、永続性（Durability）。

  • 原子性：トランザクション内のすべての操作は、すべて完了するか、すべて完了しないかのどちらかであり、途中のある時点で終了することはありません。トランザクションの実行中にエラーが発生した場合は、トランザクションがまったく実行されなかったかのように、トランザクション開始前の状態にロールバックされます。

  • 一貫性：トランザクション開始前とトランザクション終了後で、データベースの整合性が損なわれていないこと。つまり、書き込まれるデータはすべての事前定義されたルールに完全に準拠している必要があります。これには、データの精度、連鎖性、および後続のデータベースが自発的に予定された処理を完了できることが含まれます。

  • 分離性：データベースが複数の同時トランザクションに対してデータの読み書きや変更を同時に行うことを許可する能力です。分離性は、複数のトランザクションが並行して実行される際に、交差実行によってデータの不整合が発生するのを防ぐことができます。トランザクション分離にはさまざまなレベルがあり、読取り未コミット（Read uncommitted）、読取りコミット（read committed）、反復可能読取り（repeatable read）、直列化（Serializable）が含まれます。

  • 永続性：トランザクション処理が終了した後、データへの変更は永久的なものになります。システム障害が発生しても失われることはありません。

MySQL コマンドラインのデフォルト設定では、トランザクションはすべて自動コミットされます。つまり、SQL 文を実行するとすぐに COMMIT 操作が実行されます。したがって、明示的にトランザクションを開始するには、コマンド BEGIN または START TRANSACTION を使用するか、コマンド SET AUTOCOMMIT=0 を実行して現在のセッションの自動コミットを無効にする必要があります。

トランザクション制御文：

  • BEGIN または START TRANSACTION はトランザクションを明示的に開始します；

  • COMMIT は COMMIT WORK を使用することもできますが、両者は同等です。COMMIT はトランザクションをコミットし、データベースに加えられたすべての変更を永久的なものにします；

  • ROLLBACK は ROLLBACK WORK を使用することもできますが、両者は同等です。ロールバックはユーザーのトランザクションを終了し、進行中のすべての未コミットの変更を元に戻します；

  • SAVEPOINT identifier は、トランザクション内にセーブポイントを作成できます。1つのトランザクションには複数の SAVEPOINT を設定できます；

  • RELEASE SAVEPOINT identifier は、トランザクションのセーブポイントを削除します。指定されたセーブポイントがない場合、この文を実行すると例外がスローされます；

  • ROLLBACK TO identifier はトランザクションをマークポイントにロールバックします；

  • SET TRANSACTION はトランザクションの分離レベルを設定するために使用されます。InnoDB ストレージエンジンが提供するトランザクションの分離レベルは、READ UNCOMMITTED、READ COMMITTED、REPEATABLE READ、SERIALIZABLE です。

MYSQL トランザクション処理には主に2つの方法があります：

1、BEGIN、ROLLBACK、COMMIT を使用して実現する

  • BEGIN または START TRANSACTION：トランザクションを開始するために使用します。
  • ROLLBACKトランザクションのロールバック。以前の変更を取り消します。
  • COMMIT：トランザクションを確認し、コミットして、変更を永久的に有効にします。

2、SET を使用して MySQL の自動コミットモードを直接変更する：

  • SET AUTOCOMMIT=0自動コミットを無効にする
  • SET AUTOCOMMIT=1自動コミットを有効にする

BEGIN または START TRANSACTION-- トランザクションを開始するために使用します：

BEGIN; -- 或者使用 START TRANSACTION;

COMMIT-- トランザクションをコミットし、すべての変更をデータベースに永久的に保存するために使用します：

COMMIT;

ROLLBACK-- トランザクションをロールバックし、最後のコミット以降に行われたすべての変更を元に戻すために使用します：

ROLLBACK;

SAVEPOINT-- トランザクション内にセーブポイントを設定し、後でそのポイントにロールバックできるようにするために使用します：

SAVEPOINT savepoint_name;

ROLLBACK TO SAVEPOINT-- 以前に設定したセーブポイントにロールバックするために使用します：

ROLLBACK TO SAVEPOINT savepoint_name;

次に、簡単な MySQL トランザクションの例を示します：

例

-- トランザクションを開始
START TRANSACTION;

-- いくつかのSQL文を実行
UPDATE accounts SET balance = balance - 100 WHERE user_id = 1;
UPDATE accounts SET balance = balance + 100 WHERE user_id = 2;

-- コミットするかロールバックするかを判断
IF (条件) THEN
    COMMIT; -- トランザクションをコミット
ELSE
    ROLLBACK; -- トランザクションをロールバック
END IF;

簡単なトランザクションの例：

トランザクションテスト

mysql> use RUNOOB; Database changed mysql> CREATE TABLE runoob_transaction_test( id int(5)) engine=innodb; # データテーブルを作成 Query OK, 0 rows affected (0.04 sec) mysql> select * from runoob_transaction_test; Empty set (0.01 sec) mysql> begin; # トランザクションを開始 Query OK, 0 rows affected (0.00 sec) mysql> insert into runoob_transaction_test value(5); Query OK, 1 rows affected (0.01 sec) mysql> insert into runoob_transaction_test value(6); Query OK, 1 rows affected (0.00 sec) mysql> commit; # トランザクションをコミット Query OK, 0 rows affected (0.01 sec) mysql> select * from runoob_transaction_test; +------+ | id | +------+ | 5 | | 6 | +------+ 2 rows in set (0.01 sec) mysql> begin; # トランザクションを開始 Query OK, 0 rows affected (0.00 sec) mysql> insert into runoob_transaction_test values(7); Query OK, 1 rows affected (0.00 sec) mysql> rollback; # ロールバック Query OK, 0 rows affected (0.00 sec) mysql> select * from runoob_transaction_test; # ロールバックしたため、データは挿入されませんでした +------+ | id | +------+ | 5 | | 6 | +------+ 2 rows in set (0.01 sec) mysql>

    セーブポイント SAVEPOINT を使用する

    savepoint は、データベースのトランザクション処理において「サブトランザクション」（subtransaction）、別名ネストされたトランザクションを実装する方法です。トランザクションは savepoint の作成前の変更に影響を与えずに savepoint までロールバックでき、トランザクション全体を破棄する必要はありません。

    ROLLBACK によるロールバックでは、セーブポイント SAVEPOINT を設定できます。複数の操作を実行する場合、任意の文の前にロールバックできます。

    SAVEPOINT の使用

    SAVEPOINT savepoint_name;    // 声明一个 savepoint

ROLLBACK TO savepoint_name;  // 回滚到savepoint

    SAVEPOINT の削除

    セーブポイントは、トランザクション処理の完了（ROLLBACK または COMMIT の実行）後に自動的に解放されます。

    MySQL5 以降、次を使用できます：

    RELEASE SAVEPOINT savepoint_name;  // 删除指定保留点

    例えば、次のようなゲームがあるとします。ゲームは個々のステージに分かれており、1つのステージ内で多くのボスを倒さないとクリアできません。各ステージをクリアすると、ゲームは自動的にゲームの進行状況を記録し、ゲームの進行状況をリモートサーバーにアップロードします。ゲームをリセットしない限り、ゲームの進行状況を元に戻すことはできません。

    原子性：最小の操作ロジックであり、これ以上分割できません。ゲームの1つのステージのようなもので、ステージ内でどこまで進んでも、失敗したらステージの前に戻るだけです。

    トランザクションは、一連のデータベース操作を1つのステージ（1つの原子操作）に包み込みます。ステージをクリアするか、ステージの前に戻るかのどちらかです。

    永続性：トランザクションの実行が完了すると（トランザクションのコミット）、その操作はデータベース内のデータを永久的に変更します。つまり、ステージをクリアすると、ゲームの進行状況がサーバーに永久的に保存されます。

    トランザクションは AID、すなわち原子性、分離性、永続性を保証できます。ただし、一貫性はトランザクションによって保証することはできません。一貫性はアプリケーション層、開発者に依存します。
