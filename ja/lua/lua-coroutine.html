Lua コルーチン(coroutine)

コルーチンとは？

Lua のコルーチンはスレッドと比較的似ています。独立したスタック、独立したローカル変数、独立した命令ポインタを持ち、同時に他のコルーチンとグローバル変数やその他のほとんどのものを共有します。

コルーチンは特殊なスレッドと理解でき、その実行を一時停止・再開できるため、非プリエンプティブなマルチタスク処理を可能にします。

コルーチンは非常に強力な機能ですが、使い方は複雑でもあります。

基本構文

コルーチンはcoroutineモジュールによってサポートされています。

コルーチンを使用すると、関数内でcoroutine.create新しいコルーチンオブジェクトを作成し、使用してcoroutine.resumeその実行を開始します。コルーチンは呼び出すことでcoroutine.yield自らの実行を能動的に一時停止し、制御を呼び出し元に返します。

メソッド説明
coroutine.create()coroutine を作成し、coroutine を返します。引数は関数で、resume と組み合わせて使用すると関数呼び出しを起動します。
coroutine.resume()coroutine を再起動します。create と組み合わせて使用します。
coroutine.yield()coroutine を一時停止し、coroutine を一時停止状態に設定します。これは resume と組み合わせると多くの有用な効果が得られます。
coroutine.status()coroutine の状態を確認します。
注: coroutine の状態には dead、suspended、running の3つがあります。具体的にいつこのような状態になるかは、以下のプログラムを参照してください。
coroutine.wrap（）coroutine を作成し、関数を返します。この関数を呼び出すと coroutine に入ります。create と同じ機能です。
coroutine.running()実行中の coroutine を返します。coroutine はスレッドであり、running を使用すると coroutine のスレッドIDを返します。

以下の例では、Lua コルーチンの使用方法を示します。

例

function foo()
    print("コルーチン foo の実行を開始")
    local value = coroutine.yield("foo の実行を一時停止")
    print("コルーチン foo の実行を再開、渡された値: " .. tostring(value))
    print("コルーチン foo の実行を終了")
end

-- コルーチンを作成
local co = coroutine.create(foo)

-- コルーチンを起動
local status, result = coroutine.resume(co)
print(result) -- 出力: foo の実行を一時停止

-- コルーチンの実行を再開し、値を渡す
status, result = coroutine.resume(co, 42)
print(result) -- 出力: コルーチン foo の実行を再開、渡された値: 42

上記の例では、foo という名前の関数をコルーチンとして定義しました。関数内で coroutine.yield を使用してコルーチンの実行を一時停止し、値を返しました。

。メインプログラムでは、coroutine.create を使用してコルーチンオブジェクトを作成し、coroutine.resume を使用してその実行を開始しました。

最初の coroutine.resume 呼び出し後、コルーチンは coroutine.yield の位置で一時停止し、値をメインプログラムに返します。次に、coroutine.resume を再度呼び出し、コルーチンが実行を再開するときの引数として値を渡します。

上記のコードを実行すると、出力結果は次のようになります。

协同程序 foo 开始执行
暂停 foo 的执行
协同程序 foo 恢复执行，传入的值为: 42
协同程序 foo 结束执行
nil

注意すべき点は、コルーチンの状態は coroutine.status 関数で取得でき、状態を確認することでコルーチンの実行状況（実行中、一時停止中、終了済みなど）を判断できることです。

coroutine.running を見ればわかるように、coroutine は内部実装的にはスレッドです。

create で coroutine を作成するときは、新しいスレッドにイベントを登録することです。

resume を使用してイベントをトリガーすると、create した coroutine 関数が実行されます。yield に遭遇すると現在のスレッドを一時停止し、再び resume でイベントがトリガーされるのを待ちます。

次に、より詳細な例を分析します。

例

function foo (a)
    print("foo 関数の出力", a)
    return coroutine.yield(2 * a) -- 2*a の値を返す
end
 
co = coroutine.create(function (a , b)
    print("最初のコルーチン実行の出力", a, b) -- co-body 1 10
    local r = foo(a + 1)
     
    print("2回目のコルーチン実行の出力", r)
    local r, s = coroutine.yield(a + b, a - b)  -- a、b の値は最初のコルーチン呼び出し時に渡されます。
     
    print("3回目のコルーチン実行の出力", r, s)
    return b, "コルーチンを終了"                   -- b の値は2回目のコルーチン呼び出し時に渡されます。
end)
       
print("main", coroutine.resume(co, 1, 10)) -- true, 4
print("--区切り線----")
print("main", coroutine.resume(co, "r")) -- true 11 -9
print("---区切り線---")
print("main", coroutine.resume(co, "x", "y")) -- true 10 end
print("---区切り線---")
print("main", coroutine.resume(co, "x", "y")) -- cannot resume dead coroutine
print("---区切り線---")

上記の例の説明は以下のとおりです。

  • resume を呼び出してコルーチンを起動します。resume 操作は成功すると true を返し、そうでなければ false を返します。
  • コルーチンが実行されます。
  • yield ステートメントまで実行されます。
  • yield がコルーチンを一時停止し、最初の resume が戻ります。（注: ここでの yield の戻り値は resume の引数です。）
  • 2回目の resume で再びコルーチンを起動します。（注: ここでの resume の引数のうち、最初の引数以外は yield の引数になります。）
  • yield が戻ります。
  • コルーチンは実行を継続します。
  • 使用しているコルーチンが実行を完了した後に resume メソッドを呼び続けると、cannot resume dead coroutine と出力されます。

resume と yield の組み合わせの強力な点は、resume がメインプログラムにあり、外部の状態（データ）をコルーチン内部に渡すことです。一方、yield は内部の状態（データ）をメインプログラムに返します。

プロデューサー・コンシューマー問題

ここで Lua のコルーチンを使用して、プロデューサー・コンシューマーという古典的な問題を解決します。

例

local newProductor

function productor()
     local i = 0
     while true do
          i = i + 1
          send(i)     -- 生産したアイテムをコンシューマーに送信する
     end
end

function consumer()
     while true do
          local i = receive()     -- プロデューサーからアイテムを受け取る
          print(i)
     end
end

function receive()
     local status, value = coroutine.resume(newProductor)
     return value
end

function send(x)
     coroutine.yield(x)     -- x は送信する値を表し、値を返した後、そのコルーチンを一時停止します。
end

-- プログラムを起動
newProductor = coroutine.create(productor)
consumer()

スレッドとコルーチンの違い

スレッドとコルーチンの主な違いは、複数のスレッドを持つプログラムは複数のスレッドを同時に実行できますが、コルーチンは互いに協調して実行する必要があることです。

任意の指定された時点で実行されているコルーチンは1つだけであり、実行中のコルーチンは明示的に一時停止を要求された場合にのみ一時停止されます。

コルーチンは同期マルチスレッドに少し似ており、同じスレッドロックを待機する複数のスレッドはコルーチンに少し似ています。

主な違いは次のようにまとめられます。

  • スケジューリング方式: スレッドは通常、オペレーティングシステムのスケジューラによるプリエンプティブスケジューリングで、OS は異なるスレッド間で実行権を切り替えます。一方、コルーチンは非プリエンプティブスケジューリングであり、プログラマーが明示的に実行権の移行を制御します。

  • 並行性: スレッドは並行実行され、複数のスレッドが複数のプロセッサコア上で同時に実行されたり、タイムスライス方式で単一コア上で切り替えて実行されたりします。コルーチンは協調的であり、実行状態にあるコルーチンは1つだけで、他のコルーチンは現在のコルーチンが自ら実行権を放棄するのを待たなければなりません。

  • メモリ使用量: スレッドは通常、独立したスタックとコンテキスト環境が必要なため、スレッドの作成と破棄には余分なオーバーヘッドが伴います。一方、コルーチンは同じスタックとコンテキストを共有できるため、作成と破棄のオーバーヘッドは小さくなります。

  • データ共有: スレッド間ではメモリ空間を共有できますが、スレッドセーフティと同期の問題に注意する必要があります。コルーチンは通常、引数の受け渡しと戻り値によってデータ共有を行い、異なるコルーチン間のデータ分離性は良好です。

  • デバッグとエラー処理: スレッドは通常、デバッグとエラー処理がより複雑です。複数のスレッド間の相互作用と並行実行がデバッグしにくい問題を引き起こす可能性があるためです。コルーチンは、プログラマが実行フローを明示的に制御するため、デバッグとエラー処理が比較的簡単です。

全体的に、スレッドは並行実行が必要なシナリオに適しています。例えば、マルチコアプロセッサ上で並列性を利用してタスクの実行速度を向上させる場合です。一方、コルーチンは協調と調整が必要なシナリオに適しています。例えば、ステートマシン、イベント駆動プログラミング、協調的タスク処理などです。スレッドとコルーチンのどちらを選択するかは、具体的なアプリケーションの要件とプログラミングモデルに依存します。

    本文中の例の分析：

    最初の呼び出し（最初の呼び出し時、コルーチンは一時停止状態です）、resume の引数 1,10 が本体関数に渡され、1,10 が出力されます。その後 foo を呼び出して 2 が出力され、プログラムが一時停止し、その後この値が resume に返され、2番目の引数として値 4 になります。

    2回目の resume 呼び出しの引数は r で、メイン関数のprint("第二次协同程序执行输出", r)から実行を開始します。このときの状態は一時停止状態であるため、resume の引数が yield に渡され、一時停止ポイントの戻り値として r になります。

    そのため r が出力され、その後実行を続けて、次を実行します：local r, s = coroutine.yield(a + b, a - b)このとき、resume から直接呼び出された場合ではないため、yield 関数はメイン関数に渡された a,b 引数をパラメータとして使用し、結果は 11, -9 となり、その後再び一時停止します。

    結果：r 11 -9

    3回目の resume 呼び出しの引数は x, y で、プログラムの一時停止ポイントから実行し、引数は yield に渡されます。このとき yield は戻り値ポイントとして機能するため、r,s の結果は x, y になります。その後、実行を続けて return b, "结束协同程序" を実行し、b として 10 を返します。

    結果：x,y true, 10

    まとめ： resume の実行時、それが（最初の実行を除いて）一時停止状態である場合、resume の引数は yield に渡されます。yield は、パラメータ式の形式に関係なく、resume が渡したすべての引数を値として返します。

    特に注意すべきこととして、実行後に再び一時停止した場合、そのとき yield に渡される値は、メイン関数のパラメータ値です（使用する場合）。

    resume の実行が最初の場合（前述の最初の一時停止という特殊なケースは除く）、または一時停止後に再び実行される場合、resume の引数はメイン関数のパラメータとして渡されます。
