ストレージピラミッド -- なぜこれほど多くの層に分けるのか

なぜパソコンには「メモリ」と「ハードディスク」の両方があるのか、考えたことはありますか？なぜすべてのデータを最速の場所に置かないのでしょうか？

答えはコンピュータのストレージシステムの設計に隠されています——ストレージピラミッド。この講義では、アーキテクトにとって最も核心的なトレードオフの知恵を徹底的に理解します。

身近な例え：キッチン vs スーパーの倉庫

料理をするときの食材の配置を使って、まず直感的なイメージを掴みましょう。

あなたが料理をしているところを想像してください。

塩と醤油はコンロのそばに置いて、手を伸ばせば届く——これらはコンピュータのレジスタ和L1キャッシュ。

冷蔵庫の中の食材は、数歩歩いて取りに行く必要がある——これはメモリ（RAM）。

地下室に備蓄した米や麺、油などの食料は、わざわざ取りに行かなければならない——これはソリッドステートドライブ（SSD）。

そしてスーパーの倉庫にある在庫は、家に置くことすらしない——それはハードディスクドライブ（HDD）とクラウドストレージです。

これは素朴な原則を明らかにしています：よく使うものほど近い場所に置くが、近い場所はスペースが限られていて高価でもある；あまり使わないものは遠くに置き、容量が大きくより安価である。

コンピュータのストレージシステムは、まさにこの素朴な原則に従って設計されています。

ストレージピラミッド：速度と容量のトレードオフ

コンピュータ内部では、ストレージデバイスが「速度-容量-コスト」の段階的な関係に従って、ピラミッド構造を形成しています。

runoob ストレージピラミッド図 — diagram-design 仕様 SVG：紙色の背景 + ヘアラインの層分割、錆赤のアクセントは最上層のレジスタのみをマーク
マウスホバー時の詳細オーバーレイ

ストレージピラミッド模式図：上に行くほど速く小さく、下に行くほど遅く大きい。台形にマウスをホバーすると各層の詳細を確認できます。

核心となる原則

このピラミッド図は、ハードウェア設計における鉄則を明らかにしています：

  • 速いほど高価で、小さい：レジスタはCPU内部にあり、最速のトランジスタで作られていますが、わずか数キロバイトしかありません。チップ面積が非常に高価だからです。
  • 遅いほど安価で、大きい：ハードディスクドライブは磁気ヘッドと回転するプラッタを使用し、コストが極めて低く、数十TBのデータを格納できます。
  • ピラミッド構造の目的：「小さく速い + 大きく遅い」の組み合わせにより、合理的なコストで最速ストレージに近い体験を実現することです。

もしパソコンのストレージをすべてレジスタで作ったら、価格は天文学的な額になるだけでなく、チップ面積も大きくなりすぎて製造できなくなります。

逆に、すべてハードディスクドライブにしたら、パソコンは使えないほど遅くなります——どのプログラムを開くにも数百ミリ秒待たなければなりません。

各層の詳細な比較

7層のストレージの主要な属性を1つの表にまとめ、横方向の比較を容易にします。

階層代表的な容量アクセスレイテンシ相対速度物理的な位置製造コスト
レジスタ~1 KB~0.3 ns1x（基準）CPUコア内極めて高い
L1キャッシュ~64 KB~1 nsレジスタより3倍遅いCPUコア内部極めて高い
L2キャッシュ~256 KB~4 ns13倍遅いCPUコア内部非常に高い
L3キャッシュ~8 MB~12 ns40倍遅いCPUチップ上、マルチコアで共有高
メモリ (RAM)~16 GB~100 ns333倍遅いマザーボード上（独立したチップ）中程度
ソリッドステートドライブ (SSD)~1 TB~100 μs333,333倍遅い筐体内部（独立したデバイス）比較的低い
ハードディスクドライブ (HDD)~10 TB~10 ms33,333,333倍遅い筐体内部（独立したデバイス）低

桁の飛躍に注目してください：メモリはL1キャッシュより100倍遅く、SSDはメモリよりさらに1000倍遅く、HDDはSSDよりさらに100倍遅いです。各層間の速度差は桁違いです。

なぜSSDはHDDよりこれほど速いのか？

重要な違いは機械部品の有無です。

SSDはフラッシュメモリチップを使用し、純粋に電子的に読み取るため、機械部品がありません。

HDDは回転するプラッタと移動する磁気ヘッドを使用します——データを読み取るには、磁気ヘッドがまず正しいトラックに移動し（シーク時間、約5-10ms）、その後プラッタが正しい位置に回転するのを待つ必要があります（回転レイテンシ、約2-4ms）。

この機械的な移動プロセスこそ、HDDがSSDより100倍以上遅い根本的な原因です。

ピラミッドはどのように機能するか：層ごとのキャッシュ戦略

ピラミッドは静的ではない——そこには自動的に機能するデータの流れの仕組みがある。

データの流れのルール

  1. CPUがデータを必要とするとき：まず最速のL1キャッシュを探し、見つからなければL2へ、さらに見つからなければL3へ、メインメモリに至るまで。
  2. 遅い階層からデータを読み取った後：データをCPUに渡すだけでなく、より高速な階層にもコピーを保存する。そうすれば次回使うとき速い。
  3. 高速な階層がいっぱいになったらどうするか：一定の戦略（LRU——最も長く使われていないものを追い出す）に従って、使用頻度の低いデータを低速階層に戻し、新しいデータのための場所を空ける。

このプロセスはプログラマにとって完全に透過的である——プログラムを書くときにどのキャッシュを手動で管理する必要はなく、ハードウェアとOSが自動的にすべて行う。

現実世界の例

あなたがビデオファイルを編集中だとしよう：

  • ビデオファイルはHDDまたはSSDに存在する（最下層）。
  • ファイルを開くと、OSはその一部をメモリ（RAM）に読み込む。
  • 再生を開始すると、CPUは現在処理中の数フレームのデータをL3/L2/L1キャッシュにコピーする。
  • ALUによって計算中のピクセル値は、レジスタに存在する。

編集ソフトウェアで「とてもスムーズ」と感じるのは、ほとんどの場合CPUが必要なデータをキャッシュ内で見つけられるからである。

歴史的背景：ピラミッドはなぜこのような形なのか

ピラミッドの階層数は、CPUとメモリの速度差が拡大し続けた歴史的産物である。

1980年代には、CPUとメモリの速度差は大きくなかった。しかし半導体プロセスの進歩により、CPUの速度は年間約60%の割合で増加した一方、メモリの速度は年間約10%しか増加しなかった。

この拡大し続ける差は、「メモリウォール」（Memory Wall）と呼ばれる。

メモリピラミッドは、エンジニアたちが「メモリウォール」に対して取った対策である——多段階キャッシュでCPUとメインメモリの間の速度ギャップを緩和する。

年代CPUクロック周波数メモリレイテンシ速度差キャッシュ階層
1980s~10 MHz~200 ns約2倍なしまたは1階層
1990s~200 MHz~70 ns約14倍L1 + L2
2000s~3 GHz~50 ns約150倍L1 + L2 + L3
2020s~5 GHz~80 ns約400倍L1 + L2 + L3

メモリレイテンシは40年間で本質的にほとんど変わっていないことに注目！メモリが進歩していないのではなく、CPUの進歩があまりにも速すぎるのだ。メモリの物理的限界（コンデンサの充放電速度）により、そのレイテンシは大幅に短縮することが難しい。
