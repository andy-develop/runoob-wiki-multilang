C++ 変数スコープ

一般的に、変数を定義できる場所は3つあります：

  • 関数またはコードブロック内で宣言された変数は、ローカル変数と呼ばれます。。

  • 関数パラメータの定義で宣言された変数は、仮引数と呼ばれます。。

  • すべての関数の外部で宣言された変数は、グローバル変数と呼ばれます。。

スコープはプログラムの領域です。変数のスコープは次のように分類できます：

  • ローカルスコープ：関数内で宣言された変数はローカルスコープを持ち、関数内からのみアクセスできます。ローカル変数は関数が呼び出されるたびに作成され、関数の実行が完了すると破棄されます。

  • グローバルスコープ：すべての関数とコードブロックの外で宣言された変数はグローバルスコープを持ち、プログラム内の任意の関数からアクセスできます。グローバル変数はプログラムの開始時に作成され、プログラムの終了時に破棄されます。

  • ブロックスコープ：コードブロック内で宣言された変数はブロックスコープを持ち、コードブロック内からのみアクセスできます。ブロックスコープ変数はコードブロックが実行されるたびに作成され、コードブロックの実行が完了すると破棄されます。

  • クラススコープ：クラス内で宣言された変数はクラススコープを持ち、クラスのすべてのメンバ関数からアクセスできます。クラススコープ変数のライフサイクルはクラスのライフサイクルと同じです。

注意：内部スコープで宣言された変数が外部スコープの変数と同じ名前の場合、内部スコープの変数は外部スコープの変数を覆い隠します。

ローカル変数

関数またはコードブロック内で宣言された変数は、ローカル変数と呼ばれます。これらは関数内またはコードブロック内のステートメントでのみ使用できます。次の例ではローカル変数を使用しています：

例

#include <iostream> using namespace std; int main () { // ローカル変数の宣言 int a, b; int c; // 実際の初期化 a = 10; b = 20; c = a + b; cout << c; return 0; }

グローバル変数

すべての関数の外部で定義された変数（通常はプログラムの先頭）は、グローバル変数と呼ばれます。グローバル変数の値は、プログラムの全期間を通じて有効です。

グローバル変数は任意の関数からアクセスできます。つまり、グローバル変数は一度宣言されると、プログラム全体で使用できます。次の例では、グローバル変数とローカル変数を使用しています：

例

#include <iostream> using namespace std; // グローバル変数の宣言 int g; int main () { // ローカル変数の宣言 int a, b; // 実際の初期化 a = 10; b = 20; g = a + b; cout << g; return 0; }

プログラム内では、ローカル変数とグローバル変数の名前は同じにできますが、関数内では、ローカル変数の値がグローバル変数の値を覆い隠します。以下に例を示します：

例

#include <iostream> using namespace std; // グローバル変数の宣言 int g = 20; int main () { // ローカル変数の宣言 int g = 10; cout << g; return 0; }

上記のコードがコンパイルおよび実行されると、次の結果が生成されます：

10

ローカル変数とグローバル変数の初期化

ローカル変数が定義されたとき、システムはそれを初期化しないため、自分で初期化する必要があります。グローバル変数を定義するとき、システムは自動的に次の値に初期化します：

データ型初期化のデフォルト値
int 0
char '\0'
float 0
double 0
pointer NULL

変数を正しく初期化することは良いプログラミング習慣です。そうしないと、プログラムが予期しない結果を生むことがあります。

ブロックスコープとは、コードブロック内で宣言された変数を指します：

例

#include <iostream>

int main() {
    int a = 10;
    {
        int a = 20;  // ブロックスコープ変数
        std::cout << "ブロック変数: " << a << std::endl;
    }
    std::cout << "外部変数: " << a << std::endl;
    return 0;
}

上記の例では、内部のコードブロック内で a という名前の変数が宣言されており、これは外部スコープの変数 a と同じ名前です。内部スコープの変数 a は外部スコープの変数 a を覆い隠し、内部スコープで a にアクセスすると 20 が出力され、外部スコープで a にアクセスすると 10 が出力されます。

上記のコードがコンパイルおよび実行されると、次の結果が生成されます：

块变量: 20
外部变量: 10

クラススコープ

クラススコープとは、クラス内で宣言された変数を指します：

例

#include <iostream>

class MyClass {
public:
    static int class_var;  // クラススコープ変数
};

int MyClass::class_var = 30;

int main() {
    std::cout << "クラス変数: " << MyClass::class_var << std::endl;
    return 0;
}

上記の例では、MyClass クラス内に class_var という名前のクラススコープ変数が宣言されています。クラス名とスコープ解決演算子を使用して、::この変数にアクセスできます。main() 関数内で class_var にアクセスすると 30 が出力されます。

    #include <iostream>

    {
        int b = 1;

    b = 1

    静的変数

    静的データ領域に格納される変数は、プログラムの実行開始時に初期化が完了します。これが唯一の初期化です。静的記憶域に格納される変数には、グローバル変数と static 変数の2種類があります。ただし、グローバル変数と比較すると、static は変数の可視範囲を制御できます。要するに static は隠すために使われます。この使い方は一般的ではありませんが。

    PS：static ローカル変数として関数内で定義された場合、その寿命はソースプログラム全体ですが、そのスコープは自動変数と同じで、その変数を定義した関数内でのみ使用できます。その関数を退出した後、その変数は存在し続けますが、使用することはできません。

    #include <iostream>
using namespace std;

int count = 1; //全局变量

int fun()
{
    static int count = 10; // 在第一次进入这个函数的时候，变量 count 被初始化为 10！并接着自减 1，以后每次进入该函数，count 的值是上一次函数运行之后的值
    return count--;        // 就不会被再次初始化了，仅进行自减 1 的操作；在 static 发明前，要达到同样的功能，则只能使用全局变量
}
 
//int count = 1; //全局变量
 
int main()
{
     cout<<"global  "<<"local staic"<<endl;
     for(; count <= 10; ++count)
        cout<<count<<"        "<<fun()<<endl;
     return 0;
}

    また、このことから、グローバル変数とローカル静的変数 count のスコープは異なることがわかります。

    C++ グローバル変数、ローカル変数、静的グローバル変数、静的ローカル変数の違い

    C++ の変数は、定義された位置に応じてライフサイクルが異なり、異なるスコープを持ちます。スコープは6種類に分類できます：グローバルスコープ，ローカルスコープ，ステートメントスコープ，クラススコープ，名前空間スコープとファイルスコープ。

    スコープの観点から見ると：

    グローバル変数はグローバルスコープを持ちます。グローバル変数は1つのソースファイルで定義するだけで、すべてのソースファイルに作用します。もちろん、そのグローバル変数の定義を含まない他のソースファイルでは、extern キーワードを使用してこのグローバル変数を再宣言する必要があります。

    静的ローカル変数はローカルスコープを持ち、一度だけ初期化されます。最初に初期化されてからプログラムの実行が終了するまで存在し続けます。グローバル変数との違いは、グローバル変数はすべての関数に対して可視ですが、静的ローカル変数はそれを定義した関数本体に対してのみ常に可視であることです。

    ローカル変数もローカルスコープのみを持ち、自動オブジェクト（auto）です。プログラムの実行中ずっと存在するわけではなく、関数の実行中にのみ存在します。関数の1回の呼び出しの実行が終了すると、変数は破棄され、占有していたメモリも回収されます。

    静的グローバル変数もグローバルスコープを持ちますが、グローバル変数との違いは、プログラムが複数のファイルを含む場合、それが定義されているファイル内でのみ作用し、他のファイルには作用しないことです。つまり、static キーワードで修飾された変数はファイルスコープを持ちます。そのため、2つの異なるソースファイルで同じ名前の静的グローバル変数が定義されていても、それらは異なる変数です。

    メモリ空間の割り当ての観点から見ると：

    グローバル変数、静的ローカル変数、静的グローバル変数はすべて静的記憶域にスペースが割り当てられ、ローカル変数はスタックにスペースが割り当てられます。

    グローバル変数自体が静的記憶方式であり、静的グローバル変数ももちろん静的記憶方式である。この両者は記憶方式において違いはない。両者の違いは、非静的グローバル変数のスコープがソースプログラム全体にあることであり、ソースプログラムが複数のソースファイルで構成される場合、非静的グローバル変数は各ソースファイル内で有効である。一方、静的グローバル変数はそのスコープが制限され、すなわちその変数を定義したソースファイル内でのみ有効であり、同じソースプログラムの他のソースファイルでは使用できない。静的グローバル変数のスコープは1つのソースファイル内に限られるため、そのソースファイル内の関数だけが共用でき、他のソースファイルでエラーを引き起こすことを回避できる。

    • 1) 静的変数はプログラムの静的データ格納領域（データセグメント）（グローバルから見える）に置かれるため、次回の呼び出し時にも以前の代入値を保持できる。この点がスタック変数およびヒープ変数との違いである。
    • 2) staticはコンパイラに対して、自分が変数のスコープ範囲内でのみ見えることを知らせる。この点がグローバル変数との違いである。

    以上の分析からわかるように、ローカル変数を静的変数に変更することは、その記憶方式、すなわち生存期間を変更することである。グローバル変数を静的変数に変更することは、そのスコープを変更し、使用範囲を制限することである。したがって、staticという指定子は場所によって果たす役割が異なる。注意すべきである。

    Tips:

    • A、グローバル変数が単一のCファイル内でのみアクセスされる場合、この変数を静的グローバル変数に変更することで、モジュール間の結合度を低減できる。
    • B、グローバル変数が単一の関数によってのみアクセスされる場合、この変数をその関数の静的ローカル変数に変更することで、モジュール間の結合度を低減できる。
    • C、動的グローバル変数、静的グローバル変数、静的ローカル変数を設計およびアクセスする関数を作成する際は、再入問題を考慮する必要がある。なぜなら、それらはすべて静的データ格納領域に置かれ、グローバルから見えるためである。
    • D、再入可能な関数が必要な場合、関数内でstatic変数の使用を必ず避けなければならない（このような関数は「内部メモリ」機能を持つ関数と呼ばれる）。
    • E、関数内でstatic変数を使用しなければならないケース：たとえば、ある関数の戻り値がポインタ型の場合、静的ローカル変数のアドレスを戻り値としなければならない。auto型の場合、誤ったポインタが返される。

    -----------------------------------------------------------------------------------------------------------

    static グローバル変数スコープを変更し、記憶位置は変更しない

    static ローカル変数記憶位置を変更し、スコープは変更しない

    静的関数関数の戻り値の型の前にstaticキーワードを付けると、関数は静的関数として定義される。静的関数は通常の関数とは異なり、宣言されたファイル内でのみ見え、他のファイルでは使用できない。

    ソースファイル内で定義された関数が、そのファイル内の関数からのみ呼び出し可能で、同じプログラムの他のファイルの関数からは呼び出せない場合、このような関数も内部関数と呼ばれる。内部関数を定義するには、関数の型の前に「static」キーワードを1つ追加するだけでよい。

    文字型変数は単一の文字を格納するために使用され、C言語ではcharで表され、各文字変数は1バイト（8ビットの2進数）を占有する。

    整型intはメモリ内で4バイト（32ビットの2進数）の領域を占有する。

    文字 '0'：char c = '0';そのASCIIコードは実際には48であり、メモリ内では00110000と表現される。

    文字 '\0'：ASCIIコードは0で、文字列の終端を示す記号である。これはエスケープ文字である（全体として1文字とみなされる）。メモリに文字を格納する場合、対応する文字セットの文字コードを格納するため、メモリ上での表現は00000000である。

    整数 0 ：メモリ内では00000000 00000000 00000000 00000000と表現される。すべて0であっても、上記の文字 '\0' の格納長さとは異なる。
