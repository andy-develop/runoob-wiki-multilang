JavaScript クロージャ

JavaScript の変数はローカル変数またはグローバル変数にできます。

プライベート変数にはクロージャを使用できます。

グローバル変数

関数は関数内部で定義された変数にアクセスできます。例：

サンプル

function myFunction() { var a = 4; return a * a; }

試してみる »

関数は関数外部で定義された変数にもアクセスできます。例：

サンプル

var a = 4; function myFunction() { return a * a; }

試してみる »

後者のサンプルでは、aはグローバル変数です。

Webページでは、グローバル変数は window オブジェクトに属します。

グローバル変数はページ上のすべてのスクリプトで使用できます。

最初のサンプルでは、aはローカル変数です。

ローカル変数は、それを定義した関数の内部でのみ使用できます。他の関数やスクリプトコードからは利用できません。

グローバル変数とローカル変数は、たとえ名前が同じでも、それらは2つの異なる変数です。一方を変更しても、もう一方の値には影響しません。

変数を宣言するときにvarキーワードを使用しない場合、関数内で定義されていても、その変数はグローバル変数になります。

変数のライフサイクル

グローバル変数のスコープはグローバルです。つまり、JavaScriptプログラム全体を通して、グローバル変数はどこでも利用できます。

一方、関数内部で宣言された変数は、関数内部でのみ有効です。これらの変数はローカル変数であり、スコープは局所的です。関数のパラメータも局所的であり、関数内部でのみ有効です。

カウンターのジレンマ

いくつかの数値をカウントしたいとします。そして、そのカウンターがすべての関数で使用できるとします。

グローバル変数を使用して、関数でカウンターをインクリメントできます：

サンプル

var counter = 0; function add() { return counter += 1; } add(); add(); add(); //カウンターは現在 3

試してみる »

カウンターの値は add() 関数の実行時に変化します。

しかし問題は、ページ上のどのスクリプトでも、add() 関数を呼び出さなくてもカウンターを変更できることです。

関数内でカウンターを宣言すると、関数を呼び出さない限りカウンターの値を変更できません：

サンプル

function add() { var counter = 0; return counter += 1; } add(); add(); add(); //本来は 3 を出力したいのですが、期待に反して、出力されるのはすべて 1 です！

試してみる »

上記のコードは正しく出力されません。add() 関数を呼び出すたびに、カウンターが 1 に設定されるからです。

JavaScript のネスト関数でこの問題を解決できます。

JavaScript ネスト関数

すべての関数はグローバル変数にアクセスできます。

実際、JavaScript では、すべての関数はその1つ上のスコープにアクセスできます。

JavaScript はネスト関数をサポートしています。ネスト関数は1つ上の関数の変数にアクセスできます。

このサンプルでは、ネスト関数plus()は親関数のcounter変数にアクセスできます：

サンプル

function add() { var counter = 0; function plus() {counter += 1;} plus(); return counter; }

試してみる »

外部からplus()関数にアクセスできれば、カウンターのジレンマを解決できます。

また、counter = 0が一度だけ実行されるようにする必要があります。

クロージャが必要です。

JavaScript クロージャ

関数の自己呼び出しを覚えていますか？ その関数は何をするでしょうか？

サンプル

var add = (function () { var counter = 0; return function () {return counter += 1;} })(); add(); add(); add(); //カウンターは 3

試してみる »

サンプル解説

変数addは関数の自己呼び出しの戻り値を受け取ります。

自己呼び出し関数は一度だけ実行されます。カウンターを 0 に設定し、関数式を返します。

add 変数は関数として使用できます。素晴らしい点は、1つ上の関数スコープのカウンターにアクセスできることです。

これは JavaScript のクロージャと呼ばれます。これにより、関数がプライベート変数を持つことが可能になります。

カウンターは匿名関数のスコープによって保護され、add メソッドを通じてのみ変更できます。

クロージャはプライベート変数を保護するメカニズムです。関数の実行時にプライベートスコープを作成し、内部のプライベート変数を外部からの干渉から保護します。

直感的に言えば、クロージャは破棄されないスタック環境のようなものです。

    多くの人が最後のこのカウンター問題を見て困惑するのではないかと思います。私も同じです。

    コードで検証したところ、その奥義は次のとおりであることがわかりました：

    var add = (function () {
    var counter = 0;
    return function () {return counter += 1;}
})();

    注意：なぜ上記のコードは function add (){...} と直接書かずに、function を変数 add に代入しているのでしょうか？

    私たちは通常、add() を呼び出すたびに add() 内のコードブロックが再度実行されると当然のように思いますが、実際はそうではありません。

    add メソッド内の return に注目してください。return しているのは 1,2,3 のような数値ではなく、メソッドを return し、そのメソッドを add 変数に代入しています。

    つまり、この function が一度実行された後、実際に add に代入されるのは return counter += 1 というコードです。

    したがって、その後 add() を呼び出すたびに、実際には return counter += 1 を呼び出していることになります。

    さらに、記事の前述の説明と合わせると、クロージャは親メソッドのローカル変数を保持し、親メソッドの破棄に伴って破棄されないため、この counter は実際には最初の function 実行時に作成された変数に由来しています。

    var add = function () 
{
    var counter = 0;

    var add_child = function(id) {
        var counter_res = 0;
        if(id === 1)
        {
            counter_res = counter + 1;
        }
        else if(id === 2)
        {
            counter++;
            counter_res += counter;
        }
        else
        {
          counter_res = 0;
        }
        alert("子方法");  // 每次执行 add() 都会执行
        return counter_res;
    };
    return add_child;
    // counter 作用域在父函数中, 自然在其子函数中也能使用,但因为
    // 子函数还需要使用count, 所以 count 不随着父函数一起释放。
    // 利用在 function(){}() 的形式自动执行一遍父匿名函数, 赋给 add 子方法。

当以后执行add()这个函数时，其实执行的是add_child=function(){}。
这样做，闭包的目的就在于，你通过add这个对象访问不到counter这个变量，无形中创造了一个私有变量。

    上の皆さんの議論を見て、私も自分の考えを述べたいと思います。

    最初の論争について、クロージャの存在と使用が合理的かつ必須かどうか、私の答えは「YES！」です。

    私個人の見解としては、クロージャという実装方法を使ってオブジェクト内のプライベート属性を呼び出すことは、オブジェクト指向プログラミングの思考ロジックと現代のプログラミングの発展傾向により合致しています。

    例を挙げて説明します。カウンターというオブジェクトの count 値をパブリック属性に設定すれば、確かにクロージャを使わずに同じ問題を解決できます。しかし、長い目で見れば、カウンターの function はコード全体の中のほんの一部の機能にすぎません。この機能以外にも、平均値を求める function、混合統計の function などの同様の機能モジュールが含まれるでしょう。では、Window から直接呼び出せるようにするために、他の function の重要な属性をすべてグローバル属性に設定しなければならないのでしょうか？

    すべてをグローバル属性に設定したら、コードは退行しているのではないでしょうか？オブジェクトのカプセル化はますます不完全になり、より手続き型プログラミングの理念に近づきます。同時に、将来の修正や更新がますます不便になります。

    オブジェクト指向プログラミングの思考とは何か、その利点は何かについては、ここで多くを述べる必要はないと思います。

    優れたオブジェクト指向プログラミングは、完全なカプセル化を実現し、内部データにアクセスするためのインターフェースを提供することです。

    将来カウンターの機能を変更したい場合、内部の属性を修正するだけで済みます。グローバル変数の調整を考慮する必要はまったくありません。なぜなら、グローバルでの具体的な実装は依然としてクロージャ関数を通じて行われるからです。

    最後に例を使ってクロージャ関数を説明します：

    あなたがレストランで食事をするとします。ホールのエリアはグローバル領域（public）に相当し、クロージャ関数はウェイターに相当します。料理を注文したいなら、ウェイターに頼めばよいのです。

    ウェイターがいなければ、厨房でどんな料理を作っているかをどうやって知るのでしょうか？また、厨房は関係者以外立ち入り禁止の場所です（厨房は関数内部に相当し、外部からはアクセスできず、入れてもらえません）。

    そうなると、厨房は本来厨房の中にだけ置くべき料理をすべて外に並べて見せるしかありません（内部の count プロパティをグローバル属性にする）。そうすれば、そのレストランはめちゃくちゃになり、とても上品な店とは言えません。

    しかし、ウェイターがいれば、ウェイターを通じて厨房の料理を知り、注文を完了できます。ウェイター（クロージャ関数）は、外部が関数内部の属性に直接アクセスすることを実現します。

    クロージャはプライベート属性を呼び出すためのインターフェース。ずっとC++を学んできたプログラマーとして、これを見てすぐに感激で涙があふれました。

    まあ、しかしここで起きた論争を見て、一点だけ指摘したいと思います：クロージャはオブジェクト指向を実現するために必須です。

    実際、11階はクロージャをまったく理解できておらず、オブジェクト指向の意味すら理解できていません。オブジェクト指向の基本要素はカプセル化：おそらく private の変数、つまり直接変更できず、メソッドによってのみ変更できる属性が必要です。そして「オブジェクトを使えばクロージャを置き換えられる」という意見がありますが、クロージャの実際の本当の意味は、オブジェクトコンストラクターの中で使われるべきです。

    例えば、オブジェクトにある属性を持たせたいとします。増やすことだけが許され、減らすことは許されず、毎回 add 関数で特定の偶数を加えることしかできないとします。このとき、クロージャがその有用性を発揮します。この例は、上で提起されたすべての問題を比較的統一的に解決していると言えます。

    function NumPro(val){
    var counter=val;
    this.add=function(num){
        if(num%2==0) counter+=num;
    }
    this.num=function(){
        return counter;
    }
}
//alert(counter);      //报错
alert(NumPro.counter); //输出undefined(显而易见的)
var a=new NumPro(0);
alert(a.counter);      //输出undefined(不在this中)
alert(a.num());        //输出0
a.add(2);
alert(a.num());        //输出2
a.add(1);
alert(a.num());        //输出2(仅允许偶数)
a.add(10);
alert(a.num());        //输出12
var b=new NumPro(-2);
alert(b.num());        //输出-2

    明らかに、クロージャは単に「スコープ内の変数が破棄されない」というだけのものではありません。変数を直接出力するとエラーになりますし、関数名によって属性にアクセスすることもできません。また、2つのオブジェクトで出力される値には何の関係もありません。同時に、属性への直接操作を制限できます——this の中にない変数は外部からアクセスできません。

    したがって、クロージャは意図的に設計されたものであり、バグではありません。実際、Java や他のオブジェクト指向言語に触れたことがあれば、深く感じるところがあるでしょう——Javascript のオブジェクト指向はしばしば予想外です（Class さえありません）。しかし、それは他の言語の private 効果を実現できないという意味ではありません。そう考えると、ここでのクロージャは単に this.counter=num を var counter=num に変更しただけにすぎません。

    もちろん、クロージャはこれだけではありません。例えば本文中で関数を返す（名前）の巧妙な方法です。ただし、クロージャは関数内のプライベート変数がすぐには破棄されず、内部の関数からアクセスできることを意味します。これで十分です。

    さらに、実験によると、関数は直接の親関数のプライベート変数だけでなく、親の親関数やさらに上位の関数の変数にもアクセスできます（ただし、これは推奨されません……多くの場合、コードの可読性を下げるだけのようです）。しかし、もし次のように使うと：

    NumPro.prototype.numEx=function(){
    return counter;
}

    もし counter が NumPro 関数内で定義されている場合、この関数を使用するとエラーになります（そのプロトタイプ関数には明らかに counter 変数が含まれておらず、含まれていてもどう処理すればよいか不明です）。
