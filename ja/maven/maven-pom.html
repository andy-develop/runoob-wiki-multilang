Maven POM

POM（Project Object Model、プロジェクトオブジェクトモデル）は Maven の中核となる設定ファイルで、XML 形式を採用し、デフォルトの名前は次のとおりです。pom.xml。

POM は Maven プロジェクトの基本的な作業単位であり、XML ファイルです。プロジェクトの基本情報が含まれ、プロジェクトのビルド方法の説明やプロジェクト依存関係の宣言などに使用されます。

タスクやゴールを実行するとき、Maven はカレントディレクトリで POM を探し、必要な設定情報を取得して、ゴールを実行します。

POM では以下の設定を指定できます：

  • プロジェクトの依存関係
  • プラグイン
  • 実行ゴール
  • プロジェクトビルドプロファイル
  • プロジェクトバージョン
  • プロジェクト開発者リスト
  • 関連メーリングリスト情報

POM を作成する前に、まずプロジェクトグループ（groupId）とプロジェクトの一意の ID を記述する必要があります。

<project> <!--モデルバージョン--> <modelVersion>4.0.0</modelVersion> <!--会社または組織の一意の識別子であり、設定時に生成されるパスもこれから生成されます。例：com.companyname.project-group。Maven はこのプロジェクトをビルドした jar パッケージをローカルパス /com/companyname/project-group に配置します。--> <groupId>com.companyname.project-group</groupId> <!--プロジェクトの一意の ID。1 つの groupId の下に複数のプロジェクトが存在する可能性があり、artifactId によって区別されます。--> <artifactId>project</artifactId> <!--バージョン番号--> <version>1.0</version> </project>

すべての POM ファイルには project 要素と、groupId、artifactId、version の 3 つの必須フィールドが必要です。

ノード 説明
project プロジェクトのルートタグ。
modelVersion モデルバージョンは 4.0 に設定する必要があります。
groupId これはプロジェクトグループの識別子です。通常、組織またはプロジェクト内で一意です。例えば、銀行組織 com.companyname.project-group は銀行に関連するすべてのプロジェクトを所有しています。
artifactId これはプロジェクトの識別子です。通常はプロジェクト名です。例：消費者銀行。groupId と artifactId を合わせて、成果物（artifact）のリポジトリ内の位置を定義します。
version

これはプロジェクトのバージョン番号です。成果物（artifact）のリポジトリ内で、異なるバージョンを区別するために使用されます。例：

com.company.bank:consumer-banking:1.0
com.company.bank:consumer-banking:1.1

POM ファイルの基本構造：

例

<project>
    <!-- 1. 基本情報-->
    <modelVersion>4.0.0</modelVersion>
    <groupId>com.example</groupId>
    <artifactId>my-app</artifactId>
    <version>1.0.0</version>
    <packaging>jar</packaging>

    <!-- 2. メタ情報-->
    <name>My Application</name>
    <description>A demo project</description>
    <url>https://example.com</url>

    <!-- 3. 依存関係の管理-->
    <dependencies>...</dependencies>

    <!-- 4. ビルド設定-->
    <build>...</build>

    <!-- 5. 環境設定-->
    <properties>...</properties>
    <repositories>...</repositories>
</project>

プロジェクト座標（必須）：

要素説明例
modelVersionPOM モデルバージョン（固定4.0.0）<modelVersion>4.0.0</modelVersion>
groupId組織・会社識別子（逆ドメイン名）<groupId>com.example</groupId>
artifactIdプロジェクト名<artifactId>my-app</artifactId>
versionプロジェクトバージョン<version>1.0.0</version>
packagingパッケージタイプ（jar/war/pom）<packaging>jar</packaging>

メタ情報（任意）：

要素説明
nameプロジェクト名（表示用）
descriptionプロジェクトの説明
urlプロジェクトのホームページ
licensesライセンス情報
organization組織情報

<url>https://github.com/example/my-app</url>

依存関係の管理

POM ファイルではプロジェクトの依存関係を定義できます：

<dependencies>
    <dependency>
        <groupId>junit</groupId>
        <artifactId>junit</artifactId>
        <version>4.12</version>
        <scope>test</scope>
    </dependency>
</dependencies>
要素説明
groupId依存関係の組織識別子
artifactId依存関係のプロジェクト名
version依存関係のバージョン
scope依存関係スコープ（compile/test/provided/runtime）
optional任意依存関係かどうか（デフォルトfalse）

プラグイン管理

POM ファイルではビルドプロセス中のプラグインも定義できます：

<build>
    <plugins>
        <plugin>
            <groupId>org.apache.maven.plugins</groupId>
            <artifactId>maven-compiler-plugin</artifactId>
            <version>3.8.1</version>
            <configuration>
                <source>1.8</source>
                <target>1.8</target>
            </configuration>
        </plugin>
    </plugins>
</build>

よく使われるプラグイン：

  • maven-compiler-plugin：Java バージョンを指定

  • maven-surefire-plugin：テスト実行を制御

  • maven-jar-plugin：JAR パッケージをカスタマイズ

その他のよく使われる要素

properties: プロジェクト内のいくつかのプロパティ変数を定義します。

変数を定義して重複を避けるために使用します：

<properties>
    <java.version>11</java.version>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
</properties>

依存関係内で参照します：

<version>${java.version}</version>

repositories: リポジトリ設定。

リモートリポジトリを指定：

<repositories>
    <repository>
        <id>aliyun</id>
        <url>https://maven.aliyun.com/repository/public</url>
    </repository>
</repositories>

dependencyManagement: 依存関係のバージョン管理に使用され、特にマルチモジュールプロジェクトで使用されます。

<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.springframework</groupId>
            <artifactId>spring-core</artifactId>
            <version>5.3.9</version>
        </dependency>
    </dependencies>
</dependencyManagement>

profiles: 異なるビルド設定を定義し、異なる環境に応じてビルドできます。

<profiles>
    <profile>
        <id>development</id>
        <properties>
            <environment>dev</environment>
        </properties>
    </profile>
    <profile>
        <id>production</id>
        <properties>
            <environment>prod</environment>
        </properties>
    </profile>
</profiles>

継承と集約

継承：parent 要素を使用すると、ある POM ファイルは別の POM ファイルの設定を継承できます：

<parent>
    <groupId>com.example</groupId>
    <artifactId>parent-project</artifactId>
    <version>1.0-SNAPSHOT</version>
</parent>

集約：modules 要素を使用すると、1 つの POM ファイルで複数のサブモジュールを管理できます：

<modules>
    <module>module1</module>
    <module>module2</module>
</modules>

例

        <plugins>

親（Super）POM

親（Super）POM は Maven のデフォルトの POM です。すべての POM は親 POM から継承されます（この親 POM が明示的に定義されているかどうかに関係ありません）。親 POM には継承可能なデフォルト設定が含まれています。そのため、Maven が POM 内の依存関係をダウンロードする必要があることを検出すると、Super POM で設定されたデフォルトリポジトリ http://repo1.maven.org/maven2 からダウンロードします。

Maven は effective pom（Super pom にプロジェクト自身の設定を加えたもの）を使用して関連するゴールを実行します。これにより、開発者は pom.xml でできるだけ少ない設定を行うことができ、もちろんこれらの設定は上書きできます。

以下のコマンドを使用して Super POM のデフォルト設定を確認します：

mvn help:effective-pom

次に、ディレクトリ MVN/project を作成し、そのディレクトリに pom.xml を作成します。内容は次のとおりです：

<project xmlns = "http://maven.apache.org/POM/4.0.0" xmlns:xsi = "http://www.w3.org/2001/XMLSchema-instance" xsi:schemaLocation = "http://maven.apache.org/POM/4.0.0 http://maven.apache.org/xsd/maven-4.0.0.xsd"> <!--モデルバージョン--> <modelVersion>4.0.0</modelVersion> <!--会社または組織の一意の識別子であり、設定時に生成されるパスもこれから生成されます。例：com.companyname.project-group。Maven はこのプロジェクトをビルドした jar パッケージをローカルパス /com/companyname/project-group に配置します。--> <groupId>com.companyname.project-group</groupId> <!--プロジェクトの一意の ID。1 つの groupId の下に複数のプロジェクトが存在する可能性があり、artifactId によって区別されます。--> <artifactId>project</artifactId> <!--バージョン番号--> <version>1.0</version> </project>

コマンドコンソールで MVN/project ディレクトリに移動し、以下のコマンドを実行します：

C:\MVN\project>mvn help:effective-pom
