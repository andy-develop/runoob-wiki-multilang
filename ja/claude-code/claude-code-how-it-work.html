Claude Code の仕組み

簡単に言うと：Claude Code はまるで超優秀なプログラミングパートナーで、あなたのコンピュータ上で自動的にコードを書いたり、バグを修正したり、コマンドを実行したり、ファイルを検索したり……ターミナルでできるほぼすべてのことを実行できます！

このセクションでは、その内部原理（エージェントループ、モデル、ツールなど）を徹底的に理解できます。読み終えると、なぜこれほど強力なのか、そしてどう使えばより使いやすくなるのかがわかります。

Claude のワークフロー

Claude にタスクを与えると、人間のようにループ思考3つのステップ：

  1. コンテキストの収集（あなたのコード、ファイル、エラーメッセージを確認）
  2. アクションを実行（ファイルの編集、コマンドの実行、検索など）
  3. 結果の検証（成功したか、どこを調整する必要があるかを確認）

この3つのステップはタスクが完了するまで繰り返されます。もちろん、いつでも中断して新しい指示を与えたり、「別の方法を試してみて」と言ったりすることもできます。

Claude は自律的に作業できますが、常にあなたの指示に従います！

Prompt → 获取上下文 → 执行动作 → 验证结果 →（循环）→ 完成

このループ全体は2つのものによって駆動されます：

  • モデル（思考と推論を担当）
  • ツール（実際に手を動かして作業を実行）

モデル（Claude の頭脳）

Claude Code は Anthropic の Claude モデルを使用してコードを理解し、タスクを計画します。ほとんどすべてのプログラミング言語を理解でき、プロジェクト構造を把握し、複雑なタスクを小さなステップに分解して一つずつ実行することもできます。

よく使うモデルのおすすめ：

  • Sonnet：日常のコーディングタスクに最適（速度が速く、コストパフォーマンスが高い）
  • Opus：特に複雑なアーキテクチャ設計や深い推論に適している

ただし、中国国内では公式モデルはあまり使いやすくないため、他の国内モデルに切り替えることができます。

モデルの切り替え：

  • プロンプトボックスに入力/model
  • または起動時に使用claude --model sonnet

ツール（Claude が実際に手を動かせる理由）

ツールがなければ、Claude はチャットしかできません。ツールがあれば、実際にあなたのコードを変更できます！

Claude には5つのカテゴリのツールが組み込まれています：

  • ファイル操作：ファイルの読み取り、コードの変更、新規ファイル作成、名前変更
  • 検索：ファイル名または正規表現でコードをすばやく検索
  • コマンド実行：npm、git、テストの実行、サーバーの起動など
  • ウェブ検索：ドキュメントの参照、エラーメッセージの調査
  • コードインテリジェンス：型エラーの確認、定義へのジャンプ、参照の検索（対応する言語プラグインのインストールが必要）

実際の例（失敗したテストを修正する場合）：

  1. テストを実行してどこが失敗したか確認
  2. エラーログを読む
  3. 関連するソースファイルを検索
  4. ファイルを読んでロジックを理解
  5. コードを修正
  6. 再度テストを実行して検証

これがエージェントループの実際の姿です！

発展的な拡張：skills（スキル）、MCP（外部サービス）、hooks（自動化）、subagents（サブエージェント）を使用して、さらに強力にすることもできます。

Claude がアクセスできるもの

Claude Code はあなたのプロジェクト全体を閲覧できます（通常の AI が現在開いているファイルしか見られないのとは異なります）：

  • あなたのプロジェクトフォルダとすべてのサブファイル
  • ターミナルで実行できる任意のコマンド（npm、git、ビルドツールなど）
  • 現在の Git 状態（ブランチ、未コミットの変更、コミット履歴）
  • CLAUDE.mdファイル（ここにプロジェクト固有のルールを書いて、Claude に毎回覚えさせることができます）
  • 自動メモリ（プロジェクトの習慣を記憶し、MEMORY.md の最初の200行に保存します）
  • あなたが設定した拡張機能（MCP、skills など）

まさにこのおかげで、複数のファイルにまたがって修正を調整し、自動でテストを実行し、さらにはコードのコミットまで支援できます。

実行環境とインターフェース

Claude Code は3つの環境で実行できます：

  • ローカル（デフォルト）：完全にあなたのコンピュータ上で動作し、権限が最大
  • クラウド（Anthropic 仮想マシン）：大規模プロジェクトやローカルにない環境の処理に適している
  • リモートコントロール：ブラウザから操作するが、コードはローカルに残る

対応インターフェース：ターミナル、VS Code 拡張機能、JetBrains、claude.ai/code、Slack、CI/CD など。基本的な動作原理は完全に同じです！

ブランチをまたいだ作業（Git ブランチ切り替えでもシームレスに使用可能）

Claude Code の各会話はすべて現在のフォルダにバインドされています（Git ブランチにはバインドされません）。これにより非常に実用的な特性がもたらされます：

  • あなたがGit ブランチを切り替えるとき（git checkout 或 git switch）、Claude は新しいブランチのファイルを自動的に認識します、しかしあなたのチャット履歴はそのまま維持されます。
  • Claude は以前に議論したすべての内容と決定を覚えています。ブランチをまたいでもコンテキストが失われることはありません。
  • 古い会話を復元すると、表示されるのは現在のフォルダ内のセッション履歴のみです（異なるブランチでも同じフォルダにある場合は履歴を共有します）。

並行マルチブランチ開発の神ツール：
おすすめはgit worktrees各ブランチに独立したディレクトリを作成することこれにより、複数の Claude Code セッションを同時に開くことができ、各ブランチが完全に独立したクリーンな会話履歴を持ち、互いに干渉しません。

セッションの復元またはフォーク（続きから話す / 新しいラインを開始）

Claude Code は3つの柔軟なセッション操作をサポートしており、いつでも以前の進捗を引き継いだり、別のアプローチを試したりできます：

1、セッションを直接復元（最も一般的）

コマンド：

claude --continue
# 或者
claude --resume

効果：

  • 使用同じセッション ID、前回中断したところから続行
  • 完全なチャット履歴がすべて復元される
  • 注意：セッションスコープの権限は自動的に復元されないため、再度承認する必要があります

2、セッションのフォーク（おすすめ！新しい案を試しても元の会話に影響しません）

コマンド：

claude --continue --fork-session

効果：

  • 新規のセッション ID を作成
  • 現在までのすべてのチャット履歴を保持
  • 元のセッションは完全に影響を受けない
  • 同様に権限の再承認が必要

適用シーン：「別の実装方法」を試したいが、元の会話を混乱させたくない場合は、これを使いましょう！

3、複数のターミナルで同じセッションを同時に使用する（注意して使用）

  • 複数のターミナルウィンドウで、claude --continue同じセッションを復元する場合：
    • すべてのメッセージが交互に混ざり合う（まるで2人が同時に同じノートに書いているようなものです）
    • 会話が混乱する
    • 各ターミナルはその時点では自分が入力したメッセージしか見えませんが、後で復元するとすべての交錯した内容が見えます

正しい方法：並行して作業したい場合は、必ず使用し--fork-session、各ターミナルにクリーンで独立した新しいセッションを割り当ててください。

コンテキストウィンドウ（Claude の記憶容量）

Claude にはコンテキスト容量の制限があります。ほぼ満杯になると：

  • それは自動圧縮古いコンテンツ
  • あなたは入力できます/compact手動圧縮
  • 入力/context現在の使用状況を確認

スペース節約の秘訣：

  • 重要なルールを書き込むCLAUDE.md
  • skills と subagents を使って不要なコンテキスト消費を減らす

安全機構（チェックポイント + 権限制御）

1、チェックポイント（いつでも元に戻せる）Claude はファイルを変更する前に自動的にバックアップします。2回押すだけでEsc、または「さっきの変更を元に戻して」と言えば、以前の状態に戻れます。

2、権限モード（Shift + Tab で素早く切り替え）：

  • デフォルト：ファイル変更またはコマンド実行のたびに確認を求めます
  • 編集を自動的に受け入れる：ファイルの変更は確認なし、ただしコマンドは確認を求めます
  • プランモード：分析のみで実行せず、まず完全な計画を提示します

さらに、その中で.claude/settings.jsonホワイトリストに信頼するコマンドを追加できます（例：npm testは永遠に確認不要になります）。

Claude Code を効果的に使うための6つの実用 Tips

  1. それに自分の使い方を直接聞く
    「hooks を設定するには？」と入力するか、「/init」と入力すれば、ステップバイステップで教えてくれます。

  2. これは会話であり、一度きりのコマンドではない
    まず大まかな要件を伝える → それが試す → あなたが修正する：「これは違う、問題はセッション処理だ」
    毎回プロンプトを書き直す必要はありません！

  3. いつでも途中で止められる
    それが脱線したら？新しい指示を入力して Enter を押すと、すぐに止まって調整します。

  4. プロンプトは具体的であればあるほど良い
    悪い例：「ログインエラーを修正」
    良い例：「カード保有者の有効期限が切れたユーザーのチェックアウトフローが壊れています。src/payments/ を確認してください、特にトークン更新を。最初に失敗するテストを書いてから修正してください。」

  5. それに自己検証させる
    テストケースや期待される結果を追加すれば、テストを実行して確認してくれます。

  6. まず探索してから実装する
    最初にプランモード（Shift+Tab を2回）それにコードベースを分析させ、計画を立てさせる → あなたが確認してから実行させます。
