Claude Code メモリシステム（Memory）

Claude Codeのセッションが終了するたびに、コンテキストはクリアされます。

毎回Claudeに「npmではなくpnpmを使う」「インデントはスペース2つ」と伝え直さなければならないことがあるのでは？メモリシステム（Memory）まさにこのために作られました。

Claude Codeのメモリシステムとは？

Claude Codeにはセッションをまたぐ自動メモリはありません——新しいセッションは毎回、完全に新しいコンテキストウィンドウから始まります。

メモリシステムは、2つの補完的なメカニズムを通じて、知識をセッションをまたいで永続的に保存し、毎回の会話開始時に自動的に読み込むことを可能にします：

メカニズム 誰が書くか 何に適しているか
CLAUDE.mdファイル あなた（開発者）が手動で記述 プロジェクト規約、チームの取り決め、ビルドコマンドなど
Auto Memory（自動メモリ） Claudeが自動的に記録 あなたの訂正や好みから蓄積された経験

両方のメカニズムは、各セッションの開始時にコンテキストへ読み込まれます。Claudeはそれらを参照コンテキストとして扱い、強制設定とはみなしません——指示が具体的で簡潔であるほど、Claudeは一貫して従います。

メモリファイルの階層構造

Claude Codeは4層のメモリ階層を採用しており、優先度は高い順に：

1. 企业级配置（Enterprise policy）    ← 最高优先级，只读
2. 用户级 CLAUDE.md                   ← ~/.claude/CLAUDE.md，对所有项目生效
3. 项目级 CLAUDE.md                   ← 项目根目录，随 Git 提交共享给团队
4. 子目录级 CLAUDE.md                 ← src/、api/、tests/ 等子目录，按上下文加载

最も具体的なルールが優先：サブディレクトリのCLAUDE.mdは、上位層の同種のルールを上書きします。

CLAUDE.mdファイルの詳細

CLAUDE.mdとは？

CLAUDE.mdプロジェクトのルートディレクトリ（またはサブディレクトリ）に置かれるMarkdownファイルです。Claude Codeは新しいセッションを開始するたびに、それをシステムプロンプトに自動的に注入します。これはあなたが設定できる長期メモリです。

CLAUDE.mdの作成

方法1:/initコマンドで自動生成

# 在 Claude Code 会话中执行
/init

Claudeはあなたのディレクトリ構造を分析し、あなたの技術スタックに特化したCLAUDE.mdの雛形を自動生成します。例えば、Node.jsプロジェクトで/initを実行すると、Claudeがフレームワーク、テストツール、ビルドコマンドなどを自動検出し、30秒以内に完成度80%の初期ファイルを生成します。

方法2: 手動で作成

touch CLAUDE.md

推奨されるCLAUDE.mdの構造

# 项目约定

## 技术栈
- 前端：Next.js 15、TypeScript 5.7、Tailwind CSS 4
- 后端：Node.js 22、Prisma 6
- 测试：Vitest 3.2

## 代码规范
- 始终使用函数式 React 组件
- 文件名使用 kebab-case
- 测试文件与源码放在同一目录

## 常用命令
- 构建：`pnpm build`
- 测试：`pnpm test`
- 启动开发服务器：`pnpm dev`

## API 约定
- 所有 API 路由以 `/api/v1/` 开头
- 错误响应格式：`{ error: string, code: number }`

優れたCLAUDE.mdを書くための黄金律

✅ このように書きましょう：

  • 叙述的な段落ではなく、命令形と簡潔なリストを使用する
  • 具体的なバージョン番号とコマンドを含める
  • コード例を追加する（50文字の説明より5行の例のほうが効果的）
  • ファイルは200行以内にに収める（超えた部分はセッション開始時に読み込まれません）

❌ このような書き方は避けましょう：

  • 「ベストプラクティスに従う」「きれいなコードを書く」のような曖昧な指示
  • 一般的すぎるルールを入れすぎる（このプロジェクト固有の取り決めだけを入れる）
  • 古くなった情報（月に一度見直すことを推奨）

サブディレクトリのCLAUDE.md

my-project/
├── CLAUDE.md              # 全局项目规范
├── src/
│   └── CLAUDE.md          # 仅在处理 src/ 文件时加载
├── api/
│   └── CLAUDE.md          # API 特定约定
└── tests/
    └── CLAUDE.md          # 测试特定规则

Claude Codeは、対応するディレクトリ内のファイルを処理するときだけ、サブディレクトリのCLAUDE.mdを読み込みます。トークンを節約しつつ、より正確なコンテキストを提供します。

Auto Memory（自動メモリ）の詳細

どのように機能するのか？

Auto Memoryは、Claudeがセッションをまたいで知識を自律的に蓄積することを可能にします。何も手動で書く必要はありません。Claudeは作業中に自動的にメモを保存します。内容は以下の通りです：

  • ビルドコマンドとデバッグのテクニック
  • アーキテクチャ決定に関するメモ
  • コードスタイルの好み
  • ワークフローの習慣

Claudeは毎回すべてを保存するわけではありません。どの情報が将来のセッションで役立つと判断した場合のみ書き込みます。

自動メモリのファイル構造

~/.claude/projects/<project>/memory/
├── MEMORY.md          # 简洁的索引文件，每次会话开始时加载（前 200 行）
├── debugging.md       # 调试模式的详细笔记
├── api-conventions.md # API 设计决策
└── ...                # Claude 创建的其他主题文件

MEMORY.mdはメモリディレクトリ全体のインデックスであり、Claudeはこれを介して各ファイルに保存された内容を追跡します。

自動メモリのトリガー

Claudeに何かを伝えると、それは自動的にメモリへ保存されます：

你：始终使用 pnpm，不要用 npm
你：记住 API 测试需要本地运行 Redis 实例
你：我们的日期格式统一用 ISO 8601

Auto MemoryではなくCLAUDE.mdに保存したい場合？明確に指示しましょう：

你：把这条加到 CLAUDE.md

Auto Memoryの有効化 / 無効化

方法1:/memoryコマンドで切り替え（次のセクションを参照）

方法2: プロジェクト設定で構成

// .claude/settings.json
{
  "autoMemoryEnabled": false
}

方法3: 環境変数

export CLAUDE_CODE_DISABLE_AUTO_MEMORY=1
blockquote>

注意：Auto Memoryはローカルマシンレベルであり、同じGitリポジトリのすべてのワークツリーとサブディレクトリが1つのメモリディレクトリを共有します。ただしマシン間やクラウド環境間では同期されません。。

/memoryコマンド使用ガイド

/memoryはメモリシステムを管理するための中心的なコマンドです。

/memoryコマンドの機能

Claude Codeセッションで/memoryを入力すると、以下のことができます：

  • 表示現在のセッションで読み込まれたすべてのCLAUDE.mdとルールファイルのリスト
  • 切り替えAuto Memoryの有効/無効状態
  • 開くAuto Memoryフォルダのリンク
  • 任意のファイルを選択してエディタで開いて編集

#ショートカットキー——素早くメモリに追加

これは隠れた効率化の神器です：

# 始终在函数参数中使用具名参数（named parameters）

キーを押して#、覚えたい内容を入力してEnterキーを押すと、Claude Codeが自動的に対応するCLAUDE.mdファイルに書き込みます。以下のような場合に最適です：

  • プロジェクトの取り決めを記録する
  • よく使うBashコマンドを保存する
  • コードスタイルの詳細をメモする

よくある質問とデバッグ

ClaudeがCLAUDE.mdの指示を無視する？

  1. を実行して/memoryCLAUDE.mdファイルが読み込まれていることを確認する
  2. Claude CodeがCLAUDE.mdのあるディレクトリ（またはそのサブディレクトリ）で実行されていることを確認する
  3. 指示が十分に具体的か確認する——「ベストプラクティスに従う」は曖昧すぎますが、「名前付きインポートを使用する（tree-shakingとの互換性）」の方が効果的です
  4. ファイルが200行を超えていないか確認する（超えた部分は読み込まれません）

CLAUDE.mdはコンテキストであり、強制実行ではない

Claude ClaudeはCLAUDE.mdを読み取り、それに従うよう最善を尽くしますが、特に指示が曖昧または相互に矛盾する場合、厳格な準拠の保証はありません。これは「Claudeへの作業ガイド」であって「絶対に破ってはならないルール」ではないと理解しましょう。
