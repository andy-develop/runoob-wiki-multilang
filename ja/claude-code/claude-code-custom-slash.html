Claude Code カスタムスラッシュコマンド

Skills（スキル）はClaude Codeの拡張メカニズムであり、カスタムスラッシュコマンド（例：/deploy、/explain-code）を通じてClaudeの能力を強化します。

各カスタムコマンドは本質的に独立したSkillファイルであり、複雑なワークフロー、プロジェクト規範、一般的な操作をカプセル化して、あらゆるセッションで素早く呼び出すことができます。

カスタムコマンドはSkillsシステムに統合されています——[パス]にある.claude/commands/deploy.mdコマンドファイルと、[パス]にある.claude/skills/deploy/SKILL.mdスキルファイルはどちらも/deployコマンドを作成し、同じ方法で動作します。

本質的には、.claude/commands/はSkillsの短縮形であり、2つのディレクトリ構造は完全に同等です。

カスタムスラッシュコマンドを使う理由

カスタムスラッシュコマンドの核心的な価値は次のとおりです：標準化 + 再利用：

  • ワークフローの固定化：よく使う複数ステップの操作（例：「本番環境へのデプロイ」）を1つのコマンドにカプセル化します
  • チームの一貫性の確保：プロジェクト規範（例：「コードレビューチェックリスト」）をコマンドとして固定し、チームメンバーが同じ基準に従うようにします
  • 認知負荷の低減：複雑なコマンドの組み合わせを覚える必要がなく、一言で完全なワークフローをトリガーできます
  • 繰り返し入力の削減：頻度の高いタスクが複数ステップの操作から1回の呼び出しになります

Anthropic内部チームの経験則では、1日に2回以上実行するタスクはSkillにするべきです。一度正しく作れば、継続的に効果を発揮します。

ファイル構造

各Skillはディレクトリであり、必須のSKILL.mdファイルを含みます：

my-skill/
├── SKILL.md           # 主指令文件（必需）
├── template.md        # Claude 填充的模板
├── examples/
│   └── sample.md      # 展示预期格式的示例
└── scripts/
    └── validate.sh    # Claude 可以执行的脚本

ファイル形式は2つの部分に分かれます：

  • YAML frontmatter（---区切り文字の間にある）：メタデータの設定に使用します
  • Markdown本文：Claudeが呼び出し時に従う指示です

最初のカスタムスラッシュコマンドを作成する

1、スキルディレクトリを作成する

適切な場所にスキルディレクトリを作成します。保存場所によってコマンドの有効範囲が決まります：

mkdir -p ~/.claude/skills/explain-code
# 或者在项目中创建
mkdir -p .claude/skills/explain-code

2、SKILL.mdファイルを作成する

ディレクトリ内にSKILL.mdを作成し、YAML frontmatterと指示を含めます：

例

---
name: explain-code
description: コードを視覚的な図とアナロジーで説明します。コードの仕組みを説明するとき、
コードベースを解説するとき、またはユーザーが「これはどう動くのですか」と尋ねたときに使用します
---

コードを説明するときは、常に以下を含めてください：
11. **アナロジーから始める**：コードを日常生活の物に例えます
22. **図を描く**：ASCIIアートを使用してフロー、構造、関係を示します
33. **コードを段階的に解説する**：何が起こっているかを段階的に説明します
44. **落とし穴を指摘する**：よくあるエラーや誤解は何ですか？

3、カスタムコマンドを使用する

Claude Codeで直接呼び出します：

/explain-code src/auth/login.ts

Claudeが説明に一致するスキルを自動的にマッチングするか、明示的に呼び出すこともできます。

設定フィールドの詳細

フィールド 説明
name 表示名。スラッシュコマンドになります（形式：小文字、数字、ハイフン、最大64文字）
description スキルの機能と使用タイミング（推奨。Claudeの自動呼び出しはこのフィールドに依存します）
argument-hint 自動補完時に表示されるプロンプト（例：[filename] [format]）
disable-model-invocation に設定するとtrue、Claudeの自動呼び出しを防ぎます。明示的に呼び出した場合のみ有効です
user-invocable に設定するとfalse、/メニューから非表示になります。Claudeのみが呼び出せます
allowed-tools Claudeが確認なしで使用できるツールのリスト
context に設定するとfork、ブランチサブエージェントで実行されます
agent 設定するcontext: forkときに使用するサブエージェントのタイプ
paths Globパターンのリスト。スキルが有効になるファイル範囲を制限します

呼び出し制御

frontmatterを使用して、誰がそのスキルを呼び出せるかを制御します：

設定 あなたが呼び出せる Claudeが呼び出せる
（デフォルト） 是 是
disable-model-invocation: true 是 否
user-invocable: false 否 是

変数置換

スキルコンテンツ内で変数を使用すると、Claudeが自動的に置換します：

変数 説明
$ARGUMENTS 呼び出し時に渡されるすべての引数
$ARGUMENTS[N] 0ベースのインデックスで特定の引数にアクセスします
$N $ARGUMENTS[N]の短縮形
${CLAUDE_SESSION_ID} 現在のセッションID
${CLAUDE_SKILL_DIR} スキルのSKILL.mdファイルが置かれているディレクトリ

スキルの保存場所

スキルは複数の場所に保存でき、有効範囲が異なります：

場所 パス 有効範囲
エンタープライズ ホスティング設定によって決まる 組織内のすべてのユーザー
個人 ~/.claude/skills/<skill-name>/SKILL.md すべてのプロジェクト
プロジェクト .claude/skills/<skill-name>/SKILL.md 現在のプロジェクトのみ
プラグイン <plugin>/skills/<skill-name>/SKILL.md プラグインが有効な範囲

.claude/commands/内のファイルは引き続き有効で、同じfrontmatterをサポートします。スキルとコマンドが同名の場合、スキルが優先されます。

高度な例

例1：デプロイコマンド（手動呼び出しのみ）

例

---
name: deploy
description: アプリケーションを本番環境にデプロイします
disable-model-invocation: true
---

$ARGUMENTS を本番環境にデプロイします：
11. テストスイートを実行する
22. アプリケーションをビルドする
33. デプロイ先にプッシュする

例2：パラメータ付きコンポーネント移行コマンド

例

---
name: migrate-component
description: コンポーネントをあるフレームワークから別のフレームワークに移行します
---

$0 コンポーネントを $1 から $2 に移行します。
既存のすべての動作とテストを保持します。

使用法：/migrate-component SearchBar React Vue

例3：動的コンテキスト付きPR要約コマンド

例

---
name: pr-summary
description: Pull Requestの変更を要約します
context: fork
agent: Explore
allowed-tools: Bash(gh *)
---

## Pull Request コンテキスト
- PR diff: !`gh pr diff`
- PRコメント: !`gh pr view --comments`
- 変更ファイル: !`gh pr diff --name-only`

## あなたのタスク
このPull Requestを要約してください...

組み込みスラッシュコマンド

Claude Codeには、すぐに使える組み込みコマンドがいくつか用意されています：

コマンド 機能
/batch <instruction> コードベース全体にわたる大規模な変更を調整します
/claude-api APIリファレンス資料を読み込みます
/debug [description] デバッグログを有効にします
/loop [interval] <prompt> 一定間隔でプロンプトを繰り返し実行します
/simplify [focus] コードの品質問題をレビューします

ベストプラクティス

1、descriptionの書き方

descriptionはClaudeの自動呼び出しの根拠となるため、必ず明確に書きましょう：

  • トリガーのタイミングを明確にする：当用户要求审查 / 分析 / 检查代码质量时调用
  • 前提条件を説明する：在规格文档确认后使用
  • 境界を明確に書く：どのような場合に呼び出すべきでないか

2、単一責任の原則

各スキルは1つのことだけを行い、明確な入力/出力を提供します：

  • /deploy：デプロイのみを担当
  • /test：テストの実行のみを担当
  • /review：コードレビューのみを担当

3、必要に応じて呼び出し権限を設定する

  • 危険な操作（デプロイ、削除）：設定disable-model-invocation: true
  • Claude 補助タスク：設定user-invocable: false
  • 一般的なフロー：デフォルト設定を使用

4、allowed-toolsを使用して権限を制限する

セキュリティ上重要な操作に最小権限を設定：

例

---
name: read-only-analyzer
description: 読み取り専用コード分析。コードのレビューと理解に使用
allowed-tools: Read, Grep, Glob, Bash(gh *)  # これらのツールのみ許可
---

読み取り専用コード分析を実行...

チーム共有戦略

プロジェクトレベルのスキルを git にコミットして、チームで共有：

my-project/
├── .claude/
│   ├── skills/
│   │   ├── deploy/
│   │   │   └── SKILL.md
│   │   ├── test/
│   │   │   └── SKILL.md
│   │   └── review/
│   │       └── SKILL.md
│   └── commands/  # 也可以用 commands/ 目录
└── CLAUDE.md

CLAUDE.md でプロジェクト固有のスキルを参照・説明：

## 自定义斜杠命令

本项目提供以下自定义斜杠命令：

- `/deploy [env]` — 部署到指定环境（dev/staging/prod）
- `/test [module]` — 运行测试套件或指定模块
- `/review` — 执行标准代码审查

详细使用说明请参考 @.claude/skills/README.md

よくある質問

Q：スキルとコマンドディレクトリの違いは何ですか？

本質的に違いはありません。.claude/commands/ 是 .claude/skills/の短縮形で、どちらの書き方でも正常に動作します。同名の場合はスキルが優先されます。

Q：呼び出し時に複数のパラメータを渡すにはどうすればいいですか？

引用符で複数のパラメータを囲みます：/migrate SearchBar "from:React to:Vue"、その後スキル内で使用します$ARGUMENTS完全な文字列を取得します。

Q：スキルはサブエージェントで使用できますか？

はい。以下の設定によりcontext: fork 和 agentフィールドを設定することで、サブエージェントが独立したコンテキストでスキルを実行できます。

Q：Claude に頻繁に使うスキルを覚えさせるにはどうすればいいですか？

CLAUDE.md に利用可能なすべてのカスタムコマンドとその使用シナリオをリストアップすると、Claude が説明に基づいて適切なスキルを自動的にマッチングします。
