Django ルーティング

ルーティングとは簡単に言うと、ユーザーがリクエストした URL リンクに基づいて対応する処理プログラムを判断し、処理結果を返すことです。つまり、URL と Django のビューのマッピング関係を確立することです。

Django のルーティングは urls.py で設定し、urls.py 内の各設定が対応する処理メソッドに対応します。

Django のバージョンによって urls.py の設定が少し異なります：

Django 1.1.x バージョン

url() メソッド：通常パスと正規表現パスの両方で使用できます。正規表現の先頭と末尾の制限記号を手動で追加する必要があります。

実例

from django.conf.urls import url # url を使用するにはインポートが必要

urlpatterns = [
    url(r'^admin/$', admin.site.urls),
    url(r'^index/$', views.index), # 通常パス
    url(r'^articles/([0-9]{4})/$', views.articles), # 正規表現パス
]

Django 2.2.x 以降のバージョン

  • path：通常パスに使用します。正規表現の先頭と末尾の制限記号を手動で追加する必要はなく、内部で自動的に追加されます。
  • re_path：正規表現パスに使用します。正規表現の先頭と末尾の制限記号を手動で追加する必要があります。

実例

from django.urls import re_path # re_path を使用するにはインポートが必要
urlpatterns = [
    path('admin/', admin.site.urls),
    path('index/', views.index), # 通常パス
    re_path(r'^articles/([0-9]{4})/$', views.articles), # 正規表現パス
]

まとめ：Django 1.1.x バージョンの url と Django 2.2.x バージョンの re_path の使い方は同じです。

正規表現パス内のグループ

正規表現パス内の無名グループ

無名グループは位置でパラメータを渡し、一対一で対応します。

views では request を除き、他の仮引数の数は urls 内のグループ数と一致する必要があります。

urls.py

urlpatterns = [
    path('admin/', admin.site.urls),
    re_path("^index/([0-9]{4})/$", views.index),
]

views.py

from django.shortcuts import HttpResponse

def index(request, year):
    print(year) # 1つの仮引数がパス内の1つのグループの内容を表し、順番にマッチします。
    return HttpResponse('菜鸟教程')

正規表現パス内の名前付きグループ

構文：

(?P<组名>正则表达式)

名前付きグループはキーワードでパラメータを渡し、位置順序とは無関係です。

views では request を除き、他の仮引数の数は urls 内のグループ数と一致する必要があり、さらに views 内の仮引数名は urls 内のグループ名と対応する必要があります。

urls.py

urlpatterns = [
    path('admin/', admin.site.urls),
    re_path("^index/(?P[0-9]{4})/(?P[0-9]{2})/$", views.index),
]

views.py

from django.shortcuts import HttpResponse
def index(request, year, month):
    print(year,month) # 1つの仮引数がパス内の1つのグループの内容を表し、キーワードに対応してマッチします。
    return HttpResponse('菜鸟教程')

正規表現パス内の名前付きグループ

ルーティング分散 (include)

問題点：Django プロジェクト内の複数の app ディレクトリが1つの urls を共有すると混乱しやすく、後のメンテナンスも不便です。

解決策：ルーティング分散（include）を使用して、各 app ディレクトリがそれぞれ独自の urls を持つようにします。

手順：

  • 1、各 app ディレクトリ内に urls.py ファイルを作成します。
  • 2、プロジェクト名ディレクトリの urls ファイルで、パスを各 app ディレクトリに一括で振り分けます。

実例

from django.contrib import admin
from django.urls import path,include # django.urls から include をインポート
urlpatterns = [
    path('admin/', admin.site.urls),
    path("app01/", include("app01.urls")),
    path("app02/", include("app02.urls")),
]

各 app ディレクトリで、独自の urls.py ファイルを書き、パスの遷移を行います。

app01 ディレクトリ：

from django.urls import path,re_path 
from app01 import views # 从自己的 app 目录引入 views 
urlpatterns = [ 
    re_path(r'^login/(?P<m>[0-9]{2})/$', views.index, ),
]

app02 ディレクトリ：

from django.urls import path,re_path
from app02 import views # 从自己的 app 目录引入views 
urlpatterns = [ 
    re_path("^xxx/(?P[0-9]{4})/$", views.xxx), 
]

各 app ディレクトリの views.py ファイルにそれぞれのビュー関数を書きます。

逆解析

機能の追加に伴い、ルーティング層の url が変更されると、対応するビュー層とテンプレート層の url を変更する必要があり、非常に手間がかかり、メンテナンスが不便です。

このような場合、逆解析を利用できます。ルーティング層の url が変更されると、ビュー層とテンプレート層で変更後の url を動的に逆解析し、修正作業を省くことができます。

逆解析は一般に、テンプレート内のハイパーリンクやビュー内のリダイレクトで使用されます。

通常パス

urls.py でルートにエイリアスを付けます。name="ルートエイリアス"。

path("login1/", views.login, name="login")

views.py で、django.urls から reverse をインポートし、次を使用してreverse("ルートエイリアス")逆解析：

return redirect(reverse("login"))

テンプレート templates 内の HTML ファイルで、次を使用して{% url "ルートエイリアス" %}逆解析します。

<form action="{% url 'login' %}" method="post">

正規表現パス（無名グループ）

urls.py でルートにエイリアスを付けます。name="ルートエイリアス"。

re_path(r"^login/([0-9]{2})/$", views.login, name="login")

views.py で、django.urls から reverse をインポートし、次を使用してreverse("ルートエイリアス", args=(正規表現にマッチするパラメータ,))逆解析します。

return redirect(reverse("login",args=(10,)))

テンプレート templates 内の HTML ファイルで次を使用して{% url "ルートエイリアス" 正規表現にマッチするパラメータ %}逆解析します。

<form action="{% url 'login' 10 %}" method="post">

正規表現パス（名前付きグループ）

urls.py でルートにエイリアスを付けます。name="ルートエイリアス"。

re_path(r"^login/(?P<year>[0-9]{4})/$", views.login, name="login")

views.py で、django.urls から reverse をインポートし、次を使用してreverse("ルートエイリアス", kwargs={"グループ名": 正規表現にマッチするパラメータ})逆解析します。

return redirect(reverse("login",kwargs={"year":3333}))

テンプレート templates 内の HTML ファイルで、次を使用して{% url "ルートエイリアス" グループ名=正規表現にマッチするパラメータ %}逆解析します。

<form action="{% url 'login' year=3333 %}" method="post">

名前空間

名前空間（英語：Namespace）は、識別子の可視範囲を表します。

1つの識別子は複数の名前空間で定義でき、異なる名前空間での意味は互いに無関係です。

新しい名前空間には任意の識別子を定義でき、それらは重複する識別子と衝突しません。なぜなら、重複する定義はすべて他の名前空間にあるからです。

問題点：ルートエイリアス name にはスコープがありません。Django は URL を逆解析する際、プロジェクト全体を順番に検索し、最初に見つかったルートエイリアス name が指定する URL を即座に返します。異なる app ディレクトリの urls で同じルートエイリアス name を定義すると、URL の逆解析エラーが発生する可能性があります。

解決策：名前空間を使用します。

通常パス

名前空間の定義（include の中はタプル）は次の形式です：
include(("app名称：urls"，"app名称"))

実例：

path("app01/", include(("app01.urls","app01"))) 
path("app02/", include(("app02.urls","app02")))

app01/urls.py で同じルートエイリアスを付けます。

path("login/", views.login, name="login")

views.py で名前空間を使用する場合、構文は次の形式です：

reverse("app名称：路由别名")

実例：

return redirect(reverse("app01:login")

テンプレート templates 内の HTML ファイルで名前空間を使用する場合、構文は次の形式です：

{% url "app名称：路由别名" %}

実例：

<form action="{% url 'app01:login' %}" method="post">
