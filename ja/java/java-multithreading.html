Java マルチスレッドプログラミング

Java はマルチスレッドプログラミングを組み込みでサポートしています。スレッドとは、プロセス内の単一の順次制御フローのことです。1つのプロセスは複数のスレッドを並行して持つことができ、各スレッドは異なるタスクを並行して実行します。

マルチスレッドはマルチタスクの特別な形態ですが、マルチスレッドはより少ないリソースオーバーヘッドで済みます。

ここでは、スレッドに関連するもう1つの用語、プロセスを定義します。プロセスには、オペレーティングシステムによって割り当てられたメモリ空間が含まれ、1つ以上のスレッドが含まれます。スレッドは単独で存在することはできず、プロセスの一部である必要があります。プロセスは、すべての非デーモンスレッドが実行を終了するまで実行され続け、その後終了します。

マルチスレッドは、プログラマーが CPU を十分に活用するための高効率なプログラムを作成するという目的を満たします。

スレッドのライフサイクル

スレッドは動的な実行過程であり、生成から終了までの過程もあります。

次の図は、スレッドの完全なライフサイクルを示しています。

  • 新規作成状態：

    使用newキーワードとThreadクラスまたはそのサブクラスでスレッドオブジェクトを作成すると、そのスレッドオブジェクトは新規作成状態になります。この状態は、プログラムがstart()このスレッド。

  • 実行可能状態：

    スレッドオブジェクトが start() メソッドを呼び出すと、そのスレッドは実行可能状態になります。実行可能状態のスレッドは実行可能キューにあり、JVM 内のスレッドスケジューラによるスケジューリングを待機する必要があります。

  • 実行状態：

    実行可能状態のスレッドが CPU リソースを取得すると、実行できますrun()、この時点でスレッドは実行状態になります。

  • ブロック状態：

    スレッドが sleep（スリープ）、suspend（一時停止）などのメソッドを実行し、占有していたリソースを失った後、そのスレッドは実行状態からブロック状態に入ります。スリープ時間が経過した後、またはデバイスリソースを取得した後、実行可能状態に再び入ることができます。次の3つに分類できます：

    • 待機ブロック：実行状態のスレッドが wait() メソッドを実行すると、スレッドは待機ブロック状態に入ります。

    • 同期ブロック：スレッドが synchronized 同期ロックの取得に失敗した場合（同期ロックが他のスレッドに占有されているため）。

    • その他のブロック：スレッドの sleep() または join() の呼び出しによって I/O リクエストが発行されると、スレッドはブロック状態に入ります。sleep() のタイムアウト、join() によるスレッド終了待ちまたはタイムアウト、あるいは I/O 処理の完了により、スレッドは実行可能状態に戻ります。

  • 終了状態：

    実行状態のスレッドがタスクを完了するか、他の終了条件が発生すると、そのスレッドは終了状態に遷移します。

スレッドの優先度

すべての Java スレッドには優先度があり、これによりオペレーティングシステムがスレッドのスケジューリング順序を決定しやすくなります。

Java スレッドの優先度は整数で、その値の範囲は 1（Thread.MIN_PRIORITY）から 10（Thread.MAX_PRIORITY）です。

デフォルトでは、各スレッドには NORM_PRIORITY（5）の優先度が割り当てられます。

優先度の高いスレッドはプログラムにとってより重要であり、優先度の低いスレッドよりも先にプロセッサリソースを割り当てられる必要があります。ただし、スレッドの優先度はスレッドの実行順序を保証するものではなく、プラットフォームに大きく依存します。

スレッドの作成

Java にはスレッドを作成するための3つの方法があります：

  • Runnable インターフェースを実装する方法；
  • Thread クラス自体を継承する方法；
  • Callable と Future を使用してスレッドを作成する方法。

Runnable インターフェースを実装してスレッドを作成する

スレッドを作成する最も簡単な方法は、Runnable インターフェースを実装するクラスを作成することです。

Runnable を実装するには、クラスは run() メソッドの呼び出しを1つ実行するだけで済みます。宣言は次のとおりです：

public void run()

このメソッドはオーバーライドできます。重要なのは、run() が他のメソッドを呼び出し、他のクラスを使用し、変数を宣言できることを理解することです。メインスレッドと同じように。

Runnable インターフェースを実装するクラスを作成した後、その中でスレッドオブジェクトをインスタンス化できます。

Thread にはいくつかのコンストラクタが定義されていますが、次に示すものはよく使用されるコンストラクタです：

Thread(Runnable threadOb,String threadName);

ここで、threadOb は Runnable インターフェースを実装するクラスのインスタンスであり、threadName は新しいスレッドの名前を指定します。

新しいスレッドは、その start() メソッドを呼び出して初めて実行されます。

void start();

以下は、スレッドを作成して実行を開始する例です：

例

class RunnableDemo implements Runnable { private Thread t; private String threadName; RunnableDemo( String name) { threadName = name; System.out.println("Creating " + threadName ); } public void run() { System.out.println("Running " + threadName ); try { for(int i = 4; i > 0; i--) { System.out.println("Thread: " + threadName + ", " + i); //スレッドをしばらくスリープさせる Thread.sleep(50); } }catch (InterruptedException e) { System.out.println("Thread " + threadName + " interrupted."); } System.out.println("Thread " + threadName + " exiting."); } public void start () { System.out.println("Starting " + threadName ); if (t == null) { t = new Thread (this, threadName); t.start (); } } } public class TestThread { public static void main(String args[]) { RunnableDemo R1 = new RunnableDemo( "Thread-1"); R1.start(); RunnableDemo R2 = new RunnableDemo( "Thread-2"); R2.start(); } }

Thread を継承してスレッドを作成する

スレッドを作成する2つ目の方法は、Thread クラスを継承する新しいクラスを作成し、そのクラスのインスタンスを作成することです。

継承したクラスは run() メソッドをオーバーライドする必要があります。このメソッドは新しいスレッドのエントリポイントです。また、実行するには start() メソッドを呼び出す必要があります。

この方法はマルチスレッドの実装方法として挙げられていますが、本質的には Runnable インターフェースを実装したインスタンスでもあります。

例

class ThreadDemo extends Thread { private Thread t; private String threadName; ThreadDemo( String name) { threadName = name; System.out.println("Creating " + threadName ); } public void run() { System.out.println("Running " + threadName ); try { for(int i = 4; i > 0; i--) { System.out.println("Thread: " + threadName + ", " + i); //スレッドをしばらくスリープさせる Thread.sleep(50); } }catch (InterruptedException e) { System.out.println("Thread " + threadName + " interrupted."); } System.out.println("Thread " + threadName + " exiting."); } public void start () { System.out.println("Starting " + threadName ); if (t == null) { t = new Thread (this, threadName); t.start (); } } } public class TestThread { public static void main(String args[]) { ThreadDemo T1 = new ThreadDemo( "Thread-1"); T1.start(); ThreadDemo T2 = new ThreadDemo( "Thread-2"); T2.start(); } }

Callable と Future によるスレッドの作成

  • 1. Callable インターフェースの実装クラスを作成し、call() メソッドを実装します。この call() メソッドはスレッドの実行本体として機能し、戻り値を持ちます。

  • 2. Callable 実装クラスのインスタンスを作成し、FutureTask クラスを使用して Callable オブジェクトをラップします。この FutureTask オブジェクトは、その Callable オブジェクトの call() メソッドの戻り値をカプセル化します。

  • 3. FutureTaskオブジェクトをThreadオブジェクトのtargetとして使用して、新しいスレッドを作成し開始します。

  • 4. FutureTaskオブジェクトのget()メソッドを呼び出して、子スレッドの実行終了後の戻り値を取得します。

例

public class CallableThreadTest implements Callable<Integer> { public static void main(String[] args) { CallableThreadTest ctt = new CallableThreadTest(); FutureTask<Integer> ft = new FutureTask<>(ctt); for(int i = 0;i < 100;i++) { System.out.println(Thread.currentThread().getName()+"のループ変数iの値"+i); if(i==20) { new Thread(ft,"戻り値のあるスレッド").start(); } } try { System.out.println("子スレッドの戻り値："+ft.get()); } catch (InterruptedException e) { e.printStackTrace(); } catch (ExecutionException e) { e.printStackTrace(); } } @Override public Integer call() throws Exception { int i = 0; for(;i<100;i++) { System.out.println(Thread.currentThread().getName()+" "+i); } return i; } }

スレッドを作成する3つの方法の比較

  • 1. Runnable、Callableインターフェースを実装する方法でマルチスレッドを作成する場合、スレッドクラスはRunnableインターフェースまたはCallableインターフェースを実装するだけであり、他のクラスを継承することもできます。

  • 2. Threadクラスを継承する方法でマルチスレッドを作成する場合、記述は簡単です。現在のスレッドにアクセスする必要がある場合、Thread.currentThread()メソッドを使用する必要はなく、直接thisを使用して現在のスレッドを取得できます。

スレッドのいくつかの主要な概念

マルチスレッドプログラミングでは、以下のいくつかの概念を理解する必要があります：

  • スレッド同期
  • スレッド間通信
  • スレッドデッドロック
  • スレッド制御：一時停止、停止、再開

マルチスレッドの使用

マルチスレッドを効果的に利用する鍵は、プログラムが直列に実行されるのではなく並行して実行されることを理解することです。例：プログラム内に並行して実行する必要がある2つのサブシステムがある場合、このときマルチスレッドプログラミングを利用する必要があります。

マルチスレッドを使用することで、非常に効率的なプログラムを作成できます。ただし、あまりにも多くのスレッドを作成すると、プログラムの実行効率は実際には向上せず、低下することに注意してください。

コンテキストスイッチのオーバーヘッドも重要であることを覚えておいてください。あまりにも多くのスレッドを作成すると、CPUがコンテキストスイッチに費やす時間は、プログラムの実行時間よりも多くなります。

    2、では、なぜスレッドプールを使用する必要があるのでしょうか？使用するたびに手動で作成してはだめでしょうか？

    Javaでは、各リクエストの到着ごとに新しいスレッドを作成すると、オーバーヘッドがかなり大きくなります。実際の使用では、スレッドの作成と破棄にかかる時間と消費するシステムリソースはかなり大きく、実際のユーザーリクエストの処理にかかる時間とリソースよりもはるかに多くなる可能性さえあります。スレッドの作成と破棄のオーバーヘッドに加えて、アクティブなスレッドもシステムリソースを消費します。1つのJVM内で作成するスレッドが多すぎると、メモリの過剰消費や「切り替えすぎ」によってシステムがリソース不足になる可能性があります。リソース不足を防ぐために、任意の時点で処理するリクエスト数を制限し、スレッドの作成と破棄の回数、特にリソース消費量が多いスレッドの作成と破棄をできるだけ減らし、既存のオブジェクトをできる限り利用してサービスを提供するための何らかの方法を取る必要があります。（なぜ）

    スレッドプールは主に、スレッドのライフサイクルのオーバーヘッド問題とリソース不足の問題を解決するために使用されます。複数のタスクに対してスレッドを繰り返し使用することで、スレッド作成のオーバーヘッドが複数のタスクに分散され、リクエストの到着時にはスレッドがすでに存在するため、スレッド作成による遅延が解消されます。これにより、すぐにリクエストにサービスを提供でき、アプリケーションの応答が速くなります。さらに、スレッドプール内のスレッド数を適切に調整することで、リソース不足を防ぐことができます。（何の役に立つか）

    3、スレッドプールはすべてスレッドプールファクトリを通じて作成され、次にスレッドプール内のメソッドを呼び出してスレッドを取得し、さらにスレッドを通じてタスクメソッドを実行します。

    • Executors：スレッドプール作成ファクトリクラス
    • public static ExecutorServicenewFixedThreadPool(int nThreads)：スレッドプールオブジェクトを返す
    • ExecutorService：スレッドプールクラス
    • Future<?> submit(Runnable task)：スレッドプールからいずれかのスレッドオブジェクトを取得して実行する
    • Future インターフェース：スレッドタスクの実行完了後に生成された結果を記録するために使用します。スレッドプールの作成と使用

    4、ここではスレッドプールを使用してスレッドを作成する2つの方法を紹介します。

    1）：Runnableインターフェースを使用してスレッドプールを作成する

    スレッドプール内のスレッドオブジェクトを使用する手順：

    • 1、スレッドプールオブジェクトを作成する
    • 2、Runnableインターフェースのサブクラスオブジェクトを作成する
    • 3、Runnableインターフェースのサブクラスオブジェクトを送信する
    • 4、スレッドプールを閉じる

    Test.javaコードは次のとおりです：

    import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

public class Test {
    public static void main(String[] args) {
        //创建线程池对象  参数5，代表有5个线程的线程池
        ExecutorService service = Executors.newFixedThreadPool(5);
        //创建Runnable线程任务对象
        TaskRunnable task = new TaskRunnable();
        //从线程池中获取线程对象
        service.submit(task);
        System.out.println("----------------------");
        //再获取一个线程对象
        service.submit(task);
        //关闭线程池
        service.shutdown();
    }
}

    TaskRunnable.java インターフェースファイルは次のとおりです：

    public class TaskRunnable implements Runnable{
    @Override
    public void run() {
        for (int i = 0; i < 1000; i++) {
            System.out.println("自定义线程任务在执行"+i);
        }
    }
}

    2）Callableインターフェースを使用してスレッドプールを作成する

    Callableインターフェース：Runnableインターフェースと機能が似ており、スレッドのタスクを指定するために使用します。その中のcall()メソッドは、スレッドタスクの実行完了後の結果を返すために使用し、callメソッドは例外をスローできます。

    ExecutorService：スレッドプールクラス

    <T> Future<T> submit(Callable<T> task)：スレッドプールからいずれかのスレッドオブジェクトを取得し、スレッド内のcall()メソッドを実行する

    プロセスとスレッドの違い

    プロセス

    アプリケーションの実行インスタンスであり、独立したメモリ空間とシステムリソースを持ちます

    スレッド

    CPUスケジューリングとディスパッチの基本単位であり、プロセス内で演算を実行する最小単位で、独立した順次制御フローを完了できます

    プロセスとスレッドの関係

    （1）1つのスレッドは1つのプロセスにのみ属することができますが、1つのプロセスは複数のスレッドを持つことができ、少なくとも1つのスレッドを持ちます。スレッドはオペレーティングシステムが認識できる最小の実行・スケジューリング単位です。

    （2）リソースはプロセスに割り当てられ、同じプロセスのすべてのスレッドはそのプロセスのすべてのリソースを共有します。同じプロセス内の複数のスレッドは、コードセグメント（コードと定数）、データセグメント（グローバル変数と静的変数）、拡張セグメント（ヒープストレージ）を共有します。ただし、各スレッドは独自のスタックセグメントを持ち、スタックセグメントは実行時セグメントとも呼ばれ、すべてのローカル変数と一時変数を格納するために使用されます。

    （3）プロセッサはスレッドに割り当てられます。つまり、実際にプロセッサ上で実行されるのはスレッドです。

    （4）スレッドは実行中に協調して同期する必要があります。異なるプロセスのスレッド間では、メッセージ通信の方法を利用して同期を実現する必要があります。

    Java Thread における run() と start() の違い

    Javaのスレッドはjava.lang.Threadクラスを通じて実装されます。VM起動時にはmainメソッドによって定義されたスレッドが1つあります。Threadのインスタンスを作成することで新しいスレッドを作成できます。各スレッドは特定のThreadオブジェクトに対応するメソッドrun()を通じてその操作を完了します。メソッドrun()はスレッド本体と呼ばれます。Threadクラスのstart()メソッドを呼び出すことでスレッドを起動します。

    Javaでは、スレッドには通常5つの状態があります。作成、実行可能、実行、ブロック、終了です。

    • 1つ目は作成状態です。スレッドオブジェクトを生成しても、そのオブジェクトのstartメソッドを呼び出していない場合、このときスレッドは作成状態にあります。
    • 2つ目は実行可能状態です。スレッドオブジェクトのstartメソッドを呼び出すと、そのスレッドは実行可能状態に入ります。ただし、このときスレッドスケジューラはまだそのスレッドを現在のスレッドに設定していないため、実行可能状態にあります。スレッドが実行された後、待機またはスリープから戻った後も実行可能状態になります。
    • 3つ目は実行状態です。スレッドスケジューラが実行可能状態のスレッドを現在のスレッドに設定すると、このときスレッドは実行状態に入り、run関数内のコードを実行し始めます。
    • 4つ目はブロック状態です。スレッドが実行されているときに一時停止されます。通常は、何らかのイベントの発生（たとえば、あるリソースの準備完了）を待ってから実行を続けるためです。sleep、suspend、waitなどのメソッドはスレッドをブロックさせる可能性があります。
    • 5つ目は終了状態です。スレッドのrunメソッドの実行が終了するか、stopメソッドを呼び出すと、そのスレッドは終了します。終了したスレッドに対して、startメソッドを使用して実行可能状態にすることはできません。

    スレッドを実装して起動するには2つの方法があります

    • 1、Threadクラスを継承するクラスを作成し、runメソッドをオーバーライドします。startメソッドでスレッドを起動します。
    • 2、Runnableインターフェースを実装するクラスを作成し、runメソッドを実装します。new Thread(Runnable target).start()メソッドを使用して起動します。

    マルチスレッドの原理：ゲーム機で遊ぶのと同じようなものです。ゲーム機（CPU）は1台しかありませんが、遊びたい人は大勢います。そこで、startは並ぶことです！CPUに選ばれたらあなたの番になり、run()を実行します。CPUの実行タイムスライスが終了すると、このスレッドは再度並び、次のrun()を待ちます。

    start()を呼び出すと、スレッドは待機キューに置かれ、CPUのスケジューリングを待ちます。すぐに実行が開始されるとは限らず、このスレッドを実行可能状態にするだけです。その後、JVMを介してThreadスレッドがrun()メソッドを呼び出し、このスレッドのスレッド本体を実行します。わざわざstartを呼び出してからrunを呼び出すのは面倒ですが、なぜ直接runを呼び出さないのでしょうか？それはマルチスレッドの利点を実現するためであり、このstartなしでは実現できないからです。

    • 1.start() start()メソッドでスレッドを起動し、真のマルチスレッド実行を実現します。この場合、runメソッド本体のコードの実行が完了するのを待つ必要はなく、そのまま次のコードを実行できます。Threadクラスのstart()メソッドを呼び出してスレッドを起動すると、このスレッドは実行可能状態になり、まだ実行されていません。そして、このThreadクラスがrun()メソッドを呼び出して実行操作を完了します。ここでのrun()メソッドはスレッド本体と呼ばれ、実行するスレッドの内容が含まれています。runメソッドの実行が終了すると、このスレッドは終了します。その後、CPUが他のスレッドをスケジューリングします。
    • 2.run()run()メソッドを普通のメソッドとして呼び出します。プログラムは依然として順次実行され、runメソッド本体の実行が完了するのを待ってから、次のコードを実行できます。プログラムにはメインスレッドという1つのスレッドしかなく、プログラムの実行経路も1つだけです。これではスレッドを書く目的を達成できません。

    覚えておきましょう：マルチスレッドとは、CPUを時分割で利用し、マクロ的にはすべてのスレッドを同時に実行させることで、並行処理（コンカレント）とも呼ばれます。

    スレッド状態図：

    スレッドには以下の5つの状態があります。

    1. 新規作成状態(New)：スレッドオブジェクトが作成されると、新規作成状態に入ります。例：Thread thread = new Thread()。

    2. 実行可能状態(Runnable)：「実行可能状態」とも呼ばれます。スレッドオブジェクトが作成された後、他のスレッドがそのオブジェクトのstart()メソッドを呼び出して、そのスレッドを起動します。例：thread.start()。実行可能状態のスレッドは、いつでもCPUによってスケジューリングされ実行される可能性があります。

    3. 実行状態(Running)：スレッドがCPUの実行権限を取得して実行します。注意すべき点は、スレッドは実行可能状態から実行状態にのみ移行できるということです。

    4. ブロック状態(Blocked)：ブロック状態とは、スレッドが何らかの理由でCPUの使用権を放棄し、一時的に実行を停止している状態です。スレッドが実行可能状態に入って初めて、実行状態に移行する機会が得られます。ブロックの状況は次の3つに分けられます：

    • (01) 待機ブロック -- スレッドのwait()メソッドを呼び出して、スレッドにある作業の完了を待機させます。
    • (02) 同期ブロック -- スレッドがsynchronized同期ロックの取得に失敗した場合（ロックが他のスレッドに占有されているため）、同期ブロック状態に入ります。
    • (03) その他のブロック -- スレッドのsleep()やjoin()を呼び出した場合、またはI/O要求を発行した場合、スレッドはブロック状態に入ります。sleep()のタイムアウト、join()の待機スレッドの終了またはタイムアウト、I/O処理の完了時に、スレッドは再び実行可能状態に移行します。

    5. 終了状態(Dead)：スレッドの実行が完了するか、例外によってrun()メソッドを終了した場合、そのスレッドはライフサイクルを終了します。

    スレッドセーフティ問題

    発生原因：複数のスレッドが同じリソースを競合する（同じデータにアクセスする）場合です。古典的な生産者・消費者問題を参考にしてください。

    解決策：

    runメソッド内：同期コードブロック synchronized {}

    Public synchronized 返回值类型 方法名（）{} 自动释放对象锁

    Lockロックを使用する

    Lockロックはプログラマが（finallyコードブロック内で）手動で解放する必要があります。

    Lock lock=new ReentranttLock()    // Reentrant（可重用的）

    Lock実装は、synchronizedメソッドやステートメントを使用して得られるものよりも広範なロック操作を提供し、JDK1.5以降に登場しました。

    Lockインターフェースのメソッド：

    void lock()   // 获取锁 
void unlock() // 释放锁

    Lockインターフェースの実装クラス：

    java.util.concurrent.locks.ReentrantLock implements Lock

    使用手順：

    • 1. メンバーの位置にReentrantLockオブジェクトを作成します。
    • 2. スレッドセーフティ問題が発生する可能性のあるコードの前に、Lockインターフェースのlockメソッドを呼び出してロックオブジェクトを取得します。
    • 3. スレッドセーフティ問題が発生する可能性のあるコードの後に、Lockインターフェースのunlockメソッドを呼び出してロックオブジェクトを解放します。
    public class RunnableImpl implements Runnable{
    //定义一个共享的票源
    private int ticket = 100;
    //1.在成员位置创建一个ReentrantLock对象
    Lock l = new ReentrantLock();
    //设置线程任务:卖票
    @Override
    public void run() {
        //使用死循环,让卖票重复的执行
        while(true){
            //2.在可能出现线程安全问题的代码前,调用Lock接口中的方法lock获取锁对象
            l.lock();
            //判断票是否大于0
            if(ticket>0){
                //为了提高线程安全问题出现的几率,让程序睡眠10毫秒
                try {
                    //可能会产生异常的代码
                    Thread.sleep(10);
                    //进行卖票 ticket--
                    System.out.println(Thread.currentThread().getName()+"正在卖第"+ticket+"张票!");
                    ticket--;
                } catch (InterruptedException e) {
                    //异常的处理逻辑
                    e.printStackTrace();
                }finally {
                    //一定会执行的代码,一般用于资源释放(资源回收)
                    //3.在可能出现线程安全问题的代码后,调用Lock接口中的方法unlock释放锁对象
                    l.unlock();//无论程序是否有异常,都让锁对象释放掉,节约内存,提高程序的效率
                }
            }
        }
    }
}

    CompletableFutureを使用してコールバックの問題を解決します。

    import java.util.concurrent.CompletableFuture;
import java.util.concurrent.CountDownLatch;

public class CompletableFutureDemo {
    public static void main(String[] args) throws InterruptedException {
        long l = System.currentTimeMillis();
        CompletableFuture<Integer> completableFuture = CompletableFuture.supplyAsync(() -> {
            System.out.println("执行耗时操作...");
            timeConsumingOperation();
            return 100;
        });
        completableFuture.whenComplete((result, e) -> {
            System.out.println("结果：" + result);
        });
        System.out.println("主线程运算耗时:" + (System.currentTimeMillis() - l) + " ms");
        new CountDownLatch(1).await();
    }

    static void timeConsumingOperation() {
        try {
            Thread.sleep(3000);
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
