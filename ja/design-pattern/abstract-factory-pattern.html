抽象ファクトリーパターン

抽象ファクトリーパターン（Abstract Factory Pattern）は、スーパーファクトリーを中心として他のファクトリーを作成します。このスーパーファクトリーは、他のファクトリーのファクトリーとも呼ばれます。このタイプのデザインパターンは生成系パターン（クリエイショナルパターン）に属し、オブジェクトを作成する最良の方法を提供します。

抽象ファクトリーパターンでは、インターフェースは関連するオブジェクトを作成するファクトリーの役割を担い、それらのクラスを明示的に指定する必要はありません。生成された各ファクトリーは、ファクトリーパターンに従ってオブジェクトを提供できます。

抽象ファクトリーパターンは、具体的な実装クラスを指定することなく、一連の関連するオブジェクトまたは相互依存するオブジェクトを作成するためのインターフェースを提供します。抽象ファクトリーパターンを使用することで、クライアントと具体的な製品の作成プロセスを分離（デカップリング）し、クライアントがファクトリーインターフェースを通じて製品群を作成できるようにします。

概要

意図

一連の関連するオブジェクトまたは相互依存するオブジェクトを作成するためのインターフェースを提供し、それらの具体的なクラスを指定する必要はありません。

主な解決

インターフェースの選択に関する問題。

適用シナリオ

システムが複数の関連オブジェクトや依存オブジェクトを作成する必要があり、具体的なクラスを指定する必要がない場合。

解決策

製品ファミリー内で複数の製品を定義し、具象ファクトリーがこれらの製品を作成するメソッドを実装します。

キーコード

1つのファクトリーに複数の同種製品の作成メソッドを集約します。

応用例

異なるタイプのワードローブがあるとします。各ワードローブ（具象ファクトリー）は、ビジネススーツ、ファッションウェアなど、1種類の衣類（セットになった具象製品）しか収納できません。各セットには、具体的な上着とズボン（具象製品）が含まれます。すべてのワードローブはワードローブクラス（抽象ファクトリー）の具体的な実装であり、すべての上着とズボンは、それぞれ上着インターフェースとズボンインターフェース（抽象製品）を実装します。

長所

  1. 同じ製品ファミリーのオブジェクトが一緒に動作することを保証します。
  2. クライアントは各オブジェクトの具体的なクラスを知る必要がなく、コードが簡素化されます。

短所

製品ファミリーの拡張は非常に困難です。新しい製品ファミリーを追加するには、抽象ファクトリーとすべての具象ファクトリーのコードを変更する必要があります。

使用シーン

  1. QQでスキンを変更する場合、スキン一式をまとめて変更します。
  2. クロスプラットフォームアプリケーションを作成する際に、異なるオペレーティングシステム向けのプログラムを生成します。

注意事項

新しい製品ファミリーの追加は比較的容易ですが、新しい製品の階層構造の追加は困難です。

構造

抽象ファクトリーパターンには、次の主要なロール（役割）が含まれます。

  • 抽象ファクトリー（Abstract Factory）：製品オブジェクトを作成するための一連のメソッドを宣言します。各メソッドは1つの製品タイプに対応します。抽象ファクトリーはインターフェースまたは抽象クラスにできます。
  • 具象ファクトリー（Concrete Factory）：抽象ファクトリーインターフェースを実装し、具体的な製品オブジェクトのインスタンスを作成します。
  • 抽象製品（Abstract Product）：一連の製品オブジェクトの共通インターフェースまたは抽象クラスを定義し、製品オブジェクトのパブリックメソッドを記述します。
  • 具象製品（Concrete Product）：抽象製品インターフェースを実装し、具体的な製品の特定の動作と属性を定義します。

抽象ファクトリーパターンは通常、関連する製品群（ファミリー）を扱います。各具象ファクトリークラスは、その製品群内の具象製品を作成します。クライアントは抽象ファクトリーインターフェースを使用して製品オブジェクトを作成するため、具象製品の実装クラスを直接使用する必要はありません。

実装

作成するのはShape 和 Colorインターフェースと、そのインターフェースを実装するエンティティクラスです。次のステップでは、抽象ファクトリークラスを作成します。AbstractFactory。次に、ファクトリークラスを定義します。ShapeFactory 和 ColorFactory、これら2つのファクトリークラスはどちらも拡張したものです。AbstractFactory。次に、ファクトリークリエイター/ジェネレータークラスを作成します。FactoryProducer。

AbstractFactoryPatternDemoクラスは、FactoryProducerを使用して取得しますAbstractFactoryオブジェクトを。これはAbstractFactoryに形状情報を渡しますShape（CIRCLE / RECTANGLE / SQUARE）、必要なオブジェクトのタイプを取得するためです。同時に、AbstractFactoryに色情報を渡しますColor（RED / GREEN / BLUE）、必要なオブジェクトのタイプを取得するためです。

public class ColorFactory extends AbstractFactory { @Override public Shape getShape(String shapeType){ return null; } @Override public Color getColor(String color) { if(color == null){ return null; } if(color.equalsIgnoreCase("RED")){ return new Red(); } else if(color.equalsIgnoreCase("GREEN")){ return new Green(); } else if(color.equalsIgnoreCase("BLUE")){ return new Blue(); } return null; } }

ステップ 7

形状または色の情報を渡すことによってファクトリーを取得する、ファクトリークリエイター/ジェネレータークラスを作成します。

FactoryProducer.java

public class FactoryProducer { public static AbstractFactory getFactory(String choice){ if(choice.equalsIgnoreCase("SHAPE")){ return new ShapeFactory(); } else if(choice.equalsIgnoreCase("COLOR")){ return new ColorFactory(); } return null; } }

    以下の例では、マウス、キーボード、ヘッドセットが製品であり、HP、Dellがファクトリーです。

    単純ファクトリーパターン

    単純ファクトリーパターンは23種（GoFの23のデザインパターン）には含まれません。簡単に言うと、特定の製品を専門に生産するクラスがあるということです。

    例えば、下図のマウスファクトリーはマウスの専門生産で、パラメータ0を渡すとDellマウスを生産し、パラメータ1を渡すとHPマウスを生産します。

    ファクトリーパターン

    ファクトリーパターンでは、マウスファクトリーが親クラスであり、マウスを生産するインターフェースを持ちます。

    DellマウスファクトリーとHPマウスファクトリーがそれを継承し、それぞれDellマウスとHPマウスを生産できます。

    どのマウスを生産するかはパラメータで決まるのではなく、マウスファクトリーを作成する際に、Dellマウスファクトリーによって作成されます。

    その後は直接呼び出します鼠标工厂.生产鼠标()だけでよいです。

    抽象ファクトリーパターン

    抽象ファクトリーパターンとは、マウスだけでなくキーボードも生産するものです。

    つまり、PCメーカーが親クラスであり、マウス生産、キーボード生産の2つのインターフェースを持ちます。

    DellファクトリーとHPファクトリーがそれを継承し、それぞれDellマウス+Dellキーボード、HPマウス+HPキーボードを生産できます。

    ファクトリーを作成するときは、Dellファクトリーによって作成されます。

    その後、工厂.生产鼠标()であればDellマウスが生産され、工厂.生产键盘()であればDellキーボードが生産されます。

    抽象ファクトリーパターンにおいて、ファクトリーを追加する必要があるとします。

    ASUS（華碩）ファクトリーを追加するとします。その場合、Dellファクトリーと同様にPCメーカーを継承するASUSファクトリーを追加する必要があります。

    その後、マウスクラスを継承するASUSマウスを作成し、キーボードクラスを継承するASUSキーボードを作成すればよいです。

    抽象ファクトリーパターンにおいて、製品を追加する必要があるとします。

    ヘッドセットという製品を追加するとします。まず、ヘッドセットという親クラスを追加し、さらにDellヘッドセットとHPヘッドセットという2つのサブクラスを追加する必要があります。

    その後、PCメーカーという親クラスにヘッドセットを生産するインターフェースを追加します。最後に、DellファクトリーとHPファクトリーという2つのクラスで、それぞれDellヘッドセットとHPヘッドセットを生産する機能を実装します。

    Python 方式：

    # Python原生默认不支持接口，默认多继承，所有的方法都必须不能实现
from abc import  abstractmethod,ABCMeta

# 创建一个接口Shape
class Shape(metaclass=ABCMeta):
    @abstractmethod
    def draw(self):
        pass
#创建Shape的实体类
class Rectangle(Shape):
    def draw(self):
        print("Inside Rectangel:draw() method.")
class Square(Shape):
    def draw(self):
        print("Inside Square:draw() method.")
class Circle(Shape):
    def draw(self):
        print("Inside Circle:draw() method.")

# 创建一个接口Color
class Color(metaclass=ABCMeta):
    @abstractmethod
    def fill(self):
        pass
# 创建Color的实体类
class Red(Color):
    def fill(self):
        print("Inside Red.fill() method.")
class Green(Color):
    def fill(self):
        print("Inside Green.fill() method.")
class Blue(Color):
    def fill(self):
        print("Inside Blue.fill() method.")

#创建抽象工厂
class AbstractFactory(metaclass=ABCMeta):
    @abstractmethod
    def getColor(self,color):
        pass
    @abstractmethod
    def getShape(self,shape):
        pass
#创建抽象工厂实例 ShapeFactory,ColorFactory
class ShapeFactory(AbstractFactory):
    def getShape(self,shapeType):
        if shapeType == None :
            return None
        elif shapeType.upper() == "CIRCLE":
            return Circle()
        elif shapeType.upper() == "RECTANGLE":
            return Rectangle()
        elif shapeType.upper() == "SQUARE":
            return Square()
        return None
    def getColor(self,colorType):
        pass
class ColorFactory(AbstractFactory):
    def getShape(self,shapeType):
        pass
    def getColor(self,colorType):
        if colorType == None:
            return None
        elif colorType.upper() == "RED":
            return Red()
        elif colorType.upper() == "GREEN":
            return Green()
        elif colorType.upper() == "BLUE":
            return Blue()
        return None

# 创建工厂创造器/生产器类
class FactoryProducer():
    @staticmethod
    # 这里不能写成 def getFactory(self,choiceType): 否则会报错
    # 因为是静态方法，被直接调用，所以不能带self参数
    # 如果不是静态方法，必须加self参数，且需要先实例化对象，再用实例化的对象调用方法
    def getFactory(choiceType):
        if choiceType.upper() == "SHAPE":
            return ShapeFactory()
        elif choiceType.upper() == "COLOR":
            return ColorFactory()
        return None

# 调用输出
if __name__ == '__main__':
    shapeFactory = FactoryProducer.getFactory('SHAPE')
    shape1 = shapeFactory.getShape("CIRCLE")
    shape1.draw()
    shape2 = shapeFactory.getShape("RECTANGLE")
    shape2.draw()
    shape3 = shapeFactory.getShape("SQUARE")
    shape3.draw()

    colorFactory = FactoryProducer.getFactory("COLOR")
    color1 = colorFactory.getColor("RED")
    color1.fill()
    color2 = colorFactory.getColor("Green")
    color2.fill()
    color3 = colorFactory.getColor("BLUE")
    color3.fill()

    本文で述べているものは実際にはファクトリメソッドパターンであり、ただすべての工場クラスの中から抽象工場クラスを抽象化しただけである。これは抽象ファクトリパターンではない。

    }

    抽象ファクトリパターンは、関連する一連の製品オブジェクトを作成し、製品間の一貫性を保つのに役立ちます。製品を作成する柔軟な方法を提供し、クライアントコードを具体的な製品の作成プロセスから分離（デカップリング）できます。同時に、抽象ファクトリパターンは拡張性も備えており、既存のクライアントコードを変更することなく、新しい具象工場や製品タイプを簡単に導入できます。

    以下は抽象ファクトリパターンの簡単な例です。2種類のボタンとチェックボックスがあり、それぞれ異なるスタイルを持つと仮定します：

    // 抽象产品 - 按钮
interface Button {
    void render();
}

// 具体产品 - MacOS 按钮
class MacOSButton implements Button {
    public void render() {
        System.out.println("Render MacOS button");
    }
}

// 具体产品 - Windows 按钮
class WindowsButton implements Button {
    public void render() {
        System.out.println("Render Windows button");
    }
}

// 抽象产品 - 复选框
interface Checkbox {
    void render();
}

// 具体产品 - MacOS 复选框
class MacOSCheckbox implements Checkbox {
    public void render() {
        System.out.println("Render MacOS checkbox");
    }
}

// 具体产品 - Windows 复选框
class WindowsCheckbox implements Checkbox {
    public void render() {
        System.out.println("Render Windows checkbox");
    }
}

// 抽象工厂
interface GUIFactory {
    Button createButton();
    Checkbox createCheckbox();
}

// 具体工厂 - MacOS 工厂
class MacOSFactory implements GUIFactory {
    public Button createButton() {
        return new MacOSButton();
    }

    public Checkbox createCheckbox() {
        return new MacOSCheckbox();
    }
}

// 具体工厂 - Windows 工厂
class WindowsFactory implements GUIFactory {
    public Button createButton() {
        return new WindowsButton();
    }

    public Checkbox createCheckbox() {
        return new WindowsCheckbox();
    }
}

// 客户端代码
public class Main {
    public static void main(String[] args) {
        GUIFactory factory = new MacOSFactory();

        Button button = factory.createButton();
        button.render();  // Output: Render MacOS button

        Checkbox checkbox = factory.createCheckbox();
        checkbox.render();  // Output: Render MacOS checkbox
    }
}

    上記の例では、抽象製品インターフェースである Button と Checkbox、および具象製品クラスである MacOSButton、WindowsButton、MacOSCheckbox、WindowsCheckbox を定義しました。次に、抽象ファクトリインターフェースである GUIFactory と、具象ファクトリクラスである MacOSFactory と WindowsFactory を定義しました。各具象ファクトリクラスは、対応するプラットフォームの製品オブジェクトの作成を担当します。

    抽象ファクトリインターフェース GUIFactory を使用することで、クライアントのニーズに応じて特定のプラットフォームのボタンやチェックボックスを作成でき、具象製品の実装クラスに直接依存する必要がありません。
