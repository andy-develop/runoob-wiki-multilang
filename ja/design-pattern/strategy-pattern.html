ストラテジーパターン

ストラテジーパターン（Strategy Pattern）では、クラスの動作またはそのアルゴリズムを実行時に変更できます。このタイプのデザインパターンは、振る舞いパターンに属します。

ストラテジーパターンでは、一連のアルゴリズムまたはストラテジーを定義し、各アルゴリズムを独立したクラスにカプセル化して、相互に置き換えられるようにします。ストラテジーパターンを使用することで、実行時に必要に応じて異なるアルゴリズムを選択でき、クライアントコードを変更する必要はありません。

ストラテジーパターンでは、さまざまなストラテジーを表すオブジェクトと、ストラテジーオブジェクトの変更に応じて動作が変わる context オブジェクトを作成します。ストラテジーオブジェクトが context オブジェクトの実行アルゴリズムを変更します。

紹介

意図

各アルゴリズムをカプセル化して、相互に交換して使用できるようにします。

主に解決する問題

  • 類似した複数のアルゴリズムが存在する場合に、条件文（if...else など）を使用することで生じる複雑さや保守の困難さという問題を解決します。

使用シーン

  • システム内に多くのクラスがあり、それらの違いが動作のみである場合。

実装方法

  • ストラテジーインターフェースを定義する：すべてのストラテジークラスがこの統一インターフェースを実装します。
  • 具象ストラテジークラスを作成する：各ストラテジークラスは、具体的なアルゴリズムまたは動作をカプセル化します。
  • コンテキストクラス：ストラテジーオブジェクトへの参照を保持し、その参照を介してストラテジーを呼び出します。

キーコード

  • ストラテジーインターフェース：すべてのストラテジークラスが実装しなければならないメソッドを規定します。
  • 具象ストラテジークラス：ストラテジーインターフェースを実装し、具体的なアルゴリズム実装を含みます。

応用例

  1. 錦囊の妙計：それぞれの錦囊が1つのストラテジーを表し、異なる計略を含みます。
  2. 旅行手段の選択：自転車、車など、各手段が置き換え可能なストラテジーです。
  3. Java AWT の LayoutManager：異なるレイアウトマネージャーが同じインターフェースを実装し、異なるレイアウトアルゴリズムを提供します。

利点

  1. アルゴリズムの自由な切り替え：実行時に必要に応じてアルゴリズムを切り替えることができます。
  2. 多重条件判断の回避：複雑な条件文を排除します。
  3. 拡張性が良い：アルゴリズムを追加するにはストラテジークラスを1つ追加するだけでよく、既存のコードを変更する必要はありません。

欠点

  1. ストラテジークラスの数が増加する：アルゴリズムが1つ増えるごとに、ストラテジークラスを1つ追加する必要があります。
  2. すべてのストラテジークラスを公開する必要がある：ストラテジークラスは、選択して使用できるように外部に公開する必要があります。

使用上のアドバイス

  • システムに複数のアルゴリズムや動作があり、それらが相互に置き換え可能な場合は、ストラテジーパターンを使用します。
  • システムがアルゴリズムを動的に選択する必要がある場合、ストラテジーパターンは適切な選択肢です。

注意事項

  • システム内のストラテジークラスの数が多すぎる場合は、クラスの肥大化の問題を解決するために、他のパターンや設計テクニックの使用を検討してください。

構造

ストラテジーパターンには、次の主要な役割が含まれます：

  • コンテキスト（Context）：ストラテジーオブジェクトへの参照を維持し、クライアントのリクエストを具体的なストラテジーオブジェクトに委譲して実行する役割を担います。コンテキストクラスは、依存性注入、シンプルファクトリーなどの方法で具体的なストラテジーオブジェクトを取得できます。
  • 抽象ストラテジー（Abstract Strategy）：ストラテジーオブジェクトの共通インターフェースまたは抽象クラスを定義し、具体的なストラテジークラスが実装しなければならないメソッドを規定します。
  • 具象ストラテジー（Concrete Strategy）：抽象ストラテジーが定義したインターフェースまたは抽象クラスを実装し、具体的なアルゴリズムの実装を含みます。

ストラテジーパターンは、アルゴリズムとアルゴリズムを使用するコードを疎結合にすることで、異なるアルゴリズムを動的に選択する方法を提供します。クライアントコードは具体的なアルゴリズムの詳細を知る必要はなく、コンテキストクラスを呼び出すことで選択されたストラテジーを使用します。

実装

活動を定義するものを作成しますStrategyインターフェースと、それを実装したStrategyインターフェースの具象ストラテジークラス。Contextは、何らかのストラテジーを使用するクラスです。

StrategyPatternDemo、私たちのデモクラスは使用しますContextとストラテジーオブジェクトを使用して、Context が設定または使用するストラテジーが変わったときの動作の変化をデモします。

ステップ 1

インターフェースを作成します。

Strategy.java

public interface Strategy { public int doOperation(int num1, int num2); }

ステップ 2

インターフェースを実装する具象クラスを作成します。

OperationAdd.java

public class OperationAdd implements Strategy{ @Override public int doOperation(int num1, int num2) { return num1 + num2; } }

OperationSubtract.java

public class OperationSubtract implements Strategy{ @Override public int doOperation(int num1, int num2) { return num1 - num2; } }

OperationMultiply.java

public class OperationMultiply implements Strategy{ @Override public int doOperation(int num1, int num2) { return num1 * num2; } }

ステップ 3

作成しますContextクラス。

Context.java

public class Context { private Strategy strategy; public Context(Strategy strategy){ this.strategy = strategy; } public int executeStrategy(int num1, int num2){ return strategy.doOperation(num1, num2); } }

ステップ 4

使用してContextストラテジーを変更したときのStrategy動作の変化を確認します。

StrategyPatternDemo.java

public class StrategyPatternDemo { public static void main(String[] args) { Context context = new Context(new OperationAdd()); System.out.println("10 + 5 = " + context.executeStrategy(10, 5)); context = new Context(new OperationSubtract()); System.out.println("10 - 5 = " + context.executeStrategy(10, 5)); context = new Context(new OperationMultiply()); System.out.println("10 * 5 = " + context.executeStrategy(10, 5)); } }

プログラムを実行し、結果を出力します：

10 + 5 = 15
10 - 5 = 5
10 * 5 = 50

    状態パターンとの比較

    状態パターンのクラス図はストラテジーパターンと類似しており、どちらもオブジェクトの動作を動的に変更できます。ただし、状態パターンは状態遷移によって Context が保持する State オブジェクトを変更するのに対し、ストラテジーパターンは Context 自体の決定によって保持する Strategy オブジェクトを変更します。いわゆる状態遷移とは、Context が実行中に何らかの条件が変化したことにより、State オブジェクトが変化することを指します。実行中であることが必須であることに注意してください。

    状態パターンは主に状態遷移の問題を解決するために使用され、状態が遷移すると Context オブジェクトはその動作を変更します。一方、ストラテジーパターンは主に相互に置き換え可能なアルゴリズム群をカプセル化するために使用され、必要に応じて Context が使用するアルゴリズムを動的に置き換えることができます。

    Python コード：

    # Strategy Pattern with Python Code
from abc import abstractmethod,ABCMeta
# 创建一个接口
class Strategy(metaclass=ABCMeta):
    @abstractmethod
    def doOperation(self,inNum1,inNum2):
        pass
# 创建实现接口的实体类
class OperationAdd(Strategy):
    def doOperation(self,inNum1,inMum2):
        return inNum1 + inMum2
class OperationSubtract(Strategy):
    def doOperation(self,inNum1,inNum2):
        return inNum1 - inNum2
class OperationMultiply(Strategy):
    def doOperation(self,inNum1,inNum2):
        return inNum1*inNum2
# 创建Context类
class Context():
    _strategy = None
    def __init__(self,inStrategy):
        self._strategy = inStrategy
    def executeStrategy(self,inNum1,inNum2):
        return self._strategy.doOperation(inNum1,inNum2)
# 调用输出
if __name__ == '__main__':
    aContext = Context(OperationAdd())
    print("10 + 5 = {0}".format(aContext.executeStrategy(10,5)))
    aContext = Context(OperationSubtract())
    print("10 - 5 = {0}".format(aContext.executeStrategy(10, 5)))
    aContext = Context(OperationMultiply())
    print("10 * 5 = {0}".format(aContext.executeStrategy(10, 5)))

    ストラテジーパターンを使用することで、ソートアルゴリズムの実装とアルゴリズムを使用するコードを疎結合にできます。これにより、新しいソートアルゴリズムを追加する必要がある場合は、新しい具象ストラテジークラスを実装し、クライアントコードで対応するストラテジーを設定するだけでよく、既存のソートコードを変更する必要はありません。

    ストラテジーパターンは、コードの柔軟性と保守性を向上させ、実行時に必要に応じて異なるアルゴリズムを切り替えることを可能にします。また、大量の条件文の使用を回避し、コードの可読性とテスト容易性を向上させることができます。

    以下は、ストラテジーパターンの簡単な例です。ユーザーの選択に応じて異なるソートストラテジーを選択するソートアルゴリズムのアプリケーションがあると仮定します：

    // 抽象策略 - 排序算法
interface SortingStrategy {
    void sort(int[] arr);
}

// 具体策略 - 快速排序
class QuickSort implements SortingStrategy {
    public void sort(int[] arr) {
        System.out.println("Using QuickSort");
        // 快速排序的具体实现
    }
}

// 具体策略 - 归并排序
class MergeSort implements SortingStrategy {
    public void sort(int[] arr) {
        System.out.println("Using MergeSort");
        // 归并排序的具体实现
    }
}

// 环境类
class SortingContext {
    private SortingStrategy strategy;

    public void setStrategy(SortingStrategy strategy) {
        this.strategy = strategy;
    }

    public void sortArray(int[] arr) {
        strategy.sort(arr);
    }
}

// 客户端代码
public class Main {
    public static void main(String[] args) {
        int[] arr = {5, 2, 8, 1, 9};

        SortingContext context = new SortingContext();

        context.setStrategy(new QuickSort());
        context.sortArray(arr);  // Output: Using QuickSort

        context.setStrategy(new MergeSort());
        context.sortArray(arr);  // Output: Using MergeSort
    }
}

    上記の例では、抽象ストラテジーインターフェース SortingStrategy、具象ストラテジークラス QuickSort と MergeSort、およびコンテキストクラス SortingContext を定義しました。異なるソートストラテジーを設定することで、実行時に異なるソートアルゴリズムを選択して使用できます。
