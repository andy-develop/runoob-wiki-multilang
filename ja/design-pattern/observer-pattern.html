Observer パターン

Observer パターンは振る舞いに関するデザインパターンの一種で、オブジェクト間の一対多の依存関係を定義します。あるオブジェクトの状態が変化すると、そのすべての依存者に通知が行われ、自動的に更新されます。

オブジェクト間に一対多の関係が存在する場合は、Observer パターンを使用します。例えば、あるオブジェクトが変更されると、それに依存するオブジェクトに自動的に通知されます。Observer パターンは振る舞いに関するパターンに属します。

紹介

意図

オブジェクト間に一対多の依存関係を定義し、あるオブジェクトの状態が変化したときに、それに依存するすべてのオブジェクトが通知を受け取り自動的に更新します。

主に解決する問題

  • Observer パターンが解決するのは、あるオブジェクトの状態が変化したときに、他の依存オブジェクトへ自動的に通知する方法の問題であり、同時にオブジェクト間の疎結合と高い協調性を維持します。

使用シーン

  • あるオブジェクトの状態変化に合わせて他のオブジェクトも同時に更新する必要がある場合。

実装方法

  • Observer インターフェースを定義する：更新メソッドを1つ含みます。
  • 具体的な Observer を作成する：Observer インターフェースを実装し、通知を受信したときの動作を定義します。
  • Subject インターフェースを定義する：Observer の追加、削除、通知を行うメソッドを含みます。
  • 具体的な Subject を作成する：Subject インターフェースを実装し、Observer のリストを管理して、状態が変化したときに通知します。

キーコード

  • Observer リスト：Subject 内に Observer のリストを保持します。

応用例

  • オークションシステム：競売人が Subject、入札者が Observer として、オークション価格が更新されたときに入札者全員に通知します。
  • 西遊記の物語：観音様が水をまくことを状態変化とし、老いた亀が Observer としてその変化を観察します。

利点

  • 抽象結合：Observer と Subject は抽象結合されています。
  • トリガーメカニズム：状態変化時のトリガーと通知の仕組みを確立します。

欠点

  • パフォーマンスの問題：Observer が多い場合、通知処理に時間がかかる可能性があります。
  • 循環依存：循環呼び出しやシステムクラッシュを引き起こす可能性があります。
  • 変化の詳細が不足：Observer は Subject がどのように変化したかを知らず、変化が発生したことだけを知ります。

使用上のアドバイス

  • オブジェクト間の結合度を下げる必要があり、オブジェクトの状態変化が他のオブジェクトの変化をトリガーする必要がある場合に使用します。
  • Java に組み込みの Observer パターン対応クラス、例えばjava.util.Observable和java.util.Observer。

注意事項

  • 循環参照の回避：Observer と Subject の間の依存関係に注意し、循環参照を避けます。
  • 非同期実行：非同期通知を使用して、単一障害点によってシステム全体が停止するのを防ぐことを検討してください。

構造

Observer パターンには以下のような中核となる役割が含まれます：

  • Subject（サブジェクト）：被観察者またはオブザーバブルとも呼ばれ、状態を持つオブジェクトであり、Observer のリストを保持します。Subject は Observer の追加、削除、通知のメソッドを提供します。
  • Observer（オブザーバー）：Subject からの通知を受け取るオブジェクトです。Observer は更新メソッドを実装する必要があり、Subject から通知を受け取ると、そのメソッドを呼び出して更新処理を行います。
  • Concrete Subject（具体的なサブジェクト）：Subject の具体的な実装クラスです。Observer のリストを保持し、状態が変化したときに Observer へ通知します。
  • Concrete Observer（具体的なオブザーバー）：Observer の具体的な実装クラスです。更新メソッドを実装し、Subject から通知を受け取ったときに実行する具体的な操作を定義します。

Observer パターンは Subject と Observer を分離することで、オブジェクト間の疎結合を実現します。Subject の状態が変化すると、それに依存するすべての Observer が通知を受け取り、対応する更新を行います。

実装

Observer パターンは Subject、Observer、Client の3つのクラスを使用します。Subject オブジェクトには、Observer を Client オブジェクトにバインドするメソッドと、Client オブジェクトから Observer をバインド解除するメソッドがあります。私たちは作成しますSubjectクラス、Observer抽象クラスと、その抽象クラスを拡張したObserver具体的なクラス。

    Observer パターンの定義：このパターンはオブジェクト間の一対多の依存関係を定義します、Subject オブジェクトが「一」で、Observer オブジェクトが「多」です。Subject オブジェクトの状態が変化したとき、その Subject オブジェクトに依存するすべての Observer オブジェクトが通知を受け取ります，そして自動的に更新します。

    定義を詳しく分析すると、Observer パターンを正確に理解するには主に3つの点に注意する必要があります：

    1. オブジェクト間の一対多の依存関係を定義すること；

    2. Subject オブジェクトの状態が変化したとき、その Subject オブジェクトに依存するすべての Observer オブジェクトが通知を受け取ること；

    3. Observer オブジェクトは通知を受け取った後、受動的ではなく自動的に更新すること；

    その他の点はすべて細部にすぎず、具体的なビジネス要件によって決まります。例えば：

    1. Subject の役割はクラスとして定義すべきでしょうか？例えば 組み込みの java.util.Observable；それとも、Java が多重継承をサポートしない問題を回避するためにインターフェースとして定義すべきでしょうか？例えば『Head First デザインパターン』で推奨されている方法です。

    2. いつ Subject を購読（つまり Observer を登録）すべきでしょうか？ Observer オブジェクトをインスタンス化するとき同時でしょうか？例えばスレッド主の例；それともクライアントが自主的に決めるべきでしょうか？例えばこのスレッドの最初の共有メモのように。

    3. 購読解除（または登録解除）機能を実装すべきでしょうか？

    4. Subject オブジェクトが Observer に通知するとき、メッセージを伴うでしょうか？言い換えれば、「プッシュ」型のメッセージでしょうか？スレッド主の例のように；それとも「プル」型のメッセージでしょうか？

    5. マルチスレッドをサポートするでしょうか？

    上記のコードを見て、Kotlin で実装してみました：

    /**
 * 观察者
 */
interface Observer {
    fun <T : Any?> update(msg: T)
}
 
/**
 * 观察者1,2,3
 */
class Ob1(private val id: Int = 0) : Observer {
    override fun <T> update(msg: T) {
        println("接收消息，观察者$id:$msg")
    }
}
//这里是kotlin的类委托
class Ob2 : Observer by Ob1(2)
class Ob3 : Observer by Ob1(3)
 
/**
 * 被观察者（订阅者）
 */
class Subject {
 
    //存放观察者
    private  var observers =  ArrayList<Observer>()
    //订阅观察者
    fun attach(ob: Observer) {
        observers.add(ob)
    }
    //设置数据
    fun <T : Any?> setMsg(msg: T) {
        this.notify(msg)
    }
    //更新数据
    private fun <T : Any?> notify(msg: T) {
        for (iOb in this.observers) {
            iOb.update(msg)
        }
    }
}
 
/**
 * Kotlin版 观察者模式
 * @author IWH
 * Des：kotlin1.3支持主函数省略参数
 */
fun main() {
 
    val sub = Subject().apply {
        attach(Ob1())
        attach(Ob2())
        attach(Ob3())
    }
    with(sub){
        setMsg(123)
        setMsg("hello world")
        setMsg('A')
        setMsg(null)
    }
}

    被観察オブジェクトと Observer オブジェクト

    一つの被観察オブジェクトが複数の観察者オブジェクトに関連付けられる

    したがって、被観察オブジェクトには観察者オブジェクトを格納するコンテナがある

    観察者オブジェクトにも被観察オブジェクトのメンバー変数がある

    被観察オブジェクトのあるプロパティが変更されたとき、関連するすべての観察者オブジェクトに応答させたい場合、プロパティを変更するメソッド内で通知メソッドを呼び出す。そのため、通知メソッドを宣言する必要がある。すなわち、すべての観察者を走査し、すべての観察者が持つメソッド（update更新メソッド）を呼び出す。

    本質は、ある属性を変更した後に、すべての要素のあるメソッドを走査することであり、実はポリモーフィズムでもある

    Python 方式：

    # Observer Pattern with Python Code
from abc import abstractmethod,ABCMeta

# 创建一个目标对象Subject，如果有多种不同的目标，可以抽象subject，用子对象实现
class Subject:
    # 建立一个私有集合，存放观察者对象
    _observers = []
    _state = ""
    def getState(self):
        return self._state
    def setState(self,inState):
        self._state = inState
        self.notifyAllObservers()
    # 追加观察者
    def attach(self, inObserver):
        self._observers.append(inObserver)
    # 通知观察者
    def notifyAllObservers(self):
        for aObser in self._observers :
            aObser.update()

# 创建观察者抽象类
class Observer(metaclass=ABCMeta):
    subject = Subject()
    @abstractmethod
    def update(self):
        pass
    def __init__(self):
        self.subject = Subject()

# 实现具体观察者
class BinaryObserver(Observer):

    public  class Subject {    
   private List observers = new ArrayList();   
      public void addObserver(Observer observer){       
      observers.add(observer);  
      }  
      protected void notifyObservers(){ 
      for (Observer o:observers){      
         o.update(this);    
      }    
   }
}
public abstract class Observer {    
   private Action action;    
   /**     * subject 观察谁 ,action 发生变化做什么     */    
   public  void observe(E subject,Action action){        
      subject.addObserver(this);        
      this.action=action;    
   }    
   public void update(Subject subject){        
      this.action.update(subject);    
   }    
   public interface Action{        
      void update(E subject);    
   }
}
public class Patient extends Subject {    
   private int age;    
   private String disease;    
   public Patient(int age, String disease) {        
      this.age = age;        
      this.disease = disease;    
   }    
   public void setAge(int age) {        
      this.age = age;        
      this.notifyObservers();    
   }    
   public void setDisease(String disease) {        
      this.disease = disease;        
      this.notifyObservers();    
   }    
   public int getAge() {        
      return age;    
   }    
   public String getDisease() {        
      return disease;    
   }
}

    観察者パターンは疎結合を実現でき、主題と観察者の関係をより柔軟にします。新しい観察者を簡単に追加でき、実行時に観察者を動的に追加・削除・変更することもできます。また、観察者パターンはオープン・クローズド原則に準拠しており、主題と観察者は互いに影響を与えずに独立して変更できます。

    以下は簡単な観察者パターンの例です。天気監視システムを想定し、主題は天気データ、観察者は異なる表示デバイスで、それらは天気データの変化をリアルタイムで表示します：

    // 主题 - 天气数据
interface WeatherData {
    void registerObserver(WeatherObserver observer);
    void removeObserver(WeatherObserver observer);
    void notifyObservers();
}

// 观察者 - 显示设备
interface WeatherObserver {
    void update(float temperature, float humidity, float pressure);
}

// 具体主题 - 天气数据
class WeatherStation implements WeatherData {
    private List<WeatherObserver> observers;
    private float temperature;
    private float humidity;
    private float pressure;

    public WeatherStation() {
        this.observers = new ArrayList<>();
    }

    public void registerObserver(WeatherObserver observer) {
        observers.add(observer);
    }

    public void removeObserver(WeatherObserver observer) {
        observers.remove(observer);
    }

    public void notifyObservers() {
        for (WeatherObserver observer : observers) {
            observer.update(temperature, humidity, pressure);
        }
    }

    public void setMeasurements(float temperature, float humidity, float pressure) {
        this.temperature = temperature;
        this.humidity = humidity;
        this.pressure = pressure;
        notifyObservers();
    }
}

// 具体观察者 - 显示设备
class DisplayDevice implements WeatherObserver {
    private String name;

    public DisplayDevice(String name) {
        this.name = name;
    }

    public void update(float temperature, float humidity, float pressure) {
        System.out.println(name + " - Temperature: " + temperature +
                " Humidity: " + humidity + " Pressure: " + pressure);
    }
}

// 客户端代码
public class Main {
    public static void main(String[] args) {
        WeatherStation weatherStation = new WeatherStation();

        DisplayDevice display1 = new DisplayDevice("Display 1");
        DisplayDevice display2 = new DisplayDevice("Display 2");

        weatherStation.registerObserver(display1);
        weatherStation.registerObserver(display2);

        weatherStation.setMeasurements(25.5f, 65.2f, 1013.2f);
        // Output:
        // Display 1 - Temperature: 25.5 Humidity: 65.2 Pressure: 1013.2
        // Display 2 - Temperature: 25.5 Humidity: 65.2 Pressure: 1013.2

        weatherStation.removeObserver(display2);

        weatherStation.setMeasurements(27.8f, 62.8f, 1010.5f);
        // Output:
        // Display 1 - Temperature: 27.8 Humidity: 62.8 Pressure: 1010.5
    }
}

    上記の例では、主題インターフェース WeatherData と観察者インターフェース WeatherObserver、具体的な主題クラス WeatherStation と具体的な観察者クラス DisplayDevice を定義しました。観察者の登録、状態の更新、観察者への通知というプロセスを通じて、主題と観察者の間の相互作用を実現しています。
