C# 継承

継承はオブジェクト指向プログラミングにおける最も重要な概念の一つです。継承により、あるクラスに基づいて別のクラスを定義できるため、アプリケーションの作成と保守が容易になります。同時に、コードの再利用と開発時間の短縮にも役立ちます。

クラスを作成するとき、プログラマーは新しいデータメンバーとメンバー関数を完全に書き直す必要はなく、既存のクラスのメンバーを継承した新しいクラスを設計するだけで済みます。この既存のクラスは基底クラスと呼ばれ、この新しいクラスは派生クラス。

と呼ばれます。継承の考え方は〜である（IS-A）関係を実現します。例えば、哺乳類は〜である（IS-A）動物であり、犬は〜である（IS-A）哺乳類です。したがって、犬は〜である（IS-A）動物です。

基底クラスと派生クラス

あるクラスは別のクラスから継承でき、基底クラス（親クラス）と派生クラス（子クラス）と呼ばれます。

C# はクラスの多重継承をサポートしませんが、インターフェースの多重継承はサポートしており、1つのクラスで複数のインターフェースを実装できます。

要約すると：1つのクラスは複数のインターフェースを継承できますが、継承できるクラスは1つだけです。

C# で派生クラスを作成する構文は次のとおりです：

<アクセス修飾子> class <基底クラス>
{
 ...
}
class <派生クラス> : <基底クラス>
{
 ...
}

派生クラスは、明示的に private（プライベート）とマークされていない限り、基底クラスのメンバー（フィールド、メソッド、プロパティなど）を継承します。

派生クラスはキーワード base を使用して基底クラスのコンストラクターとメソッドを呼び出すことができます。

例

class BaseClass
{
    public void SomeMethod()
    {
        // Method implementation
    }
}

class DerivedClass : BaseClass
{
    public void AnotherMethod()
    {
        // Accessing base class method
        base.SomeMethod();
       
        // Method implementation
    }
}

たとえば、基底クラス Shape があり、その派生クラスが Rectangle であると仮定します：

例

using System;
namespace InheritanceApplication
{
   class Shape
   {
      public void setWidth(int w)
      {
         width = w;
      }
      public void setHeight(int h)
      {
         height = h;
      }
      protected int width;
      protected int height;
   }

   // 派生クラス
   class Rectangle: Shape
   {
      public int getArea()
      {
         return (width * height);
      }
   }
   
   class RectangleTester
   {
      static void Main(string[] args)
      {
         Rectangle Rect = new Rectangle();

         Rect.setWidth(5);
         Rect.setHeight(7);

         // オブジェクトの面積を出力
         Console.WriteLine("総面積： {0}",  Rect.getArea());
         Console.ReadKey();
      }
   }
}

上記のコードがコンパイルおよび実行されると、次の結果が生成されます：

总面积： 35

基底クラスの初期化

派生クラスは基底クラスのメンバー変数とメンバーメソッドを継承します。したがって、親クラスのオブジェクトは子クラスのオブジェクトが作成される前に作成される必要があります。メンバー初期化リストで親クラスの初期化を行うことができます。

次のプログラムはこれを示しています：

例

using System;
namespace RectangleApplication
{
   class Rectangle
   {
      // メンバー変数
      protected double length;
      protected double width;
      public Rectangle(double l, double w)
      {
         length = l;
         width = w;
      }
      public double GetArea()
      {
         return length * width;
      }
      public void Display()
      {
         Console.WriteLine("長さ： {0}", length);
         Console.WriteLine("幅： {0}", width);
         Console.WriteLine("面積： {0}", GetArea());
      }
   }//end class Rectangle  
   class Tabletop : Rectangle
   {
      private double cost;
      public Tabletop(double l, double w) : base(l, w)
      { }
      public double GetCost()
      {
         double cost;
         cost = GetArea() * 70;
         return cost;
      }
      public void Display()
      {
         base.Display();
         Console.WriteLine("コスト： {0}", GetCost());
      }
   }
   class ExecuteRectangle
   {
      static void Main(string[] args)
      {
         Tabletop t = new Tabletop(4.5, 7.5);
         t.Display();
         Console.ReadLine();
      }
   }
}

上記のコードがコンパイルおよび実行されると、次の結果が生成されます：

长度： 4.5
宽度： 7.5
面积： 33.75
成本： 2362.5

インターフェースの継承（Interface Inheritance）

1つのインターフェースは1つ以上の他のインターフェースから継承でき、派生インターフェースは基底インターフェースのすべてのメンバーを継承します。

派生インターフェースは基底インターフェースのメンバーリストを拡張できますが、それらのアクセス修飾子を変更することはできません。

例

interface IBaseInterface
{
    void Method1();
}

interface IDerivedInterface : IBaseInterface
{
    void Method2();
}

インターフェースを継承するインスタンスは、次の方法で実装できます：

例

using System;

// 基底インターフェースを定義
interface IBaseInterface
{
    void Method1();
}

// 基底インターフェースから継承する派生インターフェースを定義
interface IDerivedInterface : IBaseInterface
{
    void Method2();
}

// 派生インターフェースを実装するクラス
class MyClass : IDerivedInterface
{
    public void Method1()
    {
        Console.WriteLine("Method1 implementation");
    }

    public void Method2()
    {
        Console.WriteLine("Method2 implementation");
    }
}

class Program
{
    static void Main(string[] args)
    {
        // MyClass クラスのインスタンスを作成
        MyClass obj = new MyClass();

        // 基底インターフェースから継承したメソッドを呼び出す
        obj.Method1();

        // 派生インターフェースで追加されたメソッドを呼び出す
        obj.Method2();
    }
}

上記の例では、MyClass クラスは IDerivedInterface インターフェースを実装しているため、IBaseInterface から継承した Method1() メソッドを含む、IDerivedInterface で定義されたすべてのメソッドを提供する必要があります。Main メソッドでは、MyClass のインスタンス obj を作成し、そのメソッドを呼び出しました。

出力結果は次のとおりです：

Method1 implementation
Method2 implementation

C# 多重継承

多重継承とは、1つのクラスが複数の親クラスから同時に動作と特性を継承できる機能のことです。単一継承（1つのクラスが1つの親クラスからのみ継承できること）とは対照的です。

C# は多重継承をサポートしていません。ただし、インターフェースを使用して多重継承を実現できます。次のプログラムはこれを示しています：

例

using System;
namespace InheritanceApplication
{
   class Shape
   {
      public void setWidth(int w)
      {
         width = w;
      }
      public void setHeight(int h)
      {
         height = h;
      }
      protected int width;
      protected int height;
   }

   // 基底クラス PaintCost
   public interface PaintCost
   {
      int getCost(int area);

   }
   // 派生クラス
   class Rectangle : Shape, PaintCost
   {
      public int getArea()
      {
         return (width * height);
      }
      public int getCost(int area)
      {
         return area * 70;
      }
   }
   class RectangleTester
   {
      static void Main(string[] args)
      {
         Rectangle Rect = new Rectangle();
         int area;
         Rect.setWidth(5);
         Rect.setHeight(7);
         area = Rect.getArea();
         // オブジェクトの面積を出力
         Console.WriteLine("総面積： {0}",  Rect.getArea());
         Console.WriteLine("塗装総コスト： ${0}" , Rect.getCost(area));
         Console.ReadKey();
      }
   }
}

上記のコードがコンパイルおよび実行されると、次の結果が生成されます：

总面积： 35
油漆总成本： $2450

    なぜオブジェクトを親クラスで宣言して、子クラスでインスタンス化できるのか

    このインスタンスは子クラスのものですが、宣言時に親クラスで宣言したため、通常の方法では子クラス自身のメンバーにアクセスできず、親クラスから継承したメンバーにのみアクセスできます。

    子クラスで override を使用して、親クラスで virtual として宣言された仮想メソッドをオーバーライドした場合、親クラスをインスタンス化してそのメソッドを呼び出すと、実行時には子クラスでオーバーライドされたメソッドが呼び出されます；

    子クラスで new を使用して、親クラスで virtual として宣言された仮想メソッドを隠蔽した場合、親クラスをインスタンス化してそのメソッドを呼び出すと、実行時には親クラスの仮想メソッドが呼び出されます；

    /// <summary>  
/// 父类  
/// </summary>  
public class ParentClass  
{  
   public virtual void ParVirMethod()  
   {  
       Console.WriteLine("父类的方法...");  
   }  
}  

/// <summary>  
/// 子类1  
/// </summary>  
public class ChildClass1 : ParentClass  
{  
   public override void ParVirMethod()  
   {  
       Console.WriteLine("子类1的方法...");  
   }  
}  

/// <summary>  
/// 子类2  
/// </summary>  
public class ChildClass2 : ParentClass  
{  
   public new void ParVirMethod()  
   {  
       Console.WriteLine("子类2的方法...");  
   }  

   public void Test()  
   {  
       Console.WriteLine("子类2的其他方法...");  
   }  
}

    実行呼び出し：

    ParentClass par = new ChildClass1();  
par.ParVirMethod(); //结果："子类1的方法"，调用子类的方法，实现了多态

par = new ChildClass2();  
par.ParVirMethod(); //结果："父类的方法"，调用父类的方法，没有实现多态

    その理由を深く追究すると、両者が異なるのは原理が異なるためです：override はオーバーライド（再書き込み）であり、基底クラスのメソッドを派生クラスで直接消去して書き直すため、呼び出されるメソッドは子クラスのメソッドです。一方、new は基底クラスのメソッドを派生クラスで隠すだけなので、呼び出されるのは依然として基底クラスのメソッドです。

    応用例

    このようなニーズがあります。例えば、People クラスに Run メソッドがあり、Man と Woman の2つのクラスはどちらも People クラスから継承しており、両方とも Run メソッドをオーバーライド（override）しています（男性と女性では走り方が異なります）。

    今、男性も女性もいるグループが一緒に走っています。

    これらをすべて People 配列（peoples とします）に入れることができます。

    そして：

    foreach(People p in peoples) // peoples中对象不同（即有男有女），用于实例化的子类就不同。
{
    p.Run(); // 故而，调用的方法也不同，实现了多态
}

    ポリモーフィズムにより、p.Run() を呼び出すとき、p オブジェクト自体が男性であれば自動的に男性の Run メソッドが呼び出され、女性であれば女性の Run メソッドが呼び出されます。

    依存性逆転の原則

    依存性逆転の原則（DIP、Dependency Inversion Principle）の表現は次のとおりです：

    1、高レベルモジュールは低レベルモジュールに依存すべきではなく、両方とも抽象に依存すべきです。

    2、抽象は詳細に依存すべきではなく、詳細は抽象に依存すべきです。

    ここでいう「依存」とは「使用する」という意味です。あるクラスのメソッドを呼び出す場合、そのクラスに依存しています。そのクラスのメソッドを直接呼び出す場合、詳細に依存しています。詳細とは具体的なクラスのことです。しかし、その親クラスやインターフェースのメソッドを呼び出す場合は、抽象に依存しています。つまり、DIP を簡単に言うと、具体的なサブクラスを直接使用するのではなく、その親クラスの参照を使用してサブクラスのメソッドを呼び出すことです。これにより、具体に依存せず抽象に依存することになります。

    実際に簡単に言うと、DIP の利点は結合を解除することです。DIP を使用すると、呼び出し側は呼び出されるコードが何であるかを知る必要がありません。呼び出し側が受け取るのは親クラスの参照であり、それが具体的にどのサブクラスのインスタンスを指しているのか、呼び出されるメソッドが具体的に何であるのかも知らないからです。そのため、呼び出されるコードが別のサブクラスに密かに置き換えられても、呼び出し側は何も変更する必要がありません。これが結合の解除です。

    基底クラスアクセスについて（非表示の基底クラスメンバーへのアクセス）

    Fields -- In the derived class

    派生クラスが非表示の継承メンバーに完全にアクセスできるようにしたい場合は、基底クラスアクセス式を使用して非表示の継承メンバーにアクセスできます。

    基底クラスアクセス式は、キーワード base の後にドットとメンバー名を続けて構成されます。例：

    Console.WriteLine("{0}",base.Field1);

    上記の1行のコードにある base.Fields1 は基底クラスアクセスに該当します。

    基底クラスアクセスの例：

    class SomeClass   //基类
{
    public string Field1 = "Fields -- In the base class";
}

class OtherClass : SomeClass  //继承类OtherClass，继承于SomeClass
{
    new public string Field1 = "Fields -- In the derived class";
    public void PrintField1()
    {
        Console.WriteLine(Field1);    //访问派生类
        Console.WriteLine(base.Field1)  //访问基类
    }
}


class Program
{
   static void Main()
   {
        OtherClass oc = new OtherClass();  //实例化
        oc.PrintFields1();                //执行oc的PrintFields1()方法
   }  
}

    上記のコードは基底クラスの非表示メンバーにアクセスする例であり、実行結果は次のように出力されます：

    Fields -- In the derived class
Fields -- In the base class

    継承についていくつかの点：

    • 1、継承の構文：class 子类类名 : class 父类类名{ //子类类体 }
    • 2、継承の特徴：子クラスは親クラスのすべてのフィールド、プロパティ、メソッドを持つ
    • 3、1つのクラスは複数の子クラスを持つことができるが、親クラスは1つだけである
    • 4、あるクラスは別のクラスを継承すると同時に、他のクラスに継承されることもできる
    • 5、C#では、すべてのクラスは直接的または間接的にObjectクラスを継承している

    //     当前对象的哈希代码。
    public virtual int GetHashCode();

    [SecuritySafeCritical]
    public Type GetType();

    public virtual string ToString();

    [SecuritySafeCritical]
    protected Object MemberwiseClone();
