QoderWake入門チュートリアル

QoderWakeを使うと、ローカル環境にデジタル従業員チーム（Wakers）を編成できます。各従業員は役職、名前、人物設定、専門分野を持ち、チャットや作業を依頼できるほか、スケジュールやイベントに応じて自動的に作業を開始することもできます。

製品の中核コンセプト：7x24時間稼働するデジタル従業員"Always awake, always working."

QoderWakeはデジタル従業員管理プラットフォームであり、ローカル展開とクラウド展開に対応しています。

  • 中核となる特徴：安全で制御可能、本番環境で使用可能、継続的に進化

  • 中核となる概念：従業員ロール（Role）→ デジタル従業員（Agent）→ チーム/組織（Agent Teams）という3層構造

インストール環境の説明

QoderWakeはローカル展開とクラウド展開に対応しています。

デジタル従業員が7x24時間継続して稼働できるよう、安定してオンラインでネットワーク環境が良好な常時稼働デバイスまたはクラウドデスクトップ環境への展開を推奨します。

Windows版は近日公開予定です。現在は一般公開されていないため、まずはmacOSまたはLinuxでご利用ください。

ローカル展開の要件

より良い7x24時間の運用体験を得るために、Mac miniなど長期安定稼働が可能なローカルデバイスへの展開を推奨します。

OSバージョン要件
macOS13.0以降
LinuxUbuntu 22.04 LTS以降を推奨。ローカルWebコンソールを使用するにはGUIデスクトップを有効にする必要があります

クラウド展開の要件

主要なクラウドデスクトップおよびクラウドホスト環境に対応しています。

ブラウザでのログインとローカルWeb管理を容易にするため、无影云电脑（Wuying Cloud Computer）のエンタープライズ版またはパーソナル版を推奨します。

前提ツール

製品にはソフトウェア開発向けのデジタル従業員ロールが複数プリセットされています。インストール前にGit環境を準備し、現在のアカウントで対象のコードリポジトリに正常にアクセスできることを確認してください：

  • インストール済みgit
  • リポジトリの認証設定が完了している
  • 正常に実行できるclone、pull、push操作

ローカルおよびクラウドの展開環境は、ユーザーログイン、モデル呼び出し、コードリポジトリへのアクセスなどのために、外部ネットワークへのアクセスをサポートしている必要があります。

企業ネットワーク、プロキシ、ファイアウォール環境では、必要なHTTPSアウトバウンドアクセスを事前に許可してください。

ステップ1：QoderWakeのインストール

お使いのOSに応じて対応するインストール方法を選択してください。

macOSへのインストール

方法1：インストールパッケージを直接ダウンロード

  • Appleシリコン（ARM）：ARM版をダウンロード
  • Intelチップ：Intel版をダウンロード

方法2：ターミナルからワンクリックインストール

# 一键安装命令，自动检测平台并完成安装
curl -fsSL https://qoder-ide.oss-ap-southeast-1.aliyuncs.com/qoderwake/install.sh | bash

スクリプトが以下を自動的に実行します：プラットフォームの検出、インストールパッケージのダウンロードと検証、メインプログラムとリソースファイルのインストール、コマンドエントリをPATHに追加、ブラウザでのログイン起動、ローカル常駐サービスの起動、Webコンソールのオープン。

インストール完了後のコマンドエントリは次のとおりです：

~/.qoderwake/bin/qoderwake

Linuxへのインストール

ターミナルを開き、macOSと同じワンクリックインストールコマンドを実行します。

インストールスクリプトは以下の手順を自動的に実行します：

  1. Linux CPUアーキテクチャの検出
  2. 対応プラットフォームのQoderWakeインストールパッケージをダウンロードして検証
  3. QoderWakeメインプログラムとリソースファイルをインストール
  4. コマンドエントリを作成してPATHへの追加を試行
  5. ブラウザを起動してログイン
  6. ログイン後にローカル常駐サービスを起動または再起動
  7. ローカルWebコンソールを自動的に開く

コマンドエントリ：

~/.qoderwake/bin/qoderwake

デフォルトのWebコンソールアドレス：

http://127.0.0.1:19820

ステップ2：コンソールを開く

ブラウザでアクセスhttp://127.0.0.1:19820/。これは、お使いのローカル環境におけるQoderWakeの管理コンソールです。

従業員の管理、タスクの割り当て、権限の設定はすべてここで行います。

インターフェースレイアウトの説明

エリア機能の説明
左サイドバー「マイWaker」リストを表示し、作成済みのすべての従業員と最近のアクティビティ時間を表示します
上部ボタン「Wakerを作成」をクリックして従業員をすばやく作成。右側では新しいタスクの作成に対応
メインエリア従業員を選択するとデフォルトで対話ページが開き、直接タスクを割り当てられます
右サイドバー作成済みのタスクと現在実行中のタスクの詳細を表示します

初回アクセス時にはアカウントへのログインが案内されるので、案内に従って完了してください。

ステップ3：デジタル従業員の作成

左側の「Wakerを作成」ボタンをクリックして作成フローに入ります。

作成フロー

  1. ロールテンプレートを選択：各ロールテンプレートには、人物設定、典型的なワークフロー、コアスキルセット、デフォルトの質問が含まれています。「詳細を見る」をクリックするとプレビューできます。
  2. またはカスタムロール：プリセットロールがどれも合わない場合は、「カスタムロール」を選択し、この従業員の人物設定、専門分野、仕事のスタイルを完全に定義し、スキル、コネクタ、権限を設定できます。
  3. 基本情報を入力：従業員の名前、アバター、紹介文を入力します。プリセットロールを選択すると内容が自動的に入力されるので、必要に応じて調整できます。
  4. 保存：保存をクリックすると、従業員が作成されます。新規従業員は初回作成後にガイドが表示され、最初にどのスキルを設定すべきか、どのチャネルを接続すべきかが推奨されます。スキップして後で設定することもできます。

カスタムロールの使用効果を高めるため、作成時になるべく完全なロール情報を提供することをお勧めします——ロールの位置づけ、中核的な責務、ワークフロー、必要なスキル、および MCP などのツール機能設定。

ステップ4：従業員と作業を開始する

新規従業員の作成が完了したら、以下から選択できます直接対話 或 自動タスクの作成の2つの方法で作業を割り当てます。

対話タスク

入力ボックスに要件を直接入力して送信すると、従業員が作業を開始します。

プロセス中に実行できる操作：

操作説明
追加質問、方向調整いつでも割り込めます。従業員は文脈に沿って続行します
ファイル/スクリーンショットを添付どのターンの発言でも添付ファイルを追加できます
中断従業員の方向がずれた場合は停止させられます
承認操作従業員がファイルを操作、コマンドを実行、ネットワークにアクセスする際は、停止して同意を求めます。「許可」または「拒否」をクリックしてください
従業員の質問に回答選択に直面すると彼はあなたに確認します。カード上で直接選択できます
AIモデルの切り替え対話中に賢さが足りないと感じたり、コストを抑えたい場合は、上部のドロップダウンでモデルを切り替えて続行できます
思考プロセスの確認従業員が決定を下す前の推論プロセスをリアルタイムで確認できます
成果物の確認右側のパネルに、従業員が生成したコードパッチ、新しく生成されたファイルなどがリアルタイムで表示されます
作業ディレクトリの選択対話の下部で、従業員が作業するローカルディレクトリを選択できます

自動タスク

「毎日1回実行する」「特定のリポジトリの変更を監視して自動応答する」などのシナリオに適しています。

移動先：Waker詳細 - トリガータスク - 新規作成、以下を設定できます：

設定項目説明
タスク名と説明従業員が読めば何をすべきか分かります
AIモデル使用するモデルを選択
作業ディレクトリローカルのどのディレクトリ、どのリポジトリ、またはどのプロジェクトワークスペースで実行するか
トリガー方式（最大5種）スケジュール（1回限り/定期/複雑な周期）、イベント駆動（GitHubリポジトリの変更を監視）、ネットワークコールバック（第三者システムが固定アドレス経由で直接コールバックしてトリガー）
最大回数/期限（オプション）タスクが無限に実行されないように制限します

保存後、従業員は設定したペースで自動的に作業します。

いつでも一時停止/有効化、テストの即時実行、実行履歴の確認ができます。

ステップ5：デジタル従業員の管理

従業員詳細ページに移動すると、従業員のすべての設定を表示および調整できます。

目次機能説明
ホームアバター、ステータス、入社日数、トリガータスク数、対話タスク数、作業ヒートマップを確認します
プロジェクト作業するコードリポジトリまたはローカルディレクトリをバインドします。1つのプロジェクトには複数のソース（複数のディレクトリまたはリポジトリ）を含めることができ、プロジェクトの記憶は従業員個人の記憶と分離されています
トリガータスク彼の自動化タスクの追加/削除/変更/一時停止
対話タスク過去の対話を閲覧し、会話を続行します
記憶彼のあなたとプロジェクトに対する長期的な認識を表示/編集します。ソース：対話プロセス中の自動蓄積、手動編集、システムによる定期的な整理と重複排除。ローカルに保存され、クラウドにアップロードされません
スキルQoder公式Skills Marketplaceからインストール、カスタムスキルのローカルアップロード、または既存スキルの有効/無効の切り替えができます。組み込みスキルはアンインストールできません
コネクタ外部ツール/サービスとの連携（GitHub、Jira、GitLab など）
権限ツール保護、ファイル保護、組み込みツールポリシー。高リスク操作では承認カードが表示されます

従業員設定の詳細

メモリ管理

各従業員には独自の長期記憶があり、あなたとプロジェクトに関する認識を蓄積するために使用されます。

記憶のソースは3つあります：

ソース説明
自動蓄積対話プロセス中に、従業員が記憶する価値があると判断した情報が自動的に書き込まれます
手動書き込み記憶ページに移動して直接編集できます
システム整理定期的にシステムが彼のために整理と重複排除を行います

移動先：従業員詳細 - 記憶、すべての記憶エントリを閲覧、検索、編集できます。

記憶はローカルに保存され、クラウドにアップロードされません。

スキル（Skill）

スキルは、従業員が対話やトリガータスクで呼び出せる専門能力パッケージです。

  • スキルマーケット：Qoder公式Skills Marketplaceからインストール
  • Skillのアップロード：ローカルから自分でインポート
  • 組み込みスキル：システム標準搭載で、アンインストール不可

移動先：従業員詳細 - スキル、インストール済みスキルの確認、マーケットの検索、カスタムスキルのアップロードができます。

コネクタ（Connector）

コネクタは従業員が外部ツール/サービスと連携するための橋渡しであり、手動でのコネクタ追加をサポートしています。

プロジェクト

プロジェクトは従業員のワークスペースです。

移動先：従業員詳細 - プロジェクト、ローカルディレクトリやgitリポジトリをバインドでき、1つのプロジェクトに複数のソース（複数のディレクトリ/リポジトリ）を含めることができます。プロジェクトには独立した記憶があり、従業員個人の記憶と分離されています。

権限管理

権限は従業員が何をできるか、何をできないかを制御します。

移動先：従業員詳細 - 権限、2つのカテゴリの保護に加えて、組み込みツールポリシーが含まれます。

ツール保護

組み込みのセキュリティルールに基づいてツールパラメータを検証し、高リスクルールに該当した場合はユーザーに承認を求めます。

ルール分類検出内容
コマンドインジェクションrm、mv などの危険な操作を検出
リソース乱用fork爆弾、システム再起動などを検出
コード実行curl | bash などのリモート実行を検出
ネットワーク乱用リバースシェル、ローカルループバックアクセスを検出
機密ファイルアクセスシステムの重要なファイルへのアクセスを検出
権限昇格sudo などの権限昇格操作を検出

ファイル保護

従業員のローカルファイルに対する読み書き権限を制御します。

組み込みツール

Wakerで利用可能な組み込みツールには、「許可」/「確認」/「無効」のポリシーを設定します。

従業員の操作がセキュリティルールに該当した場合、承認カードが表示され、許可するかどうかを決定できます。

シナリオ例：バグの自動修正

2つの駆動方式でバグの自動修正を実現できます。

方法A：手動で対話を開始

  1. コンソールを開き、バックエンドエンジニアロールのWakerを選択します
  2. ダイアログボックスに要件を入力し、エラー情報を添付します
  3. 従業員が問題を分析し、根本原因を特定し、修正案を提示します
  4. 確認後、修正を実行させ、PRを提出させます

インスタンス

# ダイアログボックスに以下のような内容を入力し、エラーログを添付します
# 「このエラーの根本原因を調査して、最小限の修正案を提示してください」

# 従業員は以下のような操作を実行します：
# 1. エラーログを分析し、問題のコードを特定します
# 2. 修正案を提示して確認を求めます
# 3. コード修正を実行します
# 4. コードリポジトリにPRを提出します

作業中にコマンドを実行したりファイルを変更したりする場合、彼は先にあなたの同意を求めます。

方法B：自動タスクを設定して処理

  1. 移動先：従業員詳細 - トリガータスク - 新規作成
  2. トリガー方式は「イベント」を選択し、GitHubリポジトリのIssueの変更を監視します
  3. タスクの説明には次のように記述します：「新しいバグIssueが入ってきたら、自動的に分析して修正PRを提示します。」
  4. 保存後、リポジトリに新しいバグIssueが発生するたびに、従業員が自動的に分析と修正を開始します

2つの方式にはそれぞれ適したシナリオがあります。方法Aは一時的・一回限りの問題調査に適しており、方法Bは継続的な自動化運用に適しており、人手による介入を減らせます。

インストール後にWebコンソールを開けない場合

ローカルサービスが正常に動作しているか確認し、チェックしてください。http://127.0.0.1:19820アクセスできるかどうか。

ポートが競合している場合は、他のプログラムが19820ポートを占有していないか確認してください。

従業員がタスク実行中に止まって動かない場合

従業員があなたの承認を必要としているか確認し、チャットウィンドウに処理待ちの承認カードがあるか確認してください。

カスタムロールの効果が良くない場合

作成時には完全なロール情報を提供することをお勧めします：ロールの位置付け、中核となる責務、ワークフロー、必要なスキル、およびMCPなどのツール能力設定を含め、情報が完全であればあるほど効果が良くなります。

問題をフィードバックする方法

問題が発生した場合や製品機能についてフィードバックしたい場合は、コンソール右下のフィードバックボタンをクリックして送信してください。チームができるだけ早く返信し解決します。
