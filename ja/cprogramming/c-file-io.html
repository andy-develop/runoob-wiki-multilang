C ファイル読み書き

前の章では、C言語が処理する標準入力と標準出力デバイスについて説明しました。この章では、Cプログラマーがテキストファイルやバイナリファイルを作成し、開き、閉じる方法を紹介します。

ファイルは、テキストファイルであれバイナリファイルであれ、一連のバイトを表しています。C言語は、上位レベルの関数へのアクセスを提供するだけでなく、ストレージデバイス上のファイルを処理するための低レベル（OS）呼び出しも提供します。この章では、ファイル管理の重要な呼び出しについて説明します。

ファイルを開く

使用することができますfopen( )関数を使用して新しいファイルを作成するか、既存のファイルを開きます。この呼び出しは、型FILEのオブジェクトを初期化します。型FILEには、フローを制御するために必要なすべての情報が含まれています。以下はこの関数呼び出しのプロトタイプです：

FILE *fopen( const char *filename, const char *mode );

ここで、filenameは、ファイルに名前を付けるための文字列です。アクセスモードmodeの値は次のいずれかになります：

モード説明
r既存のテキストファイルを開き、ファイルの読み取りを許可します。
wテキストファイルを開き、ファイルへの書き込みを許可します。ファイルが存在しない場合は、新しいファイルが作成されます。ここでは、プログラムはファイルの先頭から内容を書き込みます。ファイルが存在する場合は、ファイルの内容はクリアされます（つまり、ファイルの長さは0に切り詰められます）。
aテキストファイルを開き、追記モードでファイルに書き込みます。ファイルが存在しない場合は、新しいファイルが作成されます。ここでは、プログラムは既存のファイルの内容に追記します。
r+テキストファイルを開き、ファイルの読み書きを許可します。
w+テキストファイルを開き、ファイルの読み書きを許可します。ファイルが既に存在する場合は、ファイルは長さゼロに切り詰められます。ファイルが存在しない場合は、新しいファイルが作成されます。
a+テキストファイルを開き、ファイルの読み書きを許可します。ファイルが存在しない場合は、新しいファイルが作成されます。読み取りはファイルの先頭から始まり、書き込みは追記モードのみです。

バイナリファイルを処理する場合は、上記のアクセスモードの代わりに以下のアクセスモードを使用する必要があります：

"rb", "wb", "ab", "rb+", "r+b", "wb+", "w+b", "ab+", "a+b"

ファイルを閉じる

ファイルを閉じるには、fclose() 関数を使用してください。関数のプロトタイプは次のとおりです：

 int fclose( FILE *fp );

ファイルが正常に閉じられると、fclose( )関数はゼロを返します。ファイルを閉じる際にエラーが発生した場合は、関数はEOFを返します。この関数は実際には、バッファ内のデータをフラッシュし、ファイルを閉じ、そのファイルに使用されていたすべてのメモリを解放します。EOF はヘッダーファイルstdio.h内で定義されている定数です。

C標準ライブラリは、文字単位または固定長文字列としてファイルを読み書きするためのさまざまな関数を提供します。

ファイルへの書き込み

以下は、文字をストリームに書き込む最も簡単な関数です：

int fputc( int c, FILE *fp );

関数fputc()は、引数 c の文字値を fp が指す出力ストリームに書き込みます。書き込みが成功すると、書き込んだ文字を返します。エラーが発生した場合は、EOFを返します。以下の関数を使用して、null で終わる文字列をストリームに書き込むことができます：

int fputs( const char *s, FILE *fp );

関数fputs()は、文字列sを fp が指す出力ストリームに書き込みます。書き込みが成功すると、非負の値を返します。エラーが発生した場合は、EOFを返します。また、int fprintf(FILE *fp,const char *format, ...)関数を使用して文字列をファイルに書き込むこともできます。次の例を試してください：

注意：利用可能なtmpディレクトリがあることを確認してください。そのディレクトリが存在しない場合は、コンピュータ上で先にそのディレクトリを作成する必要があります。

/tmpは通常、Linuxシステム上の一時ディレクトリです。Windowsシステムで実行する場合は、ローカル環境に存在するディレクトリに変更する必要があります。例： C:\tmp、D:\tmpなど。

例

#include <stdio.h> int main() { FILE *fp = NULL; fp = fopen("/tmp/test.txt", "w+"); fprintf(fp, "This is testing for fprintf...\n"); fputs("This is testing for fputs...\n", fp); fclose(fp); }

上記のコードがコンパイルおよび実行されると、/tmp ディレクトリに新しいファイルtest.txtを作成し、2つの異なる関数を使用して2行を書き込みます。次に、このファイルを読み取ってみましょう。

ファイルの読み取り

以下は、ファイルから1文字を読み取る最も簡単な関数です：

int fgetc( FILE * fp );

fgetc()関数は、fp が指す入力ファイルから1文字を読み取ります。戻り値は読み取った文字です。エラーが発生した場合は、EOFを返します。以下の関数を使用すると、ストリームから文字列を読み取ることができます：

char *fgets( char *buf, int n, FILE *fp );

関数fgets()は、fp が指す入力ストリームから n - 1 文字を読み取ります。読み取った文字列をバッファbufにコピーし、最後にnull文字を追加して文字列を終端します。

この関数が最後の文字を読み取る前に改行文字 '\n' またはファイルの末尾 EOF に遭遇した場合は、読み取った文字のみを返します。改行文字も含みます。また、int fscanf(FILE *fp, const char *format, ...)関数を使用してファイルから文字列を読み取ることもできますが、最初の空白文字と改行文字に遭遇すると読み取りを停止します。

例

#include <stdio.h> int main() { FILE *fp = NULL; char buff[255]; fp = fopen("/tmp/test.txt", "r"); fscanf(fp, "%s", buff); printf("1: %s\n", buff ); fgets(buff, 255, (FILE*)fp); printf("2: %s\n", buff ); fgets(buff, 255, (FILE*)fp); printf("3: %s\n", buff ); fclose(fp); }

上記のコードがコンパイルおよび実行されると、前のセクションで作成したファイルを読み取り、次の結果を生成します：

1: This
2: is testing for fprintf...

3: This is testing for fputs...

まず、fscanf()メソッドはThisのみを読み取りました。その後ろに空白文字があったためです。次に、fgets()を呼び出して、行末までの残りの部分を読み取ります。最後に、fgets()を呼び出して、2行目を完全に読み取ります。

バイナリI/O関数

次の2つの関数は、バイナリ入力と出力に使用されます：

size_t fread(void *ptr, size_t size, size_t count, FILE *stream);
size_t fwrite(const void *ptr, size_t size, size_t count, FILE *stream);

fread 和 fwriteは、C言語標準ライブラリにおいてバイナリファイルのブロック読み書きに使用される中核的な関数であり、メモリ上のデータブロックを直接操作するため、テキスト形式変換のオーバーヘッドを回避します。大容量ファイルや構造化データの一括読み書きに特に適しています。

パラメータの説明

4つのパラメータは2つの関数で意味は同じですが、データの流れる方向が逆です：

パラメータ 型 説明 fread の動作 fwrite の動作
ptr void* / const void* メモリバッファへのポインタ 読み取り先アドレス（メモリに書き込む） データソースアドレス（メモリから読み取る）
size size_t 各データブロックのバイト数 読み取りごとのブロックサイズ 書き込みごとのブロックサイズ
count size_t 読み書きするデータブロックの数 読み取りを期待するブロック数 書き込みを期待するブロック数
stream FILE* 開かれているファイルポインタ "rb" で開く必要がある "wb" で開く必要がある

実際に操作されるバイト数はsize × countであり、戻り値は正常に読み書きされたブロック数であってバイト数ではありません。戻り値が count より小さい場合、ファイルの終わり（EOF）または読み書きエラーが原因である可能性があるため、それぞれを確認する必要があります。

バイナリモードとテキストモード

fread/fwrite を使用する場合は、ファイルをバイナリモードで開く必要があります。そうしないと、データが破損する可能性があります。

なぜバイナリモードを使用しなければならないのか

テキストモードでは、Windowsプラットフォームで改行文字を自動的に\n変換して\r\n、これによりバイナリデータの完全性が損なわれる可能性があります。

Linux/macOS ではテキストモードとバイナリモードの動作は同じですが、クロスプラットフォームのコードでは明示的に"b"フラグを使用して移植性を確保する必要があります。

例

// 正しい書き方：バイナリモードを明示的に指定
FILE *fp_read  = fopen("data.bin", "rb");  // バイナリ読み取り
FILE *fp_write = fopen("data.bin", "wb");  // バイナリ書き込み

// 誤った書き方：テキストモード（Windowsではデータが改変される可能性があります）
FILE *fp_bad = fopen("data.bin", "r");     // "b" フラグが欠けている

テキスト関数との比較

どの関数を選択するかは、データ型と要件のシナリオによって異なります：

特性 fread / fwrite fprintf / fscanf
データ処理方法 メモリ上のバイナリデータをそのまま読み書き 形式に従って変換（数値 ↔ 文字列）
適用シナリオ 構造体、配列、画像、音声など 設定ファイル、ログ、レポートなど人間が読めるテキスト
パフォーマンス 快、変換オーバーヘッドなし 慢、フォーマット文字列の解析が必要
精度 精度の損失なし 浮動小数点数は精度を失う可能性がある
人間が読める いいえ（バイナリ形式） はい（プレーンテキスト形式）

構造体データの読み書き

これは fread/fwrite の最も一般的な応用例です。構造体全体を1つのデータブロックとして一度に読み書きできます。

例

#include <stdio.h>
#include <stdlib.h>

// 学生構造体を定義
// 注意：必ず固定長配列を使用すること。char *name ポインタメンバーは使えない
typedef struct {
    int id;             // 学籍番号
    char name[50];      // 氏名（固定配列。ポインタは不可）
    float score;        // 成績
} Student;

int main() {
    // ===== 構造体をファイルに書き込む =====
    Student s = {101, "Alice", 95.5f};  // データを初期化
    FILE *fp = fopen("student.bin", "wb");
    if (fp == NULL) {
        perror("ファイルを開けませんでした");
        return 1;
    }
    // 構造体全体を1つのデータブロックとして書き込む
    size_t written = fwrite(&s, sizeof(Student), 1, fp);
    if (written != 1) {
        printf("書き込みに失敗しました\n");
    }
    fclose(fp);

    // ===== ファイルから構造体を読み取る =====
    fp = fopen("student.bin", "rb");
    if (fp == NULL) {
        perror("ファイルを開けませんでした");
        return 1;
    }
    Student loaded;  // 未初期化。fread が値を埋める
    size_t read_count = fread(&loaded, sizeof(Student), 1, fp);
    if (read_count != 1) {
        printf("読み取りに失敗したか、ファイルの終端です\n");
        fclose(fp);
        return 1;
    }
    printf("学籍番号: %d, 氏名: %s, 成績: %.1f\n", loaded.id, loaded.name, loaded.score);
    fclose(fp);
    return 0;
}
学号: 101, 姓名: Alice, 成绩: 95.5

構造体にはポインタメンバーを含めることはできません（例：char *name）。なぜなら fwrite はポインタのアドレス値だけを保存し、ポインタが指す文字列の内容は保存しないからです。読み戻した時点でそのアドレスは無効になっており、ダングリングポインタが発生します。正しい方法は固定長配列を使うことです。たとえばchar name[50]。

配列データの読み書き

配列はメモリ上に連続して格納されるため、配列全体を一度に読み書きできます。

例

#include <stdio.h>

int main() {
    // 元のデータ配列
    int data[] = {1, 2, 3, 4, 5};
    int count = 5;  // 配列の要素数

    // ===== 配列をファイルに書き込む =====
    FILE *fp = fopen("array.bin", "wb");
    if (fp == NULL) {
        perror("ファイルを開けませんでした");
        return 1;
    }
    // data は &data
    fwrite(data, sizeof(int), count, fp);
    fclose(fp);
    printf("%d 個の整数を array.bin に書き込みました\n", count);

    // ===== ファイルから配列を読み取る =====
    int buffer[5] = {0};  // 0 に初期化し、読み取り結果を確認しやすくする
    fp = fopen("array.bin", "rb");
    if (fp == NULL) {
        perror("ファイルを開けませんでした");
        return 1;
    }
    size_t read_count = fread(buffer, sizeof(int), count, fp);
    if (read_count < count) {
        printf("読み取りが不完全：期待 %d 個、実際 %zu 個\n", count, read_count);
    }
    fclose(fp);

    // 読み取り結果を表示
    printf("読み取ったデータ: ");
    for (int i = 0; i < count; i++) {
        printf("%d ", buffer[i]);
    }
    printf("\n");
    return 0;
}
已写入 5 个整数到 array.bin
读取到的数据: 1 2 3 4 5

大容量ファイルの一括読み書き

大容量ファイルの場合は、ループで分割して読み書きし、全内容を一度にメモリへ読み込まないようにします。

例

#include <stdio.h>
#include <stdlib.h>

#define BUFFER_SIZE 1024 // 毎回 1KB を読み書き。必要に応じて調整可能

// 効率的なファイル複製関数
// 戻り値：0 は成功、-1 は失敗を表す
int copy_file(const char *src, const char *dst) {
    char buffer[BUFFER_SIZE];  // 中継バッファ
    FILE *in = fopen(src, "rb");
    FILE *out = fopen(dst, "wb");

    // 2つのファイルが両方とも正常に開かれたか確認
    if (!in) {
        perror("元ファイルを開けませんでした");
        return -1;
    }
    if (!out) {
        perror("コピー先ファイルを開けませんでした");
        fclose(in);   // 開かれている元ファイルを閉じる
        return -1;
    }

    // ループで読み取り、毎回最大 BUFFER_SIZE バイト
    size_t n;
    while ((n = fread(buffer, 1, BUFFER_SIZE, in)) > 0) {
        // fwrite は size=1, count=n とし、実際に読み取ったバイト数だけ書き込む
        if (fwrite(buffer, 1, n, out) != n) {
            perror("書き込みに失敗しました");
            fclose(in);
            fclose(out);
            return -1;
        }
    }

    // 読み取りがエラーで終了したか（通常の EOF ではなく）を確認
    if (ferror(in)) {
        perror("読み取りエラー");
        fclose(in);
        fclose(out);
        return -1;
    }

    fclose(in);
    fclose(out);
    printf("ファイルの複製に成功: %s -> %s\n", src, dst);
    return 0;
}

int main() {
    // 使用例：runoob テストファイルを複製する
    copy_file("runoob_input.bin", "runoob_output.bin");
    return 0;
}
文件复制成功: runoob_input.bin -> runoob_output.bin

このパターンの要点はfread実際に読み取ったバイト数を返し、次にfwrite実際に読み取ったバイト数だけを書き込むことで、末尾の余分なデータの書き込みを防ぎます。

重要な注意点

戻り値の確認

fread/fwrite を呼び出した後は必ず戻り値を確認し、正常終了と異常を区別する必要があります。

例

#include <stdio.h>

int main() {
    int buffer[100];
    FILE *fp = fopen("data.bin", "rb");
    if (fp == NULL) {
        perror("ファイルを開けませんでした");
        return 1;
    }

    // 100 個の整数の読み取りを試みる
    size_t count = fread(buffer, sizeof(int), 100, fp);

    if (count < 100) {
        // EOF とエラーを区別する
        if (feof(fp)) {
            printf("ファイルの末尾に到達しました。実際に %zu 個の要素を読み取りました\n", count);
            // この時点で読み取ったデータを引き続き処理できる
        } else if (ferror(fp)) {
            perror("読み取り中にエラーが発生しました");
            fclose(fp);
            return 1;
        }
    } else {
        printf("%zu 個の要素をすべて読み取ることに成功しました\n", count);
    }

    fclose(fp);
    return 0;
}
已到达文件末尾，实际读取 47 个元素

構造体の読み書きの落とし穴

構造体のメモリ上のレイアウトはコンパイラのアライメント戦略の影響を受けるため、クロスプラットフォームの互換性問題が発生する可能性があります。

メモリアライメントの不一致

異なるコンパイラや異なるコンパイルオプションでは、同じ構造体でも異なるメモリレイアウトになる可能性があります。

例

#include <stdio.h>

// 問題例：デフォルトアライメントでは、char の後に3バイトのパディングが入る
typedef struct {
    char c;      // 1バイトを占めるが、後ろにパディングが入る
    int i;       // 4バイトアライメントなので、実際にはオフセット4から始まる
} Mixed;

// 解決方法1：pragma pack を使って強制的にパックアラインにする
#pragma pack(push, 1) // 現在のアライメント設定を保存し、1バイトアライメントに設定
typedef struct {
    char c;      // オフセット0、1バイト
    int i;       // オフセット1、4バイト（パディングなし）
} PackedMixed;
#pragma pack(pop) // 以前のアライメント設定を復元

// 解決方法2：メンバーを手動で1つずつシリアライズする（最も安全な方法）
// この方法はコンパイラのアライメントに依存せず、クロスプラットフォーム互換性が最も高い

int main() {
    // 2つの構造体のサイズの違いを表示する
    printf("デフォルトアライメントの Mixed サイズ: %zu バイト\n", sizeof(Mixed));       // 通常は8
    printf("パックアライメントの PackedMixed サイズ: %zu バイト\n", sizeof(PackedMixed)); // 5になる
    return 0;
}
默认对齐 Mixed 大小: 8 字节
紧凑对齐 PackedMixed 大小: 5 字节

推奨される方法：クロスプラットフォームや長期保存の場合は、構造体をファイルに直接書き込むのではなく、手動シリアライズ（メンバーごとの読み書き）を優先します。これにより、アライメントとバイトオーダーの問題を完全に回避できます。

ポインタメンバーの禁止

これは初心者が最も犯しやすいエラーの1つです。

例

#include <stdio.h>
#include <string.h>
#include <stdlib.h>

// 誤った例：構造体にポインタメンバーが含まれている
typedef struct {
    int id;
    char *name;   // 危険！fwrite はポインタの値（アドレス）だけを保存し、文字列の内容は保存しない
} BadStudent;

// 正しい例：固定配列を使用する
typedef struct {
    int id;
    char name[100];  // 実際のデータは構造体内に保存されるため、安全に読み書きできる
} GoodStudent;

int main() {
    // 誤った方法の結果をデモンストレーションする
    BadStudent bs;
    bs.id = 1;
    bs.name = malloc(50);
    strcpy(bs.name, "RUNOOB");

    // BadStudent を書き込む：このとき name ポインタのアドレスが書き込まれ、文字列の内容は書き込まれない
    FILE *fp = fopen("bad.bin", "wb");
    fwrite(&bs, sizeof(BadStudent), 1, fp);
    fclose(fp);

    // BadStudent を読み戻す：name ポインタの値は以前 malloc が別のプロセスで確保したアドレスであり、完全に無効
    BadStudent loaded;
    fp = fopen("bad.bin", "rb");
    fread(&loaded, sizeof(BadStudent), 1, fp);
    fclose(fp);
    // loaded.name はダングリングポインタであり、アクセスすると未定義動作を引き起こす！

    free(bs.name);
    printf("デモは完了しましたが、読み出した name ポインタは無効です\n");
    return 0;
}
演示完成，但 load 出来的 name 指针是无效的

バッファのフラッシュ

C 標準ライブラリの I/O はバッファリングされます。重要なデータは永続化を保証するために明示的にフラッシュする必要があります。

例

#include <stdio.h>

int main() {
    FILE *fp = fopen("critical.bin", "wb");
    if (fp == NULL) {
        perror("ファイルを開けませんでした");
        return 1;
    }

    int data[] = {1, 2, 3, 4, 5};
    fwrite(data, sizeof(int), 5, fp);

    // 方法1：バッファを明示的にフラッシュし、データをすぐにディスクへ書き込む
    fflush(fp);
    printf("fflush を使用してディスクに強制フラッシュしました\n");

    // 方法2：ファイルを閉じるときに自動でフラッシュする（推奨）
    // fclose は内部で自動的に fflush を呼び出す
    fclose(fp);
    printf("fclose もバッファを自動的にフラッシュします\n");

    return 0;
}
使用 fflush 强制刷新到磁盘
fclose 也会自动刷新缓冲区

ファイルポインタの位置決め

fseek と ftell を組み合わせると、ファイルへのランダムアクセスを実現し、必要に応じて指定位置のデータを読み取ることができます。

例

#include <stdio.h>

typedef struct {
    int id;
    char name[50];
    float score;
} Student;

int main() {
    FILE *fp = fopen("students.bin", "rb");
    if (fp == NULL) {
        perror("ファイルを開けませんでした");
        return 1;
    }

    // ファイルの末尾に移動して、ファイルサイズを取得する
    fseek(fp, 0, SEEK_END);
    long file_size = ftell(fp);
    printf("ファイルサイズ: %ld バイト\n", file_size);

    // ファイル内に構造体レコードがいくつあるかを計算する
    long record_count = file_size / sizeof(Student);
    printf("%ld 件の学生レコードが含まれています\n", record_count);

    // 6番目の構造体に移動（インデックスは0始まり、オフセット = 5 * sizeof(Student)）
    fseek(fp, sizeof(Student) * 5, SEEK_SET);
    Student s;
    fread(&s, sizeof(Student), 1, fp);
    printf("6番目のレコード: id=%d, name=%s\n", s.id, s.name);

    fclose(fp);
    return 0;
}
文件大小: 6000 字节
包含 100 条学生记录
第 6 条记录: id=106, name=RUNOOB

    fseek はファイルポインタを指定位置に移動して読み取り、または挿入書き込みができます:

    int fseek(FILE *stream, long offset, int whence);

    fseek は現在の読み書き位置を offset に設定します。whence は SEEK_SET、SEEK_CUR、SEEK_END のいずれかで、ファイル先頭、現在位置、ファイル末尾のどれから offset を計算するかを決定します。

    #include <stdio.h>

    新版の VS コンパイル環境では fopen は安全ではないと警告されるため、代わりに fopen_s の使用が推奨されます。

    fopen_s と fopen の違いは次のとおりです：

    errno_t fopen_s( FILE** pFile, const char *filename, const char *mode );

FILE *fopen(const char *filename, const char *mode)

    fopen_s には3つのパラメータがあり、最初のパラメータはファイルストリームポインタのアドレスを格納するための2級ポインタです。その他は fopen と同じです。

    つまり、fopen を使用する場合は次のように書く必要があります：

    FILE* fp=NULL;
fp=fopen("\\123.txt","w+");

    一方、fopen_s を使用する場合は：

    FILE* fp=NULL;
fopen_s(&fp,"\\123.txt","w+");

    これで十分です。

    fopen() 関数について補足説明します：

    FILE *fopen( const char * filename, const char * mode );
    • この関数は実行に失敗する可能性があり、戻り値は NULL です。安全のため、戻り値の妥当性を必ず判断する必要があります。
    • この関数には複数のモードがあります。r+ と w+ は一見同じように見えますが、どちらも読み書き用でありながら、実際にはいくつかの違いがあります。
    • 1. r+ モードはファイルが見つからない場合、自動的に作成しませんが、w+ は作成します。
    • 2. r+ モードでファイルを開いた後、元のデータは消去されません。直接書き込むと、開始位置から上書きされるだけです。一方、w+ はゼロクリアしてから読み書きを開始します。
    • モードの正当性について：大文字は使用できず、小文字のみです。rb+ と r+b は両方とも有効ですが、br+ や +rb などは無効です。w と a も同様の扱いです。
    • w モードでのファイル自動作成には条件があります。対応するパス（つまりファイルが置かれるフォルダ）が存在し、かつファイルが存在しない場合のみ作成されます。そうでなければ作成されず、NULL が返されます。
