C ポインタ

C 言語のポインタを学ぶのは簡単で、しかも面白いです。ポインタを使用することで、いくつかの C プログラミングタスクの実行を簡素化できます。また、動的メモリ割り当てなど、ポインタなしでは実行できないタスクもあります。したがって、優れた C プログラマーになるためには、ポインタを学ぶことが非常に必要です。

ご存知のように、すべての変数にはメモリ位置があり、それぞれのメモリ位置は、使用可能な&演算子でアクセスされるアドレスを定義しており、メモリ内のアドレスを表します。

次の例を見てください。定義した変数のアドレスを出力します。

例

#include <stdio.h> int main () { int var_runoob = 10; int *p; // ポインタ変数の定義 p = &var_runoob; printf("var_runoob 変数のアドレス： %p\n", p); return 0; }

上記のコードがコンパイルおよび実行されると、次の結果が生成されます。

var_runoob 变量的地址： 0x7ffeeaae08d8

上記の例を通じて、メモリアドレスとは何か、そしてそれにアクセスする方法を理解しました。次に、ポインタとは何かを見てみましょう。

ポインタとは？

ポインタとはメモリアドレスのことであり、ポインタ変数はメモリアドレスを格納するための変数です。他の変数や定数と同様に、ポインタを使用して他の変数のアドレスを格納する前に、ポインタを宣言する必要があります。ポインタ変数の宣言の一般的な形式は次のとおりです。

type *var_name;

ここで、typeはポインタの基本型であり、有効な C データ型でなければなりません。var_nameはポインタ変数の名前です。ポインタを宣言するために使用するアスタリスク*は乗算で使用するアスタリスクと同じです。ただし、このステートメントでは、アスタリスクは変数がポインタであることを指定するために使用されます。以下は有効なポインタ宣言です。

int *ip; /*整数型のポインタ*/ double *dp; /*double 型のポインタ*/ float *fp; /*浮動小数点型のポインタ*/ char *ch; /*文字型のポインタ*/

すべての実際のデータ型（整数型、浮動小数点型、文字型、その他のデータ型）に対応するポインタの値の型は同じで、メモリアドレスを表す長い 16 進数です。

異なるデータ型のポインタ間の唯一の違いは、ポインタが指す変数または定数のデータ型が異なることです。

ポインタの使い方？

ポインタを使用する際には、以下の操作が頻繁に行われます。ポインタ変数の定義、変数のアドレスのポインタへの代入、ポインタ変数内の使用可能なアドレスの値へのアクセス。これらは単項演算子*を使用して、オペランドで指定されたアドレスにある変数の値を返します。次の例はこれらの操作に関するものです。

例

#include <stdio.h> int main () { int var = 20; /*実際の変数の宣言*/ int *ip; /*ポインタ変数の宣言*/ ip = &var; /*ポインタ変数に var のアドレスを格納する*/ printf("var 変数のアドレス: %p\n", &var ); /*ポインタ変数に格納されたアドレス*/ printf("ip 変数に格納されたアドレス: %p\n", ip ); /*ポインタを使用して値にアクセスする*/ printf("*ip 変数の値: %d\n", *ip ); return 0; }

上記のコードがコンパイルおよび実行されると、次の結果が生成されます。

var 变量的地址: 0x7ffeeef168d8
ip 变量存储的地址: 0x7ffeeef168d8
*ip 变量的值: 20

C における NULL ポインタ

変数を宣言するとき、割り当てる正確なアドレスがない場合は、ポインタ変数に NULL 値を代入するのは良いプログラミング習慣です。NULL 値を代入されたポインタは空NULL ポインタと呼ばれます。

NULL ポインタは、標準ライブラリで定義されている値がゼロの定数です。次のプログラムを見てください。

例

#include <stdio.h> int main () { int *ptr = NULL; printf("ptr のアドレスは %p\n", ptr ); return 0; }

上記のコードがコンパイルおよび実行されると、次の結果が生成されます。

ptr 的地址是 0x0

ほとんどのオペレーティングシステムでは、プログラムはアドレス 0 のメモリにアクセスできません。そのメモリはオペレーティングシステムによって予約されているためです。しかし、メモリアドレス 0 には特別な意味があり、そのポインタがアクセス可能なメモリ位置を指していないことを示します。慣例として、ポインタが null 値（ゼロ値）を含む場合、そのポインタは何も指していないと見なされます。

空のポインタを確認する必要がある場合は、次のように if 文を使用できます。

if(ptr) /*p が空でない場合、実行する*/ if(!ptr) /*p が空の場合、実行する*/

C ポインタの詳細

C にはポインタに関連する多くの概念があります。これらの概念はどれも簡単ですが、どれも重要です。以下に、C プログラマーが理解しておく必要があるポインタに関連する重要な概念をリストします。

概念説明
ポインタの算術演算ポインタに対しては、++、--、+、- の 4 つの算術演算を実行できます。
ポインタの配列ポインタを格納するための配列を定義できます。
ポインタへのポインタC では、ポインタへのポインタが許可されています。
関数へのポインタの受け渡し参照またはアドレスによって引数を渡すことで、渡された引数を呼び出し元の関数内で変更できます。
関数からポインタを返すC では、関数がローカル変数、静的変数、および動的に割り当てられたメモリへのポインタを返すことができます。

    ポインタは変数であり、その値は別の変数のアドレス、つまりメモリ位置の直接アドレスです。他の変数や定数と同様に、ポインタを使用して他の変数のアドレスを格納する前に、ポインタを宣言する必要があります。

    ポインタを理解するには、まずコンピュータのメモリを理解する必要があります。コンピュータのメモリは、順番に番号が付けられたメモリセルに分割されています。各変数はメモリセルに格納されており、これをアドレスと呼びます。

    #include <stdio.h>

int main ()
{
    int var = 20;   /* 实际变量的声明 此时的 VAR 这个变量是存在某个地址的，地址对应某个内存单元，该单元中存储了数据20 */
    int *ip;         /* 指针变量的声明 定义了一个指针 即一个内存单元的地址变量 */

    ip = &var;      /* 在指针变量中存储 var 的地址 就是将地址值赋值给指针这个变量*/

    /* 在指针变量中存储的地址 利用&符号直接输出了var所存储的数据的内存单元的地址*/
    printf("Address of var variable: %p\n", &var );
    
    /* 在指针变量中存储的地址 ip代表的是这个赋值到的地址的值 所以输出的是地址值 */
    printf("Address stored in ip variable: %p\n", ip );
    
    /* 使用指针访问值 *ip代表的是定义到这个内存单元之后，内存单元中所存储的数据的值也就是将20赋值给var中20这个值 */
    printf("Value of *ip variable: %d\n", *ip );

    return 0;
}

    #include <stdio.h>

{
    int *p = 0;
    int a ;
    p = &a;
    printf ("输入一个数字\n");

    printf("%d\n",*p);
}

    例では変数 a とポインタ変数 p を定義しています。p = &aポインタ変数が変数 a を指していることを示します。p に格納されているアドレスは a のアドレス &a であり、*p が指すのは p に格納されているアドレス a のメモリセル内の値です。

    ポインタのいくつかの複雑な説明：

    • int p;-- これは通常の整数型変数です
    • int *p;-- まず p から始めます。最初に * と結合するので、p はポインタであることを示します。次に int と結合するので、ポインタが指す内容の型が int 型であることを示します。したがって、p は整数データへのポインタです。
    • int p[3]-- まず p から始めます。最初に [] と結合するので、p は配列であることを示します。次に int と結合するので、配列の要素が整数型であることを示します。したがって、p は整数データで構成される配列です。
    • int *p[3];-- まず p から始めます。最初に [] と結合します。その優先順位が * より高いため、p は配列です。次に * と結合し、配列の要素がポインタ型であることを示します。さらに int と結合し、ポインタが指す内容の型が整数型であることを示します。したがって、p は整数データへのポインタで構成される配列です。
    • int (*p)[3];-- まず p から始めます。最初に * と結合し、p はポインタであることを示します。次に [] と結合します（"()" の手順は無視してかまいません。優先順位を変更するためだけです）。ポインタが指す内容が配列であることを示します。さらに int と結合し、配列の要素が整数型であることを示します。したがって、p は整数データで構成される配列を指すポインタです。
    • int **p;-- まず p から始めます。最初に * と結合し、p はポインタであることを示します。次に * と結合し、ポインタが指す要素がポインタであることを示します。さらに int と結合し、そのポインタが指す要素が整数データであることを示します。2 次ポインタおよびそれ以上の高次ポインタは複雑な型ではほとんど使用されないため、以降のより複雑な型では多段ポインタは考慮せず、最大でも 1 次ポインタのみを考慮します。
    • int p(int);-- p から始めます。最初に () と結合し、p が関数であることを示します。次に () の中を分析し、その関数が整数型の変数の引数を 1 つ持つことを示します。さらに外側の int と結合し、関数の戻り値が整数データであることを示します。
    • int (*p)(int);-- p から始めます。最初にポインタと結合し、p はポインタであることを示します。次に () と結合し、ポインタが指すものが関数であることを示します。さらに () 内の int と結合し、関数が int 型の引数を 1 つ持つことを示します。そして最外層の int と結合し、関数の戻り値の型が整数型であることを示します。したがって、p は整数型の引数を 1 つ持ち、戻り値の型が整数型である関数へのポインタです。
    • int *(*p(int))[3];まずはこの型は複雑すぎるので飛ばして構いません。p から始めて、最初に () と結合することで、p が関数であることが分かります。次に () の中に入り、int と結合することで、関数が整数型の変数パラメータを1つ持つことが分かります。その後、外側の * と結合することで、関数がポインタを返すことが分かります。そして最外部に移動し、まず [] と結合することで、返されたポインタが配列を指すことが分かります。さらに * と結合することで、配列の要素がポインタであることが分かります。最後に int と結合することで、ポインタが指す内容が整数型データであることが分かります。したがって、p は「整数データを1つパラメータとし、整数型ポインタ変数からなる配列を指すポインタ変数を返す関数」です。

    関数へのポインタ

    コードもデータも同じで、一定のメモリを占有する必要があり、もちろんベースアドレスも存在します。したがって、このベースアドレスを指すポインタを定義できます。これがいわゆる関数ポインタです。

    次のような関数があるとします：

    double func(int a,char c);
double (*p)(int a,char c);
p=&func;

    すると、関数ポインタを定義できます。

    関数の呼び出し

    double s1=func(100,'x');
double s2=(*p)(100,'x');

    上記の2つの文は等価です。

    関数ポインタ形式の受け渡しでありながら、実質はアドレス渡しである一例：

    #include <stdio.h>

void func1(int *a, int **b);

void func1(int *a, int **b)
{
   (*a)++;
   (*b)++;//这里虽然传进来的是指针的形式，但其实是指针c的地址，
          //可以认为这里本质还是值传递，只不过这个值是地址值
}

int main()
{
    int a[2] = {10, 20};
    int *b = &a[0];
    int *c = a+1;
    int **d = &c;
    
    func1(b, d);
    printf("a[0] = %d   a[1] = %d\n", a[0], a[1]);

    return 0;
}

    実行結果：a[0] = 11 a[1] = 20

    以上から分かるように、パラメータを渡す際にはポインタ形式で行いますが、実は値渡しであり、アドレス値の受け渡しであることがあります。特に多次元配列をパラメータとして渡す場合に、このような状況が発生しやすいです。

    2016年にC言語に触れましたが、当時はまったく理解できませんでした！特にポインタは、今から2年余り経って、少し理解できました。振り返ってみると、ポインタと言えばアドレスの概念が話題になります。したがって、ポインタに関連する概念は、Cのメモリ管理と組み合わせて理解する方がよいでしょう。以下では、ポインタをより良く理解する方法について説明します。

    なぜ「ポインタ」と呼ぶのでしょうか。ポインタは実はとても形象的な比喩です。以下に私の個人的な理解を述べます。

    int 変数は int 型の値を格納し、char 変数は char 型の値を格納します。一方、ポインタは特殊な変数で、メモリアドレスを格納します。このテンプレートに従って、次のように理解できます：「メモリアドレス変数」は「メモリアドレス」を格納する。これは「ポインタ変数」が「メモリアドレス」を格納することと等価です。

    オペレーティングシステムがリソースをスケジューリングする際、これらの変数に格納されたアドレスに基づいて、そのアドレスが表すメモリ領域を要求し使用します。これは、あたかもこの変数に格納されたアドレスが何らかのメモリを指しているかのようです。人々は「ポインタ」という言葉で、いわゆる「メモリアドレス変数」を総称しています。

    したがって、ポインタに関連するあらゆる概念は、メモリアドレスと関連付けて理解できます。両者には必ず関連があり、配列とポインタ、関数とポインタも同様です。

    • メモリは線形です。メモリはアドレス空間という形で私たちに見えているので、いわゆるアドレス空間も線形であると言えます。ポインタはメモリアドレスを格納するため、アドレスに対して ++ や -- のような演算を行うことができます。
    • ポインタに NULL を代入しないという2つのケースは、悪い習慣です
    • ポインタを初期化する際に NULL を代入しないこのようなポインタは未知の領域を指すことになり、NULLポインタではありませんが、アクセスが制限されたメモリ領域を指すため、使用できません。このようなポインタを、業界では「ワイルドポインタ」という形象的な名前で呼んでいます。また、デバッグが困難で、多くのコンパイラでシングルステップデバッグを行うと奇妙なエラーが発生します。よく見かける "Segmentation Fault" のようなエラーは、コード量が多い場合に非常に厄介なエラーであり、ワイルドポインタもその原因の1つです。したがって、このようなエラーを見たら、まず初期化されていないポインタがないかどうかを考えてください。
    • free() 後にポインタに NULL を代入しないポインタにメモリを割り当てると、ポインタは合法的に使用可能なメモリ領域を指すことができます。しかし、free() を使用してそのメモリ領域を解放すると、ポインタは依然としてそのメモリ領域のアドレスを保持しており、つまり依然としてそのメモリ領域を指しています。しかし、このメモリ領域は解放済みであり、アクセスできません。このとき、誤ってこのポインタを使用すると、メモリエラーが発生し、また奇妙なバグが発生する可能性があります。コードが数百行を超えるとデバッグが困難になります。業界ではこのようなポインタを総称して「ダングリングポインタ」と呼びます。このような厄介な状況を避けるために、メモリを解放した後は、そのメモリ領域を指すポインタすべてに NULL を代入する必要があります。これからも分かるように、free() 関数がメモリを解放するとき、そのメモリ領域を指すポインタとは何の関係もなく、ポインタごと処理してくれることはありません！命を大切に、「ワイルドポインタ」と「ダングリングポインタ」を遠ざけましょう！
    • 多段ポインタポインタを指すポインタであり、多次元ポインタと呼ばれることもあります。ポインタ変数は変数である以上、ポインタ変数は変数のメモリアドレスを格納できます。

    int * は int 型変数のアドレスを格納し、char * は char 型のアドレスを格納します。それなら、ポインタがポインタ変数のアドレスを格納できるのは当然ですね。

    例えば、int ** は int * のアドレスを格納し、int *** は int ** のアドレスを格納します。

    これは、2段ポインタが1段ポインタのアドレスを格納し、3段ポインタが2段ポインタのアドレスを格納するというものです。人々はこのような仕組みを「ポインタを指すポインタ」と呼びますが、実際には上位のポインタが下位のポインタのアドレスを格納しているだけです。

    したがって、上で述べたように、そのアドレスを格納すれば、それを指すことになります。つまり：

    • 2段ポインタが1段ポインタのアドレスを格納する場合、2段ポインタは1段ポインタを指すと言えます。
    • 3段ポインタが2段ポインタのアドレスを格納する場合、2段ポインタは1段ポインタを指すと言えます。
    • 多段ポインタは用途がたくさんありますが、ここでは例を挙げて詳しく説明しません。

    個人的には、ポインタはC言語の最も偉大な特性であると言えると思います。このようなモデルを通じて、メモリの一部を形象的に管理できます！

    前の投稿のコードにある興味深い現象について説明します。

    16行目の原文は次のとおりです：

    printf("p内存空间里存放的数据为:%d\n",p);

    pメモリ空間に格納されているデータはアドレスであり、そのアドレスはNULL、つまり0……0。

    而 %dは10進数の整数として出力することを意味します。したがって、この行のコードの意味は、アドレス0……0を10進数の整数に変換して出力することです。したがって、表示されるのは0。

    一方、この行のコードを次のように変更すると：

    printf("p内存空间里存放了一个内存地址，这个内存地址存放的数据为:%d\n",*p);

    その場合、表示されるはずなのはアドレス0……0に格納されているデータです。しかし、このアドレスには明らかにデータが格納されていません。プログラムをこのように書いて実行すると、プログラムがこの行で異常終了し、このprintfおよびそれ以降のprintf関数は実行されません。

    ポインタ記号を左揃えにすると、その意味をより理解しやすくなります。

    ポインタが左にある方がなぜ良いのかについて：C/C++ Pointer Alignment Style: A Justification

    int i = 5; // i 的变量类型是「整数」
int* j = 6; // j 的变量类型是「整数指针」
// * 不应该看起来像是「名称中的一部分」
// 好的规范是每行只初始化「一个变量」

    ほとんどのエディタでは、デフォルトのポインタ記号は右揃えです。例： int *i = 1

    ポインタ記号を左揃えにするには、次のようにします： int* i = 1、VS Code で設定できます。次のように設定するだけですC_CPP: Formattingエンジンを「clangFormat」から「vcFormat」に変更し、さらにC_Cpp › Vc Format › Space: Pointer Reference Alignmentを「left」に設定すると、ポインタ記号が左揃えになります。

    それでは、ポインタについてもう一度理解してみましょう：

    int p; //p是整型变量 
int* p; //p是整型指针 
int** p; //p是指向「整型指针」的指针 
int p[3]; //p是数组，数组成员是「int」 
int* p[3]; //p是数组，数组成员是「整型指针」 
int (* p)[3]; //p先被 * 修饰，是一个指针，指向一个数组，数组成员是「int」 
int p(int); //p是一个函数；「所指函数」有一个参数，「参数类型」是「int」，「返回值类型」是「int」 
int (* p)(int); //p是一个指针，指向一个函数；函数的「参数类型」是「int」，「返回值类型」是「int」 
int* (* p(int))[3]; //p是一个函数，该函数有一个「int」参数，返回一个指针，指向一个数组，数组里放的是「整型指针」
