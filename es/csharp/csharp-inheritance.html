C# Herencia

La herencia es uno de los conceptos más importantes en la programación orientada a objetos. La herencia nos permite definir una clase basándonos en otra, lo que facilita la creación y el mantenimiento de aplicaciones. También favorece la reutilización de código y ahorra tiempo de desarrollo.

Al crear una clase, el programador no necesita reescribir por completo nuevos miembros de datos y funciones miembro; solo necesita diseñar una nueva clase que herede los miembros de la clase existente. Esta clase existente se denominaclase base, y esta nueva clase se denominaclase derivada。

La idea de la herencia implementa la relación depertenencia (IS-A). Por ejemplo, un mamíferopertenece a (IS-A)un animal, un perropertenece a (IS-A)un mamífero, por lo tanto un perropertenece a (IS-A)un animal.

Clase base y clase derivada

Una clase puede heredar de otra clase, denominándose clase base (clase padre) y clase derivada (clase hija).

C# no admite la herencia múltiple de clases, pero admite la herencia múltiple de interfaces; una clase puede implementar múltiples interfaces.

En resumen:Una clase puede heredar de múltiples interfaces, pero solo puede heredar de una clase.

La sintaxis para crear una clase derivada en C# es la siguiente:

<modificador de acceso> class <clase base>
{
 ...
}
class <clase derivada> : <clase base>
{
 ...
}

La clase derivada hereda los miembros de la clase base (campos, métodos, propiedades, etc.), a menos que estén marcados explícitamente como privados (private).

La clase derivada puede invocar los constructores y métodos de la clase base mediante la palabra clave base.

Ejemplo

class BaseClass
{
    public void SomeMethod()
    {
        // Method implementation
    }
}

class DerivedClass : BaseClass
{
    public void AnotherMethod()
    {
        // Accessing base class method
        base.SomeMethod();
       
        // Method implementation
    }
}

Supongamos que hay una clase base Shape y su clase derivada es Rectangle:

Ejemplo

using System;
namespace InheritanceApplication
{
   class Shape
   {
      public void setWidth(int w)
      {
         width = w;
      }
      public void setHeight(int h)
      {
         height = h;
      }
      protected int width;
      protected int height;
   }

   // Clase derivada
   class Rectangle: Shape
   {
      public int getArea()
      {
         return (width * height);
      }
   }
   
   class RectangleTester
   {
      static void Main(string[] args)
      {
         Rectangle Rect = new Rectangle();

         Rect.setWidth(5);
         Rect.setHeight(7);

         // Imprime el área del objeto
         Console.WriteLine("Área total: {0}",  Rect.getArea());
         Console.ReadKey();
      }
   }
}

Inicialización de la clase base

La clase derivada hereda las variables miembro y los métodos miembro de la clase base. Por lo tanto, el objeto de la clase padre debe crearse antes de que se cree el objeto de la clase hija. Puede realizar la inicialización de la clase padre en la lista de inicialización de miembros.

El siguiente programa demuestra esto:

Ejemplo

using System;
namespace RectangleApplication
{
   class Rectangle
   {
      // Variables miembro
      protected double length;
      protected double width;
      public Rectangle(double l, double w)
      {
         length = l;
         width = w;
      }
      public double GetArea()
      {
         return length * width;
      }
      public void Display()
      {
         Console.WriteLine("Longitud: {0}", length);
         Console.WriteLine("Ancho: {0}", width);
         Console.WriteLine("Área: {0}", GetArea());
      }
   }//end class Rectangle  
   class Tabletop : Rectangle
   {
      private double cost;
      public Tabletop(double l, double w) : base(l, w)
      { }
      public double GetCost()
      {
         double cost;
         cost = GetArea() * 70;
         return cost;
      }
      public void Display()
      {
         base.Display();
         Console.WriteLine("Costo: {0}", GetCost());
      }
   }
   class ExecuteRectangle
   {
      static void Main(string[] args)
      {
         Tabletop t = new Tabletop(4.5, 7.5);
         t.Display();
         Console.ReadLine();
      }
   }
}

宽度： 7.5
面积： 33.75
成本： 2362.5

Herencia de interfaces (Interface Inheritance)

Una interfaz puede heredar de una o más interfaces; la interfaz derivada hereda todos los miembros de la interfaz base.

La interfaz derivada puede ampliar la lista de miembros de la interfaz base, pero no puede cambiar sus modificadores de acceso.

Ejemplo

interface IBaseInterface
{
    void Method1();
}

interface IDerivedInterface : IBaseInterface
{
    void Method2();
}

El ejemplo de herencia de interfaces se puede implementar de la siguiente manera:

Ejemplo

using System;

// Define una interfaz base
interface IBaseInterface
{
    void Method1();
}

// Define una interfaz derivada que hereda de la interfaz base
interface IDerivedInterface : IBaseInterface
{
    void Method2();
}

// Clase que implementa la interfaz derivada
class MyClass : IDerivedInterface
{
    public void Method1()
    {
        Console.WriteLine("Method1 implementation");
    }

    public void Method2()
    {
        Console.WriteLine("Method2 implementation");
    }
}

class Program
{
    static void Main(string[] args)
    {
        // Crea una instancia de la clase MyClass
        MyClass obj = new MyClass();

        // Llama al método heredado de la interfaz base
        obj.Method1();

        // Llama al método nuevo de la interfaz derivada
        obj.Method2();
    }
}

En el ejemplo anterior, la clase MyClass implementa la interfaz IDerivedInterface, por lo que debe proporcionar todos los métodos definidos en IDerivedInterface, incluido el método Method1() heredado de IBaseInterface. En el método Main, creamos una instancia obj de MyClass y llamamos a sus métodos.

El resultado es:

Method1 implementation
Method2 implementation

C# Herencia múltiple

La herencia múltiple se refiere a la capacidad de una clase de heredar comportamientos y características de más de una clase padre al mismo tiempo. En contraste con la herencia única, que se refiere a que una clase solo puede heredar de una clase padre.

C# no admite la herencia múltiple. Sin embargo, puede utilizar interfaces para implementar la herencia múltiple. El siguiente programa demuestra esto:

Ejemplo

using System;
namespace InheritanceApplication
{
   class Shape
   {
      public void setWidth(int w)
      {
         width = w;
      }
      public void setHeight(int h)
      {
         height = h;
      }
      protected int width;
      protected int height;
   }

   // Clase base PaintCost
   public interface PaintCost
   {
      int getCost(int area);

   }
   // Clase derivada
   class Rectangle : Shape, PaintCost
   {
      public int getArea()
      {
         return (width * height);
      }
      public int getCost(int area)
      {
         return area * 70;
      }
   }
   class RectangleTester
   {
      static void Main(string[] args)
      {
         Rectangle Rect = new Rectangle();
         int area;
         Rect.setWidth(5);
         Rect.setHeight(7);
         area = Rect.getArea();
         // Imprime el área del objeto
         Console.WriteLine("Área total: {0}",  Rect.getArea());
         Console.WriteLine("Costo total de pintura: ${0}" , Rect.getCost(area));
         Console.ReadKey();
      }
   }
}

    ¿Por qué un objeto puede declararse con una clase padre pero instanciarse con una clase hija?

    Esta instancia es de la clase hija, pero como la declaraste con la clase padre, no puedes acceder a los miembros propios de la clase hija mediante el método normal; solo puedes acceder a los miembros heredados de la clase padre.

    Cuando en la clase hija se usa override para reescribir un método virtual declarado con virtual en la clase padre, al instanciar la clase padre y llamar a ese método, en tiempo de ejecución se llama al método reescrito en la clase hija;

    Si en la clase hija se usa new para ocultar un método virtual declarado con virtual en la clase padre, al instanciar la clase padre y llamar a ese método, en tiempo de ejecución se llama al método virtual de la clase padre;

    /// <summary>  
/// 父类  
/// </summary>  
public class ParentClass  
{  
   public virtual void ParVirMethod()  
   {  
       Console.WriteLine("父类的方法...");  
   }  
}  

/// <summary>  
/// 子类1  
/// </summary>  
public class ChildClass1 : ParentClass  
{  
   public override void ParVirMethod()  
   {  
       Console.WriteLine("子类1的方法...");  
   }  
}  

/// <summary>  
/// 子类2  
/// </summary>  
public class ChildClass2 : ParentClass  
{  
   public new void ParVirMethod()  
   {  
       Console.WriteLine("子类2的方法...");  
   }  

   public void Test()  
   {  
       Console.WriteLine("子类2的其他方法...");  
   }  
}

    Ejecución de la llamada:

    ParentClass par = new ChildClass1();  
par.ParVirMethod(); //结果："子类1的方法"，调用子类的方法，实现了多态

par = new ChildClass2();  
par.ParVirMethod(); //结果："父类的方法"，调用父类的方法，没有实现多态

    Investigando a fondo la causa, la diferencia entre ambos se debe a que los principios son diferentes:override es reescribir, es decir, eliminar directamente el método de la clase base y reescribirlo en la clase derivada, por lo que el método llamado es el de la clase hija; mientras que new solo oculta el método de la clase base en la clase derivada, por lo que el método llamado sigue siendo el de la clase base.

    Ejemplo de aplicación

    Existe esta necesidad, por ejemplo, la clase People tiene un método Run, y las clases Man y Woman heredan de People y ambas reescriben (override) el método Run (los hombres y las mujeres corren de manera diferente).

    Ahora hay un grupo de personas corriendo juntas, con hombres y mujeres.

    Podemos ponerlos todos en un array de People (supongamos que se llama peoples).

    Entonces:

    foreach(People p in peoples) // peoples中对象不同（即有男有女），用于实例化的子类就不同。
{
    p.Run(); // 故而，调用的方法也不同，实现了多态
}

    Debido al polimorfismo, al llamar a p.Run(), si el objeto p en sí es un hombre, automáticamente llamará al método Run del hombre; si es una mujer, llamará al método Run de la mujer.

    Principio de inversión de dependencias

    El principio de inversión de dependencias, DIP, Dependency Inverse Principle, se expresa de la siguiente manera:

    1. Los módulos de alto nivel no deberían depender de los módulos de bajo nivel; ambos deberían depender de abstracciones.

    2. Las abstracciones no deberían depender de los detalles; los detalles deberían depender de las abstracciones.

    Aquí “depender” significa usar. Si llamas a un método de una clase, dependes de esa clase. Si llamas directamente al método de esta clase, dependes de los detalles; los detalles son las clases concretas. Pero si llamas a un método de su clase padre o interfaz, dependes de la abstracción. Así que DIP, en pocas palabras, significa no usar directamente la subclase concreta, sino usar una referencia de su clase padre para llamar a los métodos de la subclase; de este modo se depende de la abstracción, no de lo concreto.

    En realidad, en pocas palabras, el beneficio de DIP es eliminar el acoplamiento. Después de usar DIP, el llamador no sabe qué código está siendo llamado, porque el llamador obtiene una referencia de la clase padre; no sabe a qué instancia de subclase apunta concretamente, ni mucho menos sabe exactamente qué método se va a llamar. Por lo tanto, cuando el código llamado se reemplaza silenciosamente por otra subclase, el llamador no necesita hacer ninguna modificación; eso es desacoplar.

    Sobre el acceso a la clase base (acceso a los miembros de la clase base ocultos)

    Fields -- In the derived class

    Si se desea que la clase derivada pueda acceder completamente a los miembros heredados ocultos, se puede utilizar la expresión de acceso a la clase base para acceder a dichos miembros heredados ocultos.

    La expresión de acceso a la clase base se compone de la palabra clave base seguida de un punto y el nombre del miembro. Por ejemplo:

    Console.WriteLine("{0}",base.Field1);

    En la línea de código anterior, base.Fields1 es un acceso a la clase base.

    Ejemplo de acceso a la clase base:

    class SomeClass   //基类
{
    public string Field1 = "Fields -- In the base class";
}

class OtherClass : SomeClass  //继承类OtherClass，继承于SomeClass
{
    new public string Field1 = "Fields -- In the derived class";
    public void PrintField1()
    {
        Console.WriteLine(Field1);    //访问派生类
        Console.WriteLine(base.Field1)  //访问基类
    }
}


class Program
{
   static void Main()
   {
        OtherClass oc = new OtherClass();  //实例化
        oc.PrintFields1();                //执行oc的PrintFields1()方法
   }  
}

    El código anterior es un ejemplo de acceso a miembros ocultos de la clase base; el resultado de la ejecución es la salida:

    Fields -- In the derived class
Fields -- In the base class

    Algunos puntos sobre la herencia:

    • 1. Sintaxis de la herencia:class nombre_de_subclase : class nombre_de_clase_padre { // cuerpo de la subclase }
    • 2. Características de la herencia: la subclase posee todos los campos, propiedades y métodos de la clase padre.
    • 3. Una clase puede tener múltiples subclases, pero solo puede tener una clase padre.
    • 4. Una clase, además de heredar de otra, también puede ser heredada por otras clases.
    • 5. En C#, todas las clases heredan directa o indirectamente de la clase Object.
