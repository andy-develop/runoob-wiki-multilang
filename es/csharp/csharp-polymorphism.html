C# Polimorfismo

El polimorfismo es la capacidad de un mismo comportamiento de tener múltiples formas o manifestaciones diferentes.

PolimorfismoSignifica tener múltiples formas. En el paradigma de programación orientada a objetos, el polimorfismo suele manifestarse como "una interfaz, múltiples funciones".

El polimorfismo puede ser estático o dinámico. En elpolimorfismo estático, las respuestas de las funciones ocurren en tiempo de compilación. En elpolimorfismo dinámico, las respuestas de las funciones ocurren en tiempo de ejecución.

En C#, todos los tipos son polimórficos porque todos los tipos, incluidos los tipos definidos por el usuario, heredan de Object.

El polimorfismo es la misma interfaz que, al usar diferentes instancias, ejecuta diferentes operaciones, como se muestra en la figura:

En la vida real, por ejemplo, la acción de presionar la tecla F1:

  • Si actualmente se encuentra en la interfaz de Flash, aparecerá el documento de ayuda de AS 3;
  • Si se encuentra en Word, aparecerá la ayuda de Word;
  • Si está en Windows, aparecerá la ayuda y el soporte de Windows.

El mismo evento que ocurre en diferentes objetos produce diferentes resultados.

Polimorfismo estático

El mecanismo de conexión entre funciones y objetos en tiempo de compilación se denomina enlace temprano, también conocido como enlace estático. C# proporciona dos técnicas para implementar el polimorfismo estático, a saber:

  • Sobrecarga de funciones
  • Sobrecarga de operadores

La sobrecarga de operadores se discutirá en el siguiente capítulo; a continuación hablaremos de la sobrecarga de funciones.

Sobrecarga de funciones

No se permite que las distintas sobrecargas difieran solo en el tipo de retorno de la declaración de la función.

El siguiente ejemplo demuestra varias funciones con el mismo nombreAdd(), que se utilizan para sumar diferentes números de parámetros:

Ejemplo

using System;
namespace PolymorphismApplication
{
    public class TestData  
    {  
        public int Add(int a, int b, int c)  
        {  
            return a + b + c;  
        }  
        public int Add(int a, int b)  
        {  
            return a + b;  
        }  
    }  
    class Program  
    {  
        static void Main(string[] args)  
        {  
            TestData dataClass = new TestData();
            int add1 = dataClass.Add(1, 2);  
            int add2 = dataClass.Add(1, 2, 3);

            Console.WriteLine("add1 :" + add1);
            Console.WriteLine("add2 :" + add2);  
        }  
    }  
}

Polimorfismo dinámico

C# le permite usar la palabra claveabstractcrear clases abstractas para proporcionar la implementación parcial de una interfaz. Cuando una clase derivada hereda de dicha clase abstracta, la implementación se completa.La clase abstractacontiene métodos abstractos, que pueden ser implementados por las clases derivadas. Las clases derivadas tienen una funcionalidad más especializada.

Tenga en cuenta las siguientes reglas sobre las clases abstractas:

  • No se puede crear una instancia de una clase abstracta.
  • No se puede declarar un método abstracto fuera de una clase abstracta.
  • Al colocar la palabra clavesealedsealed delante de la definición de la clase, se puede declarar la clase comoclase sellada. Cuando una clase se declara comosealedsealed, no puede ser heredada. Una clase abstracta no puede declararse como sealed.

El siguiente programa demuestra una clase abstracta:

Ejemplo

using System;
namespace PolymorphismApplication
{
   abstract class Shape
   {
       abstract public int area();
   }
   class Rectangle:  Shape
   {
      private int length;
      private int width;
      public Rectangle( int a=0, int b=0)
      {
         length = a;
         width = b;
      }
      public override int area ()
      {
         Console.WriteLine("Rectangle 类的面积：");
         return (width * length);
      }
   }

   class RectangleTester
   {
      static void Main(string[] args)
      {
         Rectangle r = new Rectangle(10, 7);
         double a = r.area();
         Console.WriteLine("面积： {0}",a);
         Console.ReadKey();
      }
   }
}

Cuando una función definida en una clase necesita ser implementada en una clase heredada, se puede usarun método virtual.。

Un método virtual se declara con la palabra clavevirtualvirtual.

Los métodos virtuales pueden tener diferentes implementaciones en diferentes clases heredadas.

La llamada a un método virtual ocurre en tiempo de ejecución.

El polimorfismo dinámico se implementa medianteclases abstractas 和 y métodos virtuales.

El siguiente ejemplo crea la clase base Shape y las clases derivadas Circle, Rectangle y Triangle. La clase Shape proporciona un método virtual llamado Draw, que se reemplaza en cada clase derivada para dibujar la forma específica de esa clase.

Ejemplo

using System;
using System.Collections.Generic;

public class Shape
{
    public int X { get; private set; }
    public int Y { get; private set; }
    public int Height { get; set; }
    public int Width { get; set; }
   
    // 虚方法
    public virtual void Draw()
    {
        Console.WriteLine("执行基类的画图任务");
    }
}

class Circle : Shape
{
    public override void Draw()
    {
        Console.WriteLine("画一个圆形");
        base.Draw();
    }
}
class Rectangle : Shape
{
    public override void Draw()
    {
        Console.WriteLine("画一个长方形");
        base.Draw();
    }
}
class Triangle : Shape
{
    public override void Draw()
    {
        Console.WriteLine("画一个三角形");
        base.Draw();
    }
}

class Program
{
    static void Main(string[] args)
    {
        // 创建一个 List<Shape> 对象，并向该对象添加 Circle、Triangle 和 Rectangle
        var shapes = new List<Shape>
        {
            new Rectangle(),
            new Triangle(),
            new Circle()
        };

        // 使用 foreach 循环对该列表的派生类进行循环访问，并对其中的每个 Shape 对象调用 Draw 方法
        foreach (var shape in shapes)
        {
            shape.Draw();
        }

        Console.WriteLine("按下任意键退出。");
        Console.ReadKey();
    }

}

Cuando el código anterior se compila y ejecuta, produce los siguientes resultados:

画一个长方形
执行基类的画图任务
画一个三角形
执行基类的画图任务
画一个圆形
执行基类的画图任务

    Polimorfismo en C#

    Polimorfismo:Una interfaz, múltiples funciones.

    Polimorfismo estático:La respuesta (llamada) de la función ocurre en tiempo de compilación;

    Polimorfismo dinámico:La respuesta de la función ocurre en tiempo de ejecución.

    Enlace estático (enlace temprano):Mecanismo de conexión entre funciones y objetos en tiempo de compilación. Dos técnicas implementan el polimorfismo estático: sobrecarga de funciones / sobrecarga de operadores.

    Sobrecarga de funciones:Múltiples definiciones del mismo nombre de función en el mismo ámbito, que pueden diferir en el tipo o en el número de parámetros, pero no se permite que difieran solo en el tipo de retorno.

    Sobrecarga de operadores:

    La palabra clave abstract declara clases abstractas: se utiliza para la implementación parcial de una interfaz (cuando una clase derivada hereda de la clase abstracta, la implementación está completa). La clase abstracta contiene métodos abstractos, que pueden ser implementados por las clases derivadas.

    Reglas de las clases abstractas:

    • 1. No se puede crear una instancia de una clase abstracta.
    • 2. No se puede definir un método abstracto fuera de la clase abstracta.
    • 3. No se puede declarar una clase abstracta como sealed (la palabra clave sealed delante de la clase indica que dicha clase es una clase sellada y no puede ser heredada).

    La palabra clave virtual declara métodos virtuales: se utiliza para la implementación de métodos en clases heredadas (con diferentes implementaciones en diferentes clases heredadas).

    Las clases abstractas y los métodos virtuales implementan conjuntamente el polimorfismo dinámico.

    Nota: para reemplazar un método virtual en una clase heredada, es necesario declarar la palabra clave override; al pasar parámetros al método, se escribe (nombre de clase nombre de parámetro), por ejemplo public void CallArea(Shape sh), lo que significa pasar un objeto de tipo Shape.

    virtual y abstract

    virtual y abstract se utilizan para modificar la clase padre; al sobrescribir la definición de la clase padre, permiten que la clase hija la redefina.

    • 1. Los métodos modificados con virtual deben tener una implementación (aunque solo se agregue un par de llaves), mientras que los métodos modificados con abstract no pueden tener implementación.
    • 2. virtual puede ser reemplazado por la subclase, mientras que abstract debe ser reemplazado por la subclase.
    • 3. Si un miembro de la clase está modificado con abstract, la clase debe llevar abstract delante, porque solo las clases abstractas pueden tener métodos abstractos.
    • 4. No se puede crear una instancia de la clase abstract; solo se puede heredar, no instanciar.

    Sobrecarga y sobrescritura

    La sobrecarga (overload) es un mecanismo que permite distinguir funciones con el mismo nombre mediante diferentes tipos de retorno y parámetros.

    Ver:Sobrecarga de funciones

    La sobrescritura (override) se utiliza para reemplazar un método virtual de la clase base, proporcionando así un nuevo método en la clase derivada.

    Ver:Polimorfismo dinámico

    Diferencia entre métodos abstractos y métodos virtuales

    • 1. Los métodos virtuales deben tener una parte de implementación; los métodos abstractos no proporcionan una parte de implementación. Un método abstracto es un método que obliga a la clase derivada a anularlo; de lo contrario, la clase derivada no podrá ser instanciada.
    • 2. Los métodos abstractos solo pueden declararse en clases abstractas; los métodos virtuales no. Si una clase contiene un método abstracto, entonces la clase también es abstracta, y también debe declararse como abstracta.
    • 3. Los métodos abstractos deben anularse en la clase derivada; esto es similar a las interfaces. Los métodos virtuales no necesitan anularse en la clase derivada.

    En pocas palabras, los métodos abstractos deben ser implementados por las subclases. Los métodos virtuales ya están implementados; pueden ser anulados por la subclase o no, según los requisitos.

    Tanto los métodos abstractos como los métodos virtuales pueden ser anulados por las clases derivadas.

    1、Sobrecarga (overload): En el mismo ámbito (generalmente una clase), dos o más métodos con el mismo nombre de función pero con listas de parámetros diferentes se denominan sobrecarga. Tienen tres características (comúnmente conocidas como dos obligatorias y una opcional):

    • El nombre del método debe ser el mismo
    • La lista de parámetros debe ser diferente
    • El tipo de retorno puede ser diferente

    Por ejemplo:

    public void Sleep()
{
    Console.WriteLine("Animal睡觉");
}
public int Sleep(int time)
{
    Console.WriteLine("Animal{0}点睡觉", time);
    return time;
}

    2、Anulación (override): En la subclase, para satisfacer sus propias necesidades al redefinir una implementación diferente de un método, se necesita la palabra clave `override`. El método que se anula debe ser un método virtual, usando la palabra clave `virtual`. Sus características son (tres igualdades):

    • El mismo nombre del método
    • La misma lista de parámetros
    • El mismo tipo de retorno

    Por ejemplo: definición en la clase padre:

    public virtual void EatFood()
{
    Console.WriteLine("Animal吃东西");
}

    Definición en la subclase:

    public override void EatFood()
{
    Console.WriteLine("Cat吃东西");
    //base.EatFood();
}

    Consejo:A menudo los compañeros preguntan por la diferencia entre sobrecarga y anulación, y en Internet se utiliza esta diferencia como una de las preguntas frecuentes de entrevistas de C#. En realidad, estos dos conceptos no tienen ninguna relación en absoluto; solo comparten el carácter "重". No tiene sentido compararlos entre sí; basta con distinguir sus definiciones.

    3、Método virtual: Es un método definido en la clase base que permite anularse en la clase derivada, definido con la palabra clave `virtual`. Por ejemplo:

    public virtual void EatFood()
{
    Console.WriteLine("Animal吃东西");
}

    Nota: Los métodos virtuales también pueden llamarse directamente. Por ejemplo:

    Animal a = new Animal();
a.EatFood();

    El resultado de la ejecución es:

    Animal吃东西

    4、Método abstracto: Es un método definido en la clase base y que debe anularse en la clase derivada, utilizando laabstractpalabra clave. Por ejemplo:

    public abstract class Biology
{
    public abstract void Live();
}
public class Animal : Biology
{
    public override void Live()
    {
        Console.WriteLine("Animal重写的抽象方法");
        //throw new NotImplementedException();
    } 
}

    Nota:Los métodos abstractos solo pueden definirse en clases abstractas. Si no se definen en una clase abstracta, se producirá el siguiente error:

    La diferencia entre métodos virtuales y métodos abstractos es: Debido a que una clase abstracta no puede instanciarse, no hay forma de llamar a un método abstracto; es decir, un método abstracto nunca puede ser implementado.

    5、Método oculto: Un método definido en la clase derivada con el mismo nombre que algún método de la clase base, definido con la palabra clave `new`. Por ejemplo, en la clase base `Animal` hay un método `Sleep()`:

    public void Sleep()
{
    Console.WriteLine("Animal Sleep");
}

    Entonces el código para definir el método oculto en la clase derivada `Cat` es:

    new public void Sleep()
{
    Console.WriteLine("Cat Sleep");
}

    O también:

    public new void Sleep()
{
    Console.WriteLine("Cat Sleep");
}

    Nota:

    • (1) El método oculto no solo puede ocultar métodos virtuales de la clase base, sino también métodos no virtuales de la clase base.
    • (2) En el método oculto, una instancia de la clase padre llama al método de la clase padre, y una instancia de la subclase llama al método de la subclase.
    • (3) En contraste con el punto anterior: en un método anulado, una variable de la subclase llama al método anulado de la subclase; una variable de la clase padre depende de si la referencia de la clase padre apunta a una instancia de la subclase o a una instancia de sí misma. Si se refiere a una instancia de la clase padre, llama al método de la clase base; si se refiere a una instancia de la clase derivada, llama al método de la clase derivada.

    Invocación de métodos virtuales:En cuanto a la invocación, si se usa un objeto construido por la subclase para llamar a un método virtual, se llamará al método de la subclase; si se usa un objeto construido por la clase padre, se llamará al método de la clase padre.

    Invocación de métodos ocultos:En cuanto a la invocación, si se llama a un método oculto con una declaración de tipo de subclase, se llamará al método de la subclase. Si se desea llamar al método oculto, se necesita usar una declaración de tipo de clase padre para invocarlo.

    Las clases abstractas, los métodos abstractos y los métodos virtuales son conceptos importantes en la programación orientada a objetos; se utilizan para implementar polimorfismo y herencia.

    Las clases abstractas y los métodos abstractos son adecuados para los siguientes escenarios:

    • Cuando se necesita definir una clase, pero la implementación concreta de esta clase la realizan las subclases, se puede definir una clase abstracta y definir métodos abstractos en la clase abstracta. De esta manera, las subclases deben implementar estos métodos abstractos para completar la implementación concreta.
    • Cuando se necesita restringir que ciertas subclases deban implementar ciertos métodos, se pueden usar clases abstractas y métodos abstractos.

    Los métodos virtuales son adecuados para los siguientes escenarios:

    • Cuando se necesita proporcionar una implementación predeterminada en la clase base, pero la subclase puede optar por anular esta implementación, se pueden usar métodos virtuales. De esta manera, en la subclase se puede usar laoverridepalabra clave para anular el método virtual de la clase base, implementando así su propia lógica.

    En general, las clases abstractas y los métodos abstractos son más adecuados para restringir y estandarizar la estructura de herencia de las clases y la implementación de métodos, mientras que los métodos virtuales son más adecuados para escenarios donde se proporciona una implementación predeterminada y se permite que las subclases la anulen.

    En una clase abstracta, además de los métodos abstractos, también se pueden declarar los siguientes miembros como miembros abstractos:

    1. Propiedades abstractas (abstract properties): similares a los métodos abstractos, no tienen cuerpo de implementación, solo declaración, y deben implementarse en la subclase concreta.

    2. Eventos abstractos (abstract events): similares a los métodos y propiedades abstractos, deben implementarse en la subclase concreta.

    3. Indizadores abstractos (abstract indexers): similares a las propiedades abstractas, no tienen cuerpo de implementación, solo declaración, y deben implementarse en la subclase concreta.

    Además de los métodos virtuales, una clase también puede tener los siguientes miembros virtuales:

    1. Propiedades virtuales (Virtual Properties): usando lavirtualpalabra clave para definir la propiedad, que se puede anular en la subclase.

    2. Indizadores virtuales (Virtual Indexers): usando lavirtualpalabra clave para definir el indizador, que se puede anular en la subclase.

    3. Eventos virtuales (Virtual Events): usando lavirtualpalabra clave para definir el evento, que se puede anular en la subclase.

    La función de los miembros virtuales es similar a la de los métodos virtuales; pueden anularse en la clase derivada para satisfacer diferentes necesidades. Al mismo tiempo, los miembros virtuales también pueden mejorar la reutilización y la extensibilidad del código.
