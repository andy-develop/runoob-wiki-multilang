C++ Polimorfismo

PolimorfismoLiteralmente significa múltiples formas.

Cuando existe una jerarquía entre clases y las clases se relacionan mediante herencia, se utiliza el polimorfismo.

En C++, el polimorfismo (Polymorphism) es una de las características importantes de la programación orientada a objetos.

El polimorfismo de C++ permite utilizar punteros o referencias de la clase base para llamar a los métodos reescritos de la subclase, de modo que la misma interfaz pueda presentar diferentes comportamientos.

El polimorfismo hace que el código sea más flexible y genérico. El programa puede operar sobre objetos de diferentes tipos a través de punteros o referencias de la clase base, sin necesidad de distinguir explícitamente el tipo de objeto. Esto hace que el código sea más extensible: al añadir una nueva clase de forma, no es necesario modificar el programa principal.

A continuación se presentan varios puntos clave del polimorfismo:

Funciones virtuales (Virtual Functions)：

  • En la clase base se declara una función como virtual, utilizando la palabra clavevirtual。
  • La clase derivada puede reescribir (override) esta función virtual.
  • Al llamar a una función virtual, se decide qué versión de la función invocar según el tipo real del objeto.

Enlace dinámico (Dynamic Binding)：

  • También llamado enlace tardío (Late Binding); determina la implementación específica de la llamada a la función en tiempo de ejecución.
  • Se necesita utilizar un puntero o una referencia a la clase base para llamar a la función virtual; el compilador decide en tiempo de ejecución qué función invocar según el tipo real del objeto.

Funciones virtuales puras (Pure Virtual Functions)：

  • Una clase que contiene funciones virtuales puras se denomina clase abstracta (Abstract Class) y no puede instanciarse directamente.
  • Una función virtual pura no tiene cuerpo de función; al declararla se utiliza= 0。
  • Obliga a la clase derivada a proporcionar una implementación concreta.

Mecanismo de implementación del polimorfismo：

  • Tabla de funciones virtuales (V-Table): C++ en tiempo de ejecución utiliza la tabla de funciones virtuales para implementar el polimorfismo. Cada clase que contiene funciones virtuales tiene una tabla de funciones virtuales, en la que se almacenan punteros a todas las funciones virtuales de la clase.
  • Puntero de función virtual (V-Ptr): el objeto contiene un puntero a la tabla de funciones virtuales de su clase.

Ventajas de utilizar el polimorfismo：

  • Reutilización de código: a través de punteros o referencias de la clase base, se pueden operar objetos de diferentes clases derivadas, logrando la reutilización del código.
  • Extensibilidad: al añadir una clase derivada nueva, no es necesario modificar el código que depende de la clase base; solo hay que asegurarse de que la nueva clase reescriba correctamente las funciones virtuales.
  • Desacoplamiento: el polimorfismo permite que el diseño del programa sea más modular, reduciendo el acoplamiento entre clases.

Consideraciones：

  • Solo se produce polimorfismo cuando se llama a una función virtual a través de un puntero o referencia de la clase base.
  • Si se utiliza directamente un objeto de la clase derivada para llamar a la función, se invoca la versión de la clase derivada, no la de la clase base.
  • El polimorfismo requiere información de tipo en tiempo de ejecución (RTTI), lo que puede aumentar la sobrecarga del programa.

Ejemplo 1

Veamos la aplicación del polimorfismo a través de un ejemplo sencillo:

Ejemplo 1

#include <iostream>
using namespace std;

// Clase base Animal
class Animal {
public:
    // Función virtual sound, proporciona una interfaz para el sonido de diferentes animales
    virtual void sound() const {
        cout << "Animal makes a sound" << endl;
    }
   
    // Destructor virtual asegura que los objetos de las subclases se destruyan correctamente
    virtual ~Animal() {
        cout << "Animal destroyed" << endl;
    }
};

// Clase derivada Dog, hereda de Animal
class Dog : public Animal {
public:
    // Reescribe el método sound
    void sound() const override {
        cout << "Dog barks" << endl;
    }
   
    ~Dog() {
        cout << "Dog destroyed" << endl;
    }
};

// Clase derivada Cat, hereda de Animal
class Cat : public Animal {
public:
    // Reescribe el método sound
    void sound() const override {
        cout << "Cat meows" << endl;
    }
   
    ~Cat() {
        cout << "Cat destroyed" << endl;
    }
};

// Prueba del polimorfismo
int main() {
    Animal* animalPtr;  // Puntero de la clase base

    // Crea un objeto Dog y lo asigna al puntero Animal
    animalPtr = new Dog();
    animalPtr->sound();  // Llama al método sound de Dog
    delete animalPtr;    // Libera memoria, llama a los destructores de Dog y Animal

    // Crea un objeto Cat y lo asigna al puntero Animal
    animalPtr = new Cat();
    animalPtr->sound();  // Llama al método sound de Cat
    delete animalPtr;    // Libera memoria, llama a los destructores de Cat y Animal

    return 0;
}

La salida de la ejecución del programa es:

Dog barks
Dog destroyed
Animal destroyed
Cat meows
Cat destroyed
Animal destroyed

  • Función virtual: Al usar en la clase basevirtualla palabra clave para declarar la función virtual, la clase derivada puede reescribir esta función, logrando así que en tiempo de ejecución se llame a la función correcta según el tipo de objeto.

Al llamar a métodos de diferentes clases derivadas a través de un puntero de la clase base, se muestra la característica de enlace dinámico del polimorfismo.

Conceptos clave

  • Función virtual: En la clase baseShapese define la función virtualarea(). La función virtual permite que la clase derivada pueda sobrescribir esta función y, en tiempo de ejecución, llamar a la implementación adecuada según el tipo real del objeto al que apunta el puntero.

  • Enlace dinámico: Dado quearea()es una función virtual,shape->area()al llamarla, en tiempo de ejecución, segúnshapeel tipo real del objeto al que apunta (Rectangle 或 Triangle), se llama a la correspondientearea()implementación. Este mecanismo de decidir en tiempo de ejecución qué función llamar se denomina enlace dinámico, y es el núcleo del polimorfismo.

  • Polimorfismo del puntero de clase base: El puntero de clase baseshapepuede apuntar a cualquier objeto derivado deShape. Cuandoshapeapunta a diferentes objetos de clases derivadas, la llamada ashape->area()produce comportamientos diferentes, lo que refleja las características del polimorfismo.

    • Funciones virtuales

    Una función virtuales una función declarada en la clase base con la palabra clavevirtualvirtual.

    La función virtualpermite que la subclase la sobrescriba, de modo que en tiempo de ejecución, a través de un puntero o referencia de la clase base, se llame a la versión sobrescrita de la subclase, logrando así el enlace dinámico.

    Lo que queremos es que en cualquier punto del programa se pueda elegir la función a llamar según el tipo de objeto al que se llama. Esta operación se conoce comoenlace dinámico, oenlace tardío.

    Características:

    • En la clase base puede haber una implementación. Normalmente, la función virtual proporciona una implementación predeterminada en la clase base, pero la subclase puede optar por sobrescribirla.
    • Enlace dinámico: En tiempo de ejecución, se llama a la versión correspondiente de la función según el tipo real del objeto.
    • Sobrescritura opcional: La clase derivada puede sobrescribir la función virtual de forma opcional, pero no es obligatorio.

    Ejemplo

    #include <iostream>
    using namespace std;

    class Animal {
    public:
        virtual void sound() {  // Función virtual
            cout << "Animal makes a sound" << endl;
        }
    };

    class Dog : public Animal {
    public:
        void sound() override {  // Sobrescribir la función virtual
            cout << "Dog barks" << endl;
        }
    };

    int main() {
        Animal *animal = new Dog();
        animal->sound();  // Salida: Dog barks
        delete animal;
    }

    En el código anterior, sound es una función virtual de la clase Animal. Al llamar a sound() mediante el puntero Animal* animal, el programa elige llamar a Dog::sound() según el tipo real del objeto (Dog).

    Funciones virtuales puras

    Es posible que desee definir una función virtual en la clase base para redefinirla en la clase derivada y que se adapte mejor al objeto, pero si no puede dar una implementación significativa de la función virtual en la clase base, entonces se utiliza una función virtual pura.

    Una función virtual pura es una función virtual sin implementación, que se declara en la clase base con= 0para declararla.

    Una función virtual pura indica que la clase base define una interfaz, pero la implementación concreta corre a cargo de la clase derivada.

    Una función virtual pura convierte a la clase base en una clase abstracta (abstract class), que no se puede instanciar.

    Características:

    • Debe declararse en la clase base como= 0, lo que indica que no tiene implementación y la subclase debe sobrescribirla.
    • Clase abstracta: Una clase que contiene funciones virtuales puras no se puede instanciar directamente; solo se puede crear un objeto cuando la clase derivada implementa todas las funciones virtuales puras.
    • Definición de interfaz: Las funciones virtuales puras se utilizan generalmente para definir interfaces y permitir que las clases derivadas implementen comportamientos concretos.

    Podemos reescribir la función virtual area() de la clase base de la siguiente manera:

    #include <iostream> using namespace std; class Shape { public: virtual int area() = 0; // Función virtual pura, obliga a la subclase a implementar este método }; class Rectangle : public Shape { private: int width, height; public: Rectangle(int w, int h) : width(w), height(h) { } int area() override { // Implementación de la función virtual pura return width * height; } }; int main() { Shape *shape = new Rectangle(10, 5); cout << "Rectangle Area: " << shape->area() << endl; // Salida: Rectangle Area: 50 delete shape; }

    = 0Le dice al compilador que la función no tiene cuerpo; la función virtual anterior es unafunción virtual pura。

    Mecanismo de implementación del enlace dinámico: VTABLE

    El compilador crea una tabla de funciones virtuales VTABLE para cada clase que contiene funciones virtuales. Cada entrada de la tabla apunta a la dirección de una función virtual, es decir, la tabla VTABLE puede considerarse como un array de punteros a funciones; la dirección de entrada de cada función virtual es un elemento de ese array.

    Cada clase que contiene funciones virtuales tiene su propia tabla de funciones virtuales VTABLE. La VTABLE de cada clase derivada hereda las VTABLE de sus clases base. Si la VTABLE de la clase base contiene una determinada entrada (dirección de entrada de una función virtual), la VTABLE de la clase derivada también contendrá la misma entrada, pero los valores de las dos entradas pueden ser diferentes. Si la clase derivada sobrescribe la función virtual correspondiente a esa entrada, la entrada de la VTABLE de la clase derivada apuntará a la función virtual sobrescrita; si la clase derivada no redefine la función virtual correspondiente, se utiliza la dirección de la función virtual de la clase base.

    Al crear un objeto de una clase que contiene funciones virtuales, el compilador añade un puntero vptr a la distribución de memoria de cada objeto; este puntero apunta a la VTABLE de su clase. Al llamar a una función virtual a través de un puntero a un objeto de la clase base (supongamos bp), el código generado por el compilador primero obtiene el puntero vtb1 del objeto al que apunta y luego llama a la entrada correspondiente (dirección de entrada de la función virtual concreta) de la VTABLE de la clase a la que apunta vtb1.

    Cuando en la clase baseno se define una función virtual, su tamaño = tamaño de los miembros de datos; el tamaño de la clase derivada = tamaño de sus propios miembros de datos + tamaño de los miembros de datos heredados de la clase base;

    Cuando en la clase basese define una función virtual,, su longitud = longitud de los miembros de datos + longitud de la dirección de la tabla de funciones virtuales; la longitud de la clase derivada = longitud de sus propios miembros de datos + longitud de los miembros de datos heredados de la clase base + longitud de la dirección de la tabla de funciones virtuales.

    El incremento de longitud de una clase que contiene una o varias funciones virtuales es 0. Una clase con funciones virtuales solo añade un puntero para almacenar la dirección inicial de la tabla de funciones virtuales.

    Las funciones virtuales con el mismo nombre en la clase derivada y en la clase base tienen el mismo número de índice (o número de secuencia) en la VTABLE.

    Lo que se dice aquí sobre las funciones virtuales está un poco desordenado, porque la sintaxis de C++ tiene bastantes rarezas. En realidad se puede entender de forma sencilla.

    Una función virtual puede no implementarse (definirse). Una función virtual no implementada (definida) es una función virtual pura.

    Si en una clase existe una función virtual no definida, entonces no se puede usar directamente una instancia de esa clase. Se puede entender que, debido a que la función virtual no está definida, la clase es abstracta y no se puede instanciar. Se reportará un error:

    undefined reference to `vtable for xxx'

    Esto es similar a las clases abstractas y métodos abstractos de otros lenguajes: debemos implementar la clase abstracta, de lo contrario no se puede instanciar. (Virtual y abstract todavía tienen algunas diferencias.)

    Es decir, si existe el siguiente código:

    using namespace std;

class Base {
public:
    virtual void tall();
};

class People : Base {
public:
    void tall() {
        cout << "people" << endl;
    };
};

    Entonces, en el método main, no podemos usar la línea de código `Base base;`; en este momento `tall` no está implementado, la referencia a la tabla de funciones (vtable) no está definida, por lo que no se puede ejecutar. Pero podemos usar `People people;` y luegopeople.tall(); 或 (&people)->tall();Porque People implementa o, digamos, reescribe y sobrescribe el método virtual puro `tall()` de Base, de modo que ahora tiene definición en la clase People, la tabla de funciones se ha enlazado, y por lo tanto puede crearse una instancia.

    int main() {
//    Base base;//不可用

    People people;//可用
    people.tall();
    (&people)->tall();

    return 0;
}

    Lo anterior es con respecto a las funciones virtuales. Para las funciones normales, aunque solo las declaremos sin definirlas, no se producirá el problema de no poder usarlas como se mencionó.

    Las funciones virtuales o funciones virtuales puras de la clase padre siguen siendo funciones virtuales en la clase hija. A veces no queremos que una función de la clase padre sea reescrita en la clase hija; en C++11 y posteriores se puede usar la palabra clave `final` para evitar que esa función sea reescrita nuevamente.

    Ejemplo:

    #include<iostream>
using namespace std;
class Base
{
    public:
        virtual void func()
        {
            cout<<"This is Base"<<endl;
        }
};
class _Base:public Base
{
    public:
        void func() final//正确，func在Base中是虚函数
        {
            cout<<"This is _Base"<<endl;
        }
};
class __Base:public _Base
{
/*    public://不正确，func在_Base中已经不再是虚函数，不能再被重写
        void func()
        {
            cout<<"This is __Base"<<endl;
        }*/
};
int main()
{
    _Base a;
    __Base b;
    Base* ptr=&a;
    ptr->func();
    ptr=&b;
    _Base* ptr2=&b;    ptr->func();
    ptr2->func();
}

    Resultado de ejecución del programa anterior:

    This is _Base
This is _Base
This is _Base

    Si no se desea que una clase sea heredada, también se puede usar la palabra clave `final`.

    El formato es el siguiente:

    class Class_name final
{
    ...
};

    Entonces esa clase no podrá ser heredada.
