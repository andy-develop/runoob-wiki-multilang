Introducción a Redis

Redis (Remote Dictionary Server) es una base de datos en memoria de código abierto, bajo el protocolo BSD, que proporciona un sistema de almacenamiento de clave-valor de alto rendimiento, comúnmente utilizado en escenarios como caché, colas de mensajes, almacenamiento de sesiones, etc.

  • Rendimiento extremadamente alto:Redis es conocido por su extremadamente alto rendimiento, capaz de soportar cientos de miles de operaciones de lectura y escritura por segundo24. Esto convierte a Redis en la opción ideal para manejar solicitudes de alta concurrencia, especialmente en escenarios que requieren respuestas rápidas, como caché, gestión de sesiones, clasificaciones, etc.

  • Tipos de datos enriquecidos:Redis no solo admite almacenamiento básico de clave-valor, también proporciona tipos de datos enriquecidos, incluyendo cadenas, listas, conjuntos, tablas hash, conjuntos ordenados, etc. Estos tipos de datos brindan a los desarrolladores capacidades flexibles de manipulación de datos, permitiendo que Redis se adapte a diversos escenarios de aplicación.

  • Operaciones atómicas:Todas las operaciones de Redis son atómicas, lo que significa que una operación o se ejecuta completamente o no se ejecuta en absoluto. Esta característica es crucial para garantizar la consistencia e integridad de los datos, especialmente al manejar transacciones en entornos de alta concurrencia.

  • Persistencia:Redis admite la persistencia de datos, pudiendo guardar los datos en memoria en el disco para recuperarlos después de un reinicio del sistema. Esto proporciona seguridad a los datos de Redis, asegurando que no se pierdan por fallos del sistema.

  • Compatibilidad con el modelo publicar/suscribir:Redis incorpora el modo de publicación/suscripción (Pub/Sub), que permite la comunicación entre clientes mediante el paso de mensajes. Esto hace que Redis pueda funcionar como plataforma para colas de mensajes y transmisión de datos en tiempo real.

  • Modelo de un solo hilo:Aunque Redis es de un solo hilo, maneja solicitudes concurrentes mediante un eficiente modelo basado en eventos, garantizando alto rendimiento y baja latencia. El modelo de un solo hilo también simplifica la complejidad del control de concurrencia.

  • Replicación maestro-esclavo:Redis admite la replicación maestro-esclavo, que permite respaldar datos o distribuir solicitudes de lectura mediante nodos esclavos, mejorando la disponibilidad de los datos y la escalabilidad del sistema.

  • Amplia gama de escenarios de aplicación:Redis se utiliza ampliamente en varios escenarios, incluyendo, entre otros, sistemas de caché, almacenamiento de sesiones, clasificaciones, análisis en tiempo real, indexación de datos geoespaciales, etc.

  • Soporte de la comunidad:Redis cuenta con una activa comunidad de desarrolladores que proporciona abundante documentación, tutoriales y bibliotecas de terceros, brindando un sólido apoyo y ricos recursos a los desarrolladores.

  • Compatibilidad multiplataforma:Redis puede ejecutarse en múltiples sistemas operativos, incluyendo Linux, macOS y Windows, lo que permite desplegarlo de manera flexible en diferentes pilas tecnológicas.

¿En qué se diferencia Redis de otros almacenes de clave-valor?

La principal diferencia entre Redis y otros sistemas de almacenamiento de clave-valor radica en que ofrece tipos de datos enriquecidos, capacidades de lectura y escritura de alto rendimiento, operaciones atómicas, mecanismos de persistencia y un conjunto de características amplio.

A continuación se presentan algunas particularidades de Redis:

  • Tipos de datos enriquecidos:Redis no solo admite datos simples de tipo clave-valor, sino que también proporciona almacenamiento de estructuras de datos como listas, conjuntos, zsets (conjuntos ordenados), hash, etc. Estos tipos de datos pueden satisfacer mejor necesidades empresariales específicas, permitiendo que Redis se utilice en una gama más amplia de escenarios.

  • Capacidad de lectura y escritura de alto rendimiento:Redis puede alcanzar una velocidad de lectura de 110000 veces/s y una velocidad de escritura de 81000 veces/s. Este alto rendimiento se debe principalmente a que Redis almacena los datos en memoria, lo que mejora significativamente la velocidad de acceso a los datos.

  • Operaciones atómicas:Todas las operaciones de Redis son atómicas, lo que significa que una operación o se ejecuta completamente o no se ejecuta en absoluto. Esta característica es muy importante para garantizar la consistencia e integridad de los datos.

  • Mecanismo de persistencia:Redis admite la persistencia de datos, pudiendo guardar los datos en memoria en el disco para poder cargarlos nuevamente tras un reinicio del sistema. Esto proporciona seguridad a los datos de Redis, asegurando que no se pierdan por fallos del sistema.

  • Amplio conjunto de características:Redis también admite funciones avanzadas como el modo de publicación/suscripción (publish/subscribe), notificaciones, expiración de claves, etc. Estas características permiten que Redis se utilice en escenarios complejos como colas de mensajes, análisis de datos en tiempo real, etc.

  • Replicación maestro-esclavo y alta disponibilidad:Redis admite el modo de respaldo de datos maestro-esclavo, proporcionando funciones de respaldo de datos y replicación maestro-esclavo, lo que mejora la disponibilidad y tolerancia a fallos de los datos.

  • Soporte para scripts Lua:Redis admite el uso de scripts Lua para escribir operaciones complejas, que pueden ejecutarse en el lado del servidor, ofreciendo mayor flexibilidad y potentes funciones.

  • Modelo de un solo hilo:Aunque Redis es de un solo hilo, maneja solicitudes concurrentes mediante un eficiente modelo basado en eventos, garantizando alto rendimiento y baja latencia.

    ¿Qué es el protocolo BSD?

    El protocolo de código abierto BSD es un protocolo que otorga gran libertad a los usuarios. Se puede usar y modificar el código fuente libremente, e incluso redistribuir el código modificado como software de código abierto o propietario. Cuando publicas código que utiliza el protocolo BSD, o desarrollas tu propio producto basándote en código con protocolo BSD, debes cumplir tres condiciones:

    • Si el producto redistribuido incluye código fuente, el código fuente debe incluir el protocolo BSD del código original.
    • Si solo se redistribuye una biblioteca/software binario, la documentación y la declaración de derechos de autor de la biblioteca/software deben incluir el protocolo BSD del código original.
    • No se puede utilizar el nombre del autor/institución del código de código abierto ni el nombre del producto original para promoción de mercado.

    El código BSD fomenta el intercambio de código, pero debe respetar los derechos de autor del autor del código. Dado que BSD permite a los usuarios modificar y redistribuir el código, y también permite usar o desarrollar software comercial sobre el código BSD para publicar y vender, es un protocolo muy amigable para la integración comercial.

    Muchas empresas eligen el protocolo BSD como primera opción al seleccionar productos de código abierto, porque pueden controlar completamente el código de terceros y modificarlo o realizar un desarrollo derivado cuando sea necesario.

    ¿Qué es la atomicidad, qué es una operación atómica?

    Por ejemplo:

    A quiere transferir 1000 dólares de su cuenta a la cuenta de B. El proceso desde que A comienza la transferencia hasta que finaliza se denomina transacción. En esta transacción, se deben realizar las siguientes operaciones:

    • 1. Restar 1000 dólares de la cuenta de A. Si la cuenta de A tenía originalmente 3000 dólares, ahora serán 2000 dólares.
    • 2. Añadir 1000 dólares a la cuenta de B. Si la cuenta de B tenía originalmente 2000 dólares, ahora serán 3000 dólares.

    Si, cuando ya se han restado 1000 dólares de la cuenta de A, ocurre un imprevisto, como un corte de electricidad, que provoca la terminación accidental de la transacción, y en ese momento a la cuenta de B aún no se le han añadido los 1000 dólares, decimos que la operación ha fallado y se debe realizar una reversión (rollback). La reversión consiste en volver al estado anterior al inicio de la transacción, es decir, al estado en el que la cuenta de A aún no había perdido los 1000 dólares y la cuenta de B estaba en su estado original. En ese momento, la cuenta de A sigue teniendo 3000 dólares y la cuenta de B sigue teniendo 2000 dólares.

    Llamamos operación atómica a aquella en la que o todo tiene éxito (la cuenta de A reduce correctamente 1000 y al mismo tiempo la cuenta de B aumenta correctamente 1000), o todo falla (la cuenta de A vuelve a su estado original y la cuenta de B también vuelve a su estado original).

    Si una transacción puede considerarse como un programa, o se ejecuta completamente o no se ejecuta en absoluto. Esta característica se denomina atomicidad.
