Tipos de datos de Redis

Redis principalmente admite los siguientes tipos de datos:

  • string (cadena):Unidad básica de almacenamiento de datos, puede almacenar cadenas, enteros o números de punto flotante.
  • hash (hash):Un conjunto de pares clave-valor, puede almacenar múltiples campos.
  • list (lista):Una lista simple, puede almacenar una serie de elementos de cadena.
  • set (conjunto):Un conjunto desordenado, puede almacenar elementos de cadena no repetidos.
  • zset (sorted set: conjunto ordenado):Similar a un conjunto, pero cada elemento tiene una puntuación (score) asociada.
  • Bitmaps (mapas de bits):Basado en el tipo de cadena, puede operar sobre cada bit.
  • HyperLogLogs (hiperlogaritmos):Se utiliza para la estadística de cardinalidad, puede estimar el número de elementos únicos en un conjunto.
  • Geospatial (geoespacial):Se utiliza para almacenar información de ubicación geográfica.
  • Publicar/Suscribir (Pub/Sub):Un patrón de comunicación de mensajes que permite a los clientes suscribirse a canales de mensajes y recibir mensajes publicados en ese canal.
  • Streams (flujos):Se utiliza para colas de mensajes y almacenamiento de registros, admite persistencia de mensajes y ordenación por tiempo.
  • Modules (módulos):Redis admite la carga dinámica de módulos, lo que permite ampliar las funciones de Redis.

String (cadena)

string es el tipo más básico de Redis; puedes entenderlo como un tipo idéntico a Memcached, donde una clave (key) corresponde a un valor (value).

El tipo string es binario seguro. Esto significa que el string de Redis puede contener cualquier dato, como imágenes jpg u objetos serializados.

El tipo string es el tipo de datos más básico de Redis; el valor de tipo string puede almacenar hasta 512 MB.

Comandos comunes

  • SET key value: Establece el valor de la clave.
  • GET key: Obtiene el valor de la clave.
  • INCR key: Incrementa el valor de la clave en 1.
  • DECR key: Decrementa el valor de la clave en 1.
  • APPEND key value: Añade el valor al final del valor de la clave.

Ejemplo

redis 127.0.0.1:6379> SET runoob "菜鸟教程"
OK
redis 127.0.0.1:6379> GET runoob
"菜鸟教程"

En el ejemplo anterior usamos de Redis elSET 和 GETcomando. La clave es runoob, y el valor correspondiente esTutorial para novatos。

Nota:Una clave puede almacenar hasta 512 MB.

Hash (hash)

El hash de Redis es un conjunto de pares clave-valor (key=>value), similar a una pequeña base de datos NoSQL.

El hash de Redis es una tabla de mapeo de campos (field) y valores (value) de tipo string; el hash es especialmente adecuado para almacenar objetos.

Cada hash puede almacenar hasta 2^32 - 1 pares clave-valor.

    Comandos comunes

  • HSET key field value: Establece el valor del campo en la tabla hash.
  • HGET key field: Obtiene el valor del campo en la tabla hash.
  • HGETALL key: Obtiene todos los campos y valores de la tabla hash.
  • HDEL key field: Elimina uno o más campos de la tabla hash.

Ejemplo

DEL runoobSe utiliza para eliminar la clave utilizada anteriormente en las pruebas; de lo contrario, se producirá un error:(error) WRONGTYPE Operation against a key holding the wrong kind of value

redis 127.0.0.1:6379> DEL runoob
redis 127.0.0.1:6379> HMSET runoob field1 "Hello" field2 "World"
"OK"
redis 127.0.0.1:6379> HGET runoob field1
"Hello"
redis 127.0.0.1:6379> HGET runoob field2
"World"

En el ejemplo usamos RedisHMSET, HGETcomando,HMSETestablecimos dosfield=>valuepares, HGET obtiene el correspondientefieldcorrespondientevalue。

List (lista)

La lista de Redis es una lista simple de cadenas, ordenada según el orden de inserción. Puedes agregar un elemento al principio (izquierda) o al final (derecha) de la lista.

La lista puede almacenar hasta 2^32 - 1 elementos.

Comandos comunes

  • LPUSH key value: Inserta el valor en el encabezado de la lista.
  • RPUSH key value: Inserta el valor al final de la lista.
  • LPOP key: Elimina y obtiene el primer elemento de la lista.
  • RPOP key: Elimina y obtiene el último elemento de la lista.
  • LRANGE key start stop: Obtiene los elementos de la lista dentro del rango especificado.

Ejemplo

redis 127.0.0.1:6379> DEL runoob
redis 127.0.0.1:6379> lpush runoob redis
(integer) 1
redis 127.0.0.1:6379> lpush runoob mongodb
(integer) 2
redis 127.0.0.1:6379> lpush runoob rabbitmq
(integer) 3
redis 127.0.0.1:6379> lrange runoob 0 10
1) "rabbitmq"
2) "mongodb"
3) "redis"
redis 127.0.0.1:6379>

Set (conjunto)

El Set de Redis es un conjunto desordenado de tipo string.

El conjunto se implementa mediante una tabla hash, por lo que la complejidad de agregar, eliminar y buscar es O(1).

Comandos comunes

  • SADD key value: Agrega uno o más miembros al conjunto.
  • SREM key value: Elimina uno o más miembros del conjunto.
  • SMEMBERS key: Devuelve todos los miembros del conjunto.
  • SISMEMBER key value: Determina si el valor es un miembro del conjunto.

Comando sadd

Agrega un elemento string al conjunto set correspondiente a la clave; devuelve 1 si tiene éxito y 0 si el elemento ya está en el conjunto.

sadd key member

Ejemplo

redis 127.0.0.1:6379> DEL runoob
redis 127.0.0.1:6379> sadd runoob redis
(integer) 1
redis 127.0.0.1:6379> sadd runoob mongodb
(integer) 1
redis 127.0.0.1:6379> sadd runoob rabbitmq
(integer) 1
redis 127.0.0.1:6379> sadd runoob rabbitmq
(integer) 0
redis 127.0.0.1:6379> smembers runoob

1) "redis"
2) "rabbitmq"
3) "mongodb"

Nota:En el ejemplo anterior, rabbitmq se agregó dos veces, pero debido a la unicidad de los elementos en el conjunto, el segundo elemento insertado se ignorará.

El número máximo de miembros en el conjunto es 232- 1 (4294967295, cada conjunto puede almacenar más de 4 mil millones de miembros).

zset (sorted set: conjunto ordenado)

El zset de Redis, al igual que set, es un conjunto de elementos de tipo string y no permite miembros duplicados.

La diferencia es que cada elemento está asociado a una puntuación de tipo double. Redis ordena los miembros del conjunto de menor a mayor precisamente mediante la puntuación.

Los miembros del zset son únicos, pero las puntuaciones (score) pueden repetirse.

Comandos comunes

  • ZADD key score value: Agrega uno o más miembros al conjunto ordenado, o actualiza la puntuación de los miembros existentes.
  • ZRANGE key start stop [WITHSCORES]: Devuelve los miembros dentro del rango especificado.
  • ZREM key value: Elimina uno o más miembros del conjunto ordenado.
  • ZSCORE key value: Devuelve el valor de puntuación de los miembros en el conjunto ordenado.

Comando zadd

Agrega elementos al conjunto; si el elemento ya existe en el conjunto, actualiza su score correspondiente.

zadd key score member

Ejemplo

redis 127.0.0.1:6379> DEL runoob
redis 127.0.0.1:6379> zadd runoob 0 redis
(integer) 1
redis 127.0.0.1:6379> zadd runoob 0 mongodb
(integer) 1
redis 127.0.0.1:6379> zadd runoob 0 rabbitmq
(integer) 1
redis 127.0.0.1:6379> zadd runoob 0 rabbitmq
(integer) 0
redis 127.0.0.1:6379> ZRANGEBYSCORE runoob 0 1000
1) "mongodb"
2) "rabbitmq"
3) "redis"

    Nota: Redis admite múltiples bases de datos, y los datos de cada base de datos están aislados y no se pueden compartir. Además, esto solo existe en modo independiente (standalone); si es un clúster, no existe el concepto de bases de datos.

    Redis es un servidor de almacenamiento con estructura de diccionario. En realidad, una instancia de Redis proporciona múltiples diccionarios para almacenar datos, y el cliente puede especificar en qué diccionario almacenar los datos. Esto es similar a poder crear múltiples bases de datos en una instancia de base de datos relacional, por lo que cada diccionario puede entenderse como una base de datos independiente.

    Cada base de datos se nombra externamente con un número incremental que comienza desde 0. Redis admite 16 bases de datos por defecto (se pueden configurar más mediante el archivo de configuración, sin límite superior). Este número se puede modificar configurando "databases". Después de que el cliente establece una conexión con Redis, selecciona automáticamente la base de datos 0, pero se puede cambiar de base de datos en cualquier momento con el comando SELECT. Por ejemplo, para seleccionar la base de datos 1:

    redis> SELECT 1
OK
redis [1] > GET foo
(nil)

    Sin embargo, estas bases de datos nombradas con números se diferencian de lo que comúnmente entendemos como bases de datos. En primer lugar, Redis no admite personalizar el nombre de las bases de datos; cada base de datos se nombra con un número, y el desarrollador debe registrar por su cuenta qué datos se almacenan en cada base de datos. Además, Redis tampoco admite establecer diferentes contraseñas de acceso para cada base de datos, por lo que un cliente o bien puede acceder a todas las bases de datos, o bien no tiene permiso para acceder a ninguna. El punto más importante es que las múltiples bases de datos no están completamente aisladas entre sí; por ejemplo, el comando FLUSHALL puede vaciar los datos de todas las bases de datos de una instancia de Redis. En resumen, estas bases de datos se asemejan más a un espacio de nombres (namespace) y no son adecuadas para almacenar datos de diferentes aplicaciones. Por ejemplo, se puede usar la base de datos 0 para almacenar los datos del entorno de producción de una aplicación y la base de datos 1 para almacenar los datos del entorno de pruebas, pero no es adecuado usar la base de datos 0 para los datos de la aplicación A y la base de datos 1 para los datos de la aplicación B. Diferentes aplicaciones deberían usar diferentes instancias de Redis para almacenar datos. Dado que Redis es muy ligero, una instancia vacía de Redis ocupa solo alrededor de 1 MB de memoria, por lo que no hay que preocuparse de que múltiples instancias de Redis ocupen mucha memoria adicional.
