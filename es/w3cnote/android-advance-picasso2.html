Orden de solicitudes de imágenes

Prioridad: HIGH, MEDIUM, LOW

Supongamos un escenario en el que la carga de imágenes necesita mostrarse por prioridad; en ese caso se usarápriority()Este método requiere uno de los tres parámetros:HIGH,MEDIUM,LOW, por defecto, todas las solicitudes son MEDIUM.

//HIGH
Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .fit()
    .priority(Picasso.Priority.HIGH)
    .into(imageViewHero);

//LOW
Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[2])
    .fit()
    .priority(Picasso.Priority.LOW)
    .into(imageViewLowPrioRight);

注: usarpriority()No garantiza al 100% el orden de visualización de las imágenes, solo es la prioridad de la solicitud.

tag() Agrupar solicitudes

Ya conoce la prioridad de las solicitudes de imágenes, pero quizás no sea suficiente. Supongamos que necesitamos cancelar, pausar y reanudar varias solicitudes de imágenes al mismo tiempo; para esto se usarátag()

tag()Puede usar cualquier objeto de Java como parámetro, porque con base en estos podemos construir grupos de imágenes. El grupo de imágenes tiene las siguientes opciones:

  • Pausar solicitudes pauseTag()
  • Reanudar solicitudes resumeTag()
  • Cancelar solicitudes cancelTag()

Quizás todavía no entienda qué es esto exactamente; veamos un pequeño ejemplo.

Ejemplo: pauseTag() y resumeTag()

Supongamos que tenemos una aplicación de correo, cuyo contenido se muestra principalmenteListViewusando.

Ahora, imaginemos una situación: el usuario busca cierta información y luego se desplaza rápidamente. ListView normalmente recicla y reutiliza rápidamente cada contenedor; sin embargo, Picasso intentará hacer una solicitud para cada elemento y luego la cancelará inmediatamente, porque el usuario se desplaza rápidamente.

Para reducir más solicitudes, podemos esperar a que ListView termine de desplazarse para cargar las imágenes; el usuario no notará ninguna diferencia, pero así se habrá reducido la cantidad de solicitudes.

La implementación es muy fácil. Primero, agregue una etiqueta a su solicitud de Picasso.

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .tag("Profile ListView") // can be any Java object
    .into(imageViewWithTag);

//接着，实现一个  `AbsListView.OnScrollListener` 和重写  `onScrollStateChanged()`

@Override
public void onScrollStateChanged(AbsListView view, int scrollState) {
final Picasso picasso = Picasso.with(context);

if (scrollState == SCROLL_STATE_IDLE || scrollState == SCROLL_STATE_TOUCH_SCROLL) {
      picasso.resumeTag(context);
} else {
      picasso.pauseTag(context);
}
}

//最后一步
listView.setOnScrollListener(onScrollListener);

Cuando ListView está en un estado de desplazamiento muy rápido, pausa todas las solicitudes; cuando el desplazamiento es normal o se detiene, reanuda las solicitudes.

Código de ejemplo del sitio oficial

Nota: este artículo usa principalmente String como tag; quizás quiera usar un objeto diferente, quizás piense enContext or Activity, Fragment, pero la documentación oficial advierteSi el usuario abandonaActivity, el recolector de basura podría no poder destruir el objeto Activity debido a Picasso, y se produciría una fuga de memoria.

Callbacks, RemoteView y Notifications

Diferencias entre fetch(), get() y Target

fetch()： fetch()Cargará la imagen de forma asíncrona en un subproceso en segundo plano, pero no la mostrará enImageViewni devolverá un Bitmap; este método solo la guardará en la caché de disco y de memoria. Se puede usar para cargar la imagen actual más adelante.

get()： get()Carga la imagen de forma síncrona y devuelve unBitmapobjeto.Targets：La opción into, además de pasar un objeto ImageView, también puede pasar un Target, que es un callback.

Usar Target como mecanismo de callback

Hasta ahora,.into()siempre hemos estado pasando un objeto ImageView; por supuesto, este método también tiene sobrecargas. Veamos directamente un ejemplo y quizás lo entienda de inmediato.

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .into(target);

//下面是重点
private Target target = new Target() {  
    @Override
    public void onBitmapLoaded(Bitmap bitmap, Picasso.LoadedFrom from){
        // 图片加载成功
    }
    @Override
    public void onBitmapFailed(Drawable errorDrawable) {
        // 图片加载失败
    }
    @Override
    public void onPrepareLoad(Drawable placeHolderDrawable) {
        //图片加载中
    }
};

Nota:Aquí no se recomienda usar clases anónimas; el mecanismo de recolección de basura podría recolectar su objetivo y no obtendrá el Bitmap

Rotación y transformación de imágenes

Además de rotar por defecto alrededor del centro, a veces podemos necesitar rotar alrededor de otros ejes; podemos llamar arotate(float degrees, float pivotX, float pivotY)。

Transformación

La rotación es solo una pequeña parte de las técnicas de procesamiento de imágenes; Picasso también proporcionaTransformationpara el procesamiento de imágenes. Solo necesita implementarTransformationun método principal de la interfaztransform(android.graphics.Bitmap source), este método recibe un Bitmap y devuelve el transformado. Después de implementar esta interfaz, solo necesita llamar en Picassotransform(Transformation transformation)para completar la transformación de la imagen. Después de tanto hablar, veamos dos ejemplos.

Desenfoque de imagen

Primero, necesitamos implementarTransformationla interfaz, mediante el uso deRenderScript. Pero este artículo no tiene la intención de presentarRenderScript, pero debemos entender que se puede usar para desenfocar imágenes.

public class BlurTransformation implements Transformation {

    RenderScript rs;

    public BlurTransformation(Context context) {
        super();
        rs = Renderscript.create(context);
    }

    @Override
    public Bitmap transform(Bitmap bitmap) {
        // 创建一个位图，
        Bitmap blurredBitmap = bitmap.copy(Bitmap.Config.ARGB_8888, true);

        // 分配内存
        Allocation input = Allocation.createFromBitmap(rs, blurredBitmap, Allocation.MipmapControl.MIPMAP_FULL, Allocation.USAGE_SHARED);
        Allocation output = Allocation.createTyped(rs, input.getType());

        // 加载一个特定的脚本
        ScriptIntrinsicBlur script = ScriptIntrinsicBlur.create(rs, Element.U8_4(rs));
        script.setInput(input);

        // 设置模糊半径
        script.setRadius(10);

        // 启动ScriptIntrinisicBlur
        script.forEach(output);

        // 输出
        output.copyTo(blurredBitmap);

        bitmap.recycle();
        return blurredBitmap;
    }

    @Override
    public String key() {
        return "blur";
    }
}

Una vez completada la definición, la llamada en Picasso será muy sencilla.

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .transform(new BlurTransformation(context))
    .into(imageViewTransformationBlur);

Desenfoque y escala de grisesNo solo eso, eltransformmétodo de Picasso también proporcionatransform(List<? extends Transformation> transformations), lo que significa que podemos aplicar una serie de transformaciones a la imagen. Aquí, implementaremos además una escala de grises.

public class GrayscaleTransformation implements Transformation {

    private final Picasso picasso;

    public GrayscaleTransformation(Picasso picasso) {
        this.picasso = picasso;
    }

    @Override
    public Bitmap transform(Bitmap source) {
        Bitmap result = createBitmap(source.getWidth(), source.getHeight(), source.getConfig());
        Bitmap noise;
        try {
            noise = picasso.load(R.drawable.noise).get();
        } catch (IOException e) {
            throw new RuntimeException("Failed to apply transformation! Missing resource.");
        }

        BitmapShader shader = new BitmapShader(noise, REPEAT, REPEAT);

        ColorMatrix colorMatrix = new ColorMatrix();
        colorMatrix.setSaturation(0);
        ColorMatrixColorFilter filter = new ColorMatrixColorFilter(colorMatrix);

        Paint paint = new Paint(ANTI_ALIAS_FLAG);
        paint.setColorFilter(filter);

        Canvas canvas = new Canvas(result);
        canvas.drawBitmap(source, 0, 0, paint);

        paint.setColorFilter(null);
        paint.setShader(shader);
        paint.setXfermode(new PorterDuffXfermode(PorterDuff.Mode.MULTIPLY));

        canvas.drawRect(0, 0, canvas.getWidth(), canvas.getHeight(), paint);

        source.recycle();
        noise.recycle();

        return result;
    }

    @Override
    public String key() {
        return "grayscaleTransformation()";
    }
}

Después de completarlo, volvemos a la referencia en Picasso; esta vez solo necesitamos crear una colección List.

List<Transformation> transformations = new ArrayList<>();

transformations.add(new GrayscaleTransformation(Picasso.with(context)));  
transformations.add(new BlurTransformation(context));

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .transform(transformations)
    .into(imageViewTransformationsMultiple);

Caché de imágenes

Configuración de caché predeterminada de Picasso.

Caché de memoria LRU: 15% de la RAM disponible Caché de disco: 2% del espacio de almacenamiento, hasta 50mb, pero no menos de 5mb Tres subprocesos de descarga para acceso a disco y red

Podemos cambiar el tamaño de la caché, pero eso está fuera del alcance de este blog. Volviendo al tema de la caché de imágenes, Picasso primero intenta cargar la imagen desde la caché de memoria; si no está, busca en la caché de disco; si tampoco está en el disco, inicia una solicitud de red (memoria -> disco -> solicitud de red). Además, todas las imágenes solicitadas se almacenan en ambas cachés (hasta que deben eliminarse para liberar espacio). Si cree que esta estrategia de caché no es suficiente para usted, podemos verMemoryPolicy

Estrategia de memoria

Primero, Picasso obtiene la imagen solicitada preferentemente de la memoria; si desea omitir este paso, puede usarmemoryPolicy(MemoryPolicy policy, MemoryPolicy... additional)。 MemoryPolicyes una enumeración simple con dos valoresNO_CACHE和NO_STORE。

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[1])
    .memoryPolicy(MemoryPolicy.NO_CACHE)
    .into(imageViewFromDisk);

Si quiere saber para qué se usa NO_STORE: es para que la imagen solicitada no se almacene en caché en la memoria. Veamos el siguiente ejemplo.

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[1])
    .memoryPolicy(MemoryPolicy.NO_CACHE, MemoryPolicy.NO_STORE)
    .into(imageViewFromDisk);

Esto hace que la imagen solicitada no se almacene en caché en memoria y que Picasso tampoco la busque en memoria. La ventaja es que acelera la recuperación de memoria, porque la API existente no puede limpiar la caché de memoria.

Estrategia de red

Si desea omitir la caché de disco, puede llamar a.networkPolicy(NetworkPolicy policy, NetworkPolicy... additional) 与 NetworkPolicy.NO_CACHEcomo parámetro.

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[2])
    .networkPolicy(NetworkPolicy.NO_CACHE)
    .into(imageViewFromNetwork);

Finalmente, también se proporciona una tercera opciónNetworkPolicy：OFFLINE. Si se usa esto como parámetro, Picasso solo buscará la imagen en la caché y no enviará una solicitud incluso si hay red.

Indicador de caché

Personalizar Picasso usando Picasso.Builder

Picasso tiene métodos directos para modificar la instancia de Picasso.Picasso.Builder类Se puede usar esto para personalizar Picasso.

Personalización local de Picasso

Antes de entrar en la personalización de Picasso, necesitamos repasar brevemente cómo obtener una instancia estándar de Picasso.

Picasso picasso = Picasso.with(Context);

Este método devuelve el Picasso estándar. Si necesitas crear una instancia personalizada, una forma es crearPicasso.Builderel objeto para hacer ajustes.

// 创建 Picasso.Builder 对象
Picasso.Builder picassoBuilder = new Picasso.Builder(context);
// TODO
Picasso picasso = picassoBuilder.build()

A continuación, podemos usar el Picasso personalizado para cargar imágenes.

picasso  
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .into(imageView1)

Usar Picasso personalizado globalmente

La forma de crear y modificar instancias de Picasso se mantiene igual.

// 创建 Picasso.Builder 对象
Picasso.Builder picassoBuilder = new Picasso.Builder(context);

//TODO
Picasso picasso = picassoBuilder.build();

Para hacer que este Picasso sea global, solo tenemos que llamar aPicasso.setSingletonInstance(picasso);Normalmente, esto debería inicializarse al iniciar la aplicación.

try {  
    Picasso.setSingletonInstance(picasso);
} catch (IllegalStateException ignored) {
}

Una vez que hayas personalizado el Picasso global, todas lasPicasso.with(Context context)llamadas devolverán el Picasso personalizado.

Aunque hemos aprendido a personalizar Picasso, todavía no entendemos qué se puede hacer con un Picasso personalizado.

Personalizar Picasso: cambiar el descargador

Picasso usa por defecto los mejores componentes de caché y red disponibles. Si quieres cambiar el descargador predeterminado, puedesPicasso.Builderllamar adownloader(Downloader downloader), por ejemplo, nuestro OkHttp.

Picasso.Builder picassoBuilder = new Picasso.Builder(context);

//更改下载器。
picassoBuilder.downloader(new OkHttpDownloader(new OkHttpClient()));

Picasso picasso = picassoBuilder.build();

Pero hay un punto a tener en cuenta: si las imágenes que cargas provienen de tu propio servidor, y el servidor usa HTTPS, y además requiere una firma, en ese caso OkHttp no podrá cargar las imágenes debido a problemas de SSL. En ese momento puedes optar por usar UnsafeOkHttpClient para evitar ese problema.

picassoBuilder.downloader(  
    new OkHttpDownloader(
        UnsafeOkHttpClient.getUnsafeOkHttpClient()
    )
);

Manejo personalizado de solicitudes

Seguimos con la personalización de Picasso; primero veamos un fragmento de código.

Picasso.Builder picassoBuilder = new Picasso.Builder(context);

picassoBuilder.addRequestHandler(new EatFoodyRequestHandler());

Picasso picasso = picassoBuilder.build();

Lo único que puede resultar confuso esEatFoodyRequestHandler, que es una clase que extendemosRequestHandlerde tipo personalizado (procesamiento de solicitudes); así que veamos qué esRequestHandler。

Implementación de RequestHandler

Esta es una clase abstracta que tiene dos métodos que deben implementarse.

boolean canHandleRequest(Request data) Result load(Request request, int networkPolicy)

El primer método le permite a Picasso saber si este manejador de solicitudes puede manejar la solicitud actual; si es así, la solicitud se pasará aload()el método.

Veamos cómo se implementa esta clase en su totalidad.

public class EatFoodyRequestHandler extends RequestHandler {  
    private static final String EAT_FOODY_RECIPE_SCHEME = "eatfoody";
    @Override
    public boolean canHandleRequest(Request data) {
        return EAT_FOODY_RECIPE_SCHEME.equals(data.uri.getScheme());
    }

    @Override
    public Result load(Request request, int networkPolicy) throws IOException {
        //获取请求的host
       String imageKey = request.uri.getHost(); 
       Bitmap bitmap;
       if (imageKey.contentEquals("cupcake")) {
           bitmap = BitmapFactory.decodeResource(getResources(), R.drawable.cupcake);
       }else if (imageKey.contentEquals("full_cake")) {
           bitmap = BitmapFactory.decodeResource(getResources(), R.drawable.full_cake);
       }else {
           bitmap = BitmapFactory.decodeResource(getResources(), R.mipmap.ic_launcher);
       }
       return new Result(bitmap, Picasso.LoadedFrom.DISK);
    }
}

El código no parece difícil de entender; primerocanHandleRequesten el método se comprueba si el protocolo de la uri es igual aeatfoodySi no es así, Picasso vuelve al flujo de descarga estándar. Si es así, entonces entrará enloadel método. Dentro delloadmétodo, juzgamos lahostparte de la uri; luego, según el resultado, devolvemos el bitmap correspondiente.

//这会按照标准的流程加载图片
picasso  
    .load("http://i.imgur.com/DvpvklR.png")
    .into(imageView1);

//他会进入 load 方法中的逻辑判断去加载 `R.drawable.full_cake`
picasso  
    .load("eatfoody://cupcake")
    .into(imageView2)
