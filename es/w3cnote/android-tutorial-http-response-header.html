7.1.2 Aprendizaje de los encabezados de solicitud y respuesta HTTP en Android

Categoría Tutorial básico de introducción a Android

Introducción a esta sección:

En la sección anterior conocimos la programación de red en Android y también aprendimos los conceptos básicos de HTTP. En esta sección vamos a estudiar los encabezados de solicitud y respuesta de HTTP. Por supuesto, también podemos considerar esta sección como documentación, ¡solo hay que consultarla cuando sea necesario!

1. Encabezados de mensaje de las solicitudes HTTP:

Aquí mostramos la imagen dada en la sección anterior. Según la tabla que se da a continuación, ¡cada uno puede apreciar por sí mismo las funciones de los encabezados de solicitud relacionados! PD: La primera línea es la línea de solicitud: método de solicitud + nombre del recurso + número de versión del protocolo HTTP. Además, el encabezado de solicitud es solo información para el servidor o algo simple; en cuanto a cómo procesarlo, ¡lo decide el servidor!

Tabla comparativa de información de los encabezados de solicitud HTTP Request Header:

Header Explicación Ejemplo
Accept Especifica el tipo de contenido que el cliente puede recibir. Accept: text/plain, text/html
Accept-Charset Conjunto de codificación de caracteres que el navegador puede aceptar. Accept-Charset: iso-8859-5
Accept-Encoding Especifica el tipo de codificación de compresión del contenido devuelto por el servidor web que el navegador puede admitir. Accept-Encoding: compress, gzip
Accept-Language Idiomas que el navegador puede aceptar. Accept-Language: en,zh
Accept-Ranges Puede solicitar uno o más campos de subrango de la entidad de la página web. Accept-Ranges: bytes
Authorization Certificado de autorización para la autorización HTTP. Authorization: Basic QWxhZGRpbjpvcGVuIHNlc2FtZQ==
Cache-Control Especifica el mecanismo de caché que siguen la solicitud y la respuesta. Cache-Control: no-cache
Connection Indica si se necesita una conexión persistente. (HTTP 1.1 usa conexión persistente por defecto). Connection: close
Cookie Cuando se envía una solicitud HTTP, todos los valores de cookie guardados bajo el dominio de la solicitud se envían junto con la solicitud al servidor web. Cookie: $Version=1; Skin=new;
Content-Length Longitud del contenido de la solicitud. Content-Length: 348
Content-Type Información MIME de la solicitud correspondiente a la entidad. Content-Type: application/x-www-form-urlencoded
Date Fecha y hora de envío de la solicitud. Date: Tue, 15 Nov 2010 08:12:31 GMT
Expect Comportamiento específico del servidor solicitado. Expect: 100-continue
From Correo electrónico del usuario que realiza la solicitud. From: user@email.com
Host Especifica el nombre de dominio y el número de puerto del servidor solicitado. Host: www.zcmhi.com
If-Match Solo es válido si el contenido de la solicitud coincide con la entidad. If-Match: "737060cd8c284d8af7ad3082f209582d"
If-Modified-Since Si la parte solicitada se modifica después de la hora especificada, la solicitud tiene éxito; si no se modifica, devuelve el código 304. If-Modified-Since: Sat, 29 Oct 2010 19:43:31 GMT
If-None-Match Si el contenido no ha cambiado, devuelve el código 304. El parámetro es el Etag enviado anteriormente por el servidor; se compara con el Etag de la respuesta del servidor para determinar si ha cambiado. If-None-Match: "737060cd8c284d8af7ad3082f209582d"
If-Range Si la entidad no ha cambiado, el servidor envía al cliente la parte que faltaba; de lo contrario, envía la entidad completa. El parámetro también es Etag. If-Range: "737060cd8c284d8af7ad3082f209582d"
If-Unmodified-Since La solicitud solo tiene éxito si la entidad no ha sido modificada después de la hora especificada. If-Unmodified-Since: Sat, 29 Oct 2010 19:43:31 GMT
Max-Forwards Limita el tiempo en que la información se transmite a través de proxies y pasarelas. Max-Forwards: 10
Pragma Se usa para incluir instrucciones específicas de la implementación. Pragma: no-cache
Proxy-Authorization Certificado de autorización para conectarse al proxy. Proxy-Authorization: Basic QWxhZGRpbjpvcGVuIHNlc2FtZQ==
Range Solicita solo una parte de la entidad, especificando un rango. Range: bytes=500-999
Referer Dirección de la página web anterior, seguida por la página web actualmente solicitada, es decir, la página de origen. Referer: http://blog.csdn.net/coder_pig
TE Codificación de transferencia que el cliente está dispuesto a aceptar, y notifica al servidor que acepte los encabezados finales (trailing headers). TE: trailers,deflate;q=0.5
Upgrade Especifica al servidor un determinado protocolo de transferencia para que el servidor realice la conversión (si lo admite). Upgrade: HTTP/2.0, SHTTP/1.3, IRC/6.9, RTA/x11
User-Agent El contenido de User-Agent incluye la información del usuario que realiza la solicitud. User-Agent: Mozilla/5.0 (Linux; X11)
Via Notifica la dirección de la puerta de enlace intermedia o del servidor proxy, y el protocolo de comunicación. Via: 1.0 fred, 1.1 nowhere.com (Apache/1.1)
Warning Información de advertencia sobre la entidad del mensaje. Warn: 199 Miscellaneous warning

2. Encabezados de respuesta HTTP:

También mostramos la imagen de la sección anterior: PD: La primera línea es, en orden: número de versión del protocolo, código de estado. 302 significa que aquí no está, pero está en otro lugar; la página se ha redirigido mediante Location.

Tabla comparativa de información de los encabezados de respuesta HTTP Responses Header:

Header Explicación Ejemplo
Accept-Ranges Indica si el servidor admite solicitudes de rango especificado y qué tipo de solicitudes por segmentos. Accept-Ranges: bytes
Age Tiempo estimado desde el servidor original hasta el caché del proxy (en segundos, no negativo). Age: 12
Allow Comportamiento de solicitud válido para un recurso de red; si no está permitido, devuelve 405. Allow: GET, HEAD
Cache-Control Indica a todos los mecanismos de caché si pueden almacenar en caché y qué tipo. Cache-Control: no-cache
Content-Encoding Tipos de codificación de compresión del contenido devuelto que admite el servidor web. Content-Encoding: gzip
Content-Language Idioma del cuerpo de la respuesta. Content-Language: en,zh
Content-Length Longitud del cuerpo de la respuesta. Content-Length: 348
Content-Location Dirección alternativa que puede sustituir al recurso solicitado. Content-Location: /index.htm
Content-MD5 Valor de verificación MD5 del recurso devuelto. Content-MD5: Q2hlY2sgSW50ZWdyaXR5IQ==
Content-Range Posición en bytes de esta parte dentro del cuerpo de respuesta completo. Content-Range: bytes 21010-47021/47022
Content-Type Tipo MIME del contenido devuelto. Content-Type: text/html; charset=utf-8
Date Hora en que el servidor original emitió el mensaje. Date: Tue, 15 Nov 2010 08:12:31 GMT
ETag Valor actual de la etiqueta de entidad de la variable solicitada. ETag: "737060cd8c284d8af7ad3082f209582d"
Expires Fecha y hora en que la respuesta caduca. Expires: Thu, 01 Dec 2010 16:00:00 GMT
Last-Modified Hora de la última modificación del recurso solicitado. Last-Modified: Tue, 15 Nov 2010 12:45:26 GMT

Pragma Incluye instrucciones específicas de la implementación que pueden aplicarse a cualquier destinatario en la cadena de respuesta. Pragma: no-cache
Proxy-Authenticate Señala el esquema de autenticación y los parámetros que se pueden aplicar a la URL del proxy. Proxy-Authenticate: Basic

3. Verificación con código de la función de los encabezados de respuesta:

Bien, después de ver tantos conceptos, ¿cómo no vamos a poner manos a la obra? ¿Verdad? Entonces escribamos algunos códigos sencillos para verificar las funciones de algunos encabezados de respuesta comunes, con el fin de profundizar nuestro entendimiento. Aquí, en el lado del servidor usaremos el Servlet más simple para implementarlo. Si no conoces Java Web, solo tienes que copiar el código, configurar web.xml y poner el nombre de la clase del Servlet, por ejemplo:

<servlet>
    <servlet-name>FirstServlet</servlet-name>
    <servlet-class>com.jay.server.FirstServlet</servlet-class>
</servlet>
<servlet-mapping>
    <servlet-name>FirstServlet</servlet-name>
    <url-pattern>/FirstServlet</url-pattern>
</servlet-mapping>

¡Solo cámbialo al nombre de clase correspondiente!

1) Redirección de página mediante Location

Código de implementación：

package com.jay.http.test;

import java.io.IOException;
import javax.servlet.ServletException;
import javax.servlet.http.HttpServlet;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;

public class ServletOne extends HttpServlet {
    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {
        //告诉浏览器响应码，以及重定向页面
        resp.setStatus(302);
        resp.setHeader("Location", "http://www.baidu.com");
    }
    @Override
    protected void doPost(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {
        this.doGet(req, resp);
    }
}

2) Indicar al navegador el formato de compresión de los datos mediante Content-Encoding

Código de implementación:

package com.jay.http.test;

import java.io.ByteArrayOutputStream;
import java.io.IOException;
import java.util.zip.GZIPOutputStream;
import javax.servlet.ServletException;
import javax.servlet.http.HttpServlet;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;

public class ServletTwo extends HttpServlet {
    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {
        String data = "Fresh air and sunshine can have an amazing effect on our feelings. "
                + "Sometimes when we are feeling down, all that we need to do is simply to go "
                + "outside and breathe. Movement and exercise is also a fantastic way to feel better. "
                + "Positive emotions can be generated by motion. So if we start to feel down,"
                + " take some deep breathes, go outside, feel the fresh air, "
                + "let the sun hit our face, go for a hike, a walk, a bike ride, "
                + "a swim, a run, whatever. We will feel better if we do this.";
        System.out.println("原始数据长度:" + data.getBytes().length);
        // 对数据进行压缩:
        ByteArrayOutputStream bout = new ByteArrayOutputStream();
        GZIPOutputStream gout = new GZIPOutputStream(bout);
        gout.write(data.getBytes());
        gout.close();
        // 得到压缩后的数据
        byte gdata[] = bout.toByteArray();
        resp.setHeader("Content-Encoding", "gzip");
        resp.setHeader("Content-Length", gdata.length + "");
        resp.getOutputStream().write(gdata);

    }
    protected void doPost(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {
        doGet(req, resp);
    };
}

3) Establecer el tipo de datos devueltos mediante content-type

Lo que devuelve el servidor a veces puede ser un text/html, a veces un image/jpeg, o también un video video/avi. El navegador puede mostrar los datos de diferentes maneras según el tipo de datos correspondiente. Bien, aquí haremos un ejemplo de lectura de PDF.

Código de implementación： 

package com.jay.http.test;

import java.io.IOException;
import java.io.InputStream;
import java.io.OutputStream;

import javax.servlet.ServletException;
import javax.servlet.http.HttpServlet;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;

public class ServletThree extends HttpServlet {
    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {
        resp.setHeader("content-type", "application/pdf");
        InputStream in = this.getServletContext().getResourceAsStream("/file/android编码规范.pdf");
        byte buffer[] = new byte[1024];
        int len = 0;
        OutputStream out = resp.getOutputStream();
        while((len = in.read(buffer)) > 0)
        {
            out.write(buffer,0,len);
        }
    }
    
    protected void doPost(HttpServletRequest req, HttpServletResponse resp) throws
       ServletException ,IOException 
    {
        doGet(req, resp);
    };
}

Resultado de ejecución:

Introduce en el navegador: http://localhost:8080/HttpTest/ServletThree

¡Bien! Efectivamente se puede leer el PDF. Por cierto, ya coloqué este PDF en el directorio file de webroot; de lo contrario, lanzaría una excepción de puntero nulo ~:

Por supuesto, también puedes intentar reproducir una pieza de música o video, solo necesitas modificar el parámetro content-type.

4) Usar el encabezado de respuesta refresh para que el navegador salte a otra página después de unos segundos

Sí, generalmente podemos tener esta necesidad, por ejemplo, refrescar una página cada pocos segundos, o después de cargar una página durante unos segundos saltar a otra página. Entonces refresh puede satisfacer tu necesidad ~

Código de implementación:

package com.jay.http.test;

import java.io.IOException;

import javax.servlet.ServletException;
import javax.servlet.http.HttpServlet;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;

public class ServletFour extends HttpServlet {
    public int second = 0;
    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {
        //1.浏览器每隔2秒定时刷新页面
//        resp.setHeader("refresh", "2");
//        resp.getWriter().write(++second + "");
//        System.out.println("doGet方法被调用~");
        
        //2.进入页面5s后，然页跳到百度~
        resp.setHeader("refresh", "5;url='http://www.baidu.com'");
        resp.getWriter().write("HE HE DA~");
    }
    
    protected void doPost(HttpServletRequest req, HttpServletResponse resp) throws ServletException ,IOException 
    {
        doGet(req, resp);
    };
}

Resultado de ejecución：

  • En el caso 1, la página se refresca cada 2 segundos; podemos ver que el número mostrado va aumentando. Además, el método doGet se sigue llamando, lo que demuestra que la página realmente se está refrescando.
  • En el caso 2, después de entrar a la página, en 5 segundos salta automáticamente a Baidu ~

5) Usar el encabezado de respuesta content-disposition para que el navegador descargue archivos

Esto es muy sencillo. Solo tenemos que quitar la línea que establece Content-type en el punto ③ y luego añadir: resp.setHeader("content-disposition", "attachment;filename=Android.pdf");

Código de implementación： 

package com.jay.http.test;

import java.io.IOException;
import java.io.InputStream;
import java.io.OutputStream;

import javax.servlet.ServletException;
import javax.servlet.http.HttpServlet;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;

public class ServletFive extends HttpServlet {
    
    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {
        resp.setHeader("content-disposition", "attachment;filename=Android.pdf");
        InputStream in = this.getServletContext().getResourceAsStream("/file/android编码规范.pdf");
        byte buffer[] = new byte[1024];
        int len = 0;
        OutputStream out = resp.getOutputStream();
        while((len = in.read(buffer)) > 0)
        {
            out.write(buffer,0,len);
        }
    }
    
    @Override
    protected void doPost(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {
        doGet(req, resp);
    }
}
