Versión real:

1. Los desarrolladores crean el programa, convencidos de que no tiene defectos.

2. Pruebas del producto. Se encuentran 20 defectos.

3. Los desarrolladores corrigen 10 de ellos y explican al departamento de pruebas que los otros 10 no son defectos reales.

4. Los testers descubren que 5 de los defectos corregidos aún tienen problemas, y además encuentran 15 defectos nuevos.

5. Los pasos 3 y 4 se repiten 3 veces.

6. Debido a la presión del mercado y a las apresuradas declaraciones del producto generadas por un plan de desarrollo demasiado optimista, el producto se lanza oficialmente.

7. Los usuarios encuentran 137 defectos nuevos.

8. Los desarrolladores originales, después de cobrar sus cheques de lealtad, desaparecen sin dejar rastro.

9. El nuevo equipo de desarrollo convocado corrige la mayoría de los 137 defectos, pero provoca 456 nuevos defectos.

10. Los desarrolladores originales envían una postal desde las Islas Fiyi al departamento de pruebas, al que se le deben salarios. Todo el departamento de pruebas renuncia.

11. La empresa, con las ganancias del producto recientemente lanzado con 783 defectos, compra acciones y rechaza la adquisición hostil de un competidor.

12. La junta directiva trae a un nuevo CEO. Él contrata nuevos desarrolladores para rehacer el producto.

13. Los desarrolladores crean el programa, convencidos de que no tiene defectos...

Versión de libro:

Las seis fases del ciclo de vida del software

1. Definición y planificación del problema
Esta fase consiste en la discusión conjunta entre el desarrollador de software y la parte que demanda los requisitos, principalmente para determinar los objetivos de desarrollo del software y su viabilidad.

2. Análisis de requisitos
Cuando se confirma la viabilidad del desarrollo del software, se realiza un análisis detallado de cada función que el software debe implementar. La fase de análisis de requisitos es una fase muy importante; si se hace bien, sentará una buena base para el éxito de todo el proyecto de desarrollo de software. "Lo único constante es el cambio en sí mismo." De igual manera, los requisitos también cambian y se profundizan continuamente durante todo el proceso de desarrollo de software, por lo que debemos establecer un plan de cambios de requisitos para hacer frente a estos cambios y garantizar el buen desarrollo de todo el proyecto.

3. Diseño del software
Esta fase principalmente diseña todo el sistema de software según los resultados del análisis de requisitos, como el diseño del marco del sistema, el diseño de la base de datos, etc. El diseño de software generalmente se divide en diseño general y diseño detallado. Un buen diseño de software sentará una buena base para la programación del software.

4. Implementación del software (codificación del programa)
Esta fase consiste en convertir los resultados del diseño del software en código de programa ejecutable por computadora. En la codificación del programa, se deben establecer normas de escritura unificadas y conformes a los estándares, para garantizar la legibilidad y facilidad de mantenimiento del programa, y mejorar la eficiencia de ejecución del programa.

5. Pruebas de software
Tras completar el diseño del software, se deben realizar pruebas rigurosas para descubrir y corregir los problemas que existan durante todo el proceso de diseño. Todo el proceso de pruebas se lleva a cabo en tres fases: pruebas unitarias, pruebas de integración y pruebas de sistema. Los métodos de prueba principales son las pruebas de caja blanca y las pruebas de caja negra. Durante el proceso de pruebas, es necesario establecer un plan de pruebas detallado y llevarlo a cabo estrictamente de acuerdo con el plan, para reducir la arbitrariedad en las pruebas.

6. Operación y mantenimiento
El mantenimiento del software es la fase de mayor duración en el ciclo de vida del software. Después de que el desarrollo del software se completa y se pone en uso, por diversas razones, el software ya no puede seguir adaptándose a los requisitos del usuario. Para prolongar la vida útil del software, es necesario realizar mantenimiento sobre él. El mantenimiento del software incluye dos aspectos: mantenimiento correctivo y mantenimiento de mejora.
