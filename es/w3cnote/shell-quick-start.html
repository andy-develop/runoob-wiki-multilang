¿Qué es un script de Shell?

Un script de Shell (en inglés: Shell script) es un programa de computadora y un archivo de texto cuyo contenido está compuesto por una serie de comandos de shell, que funcionan después de ser interpretados por el Unix Shell. Se diseña como un lenguaje de script, y su modo de funcionamiento es equivalente al de un lenguaje interpretado. El shell de Unix actúa como intérprete de línea de comandos; después de leer el script de shell, ejecuta secuencialmente los comandos de shell contenidos en él y luego genera resultados. Con los scripts de shell se puede realizar administración del sistema, operaciones con archivos, etc.

En Unix y todos los sistemas tipo Unix, como Linux, FreeBSD y otros sistemas operativos, existen los scripts de Shell. Según los diferentes tipos de shell de Unix, los scripts de shell también tienen varios dialectos. Los archivos por lotes en DOS, OS/2 y Microsoft Windows tienen funciones similares a los scripts de shell.

Veamos un ejemplo

#!/bin/sh
cd ~
mkdir shell_tut
cd shell_tut

for ((i=0; i<10; i++)); do
    touch test_$i.txt
done

Análisis de ejemplo:

  • Línea 1: especifica el intérprete de scripts; aquí se usa /bin/sh como intérprete.
  • Línea 2: cambia al directorio home del usuario actual.
  • Línea 3: crea un directorio shell_tut.
  • Línea 4: cambia al directorio shell_tut.
  • Línea 5: condición de bucle; se repite un total de 10 veces.
  • Línea 6: crea un archivo test_1...10.txt.
  • Línea 7: fin del cuerpo del bucle.

cd, mkdir y touch son programas incluidos en el sistema, generalmente en los directorios /bin o /usr/bin. for, do y done son palabras clave del lenguaje de scripts sh.

Entorno

La programación shell, al igual que la programación en Java o PHP, solo requiere un editor de texto para escribir código y un intérprete de scripts que pueda interpretar y ejecutar.

Los sistemas operativos actuales más comunes son compatibles con la programación shell. La programación shell descrita en este documento se refiere al shell en Linux, y trata básicamente funciones bajo el estándar POSIX, por lo que también es aplicable a Unix y BSD (como Mac OS).

Linux

Linux viene con un intérprete de shell instalado por defecto.

Mac OS

Mac OS no solo incluye los dos intérpretes más básicos, sh y bash, sino que también incorpora intérpretes menos comunes como ksh, csh y zsh.

Emuladores en Windows

Windows no incluye un intérprete de shell de fábrica; es necesario instalarlo por su cuenta. Para poder usar también herramientas como grep, awk, curl, es mejor instalar Cygwin o MinGW para emular el entorno Linux.

  • cygwin
  • mingw

Intérprete de scripts

sh

Es decir, Bourne shell, el intérprete de shell del estándar POSIX (Portable Operating System Interface). Su ruta binaria suele ser /bin/sh, y fue desarrollado por Bell Labs.

bash

Bash es un reemplazo de Bourne shell, pertenece al Proyecto GNU, y su ruta binaria suele ser /bin/bash. En la industria, bash, sh y shell se usan a menudo indistintamente; por ejemplo, a menudo verá en anuncios de contratación de ingenieros de operaciones: familiarizado con la programación Bash en Linux, dominio de la programación Shell.

En CentOS, /bin/sh es un enlace simbólico a /bin/bash:

[root@centosraw ~]# ls -l /bin/*sh
-rwxr-xr-x. 1 root root 903272 Feb 22 05:09 /bin/bash
-rwxr-xr-x. 1 root root 106216 Oct 17  2012 /bin/dash
lrwxrwxrwx. 1 root root      4 Mar 22 10:22 /bin/sh -> bash

Pero en Mac OS no es así; /bin/sh y /bin/bash son dos archivos diferentes, aunque sus tamaños difieren solo en unos 100 bytes:

iMac:~ wuxiao$ ls -l /bin/*sh
-r-xr-xr-x  1 root  wheel  1371648  6 Nov 16:52 /bin/bash
-rwxr-xr-x  2 root  wheel   772992  6 Nov 16:52 /bin/csh
-r-xr-xr-x  1 root  wheel  2180736  6 Nov 16:52 /bin/ksh
-r-xr-xr-x  1 root  wheel  1371712  6 Nov 16:52 /bin/sh
-rwxr-xr-x  2 root  wheel   772992  6 Nov 16:52 /bin/tcsh
-rwxr-xr-x  1 root  wheel  1103984  6 Nov 16:52 /bin/zsh

Lenguajes de programación de alto nivel

En teoría, cualquier lenguaje que proporcione un intérprete (no solo un compilador) puede ser adecuado para la programación de scripts. Los lenguajes interpretados comunes se pueden usar para programar scripts, como: Perl, Tcl, Python, PHP, Ruby. Perl es el lenguaje de programación de scripts más veterano; Python también se ha convertido en estos años en un intérprete preinstalado en algunas distribuciones de Linux.

Los lenguajes compilados, siempre que tengan un intérprete, también se pueden usar para programación de scripts. Por ejemplo, C shell está integrado (/bin/csh), Java tiene el intérprete de terceros JShell, y Ada tiene el intérprete de pago AdaScript.

El siguiente es un ejemplo de PHP Shell Script (suponiendo que el archivo se llame test.php):

#!/usr/bin/php
<?php
for ($i=0; $i < 10; $i++) {
    echo $i . "\n";
}

Ejecución:

/usr/bin/php test.php

O bien:

chmod +x test.php
./test.php

Cómo elegir el lenguaje de programación shell

Familiar vs Desconocido

Si ya domina un lenguaje de programación (como PHP, Python, Java, JavaScript), se recomienda que use directamente ese lenguaje para escribir programas de script. Aunque en algunos aspectos puede ser un poco verboso, puede aprovechar la experiencia en ese lenguaje (pruebas unitarias, depuración paso a paso, IDE, bibliotecas de terceros).

El costo de aprendizaje adicional es muy pequeño; solo necesita aprender a usar el intérprete de shell (JShell, AdaScript).

Simple vs Avanzado

Si cree que escribir scripts de shell en su lenguaje familiar (como Java, C) es demasiado verboso, y solo quiere hacer cosas como respaldar archivos, instalar software, descargar datos, aprender a usar sh y bash será una buena idea.

El shell solo define un lenguaje de programación muy simple. Por lo tanto, si su programa de script tiene una complejidad alta, o si las estructuras de datos a manipular son relativamente complejas, entonces debería usar lenguajes de script como Python o Perl, o un lenguaje de alto nivel que ya domine. Porque sh y bash son débiles en este aspecto, por ejemplo:

  • Sus funciones solo pueden devolver cadenas, no pueden devolver arreglos.
  • No admite programación orientada a objetos; no puede implementar algunos patrones de diseño elegantes.
  • Es interpretado; se ejecuta mientras se interpreta, ni siquiera como la precompilación de PHP. Si su script contiene un error (por ejemplo, llamar a una función inexistente), mientras no se ejecute esa línea, no se reportará el error.

Compatibilidad del entorno

Si sus scripts son para que otros usuarios los usen, usar sh o bash le dará la mejor compatibilidad de entorno. Perl ha sido durante mucho tiempo un estándar de Linux; Python también se ha convertido en un estándar en algunas distribuciones de Linux en estos años. En cuanto a Mac OS, tiene instalados de forma predeterminada lenguajes de programación principales como Perl, Python, Ruby, PHP, Java.

Primer script de shell

Escribir

Abra un editor de texto, cree un archivo nuevo con extensión sh (sh representa shell). La extensión no afecta la ejecución del script; solo es para que el nombre sea indicativo. Si escribe scripts de shell en PHP, use la extensión php.

Ingrese algo de código; la primera línea generalmente es así:

#!/bin/bash
#!/usr/bin/php

"#!" es una marca convenida; le dice al sistema qué intérprete se necesita para ejecutar este script.

Ejecutar

Hay dos métodos para ejecutar scripts de Shell:

Hay dos métodos para ejecutar scripts de Shell:

Como programa ejecutable

chmod +x test.sh
./test.sh

Tenga en cuenta que debe escribir ./test.sh, no test.sh. Lo mismo ocurre al ejecutar otros programas binarios; si escribe directamente test.sh, el sistema Linux buscará en PATH si existe algo llamado test.sh. Pero solo /bin, /sbin, /usr/bin, /usr/sbin, etc. están en PATH; su directorio actual normalmente no está en PATH, por lo que escribir test.sh no encontrará el comando. Debe usar ./test.sh para indicar al sistema que busque en el directorio actual.

Al ejecutar scripts de bash de esta manera, la primera línea debe estar escrita correctamente para que el sistema encuentre el intérprete adecuado.

Aquí, el "sistema" en realidad es la aplicación shell (imagínese el Explorador de Windows), pero deliberadamente lo llamé sistema para facilitar la comprensión. Dado que este sistema se refiere al shell, ¿se puede omitir la primera línea en un script que usa /bin/sh como intérprete? Sí.

Como parámetro del intérprete

Este método de ejecución consiste en ejecutar directamente el intérprete, cuyo parámetro es el nombre del archivo del script de shell, por ejemplo:

/bin/sh test.sh
/bin/php test.php

Los scripts ejecutados de esta manera no necesitan especificar la información del intérprete en la primera línea; escribirla tampoco sirve.
