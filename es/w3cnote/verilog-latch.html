6.5 Verilog Evitar Latch

Categoría Tutorial de Verilog

Palabras clave: flip-flop, latch

El significado de Latch

El latch es una celda de almacenamiento disparada por nivel. La acción de almacenamiento de datos depende del valor de nivel de la señal de reloj de entrada (o habilitación). Solo cuando el latch está en estado habilitado, la salida cambia con la entrada de datos.

Cuando la señal de nivel no está activa, la señal de salida cambia con la señal de entrada, como si pasara a través de un buffer; cuando el nivel está activo, la señal de salida se bloquea (latch). Cualquier cambio en la señal de excitación provocará directamente un cambio en el estado de salida del latch, y es muy probable que se produzcan oscilaciones debido a la inestabilidad de las características transitorias.

El flip-flop es una celda de almacenamiento sensible al flanco. La acción de almacenamiento de datos (transición de estado) se sincroniza mediante el flanco ascendente o descendente de una señal (limitando la transición de estado de la celda de almacenamiento a un período de tiempo muy corto).

El registro (register) es una variable en Verilog que se utiliza para almacenar temporalmente los datos que participan en las operaciones y los resultados de las operaciones. Cuando una variable se declara como registro, puede sintetizarse como flip-flop, como latch, o incluso como variable tipo wire. Sin embargo, en la mayoría de los casos esperamos que se sintetice como flip-flop, pero a veces, debido a problemas en la escritura del código, se sintetiza como una estructura de latch no deseada.

Los principales peligros del latch son:

  • 1) El estado de entrada puede cambiar varias veces, lo que fácilmente genera glitches, aumentando la incertidumbre del circuito de la siguiente etapa;
  • 2) En la mayoría de los recursos FPGA, puede requerir más recursos que un flip-flop para implementar la estructura de latch;
  • 3) La aparición de latches hace que el análisis de tiempo estático sea más complejo.

El latch se usa a menudo para el control de reloj de compuerta (clock gating). En el diseño general, debemos evitar la generación de latches.

Estructura if incompleta

En lógica combinacional, una estructura if-else incompleta generará un latch.

Por ejemplo, en el siguiente modelo, a la sentencia if le falta la estructura else. El sistema asume por defecto que en la rama else el valor del registro q permanece sin cambios, es decir, tiene la función de almacenar datos, por lo que el registro q se sintetizará como una estructura de latch.

Ejemplo

module module1_latch1(
    input       data,
    input       en ,
    output reg  q) ;
   
    always @(*) begin
        if (en) q = data ;
    end

endmodule

Hay principalmente dos métodos para evitar este tipo de latch: uno es completar la estructura if-else, o asignar un valor inicial a la señal.

Por ejemplo, la sentencia always del modelo anterior se puede cambiar a las siguientes dos formas:

Ejemplo

    // Completar la estructura de ramas condicionales
    always @(*) begin
        if (en)  q = data ;
        else     q = 1'b0 ;
    end

    // Asignar valor inicial
    always @(*) begin
        q = 1'b0 ;
        if (en) q = data ; // Si en está activo, reescribir el valor de q; de lo contrario, q se mantendrá en 0
    end

Pero en lógica secuencial, una estructura if-else incompleta no generará un latch, como en el siguiente modelo.

Esto se debe a que el registro q tiene función de almacenamiento, y su valor solo cambia en el flanco del reloj, que es precisamente la característica de un flip-flop.

Ejemplo

module module1_ff(
    input       clk ,
    input       data,
    input       en ,
    output reg  q) ;
   
    always @(posedge clk) begin
        if (en) q <= data ;
    end

endmodule

En lógica combinacional, cuando hay muchas sentencias de asignación en una sentencia condicional, la incompletitud de las sentencias de asignación en cada rama también puede generar un latch.

De hecho, si se analiza la lógica de cada señal por separado, esto equivale a una estructura if-else incompleta, donde las señales de registro relacionadas carecen de comportamiento de asignación en otras condiciones. Por ejemplo:

Ejemplo

module module1_latch11(
    input       data1,
    input       data2,
    input       en ,
    output reg  q1 ,
    output reg  q2) ;
   
    always @(*) begin
        if (en)   q1 = data1 ;
        else      q2 = data2 ;
    end

endmodule

Esta situación también se puede evitar completando las sentencias de asignación o asignando valores iniciales. Por ejemplo:

Ejemplo

    always @(*) begin
        //q1 = 0; q2 = 0; // o asignar valores iniciales a q1/q2 aquí
        if (en)  begin
            q1 = data1 ;
            q2 = 1'b0 ;
        end
        else begin
            q1 = 1'b0 ;
            q2 = data2 ;
        end
    end

Estructura case incompleta

El principio de que la sentencia case genere un latch es casi el mismo que el de la sentencia if. En lógica combinacional, cuando la lista de opciones de case no está completa y no se agrega la palabra clave default, o hay múltiples sentencias de asignación incompletas, también se generará un latch. Por ejemplo:

Ejemplo

module module1_latch2(
    input       data1,
    input       data2,
    input [1:0] sel ,
    output reg  q ) ;
   
    always @(*) begin
        case(sel)
            2'b00:  q = data1 ;
            2'b01:  q = data2 ;
        endcase
    end

endmodule

Por supuesto, también hay dos métodos para eliminar este tipo de latch: completar la lista de opciones de case, o asignar valores iniciales a la señal.

Al completar la lista de opciones de case, se pueden enumerar todos los resultados de las opciones, o se puede usar la palabra clave default para representar los resultados de otras opciones.

Por ejemplo, la sentencia always anterior tiene las siguientes 2 formas de modificación.

Ejemplo

    always @(*) begin
        case(sel)
            2'b00:    q = data1 ;
            2'b01:    q = data2 ;
            default:  q = 1'b0 ;
        endcase
    end

    always @(*) begin
        case(sel)
            2'b00:  q = data1 ;
            2'b01:  q = data2 ;
            2'b10, 2'b11 :  
                    q = 1'b0 ;
        endcase
    end

Asignación o condición de la señal original

En lógica combinacional, si la fuente de asignación de una señal incluye la propia señal, o si la condición de juicio contiene la lógica de la propia señal, también se generará un latch. Porque en este caso la señal también necesita tener función de almacenamiento, pero no hay un reloj que la impulse. Este tipo de problema puede aparecer en sentencias if, sentencias case y expresiones con ?. Por ejemplo:

Ejemplo

    //signal itself as a part of condition
    reg a, b ;
    always @(*) begin
        if (a & b)  a = 1'b1 ;   //a -> latch
        else a = 1'b0 ;
    end
   
    //signal itself are the assigment source
    reg        c;
    wire [1:0] sel ;
    always @(*) begin
        case(sel)
            2'b00:    c = c ;    //c -> latch
            2'b01:    c = 1'b1 ;
            default:  c = 1'b0 ;
        endcase
    end

    //signal itself as a part of condition in "? expression"
    wire      d, sel2;
    assign    d =  (sel2 && d) ? 1'b0 : 1'b1 ;  //d -> latch

Solo hay una forma de evitar este tipo de latch: evitar esta escritura en lógica combinacional. La señal no debe asignarse a sí misma, y no se debe usar la propia señal asignada en la lógica de la condición de juicio.

Por ejemplo, si no se requiere una salida inmediata, se puede retrasar la señal por un ciclo de reloj antes de combinarla con la lógica relacionada. El primer código que generaba el latch anterior se puede describir como:

Ejemplo

    reg   a, b ;
    reg   a_r ;
   
    always (@posedge clk)
        a_r  <= a ;
       
    always @(*) begin
        if (a_r & b)  a = 1'b1 ;   //there is no latch
        else a = 1'b0 ;
    end

Lista de señales sensibles incompleta

Si en lógica combinacional la lista sensible dentro del bloque always@() no está completa y no se dispara cuando debería, el registro relacionado aún conservará el resultado de salida anterior, generando así un latch.

En este caso, completar las señales sensibles o usar directamente always@(*) puede eliminar el latch.

Resumen

En resumen, para evitar la generación de latches, en lógica combinacional se deben tener en cuenta los siguientes puntos:

  • 1) Las sentencias if-else o case deben tener una estructura completa
  • 2) No colocar la señal asignada en la fuente de asignación, ni en la condición de juicio
  • 3) Se recomienda usar más always@(*) para la lista de señales sensibles
