HTML

¿Qué pasa, DOCTYPE?

No definir el DOCTYPE es un crimen castigado con pena de muerte. Antes probablemente usabas el siguiente DOCTYPE, pero debes saber que ya existe un código más limpio y claro que lo ha reemplazado.

<!DOCTYPE html PUBLIC "-//W3C//DTD XHTML 1.0 Transitional//EN"
    "http://w3.org/TR/xhtml1/DTD/xhtml1-transitional.dtd">

Lo ideal es usar el DOCTYPE de HTML5; todos los navegadores modernos lo soportan, e incluso los navegadores que no soportan HTML5, como IE6 e IE7, entrarán en modo estándar gracias a él. VerFuente。 

<!DOCTYPE html>

Escribe marcado válido y semánticamente claro

Escribir el código de un sitio con HTML limpio y semánticamente claro es algo que siempre buscamos con empeño. A veces descubrimos que la forma en que otros configuraron la página nos limita, o a veces escribimos plantillas de correo en formato HTML. Pero nunca te desvíes de las especificaciones de HTML, ni siquiera para resolver un bug de compatibilidad con un navegador concreto.

Todos los títulos deberían empezar desde<h2>crearse por niveles, y los párrafos de texto siempre deben colocarse en<p>etiquetas, y así sucesivamente. Si escribes HTML con semántica clara, las páginas resultantes serán más ordenadas, concisas y fáciles de parsear por los rastreadores de los motores de búsqueda. Es la forma más sencilla de optimización SEO que puedes aplicar.

Manejo del clic con el botón central del ratón

Una de las deficiencias de usabilidad más frustrantes en las aplicaciones web modernas es la variación de la funcionalidad de los hiperenlaces. Algunos elementos que parecen hiperenlaces pueden tener asignada una función de clic mediante JavaScript, lo que rompe la función del clic con el botón central (abrir la página del enlace en una nueva pestaña). Incluso si pueden abrirse en una pestaña nueva, solo tienen un#href que te llevará de vuelta a la misma página.

Un ejemplo moderno y popular que ilustra perfectamente este problema es Twitter. En toda su aplicación, hacer clic con el botón central en un nombre de usuario o avatar produce resultados completamente distintos.

<!-- 旧的方式，破坏网页语义 -->
<a href="../index.html"></a>

<!-- 如果鼠标点击不能产生一个页面，那就不是超链接 -->
<span class="link" role="link"></span>

Otra alternativa es usar#rutas guiadas, que mapean URLs normales a#enlaces guiados, y luego obtienen fragmentos de página mediante AJAX. Las bibliotecas que ofrecen esta funcionalidad deberían poder mostrar la página normalmente al hacer clic con el botón central, o cargar el contenido de la página en el área designada al hacer clic con el botón izquierdo. Sin embargo, hay que proceder con cautela, ya que muchos consideran quelos enlaces # están dañando las aplicaciones web.。

Espaciado y formato del código

Cualquier discusión sobre formato de código, espaciado y posición de las llaves genera un acalorado debate. Para esto, creo que la regla más simple es: a menos que estés dispuesto a reformatear todo el archivo de código, respeta y mantén el formato del archivo existente. Esto significa que si ves que en un archivo JS las llaves no se escriben en una línea nueva, tu código debe mantener las llaves en la misma línea. Si tu código no es consistente con el resto del archivo, no debería pasar el proceso de revisión de código.

Un formato de código consistente hace que el código sea más legible y también significa que es fácil de modificar con comandos de buscar/reemplazar. Afortunadamente, nuestros propios hábitos de programación son muy similares a las recomendaciones oficiales de jQuery. Hay pequeñas diferencias, pero son cuestiones personales o cosas que sentimos que no podíamos mantener. VerGuía de estilo del núcleo de jQuery

Evita contaminar el espacio de nombres global

La dependencia excesiva de variables globales es algo de lo que todos en nuestro equipo — especialmente yo — nos sentimos particularmente culpables. La discusión sobre por qué las variables globales son malas es bastante directa: aumenta la probabilidad de conflictos entre scripts y variables, y los archivos fuente y el propio espacio de nombres se llenan de innumerables variables con nombres ambiguos.

Douglas CrockfordCreo firmemente que la calidad del código de una aplicación JavaScript puede evaluarse por la cantidad de variables globales que usa; cuanto menos, mejor. Como no todo puede definirse como local (aunque, siendo honestos, lo que estás considerando ahora sí puede, no seas perezoso), necesitas encontrar formas de organizar tus variables para evitar conflictos y minimizar la expansión del espacio de nombres. El método más simple es adoptar una variable única o reducir al máximo los módulos que usan esas variables globales. Crockford mencionó que YUI usa solo una variable global, YAHOO. En su artículo"Global Domination"analiza más detalles.

Considera este caso: en aplicaciones web pequeñas, las variables globales suelen usarse para guardar ajustes a nivel de aplicación. Puedes definir un objeto con el nombre de tu proyecto o settings, lo cual es mejor en general.

// 被污染的全局命名空间
var settingA = true;
var settingB = false;
var settingC = "test";

// 用 settings 作为对象命名
var settings = {
    settingA: true,
    settingB: false,
    settingC: "test"
}

Sin embargo, si podemos reducir la probabilidad de conflictos evitando variables globales, pero estandarizamos el espacio de nombres con el mismo nombre, ¿no aumentaría la probabilidad de conflictos entre aplicaciones? Bueno, esa preocupación es válida. Por eso, se recomienda usar el nombre específico de tu aplicación como espacio de nombres global, o reasignar tu espacio de nombres con el mismo patrón que usa jQuery.$.noConflict()método.

var myAppName = {
    settings: {
        settingA: true
    }
}

//访问全局变量
myAppName.settings.settingA; // true

Rendimiento de bucles: almacenar en caché la longitud del array

Los bucles son probablemente la parte más importante del ajuste de rendimiento en JavaScript. Ahorrar uno o dos milisegundos dentro de un bucle puede suponer varios segundos en total. Un truco es almacenar en caché la longitud del array para no tener que calcularla en cada iteración.

var toLoop = new Array(1000);

for (var i = 0; i < toLoop.length; i++) {
    // 败家玩意 - 长度会反复算 1000 次你知道不？
}

for (var i = 0, len = toLoop.length; i < len; i++) {
    // 会过日子 - 长度只计算一次，然后缓存了
}

Excepción

Si recorres un array para buscar y eliminar un elemento, eso cambia la longitud del array. En cualquier momento en que añadas o elimines elementos dentro del bucle para cambiar la longitud del array, te estás buscando problemas. En ese caso, o restableces la longitud del array después de cada cambio, o no la almacenes en caché.

Rendimiento de bucles: usar 'break;' y 'continue;'

La capacidad de saltar iteraciones y de salir de los bucles es muy útil para evitar ciclos de bucle costosos.

Si estás buscando dentro de un bucle, ¿qué haces después de encontrar lo que buscas? Por ejemplo, en un bucle de 1000 elementos, llegas a la mitad y encuentras lo que querías. ¿Dejas que el bucle continúe iterando sobre los 500 elementos restantes, ignorando que las declaraciones if posteriores ya no tendrán oportunidad de cumplirse? ¡No! Deberías salir del bucle, ¡sin duda!

var bigArray = new Array(1000);

for (var i = 0, len = bigArray.length; i < len; i++) {
    if (i === 500) {
        break;
    }
    console.log(i); // 这样只会输出 0 - 499
}

Otro problema es saltar una iteración específica y continuar con el bucle. Aunque condiciones como par/impar pueden manejarse reemplazandoi++pori + 2, algunas condiciones aún requieren una detección específica y luego activar una operación de salto. Cualquier cosa que evite ejecutar la iteración completa es útil.

var bigArray = new Array(1000);

for (var i = 0, len = bigArray.length; i < len; i++) {
    if (condition) {
        continue;
    }
    doCostlyStuff();
}

Minimiza los repintados y los reflows

Los repintados y los reflows están relacionados con el proceso de volver a renderizar el DOM, que ocurre cuando se cambian propiedades o elementos específicos. Un repintado se activa cuando se altera la apariencia de un elemento sin ajustar el diseño.artículodescribe estos cambios como cambios de estilo, como la visibilidad o el color de fondo. El reflow es una operación más costosa, provocada por cambios que ajustan el diseño de la página. Por ejemplo, añadir o eliminar elementos, cambiar el ancho o el alto de un elemento, o incluso cambiar el tamaño de la ventana del navegador. El peor caso es un efecto dominó donde el reflow provoca que los elementos ancestros, hermanos e hijos también necesiten reflow.

Sin duda, los repintados y los reflows deberían evitarse en la medida de lo posible, pero ¿cómo lograrlo?

Ejemplo de reflow

En realidad, no es que el siguiente código sea malo. Pero supongamos primero que el arrayarrtiene 10 elementos

var myList = document.getElementById("myList");

for (var i = 0, len = arr.length; i < len; i++) {

    myList.innerHTML += "<li>" + arr[i].title + "</li>"; //重新布局 -- 增加到元素

}

En elforbucle anterior, cada iteración activa un reflow. 10 iteraciones significan 10 reflows.

Ahora considera el siguiente código:

var constructedHTML = "";

for (var i = 0, len = arr.length; i < len; i++) {
    constructedHTML += "<li>" + arr[i].title + "</li>"; //没有重新布局 - 增加到字符串
}

document.getElementById("myList").innerHTML = constructedHTML; //在这里重新布局

En este escenario, los elementos que se deben añadir se construyen en una cadena. No se produce ningún reflow dentro del bucle porque el DOM no cambia. Solo cuando el array se ha recorrido por completo y la cadena construida se aplica a cierta propiedad de un objeto,innerHTML, es cuando se produce el único reflow de la función.

Hay innumerables reflows y repintados que pueden evitarse; con suerte, conocerás esos trucos. Hay abundante material de lectura sobre este tema, pero la mayoría de él hace referencia al artículo de Nicole Sullivanartículo, que es un punto de partida perfecto. Además de las lecciones de aquí, hay otras lecciones importantes que aprender al tratar con los diversos términos técnicos de la era de la "web 3.0" y HTML5. El análisis anterior se aplica directamente a escribir código jQuery. No uses microsegundos para generar ID únicos

Desde los inicios del desarrollo web, ha sido popular un método para generar identificadores únicos. La práctica consiste en añadir el número de microsegundos desde el 1 de enero de 1970 a tu ID estático, como se muestra a continuación:

var myID = "static" + new Date().getTime();

Solía ser un método bastante infalible, porque incluso si dos fragmentos de código así se ejecutaran consecutivamente, habría unos pocos milisegundos entre ellos. Pero ahora los nuevos navegadores vienen con nuevos motores JavaScript, acompañados de velocidades de reloj cada vez mayores. A estas alturas, el código anterior tiene más probabilidades de producir el mismo valor de milisegundos que de producir una diferencia.

Esto puede provocar errores difíciles de depurar con los métodos tradicionales. Debido a que tu DOM se crea en tiempo de ejecución, las pruebas tradicionales sobre el código fuente de la página no pueden detectar el error de múltiples IDs duplicados. El mecanismo de manejo de errores de Javascript y jQuery toma la primera coincidencia como ID e ignora los demás IDs duplicados. ¡Así que ni siquiera lanza un error de JS!

Así no funciona; el único método real es poner puntos de interrupción y registros (logs) línea por línea. Pero si el punto de interrupción no está en el lugar correcto, ¡tus milisegundos no entrarán en conflicto!

La buena noticia es que hay muchos métodos alternativos para generar IDs únicos. Dicho de manera pedante, la función de números aleatorios de la computadora en realidad no es verdaderamente aleatoria, porque sigue derivando del tiempo del sistema. Aunque esto es digno de atención, la probabilidad de colisión de números aleatorios es minúscula.

var myID = "static" + Math.round(Math.random() * 10000);

Personalmente prefiero el método de generar un GUID manualmente. Técnicamente, un GUID se crea a partir de tu hardware, pero la siguiente función de Javascript lo hace bastante bien. Lo tomé prestado deuna publicación de stack overflowy es una función bastante útil.

function S4() {
   return (((1+Math.random())*0x10000)|0).toString(16).substring(1);
}
function guid() {
   return (S4()+S4()+"-"+S4()+"-"+S4()+"-"+S4()+"-"+S4()+S4()+S4());
}


var myID = "static" + guid();

Entender el modelo de cajas es clave

El "modelo de caja" es un factor crítico y decisivo para entender cómo el navegador renderiza las páginas. Una comprensión completa de su complejidad puede simplificar tu trabajo de forma milagrosa. El modelo de caja describe la forma en que se calculan las dimensiones físicas de un elemento HTML. Si un elemento de bloque tiene un ancho fijo, digamos 100px, ¿cómo se deben determinar su padding, border y margin?

Muchos sitios web tienen descripciones en profundidad, pero seamos breves: en los navegadores que cumplen con los estándares, border y padding se colocan fuera del ancho especificado. Es mejor explicarlo con un gráfico. Por ejemplo, el siguiente código:

.foo {
    width: 150px;
    height: 150px;
    padding: 25px;
    border: 25px solid;
    margin: 20px;
}

Lo que quizá estimarías (modo Quirks)

padding y border se calculan hacia adentro, de modo que la altura y el ancho se mantienen en 150px.

Lo que ves (modo estándar)

Sin embargo, el ancho y la altura reales son 250px. Es decir, 150px + (2 * 25) + (2 * 25).

Si este resultado te parece extraño, no eres el único (bueno, eres un humano, solo que hay otros que piensan igual). Ahora hay una solución a mano: introducir una propiedad CSS llamadabox-sizing, esta propiedad es compatible conIE8 y versiones posterioresy se aplica a todos. Te permite elegir la forma exacta de calcular las dimensiones del elemento, lo que puede sacarte de apuros. Los parámetros específicos admitidos varían según el navegador y requieren prefijos de los fabricantes; para más detalles, consulta lacaniuse.com 。 

/* 旧方法 (178 + 20 + 2 = 200) */
.foo {
    width: 178px;
    padding: 10px;
    border: 1px;
}

/* 更好的方法 */
.foo {
    width: 200px;
    padding: 10px;
    border: 1px;
        -webkit-box-sizing: border-box;
        -moz-box-sizing: border-box;
        box-sizing: border-box;
}

Aunque siempre puedes calcular mentalmente el ancho, restando y sumando entre los distintos píxeles (como se hacía en el primer método), cuando entran en juego diferentes unidades de ancho (como porcentajes o EM), ya nadie puede saber cómo hacerlo. Por ahora, aparte de envolver el elemento en un elemento padre, para asegurar que el ancho ypadding/margin/borderspuedan separarse por completo, no hay otra solución.

Saber cuándo usar float y cuándo usar position

La era de usar tablas para la maquetación ha terminado. Ahora debemos admitir que podemos concentrarnos en entender cómo funcionan float y position. Aquí se necesita dominar un modelo de pensamiento particular, y creo que lo mejor es aprenderlo mediante la práctica.

Usar float para extraer elementos del DOM y forzarlos a la izquierda o a la derecha es bastante fiable. Se han convertido en el comodín del desarrollo frontend en la era posterior al diseño con tablas, quizás porque antes los navegadores tenían undisplay: inline 和 inline-blocksoporte deficiente, y los errores que surgían en el soporte de position.z-indexErrores. Pero ahora ya no hay excusa. inline-block está bien soportado, y con un pequeño ajuste se puede hacer funcionar en IE7.

Gracias a Dios, los antiguos debates que impedían el posicionamiento absoluto de elementos con CSS han desaparecido. En teoría, la propiedad de posicionamiento te permite colocar elementos en la página usando coordenadas X e Y, de una manera simple y directa que los desarrolladores de Flash deberían conocer bien.

Entender Position

Al posicionar elementos con CSS, es muy importante entender un hecho: la posición siempre es relativa al elemento padre más cercano que tenga una propiedad de posicionamiento. Cuando la gente empieza a usar CSS, hay un malentendido común de queposition: absolute;es relativa al elemento raíz de la página. Creo que este malentendido proviene de los casos en que el elemento no tiene ningún elemento padre con estilo position; en esos casos, su conclusión es correcta. Al recorrer el árbol DOM hacia arriba sin encontrar ningún elemento con estilo de posicionamiento, se posiciona respecto al elemento raíz de la página.

Entonces, siposition: absolute;saca al elemento del flujo en el que se encuentra, ¿cómo lo posicionas en relación con su elemento padre? El método es sencillo. El elemento padre necesita definirposition: relative;el estilo, y entonces todos los elementos hijos se colocan en el orden arriba, derecha, abajo, izquierda. Con este conocimiento, ¿cómo implementarías el siguiente diseño bastante intuitivo?

Usandofloat, necesitarás envolver estos elementos en un elemento padre, y luego.oneponer float a la izquierda, y luego ajustar.two 和 .three 的 float 和 margin. Al final deberías escribir algo como lo siguiente:

.parent {
    /* ghetto clearfix */
    width: 310px;
    overflow: auto;
}
.one {
    width: 200px;
    height: 210px;
    float: left;
}
.two {
    width: 100px;
    height: 100px;
    float: right;
    margin-bottom: 10px;
}
.three {
    width: 100px;
    height: 100px;
    float: right;
}

Como dijimos antes, usarpositionnos permite mostrar elementos en la pantalla de forma muy explícita según coordenadas X e Y. El método con float anterior separa el texto largo de la página, mientras que el siguiente método asegura que todos los elementos estén en su posición normal, sin importar el contenido de la página.

.parent {
    position: relative;
    width: 310px;
    height: 210px;
}

    position: absolute;
}
.one {
    top: 0;
    left: 0;
    width: 200px;
    height: 210px;

.two {
    top: 0;
    right: 0;
    width: 100px;
    height: 100px;

    bottom: 0;
    right: 0;
    width: 100px;
    height: 100px;
}

Si alternamos entre formatos de parámetros CSS de una sola línea y de varias líneas, el espacio en blanco en CSS también variará. No entraré en demasiado detalle sobre esto.

Formato abreviado de CSS

Agrupación de propiedades

Agrupar las propiedades es el método más efectivo para reducir en gran medida el tamaño de los archivos CSS. Es muy importante entender cómo se ordenan las propiedades (en el sentido de las agujas del reloj: arriba, derecha, abajo, izquierda) y cómo acortarlas aún más (arriba y abajo, izquierda y derecha).

/* 逐个定义，太长了 */
padding-top: 1px;
padding-right: 2px;
padding-bottom: 1px;
padding-left: 2px;

/* 上，右，下，左，好很多 */
padding: 1px 2px 1px 2px;

/* 上和下，左和右，最优 */
padding: 1px 2px;

De 0px a héroe

A una propiedad con valor0asignarle un tipo de unidad es redundante. No importa si un elemento está a0pxo a0 elephantsde la izquierda; lo que importa es que esté pegado a la izquierda.

/* 不好 */
padding: 0px 10px;


/* 好 */
padding: 0 10px;

Para la tarea de mantener múltiples secciones de estilos en una hoja de estilos, añadir comentarios a grandes bloques de CSS es una buena práctica. Limpiar flotadores

Limpiar un<div>flotado solía implicar DOM adicional, porque conllevaba añadir un elemento de limpieza extra. Un método mejor es dar al elemento padre un ancho explícito ('auto' no funciona en todos los navegadores y escenarios) y establecer overflow en 'auto' u 'hidden'. 'hidden' tiene obviamente mejor compatibilidad, pero en algunas versiones compatibles con IE, 'auto' funciona mejor.

HTML:

<div class="parentElement">
    <div class="childElement">
        I'm floated left!
    </div>
    I'm normal text that wraps around the float
</div>

CSS:

.parentElement {
    width: 100%;
    overflow: hidden;
}
.childElement {
    float: left;
}

Centrado vertical y horizontal

Centrar horizontalmente un elemento no es ciencia avanzada; estoy seguro de que la mayoría de vosotros conocéis el siguiente fragmento de código:

.class {
    width: 960px;
    margin: 0 auto;
}

Los desarrolladores frontend han utilizado este código durante mucho tiempo sin entender por qué no funciona para el centrado vertical. Desde mi punto de vista, es importante recordar que el elemento padre generalmente tiene unheight: auto;estilo, y tampoco tiene la altura del 100% necesaria para centrar verticalmente el elemento. Aplicarposition: absolute;transfiere efectivamente el elemento al modo de posicionamiento, y entonces el margen establecido en auto ayuda automáticamente a ajustar su posición, logrando el centrado.

.exactMiddle {
    width: 100px;
    height: 100px;
    position: absolute;
    top: 0;
    right: 0;
    bottom: 0;
    left: 0;
    margin: auto;
}

Las desventajas de este método incluyen la falta de soporte en IE6 e IE7, y que cuando el navegador se reduce hasta ser más pequeño que el objeto centrado, no aparece la barra de desplazamiento. Enesta página webse enumeran más métodos (este es el cuarto), pero este es actualmente el mejor método.

Centrar verticalmente texto dentro de un elemento también es muy sencillo. Si el texto es de una sola línea, como en un elemento de navegación horizontal, puedes establecerline-heightla altura física del elemento.

#horizNav li {
    height: 32px;
    line-height: 32px;

Compatibilidad descendente agresiva

Cabe señalar que este párrafo es mi opinión personal y solo se aplica a ciertos casos. En grandes proyectos comerciales o soluciones empresariales que dependen de navegadores antiguos, la postura de la compatibilidad descendente progresiva no será fácilmente aceptada.

Compatibilidad descendente progresiva significa que si un navegador concreto (de una versión antigua) no puede renderizar un efecto concreto, se debe ignorar directamente. Un botón CSS3 es un buen ejemplo. Efectos comoborder-radius， box-shadow， text-shadow 和 gradientsse mostrarán en navegadores avanzados. Para navegadores un poco más antiguos, se puede usar una.PNGimagen como un recurso inofensivo, y la más elegante de todas las soluciones debería ser proporcionar un PNG-Fix para IE6, o usarfilterparámetros para reemplazar propiedades como gradients y shadows. Sin embargo, en este caso, el enfoque de compatibilidad descendente progresiva hará que ignores los navegadores antiguos y muestres en ellos un objeto plano y aceptable.

En pocas palabras, la compatibilidad descendente progresiva viene a ser:Si tu navegador no puede renderizar degradados o sombras de caja, es tu mala suerte.。

Aunque esto no es ideal para todas las situaciones, este método asegura que el proyecto se entregue a tiempo y que el producto principal sea utilizable, sin tener que depender de trucos para navegadores.
