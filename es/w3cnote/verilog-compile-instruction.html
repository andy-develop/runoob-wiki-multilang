2.5 Directivas de compilación de Verilog

Categoría Tutorial de Verilog

Con una comilla invertida`comienzan ciertos identificadores que son directivas de compilación del sistema Verilog.

Las directivas de compilación proporcionan una gran comodidad para la escritura, compilación y depuración del código Verilog.

A continuación se presentan las 8 directivas de compilación completas, de las cuales las primeras 4 se usan con mayor frecuencia.

`define, `undef

En la fase de compilación,`definese usa para el reemplazo de texto, similar a#define。

Una vez que`definela directiva es compilada, será efectiva durante todo el proceso de compilación. Por ejemplo, en un archivo se define:

`define    DATA_DW     32

Entonces en otro archivo también se puede usar DATA_DW directamente.

`define    S     $stop;   
//用`S来代替系统函数$stop; (包括分号)
`define    WORD_DEF   reg [31:0]       
//可以用`WORD_DEF来声明32bit寄存器变量

`undefSe usa para cancelar la definición de macro anterior, por ejemplo:

`define    DATA_DW     32
……
reg  [DATA_DW-1:0]    data_in   ;
……
`undef DATA_DW

`ifdef, `ifndef, `elsif, `else, `endif

Estas pertenecen a las directivas de compilación condicional. Por ejemplo, en el siguiente ejemplo, si se define MCU51, se usa la primera especificación de parámetros; si no se define MCU y se define WINDOW, se usa la segunda; si ninguno de los dos está definido, se usa la tercera.

`ifdef       MCU51
    parameter DATA_DW = 8   ;
`elsif       WINDOW
    parameter DATA_DW = 64  ;
`else
    parameter DATA_DW = 32  ;
`endif

`elsif, `elsePara la directiva de compilación`ifdefla directiva es opcional, es decir, puede haber solo`ifdef 和 `endifforman un bloque de directivas de compilación condicional.

Por supuesto, también se puede usar`ifndefpara configurar la compilación condicional, lo que indica que si no hay una definición de macro relacionada, se ejecutan las sentencias correspondientes.

En el siguiente ejemplo, si se define WINDOW, se usa la segunda especificación de parámetros. Si no se define WINDOW, se usa la primera especificación de parámetros.

Ejemplo

`ifndef     WINDOW
    parameter DATA_DW = 32 ;  
 `else
    parameter DATA_DW = 64 ;
 `endif

`include

Usar`includepuede incrustar un archivo Verilog dentro de otro archivo Verilog en tiempo de compilación, similar a la estructura #include en C. Esta directiva se usa generalmente para incluir archivos de cabecera globales o comunes en el archivo de diseño.

La ruta del archivo puede ser una ruta relativa o una ruta absoluta.

`include         "../../param.v"
`include         "header.v"

`timescale

En el modelo Verilog, el retardo tiene una expresión de unidad de tiempo específica, y se usa`timescalela directiva de compilación asocia la unidad de tiempo con el tiempo real.

Esta directiva se usa para definir la unidad y precisión del retardo y la simulación, con el formato:

`timescale      time_unit / time_precision

time_unit representa la unidad de tiempo, time_precision representa la precisión de tiempo. Ambos están compuestos por un número y una unidad: s (segundo), ms (milisegundo), us (microsegundo), ns (nanosegundo), ps (picosegundo) y fs (femtosegundo). La precisión de tiempo puede ser igual a la unidad de tiempo, pero la magnitud de la precisión de tiempo no puede exceder la magnitud de la unidad de tiempo. Por ejemplo, en el siguiente ejemplo, la salida Z retrasará 5.21ns el resultado de A&B.

Ejemplo

`timescale 1ns/100ps    //la unidad de tiempo es 1ns, la precisión es 100ps, válido
//`timescale 100ps/1ns //no válido
module AndFunc(Z, A, B);
    output Z;
    input A, B ;
    assign #5.207 Z = A & B
endmodule

Durante el proceso de compilación,`timescalela directiva afectará los valores de retardo en todos los módulos posteriores, hasta que se encuentre otra`timescaledirectiva o`resetalldirectiva.

Dado que en Verilog no hay un valor predeterminado de`timescale, si no se especifica`timescale, entonces el módulo Verilog heredará los`timescaleparámetros. Esto puede causar errores de diseño.

Si múltiples módulos en un diseño llevan`timescaleel simulador siempre se posiciona en la precisión de retardo mínima de todos los módulos, y todos los retardos se convierten en consecuencia a la precisión de retardo mínima; la unidad de retardo no se ve afectada. Por ejemplo:

Ejemplo

`timescale 10ns/1ns      
module test;
    reg        A, B ;
    wire       OUTZ ;
 
    initial begin
        A     = 1;
        B     = 0;
        # 1.28    B = 1;
        # 3.1     A = 0;
    end
 
    AndFunc        u_and(OUTZ, A, B) ;
endmodule

En el módulo AndFunc, 5.207 corresponde a 5.21ns.

En el módulo test, 1.28 corresponde a 13ns, 3.1 corresponde a 31ns.

Pero al simular test, dado que la precisión mínima en AndFunc es 100ps, la precisión de retardo en test se reajustará. 13ns corresponderá a 130*100ps, y 31ns corresponderá a 310*100ps. Durante la simulación, la precisión de retardo también usará 100ps. El tamaño de la unidad de tiempo de simulación no tiene efecto.

Si hay submódulos en paralelo, los `timescale entre submódulos no se afectan entre sí.

Por ejemplo, si se instancia otro submódulo OrFunc dentro del módulo test. Al simular test, el retardo #5.207 en OrFunc sigue correspondiendo a 52ns.

Ejemplo

//submódulo:
`timescale 10ns/1ns      //la unidad de tiempo es 1ns, la precisión es 100ps, válido
module OrFunc(Z, A, B);
    output Z;
    input A, B ;
    assign #5.207 Z = A | B
endmodule
 
//módulo de nivel superior:
`timescale 10ns/1ns      
module test;
    reg        A, B ;
    wire       OUTZ ;
    wire       OUTX ;
 
    initial begin
        A     = 1;
        B     = 0;
        # 1.28    B = 1;
        # 3.1     A = 0;
    end
 
    AndFunc        u_and(OUTZ, A, B) ;
    OrFunc         u_and(OUTX, A, B) ;
 
endmodule

En este ejemplo, al simular test, el retardo #5.207 en OrFunc sigue correspondiendo a 52ns.

`timescaleLa configuración de precisión de tiempo afectará el tiempo de simulación. Cuanto menor sea la precisión de tiempo, más memoria ocupará durante la simulación y más largo será el tiempo de simulación real. Por lo tanto, si no es necesario, se debe intentar establecer una precisión de tiempo mayor.

`default_nettype

Esta directiva se usa para especificar que las variables de red implícitas sean del tipo red, es decir, define las conexiones no declaradas como tipo red.

`default_nettype wand

Este ejemplo define la red por defecto como tipo cable Y (wired AND). Por lo tanto, si después de esta directiva, en cualquier módulo, una conexión no está declarada, se supone que es del tipo cable Y.

`default_nettype none

Después de esta definición de ejemplo, ya no se generarán automáticamente variables de tipo wire.

Por ejemplo, la primera forma de escritura a continuación no reportará Error al compilar, mientras que la segunda no pasará la compilación.

Ejemplo

//Z1 se usa sin definición, el sistema asume por defecto que Z1 es una variable tipo wire, hay Warning sin Error
module test_and(
        input      A,
        input      B,
        output     Z);
    assign Z1 = A & B ;  
endmodule

Ejemplo

//Z1 se usa sin definición, debido a la existencia de la directiva de compilación, el sistema reportará Error, detectando así el error de escritura
`default_nettype none
module test_and(
        input      A,
        input      B,
        output     Z);
    assign Z1 = A & B ;  
endmodule

`resetall

Esta directiva del compilador restablece todas las directivas de compilación a sus valores predeterminados.

`resetallPuede hacer que el tipo de conexión predeterminado sea tipo red.

当 `resetallAl agregarse al final del módulo, se puede`timescalecancelar para evitar una mayor transmisión, solo se asegura que la actual`timescalesea efectiva localmente, evitando la herencia incorrecta de `timescale.

`celldefine, `endcelldefine

Estas dos directivas de programa se usan para marcar un módulo como módulo de celda, e incluyen la definición del módulo. Por ejemplo, algunas puertas AND, OR, NOT, algunas celdas PLL, modelos PAD, y algunos IP analógicos, etc.

Ejemplo

`celldefine
module (
    input      clk,
    input      rst,
    output     clk_pll,
    output     flag);
        ……
endmodule
`endcelldefine

`unconnected_drive, `nounconnected_drive

En la instanciación de módulos, cualquier puerto de entrada no conectado que aparezca entre estas dos directivas de compilación estará en estado de polarización directa o en estado de polarización inversa.

`unconnected_drive pull1
. . .
 / *在这两个程序指令间的所有未连接的输入端口为正偏电路状态（连接到高电平） * /
`nounconnected_drive
`unconnected_drive pull0
. . .
 / *在这两个程序指令间的所有未连接的输入端口为反偏电路状态（连接到低电平） * /
`nounconnected_drive
