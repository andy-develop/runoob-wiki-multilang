7.4 Conversión de números reales y enteros en Verilog

Categoría Tutorial de Verilog: nivel avanzado

Palabras clave: número de punto fijo, número de punto flotante, $realtobits, $bitstoreal

Esta sección presenta principalmente las funciones de conversión mutua entre números reales y enteros: $realtobits, $bitstoreal, y también explica cómo se representan las variables de tipo real (igual que double float en C) mediante códigos binarios de múltiples bits.

Representación binaria de decimales

Representación binaria de decimales

Cuando un entero decimal se representa en binario, se requiere dividir el dato entre 2 y luego tomar el resto.

Para representar la parte fraccionaria en binario es exactamente lo contrario: se requiere multiplicar el dato por 2 y luego determinar si la parte entera es mayor o igual que 1.

El proceso para obtener la representación binaria de la parte fraccionaria 0.3125 de 2.3125 es el siguiente:

Proceso de cálculoDecisiónBit binario
0.3125 x 2 = 0.625< 10
0.625 x 2 = 1.25≥ 11
(1.25 - 1) x 2 = 0.5< 10
0.5 x 2 = 1≥ 11
Resultado: usar 4 bits binarios para representar la parte fraccionaria.stop0101

Por lo tanto, la representación binaria de 2.3125 es dec2bin(2.3125) = bin(10.0101). Aquí el punto decimal solo se usa para distinguir la posición de la parte fraccionaria, es decir, la parte fraccionaria se representa con un código binario de 4 bits. En realidad, el marcador de punto decimal no existe.

Al representar decimales en binario, también existe un método rápido. Si la parte fraccionaria se representa con N bits, el valor numérico de la representación binaria de un decimal num es:

dec2bin(num) = bin(num x 2^N )

Por ejemplo, el proceso de conversión de 2.3125 es el siguiente:

2.3125 x 2 ^ 4 = 37 = bin(100101)

Si el ancho de bits de la parte fraccionaria es 4, entonces dec2bin(2.3125) = bin(10.0101).

Conversión de binario a decimal

Al convertir un entero binario a decimal, es necesario realizar la operación de multiplicar cada bit por potencias de 2 y acumular los resultados.

Al convertir una fracción binaria a decimal, es necesario realizar la operación de multiplicar cada bit por potencias de 1/2 y acumular los resultados.

Por ejemplo, cuando el ancho de bits de la parte fraccionaria es 4, el decimal representado por la parte fraccionaria de bin(11.1001) es:

bin2dec(1001) = 1 x 2^(-1) + 0 x 2^(-2) + 0 x 2^(-3) + 1 x 2^(-4) = 0. 5625

Entonces, la fracción binaria bin(11.1001) con una parte fraccionaria de 4 bits representa el decimal 3.5626.

El método rápido para convertir a decimal una fracción binaria num con una parte fraccionaria de N bits es:

bin2dec(num) = num / 2^N

Por ejemplo, el proceso de cálculo del decimal representado por bin(11.1001) es:

bin(11.1001) = bin(111001) / (2^4) = 57/16 = 3.5625 。

En realidad, el compilador de Verilog no distingue si una variable de múltiples bits representa un entero o un decimal; todas las operaciones se realizan artificialmente a nivel del punto decimal.

Método de representación de números de punto flotante

Un número de punto fijo es aquel cuya posición del punto decimal permanece fija. Un entero es un tipo de número de punto fijo, porque el punto decimal siempre está después del último dígito.

Un número de punto flotante es aquel cuya posición del punto decimal no es fija. Por ejemplo, 1.2 x 1.3 = 1.56; la posición del punto decimal siempre está flotando, por eso se llama punto flotante.

Por supuesto, también se puede fijar la posición del punto decimal de un decimal; esto se llama decimal de punto fijo. Pero este método de representación reduce la precisión del decimal. Por ejemplo, si se fija que solo haya un dígito después del punto decimal para representar el número, entonces 1.2 x 1.3 = 1.5, perdiendo parte de los datos.

Método general de representación de números de punto flotante decimales:

dec(num) = (-1) ^ S x M x (10^E );

S es el bit de signo; cuando es 1 representa un número negativo, cuando es 0 representa un número positivo.

E es la parte exponencial del factor de escala, representada como un entero, denominada exponente. El exponente indica la posición del punto decimal en la palabra de código, por lo que determina el rango de representación del número de punto flotante.

M es la parte fraccionaria, denominada mantisa. El ancho de bits de la mantisa determina la precisión de representación del número de punto flotante.

Por ejemplo, el número 100.0344 se puede representar como:

1995.0907 = (-1) ^ 0 x 199.50907 x 10^1 （正数，尾数为199.50907,  阶码为1）
= (-1) ^ 0 x 1.9950907 x 10^3 
= (-1) ^ 0 x 0.19950907 x 10^ 4

De manera similar, el método general de representación de números de punto flotante binarios:

dec(num) = (-1) ^ S x M x (2^E )

Por ejemplo:

dec(2.3125) (十进制)  =  bin(10.0101) 
              = bin(10.0101) x 2^0
              = bin(1.00101) x 2^1 (正数，尾数为 1.00101，阶码为 1）
              = bin(0.100101) x 2^2

Como se puede ver arriba, para el mismo número de punto flotante, diferentes métodos de representación dan como resultado mantisas y exponentes distintos. Para facilitar la portabilidad, en 1985 el IEEE (Institute of Electrical and Electronics Engineers, Instituto de Ingenieros Eléctricos y Electrónicos) propuso el estándar IEEE-754 como estándar unificado para el formato de representación de números de punto flotante.

El estándar IEEE-754 utiliza lógicamente una terna {S, E, M} para representar el número de punto flotante Num.

S representa el bit de signo; 0 y 1 representan números positivos y negativos, respectivamente.

E representa la parte exponencial, denominada código sesgado. Para evitar exponentes positivos y negativos, el código sesgado se obtiene sumando un desplazamiento fijo al exponente. Por lo tanto, el exponente se puede obtener a partir del código sesgado: E - 2^(W-1) + 1. W es el ancho de bits del código sesgado. La base del exponente es 2.

M representa la mantisa. El bit más significativo de la mantisa siempre es 1, pero la parte de la mantisa no almacena ese bit, solo almacena la parte fraccionaria. Por lo tanto, el valor real representado por la mantisa es 1.M.

Se estipula que los números de punto flotante de precisión simple se almacenan en 4 bytes y los de doble precisión en 8 bytes. El diagrama es el siguiente.

Formato de precisión simple (32 bits): S, bit de signo, de 1 bit de ancho; E, exponente, de 8 bits de ancho, con un desplazamiento del exponente de 127 (7'h7F); M, mantisa, de 23 bits de ancho, representa la parte fraccionaria, y el punto decimal se coloca al inicio del campo de la mantisa.

Formato de doble precisión (64 bits): S, bit de signo, de 1 bit de ancho; E, exponente, de 11 bits de ancho, con un desplazamiento del exponente de 1023 (10'h3FF); M, mantisa, de 52 bits de ancho, representa la parte fraccionaria, y el punto decimal se coloca al inicio del campo de la mantisa.

El valor verdadero de un número de punto flotante N de 32 bits se puede expresar como:

Num = (-1)^S × (1.M) × 2 ^(E-127)

El valor verdadero de un número de punto flotante N de 64 bits se puede expresar como:

Num = (-1)^S × (1.M) × 2 ^(E-1023)

Por ejemplo, el decimal representado por el código binario 64'h4002_8000_0000_0000 correspondiente a un número de punto flotante de doble precisión es:

Num = (-1)^0 x  (1+ 8'h28/2**8) x 2^((12'h400 & 11'h7FF)-1023) = 2.3125

El proceso de cálculo de la mantisa anterior omite la serie de "0" posteriores y solo toma los primeros 8 bits significativos.

Por ejemplo, el proceso de representación binaria del número de punto flotante de doble precisión -13.14 es:

Se necesita 1 bit para representar el bit de signo.S = 1
Se necesitan 4 bits para representar la parte entera.13 = bin(1101) = bin(1.101) x 2^3
Se necesitan 11 bits para representar el exponente.E = 3 + 1023 = 11'h402
Se necesitan (52-3) bits para representar la parte fraccionaria.0.14 * 2^(52-3) = 78812993478983.688
≈ 78812993478984 = 49'h47ae147ae148
Se necesitan 52 bits para representar la mantisa: integrando las dos partes fraccionarias.M = (bin(101)<<49) + 49'h47ae147ae148
= 52'ha47ae147ae148
Código binario del número de punto flotante{S, E, M} = 32'hc02a_47ae_147a_e148

Y la variable de tipo real en Verilog es precisamente una variable de punto flotante de doble precisión de 64 bits según el estándar IEEE-754.

Funciones de conversión

Tarea de sistema invocadaDescripción de la tarea
int_val = $rtoi( real_val ) ;Conversión de real real_val a entero int_val
Por ejemplo, 3.14 -> 3
real_val = $itor( int_val ) ;Conversión de entero int_vla a real real_val
Por ejemplo, 3 -> 3.0
vec_val = $realtobits( real_val ) ;Conversión de un real a un vector de registro de múltiples bits
En el registro, los datos de punto flotante de doble precisión se almacenan según el estándar IEEE-754
real_val = $bitstoreal( vec_val ) ;Conversión de un vector de registro de múltiples bits a un real

El proceso de generación o conversión de variables de tipo real debe cumplir con el estándar IEEE Std 754-1985 [B1].

Utilice $realtobits y $bitstoreal para convertir los datos:

Ejemplo

   //real, bits
   reg [63:0]   num_bits ;
   initial begin
      num_bits  = 64'h4002_8000_0000_0000 ;
      $display("-14.13 -> hex: %h", $realtobits(-13.14));
      $display("64'h4002_8000_0000_0000 -> real: %f", $bitstoreal(num_bits));
   end

El log de simulación es el siguiente; se puede ver que la conversión es correcta.

Utilice $itor y $rtoi para realizar la conversión de formato de los datos:

Ejemplo

   //$itor, $rtoi
   initial begin
      $display();
      $display("Real to integer: %h", $rtoi(13.14));
      $display("Display integer in float: %f", 1001);
      $display("Integer to real: %f", $itor(1001));
   end

Según el siguiente log de simulación, cuando $rtoi convierte un real (13.14) a un entero (4'hd), solo toma la parte entera. Cuando $itor convierte un entero (1001) a un real (1001.000000), parece que no hay ningún cambio.

En realidad, la función de $rtoi y $itor es cambiar el método de almacenamiento de la variable.

Por ejemplo, cuando 14 se almacena como variable de tipo entero, su representación es 32'h1110; mientras que si se almacena como variable de tipo real, su representación es 64h402c_0000_0000_0000.
