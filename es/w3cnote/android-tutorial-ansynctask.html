3.7 Tarea asíncrona AsyncTask

Categoría Tutorial básico de introducción a Android

Introducción a esta sección:

En esta sección presentamos una clase ligera que Android nos proporciona para manejar tareas asíncronas: AsyncTask. Generalmente heredamos de AsyncTask, luego implementamos la operación asíncrona en la clase y después retroalimentamos el progreso de la ejecución asíncrona al hilo principal de la UI. Bueno, quizás algunos conceptos no los entiendan, creo que es necesario explicar el concepto de multihilo, ¡así que primero expliquemos algunas cosas conceptuales!

1. Conceptos relacionados

1) ¿Qué es el multihilo?

Respuesta: Primero hay que entender estos términos: aplicación, proceso, hilo, ¡¡multihilo!!

  • Aplicación (Application): un conjunto de instrucciones escritas en algún lenguaje para completar una tarea específica (un conjunto de código estático)
  • Proceso (Process) :un programa en ejecución, unaunidad independientede programación del sistema y asignación de recursos. El sistema operativo asigna un espacio de memoria a cada proceso; la ejecución dinámica secuencial del programa experimenta el proceso completo de carga de código -> ejecución -> finalización de la ejecución.
  • Hilo (Thread): una unidad de ejecución más pequeña que un proceso, cada proceso puede tener múltiples hilos,¡Un hilo necesita estar dentro de un proceso para poder ejecutarse!¡¡¡Los hilos son gestionados por el programa!!! ¡¡¡Mientras que los procesos son programados por el sistema!!!
  • Concepto de multihilo (Multithreading): ejecutar múltiples instrucciones en paralelo, dividir losintervalos de tiempode la CPU según el algoritmo de programación y asignarlos a cada hilo; en realidad esejecución por tiempo compartido, solo que el tiempo de conmutación es muy corto, ¡el usuario siente que es simultáneo!

Pongamos un ejemplo sencillo:Tienes QQ abierto y de repente quieres escuchar música, ¿necesitas cerrar QQ y luego iniciar el reproductor XX? La respuesta es no, simplemente abrimos el reproductor y ponemos la canción, QQ sigue ejecutándose, ¿verdad? Esto es multihilo simple. En el desarrollo real también hay ejemplos así: por ejemplo, mientras la aplicación se está ejecutando, se descubre una nueva versión y se quiere actualizar en segundo plano; en este momento generalmente creamos un hilo en segundo plano para descargar el APK de la nueva versión, pero mientras tanto todavía podemos usar otras funciones de la aplicación. ¡Este es un ejemplo de uso de multihilo!

2) Conceptos de síncrono y asíncrono:

Respuesta:Síncrono: cuando ejecutamos una función, mientras no se obtenga el resultado, ¡esta llamada no puede regresar! En términos simples, hay que esperar a que la primera cosa termine para poder hacer la siguiente. Un ejemplo sencillo: por ejemplo, si vas a tener relaciones sexuales, para evitar un embarazo, primero debes ponerte el condón y luego tener relaciones, ¿verdad? Condón puesto -> luego tener sexo. Si no tienes condón, entonces la acción de tener sexo debe esperar hasta que compres el condón y te lo pongas; en ese momento puedes comenzar. Un ejemplo gráfico, ♪(^∇^*)Asíncrono: es lo opuesto a síncrono. Después de ejecutar una función, no necesitamos obtener el resultado de inmediato; podemos realizar otras operaciones con normalidad. Esta función puede notificarnos o llamarnos mediante una devolución de llamada cuando se complete. Sigue siendo el ejemplo de descarga en segundo plano: después de ejecutar la función de descarga, no necesitamos preocuparnos por su proceso de descarga; cuando termine, solo tiene que notificarnos.

3) ¿Por qué Android introduce tareas asíncronas?

Respuesta: porque cuando un programa Android se inicia, también se inicia un hilo principal (Main Thread) correspondiente. Este hilo principal es el responsable de manejar los eventos relacionados con la UI. A veces también lo llamamos hilo de UI. Y en las aplicaciones Android debemos cumplir con las reglas de este modelo de un solo hilo:Las operaciones de UI de Android no son seguras para los hilos y estas operaciones deben ejecutarse en el hilo de UI.Si estamos en un hilo que no es de UI, por ejemplo, creamos otro hilo con new Thread() en el hilo principal y luego modificamos directamente el valor de un control de UI dentro de él, en este momento se lanzará la siguiente excepción:android.view.ViewRoot$CalledFromWrongThreadException: Only the original thread that created a view hierarchy can touch its viewsAdemás, hay otro punto: si ponemos todas las operaciones que consumen tiempo en el hilo de UI y el hilo de UI no responde a la solicitud durante más de 5 segundos, entonces se producirá una excepción ANR (Application Not Responding), es decir, la aplicación no responde. Finalmente, otro punto: después de Android 4.0, se prohíbe ejecutar operaciones de red en el hilo de UI; de lo contrario, se reportará:android.os.NetworkOnMainThreadException

Todas las razones anteriores explican el significado de que Android introduzca tareas asíncronas. Por supuesto, para implementar la asincronía también podemos no usar AsyncTask, que explicamos en esta sección; podemos crear nuestro propio hilo y, después de completar las operaciones relacionadas, actualizar la UI mediante los siguientes dos métodos:

  1. El Handler que aprendimos antes: escribimos la actualización de UI en el Handler y luego notificamos la actualización de UI mediante métodos como sendMessage(). Además, no olvides la diferencia entre escribir Handler en el hilo principal y en el hilo secundario.
  2. Usa Activity.runOnUiThread(Runnable) para crear el código de actualización de UI en un Runnable; al actualizar la UI, solo pasa el objeto Runnable.

2. Análisis completo de AsyncTask:

1) ¿Por qué usar AsyncTask?

Respuesta: podemos usar los dos métodos anteriores para completar nuestras operaciones asíncronas. Si las operaciones asíncronas que tenemos que escribir son muchas o bastante complicadas, ¿acaso vamos a usar new Thread() y luego notificar la actualización de la UI con los métodos anteriores? A los programadores les gusta ser perezosos. Ya que oficialmente nos proporcionan AsyncTask, una clase asíncrona ligera encapsulada, ¿por qué no usarla? Con unas pocas decenas de líneas de código podemos completar nuestra operación asíncrona, y el progreso es controlable. En comparación con Handler, AsyncTask es más simple y rápido. Por supuesto, esto solo es adecuado para operaciones asíncronas simples. Además, donde más se usan las operaciones asíncronas en la práctica son las operaciones de red, la carga de imágenes, la transferencia de datos, etc. AsyncTask puede satisfacer temporalmente las necesidades de los principiantes para escribir aplicaciones pequeñas. Pero cuando realmente se hacen proyectos en una empresa, usamos más frameworks de terceros, como Volley, OkHttp, android-async-http, XUtils, etc. En los tutoriales avanzados posteriores elegiremos 1 o 2 frameworks para aprender. Por supuesto, puedes buscar materiales para aprender por tu cuenta, ¡pero dominar AsyncTask sigue siendo muy necesario!

Definir una operación con retardo para simular la descarga:

public class DelayOperator {  
    //延时操作,用来模拟下载  
    public void delay()  
    {  
        try {  
            Thread.sleep(1000);  
        }catch (InterruptedException e){  
            e.printStackTrace();;  
        }  
    }  
}

Personalizar AsyncTask:

public class MyAsyncTask extends AsyncTask<Integer,Integer,String>  
{  
    private TextView txt;  
    private ProgressBar pgbar;  
  
    public MyAsyncTask(TextView txt,ProgressBar pgbar)  
    {  
        super();  
        this.txt = txt;  
        this.pgbar = pgbar;  
    }  
  
  
    //该方法不运行在UI线程中,主要用于异步操作,通过调用publishProgress()方法  
    //触发onProgressUpdate对UI进行操作  
    @Override  
    protected String doInBackground(Integer... params) {  
        DelayOperator dop = new DelayOperator();  
        int i = 0;  
        for (i = 10;i <= 100;i+=10)  
        {  
            dop.delay();  
            publishProgress(i);  
        }  
        return  i + params[0].intValue() + "";  
    }  
  
    //该方法运行在UI线程中,可对UI控件进行设置  
    @Override  
    protected void onPreExecute() {  
        txt.setText("开始执行异步线程~");  
    }  
  
  
    //在doBackground方法中,每次调用publishProgress方法都会触发该方法  
    //运行在UI线程中,可对UI控件进行操作  
  
  
    @Override  
    protected void onProgressUpdate(Integer... values) {  
        int value = values[0];  
        pgbar.setProgress(value);  
    }  
}

MainActivity.java：

public class MyActivity extends ActionBarActivity {  
  
    private TextView txttitle;  
    private ProgressBar pgbar;  
    private Button btnupdate;  
  
    @Override  
    protected void onCreate(Bundle savedInstanceState) {  
        super.onCreate(savedInstanceState);  
        setContentView(R.layout.activity_main);  
        txttitle = (TextView)findViewById(R.id.txttitle);  
        pgbar = (ProgressBar)findViewById(R.id.pgbar);  
        btnupdate = (Button)findViewById(R.id.btnupdate);  
        btnupdate.setOnClickListener(new View.OnClickListener() {  
            @Override  
            public void onClick(View v) {  
                MyAsyncTask myTask = new MyAsyncTask(txttitle,pgbar);  
                myTask.execute(1000);  
            }  
        });  
    }  
}
