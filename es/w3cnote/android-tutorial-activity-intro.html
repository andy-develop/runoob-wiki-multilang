2. Algunos conceptos de Activity, Task y Back Stack

A continuación, vamos a entender el mecanismo de gestión de Activity en Android, lo que involucra dos términos: ¡Task y Back Stack!

Análisis conceptual:

Nuestras aplicaciones generalmente se componen de múltiples Activities, y Android nos proporciona un concepto deTask (tarea)que consiste en reunir varias Activities relacionadas para luego realizar saltos y retornos entre Activities. Por supuesto, este Task es solo un concepto a nivel de framework, y la estructura de datos que implementa Task en Android esBack Stack (pila de retroceso)¡Seguro que no les resulta extraña la estructura de datos de pila; en Java también existe la clase de colección Stack! La pila tiene las siguientes características:

Último en entrar, primero en salir (LIFO); operaciones comunes: empujar a la pila (push), sacar de la pila (pop); lo que está en la parte superior se llama cima de la pila, y lo que está en la parte inferior se llama fondo de la pila.

Y la Back Stack en Android también tiene las características anteriores, y gestiona las Activity de la siguiente manera:

Cuando se cambia a una nueva Activity, esta Activity se introduce en la pila y se convierte en la cima. Cuando el usuario pulsa la tecla Back, la Activity en la cima sale de la pila, y la Activity que le sigue pasa a la cima.

Veamos un diagrama de flujo proporcionado por la documentación oficial:

Análisis del flujo:

En la aplicación existen tres activities: A1, A2 y A3. Cuando el usuario toca el icono de la aplicación en el Launcher o en la pantalla de inicio, se inicia la principal A1; luego A1 abre A2, y A2 abre A3. En este momento hay tres Activities en la pila, y estas tres Activities están por defecto en la misma tarea (Task). Cuando el usuario presiona atrás, se saca A3, quedando solo A1 y A2 en la pila; al presionar atrás de nuevo, se saca A2, quedando solo A1; al continuar presionando atrás, se saca A1, la tarea se elimina, ¡es decir, el programa sale!

Luego saqué una conclusión:

Task es una colección de Activities, es un concepto; en realidad se usa la Back Stack para almacenar las Activities. Puede haber múltiples Tasks, pero solo una pila está al frente al mismo tiempo; las demás están en segundo plano. ¿Entonces cómo se crea la pila?

Respuesta: cuando abrimos una nueva aplicación tocando su icono desde la pantalla principal, se crea una nueva Task. Por ejemplo:
Al abrir la aplicación tocando el icono de la app de contactos, en este momento se crea una nueva pila 1, y luego se comienzan a añadir las nuevas Activities que se generan. Puede que desde la app de contactos abramos la página de la app de SMS, pero en este momento no se crea una nueva pila, sino que se continúa añadiendo a la pila 1. Esto es un modo de experiencia de usuario que Android promueve: que el cambio entre diferentes aplicaciones haga sentir al usuario como si fuera la misma aplicación, una experiencia de usuario muy fluida; oficialmente se denomina seamless (sin costuras). —————— Si en este momento presionamos la tecla Home y volvemos a la pantalla principal, la pila 1 pasa a segundo plano. Entonces podemos tener las dos operaciones siguientes:
1) Pulsar la tecla de menú (ese botón cuadrado), tocar para abrir el programa reciente, y entonces la pila 1 vuelve al primer plano. O bien tocamos el icono de contactos en la pantalla principal para abrir la aplicación; en este caso tampoco se crea una nueva pila, y la pila 1 vuelve al primer plano.
2) Si en este momento tocamos otro icono para abrir una nueva aplicación, entonces se creará una nueva pila 2; la pila 2 pasará al primer plano, mientras que la pila 1 continúa en segundo plano.
3) Y así sucesivamente... ¡y así en adelante!

3. Gestión de Task

1) Traducción del documento:

1) Traducción del documento

Continuando con el documento, comenzando por "Managing Tasks" en la documentación, la traducción es la siguiente:

Como se mencionó anteriormente, Android añade las Activities recién iniciadas con éxito a la misma Task y gestiona múltiples Tasks y la Back Stack de manera "primero en entrar, primero en salir", de modo que el usuario no necesita preocuparse por cómo interactúan las Activities con las Tasks ni por cómo existen en la Back Stack. Quizás quieras cambiar esta forma normal de gestión. Por ejemplo, quieres que una de tus Activities se gestione en una nueva Task; o solo quieres instanciar una Activity; o quieres limpiar todas las Activities de la Task excepto la Activity raíz cuando el usuario abandona la tarea. Puedes hacer estas cosas y más, simplemente modificando los valores de atributos relevantes de <activity> en AndroidManifest.xml, o pasando un Intent con banderas especiales a startActivity() en el código, para lograr fácilmente la gestión de las Activities.

Los atributos que podemos usar en <activity> son los siguientes:

  • taskAffinity
  • launchMode
  • allowTaskReparenting
  • clearTaskOnLaunch
  • alwaysRetainTaskState
  • finishOnTaskLaunch

Los principales indicadores de Intent que puedes usar son:

  • FLAG_ACTIVITY_NEW_TASK
  • FLAG_ACTIVITY_CLEAR_TOP
  • FLAG_ACTIVITY_SINGLE_TOP

Bien, a continuación presentamos cómo se usan uno por uno:

2) taskAffinity y allowTaskReparenting

De forma predeterminada, en una aplicación,todas las activities tienen una Affinitylo que hace que pertenezcan a la misma Task. Puedes entenderlo como un indicador de si están en la misma Task. Sin embargo, cada Activity puede establecer una Affinity separada mediante el atributo taskAffinity en <activity>. Las Activities de diferentes aplicaciones pueden compartir la misma Affinity, y las diferentes Activities dentro de la misma aplicación también pueden configurarse con distintas Affinities. El atributo Affinity tiene efecto en dos casos:

1) Cuando el objeto Intent que inicia la activity contieneFLAG_ACTIVITY_NEW_TASKla bandera: Cuando el objeto Intent pasado a startActivity() contiene la bandera FLAG_ACTIVITY_NEW_TASK, el sistema busca para la Activity que se va a iniciar una Task diferente de la Activity actual. Si el atributo Affinity de la Activity a iniciar no es igual al atributo Affinity de ninguna de las Tasks actuales, el sistema crea una nueva Task con ese atributo Affinity y empuja la Activity a iniciar a la pila de la nueva Task; de lo contrario, empuja la Activity a la pila que tiene el mismo atributo Affinity.

2）allowTaskReparentingSi el atributo se establece en true. Si el atributo allowTaskReparenting de una activity es true, esta puede moverse de una Task (Task1) a otra Task (Task2) con la misma Affinity (cuando Task2 se lleva a primer plano). Si un archivo .apk contiene múltiples "aplicaciones" desde la perspectiva del usuario, es posible que necesites asignar diferentes valores de Affinity a esas Activities.

3）launchMode：

Cuatro valores opcionales. El modo de inicio es el núcleo de nuestro estudio; lo explicaremos en detalle más abajo. Son:standard(por defecto),singleTop，singleTask，singleInstance

4) Vaciar la pila

Cuando el usuario abandona la Task durante mucho tiempo (la task actual se mueve a segundo plano), el sistema elimina todas las Activities de la task excepto la Activity de la parte inferior de la pila. De este modo, cuando el usuario regresa a la Task, solo queda la Activity inicial de esa task. ¡Podemos cambiar este comportamiento modificando los siguientes atributos!

alwaysRetainTaskState: Si este atributo de la Activity de la parte inferior de la pila se establece en true, la situación anterior no ocurrirá. Todas las activities de la Task se conservarán durante mucho tiempo.

clearTaskOnLaunchSi el atributo de la activity de la parte inferior de la pila se establece en true, una vez que el usuario abandone la Task, las Activities de la pila de la Task se vaciarán hasta dejar solo la activity de la parte inferior. Esta situación es exactamente la contraria a alwaysRetainTaskState. Incluso si el usuario se va solo por un breve momento, la task volverá a su estado inicial (solo quedará la activity de la parte inferior).

finishOnTaskLaunchSimilar a clearTaskOnLaunch, pero solo opera sobre una activity individual, no sobre toda la Task. Puede finalizar cualquier Activity, incluida la Activity de la parte inferior de la pila. Cuando se establece en true, la Activity actual solo existe como parte de la Task durante la sesión actual; cuando el usuario sale de la Activity y regresa, esta ya no existirá.

Primero veamos el diagrama de resumen:

Detalle de los modos:

Modo standard:

Modo de inicio estándar, también es el modo de inicio predeterminado de las activities. Una activity iniciada en este modo puede ser instanciada múltiples veces, es decir, pueden existir varias instancias de una activity en la misma tarea, y cada instancia procesará un objeto Intent. Si el modo de inicio de la Activity A es standard, y A ya se ha iniciado, al iniciar la Activity A nuevamente dentro de A, es decir, llamar a startActivity(new Intent(this, A.class)), se iniciará otra instancia de A encima de A, es decir, el estado actual de la pila es A-->A.

Modo singleTop:

Si una instancia de una Activity iniciada en modo singleTop ya existe en la cima de la pila de tareas, al volver a iniciar esta Activity no se creará una nueva instancia, sino que se reutilizará la instancia situada en la cima, y se llamará al método de esa instanciaonNewIntent()para pasar el objeto Intent a esta instancia. Por ejemplo, si el modo de inicio de A es singleTop, y una instancia de A ya existe en la cima de la pila, al llamar a startActivity(new Intent(this, A.class)) para iniciar A, no se volverá a crear una instancia de A, sino que se reutilizará la instancia original y se llamará al método onNewIntent() de la instancia original. En ese momento, en la pila de tareas solo hay una instancia de A. Si una instancia de una activity iniciada en modo singleTop ya existe en la pila de tareas, pero no está en la cima, su comportamiento es el mismo que en el modo standard, y también se crearán múltiples instancias.

Modo singleTask:

Solo se permite una instancia de Activity en el sistema. Si ya existe una instancia en el sistema, la tarea que contiene esta instancia se moverá a la parte superior, y el intent se enviará a través de onNewIntent(). Si no existe, se creará una nueva Activity y se colocará en la tarea adecuada.

Un problema mencionado en la documentación oficial:

El sistema creará una nueva tarea e instanciará esta Activity como la raíz (root) de la nueva tarea. Esto requiere que configuremos taskAffinity. El resultado después de usar taskAffinity:

Modo singleInstance

Garantiza que, sin importar desde qué Task se inicie la Activity, el sistema solo creará una instancia de Activity, y la añadirá a la cima de la pila de la nueva Task. Es decir, otras activities iniciadas por esta instancia se ejecutarán automáticamente en otra Task. Cuando se vuelve a iniciar la instancia de esta activity, se reutilizarán la tarea y la instancia existentes. Y se llamará al método onNewIntent() de esta instancia para pasar la instancia de Intent a esta instancia. Igual que singleTask, en el sistema solo existirá una instancia de esta Activity al mismo tiempo.

5. Actividad complementaria

Puede haber algunas cosas sobre Activity que aún no se han mencionado. Aquí se reserva un espacio, y todo lo que se haya omitido se completará aquí. En primer lugar, siguiendo la sugerencia del compañero del grupo 珠海-坤, también pego la clase de gestión de Activity de OSChina (开源中国). Bueno, aquí está; todos pueden usarla directamente en sus proyectos~

1) Clase de gestión de Activity del cliente de OSChina:

package net.oschina.app;

import java.util.Stack;

import android.app.Activity;
import android.app.ActivityManager;
import android.content.Context;


public class AppManager {
    
    private static Stack<Activity> activityStack;
    private static AppManager instance;
    
    private AppManager(){}
    /**
     * 单一实例
     */
    public static AppManager getAppManager(){
        if(instance==null){
            instance=new AppManager();
        }
        return instance;
    }
    /**
     * 添加Activity到堆栈
     */
    public void addActivity(Activity activity){
        if(activityStack==null){
            activityStack=new Stack<Activity>();
        }
        activityStack.add(activity);
    }
    /**
     * 获取当前Activity（堆栈中最后一个压入的）
     */
    public Activity currentActivity(){
        Activity activity=activityStack.lastElement();
        return activity;
    }
    /**
     * 结束当前Activity（堆栈中最后一个压入的）
     */
    public void finishActivity(){
        Activity activity=activityStack.lastElement();
        finishActivity(activity);
    }
    /**
     * 结束指定的Activity
     */
    public void finishActivity(Activity activity){
        if(activity!=null){
            activityStack.remove(activity);
            activity.finish();
            activity=null;
        }
    }
    /**
     * 结束指定类名的Activity
     */
    public void finishActivity(Class<?> cls){
        for (Activity activity : activityStack) {
            if(activity.getClass().equals(cls) ){
                finishActivity(activity);
            }
        }
    }
    /**
     * 结束所有Activity
     */
    public void finishAllActivity(){
        for (int i = 0, size = activityStack.size(); i < size; i++){
            if (null != activityStack.get(i)){
                activityStack.get(i).finish();
            }
        }
        activityStack.clear();
    }
    /**
     * 退出应用程序
     */
    public void AppExit(Context context) {
        try {
            finishAllActivity();
            ActivityManager activityMgr= (ActivityManager) context.getSystemService(Context.ACTIVITY_SERVICE);
            activityMgr.restartPackage(context.getPackageName());
            System.exit(0);
        } catch (Exception e) {    }
    }
}

Resumen de esta sección:

Bien, esto es todo por esta sección. El contenido es bastante difícil de entender; por ahora solo necesitas saberlo. Resumamos las operaciones relacionadas con la programación general de las Tasks:

  • Pulsar la tecla Home para pasar la Task anterior a segundo plano.
  • Mantener pulsada la tecla Home para mostrar la lista de Tasks ejecutadas recientemente.
  • Hacer clic en el icono de la app en el Launcher o en la pantalla de inicio (HomeScreen) para abrir una nueva Task, o llevar una Task existente al primer plano.
  • Al iniciar una Activity en modo singleTask, el sistema buscará si ya existe una Task adecuada en el sistema. Si existe, llevará esta Task al primer plano para reutilizarla. Si en esta Task ya existe una instancia de la Activity que se va a iniciar, se eliminarán todas las Activities que estén por encima de esta instancia y se mostrará esta instancia al usuario. Si en la Task existente no hay una instancia de la Activity que se va a iniciar, se iniciará una instancia en la parte superior de esta Task. Si esta Task no existe, se iniciará una nueva Task, y en esta nueva Task se iniciará una instancia de la Activity en modo singleTask.
  • Al iniciar una Activity en modo singleInstance, el sistema buscará si ya existe una instancia de esta Activity en el sistema. Si existe, llevará al primer plano la Task donde se encuentra esta instancia y reutilizará esta instancia de Activity (en esa Task solo está esta Activity). Si no existe, se abrirá una nueva tarea, y en esta nueva Task se iniciará una instancia de la Activity en modo singleInstance.
