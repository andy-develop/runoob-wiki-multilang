Decoradores de funciones en Python

Categorías Técnicas de programación

Los decoradores (Decorators) son una parte importante de Python. En pocas palabras: son funciones que modifican la funcionalidad de otras funciones. Ayudan a que nuestro código sea más corto y más "Pythonic" (con estilo Python). La mayoría de los principiantes no saben dónde usarlos, así que voy a compartir en qué áreas los decoradores pueden hacer tu código más limpio. Primero, vamos a discutir cómo escribir tus propios decoradores.

Este es probablemente uno de los conceptos más difíciles de dominar. Lo discutiremos paso a paso, para que puedas entenderlo completamente.

Todo es un objeto

Primero, entendamos las funciones en Python:

def hi(name="yasoob"): return "hi " + name print(hi()) # output: 'hi yasoob' # Incluso podemos asignar una función a una variable, por ejemplo greet = hi # Aquí no estamos usando paréntesis, porque no estamos llamando a la función hi # Sino que la estamos colocando dentro de la variable greet. Intentemos ejecutar esto print(greet()) # output: 'hi yasoob' # Si eliminamos la función hi anterior, ¡veamos qué sucede! del hi print(hi()) #outputs: NameError print(greet()) #outputs: 'hi yasoob'

Definir funciones dentro de funciones

Eso son los conceptos básicos de las funciones. Llevemos tu conocimiento un paso más allá. En Python podemos definir otra función dentro de una función:

def hi(name="yasoob"): print("now you are inside the hi() function") def greet(): return "now you are in the greet() function" def welcome(): return "now you are in the welcome() function" print(greet()) print(welcome()) print("now you are back in the hi() function") hi() #output:now you are inside the hi() function # now you are in the greet() function # now you are in the welcome() function # now you are back in the hi() function # Lo anterior muestra que cada vez que llames a hi(), greet() y welcome() serán llamadas a la vez. # Luego, las funciones greet() y welcome() no son accesibles fuera de la función hi(), por ejemplo: greet() #outputs: NameError: name 'greet' is not defined

Ahora sabemos que podemos definir otras funciones dentro de una función. Es decir, podemos crear funciones anidadas. Ahora necesitas aprender un poco más: las funciones también pueden devolver funciones.

Devolver funciones desde una función

En realidad, no es necesario ejecutar otra función dentro de una función; también podemos devolverla como salida:

def hi(name="yasoob"): def greet(): return "now you are in the greet() function" def welcome(): return "now you are in the welcome() function" if name == "yasoob": return greet else: return welcome a = hi() print(a) #outputs: <function greet at 0x7f2143c01500> # Lo anterior muestra claramente que `a` ahora apunta a la función greet() dentro de la función hi() # Ahora prueba esto print(a()) #outputs: now you are in the greet() function

Mira este código otra vez. En la sentencia if/else devolvemos greet y welcome, no greet() y welcome(). ¿Por qué? Porque cuando pones un par de paréntesis después, la función se ejecuta; sin embargo, si no le pones paréntesis, se puede pasar por todas partes y asignarse a otras variables sin ejecutarla. ¿Lo entiendes? Déjame explicarlo con un poco más de detalle.

  • Cuando escribimosa = hi()，hi()se ejecutará, y como el parámetro name por defecto es yasoob, la funcióngreet()es devuelta.

  • También podemos imprimirhi()(), esto mostrará:now you are in the greet() function。

  • Si cambiamos la sentencia aa = hi(name = "ali"), entonceswelcome()la función será devuelta.

Pasar una función como argumento a otra función

def hi(): return "hi yasoob!" def doSomethingBeforeHi(func): print("I am doing some boring work before executing hi()") print(func()) doSomethingBeforeHi(hi) #outputs:I am doing some boring work before executing hi() # hi yasoob!

Ahora tienes todo el conocimiento necesario para aprender qué son realmente los decoradores. Los decoradores te permiten ejecutar código antes y después de una función.

Tu primer decorador

En el ejemplo anterior, ¡ya hemos creado un decorador! Ahora modifiquemos el decorador anterior y escribamos un programa un poco más útil:

def a_new_decorator(a_func): def wrapTheFunction(): print("I am doing some boring work before executing a_func()") a_func() print("I am doing some boring work after executing a_func()") return wrapTheFunction def a_function_requiring_decoration(): print("I am the function which needs some decoration to remove my foul smell") a_function_requiring_decoration() #outputs: "I am the function which needs some decoration to remove my foul smell" a_function_requiring_decoration = a_new_decorator(a_function_requiring_decoration) #now a_function_requiring_decoration is wrapped by wrapTheFunction() a_function_requiring_decoration() #outputs:I am doing some boring work before executing a_func() # I am the function which needs some decoration to remove my foul smell # I am doing some boring work after executing a_func()

¿Lo ves? Acabamos de aplicar los principios que aprendimos antes. ¡Esto es exactamente lo que hacen los decoradores en Python! Envuelven una función y modifican su comportamiento de una forma u otra. Ahora quizás te preguntes, en nuestro código no usamos el símbolo@¿símbolo? Eso es solo una forma abreviada de generar una función decorada. Aquí es cómo usamos@para ejecutar el código anterior:

@a_new_decorator def a_function_requiring_decoration(): """Hey you! Decorate me!""" print("I am the function which needs some decoration to " "remove my foul smell") a_function_requiring_decoration() #outputs: I am doing some boring work before executing a_func() # I am the function which needs some decoration to remove my foul smell # I am doing some boring work after executing a_func() #the @a_new_decorator is just a short way of saying: a_function_requiring_decoration = a_new_decorator(a_function_requiring_decoration)

Espero que ahora tengas una comprensión básica de cómo funcionan los decoradores de Python. Si ejecutamos el siguiente código, hay un problema:

print(a_function_requiring_decoration.__name__)
# Output: wrapTheFunction

¡Esto no es lo que queríamos! La salida (Output) debería ser "a_function_requiring_decoration". Aquí la función fue reemplazada por warpTheFunction. Sobrescribió el nombre de nuestra función y la cadena de documentación (docstring). Afortunadamente, Python nos proporciona una función simple para resolver este problema: functools.wraps. Modifiquemos el ejemplo anterior para usar functools.wraps:

from functools import wraps def a_new_decorator(a_func): @wraps(a_func) def wrapTheFunction(): print("I am doing some boring work before executing a_func()") a_func() print("I am doing some boring work after executing a_func()") return wrapTheFunction @a_new_decorator def a_function_requiring_decoration(): """Hey yo! Decorate me!""" print("I am the function which needs some decoration to " "remove my foul smell") print(a_function_requiring_decoration.__name__) # Output: a_function_requiring_decoration

Ahora es mucho mejor. A continuación, aprendamos algunos casos de uso comunes de los decoradores.

Plantilla estándar:

from functools import wraps def decorator_name(f): @wraps(f) def decorated(*args, **kwargs): if not can_run: return "Function will not run" return f(*args, **kwargs) return decorated @decorator_name def func(): return("Function is running") can_run = True print(func()) # Output: Function is running can_run = False print(func()) # Output: Function will not run

Nota:@wrapsAcepta una función para decorarla y agrega funcionalidades como copiar el nombre de la función, la cadena de documentación, la lista de parámetros, etc. Esto nos permite acceder a los atributos de la función antes de ser decorada desde dentro del decorador.

Casos de uso

Ahora veamos dónde brillan especialmente los decoradores y cómo usarlos puede hacer que algunas cosas sean más fáciles de manejar.

Autorización (Authorization)

Los decoradores pueden ayudar a verificar si una persona está autorizada para usar un endpoint de una aplicación web. Se usan ampliamente en los frameworks web Flask y Django. Aquí hay un ejemplo de uso de autorización basada en decoradores:

from functools import wraps def requires_auth(f): @wraps(f) def decorated(*args, **kwargs): auth = request.authorization if not auth or not check_auth(auth.username, auth.password): authenticate() return f(*args, **kwargs) return decorated

Registro (Logging)

El registro (logging) es otro punto destacado del uso de decoradores. Este es un ejemplo:

from functools import wraps def logit(func): @wraps(func) def with_logging(*args, **kwargs): print(func.__name__ + " was called") return func(*args, **kwargs) return with_logging @logit def addition_func(x): """Do some math.""" return x + x result = addition_func(4) # Output: addition_func was called

Apuesto a que ya estás pensando en otro uso inteligente de los decoradores.

Decoradores con parámetros

Pensemos en esta cuestión: ¿no es @wraps también un decorador? Pero recibe un argumento, como cualquier función normal puede hacer. Entonces, ¿por qué no hacemos lo mismo? Esto es porque cuando usas la sintaxis @my_decorator, estás aplicando una función envolvente que toma una sola función como argumento. Recuerda, en Python todo es un objeto, ¡y esto incluye a las funciones! Con esto en mente, podemos escribir funciones que devuelvan una función envolvente.

Incrustando decoradores en funciones

Volvamos al ejemplo del registro y creemos una función envolvente que nos permita especificar un archivo de registro para la salida.

from functools import wraps def logit(logfile='out.log'): def logging_decorator(func): @wraps(func) def wrapped_function(*args, **kwargs): log_string = func.__name__ + " was called" print(log_string) # Abrir el archivo de registro y escribir el contenido with open(logfile, 'a') as opened_file: # Ahora envía el registro al archivo de registro especificado opened_file.write(log_string + '\n') return func(*args, **kwargs) return wrapped_function return logging_decorator @logit() def myfunc1(): pass myfunc1() # Output: myfunc1 was called # Ahora aparece un archivo llamado out.log, cuyo contenido es la cadena anterior @logit(logfile='func2.log') def myfunc2(): pass myfunc2() # Output: myfunc2 was called # Ahora aparece un archivo llamado func2.log, cuyo contenido es la cadena anterior

Clases de decoradores

Ahora tenemos un decorador logit apto para producción, pero cuando ciertas partes de nuestra aplicación todavía son frágiles, las excepciones pueden ser algo que requiera atención más urgente. Por ejemplo, a veces solo quieres registrar en un archivo. Pero a veces quieres enviar un correo electrónico con el problema que llama tu atención, manteniendo también el registro como constancia. Este es un escenario para usar herencia, pero hasta ahora solo hemos visto funciones para construir decoradores.

Afortunadamente, las clases también se pueden usar para construir decoradores. Entonces, ahora reconstruyamos logit usando una clase en lugar de una función.

from functools import wraps class logit(object): def __init__(self, logfile='out.log'): self.logfile = logfile def __call__(self, func): @wraps(func) def wrapped_function(*args, **kwargs): log_string = func.__name__ + " was called" print(log_string) # Abrir el archivo de registro y escribir with open(self.logfile, 'a') as opened_file: # Ahora envía el registro al archivo especificado opened_file.write(log_string + '\n') # Ahora, envía una notificación self.notify() return func(*args, **kwargs) return wrapped_function def notify(self): # logit solo registra, no hace nada más pass

Esta implementación tiene una ventaja adicional: es más limpia que el enfoque de funciones anidadas, y envuelve una función con la misma sintaxis de antes:

@logit()
def myfunc1():
    pass

Ahora, creemos una subclase de logit para añadir la funcionalidad de email (aunque el tema del email no se desarrollará aquí).

class email_logit(logit): '''Una versión de logit que puede enviar un email al administrador cuando se llama a la función''' def __init__(self, email='admin@myproject.com', *args, **kwargs): self.email = email super(email_logit, self).__init__(*args, **kwargs) def notify(self): # Enviar un email a self.email # Aquí no se implementa pass

A partir de ahora, @email_logit tendrá el mismo efecto que @logit, pero además de registrar, enviará un correo electrónico al administrador.

    Antes de hablar de los decoradores de Python, quiero poner un ejemplo, aunque es un poco subido de tono, encaja muy bien con el tema de los decoradores.

    La función principal de la ropa interior que todos tenemos es cubrir las partes íntimas, pero en invierno no puede protegernos del viento ni del frío. ¿Qué hacemos? Una solución que se nos ocurrió es modificar la ropa interior para hacerla más gruesa y más larga. De esta manera, no solo mantiene la función de cubrir, sino que también proporciona abrigo. Sin embargo, hay un problema: después de convertir la ropa interior en pantalones largos, aunque sigue teniendo función de cubrir, en esencia ya no es una verdadera ropa interior. Entonces la gente inteligente inventó los pantalones largos y, sin afectar a la ropa interior, se los puso directamente por fuera. Así, la ropa interior sigue siendo ropa interior, y con los pantalones largos el bebé ya no pasa frío. El decorador es como los pantalones largos de los que hablamos: sin afectar a la función de la ropa interior, proporciona abrigo a nuestro cuerpo.

    Antes de hablar de los decoradores, primero hay que entender una cosa: las funciones en Python no son como en Java o C++. En Python, una función puede pasarse como parámetro a otra función, igual que una variable normal. Por ejemplo:

    def foo():
    print("foo")

def bar(func):
    func()

bar(foo)

    Volvamos formalmente a nuestro tema. Un decorador es, en esencia, una función o clase de Python que permite a otras funciones o clases añadir funcionalidades adicionales sin necesidad de realizar ninguna modificación en el código. El valor de retorno de un decorador también es un objeto de función/clase. Se utiliza a menudo en escenarios que requieren aspectos transversales, como inserción de registros, pruebas de rendimiento, gestión de transacciones, caché, verificación de permisos, etc. El decorador es un diseño excelente para resolver este tipo de problemas. Con los decoradores, podemos extraer una gran cantidad de código repetido que no tiene relación directa con la función en sí, e introducirlo en el decorador para reutilizarlo. En resumen, la función del decorador es añadir funcionalidades adicionales a objetos ya existentes.

    Veamos primero un ejemplo sencillo, aunque el código real puede ser mucho más complejo:

    def foo():
    print('i am foo')

    Ahora hay un nuevo requisito: queremos registrar el log de ejecución de la función, así que añadimos código de logging al código:

    def foo():
    print('i am foo')
    logging.info("foo is running")

    Si las funciones bar() y bar2() también tienen requisitos similares, ¿qué hacemos? ¿Escribir otro logging dentro de la función bar? Eso generaría una gran cantidad de código repetido. Para reducir la duplicación de código, podemos hacer lo siguiente: definir una nueva función que se encargue específicamente del log; después de procesar el log, se ejecuta el código de negocio real.

    def use_logging(func):
    logging.warn("%s is running" % func.__name__)
    func()

def foo():
    print('i am foo')

use_logging(foo)

    Lógicamente, no hay problema y la funcionalidad se implementa, pero al llamar ya no invocamos la función foo, que es la lógica de negocio real, sino que usamos la función use_logging, lo que rompe la estructura original del código. Ahora tenemos que pasar la función foo original como parámetro a use_logging cada vez. Entonces, ¿hay una mejor manera? Por supuesto que la hay: la respuesta es el decorador.

    Decorador simple

    def use_logging(func):

    def wrapper():
        logging.warn("%s is running" % func.__name__)
        return func()   # 把 foo 当做参数传递进来时，执行func()就相当于执行foo()
    return wrapper

def foo():
    print('i am foo')

foo = use_logging(foo)  # 因为装饰器 use_logging(foo) 返回的时函数对象 wrapper，这条语句相当于  foo = wrapper
foo()                   # 执行foo()就相当于执行 wrapper()

    use_logging es un decorador, una función normal que envuelve a la función func que ejecuta la lógica de negocio real. Parece como si foo fuera decorada por use_logging. use_logging también devuelve una función, y esa función se llama wrapper. En este ejemplo, la entrada y la salida de la función forman lo que se llama un aspecto transversal; esta forma de programación se conoce como programación orientada a aspectos.

    @ Azúcar sintáctico

    Si has estado en contacto con Python durante un tiempo, seguro que el símbolo @ no te resulta desconocido. Efectivamente, el símbolo @ es el azúcar sintáctico del decorador. Se coloca en el lugar donde se define la función, de modo que se puede omitir el último paso de asignación.

    def use_logging(func):

    def wrapper():
        logging.warn("%s is running" % func.__name__)
        return func()
    return wrapper

@use_logging
def foo():
    print("i am foo")

foo()

    Como se muestra arriba, con @ podemos omitir la línea foo = use_logging(foo) y llamar directamente a foo() para obtener el resultado deseado. ¿Lo veis? La función foo() no necesita ninguna modificación; solo hay que añadir el decorador en el lugar de la definición, y la llamada sigue siendo igual que antes. Si tenemos otras funciones similares, podemos seguir usando el decorador para decorar funciones, sin tener que modificarlas repetidamente ni añadir nuevas envolturas. Así mejoramos la reutilización del programa y aumentamos su legibilidad.

    La gran comodidad de los decoradores en Python se debe a que las funciones de Python pueden, como los objetos normales, pasarse como parámetros a otras funciones, asignarse a otras variables, servir como valor de retorno y definirse dentro de otra función.

    *args、**kwargs

    Alguien puede preguntar: ¿y si mi función de lógica de negocio foo necesita parámetros? Por ejemplo:

    def foo(name):
    print("i am %s" % name)

    Podemos especificar los parámetros al definir la función wrapper:

    def wrapper(name):
        logging.warn("%s is running" % func.__name__)
        return func(name)
    return wrapper

    De esta manera, los parámetros definidos por la función foo pueden definirse en la función wrapper. En ese momento, alguien volverá a preguntar: ¿y si la función foo recibe dos parámetros? ¿Y tres? Incluso podría recibir muchísimos. Cuando el decorador no sabe cuántos parámetros tiene foo, podemos usar *args en su lugar:

    def wrapper(*args):
        logging.warn("%s is running" % func.__name__)
        return func(*args)
    return wrapper

    De este modo, no importa cuántos parámetros defina foo, puedo pasarlos todos completos a func. Así no se afecta la lógica de negocio de foo. Algunos lectores preguntarán entonces: ¿y si la función foo también define algunos parámetros de palabra clave? Por ejemplo:

    def foo(name, age=None, height=None):
    print("I am %s, age %s, height %s" % (name, age, height))

    En ese caso, puedes especificar parámetros de palabra clave en la función wrapper:

    def wrapper(*args, **kwargs):
        # args是一个数组，kwargs一个字典
        logging.warn("%s is running" % func.__name__)
        return func(*args, **kwargs)
    return wrapper

    Decorador con parámetros

    Los decoradores tienen una flexibilidad aún mayor, como los decoradores con parámetros. En la llamada al decorador anterior, el único parámetro que recibía era la función foo que ejecuta el negocio. La sintaxis de los decoradores nos permite proporcionar otros parámetros en la llamada, como @decorator(a). Esto ofrece una mayor flexibilidad tanto para escribir como para usar decoradores. Por ejemplo, podemos especificar en el decorador el nivel de log, porque distintas funciones de negocio pueden necesitar niveles de logging diferentes.

    def use_logging(level):
    def decorator(func):
        def wrapper(*args, **kwargs):
            if level == "warn":
                logging.warn("%s is running" % func.__name__)
            elif level == "info":
                logging.info("%s is running" % func.__name__)
            return func(*args)
        return wrapper

    return decorator

@use_logging(level="warn")
def foo(name='foo'):
    print("i am %s" % name)

foo()

    El use_logging anterior es un decorador que admite parámetros. En realidad es una envoltura de función sobre el decorador original, y devuelve un decorador. Podemos entenderlo como un cierre que contiene parámetros. Cuando lo llamamos con @use_logging(level="warn"), Python es capaz de detectar esta capa de envoltura y pasar los parámetros al entorno del decorador.

    @use_logging(level="warn")Equivale a@decorator

    Decorador de clase

    Así es, un decorador no solo puede ser una función, sino también una clase. En comparación con los decoradores de función, los decoradores de clase tienen ventajas como mayor flexibilidad, alta cohesión y encapsulamiento. El uso de un decorador de clase se basa principalmente en el método __call__ de la clase; cuando se aplica el decorador a una función mediante la forma @, se invoca este método.

    class Foo(object):
    def __init__(self, func):
        self._func = func

    def __call__(self):
        print ('class decorator runing')
        self._func()
        print ('class decorator ending')

@Foo
def bar():
    print ('bar')

bar()
functools.wraps

    El uso de decoradores reutiliza enormemente el código, pero tiene un inconveniente: la metainformación de la función original desaparece, como el docstring, __name__ y la lista de parámetros de la función. Veamos un ejemplo:

    # 装饰器
def logged(func):
    def with_logging(*args, **kwargs):
        print func.__name__      # 输出 'with_logging'
        print func.__doc__       # 输出 None
        return func(*args, **kwargs)
    return with_logging

# 函数
@logged
def f(x):
   """does some math"""
   return x + x * x

logged(f)

    No es difícil darse cuenta de que la función f es reemplazada por with_logging. Por supuesto, su docstring y __name__ se convierten en la información de la función with_logging. Afortunadamente tenemos functools.wraps. wraps también es un decorador que copia la metainformación de la función original a la función func dentro del decorador, de modo que la función func dentro del decorador también tiene la misma metainformación que la función original foo.

    from functools import wraps
def logged(func):
    @wraps(func)
    def with_logging(*args, **kwargs):
        print func.__name__      # 输出 'f'
        print func.__doc__       # 输出 'does some math'
        return func(*args, **kwargs)
    return with_logging

@logged
def f(x):
   """does some math"""
   return x + x * x

            return func(*args, **kwargs)
            WrapsDecorator.__name__=fWrap.__name__
            WrapsDecorator.__doc__=fWrap.__doc__
        return WrapsDecorator
    return TmpWraps

    Además, este decorador no solo copia la metainformación de la función como __name__ y __doc__, sino que también copia mucha otra información. El código de implementación correcto es el siguiente:

    def mywraps(fwrap):
    def TmpWraps(func):
        def dec(**args):
            return func(**args)
        meta_info=['__module__', '__name__', '__qualname__', '__doc__', '__annotations__']
        for meta in meta_info:
            setattr(dec,meta,getattr(fwrap,meta))
        #逐个获取fwrap函数的元信息，并复制到dec函数上
        return dec
    return TmpWraps

    Además, para el decorador de clase, quizá la siguiente explicación sea más amigable para los principiantes:

    El decorador también se puede implementar mediante una clase. En realidad, se aprovechan principalmente las siguientes características de la clase para implementar indirectamente la funcionalidad de un decorador de función:

    La sintaxis de llamada de función f() es equivalente a la instanciación de la clase, es decir, llamar a la función __init__ de la clase para crear un objeto.

    La llamada al objeto obj() equivale a ejecutar el método mágico __call__ del objeto.

    Implementar el decorador mediante una clase puede evitar el anidamiento de más de 2 capas que se da en el decorador de función, porque si hay tres capas, la función más externa puede considerarse como la llamada a la función __init__ de la clase. Esto hace que el código sea más fácil de leer y mantener.

    En esencia, basta con implementar los métodos mágicos __init__ y __call__ de la clase, recibir los parámetros del decorador en la función __init__ e implementar la estructura concreta del decorador en la función __call__.

    A continuación se muestra un ejemplo de uso de una clase para implementar un decorador con parámetros; se puede observar la diferencia.

    from functools import wraps 
#定义一个装饰器名称的类
class  with_para_decorator: 
    #在类的__init__函数内接受装饰器参数，并赋值给类的实例参数，这样可以让其他函数随时使用
    #当然，如果装饰器没有参数，此处不转a,b即可，相当于类无参实例化
    def __init__(self,a,b):    
        self.a=a
        self.b=b
    #在类的__call__函数内接受被装饰函数，并具体定义装饰器
    def __call__(self,func):   
    @wraps(func)   
    def wrap_function(arg1,arg2):  
        print('装饰带参数的函数，函数传的参数为：{0}, {1}'.format(arg1,arg2))
        print('带参数的装饰器，装饰器传的参数为：{0}, {1}'.format(self.a,self.b))
        return func(arg1,arg2)   
    return wrap_function
#使用装饰器
@with_para_decorator(1,2)  
def need_decorate(a,b):   
pass
need_decorate(4,5)

    El análisis del principio concreto del código anterior es el siguiente:

    • @with_para_decorator(1,2), como es el nombre de la clase, equivale a usar los parámetros (1,2) para crear y devolver una instancia de la clase, por ejemplo, obj.
    • En este momento, la sintaxis se convierte en @obj, lo que equivale a need_decorate=obj(need_decorate); entonces se invoca el método mágico obj.__call__, y en ese método mágico implementamos concretamente la funcionalidad del decorador.
    • Se puede ver que su principio de funcionamiento esencial no es diferente del decorador de función; solo transforma el anidamiento de tres funciones en un anidamiento de dos niveles entre una función __init__ y una función __call__.
    • Al compararlos, se puede ver que el decorador de clase tiene un código más intuitivo.
