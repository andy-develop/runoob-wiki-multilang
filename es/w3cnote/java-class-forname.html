Explicación detallada de Java class.forname

Categoría Tecnología de programación

Para la mayoría de las personas, la primera vez que venclass.forName(String className)esta línea de código debería ser cuando se utilizaJDBCel método de conexión a la base de datos.

Ejemplo

import com.mysql.jdbc.Driver; import java.sql.*; public class JdbcDemo { public static void main(String[] args) throws SQLException, ClassNotFoundException { String url = "jdbc:mysql://127.0.0.1:3306/mydb"; String username = "root"; String password = "redhat"; Class.forName("com.mysql.jdbc.Driver"); Connection connection = DriverManager.getConnection(url, username, password); String sql = "SELECT * FROM msg"; PreparedStatement prepareStatement = connection.prepareStatement(sql); ResultSet resultSet = prepareStatement.executeQuery(); resultSet.next(); String address = resultSet.getString("address"); System.out.println(address); } }

Class.forNameDespués de pasar com.mysql.jdbc.Driver, se sabe que la base de datos a la que me conecto es mysql. ¿Por qué es esto? Miremos el código fuente:

@CallerSensitive public static Class<?> forName(String className) throws ClassNotFoundException { Class<?> caller = Reflection.getCallerClass(); return forName0(className, true, ClassLoader.getClassLoader(caller), caller); }

Se descubre que llama al método forName0. Continuemos rastreando para ver:

private static native Class<?> forName0(String name, boolean initialize, ClassLoader loader, Class<?> caller) throws ClassNotFoundException;

Al ser un método nativo, el código fuente solo puede llegar hasta aquí. Miremos de nuevo la descripción de la documentación oficial:https://docs.oracle.com/javase/7/docs/api/java/lang/Class.html#forName(java.lang.String)

Returns the Class object associated with the class or interface with the given string name, using the given class loader. Given the fully qualified name for a class or interface (in the same format returned by getName) this method attempts to locate, load, and link the class or interface. The specified class loader is used to load the class or interface. If the parameter loader is null, the class is loaded through the bootstrap class loader. The class is initialized only if the initialize parameter is true and if it has not been initialized earlier.

Una traducción aproximada es: devuelve un objeto Class de una clase o interfaz dada. Si no se proporciona un classloader, se utilizará el cargador de clases raíz. Si el parámetro initalize se pasa como true, entonces la clase dada, si no ha sido inicializada previamente, será inicializada. Cuando dimos el primer paso en JDBC, el parámetro que se pasó fue com.mysql.jdbc.Driver. Es decir, esta clase será inicializada. Veamos el contenido de esta clase:

public class Driver extends NonRegisteringDriver implements java.sql.Driver { static { try { java.sql.DriverManager.registerDriver(new Driver()); } catch (SQLException E) { throw new RuntimeException("Can't register driver!"); } } public Driver() throws SQLException { // Required for Class.forName().newInstance() } }

Descubrimos que esta clase también es súper simple. Una constructora y un bloque de código estático. Sabemos que cuando la clase se inicializa, el contenido del bloque de código estático se ejecutará. Es decir, nosotrosClass.forNamey escribir directamenteDriverManager.registerDriver(new Driver)Las funciones de ambos son equivalentes. Cambiemos a esta forma y probemos de nuevo:

public class JdbcDemo { public static void main(String[] args) throws SQLException, ClassNotFoundException { String url = "jdbc:mysql://127.0.0.1:3306/mydb"; String username = "root"; String password = "redhat"; //Class.forName("com.mysql.jdbc.Driver"); DriverManager.registerDriver(new Driver()); Connection connection = DriverManager.getConnection(url, username, password); String sql = "SELECT * FROM msg"; PreparedStatement prepareStatement = connection.prepareStatement(sql); ResultSet resultSet = prepareStatement.executeQuery(); resultSet.next(); String address = resultSet.getString("address"); System.out.println(address); } }

Descubrimos que el código aún se ejecuta normalmente.

Resumiendo: Class.forNameLa función del método es inicializar la clase dada. Y en la clase Driver de MySQL que proporcionamos, en el bloque de código estático se registra el controlador mediante el DriverManager de JDBC. También podemos usar directamente el administrador de controladores de JDBC para registrar el controlador mysql, reemplazando así el uso deClass.forName。

    Comprender Class.forName()

    Concepto de la clase Class

    Class también es una clase Java; guarda la meta información (metainformación) de la clase Java correspondiente, que se usa para describir la estructura de esta clase, por ejemplo, describir qué miembros tiene una clase, qué métodos tiene, etc. Generalmente se usa en reflexión.

    Explicación detallada:El programa fuente de Java (archivo .java), después de ser compilado por el compilador de Java, se convierte en código de bytes de Java (archivo .class). El cargador de clases se encarga de leer el código de bytes de Java y convertirlo en una instancia de la clase java.lang.Class (objeto Class). Es decir, en Java, cada clase Java tiene un objeto Class correspondiente, que se utiliza para representar la información de tipo de esta clase Java.

    Concepto de carga de clases

    Cuando se usa una clase (por ejemplo, al crear una instancia de una clase con new), se comprueba si esta clase se ha cargado en memoria. Si no, se ejecuta la operación de carga.

    Lee los datos del archivo class correspondiente a la clase, analiza estos datos y construye una instancia de la clase Class correspondiente a esta clase. En este momento, la JVM puede usar esta clase, por ejemplo, instanciarla o llamar a sus métodos estáticos.

    Java también proporciona interfaces para cargar clases manualmente; el método class.forName() es uno de ellos. (En resumen, en realidad se trata de generar el Class de esta clase).

    Concepto del cargador de clases

    Como su nombre lo indica, el cargador de clases (class loader) se utiliza para cargar clases de Java en la máquina virtual de Java. En general, la forma en que la máquina virtual de Java utiliza las clases de Java es la siguiente: el programa fuente de Java (archivo .java), después de ser compilado por el compilador de Java, se convierte en código de bytes de Java (archivo .class). El cargador de clases se encarga de leer el código de bytes de Java y convertirlo en una instancia de la clase java.lang.Class. Cada una de estas instancias se utiliza para representar una clase de Java. A través del método newInstance() de esta instancia, se puede crear un objeto de dicha clase. Básicamente, todos los cargadores de clases son instancias de la clase java.lang.ClassLoader.

    Concepto de inicialización de clases

    Después de que la clase se carga, la JVM ya ha obtenido una instancia de Class que describe la estructura de la clase. Pero aún se necesita realizar la operación de inicialización de la clase antes de poder usarla normalmente. La operación de inicialización de la clase consiste en ejecutar las declaraciones estáticas de la clase, incluyendo la declaración de variables estáticas y los bloques de código estático.

    Método Class.forName()

    El significado de este método es: cargar la clase especificada por el parámetro e inicializarla.

    Aplicación en la conexión de bases de datos con JDBC

    Llegado a este punto, sin necesidad de explicación, el lector también entenderá por qué, al usar JDBC para conectar a la base de datos, se debe ejecutarClass.forName('驱动类名')El método: cargar el archivo class de la clase controladora en la memoria, formar una instancia de la clase Class que describa la estructura de esta clase controladora e inicializar dicha clase controladora, de modo que la JVM pueda usarla. Ese es el significado del método Class.forName().

    Los amigos con experiencia en desarrollo de bases de datos notarán que, al cargar el paquete del controlador de base de datos, ¿por qué algunos no llaman al método newInstance()? Es decir, en algunas formas de escribir la conexión JDBC a la base de datos es Class.forName(xxx.xx.xx); y en otras: Class.forName(xxx.xx.xx).newInstance(). ¿Por qué existen estas dos formas de escritura?

    Como se mencionó anteriormente,Class.forName("");su función es solicitar a la JVM que busque y cargue la clase especificada. Si en la clase hay un inicializador estático, la JVM necesariamente ejecutará el bloque de código estático de dicha clase. Y en la especificación de JDBC se requiere explícitamente que esta clase Driver debe registrarse en DriverManager, es decir, el código de la clase Driver de cualquier controlador JDBC debe ser similar al siguiente:

    public class MyJDBCDriver implements Driver { 
    static { 
        DriverManager.registerDriver(new MyJDBCDriver()); 
    } 
}

    Dado que el registro ya se ha realizado en el inicializador estático, cuando usamos JDBC solo necesitamosClass.forName(XXX.XXX);es suficiente.

    La diferencia entre Class.forName() y xxx.class

    Todas las clases se cargan dinámicamente en la JVM en su primer uso. Cuando el programa crea la primera referencia a un miembro estático de la clase, esta se carga. Esto también demuestra que el constructor es un método estático de la clase, incluso si no tiene la palabra clave static delante. Por lo tanto, usar el operador new para crear un objeto de la clase también se considera una referencia a un miembro estático de la clase.

    Por lo tanto, un programa Java no se carga por completo antes de comenzar a ejecutarse; sus distintas partes se cargan cuando se necesitan.

    El cargador de clases primero verifica si el objeto Class de esta clase ya se ha cargado. Si aún no se ha cargado, el cargador de clases predeterminado buscará el archivo .class según el nombre de la clase. Cuando se carga el código de bytes de esta clase, se somete a verificación para asegurarse de que no haya sido dañado.

    Los objetos Class solo se cargan cuando se necesitan. La inicialización estática se realiza cuando se carga la clase.

    En cuanto aClass.forName()este método es un miembro estático de la clase Class. Los objetos Class son como cualquier otro objeto; podemos obtener y manipular sus referencias. forName() es un método para obtener una referencia al objeto Class. Toma como parámetro de entrada un String que contiene el nombre textual de la clase objetivo y devuelve una referencia a un objeto Class. Si el método forName() descubre que una clase aún no se ha cargado, cargará activamente esta clase; durante el proceso de carga, las cláusulas static de la clase se ejecutarán.

    Java también proporciona otro método para generar referencias a objetos Class, que es usar literales de clase. De la forma: xxx.class. Pero cuando esta forma crea una referencia al objeto Class, no inicializa automáticamente el objeto Class. La inicialización se retrasa hasta que se hace la primera referencia a un método estático o a un campo estático no constante.

    public class Initable {  
    static final int staticFinal = 47;  
    static final int staticFianl2 = ClassInitialization.rand.nextInt(1000);  
    static {  
        System.out.println("Initializing Initable");  
    }  
}
    public class Initable2 {  
    static int staticNonFinal = 147;  
    static {  
        System.out.println("Initializing Initable2");  
    }  
}
    public class Initable3 {  
    static int staticNonFinal = 74;  
    static {  
        System.out.println("Initializing Initable3");  
    }  
}
    public class ClassInitialization {  
    public static Random rand = new Random(47);  
    public static void main(String[] args) throws ClassNotFoundException {  
        Class initable = Initable.class;  
        System.out.println("after creating Initable ref");  
        //Does not trigger initialization  
        System.out.println(Initable.staticFinal);  
        //Does trigger initialization  
        System.out.println(Initable.staticFianl2);  
        //Does trigger initialization  
        System.out.println(Initable2.staticNonFinal);  
        Class initable3 = Class.forName("chapter13.t2.Initable3");  
        System.out.println("after creating Initable3 ref");  
        System.out.println(Initable3.staticNonFinal);  
    }  
}

    Resultado de la ejecución:

    after creating Initable ref  
47  
Initializing Initable  
258  
Initializing Initable2  
147  
Initializing Initable3  
after creating Initable3 ref  
74

    En la creación de la referencia a initable se puede ver que solo usar la sintaxis .class para obtener una referencia a la clase no produce inicialización. Pero Class.forName() inicializa de inmediato. Si un valor static final es una "constante en tiempo de compilación", como Initable.staticFinal, entonces este valor se puede leer sin necesidad de inicializar la clase Initable. Pero si solo se establece un campo como static y final, no es suficiente para garantizar ese comportamiento; por ejemplo, el acceso a Initable.staticFianl2 forzará la inicialización del tipo, porque no es una constante en tiempo de compilación.
