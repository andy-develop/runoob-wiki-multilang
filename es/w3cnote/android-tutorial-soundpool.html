9.1 Usar SoundPool para reproducir efectos de sonido (Duang~)

Categoría Tutorial básico de introducción a Android

Introducción de esta sección:

El Capítulo 9 presenta el desarrollo multimedia en Android. Más que desarrollo multimedia, es el uso de las API relacionadas con multimedia. Hablemos de las cosas relacionadas con multimedia que hacemos en el desarrollo real: tomar fotos, grabar audio, reproducir música, reproducir video...

Bueno, parece que eso es todo, ¿verdad? Por ejemplo, para reproducir música, solo llamamos a MediaPlayer, encontramos el archivo de música y luego llamamos al método play para reproducir... Por supuesto, el desarrollo multimedia real es otro campo, la codificación y decodificación de audio y video. Nosotros, los novatos, solo podemos admirarlo por ahora. ¡Es suficiente con saber cómo llamar a estas API! Por cierto, también debemos explicar algunos conocimientos básicos sobre el framework multimedia de Android:

En Android, el framework multimedia preinstalado es OpenCore.OpenCoreOpenCore tiene la ventaja de considerar la portabilidad multiplataforma, y ha sido verificado por múltiples partes, por lo que es relativamente estable; pero su desventaja es que es demasiado grande y complejo, y requiere bastante tiempo de mantenimiento. Desde Android 2.0, Google introdujo una arquitectura un poco más simple, Stagefright,Stagefrightque, por supuesto, no abandonó por completo OpenCore; principalmente se creó una capa OMX, que solo hace referencia a la parte omx-component de OpenCore. Originalmente tenía la tendencia a reemplazar gradualmente a OpenCORE, pero en agosto de este año se descubrió una vulnerabilidad en Stagefright que permite la ejecución remota de código mediante el envío de un mensaje MMS especialmente diseñado.

Esta vulnerabilidad afecta a Android 2.2 y versiones posteriores, y tiene un impacto relativamente menor en 4.1 y versiones posteriores.No lo entiendo, pero suena impresionante.(Ni siquiera sé de qué diablos habla). Bueno, ¡fin de la explicación! Con saber estas cosas es suficiente.

Por cierto, este framework multimedia se encuentra en la tercera capa de la arquitectura de Android (Libraries)Media Framework! Además, si quieres saber qué tipos de datos de audio y video admite este framework multimedia de Android, consulta la documentación oficial:

Vaya, hubo demasiada charla al principio, casi me olvido de que el protagonista de hoy esSoundPool. Como dice el título, SoundPool se usa generalmente para reproducir efectos de sonido densos, rápidos y breves, como efectos especiales: Duang~. Se usa más en juegos. También puedes agregar este efecto de sonido a tu APP, por ejemplo, al entrar en Kugou Music reproduce "Hola, Kugou". En realidad, esta idea es buena, porque indirectamente le da al usuario una idea del volumen del reproductor actual. De lo contrario, si el usuario pone una canción y de repente suena "Little Apple", haciendo que las señoras cercanas empiecen a bailar, no sería bueno, ¿verdad? Además de en los reproductores de música, puedes agregarlo en aplicaciones normales, por ejemplo, al recibir notificaciones push o nuevos mensajes de chat, reproducir un tono de aviso. Por ejemplo, la nueva versión de Super Timetable agregó esto: al recibir una notificación push, reproduce un breve sonido "biao biao". Un objeto SoundPool puede considerarse como una colección de muestras que pueden importarse desde un APK o cargarse desde el sistema de archivos. Utiliza el servicio MediaPlayer para decodificar audio en un flujo PCM crudo de 16 bits. Esta característica permite que las aplicaciones compriman el flujo sin tener que soportar lo que la descompresión conlleva durante la reproducción:CPU carga y retraso.SoundPool utilizagrupo de efectos de sonidopara gestionar múltiplesflujos de reproducción.Si se excede el número máximo de flujos, SoundPool detendrá automáticamente los flujos previamente reproducidos según la prioridad. Además, SoundPool también admite configurar parámetros como la calidad del sonido, el volumen y la velocidad de reproducción. Bien, sin más preámbulos, comencemos con el contenido de esta sección: Documentación oficial de la API:SoundPool

1. Introducción a los métodos relacionados:

1) Método constructor:

SoundPool(int maxStreams, int streamType, int srcQuality) Los parámetros son, en orden:

  • ① Especifica cuántos sonidos se admiten: el número máximo de flujos que pueden existir simultáneamente en el objeto SoundPool.
  • ② Especifica el tipo de sonido. Los tipos de flujo se pueden dividir enSTREAM_VOICE_CALL, STREAM_SYSTEM, STREAM_RING,STREAM_MUSIC 和 STREAM_ALARMcuatro tipos. Se definen en AudioManager.
  • ③ Especifica la calidad del sonido (calidad de transformación de la frecuencia de muestreo). Generalmente se establece directamente en 0.

En versiones anteriores se puede usar el método constructor anterior, pero después de API 21 (Android 5.0) este constructor está obsoleto. En su lugar se usa algo llamado SoundPool.Builder. Para instanciar SoundPool, solo necesitamos llamar:

SoundPool.Builder spb = new SoundPool.Builder();
spb.setMaxStreams(10);
spb.setAudioAttributes(null);    //转换音频格式
SoundPool sp = spb.build();      //创建SoundPool对象

Para usar el código anterior, la versión de TargetSDK debe ser mayor o igual a 21. Además, si la versión de minSDK es menor que 21, aparecerá la siguiente advertencia:

2) Introducción a los métodos comunes:

①Cargar recursos de sonido：

  • load(Context context, int resId, int priority)
  • load(String path, int priority)
  • load(FileDescriptor fd, long offset, long length, int priority)
  • load(AssetFileDescriptor afd, int priority) Los métodos anteriores devuelven un ID de sonido. Después podemos usar este ID para reproducir el sonido especificado.

Introducción a los parámetros：

  • context: contexto
  • resId: ID de recurso
  • priority: un parámetro que no sirve de mucho. Se recomienda establecerlo en 1 para mantener la compatibilidad futura.
  • path: ruta del archivo
  • FileDescriptor: parece que es un flujo, esto tampoco lo sé.
  • AssetFileDescriptor: lee un archivo de recursos desde el directorio asset. Uso:AssetFileDescriptor descriptor = assetManager.openFd("biaobiao.mp3")；

②Control de reproducción：

play(int soundID, float leftVolume, float rightVolume, int priority, int loop, float rate)

Los parámetros son, en orden:

  • soundID: el ID de sonido devuelto por Load()
  • leftVolume: configuración del volumen del canal izquierdo
  • rightVolume: configuración del volumen del canal derecho
  • priority: especifica la prioridad del sonido a reproducir. Cuanto mayor sea el valor, mayor será la prioridad.
  • loop: especifica si se repite: -1 significa repetición infinita, 0 significa sin repetición, otros valores indican el número de veces que se repetirá.
  • rate: especifica la velocidad de reproducción: una tasa de reproducción de 1.0 permite que el sonido se reproduzca a su frecuencia original, mientras que una tasa de 2.0 permite que se reproduzca al doble de su frecuencia original. Si la tasa es 0.5, la velocidad de reproducción es la mitad de la frecuencia original. El rango de valores para la velocidad de reproducción es de 0.5 a 2.0.

③Liberación de recursos：

Se puede llamar al métodorelease()para liberar toda la memoria y los recursos ocupados por los objetos SoundPool. Por supuesto, también se puede liberar según el ID del sonido.

3. Ejemplo de código de uso:

Imagen del efecto de ejecución：

Al hacer clic en el botón, suena "Duang". Aquí se demuestran dos métodos de load: raw y assets.

Código clave：

MainActivity.java：

public class MainActivity extends AppCompatActivity implements View.OnClickListener{

    private Button btn_play1;
    private Button btn_play2;
    private Button btn_play3;
    private Button btn_play4;
    private Button btn_play5;
    private Button btn_release;
    private AssetManager aManager;
    private SoundPool mSoundPool = null;
    private HashMap<Integer, Integer> soundID = new HashMap<Integer, Integer>();

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);
        aManager = getAssets();
        try {
            initSP();
        } catch (Exception e) {
            e.printStackTrace();
        }
        bindViews();
    }

    private void bindViews() {
        btn_play1 = (Button) findViewById(R.id.btn_play1);
        btn_play2 = (Button) findViewById(R.id.btn_play2);
        btn_play3 = (Button) findViewById(R.id.btn_play3);
        btn_play4 = (Button) findViewById(R.id.btn_play4);
        btn_play5 = (Button) findViewById(R.id.btn_play5);
        btn_release = (Button) findViewById(R.id.btn_release);

        btn_play1.setOnClickListener(this);
        btn_play2.setOnClickListener(this);
        btn_play3.setOnClickListener(this);
        btn_play4.setOnClickListener(this);
        btn_play5.setOnClickListener(this);
        btn_release.setOnClickListener(this);

    }

    private void initSP() throws Exception{
        //设置最多可容纳5个音频流，音频的品质为5
        mSoundPool = new SoundPool(5, AudioManager.STREAM_SYSTEM, 5);
        soundID.put(1, mSoundPool.load(this, R.raw.duang, 1));
        soundID.put(2 , mSoundPool.load(getAssets().openFd("biaobiao.mp3") , 1));  //需要捕获IO异常
        soundID.put(3, mSoundPool.load(this, R.raw.duang, 1));
        soundID.put(4, mSoundPool.load(this, R.raw.duang, 1));
        soundID.put(5, mSoundPool.load(this, R.raw.duang, 1));
    }

    @Override
    public void onClick(View v) {
        switch (v.getId()){
            case R.id.btn_play1:
                mSoundPool.play(soundID.get(1), 1, 1, 0, 0, 1);
                break;
            case R.id.btn_play2:
                mSoundPool.play(soundID.get(2), 1, 1, 0, 0, 1);
                break;
            case R.id.btn_play3:
                mSoundPool.play(soundID.get(3), 1, 1, 0, 0, 1);
                break;
            case R.id.btn_play4:
                mSoundPool.play(soundID.get(4), 1, 1, 0, 0, 1);
                break;
            case R.id.btn_play5:
                mSoundPool.play(soundID.get(5), 1, 1, 0, 0, 1);
                break;
            case R.id.btn_release:
                mSoundPool.release();   //回收SoundPool资源
                break;
        }
    }
}

El código es muy simple. Además, si haces clic en el último botón, SoundPool se liberará, y luego los otros botones ya no harán "Duang".

4. OnLoadCompleteListener: monitorear si el archivo de sonido se ha cargado

Esto lo recordé de repente, justo cuando terminaba de escribir otro artículo. Su uso también es muy simple: podemos agregar OnLoadCompleteListener al código anterior, sobrescribir el método onLoadComplete() y finalmente configurarlo en el objeto SoundPool.

mSoundPool.setOnLoadCompleteListener(new SoundPool.OnLoadCompleteListener() {
    @Override
    public void onLoadComplete(SoundPool soundPool, int sampleId, int status) {
        Toast.makeText(MainActivity.this,"加特技准备完毕~",Toast.LENGTH_SHORT).show();
    }
});
