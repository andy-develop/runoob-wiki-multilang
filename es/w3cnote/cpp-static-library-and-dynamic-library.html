C++ bibliotecas estáticas y dinámicas

Categoría Tecnología de programación

De esta presentaciónel objetivoes — que todos aprendan a crear y usar bibliotecas estáticas y dinámicas, conozcan la diferencia entre bibliotecas estáticas y dinámicas y sepan cómo elegir al usarlas. Aquí no se profundiza en el formato subyacente, el diseño de memoria, etc. de las bibliotecas estáticas y dinámicas. A los interesados, se recomienda un libro: "Autorreflexión del programador: enlace, carga y bibliotecas".

1. Qué es una biblioteca

Una biblioteca es código existente, maduro y reutilizable que ya está escrito.En la práctica, cada programa depende de muchas bibliotecas subyacentes básicas; es imposible que el código de cada persona comience desde cero, por lo tanto, la existencia de las bibliotecas tiene un significado extraordinario.。

En esencia, una biblioteca es una forma binaria de código ejecutable que puede ser cargada en memoria por el sistema operativo para su ejecución. Hay dos tipos de bibliotecas: estáticas (.a, .lib) y dinámicas (.so, .dll).

Lo de estática y dinámica se refiere al enlazado. Repasemos los pasos para compilar un programa hasta convertirlo en un ejecutable:

2. Biblioteca estática

Se llama "biblioteca estática" porque en la etapa de enlazado, los archivos objeto .o generados por el ensamblador se enlazan y empaquetan junto con las bibliotecas referenciadas dentro del archivo ejecutable. Por lo tanto, el método de enlazado correspondiente se denomina enlace estático.

Imaginemos: una biblioteca estática se enlaza junto con los archivos objeto generados por el ensamblador para formar un ejecutable, por lo que la biblioteca estática debe tener un formato similar al de los archivos .o. De hecho, una biblioteca estática puede considerarse simplemente comoun conjunto de archivos objeto (.o/.objarchivos) que forman una colección, es decir, un archivo formado por muchos archivos objeto comprimidos y empaquetados. Resumen de las características de las bibliotecas estáticas:

- El enlazado de la biblioteca estática con las funciones se realiza en el momento de la compilación.

- En tiempo de ejecución, el programa ya no tiene relación con la biblioteca de funciones, lo que facilita la portabilidad.

- Se desperdician espacio y recursos, porque todos los archivos objeto relacionados y las bibliotecas de funciones implicadas se enlazan y combinan en un solo archivo ejecutable.

A continuación, escribiremos algunas clases simples de C++ para operaciones aritméticas básicas, las compilaremos como una biblioteca estática para que otros las usen. El archivo de cabecera es el siguiente:

Archivo de cabecera StaticMath.h

{
public:

    ~StaticMath(void);

    static double sub(double a, double b);//减法
    static double mul(double a, double b);//乘法
    static double div(double a, double b);//除法

    void print();
};

2.1. Creación y uso de bibliotecas estáticas en Linux

2.1.1. Reglas de nomenclatura de bibliotecas estáticas en Linux

La convención de nomenclatura para bibliotecas estáticas en Linux debe ser "lib[your_library_name].a": "lib" es el prefijo, en el medio va el nombre de la biblioteca estática, y la extensión es .a.

2.1.2. Creación de una biblioteca estática (.a)

A través del proceso anterior se puede saber que el procedimiento para crear una biblioteca estática en Linux es el siguiente:

- Primero, compilar el archivo de código a un archivo objeto .o (StaticMath.o)

g++ -c StaticMath.cpp

Tenga en cuenta el parámetro -c; de lo contrario, se compilará directamente como un archivo ejecutable.

- Luego, mediante la herramienta ar, empaquetar el archivo objeto en un archivo de biblioteca estática .a

ar -crv libstaticmath.a StaticMath.o

Generar la biblioteca estáticalibstaticmath.a。

Los proyectos más grandes suelen escribir archivos makefile (CMake y otras herramientas de gestión de proyectos) para generar la biblioteca estática, ya que introducir múltiples comandos es demasiado engorroso.

2.1.3. Uso de la biblioteca estática

Escribir el código de prueba que utilice la biblioteca estática creada anteriormente:

Código de prueba: 
#include "StaticMath.h"
#include <iostream>
using namespace std;

int main(int argc, char* argv[])
{
    double a = 10;
    double b = 2;

    cout << "a + b = " << StaticMath::add(a, b) << endl;
    cout << "a - b = " << StaticMath::sub(a, b) << endl;
    cout << "a * b = " << StaticMath::mul(a, b) << endl;
    cout << "a / b = " << StaticMath::div(a, b) << endl;

    StaticMath sm;
    sm.print();

    system("pause");
    return 0;
}

Para usar una biblioteca estática en Linux, solo es necesario, al compilar, especificar la ruta de búsqueda de la biblioteca estática (opción -L) y especificar el nombre de la biblioteca estática (no se necesitan el prefijo lib ni el sufijo .a, opción -l).

# g++ TestStaticLibrary.cpp -L../StaticLibrary -lstaticmath

- -L: indica el directorio donde se encuentra la biblioteca a enlazar.

- -l: especifica la biblioteca dinámica necesaria al enlazar. El compilador tiene reglas de nomenclatura implícitas al buscar bibliotecas de enlace dinámico: antepone "lib" al nombre dado y añade ".a" o ".so" al final para determinar el nombre de la biblioteca.

3. Biblioteca dinámica

A través de la introducción anterior, se descubre que la biblioteca estática es fácil de usar y entender, y también logra el propósito de reutilización de código. Entonces, ¿por qué se necesitan también bibliotecas dinámicas?

3.1. ¿Por qué se necesitan también bibliotecas dinámicas?

Por qué se necesitan bibliotecas dinámicas se debe, en realidad, a las características de las bibliotecas estáticas.

- El desperdicio de espacio es un problema de las bibliotecas estáticas.

- Otro problema es que las bibliotecas estáticas causan inconvenientes en la actualización, implementación y publicación de programas. Si la biblioteca estática liba.lib se actualiza, todas las aplicaciones que la usan deben recompilarse y publicarse para los usuarios (para los jugadores, puede ser un cambio muy pequeño, pero provoca que todo el programa se descargue de nuevo,actualización completa）。

Las bibliotecas dinámicas no se enlazan al código objeto durante la compilación del programa, sino que se cargan solo cuando el programa se ejecuta.Si diferentes aplicaciones llaman a la misma biblioteca, solo se necesita una instancia de esa biblioteca compartida en la memoria., lo que evita el problema del desperdicio de espacio. Como las bibliotecas dinámicas se cargan solo cuando el programa se ejecuta, también se resuelven los inconvenientes que las bibliotecas estáticas causan en la actualización, implementación y publicación de programas. Los usuarios solo necesitan actualizar la biblioteca dinámica,actualización incremental。

Resumen de las características de las bibliotecas dinámicas:

- La biblioteca dinámica aplaza la carga y el enlazado de algunas funciones de biblioteca hasta el período de ejecución del programa.

- Permite compartir recursos entre procesos. (Por eso las bibliotecas dinámicas también se denominan bibliotecas compartidas).

- Hace que la actualización de algunos programas sea sencilla.

- Incluso se puede lograr que la carga y el enlazado sean controlados completamente por el programador en el código del programa (llamada explícita）。

Windows y Linux tienen formatos de archivo ejecutable diferentes, por lo que hay algunas diferencias al crear bibliotecas dinámicas.

- En el sistema Windows, el formato de archivo ejecutable es el formato PE, y la biblioteca dinámica necesita unLa función DllMain sirve como punto de entrada de inicialización; normalmente, al declarar funciones exportadas, se necesita _declspec(dllexport).Palabra clave。

- Bajo Linux, los archivos ejecutables compilados con gcc tienen por defecto el formato ELF,no requieren un punto de entrada de inicialización, ni tampoco declaraciones especiales para las funciones,por lo que resulta más conveniente escribirlos.

A diferencia de la creación de bibliotecas estáticas, no se necesitan herramientas de empaquetado (ar, lib.exe); basta con usar el compilador para crear una biblioteca dinámica.

3.2. Creación y uso de bibliotecas dinámicas en Linux

3.2.1. Reglas de nomenclatura de las bibliotecas dinámicas en Linux

El nombre de la biblioteca de enlace dinámico tiene la forma libxxx.so; el prefijo es "lib" y el sufijo es ".so".

- Para el archivo de biblioteca real, cada biblioteca compartida tiene un nombre especial llamado "soname". Después de que el programa se inicia, este usa ese nombre para indicar al cargador dinámico qué biblioteca compartida debe cargar.

- En el sistema de archivos, soname es solo un enlace a la biblioteca dinámica real. Para las bibliotecas dinámicas, cada biblioteca también tiene otro nombre para que lo use el compilador. Es un archivo de enlace que apunta al archivo de imagen de la biblioteca real (lib+soname+.so).

3.2.2. Creación de bibliotecas dinámicas (.so)

Escribir el código de la biblioteca dinámica de operaciones aritméticas básicas:

Archivo de cabecera DynamicMath.h 
#pragma once
class DynamicMath
{
public:
        DynamicMath(void);
        ~DynamicMath(void); 

        static double add(double a, double b);//加法
        static double sub(double a, double b);//减法
        static double mul(double a, double b);//乘法
        static double div(double a, double b);//除法
        void print();
};

- Primero, generar el archivo objeto; en este paso se debe añadir la opción del compilador -fpic

g++ -fPIC -c DynamicMath.cpp

-fPIC crea código compilado independiente de la dirección (pic, position independent code), para poder compartirlo entre múltiples aplicaciones.

- Luego, generar la biblioteca dinámica; en este paso se debe añadir la opción del enlazador -shared

g++ -shared -o libdynmath.so DynamicMath.o

-shared especifica la generación de una biblioteca de enlace dinámico.

En realidad, los dos pasos anteriores se pueden combinar en un solo comando:

g++ -fPIC -shared -o libdynmath.so DynamicMath.cpp

3.2.3. Uso de bibliotecas dinámicas

Escribir el código de prueba que usa la biblioteca dinámica:

Código de prueba: 
#include "../DynamicLibrary/DynamicMath.h"

#include <iostream>
using namespace std;

int main(int argc, char* argv[])
{
    double a = 10;
    double b = 2;

    cout << "a + b = " << DynamicMath::add(a, b) << endl;
    cout << "a - b = " << DynamicMath::sub(a, b) << endl;
    cout << "a * b = " << DynamicMath::mul(a, b) << endl;
    cout << "a / b = " << DynamicMath::div(a, b) << endl;

    DynamicMath dyn;
    dyn.print();
    return 0;
}

Enlazar la biblioteca dinámica para compilar el archivo ejecutable (igual que con la biblioteca estática):

g++ TestDynamicLibrary.cpp -L../DynamicLibrary -ldynmath

¡¡¡Se descubre que sigue dando error!!! Entonces, ¿cómo se localiza el archivo de biblioteca compartida durante la ejecución?

1) Cuando el sistema carga el código ejecutable, sabe el nombre de la biblioteca de la que depende, pero aún necesita conocer la ruta absoluta. En este momento se requiere el cargador dinámico del sistema (dynamic linker/loader).

2) Para los programas ejecutables en formato ELF, esto lo realiza ld-linux.so*; busca en el orden siguiente: la sección DT_RPATH del archivo ELF — la variable de entorno LD_LIBRARY_PATH — la lista de archivos /etc/ld.so.cache — los directorios /lib/ y /usr/lib; al encontrar el archivo de biblioteca, lo carga en memoria.

- Si se instala en /lib o /usr/lib, entonces ld puede encontrarla por defecto, sin necesidad de hacer nada más.

- Si se instala en otro directorio, hay que añadirla al archivo /etc/ld.so.cache; los pasos son los siguientes:

-- Editar el archivo /etc/ld.so.conf y añadir la ruta del directorio donde se encuentra el archivo de biblioteca

-- Ejecutar ldconfig; este comando reconstruirá el archivo /etc/ld.so.cache

Copiamos la biblioteca dinámica creada a /usr/lib y luego ejecutamos el programa de prueba.

3.3. Creación y uso de bibliotecas dinámicas en Windows

3.3.1. Creación de bibliotecas dinámicas (.dll)

En comparación con Linux, crear una biblioteca dinámica en el sistema Windows es un poco más complicado. Primero, se necesita una función DllMain que sirva como punto de entrada de inicialización (al crear un programa de consola Win32, marcar el tipo DLL generará automáticamente este archivo):

Archivo de entrada dllmain.cpp 
// dllmain.cpp : Defines the entry point for the DLL application.
#include "stdafx.h"

BOOL APIENTRY DllMain( HMODULE hModule,
                       DWORD  ul_reason_for_call,
                       LPVOID lpReserved
                     )
{
    switch (ul_reason_for_call)
    {
    case DLL_PROCESS_ATTACH:
    case DLL_THREAD_ATTACH:
    case DLL_THREAD_DETACH:
    case DLL_PROCESS_DETACH:
        break;
    }
    return TRUE;
}

Normalmente, al declarar las funciones exportadas, se necesita la palabra clave _declspec(dllexport):

Archivo de cabecera DynamicMath.h 
#pragma once
class DynamicMath
{
public:
    __declspec(dllexport) DynamicMath(void);
    __declspec(dllexport) ~DynamicMath(void);

    static __declspec(dllexport) double add(double a, double b);//加法
    static __declspec(dllexport) double sub(double a, double b);//减法
    static __declspec(dllexport) double mul(double a, double b);//乘法
    static __declspec(dllexport) double div(double a, double b);//除法

    __declspec(dllexport) void print();
};

Para generar la biblioteca dinámica es necesario configurar las propiedades del proyecto: abrir el "Panel de propiedades" del proyecto -- "Propiedades de configuración" -- "General", y en "Tipo de configuración" seleccionar "Biblioteca dinámica".

Aquí puede surgir una duda: ¿por qué la biblioteca dinámica también tiene un archivo DynamicLibrary.lib? Es decir, tanto la biblioteca de enlace estático como la de enlace dinámico terminan teniendo un archivo lib; entonces, ¿cuál es la diferencia entre ambos? En realidad, son dos cosas completamente distintas.

El tamaño de StaticLibrary.lib es de 190KB, el de DynamicLibrary.lib es de 3KB; el archivo lib correspondiente a la biblioteca estática se llamabiblioteca estática, y el archivo lib correspondiente a la biblioteca dinámica se llama [biblioteca de importación]. En realidad, la biblioteca estática en sí ya contiene el código de ejecución real, la tabla de símbolos, etc., mientras quepara la biblioteca de importación, su código de ejecución real se encuentra en la biblioteca dinámica; esta solo contiene la tabla de símbolos de direcciones, etc., para garantizar que el programa encuentre cierta información básica de direcciones de las funciones correspondientes.。

4. Llamada explícita a bibliotecas dinámicas

El método de uso de bibliotecas dinámicas presentado anteriormente es similar al de las bibliotecas estáticas y pertenece a la llamada implícita; al compilar se especifican la biblioteca correspondiente y la ruta de búsqueda. En realidad, las bibliotecas dinámicas también se pueden llamar explícitamente.[EnCel lenguaje], ¡llamar explícitamente a una biblioteca dinámica es facilísimo!

4.1. Llamada explícita a bibliotecas dinámicas en Linux

#include <dlfcn.h>, que proporciona las siguientes interfaces:

-  void * dlopen( const char *pathname, int mode ): la función abre el archivo de biblioteca de enlace dinámico especificado en el modo especificado y devuelve un manejador al proceso que la llama.

-  void* dlsym(void* handle, const char* symbol): dlsym, basándose en el manejador (pHandle) y el símbolo (symbol) de la biblioteca de enlace dinámico, devuelve la dirección correspondiente al símbolo. Con esta función no solo se puede obtener la dirección de una función, sino también la dirección de una variable.

-  int dlclose(void *handle): dlclose se utiliza para cerrar la biblioteca de enlace dinámico del manejador especificado; solo cuando el contador de uso de esta biblioteca de enlace dinámico llega a 0, el sistema la descarga realmente.

- const char *dlerror(void): cuando las funciones de operación de la biblioteca de enlace dinámico fallan al ejecutarse, dlerror puede devolver el mensaje de error; si el valor de retorno es NULL, significa que la operación se ejecutó correctamente.

4.2. Llamada explícita a bibliotecas dinámicas en Windows

La aplicación debe realizar llamadas a funciones para cargar explícitamente la DLL en tiempo de ejecución. Para vincularse explícitamente a una DLL, la aplicación debe:

- Llamar aLoadLibrary(o una función similar) para cargar la DLL y obtener el manejador del módulo.

- Llamar aGetProcAddress, para obtener un puntero a función de cada función exportada que la aplicación deba llamar. Dado que la aplicación llama a las funciones de la DLL a través de punteros, el compilador no genera referencias externas, por lo que no es necesario vincular con la biblioteca de importación.

- Después de usar la DLL, llamar aFreeLibrary。

4.3. Puntos a tener en cuenta al llamar explícitamente a bibliotecas dinámicas de C++

Para C++, la situación es un poco más complicada. La dificultad de cargar explícitamente una biblioteca dinámica de C++se debe en parte ael name mangling de C++；y en parte porque no se proporciona unAPImecanismo adecuado para cargar clases,en C++, es posible que necesite usar una clase de la biblioteca, y esto requiere crear una instancia de dicha clase, lo cual no es fácil de lograr.

name manglingSe puede resolver mediante extern "C". C++ tiene una palabra clave específica para declarar funciones con binding de C: extern "C". Las funciones declaradas con extern "C" usarán el nombre de la función como nombre de símbolo, igual que las funciones de C. Por lo tanto, solo las funciones no miembro pueden declararse como extern "C" y no pueden sobrecargarse. A pesar de las muchas limitaciones, las funciones extern "C" son muy útiles porque pueden cargarse dinámicamente con dlopen como las funciones de C. Agregar el calificador extern "C" no significa que no se pueda usar código C++ dentro de la función; al contrario, sigue siendo una función C++ completa y puede usar cualquier característica de C++ y varios tipos de parámetros.

Además, sobre cómo obtener clases de una biblioteca dinámica de C++, adjunto algunos artículos relacionados, pero no recomiendo hacerlo:

- «LoadLibrary para invocar la Class en una DLL»:http://www.cppblog.com/codejie/archive/2009/09/24/97141.html

-  《C++ dlopen mini HOWTO》：http://blog.csdn.net/denny_233/article/details/7255673

Usar "explícitamente" la Class en una biblioteca dinámica de C++ es algo muy tedioso y peligroso; por lo tanto, si se puede usar "implícitamente", no use "explícitamente"; si se puede usar estática, no use dinámica.

5. Anexo: comandos relacionados con bibliotecas en Linux

5.1. Opciones de compilación de g++ (gcc)

- -shared: especifica generar una biblioteca de enlace dinámico.

- -static: especifica generar una biblioteca de enlace estático.

- -fPIC: indica compilar como código independiente de posición, utilizado para compilar bibliotecas compartidas. Los archivos objeto deben crearse como código independiente de posición; conceptualmente, cuando el programa ejecutable los carga, pueden colocarse en cualquier lugar de la memoria del programa ejecutable.

- -L.: indica el directorio donde se encuentra la biblioteca a enlazar.

- -l: especifica la biblioteca dinámica necesaria al enlazar. El compilador tiene una regla de nomenclatura implícita al buscar bibliotecas de enlace dinámico: antepone "lib" al nombre dado y añade ".a/.so" para determinar el nombre de la biblioteca.

- -Wall: genera toda la información de advertencia.

- -ggdb: esta opción generará, en la medida de lo posible, información de depuración utilizable por gdb.

- -g: el compilador genera información de depuración al compilar.

- -c: solo activa el preprocesado, la compilación y el ensamblado, es decir, convierte el programa en un archivo objeto (archivo .o).

- -Wl,options: pasa los argumentos (options) al enlazador ld. Si hay comas en options, divide options en múltiples opciones y luego las pasa al programa enlazador.

5.2. Comando nm

A veces puede ser necesario ver qué funciones contiene realmente una biblioteca,nmel comandopuede imprimir todos los símbolos involucrados en la biblioteca. La biblioteca puede ser estática o dinámica. Los símbolos listados por nm son muchos; hay tres tipos comunes:

- Uno es invocado en la biblioteca pero no está definido en ella (indica que se necesita el soporte de otras bibliotecas), representado con U;

- Uno es una función definida en la biblioteca, representada con T; este es el más común;

- Uno es el llamado símbolo "débil"; aunque está definido en la biblioteca, puede ser sobrescrito por símbolos del mismo nombre en otras bibliotecas, representado con W.

$nm libhello.h

6. Resumen

La diferencia entre ambos radica enque el momento en que el código se carga es diferente.。

- La biblioteca estática se enlaza al código objeto durante la compilación del programa; en tiempo de ejecución, el programa ya no necesitará esa biblioteca estática,por lo que su tamaño es mayor.。

- La biblioteca dinámica no se enlaza al código objeto durante la compilación del programa, sino que se carga cuando el programa se ejecuta; por lo tanto, la biblioteca dinámica debe existir durante la ejecución del programa,por lo que el tamaño del código es menor.。

La ventaja de las bibliotecas dinámicas es que si diferentes aplicaciones llaman a la misma biblioteca, solo se necesita una instancia de esa biblioteca compartida en memoria. Pero junto con las ventajas, también hay problemas, como el clásico problema de DLL Hell. Sobre cómo evitar los problemas de gestión de bibliotecas dinámicas, se puede buscar información relevante por su cuenta.
