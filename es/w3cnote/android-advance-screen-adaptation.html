1.1 La adaptación de pantalla popular en Android

Categoría Tutorial de extensión de Android

Introducción

El meme que trajo el código abierto de Android no es otro que el problema de compatibilidad entre diferentes modelos y versiones de teléfonos móviles, convirtiéndose a la vez en un desafío que todo desarrollador de Android debe enfrentar, o más bien varios problemas diversos que llegan sin previo aviso. Este artículo presentará principalmente los problemas de adaptación entre los problemas de compatibilidad.

Conceptos básicos

  • Tamaño de pantalla

    La longitud de la diagonal de la pantalla, generalmente expresada en “pulgadas”.

  • Resolución

    Se refiere al número de píxeles en la pantalla del teléfono.

  • Densidad de píxeles de pantalla (Pixels Per Inch)

    Número de píxeles por pulgada. En detalle, es el número de píxeles en la diagonal dividido por el tamaño de la pantalla.

Combinando los puntos anteriores de la pantalla, el sistema Android define varios valores estándar de DPI (PPI).

Píxeles independientes dp

Es precisamente debido a las diferencias en la densidad de pantalla que la misma longitud en píxeles se muestra de manera diferente en diferentes pantallas. El sistema Android usa mdpi, es decir, 160dpi, como estándar; en esta pantalla 1px = 1dp. En otras pantallas se realiza la conversión proporcional: en hdpi (240dpi), 1dp = 1.5px... (es decir, ldpi:mdpi:hdpi:xhdpi:xxhdpi = 3:4:6:8:12).

Píxeles independientes sp

En el desarrollo, para establecer el tamaño de la fuente se usa sp como unidad. El tamaño de fuente establecido con esta unidad se ve afectado por el tamaño de fuente del sistema. Se recomienda usar 12sp, 14sp, 18sp, 22sp como tamaños de fuente.

Resolver la adaptación de pantalla

Con los conceptos básicos sobre pantallas, en el desarrollo real los problemas de fragmentación siguen apareciendo, por lo tanto, ¡comencemos el viaje de la adaptación de pantalla!

Adaptación de imágenes

Además de lo que Xiaozhu escribió en artículos anteriores sobre el uso deimágenes .9Además, en más ocasiones tenemos que resolver el problema de la distorsión de las imágenes.

Proceso de carga de imágenes del SDK de Android

  1. El SDK de Android selecciona automáticamente los archivos de recursos correspondientes según la densidad de pantalla para renderizarlos y cargarlos. Por ejemplo, si el SDK detecta que la resolución de tu teléfono es xhdpi, buscará primero los recursos de imagen correspondientes en la carpeta xhdpi;
  2. Si no hay recursos de imagen en la carpeta xhdpi, entonces buscará en carpetas de mayor resolución, como xxhdpi, hasta encontrar un recurso de imagen con el mismo nombre y lo reducirá proporcionalmente a una imagen xhdpi;
  3. Si la búsqueda hacia arriba aún no encuentra la imagen, entonces buscará en carpetas de menor resolución, como hdpi, hasta encontrar un recurso de imagen con el mismo nombre y lo ampliará proporcionalmente a una imagen xhdpi.

Por lo tanto, al trabajar con el diseñador gráfico, se debe elegir imágenes lo más grandes posible, teniendo en cuenta las resoluciones de pantalla principales actuales.

Empecemos por layout_weight. layout_weight es un atributo de android.widget.LinearLayout. En pocas palabras, solo se puede usar en los hijos de LinearLayout. Por supuesto, no hace falta hablar de wrap_content y match_parent. Seguramente todos ya saben cómo usarlo. Solo que layout_weight tiene algunas consideraciones. No sé si debería redundar. ¡Olvídenlo! Calificadores

Calificador de tamaño

  • Escenario de uso

    Los amigos que han usado tabletas y teléfonos seguramente habrán visto que una app puede tener esta situación: en un teléfono (pantalla más pequeña), se usa un panel único para mostrar contenido. En una tableta, se implementa un modo de doble panel para mostrar más contenido.

  • Método de uso

    Podemos usar el calificador de tamaño (layout-large) creando un archivo. Así, nuestro directorio se verá así, y le pondremos contenido diferente.

    res/layout/activity_main.xml

    <LinearLayout xmlns:android="http://schemas.android.com/apk/res/android" android:orientation="vertical" android:layout_width="match_parent" android:layout_height="match_parent"> <fragment android:id="@+id/left_fragment" android:layout_height="match_parent" android:name="com.xlhgo.demo.LeftFragment" android:layout_width="match_parent" /> </LinearLayout>

    res/layout-large/activity_main.xml

    <LinearLayout xmlns:android="http://schemas.android.com/apk/res/android" android:layout_width="match_parent" android:layout_height="match_parent" android:orientation="horizontal"> <fragment android:id="@+id/left_fragment" android:layout_height="match_parent" android:layout_width="0dp" android:layout_weight="1" android:name="com.xlhgo.demo.LeftFragment" /> <fragment android:id="@+id/right_fragment" android:layout_height="match_parent" android:layout_width="0dp" android:layout_weight="1" android:name="com.xlhgo.demo.RightFragment /> </LinearLayout>

  • Notas

    Este método solo es adecuado antes de Android 3.2; después, hay un nuevo juguete.

Calificador de ancho mínimo

Sobre la base del calificador de tamaño original, la existencia de large es muy ambigua. Google (papá Google) trae una nueva forma de jugar: el calificador de ancho mínimo (Smallest-width).

  • Método de uso

    res/layout-sw600dp/activity_main.xml

    <LinearLayout xmlns:android="http://schemas.android.com/apk/res/android" android:layout_width="match_parent" android:layout_height="match_parent" android:orientation="horizontal"> <fragment android:id="@+id/left_fragment" android:layout_height="match_parent" android:layout_width="0dp" android:layout_weight="1" android:name="com.xlhgo.demo.LeftFragment" /> <fragment android:id="@+id/right_fragment" android:layout_height="match_parent" android:layout_width="0dp" android:layout_weight="1" android:name="com.xlhgo.demo.RightFragment /> </LinearLayout>

  • Análisis

    Es decir, para dispositivos con un ancho mínimo mayor o igual a 600 dp, el sistema elegirá el diseño layout-sw600dp/main.xml (doble panel); de lo contrario, elegirá el diseño layout/activity_main.xml (panel único).

    Pero los dispositivos con versiones de Android anteriores a 3.2 no admiten esta técnica, porque estos dispositivos no pueden reconocer sw600dp como calificador de tamaño, por lo que aún necesitamos usar el calificador large. De este modo, habrá un archivo llamado res/layout-large/main.xml (igual que res/layout-sw600dp/activity_main.xml). Jeje, Android ya lo había previsto todo.

Usar alias de diseño

Para resolver el problema anterior, usamos alias de diseño.

  • Método de uso:

    Movemos el diseño original res/layout-sw600dp/activity_main.xml al directorio res/layoout/ y lo llamamos activity_main_(xxx).xml (la convención de nomenclatura de xxx es mejor estandarizarla, unificando criterios).

    A continuación veamos los diseños de values-large y values-sw600dp.

    <resources> <item name="main" type="layout">@layout/activity_main_(xxx)</item> </resources>

Calificador de orientación de pantalla (Orientation)

  • res/layout-land
  • res/layout-port
  • res/layout-sw600dp-land
  • res/layout-sw600dp-port

Uso de dimen

Incluso usando dp, en realidad no se puede resolver completamente el problema de adaptación de pantalla, especialmente en el diseño horizontal es más fácil de notar, porque los valores dp de ancho y alto de una pantalla varían entre diferentes teléfonos. Por lo tanto, no importa cómo se asignen valores dp a los controles, no se puede resolver bien la adaptación.

  • Solución

    Dividimos el ancho de una pantalla en 320 partes y la altura en 480 partes, luego asignamos un valor a cada unidad según los píxeles reales, y los colocamos en lay_x.xml y lay_y.xml dentro de la carpeta correspondiente values-widthxheight.

  • Código específico

    import java.io.File; import java.io.FileNotFoundException; import java.io.FileOutputStream; import java.io.PrintWriter; /** * Created by xlh on 2016/12/4. */ public class MakeXml { private final static String rootPath = "F:\\layoutroot\\values-{0}x{1}\\"; //Se puede modificar según tu propia situación. private final static float dw = 320f; private final static float dh = 480f; private final static String WTemplate = "<dimen name=\"x{0}\">{1}px</dimen>\n"; private final static String HTemplate = "<dimen name=\"y{0}\">{1}px</dimen>\n"; public static void main(String[] args) { makeString(320, 480); makeString(480, 800); makeString(480, 854); makeString(540, 960); makeString(600, 1024); makeString(720, 1184); makeString(720, 1196); makeString(720, 1280); makeString(768, 1024); makeString(800, 1280); makeString(1080, 1812); makeString(1080, 1920); makeString(1440, 2560); } public static void makeString(int w, int h) { StringBuffer sb = new StringBuffer(); sb.append("<?xml version=\"1.0\" encoding=\"utf-8\"?>\n"); sb.append("<resources>"); float cellw = w / dw; for (int i = 1; i < 320; i++) { sb.append(WTemplate.replace("{0}", i + "").replace("{1}", change(cellw * i) + "")); } sb.append(WTemplate.replace("{0}", "320").replace("{1}", w + "")); sb.append("</resources>"); StringBuffer sb2 = new StringBuffer(); sb2.append("<?xml version=\"1.0\" encoding=\"utf-8\"?>\n"); sb2.append("<resources>"); float cellh = h / dh; for (int i = 1; i < 480; i++) { sb2.append(HTemplate.replace("{0}", i + "").replace("{1}", change(cellh * i) + "")); } sb2.append(HTemplate.replace("{0}", "480").replace("{1}", h + "")); sb2.append("</resources>"); String path = rootPath.replace("{0}", h + "").replace("{1}", w + ""); File rootFile = new File(path); if (!rootFile.exists()) { rootFile.mkdirs(); } File layxFile = new File(path + "lay_x.xml"); File layyFile = new File(path + "lay_y.xml"); try { PrintWriter pw = new PrintWriter(new FileOutputStream(layxFile)); pw.print(sb.toString()); pw.close(); pw = new PrintWriter(new FileOutputStream(layyFile)); pw.print(sb2.toString()); pw.close(); } catch (FileNotFoundException e) { e.printStackTrace(); } } public static float change(float a) { int temp = (int) (a * 100); return temp / 100f; } }

    En cada directorio correspondiente hay lay_x.xml y lay_y.xml.

    El código dentro también es muy regular.

  • Método de uso

    Con estos archivos, es muy conveniente usarlos. Supongamos que la imagen que me da el diseñador es de 320*480, entonces se puede llamar directamente así: android:layout_xxx="@dimen/xxxx"

Diseño de porcentaje

En cuanto al diseño de porcentaje, si no recuerdo mal, fue una novedad a principios del 15. Como es el hijo predilecto de Google, no diré mucho, primero les doy directamente el enlace oficial:android-percent-support-lib-sample

No es más que un diseño de porcentaje. Si se puede comunicar razonablemente con el diseñador, esta será una buena opción en el desarrollo de Android.

<?xml version="1.0" encoding="utf-8"?> <android.support.percent.PercentRelativeLayout xmlns:android="http://schemas.android.com/apk/res/android" xmlns:app="http://schemas.android.com/apk/res-auto" android:layout_width="match_parent" android:layout_height="wrap_content"> <Button android:layout_width="0dp" android:layout_height="wrap_content" android:text="30%" app:layout_widthPercent="30%"/> <Button android:layout_width="0dp" android:layout_height="wrap_content" android:layout_alignParentRight="true" android:text="20%" app:layout_widthPercent="20%"/> </android.support.percent.PercentRelativeLayout>
