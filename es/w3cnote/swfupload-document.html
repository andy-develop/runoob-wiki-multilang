SWFUpload

SWFUploadOriginalmente eraVinterwebb.seuna herramienta de carga de archivos en el lado del cliente. Combina JavaScript y Flash, proporcionando en el navegador una funcionalidad superior a la etiqueta de carga tradicional <input type="file" /> (y una buena experiencia de usuario).

Las principales características de SWFUpload:

  • Se pueden seleccionar múltiples archivos en el cuadro de diálogo de exploración de archivos.
  • Carga de archivos estilo AJAX, sin necesidad de recargar la página.
  • Diversos eventos durante el proceso de carga.
  • Se puede ajustar el tamaño de las imágenes en el cliente.
  • Los espacios de nombres de clases que utiliza son compatibles con varias bibliotecas JS (p. ej., jQuery, Prototype, etc.).
  • Compatible con Flash 9 y Flash 10 (el soporte para Flash 8 se eliminó en la versión 2.2.0).

La filosofía de diseño de SWFUpload es diferente a la de otras herramientas de carga basadas en Flash. SWFUpload ofrece al desarrollador el mayor control posible sobre la interfaz de usuario (UI). El desarrollador puede usar XHTML, CSS y JavaScript para adaptarlo al estilo de su propio sitio web. Proporciona un conjunto simple de eventos de JavaScript para actualizar el estado de la carga, y el desarrollador puede mostrar el progreso de la subida de archivos en la página web basándose en estos eventos.

Desafortunadamente, Flash Player 10 nos obliga a usar un botón (después de hacer clic) para poder abrir el diálogo de selección de archivos, pero SWFUpload permite al desarrollador modificar el texto y la apariencia de este botón mediante JavaScript.

SWFUpload v2

SWFUpload v2 incluye muchas características nuevas, estabilidad mejorada, corrige algunos errores de Flash Player y proporciona algunos complementos útiles (Plug-ins). Las nuevas características incluyen:

  • Puede aprovechar las características de seguridad de Flash Player 10.
  • Puede enviar datos adicionales mediante POST junto con la carga.
  • Envía datos POST para cada archivo que se sube.
  • Conjuntos de eventos completos y mejorados.
  • Todos los ajustes y parámetros pueden configurarse de manera flexible.
  • Puede obtener los datos devueltos por el servidor.
  • Puede pausar el archivo que se está subiendo en lugar de cancelarlo.
  • Puede modificar el orden de carga libremente.
  • Puede proporcionar un cuadro de diálogo de selección de archivos único o múltiple.
  • Puede limitar la longitud de la cola de carga, el tamaño de los archivos y la cantidad de archivos a cargar.
  • Puede manejar mejor los archivos de 0 bytes.
  • Cada archivo tiene un evento de confirmación de carga.

Overview

HTML Upload

El cuadro de carga HTML estándar solo ofrece un botón y un campo de texto para que el usuario seleccione un único archivo. Luego se envía mediante el formulario. El archivo completo debe esperar a que termine su carga para poder confirmar y comprobar el tamaño del archivo o su extensión, y durante el proceso de carga hay muy poca retroalimentación. Esto causa algunas inconveniencias de uso.

Pero la carga HTML tradicional es muy simple, de un solo paso, y todos los navegadores la soportan.

SWFUpload

SWFUpload utiliza una película Flash (flash movie) para seleccionar y cargar archivos. La película contiene un botón personalizable que activa el cuadro de diálogo de selección de archivos. El cuadro de diálogo de selección permite al usuario elegir un solo archivo o varios archivos. Los tipos de archivo seleccionables también se pueden restringir; el desarrollador puede limitar al usuario a que solo seleccione los archivos apropiados especificados, por ejemplo *.jgp;*.gif.

Una vez que se seleccionan los archivos y se hace clic en Aceptar, cada archivo se valida y se coloca en la cola. Cuando Flash carga los archivos, se activan los eventos de JavaScript predefinidos por el desarrollador para actualizar la interfaz de usuario en la página, y también se proporcionan en tiempo real el estado de la carga y los mensajes de error.

La carga de archivos es independiente de la página y del formulario. Cada archivo se sube individualmente a la página de procesamiento, lo que permite al servidor manejar los archivos de forma sencilla y fácil. El servicio de carga proporcionado por Flash hace que no sea necesario enviar ni recargar toda la página. Esto se parece un poco a las aplicaciones AJAX. Los datos del formulario en la página se procesan por separado de la carga de archivos controlada por Flash.

Introducción (Getting Started)

SWFUpload no es un control de carga de arrastrar y soltar. Por lo tanto, se requieren algunos conocimientos de DOM y JavaScript. Varios ejemplos (demos) mostrarán las capacidades de SWFUpload y cómo usarlas para completar tareas.

SWFUpload consta de 4 partes:

  1. Inicialización y configuración (JavaScript)
  2. Biblioteca de JavaScript: SWFUpload.js
  3. Control Flash: swfupload.swf y swfupload_fp9.swf
  4. Mecanismo de manejo de eventos (JavaScript)

Muchos de los problemas al usar SWFUpload provienen de la configuración. Un manejo incorrecto de eventos, errores de Flash/navegador o la configuración del servidor.

Inicialización y configuración (Initialization and Settings)

SWFUpload debe inicializarse en la página. Normalmente se hace en el evento window.onload de JavaScript. El constructor de SWFUpload necesita recibir un objeto del tipo Object (JavaScript). Los datos de este objeto se pasan directamente al constructor.

La referencia al objeto SWFUpload inicializado debe conservarse bien (yukon: es decir, almacenarla en una variable, como `swfu` en el ejemplo), porque esta referencia también es necesaria para iniciar la carga de archivos y controlar otras características.

Ejemplo:Al inicializar SWFUpload, se puede pasar directamente un objeto anónimo para configurar los parámetros.

var swfu; window.onload = function () { swfu = new SWFUpload({ upload_url : "http://www.swfupload.org/upload.php", //处理上传文件的地址 flash_url : "http://www.swfupload.org/swfupload.swf", //核心功能swf的地址 flash9_url : "http://www.swfupload.org/swfupload_fp9.swf", file_size_limit : "20 MB" //文件大小限制 }); };

Ejemplo:También se puede usar una variable de objeto (settings_object) para pasar los parámetros de configuración al inicializar SWFUpload.

var swfu; window.onload = function () { var settings_object = { upload_url : "http://www.swfupload.org/upload.php", flash_url : "http://www.swfupload.org/swfupload.swf", flash9_url : "http://www.swfupload.org/swfupload_fp9.swf", file_size_limit : "20 MB" }; swfu = new SWFUpload(settings_object); };

Biblioteca de JavaScript (JavaScript library)

Si desea utilizar SWFUpload, el archivo de la biblioteca JavaScript (swfupload.js) debe incluirse en la página que se vaya a usar.

Una vez que se crea el objeto SWFUpload, se puede acceder a numerosas funciones. El desarrollador puede usarlas para controlar SWFUpload.

Ejemplo:Cómo incluir la biblioteca swfupload.js

<script type="text/javascript" src="../www.swfupload.org/swfupload.js"></script>

Ejemplo:Inicialización bajo demanda de SWFUpload.

var swfu = new SWFUpload({ upload_url : "http://www.swfupload.org/upload.php", flash_url : "http://www.swfupload.org/swfupload.swf", flash9_url : "http://www.swfupload.org/swfupload_fp9.swf", button_placeholder_id : "spanSWFUploadButton" //yukon：这里有个新参数，将会使用js在id为"spanSWFUploadButton"的标签容器如span，div中创建一个"选择"按钮 });

【Contenido nuevo】Control Flash (Flash Control)

La biblioteca js de SWFUpload puede cargar dinámicamente el control Flash (swfupload.swf o swfupload_fp9.swf).

La dirección del archivo del control Flash debe definirse en el objeto de configuración de SWFUpload en el momento de la inicialización.

El control Flash es en realidad una pequeña película Flash que puede controlar la selección, validación y carga de archivos.

En la página se presenta al usuario como un botón de interfaz personalizable, y puede detectar la versión de Flash Player (9, 10) para cargar automáticamente el control Flash adecuado a la versión del reproductor del usuario.

Usando flash_url y flash9_url se pueden configurar las rutas de swfupload.swf o swfupload_fp9.swf. (yukon: ya se ha escrito en los ejemplos anteriores)

Manejo de eventos (The Event Handlers)

Los desarrolladores deben crear un conjunto de funciones js para manejar los eventos de SWFUpload. Estas funciones se activan y ejecutan cuando ocurren varios eventos importantes.

Al manejar los eventos de SWFUpload, los desarrolladores pueden proporcionar retroalimentación sobre el progreso de la carga, mensajes de error, finalización de la carga, etc. Nota: los desarrolladores no deben sobrescribir las funciones almacenadas en SWFUpload.prototype.

Ejemplo:Manejo de eventos e inicialización de SWFUpload.

// Función de manejo del evento de inicio de carga (uploadStart). El valor de la propiedad "upload_start_handler" del objeto de configuración debe ser el nombre de esta función. var myCustomUploadStartEventHandler = function (file) { var continue_with_upload; if (file.name === "the sky is blue") { continue_with_upload = true; } else { continue_with_upload = false; } return continue_with_upload; }; // Función de manejo del evento de carga exitosa (uploadSuccess). El valor de la propiedad "upload_success_handler" del objeto de configuración debe ser el nombre de esta función. var myCustomUploadSuccessEventHandler = function (file, server_data, receivedResponse) { alert("The file " + file.name + " has been delivered to the server. The server responded with " + server_data); }; // Create the SWFUpload Object var swfu = new SWFUpload({ upload_url : "http://www.swfupload.org/upload.php", flash_url : "http://www.swfupload.org/swfupload.swf", flash9_url : "http://www.swfupload.org/swfupload_fp9.swf", file_size_limit : "200 MB", upload_start_handler : myCustomUploadStartEventHandler, upload_success_handler : myCustomUploadSuccessEventHandler

Variables globales y constantes (Globals and Constants)

SWFUpload define algunas variables globales y constantes que son muy útiles para aplicaciones avanzadas de SWFUpload y para el manejo de errores; todas son de solo lectura.

【Contenido nuevo】SWFUpload.instances

SWFUpload.instances es un objeto de matriz que almacena referencias a todas las instancias de SWFUpload en una página. Flash Player se basa en este objeto de matriz para llamar a las funciones correctas de manejo de eventos. El índice del objeto de matriz SWFUpload.instances (SWFUpload.instances[index]) es la propiedad movieName.

SWFUpload.movieCount

SWFUpload.movieCount es una variable global que registra cuántas instancias del objeto SWFUpload se han creado en la página y se usa para asegurar que cada película Flash reciba un movieName único.

【Contenido nuevo】SWFUpload.QUEUE_ERROR

SWFUpload.QUEUE_ERROR es un objeto js simple que contiene constantes de códigos de error de cola (Queue Error code). Se utiliza para determinar qué código de error se enviará cuando ocurra un error de cola de archivos (fileQueueError).

SWFUpload.QUEUE_ERROR = { QUEUE_LIMIT_EXCEEDED : -100, FILE_EXCEEDS_SIZE_LIMIT : -110, ZERO_BYTE_FILE : -120, INVALID_FILETYPE : -130 };
  • QUEUE_LIMIT_EXCEEDED - Indica que el usuario puso en cola demasiados archivos, superando la longitud máxima de la cola. Sin embargo, una vez que los archivos en la cola se cargan o se eliminan, el usuario aún puede agregar archivos a la cola de espera de carga.
  • FILE_EXCEEDS_SIZE_LIMIT - Indica que se superó el límite de tamaño de archivo (file_size_limit).
  • ZERO_BYTE_FILE - Indica que el archivo seleccionado es de 0 bytes. Flash Player no puede procesar archivos vacíos. Cargar iconos de acceso directo de Windows también puede desencadenar este error.
  • INVALID_FILETYPE - Indica que la extensión del archivo seleccionado no coincide con la permitida. Este error puede ocurrir cuando el usuario ingresa manualmente un nombre de archivo con una extensión no permitida, en lugar de seleccionar el archivo con un clic del ratón.

【Contenido nuevo】SWFUpload.UPLOAD_ERROR

SWFUpload.UPLOAD_ERROR también es un objeto de matriz js simple que contiene constantes de códigos de error de carga (Upload Error code constants). Se utiliza para determinar qué código de error se enviará cuando ocurra el evento de error de carga (uploadError).

SWFUpload.UPLOAD_ERROR = { HTTP_ERROR : -200, MISSING_UPLOAD_URL : -210, IO_ERROR : -220, SECURITY_ERROR : -230, UPLOAD_LIMIT_EXCEEDED : -240, UPLOAD_FAILED : -250, SPECIFIED_FILE_ID_NOT_FOUND : -260, FILE_VALIDATION_FAILED : -270, FILE_CANCELLED : -280, UPLOAD_STOPPED : -290 };
  • HTTP_ERROR - Se intentó cargar al servidor, pero este no devolvió el código de estado 200 (200 significa sin anomalías).
  • MISSING_UPLOAD_URL - No se ha configurado la dirección de carga (upload_url).
  • IO_ERROR - Ocurrió algún error al leer y enviar el archivo. Generalmente sucede cuando el servidor cierra inesperadamente la conexión del terminal.
  • SECURITY_ERROR - Error de seguridad; la carga viola las restricciones de seguridad. Es poco común.
  • UPLOAD_LIMIT_EXCEEDED - El usuario intentó cargar más archivos que el número preestablecido.
  • UPLOAD_FAILED - Se produjo un error al intentar inicializar la carga. Es poco común.
  • SPECIFIED_FILE_ID_NOT_FOUND - Un archivo comenzó a cargarse, pero no se encontró el archivo. (yukon: después de seleccionar el archivo y agregarlo a la cola, el usuario cambió el nombre del archivo o lo eliminó en el disco, etc.)
  • FILE_VALIDATION_FAILED - Se devolvió algún error cuando comenzó la carga.
  • FILE_CANCELLED - Se canceló la carga (se llamó a la función cancelUpload).
  • UPLOAD_STOPPED - Se pausó la carga (se llamó a la función stopUpload).
  • RESIZE_ERROR - Se produjo algún error al cambiar el tamaño de la imagen.

【Contenido nuevo】SWFUpload.FILE_STATUS

SWFUpload.FILE_STATUS es un objeto de matriz js que contiene constantes de códigos de estado de archivo (File Status code constants). Se utiliza para comprobar la propiedad file status del objeto File.

SWFUpload.FILE_STATUS = { QUEUED : -1, IN_PROGRESS : -2, ERROR : -3, SUCCESS : -4, CANCELLED : -5 };
  • QUEUED - Indica que este archivo está esperando en la cola de carga.
  • IN_PROGRESS - Indica que este archivo se está cargando actualmente.
  • ERROR - Indica que este archivo provocó un error de cola o de carga.
  • COMPLETE - Indica que este archivo se ha transferido correctamente al servidor.
  • CANCELLED - Indica que la carga de este archivo fue cancelada (se llamó a la función cancelUpload).

【Nuevo】SWFUpload.UPLOAD_TYPE [Función: determinar el tipo de carga]

SWFUpload.UPLOAD_TYPE es un objeto de matriz js que contiene constantes de tipo de carga (Upload Type constants). Se utiliza para comprobar la propiedad de tipo de carga del objeto File (upload type property).

  • NORMAL - Carga normal de SWFUpload.
  • RESIZED - Carga de una imagen cuyo tamaño fue ajustado; los datos se envían mediante el método POST de HTTP.

【Contenido nuevo】SWFUpload.BUTTON_ACTION [Función: determina la acción a ejecutar después de hacer clic en el botón]

SWFUpload.BUTTON_ACTION es un objeto de matriz js que contiene constantes de códigos de acción de botón (button action code constants). Se utiliza para establecer el valor de la acción del botón (button_action), permitiendo así configurar las respuestas correspondientes del botón interactivo en la película Flash a varias acciones del ratón.

SWFUpload.BUTTON_ACTION = { SELECT_FILE : -100, SELECT_FILES : -110, START_UPLOAD : -120 }

  • SELECT_FILE - Al hacer clic en el botón, se abre un cuadro de diálogo de selección de un solo archivo. El evento de clic del ratón (configurado en js) no se activará.
  • SELECT_FILES - Al hacer clic en el botón, se abre un cuadro de diálogo de selección de múltiples archivos. El evento de clic del ratón (configurado en js) no se activará.
  • START_UPLOAD - Al hacer clic en el botón, el primer archivo en la cola de carga será cargado. El evento de clic del ratón (configurado en js) no se activará.
  • NONE - En este caso, el evento de clic del ratón (configurado en js) se activará.
  • JAVASCRIPT - Igual que NONE. Este valor está en desuso.

【Contenido nuevo】SWFUpload.CURSOR [Función: cambiar el estilo del cursor]

SWFUpload.CURSOR es un objeto de matriz js que contiene constantes de cursor de botón. Se utiliza para establecer el valor del cursor del botón (button_cursor), cambiando así el estilo del cursor cuando el ratón apunta al botón.

SWFUpload.CURSOR = { ARROW : -1, HAND : -2 }
  • ARROW - El cursor se muestra como un puntero de flecha.
  • HAND - El cursor se muestra como una mano.

【Contenido nuevo】SWFUpload.WINDOW_MODE [Función: modo de visualización de la película]

SWFUpload.WINDOW_MODE es un objeto array de JS que contiene las constantes de parámetros del modo de ventana de la película del botón (button movie wmode parameter constants). Se usa para indicar al navegador cómo presentar la película Flash.

Algunas configuraciones de WINDOW_MODE/WMODE pueden causar problemas en ciertos navegadores. Ver detalles a continuación.Known Issues.

SWFUpload.WINDOW_MODE = { WINDOW : "window", TRANSPARENT : "transparent", OPAQUE : "opaque" };
  • WINDOW es el modo predeterminado. La película Flash se dibuja en la capa superior de la página.
  • OPAQUE permite que otros elementos de la página cubran esta película de botón.
  • TRANSPARENT: transparente. El fondo del botón se vuelve transparente, permitiendo que los elementos HTML se muestren debajo.

[Nuevo] SWFUpload.RESIZE_ENCODING [Función: indica el formato de codificación de la imagen]

SWFUpload.RESIZE_ENCODING es un objeto array de JS que contiene las constantes de tipo de codificación de redimensionamiento (resize encoding type constants). Se utiliza para indicar el formato de codificación de la imagen redimensionada.

  • JPEG: formato de codificación JPEG.
  • PNG: formato de codificación PNG.

[Nuevo] SWFUpload.onload [Función: define la función de operación después de que la página haya terminado de cargarse]

onload es una función que se puede ejecutar mediante el método addDOMLoadEvent de swfobject. A través de este método, puedes ejecutar tu script después de que la página haya terminado de cargarse. Sin embargo, debes asegurarte de no haber utilizado otros métodos similares (por ejemplo, "Ready" del framework jQuery o "dom:loaded" de la biblioteca Prototype).

SWFUpload.onload = function () { new SWFUpload(settingsObject); }

Un ejemplo anterior inicializará SWFUpload en el evento de carga más temprano del navegador. La mayoría de los eventos de preparación del DOM (DOMReady event) se ejecutan justo después del evento window.onload.

Propiedades

Siga las descripciones de la lista de propiedades a continuación para usar estas propiedades. Si se utiliza incorrectamente una propiedad de solo lectura o solo escritura, se producirá un error de SWFUpload.

[Nuevo contenido] customSettings (lectura/escritura) [Función: configuración personalizada por el desarrollador]

La propiedad "customSettings" es un objeto vacío de JS. Se utiliza para almacenar datos relacionados con una instancia de SWFUpload. Su contenido se puede inicializar usando la propiedad custom_settings del objeto de configuración.

Example:

// 初始化 SWFUpload 对象时使用一些自定义设置 var swfu = new SWFUpload({ custom_settings : { custom_setting_1 : "custom_setting_value_1", custom_setting_2 : "custom_setting_value_2", custom_setting_n : "custom_setting_value_n", } }); swfu.customSettings.custom_setting_1 = "custom_setting_value_1"; // 改变一个已有的自定义设置 swfu.customSettings.myNewCustomSetting = "new custom setting value"; // 添加一个新的自定义设置 // 用一个全新的对象来重写自定义设置 swfu.customSettings = { custom_setting_A : "custom_setting_value_A", custom_setting_B : "custom_setting_value_B" };

Los valores almacenados en el objeto customSettings pueden ser accedidos fácilmente por las funciones de manejo de eventos: (yukon: esta propiedad aprovecha las características dinámicas de JS, otorgando al desarrollador un alto grado de libertad de desarrollo)

function uploadSuccess(file, serverData, receivedResponse) { if (this.customSettings.custom_setting_A === true) { alert("Checked the custom setting!"); } }

movieName (solo lectura) [Función: almacena el identificador único de una instancia de SWFUpload]

Contiene el nombre identificador único de una instancia de SWFUpload. Este valor se puede pasar a Flash para ayudar a la interacción entre ActionScript y JavaScript. Se utiliza para indexar las instancias almacenadas en el array SWFUpload.instances. No debes ni puedes cambiarlo.

Métodos

Los siguientes métodos se utilizan para operar SWFUpload. Algunos métodos pueden vincularse al evento de clic de elementos DOM, otros se invocan internamente para el manejo de eventos de SWFUpload.

object addSetting(setting_name, value, default_value)

En desuso The addSetting function sets a setting value. If the value is undefined then the default_value is used. The function is used by SWFUpload

addSetting returns the value that was stored in the setting.

object getSetting(setting_name)

【Contenido nuevo】Eventos Events

SWFUpload dispara una serie de eventos durante su funcionamiento. Los desarrolladores pueden utilizar estos eventos de devolución de llamada para controlar la interfaz de usuario, controlar las operaciones o informar errores.

Todos los eventos se invocan en el contexto de la instancia de SWFUpload, por lo que usar this en estos eventos de devolución de llamada permite acceder directamente a la instancia que disparó el evento.

Todos los eventos deben configurarse previamente en el parámetro setting al inicializar la instancia.

【Nuevo:】

Al subir un archivo, los eventos se invocan en el siguiente orden (cadena de eventos de subida):

  • uploadResizeStart: inicio de la subida con la función de ajuste de tamaño de imagen añadida.
  • uploadStart: inicio de subida normal.
  • uploadProgress: subida en curso (se invoca repetidamente durante el proceso de subida del archivo).
  • uploadError: error de subida (se invoca cuando ocurre algún error; el archivo en subida será cancelado o detenido).
  • uploadSuccess: subida exitosa (el archivo se subió correctamente y el servidor recibió datos utilizables).
  • uploadComplete: subida completada (la subida ha terminado; SWFUpload se prepara para subir el siguiente).

Descripción detallada de los parámetros de configuración (Settings Description)

[Nuevo] upload_url

Valor por defecto:Cadena vacía

La configuración de upload_url recibe una URL completa, absoluta o relativa al archivo SWF. Se recomienda usar una ruta absoluta completa para evitar errores en la ruta de solicitud causados por el navegador y Flash Player al modificar la configuración de la ruta base. (yukon: esto es en realidad relativo; si tu swfupload y la página de procesamiento de carga de PHP siempre están en la misma carpeta del sitio, yo recomendaría usar una ruta relativa)

Si la propiedad preserve_relative_urls del objeto de configuración es false, SWFUpload convertirá las rutas relativas en rutas absolutas para evitar que la URL sea interpretada en diferentes formatos por Flash Player en distintos sistemas. Si desactivas esta conversión de SWFUpload, deberías usar rutas relativas para especificar la ubicación de swfupload.swf.

Nota:Aquí se debe considerar el modelo de dominio de seguridad de Flash Player.

Valor por defecto:Filedata

El parámetro file_post_name le permite establecer el valor del nombre (name) del archivo cargado en la información POST (similar al atributo name de <input type="file" name="Filedata"/> en un formulario tradicional).

Nota: (pendiente para la versión 2.5)En Linux, este parámetro no tiene efecto; el nombre recibido es siempre "Filedata". Por lo tanto, para garantizar la máxima compatibilidad, se recomienda usar el valor por defecto para este parámetro.

[Nuevo] post_params

Valor por defecto:Un objeto Object vacío

post_params define un conjunto de pares clave/valor que permite enviar datos adicionales al servidor junto con cada archivo durante la carga. Esta propiedad se puede asignar con un objeto array de JavaScript. Los pares clave/valor deben ser solo cadenas o números. (Se puede comprobar con la función typeof() de JavaScript)

Nota: Flash Player 8 no admite el envío de datos POST adicionales. SWFUpload enviará automáticamente post_params en forma de query string.

use_query_string

Valor por defecto:false

El valor de esta propiedad puede ser true o false; establece si post_params se envía mediante GET. Si es false, se envía mediante POST. Introducido desde v2.1.0.

[Nuevo] preserve_relative_urls

Valor por defecto:false

preserve_relative_urls tiene como valor posible una variable booleana. Indica si SWFUpload convierte o no las URL relativas en absolutas. Si se establece en true, no se realizará la conversión. El valor por defecto es false, es decir, se convierte automáticamente.

requeue_on_error

Valor por defecto:false

El valor de esta propiedad puede ser true o false. Si se establece en true, cuando un objeto de archivo experimenta un error uploadError (excepto errores de fileQueue y errores FILE_CANCELLED), el objeto de archivo se vuelve a insertar al frente de la cola de carga de archivos, en lugar de descartarse. Si es necesario, el archivo reinsertado puede cargarse nuevamente. Si se desea eliminar ese objeto de archivo de la cola de carga, se debe usar el método cancelUpload.

Todos los eventos asociados con el fallo de carga también se dispararán uno a uno, por lo que volver a poner en cola un archivo cuya carga falló puede causar conflictos con Queue Plugin (o con el código personalizado que carga automáticamente toda la cola de archivos). Si en el código se llama al método startUpload para cargar automáticamente el siguiente archivo y además no se toma ninguna medida para sacar de la cola al archivo que falló, ese archivo fallido reinsertado comenzará a cargarse de nuevo, luego fallará de nuevo, se reinsertará, se cargará de nuevo... entrando en un bucle sin fin.

Esta configuración se introdujo en v2.1.0.

http_success

Valor por defecto:[]

Este array permite personalizar los códigos de estado HTTP que disparan el evento success. El código de estado 200 siempre dispara success, y solo el estado 200 proporciona serverData.

Cuando se acepta un código de estado HTTP distinto de 200, el servidor no necesita devolver contenido.

[Nuevo] assume_success_timeout

Valor por defecto: 0

assume_success_timeout establece cuántos segundos esperará SWFUpload para detectar la respuesta del servidor; al superar el tiempo de espera, se forzará el disparo del evento de carga exitosa (uploadSuccess). Esta propiedad sirve para funcionar correctamente bajo errores de Flash Player, evitando largas esperas de respuesta del servidor y resolviendo el error de Flash Player en el sistema operativo Mac que impide que el servidor devuelva contenido.

Flash ignorará la respuesta del servidor 30 segundos después de que se dispare el último evento uploadProgress y forzará el disparo del evento de carga exitosa.

Si assume_success_timeout se establece en 0, esta característica se desactiva. SWFUpload esperará durante mucho tiempo a que Flash Player dispare el evento uploadSuccess.

file_types

Valor por defecto:*.*

Establece las reglas de filtrado de tipos de archivo en el cuadro de diálogo de selección de archivos. Esta propiedad recibe extensiones de tipo de archivo separadas por punto y coma, por ejemplo "*.jpg;*.gif", lo que permite que el usuario solo vea y seleccione archivos de tipo jpg y gif en el cuadro de diálogo. Por defecto se aceptan todos los tipos de archivo.

Recordatorio:Esta configuración es solo un filtro del navegador del cliente; no impone ninguna restricción de filtrado de tipos de archivo en el procesamiento del lado del servidor. Si necesita hacer un filtrado estricto de archivos, el servidor también debe realizar una detección mediante programación.

file_types_description

Valor por defecto:All Files

file_size_limit

Valor por defecto:0

Si se omite la unidad, se usa KB por defecto. El valor especial 0 indica que no hay límite de tamaño de archivo.

Recordatorio:Esta configuración solo es válida en el navegador del cliente; no tiene ninguna restricción en el procesamiento de archivos del lado del servidor. Si necesita hacer un filtrado estricto de archivos, el servidor también debe procesarlo mediante programación.

file_upload_limit

Valor por defecto:0

Establece el número máximo de archivos que la instancia de SWFUpload permite cargar, y también es el límite superior de la propiedad file_queue_limit en el objeto de configuración. Una vez que el usuario ha cargado exitosamente o ha añadido archivos a la cola alcanzando el número máximo, no se pueden añadir más archivos. El valor especial 0 indica que no hay límite en la cantidad de archivos. Solo los archivos cargados exitosamente (cuando la carga dispara el evento uploadSuccess) cuentan para el límite de carga. El método setStats puede usarse para modificar la cantidad de archivos cargados exitosamente.

Nota:Este valor no se puede usar entre páginas; se restablece cuando la página se actualiza. El límite estricto de cantidad de archivos cargados debe ser detectado y gestionado por el servidor.

file_queue_limit

Valor por defecto:0

Desde la versión v2.0 de SWFUpload se introdujeron varios complementos. Estos ayudan a SWFUpload a implementar algunas funciones.

La documentación de uso de la mayoría de los complementos se encuentra en la carpeta de complementos (plugin) de js.

Problemas conocidos (Known Issues)

Flash Player y los errores de muchos navegadores afectan a SWFUpload. Pero seguimos trabajando duro.

Cancelación en Linux (Cancelling in Linux)

Con Flash Player 9 y versiones anteriores, ejecutar la función de cancelar la carga en el sistema operativo Linux puede provocar que el navegador se bloquee. Sin embargo, las versiones más recientes de Flash Player han mejorado este problema.

Progreso de carga en Linux (Upload Progress in Linux)

Flash Player en Linux solo envía un evento de progreso de carga (uploadProgress) después de que la carga se completa, en lugar de enviarlo continuamente durante el proceso de carga como en Windows.

Esto se debe a que algunas distribuciones de Linux bloquean todo el navegador durante el proceso de carga.

Progreso de carga en Mac (Upload Progress in OS X)

Hemos recibido algunos informes de que Flash Player en el sistema operativo Mac no puede activar el evento uploadProgress. Los detalles aún deben investigarse, pero tenga en cuenta su posible problema.

MIME Type

Independientemente del formato MIME real del archivo, Flash Player usa el formato mimeapplication/octet-streampara subir todos los archivos.

Número máximo de archivos seleccionables (Maximum number of selected files)

Flash Player no limita el número máximo de archivos que se pueden seleccionar para subir, pero limita la longitud total de los nombres de archivo. Esta cadena se compone así: "nombre de archivo" espacio "nombre de archivo"... El número de archivos que se pueden subir depende de la limitación del sistema operativo sobre la longitud total del nombre de archivo. Si el usuario selecciona demasiados archivos, recibirá un mensaje de advertencia de Flash Player, que se mostrará en el cuadro de diálogo de selección de archivos (yukon: en XP subí 173 archivos de una vez y no hubo advertencia...)

Proxy (Proxies)

Flash Player puede no utilizar correctamente el proxy. Tiene algunos problemas al manejar la autenticación del proxy, lo que puede causar ciertos conflictos.

Algunos programas antivirus utilizan un proxy de cliente local para recibir los archivos subidos y escanearlos (parece que interceptan el archivo subido y lo escriben en un servidor proxy; solo después de escanearlo lo envían realmente al servidor de destino). Esto hace que SWFUpload crea erróneamente que todo el archivo se ha subido, y emitirá una gran cantidad de eventos uploadProgress hasta llegar al 100%. Mientras el proxy realmente sube el archivo al servidor de destino, SWFUpload parece estar pausado.

Kaspersky antivirus: Kaspersky(y otros antivirus) implementan un proxy de cliente para interceptar los datos de carga salientes locales. SWFUpload no puede detectar la existencia de este sistema proxy. Estos servidores proxy pueden recibir los archivos subidos muy rápidamente, escanearlos y luego enviarlos al servidor de destino.

Módulo de seguridad Apache mod_security

El módulo de seguridad de Apache, mod_security, valida los mensajes POST que recibe el servidor. Flash Player implementa un caso límite (an edge case, ¿se traduce como 'forma astuta'?) (hay un parámetro que decide si validar) para subir archivos por POST, y el servidor también lo implementa.

Capa de sockets seguros (SSL)

Hemos recibido algunos informes de que Flash Player no puede subir a través de SSL. Los detalles de este problema aún no se han confirmado, pero parece que la carga bajo SSL no es fiable. Especialmente cuando se utilizan certificados autofirmados de clave pública (self-signed certificates) aparecen problemas.

Asimismo, los certificados SSL emitidos por una autoridad de certificación (CA) no confiable no pueden ser aceptados por Flash. Porque Flash no proporciona un método para aceptar dichos certificados. Como en el error de cookies mencionado anteriormente, Flash Player en Windows solo acepta certificados emitidos por CA de su lista de confianza, independientemente del certificado que esté utilizando el navegador.

Autenticación (Authentication)

El mecanismo de autenticación HTTP no es bien compatible con Flash Player. Las versiones más recientes de Flash Player son algo mejores, pero las versiones antiguas pueden provocar que el navegador se bloquee.

Conexiones terminadas prematuramente (Prematurely terminated connections)

Terminar prematuramente la respuesta (por ejemplo, el método Response.end() en ASP.NET) hará que, aunque la carga se haya completado, SWFUpload informe de un error de carga.

Nombre POST del archivo (Filedata POST name in Linux)

Cambiar el nombre de recepción del archivo (por defecto "Filedata", propiedad file_post_name en el objeto de configuración) no funciona en Flash Player de Linux.

Cookie bug

En Windows, en navegadores que no son IE (FireFox, Opera, Safari, etc.), el plugin de Flash enviará las cookies de IE. Esto rompe los mecanismos de sesión y autenticación de muchos servidores.

Los desarrolladores deben resolver manualmente el problema de transmitir la información de sesión y las cookies de autenticación, y también deben modificar manualmente la sesión en el servidor si quieren usar sesiones.

Sin embargo, el paquete de SWFUpload proporciona un código de ejemplo en PHP o ASP.Net para resolver este error.

Errores de la clase ExternalInterface (ExternalInterface bugs)

Cuando interactúa con el navegador/JavaScript, Flash Player no puede codificar correctamente los datos usando el método escape. SWFUpload ha hecho un gran esfuerzo para resolver este problema. Si este error se corrige en el futuro, SWFUpload enviará además datos codificados con escape.

Error de datos de servidor demasiado largos (Server Data length bugs)

Los datos de respuesta demasiado largos del servidor causan errores en Flash Player en sistemas Mac o Linux. Los datos pueden cortarse, alterarse o duplicarse en parte. Recomendamos que los datos que envía el servidor sean lo más breves y concisos posible.

Avant Browser

Una vez que se ha almacenado en caché, SWFUpload no funciona correctamente en el navegador Avant.

Desde la versión 2.2.0 de SWFUpload se añadió la configuración prevent_swf_caching para intentar resolver este problema.

Cuadro de diálogo de selección de archivos y cambio de página (File Dialog & Page Changing)

Salir o actualizar la página mientras aparece el cuadro de diálogo de selección de archivos provocará que el navegador se bloquee. (En todos los navegadores y sistemas operativos)

Esta situación ocurre sobre todo cuando se define un enlace <a> cuyo "onclick" llama a selectFile/selectFiles, pero no se desactiva la acción de navegación predeterminada. Al hacer clic en el enlace, se salta a otra página y al mismo tiempo se abre el cuadro de diálogo de selección de archivos.

(yukon: otra posibilidad: el programa fuerza la actualización o redirección de la página. Por ejemplo, refresh en la etiqueta <meta> de HTML, Response.Redirect() en ASP.NET, header() en PHP, etc.)

Scripts de carga con ejecución demasiado larga (Long Running Upload Scripts)

Después de que Flash sube archivos al servidor web, se ejecuta el programa receptor de la carga. El programa receptor decide si almacenarlos, crear miniaturas, escanear virus, etc. Si el programa receptor no devuelve ningún dato en 30 segundos, Flash cortará la conexión y devolverá un error de E/S.

Si no quieres que esto ocurra, durante el proceso haz que el servidor devuelva algunos caracteres o datos (si puedes).

Por ejemplo, en PHP, aunque el script PHP puede continuar completando la operación con éxito después de que Flash se desconecte, Flash no recibirá ningún dato de retorno después de la desconexión.

Modo de ventana WMODE / BUTTON_WINDOW_MODE

En algunos navegadores, si el control flash no está dentro del área visible de la pantalla, el WMODE configurado (establecido por BUTTON_WINDOW_MODE) impedirá la carga del control flash. Solo cuando se mueve la barra de desplazamiento para que el control flash entre en el área visible, se cargará y se mostrará.

(yukon: esto se hace para que la página se muestre lo antes posible. Por ejemplo, si abres una carpeta llena de imágenes, ajustas la vista a miniaturas y deslizas hacia abajo rápidamente, verás que los archivos de imagen inferiores van mostrando su contenido gradualmente.)

Esta característica puede tener efectos negativos en el plugin SWFObject. Los eventos de SWFUpload pueden no activarse, y la imagen de fondo del botón puede no cargarse hasta que el control se haya renderizado por completo.

En algunos sistemas operativos (Linux), cuando WMODE se establece en transparente, el cuadro de diálogo de selección de archivos abierto por Flash aparecerá detrás de la ventana del navegador.

Fugas de memoria (Memory Leaks)

Algunos navegadores (especialmente IE) no pueden recuperar memoria después de que Flash Player use la clase ExternalInterface para interactuar con JS (por ejemplo, SWFUpload). Generar demasiadas instancias de SWFUpload y actualizar la página varias veces provocará que el navegador consuma demasiada memoria, lo que a su vez provocará que el navegador se bloquee u otros errores del sistema.

En SWFUpload versión 2.2.0, implementamos algunos mecanismos para prevenir fugas de memoria. Sin embargo, se recomienda llamar al método destroy() al cerrar la página. Si usa cientos de instancias de SWFUpload en una página, debe probar cuidadosamente para evitar fugas de memoria.

Algunos problemas relacionados con el sistema operativo Mac (Other Mac Issues)

  • Es posible que los datos devueltos por el servidor o Flash Player en sistemas Mac no activen el evento uploadSuccess. Hemos añadido una configuración assume_success_timeout para ayudar a resolver este problema. Pero en general, devolver un campo breve después de una recepción exitosa es muy fácil y confiable.
  • Algunos usuarios informan que hay problemas al cargar archivos a direcciones que contienen subdominios en sistemas Mac.
  • Algunos usuarios informan que las redirecciones (código de estado HTTP 302) no son manejadas correctamente por Mac Flash Player. En Windows parece que no hay este problema. Las redirecciones 302 se usan a menudo en algunos modos de autenticación y marcos de diseño MVC.
  • La documentación de desarrollo de Flash indica que en sistemas anteriores a OS X 10.3, bytes loaded siempre será -1. SWFUpload lo cambia a 0, pero total bytes no se enviará, y el progreso nunca llegará al 100%. Por lo tanto, configure la actualización de la interfaz de usuario para que muestre el 100% cuando se emitan los eventos uploadSuccess o uploadComplete al finalizar la carga. De esta manera, la interfaz de usuario será consistente en todos los sistemas.
  • Algunos usuarios informan que Mac Flash Player tendrá problemas cuando la ruta de carga contenga caracteres de espacio. Por favor, reemplácelos con + o %20.
  • Algunos usuarios informan que Mac Flash Player agregará el número de puerto en el encabezado HTTP HOST (por ejemplo, http://www.example.com:80). Si verifica este parámetro, tenga cuidado con este problema.
  • Si un archivo contiene solo una bifurcación de recursos (resource fork), será tratado por Flash Player como un archivo de 0 bytes y no se podrá cargar (Nota: Flash Player 10.1 puede haber resuelto este problema).
