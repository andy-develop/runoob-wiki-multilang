2. Ofuscación

Antes de publicar la aplicación, ofuscar el código puede hacer que, incluso si nuestro código es decompilado, sea difícil de leer. AS integra por sí mismo la utilidad de JavaProGuardcomo herramienta de compresión, optimización y ofuscación; el archivo de reglas de ofuscación es:proguard-rules.proSi deseas habilitar las reglas de ofuscación, modificabuild.gradlelo correspondiente enminifyEnabled为turepara activar la ofuscación.ofuscar el códigoAdemás, también puedereducir el volumen de la aplicación, realizaroptimización a nivel de bytecode¡Hace que nuestra APP se ejecute más rápido! Además, después de la ofuscación, por defectoapp/build/outputs/mapping/releasese generará enmapping.txt, archivo de reglas de ofuscaciónCon este archivo se puede revertir al código anterior a la ofuscación. Además, hay algunos lugares que deben evitar ser ofuscados; de lo contrario, la APP dará errores al ejecutarse.

Debido a la limitación de espacio, no explicaré aquí las reglas de ofuscación; si te interesa, puedes ir a:Ofuscación de Android: de principiante a expertoAquí usaré directamente una plantilla genérica de Internet; si se trata de bibliotecas de terceros, los documentos oficiales generalmente incluyen reglas de ofuscación, solo hay que copiar y pegar. La plantilla genérica es la siguiente:

#指定压缩级别
-optimizationpasses 5

#不跳过非公共的库的类成员
-dontskipnonpubliclibraryclassmembers

#混淆时采用的算法
-optimizations !code/simplification/arithmetic,!field/*,!class/merging/*

#把混淆类中的方法名也混淆了
-useuniqueclassmembernames

#优化时允许访问并修改有修饰符的类和类的成员
-allowaccessmodification

#将文件来源重命名为“SourceFile”字符串
-renamesourcefileattribute SourceFile
#保留行号
-keepattributes SourceFile,LineNumberTable
#保持泛型
-keepattributes Signature

#保持所有实现 Serializable 接口的类成员
-keepclassmembers class * implements java.io.Serializable {
    static final long serialVersionUID;
    private static final java.io.ObjectStreamField[] serialPersistentFields;
    private void writeObject(java.io.ObjectOutputStream);
    private void readObject(java.io.ObjectInputStream);
    java.lang.Object writeReplace();
    java.lang.Object readResolve();
}

#Fragment不需要在AndroidManifest.xml中注册，需要额外保护下
-keep public class * extends android.support.v4.app.Fragment
-keep public class * extends android.app.Fragment

# 保持测试相关的代码
-dontnote junit.framework.**
-dontnote junit.runner.**
-dontwarn android.test.**
-dontwarn android.support.test.**
-dontwarn org.junit.**

3. Firma y empaquetado

La importancia de la firma de aplicaciones es evidente,es la marca única de la aplicación，y la credencial de identidad del desarrollador¡Esto puede evitar que las aplicaciones ya instaladas por los usuarios sean sobrescritas o reemplazadas por terceros malintencionados! Este tipo de reempaquetado tras la ingeniería inversa de una APP es muy común en apps de pago y juegos App.

En cuanto a la generación y empaquetado de firmas, la documentación oficial ya contiene una explicación detallada (posiblemente se necesite una VPN):

4. Reducción de APK

El APK, tras la ofuscación y el empaquetado con firma, tiene un tamaño de 1.4 MB. Pero para ser una aplicación de visualización de imágenes sin apenas imágenes y sin bibliotecas de terceros, realmente deja mucho que desear, así que es indispensable reducir un poco nuestro APK.

La herramienta integrada en Android StudioAPK Analyzerpuede hacer un análisis cuantitativo de nuestro APK:

Se puede ver que res ocupa la mayor proporción, y la razón son nuestros iconos. No voy a eliminar las imágenes ni las carpetas, solo usaré una herramienta para comprimir las imágenes. Aquí recomiendo una herramienta genial:ImageOptim

Después de comprimir, verás que el tamaño del APK se convierte en 1.3 MB; en este momento, analicemos de nuevo:

Parece que no hay un gran cambio, pero el APK simplemente se ha reducido en 0.1 MB. La compresión de los recursos de imagen es la operación más básica para reducir el APK. Sobre las otras técnicas de optimización, las discutiremos en detalle en versiones posteriores; el proyecto es pequeño y el potencial de optimización es muy bajo...

5. Publicación de la aplicación

No me preguntes por qué esel mercado Coolapk, los aficionados al modding de móviles suelen rondar por Coolapk ~Publicamos nuestra aplicación, luego completamos la información de descripción correspondiente y subimos capturas de pantalla; a continuación, haz clic enVersión de APK

Sube nuestro APK; aquí se validará el nombre de paquete del APK. Lo escribí mal y no lo había notado; solo después de corregirlo pude continuar.

Después de subirlo, hay que esperar la verificación; si la pasa, se puede enviar.

¡Una vez publicado, toca esperar la revisión!

Cuando el administrador lo apruebe mañana, ¡podremos encontrar nuestra App en Coolapk!

git checkout master # 切换到master分支
git rebase develop  # 合并develop分支
git push origin master # 推送到远程master分支
git tag v1.0.0  # 为当前commit打上TAG
git push origin v1.0.0 # 把TAG推送到远程仓库
