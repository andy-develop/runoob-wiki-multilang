Crear hilos

En la plataforma Windows, la API de Windows ofrece soporte para multihilo. En el concepto anterior de procesos e hilos mencionamos que un programa tiene al menos un hilo; este hilo se denomina hilo principal (main thread). Si no creamos hilos explícitamente, entonces el programa que producimos es un programa de un solo hilo que solo tiene el hilo principal.

A continuación, veamos las operaciones y métodos relacionados con hilos en Windows:

CreateThread y CloseHandle

CreateThread se utiliza para crear un hilo; su prototipo de función es el siguiente:

HANDLE WINAPI CreateThread(
    LPSECURITY_ATTRIBUTES   lpThreadAttributes, //线程安全相关的属性，常置为NULL
    SIZE_T                  dwStackSize,        //新线程的初始化栈在大小，可设置为0
    LPTHREAD_START_ROUTINE  lpStartAddress,     //被线程执行的回调函数，也称为线程函数
    LPVOID                  lpParameter,        //传入线程函数的参数，不需传递参数时为NULL
    DWORD                   dwCreationFlags,    //控制线程创建的标志
    LPDWORD                 lpThreadId          //传出参数，用于获得线程ID，如果为NULL则不返回线程ID
);

Descripción:

  • lpThreadAttributes: puntero a la estructura SECURITY_ATTRIBUTES; determina si el identificador devuelto puede ser heredado por procesos secundarios. Si es NULL, indica que el identificador devuelto no puede ser heredado por procesos secundarios.

  • dwStackSize: tamaño inicial de la pila del hilo, en bytes. El sistema alinea este valor.

  • lpStartAddress: puntero a una función; esta función será invocada y ejecutada por el hilo. Por lo tanto, esta función también se llama función de hilo (ThreadProc), y es la dirección de inicio de la ejecución del hilo. La función de hilo es una función de devolución de llamada, invocada por el sistema operativo dentro del hilo. El prototipo de la función de hilo es el siguiente:

    DWORD WINAPI ThreadProc(LPVOID lpParameter);    //lpParameter是传入的参数，是一个空指针

  • lpParameter: parámetro pasado a la función de hilo (ThreadProc); si no es necesario pasar parámetros, es NULL.

  • dwCreationFlags: indicadores que controlan la creación del hilo. Hay tres tipos: 0: el hilo se ejecuta inmediatamente después de su creación; CREATE_SUSPENDED: el hilo entra en estado de listo después de su creación y no se invoca hasta que el hilo se despierte; STACK_SIZE_PARAM_IS_A_RESERVATION: el parámetro dwStackSize especifica el tamaño de la pila inicial del hilo. Si no se especifica el indicador STACK_SIZE_PARAM_IS_A_RESERVATION, dwStackSize se establecerá en el valor reservado por el sistema.

  • Valor de retorno: si el hilo se crea correctamente, devuelve el identificador del nuevo hilo; de lo contrario, devuelve NULL. Si falla la creación del hilo, se puede obtener información de error mediante la función GetLastError.

    BOOL WINAPI CloseHandle(HANDLE hObject);        //关闭一个被打开的对象句柄
    Esta función se puede usar para cerrar el identificador del hilo creado. Si la función se ejecuta correctamente, devuelve true (distinto de 0); si falla, devuelve false (0). Si la ejecución falla, se puede llamar a la función GetLastError para obtener información de error.

CreateMutex、WaitForSingleObject、ReleaseMutex

De 【Demo2】 se puede ver que, aunque los hilos secundarios creados se ejecutaron con normalidad, el resultado de salida no es el efecto esperado. El efecto que esperábamos era que, después de cada declaración de salida, se insertara automáticamente un salto de línea, pero no todos los resultados son así. Esto se debe a que no se realizó la sincronización durante la ejecución de los hilos. Por ejemplo, en la primera línea de salida, después de que el hilo principal imprime "Hilo principal ===", se agota su intervalo de tiempo (quantum); entonces le toca al hilo secundario 1 imprimir. Después de que el hilo secundario imprime "Hilo 1 —", su intervalo de tiempo también se agota; entonces le toca al hilo principal ejecutar e imprimir "0", y luego le toca al hilo secundario 1 imprimir "0". Así aparece el resultado "Hilo principal === Hilo 1 — 0 0".

Hilo principal: cout << "Hilo principal === " << i << endl;
Hilo secundario: cout << pThreadData->strThreadName << " — " << i << endl;

Para evitar esta situación, hacemos una sincronización simple de los hilos; aquí usamos el mutex (Mutex).

Un mutex (Mutex) es similar a un semáforo binario; el recurso solo permite que un hilo acceda a él. A diferencia del semáforo binario, un semáforo puede ser adquirido y liberado por cualquier hilo en todo el sistema, es decir, el mismo semáforo puede ser adquirido por un hilo y liberado por otro. En cambio, un mutex requiere que el hilo que adquirió el bloqueo de mutex sea quien lo libere; no es válido que otros hilos liberen el mutex en su lugar.

Al usar mutex para la sincronización de hilos, se utilizarán las siguientes funciones:

HANDLE WINAPI CreateMutex(
    LPSECURITY_ATTRIBUTES lpMutexAttributes,        //线程安全相关的属性，常置为NULL
    BOOL                  bInitialOwner,            //创建Mutex时的当前线程是否拥有Mutex的所有权
    LPCTSTR               lpName                    //Mutex的名称
);

Descripción:lpMutexAttributes también es una estructura de seguridad, con la misma función que lpThreadAttributes en CreateThread; determina si el identificador devuelto puede ser heredado por procesos secundarios. Si es NULL, indica que el identificador devuelto no puede ser heredado por procesos secundarios. bInitialOwner indica si el hilo actual que crea el Mutex posee la propiedad del Mutex; si es TRUE, se especifica que el hilo creador actual es el propietario del objeto Mutex, y otros hilos deben llamar a ReleaseMutex antes de acceder. lpName es el nombre del Mutex.

DWORD WINAPI WaitForSingleObject(
    HANDLE hHandle,                             //要获取的锁的句柄
    DWORD  dwMilliseconds                           //超时间隔
);

Descripción:La función de WaitForSingleObject es esperar por un objeto especificado (como un objeto Mutex) hasta que el objeto esté en estado no ocupado (como cuando el objeto Mutex es liberado) o hasta que se exceda el intervalo de tiempo establecido. Además, hay una función similar, WaitForMultipleObjects, cuya función es esperar por uno o todos los objetos especificados hasta que todos los objetos estén en estado no ocupado, o hasta que se exceda el intervalo de tiempo establecido.

hHandlehObject: identificador del objeto especificado que se va a esperar. dwMilliseconds: intervalo de tiempo de espera, en milisegundos; si dwMilliseconds no es 0, se espera hasta que se agote el intervalo de tiempo dwMilliseconds o el objeto pase al estado no ocupado; si dwMilliseconds es INFINITE, significa espera indefinida hasta que el objeto esperado esté en estado no ocupado.

BOOL WINAPI ReleaseMutex(HANDLE hMutex);

Descripción:Libera el objeto de bloqueo mutex que se posee; hMutex es el identificador del mutex a liberar.

Para entender mejor la importancia de la sincronización de hilos y el método de uso del mutex, veamos otro ejemplo.

Comprar billetes de tren es una de las cosas que más preocupan a todos al volver a casa durante el Festival de Primavera. Simulemos brevemente un sistema de venta de billetes de tren (para simplificar el programa, extraemos el modelo más simple para simular): hay 500 billetes de tren de Pekín a Ganzhou, vendidos simultáneamente en 8 ventanillas, garantizando la estabilidad del sistema y la atomicidad de los datos.

Programa de prueba:

//售票系统
void Test2()
{
    //创建一个互斥量
    g_hMutex = CreateMutex(NULL, FALSE, NULL);

    //初始化火车票
    TICKET ticket;
    ticket.nCount = 100;
    strcpy(ticket.strTicketName, "北京-->赣州");

    const int THREAD_NUMM = 8;
    THD_DATA threadSale[THREAD_NUMM];
    HANDLE hThread[THREAD_NUMM];
    for(int i = 0; i < THREAD_NUMM; ++ i)
    {
        threadSale[i].pTicket = &ticket;
        string strThreadName = convertToString(i);

        strThreadName = "窗口" + strThreadName;

        strcpy(threadSale[i].strThreadName, strThreadName.c_str());

        //创建线程
        hThread[i] = CreateThread(NULL, NULL, SaleTicket, &threadSale[i], 0, NULL);

        //请求获得一个互斥量锁
        WaitForSingleObject(g_hMutex, INFINITE);
        cout << threadSale[i].strThreadName << "开始出售 " << threadSale[i].pTicket->strTicketName << " 的票..." << endl;
        //释放互斥量锁
        ReleaseMutex(g_hMutex);

        //关闭线程
        CloseHandle(hThread[i]);
    }

    system("pause");
}
