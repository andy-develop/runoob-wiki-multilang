45 trucos clásicos de desarrollo en JavaScript

Categoría Técnicas de programación

JavaScript es un lenguaje de programación excepcional a nivel mundial, que puede utilizarse para desarrollo web, desarrollo de aplicaciones móviles (PhoneGap, Appcelerator), desarrollo del lado del servidor (Node.js y Wakanda), etc. JavaScript es también el primer lenguaje con el que muchos novatos entran al mundo de la programación. Puede usarse tanto para mostrar simples cuadros de alerta en el navegador como para controlar robots mediante nodebot o nodruino. Los desarrolladores capaces de escribir código JavaScript con una estructura clara y un rendimiento eficiente se han convertido hoy en día en los más solicitados del mercado laboral.

En este artículo, compartiré algunos consejos, trucos y mejores prácticas de JavaScript que, salvo unas pocas excepciones, son aplicables tanto al motor de JavaScript del navegador como al intérprete de JavaScript del lado del servidor.

El código de ejemplo de este artículo ha sido probado en la última versión de Google Chrome 30 (V8 3.20.17.15).

1. Al asignar valor a una variable por primera vez, asegúrate de usarvarpalabra clave

Si una variable se asigna sin declararse, por defecto se convierte en una nueva variable global; debes evitar usar variables globales en la medida de lo posible.

2. Usa===en lugar de==

==和!=El operador convierte automáticamente los tipos de datos cuando es necesario. Pero===和!==no lo hacen; comparan tanto el valor como el tipo de datos, lo que también los hace más==和!=rápidos.

[10] === 10    // is false
[10]  == 10    // is true
'10' == 10     // is true
'10' === 10    // is false
 []   == 0     // is true
 [] ===  0     // is false
 '' == false   // is true but true == "a" is false
 '' === false  // is false

3、undefined、null, 0, false, NaN y cadenas vacías tienen un resultado lógico de false

4. Usa punto y coma al final de la línea

En la práctica es mejor usar el punto y coma; si olvidas escribirlo, no pasa nada, la mayoría de las veces el intérprete de JavaScript lo añade automáticamente. Para saber por qué usar el punto y coma, consulta el artículoLa verdad sobre el punto y coma en JavaScript。

25. Problemas con el cálculo de punto flotante

0.1 + 0.2 === 0.3 // is false 
9007199254740992 + 1 // is equal to 9007199254740992
9007199254740992 + 2 // is equal to 9007199254740994

¿Por qué? Porque 0.1+0.2 es igual a 0.30000000000000004. Los números de JavaScript se construyen siguiendo el estándar IEEE 754; internamente se representan como números de coma flotante de 64 bits. Puedes consultarCómo se codifican los números en JavaScript.

Se puede resolver usandotoFixed()和toPrecision()para resolver este problema.

En cambio:

Otro beneficio es que,i和lenlas dos variables están enforla primera declaración del bucle; ambas solo se inicializan una vez, esto es más rápido que la siguiente forma de escritura:

for (var i = 0; i < arrayNumbers.length; i++)

35. Al pasar asetInterval()和setTimeout()usa una función en lugar de una cadena

Si se pasa asetTimeout()和setInterval()una cadena, la convertirán de manera similar aevalla conversión mediante eval; esto ciertamente será más lento, por lo tanto no uses:

setInterval('doSomethingPeriodically()', 1000);  
setTimeout('doSomethingAfterFiveSeconds()', 5000);

En cambio usa:

setInterval(doSomethingPeriodically, 1000);  
setTimeout(doSomethingAfterFiveSeconds, 5000);

40. No uses try-catch-finally dentro de bucles

En try-catch-finally, la parte catch, al ejecutarse, asigna la excepción a una variable; esta variable se construye como una nueva variable dentro del ámbito de ejecución.

Evita:

var object = ['foo', 'bar'], i;  
for (i = 0, len = object.length; i <len; i++) {  
    try {  
        // do something that throws an exception 
    }  
    catch (e) {   
        // handle exception  
    } 
}

En su lugar, debes:

var object = ['foo', 'bar'], i;  
try { 
    for (i = 0, len = object.length; i <len; i++) {  
        // do something that throws an exception 
    } 
} 
catch (e) {   
    // handle exception  
}

41. Al usar XMLHttpRequests, asegúrate de establecer un tiempo de espera (timeout)

Cuando una XMLHttpRequest se ejecuta y no hay respuesta durante mucho tiempo (como problemas de red), se debe cancelar la conexión; esto se puede hacer mediantesetTimeout()para completar esta tarea:

var xhr = new XMLHttpRequest (); 
xhr.onreadystatechange = function () {  
    if (this.readyState == 4) {  
        clearTimeout(timeout);  
        // do something with response data 
    }  
}  
var timeout = setTimeout( function () {  
    xhr.abort(); // call error callback  
}, 60*1000 /* timeout after a minute */ ); 
xhr.open('GET', url, true);  
xhr.send();

También ten en cuenta que no debes realizar múltiples peticiones XMLHttpRequests al mismo tiempo.

42. Maneja el tiempo de espera de WebSocket

Normalmente, después de que se crea una conexión WebSocket, si no hay actividad en 30 segundos, el servidor aplicará un tiempo de espera a la conexión; el firewall también puede aplicar un tiempo de espera a las conexiones sin actividad en un período determinado.

Para evitar que esto ocurra, se puede enviar un mensaje vacío al servidor a intervalos regulares. Esto se puede lograr con las siguientes dos funciones: una para mantener la conexión activa y otra específicamente para finalizar ese estado.

var timerID = 0; 
function keepAlive() { 
    var timeout = 15000;  
    if (webSocket.readyState == webSocket.OPEN) {  
        webSocket.send('');  
    }  
    timerId = setTimeout(keepAlive, timeout);  
}  
function cancelKeepAlive() {  
    if (timerId) {  
        cancelTimeout(timerId);  
    }  
}

keepAlive()Las funciones se pueden colocar en elonOpen()final del método,cancelKeepAlive()y la otra en elonClose()final del método.
