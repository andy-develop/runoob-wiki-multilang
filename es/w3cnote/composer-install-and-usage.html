Instalación y uso de Composer

Categoría Tecnología de programación

Composer es una herramienta de gestión de dependencias para PHP, utilizada para gestionar las bibliotecas y sus versiones que requiere un proyecto.

Composer define las dependencias mediante el archivo composer.json y maneja automáticamente la instalación y actualización.

De manera predeterminada, Composer no se instala globalmente, sino que se instala en un directorio específico del proyecto (por ejemplo, vendor).

Composer requiere PHP versión 5.3.2 o superior, y necesita tener habilitado openssl.

Composer puede ejecutarse en plataformas Windows, Linux y OSX.

Características principales

  1. Gestión de dependencias: instala y gestiona automáticamente las bibliotecas requeridas por el proyecto.

  2. Autocarga: genera archivos de autocarga para simplificar la carga de clases.

  3. Control de versiones: admite control de versiones semántico, garantizando la compatibilidad de las bibliotecas de dependencias.

  4. Soporte de scripts: permite ejecutar scripts personalizados en eventos específicos (como instalación o actualización).

Composer genera el archivo vendor/autoload.php; solo necesita incluirlo en el proyecto para cargar clases automáticamente:

require 'vendor/autoload.php';

Instalación de Composer

Plataforma Windows

En la plataforma Windows, solo necesitamos descargarComposer-Setup.exey luego instalarlo paso a paso.

Tenga en cuenta que necesita habilitar la configuración de openssl. Abrimos el archivo php.ini en el directorio de PHP y quitamos el punto y coma que está antes deextension=php_openssl.dllEliminar el punto y coma anterior es suficiente.

Después de una instalación exitosa, podemos ingresar en la ventana de comandos (cmd) el comandocomposer --versionpara verificar si la instalación fue exitosa:

A continuación, podemos cambiar al espejo completo de Composer de Alibaba Cloud:

composer config -g repo.packagist composer https://mirrors.aliyun.com/composer/

Cancelar configuración:

composer config -g --unset repos.packagist

Configuración del proyecto

Solo modifica la configuración del proyecto actual; solo el proyecto actual puede usar esta dirección de espejo:

composer config repo.packagist composer https://mirrors.aliyun.com/composer/

Cancelar configuración:

composer config --unset repos.packagist

Depuración

Agregar -vvv al comando composer puede mostrar información detallada. El comando es el siguiente:

composer -vvv require alibabacloud/sdk

¿Problemas?

1. Se recomienda primero actualizar la versión de Composer a la más reciente:

composer self-update

2. Ejecute el comando de diagnóstico:

composer diagnose

3. Limpiar la caché:

composer clear

4. Si el proyecto se instaló previamente a través de otra fuente, debe actualizar el archivo composer.lock. Ejecute el comando:

composer update --lock

5. Reintente una vez

Plataforma Linux

En la plataforma Linux, puede usar los siguientes comandos para instalar:

# php -r "copy('https://install.phpcomposer.com/installer', 'composer-setup.php');"
# php composer-setup.php

Mueva composer.phar para que Composer pueda ser invocado globalmente:

# mv composer.phar /usr/local/bin/composer

Cambie al espejo nacional:

# composer config -g repo.packagist composer https://mirrors.aliyun.com/composer/

Actualizar composer:

# composer selfupdate

El sistema Mac OS puede usar los siguientes comandos para instalar:

$ sudo mv composer.phar /usr/local/bin/composer

Cambie al espejo nacional:

$ composer config -g repo.packagist composer https://mirrors.aliyun.com/composer/

Actualizar composer:

$ composer selfupdate

Uso de Composer

Para usar Composer, primero debemos crear un archivo composer.json en el directorio del proyecto. El archivo describe las dependencias del proyecto.

El formato del archivo es el siguiente:

{
    "require": {
        "monolog/monolog": "1.2.*"
    }
}

El archivo anterior indica que necesitamos descargar cualquier versión de monolog a partir de 1.2.

Luego, solo ejecute el siguiente comando para instalar los paquetes de dependencias:

composer install

Comando require

Además de usar el comando install, también podemos usar el comando require para instalar rápidamente una dependencia sin necesidad de agregar manualmente la información de la dependencia en composer.json:

$ composer require monolog/monolog

Composer primero encontrará una versión adecuada, luego actualizará el archivo composer.json, agregará la información relevante del paquete monolog/monolog en la sección require, descargará e instalará las dependencias correspondientes, y finalmente actualizará el archivo composer.lock y generará el archivo de autocarga de PHP.

Comando update

El comando update se utiliza para actualizar todos los paquetes del proyecto, o ciertos paquetes específicos:

# 更新所有依赖
$ composer update

# 更新指定的包
$ composer update monolog/monolog

# 更新指定的多个包
$ composer update monolog/monolog symfony/dependency-injection

# 还可以通过通配符匹配包
$ composer update monolog/monolog symfony/*

Cabe señalar que la versión a la que un paquete puede actualizarse estará limitada por las restricciones de versión; el paquete no se actualizará a una versión fuera del rango permitido por la restricción. Por ejemplo, si la restricción de versión del paquete en composer.json es ^1.10 y la versión más reciente es 2.0, entonces el comando update no puede actualizar el paquete a la versión 2.0; solo puede actualizarlo como máximo a una versión 1.x. Para las restricciones de versión, consulte la introducción más adelante.

Comando remove

El comando remove se utiliza para eliminar un paquete y sus dependencias (siempre que las dependencias no sean utilizadas por otros paquetes). Si una dependencia es utilizada por otros paquetes, no se puede eliminar:

$ composer remove monolog/monolog
Loading composer repositories with package information
Updating dependencies (including require-dev)
Package operations: 0 installs, 0 updates, 2 removals
  - Removing psr/log (1.0.2)
  - Removing monolog/monolog (1.23.0)
Generating autoload files

Comando search

El comando search permite buscar paquetes:

$ composer search monolog

Este comando mostrará el paquete y su información de descripción. Si solo desea mostrar el nombre del paquete, puede usar el parámetro--only-nameparámetro:

$ composer search --only-name monolog

Comando show

El comando show puede listar la información de los paquetes utilizados por el proyecto actual:

# 列出所有已经安装的包
$ composer show

# 可以通过通配符进行筛选
$ composer show monolog/*

# 显示具体某个包的信息
$ composer show monolog/monolog

Restricciones básicas

Versión exacta

Podemos indicarle a Composer la versión exacta a instalar, por ejemplo: 1.0.2, especificando la versión 1.0.2.

Rango

Puede especificar el rango de un paquete utilizando operadores de comparación. Estos operadores incluyen:>，>=，<，<=，!=。

Puede definir varios rangos; use un espacio o una coma , para representar el Y lógico, y use una doble barra vertical || para representar el O lógico. La prioridad de Y es mayor que la de O. Ejemplo:

  • >=1.0
  • >=1.0 <2.0
  • >=1.0 <1.1 || >=1.2

También podemos usar un guion-para especificar un rango de versiones.

El lado izquierdo del guion indica>=la versión de ...; si la versión de la derecha no es un número de versión completo, se completará con comodines. Por ejemplo,1.0 - 2.0es equivalente a>=1.0.0 <2.1（2.0equivale a2.0.*), y1.0.0 - 2.1.0es equivalente a>=1.0.0 <=2.1.0。

Comodín

Puede usar comodines para establecer versiones.1.0.*equivale a>=1.0 <1.1。
Ejemplo:1.0.*

Tilde ~

Primero explicaremos el uso del operador ~ mediante el siguiente ejemplo:~1.2equivale a>=1.2 <2.0.0, y~1.2.3equivale a>=1.2.3 <1.3.0. Para los proyectos que utilizanSemantic Versioningcomo estándar de número de versión, este tipo de restricción de versión es muy práctico. Por ejemplo,~1.2define un número de versión menor mínimo, y luego puede actualizar a cualquier versión inferior a 2.0 sin problemas, porque segúnSemantic Versioningla definición de versión de ..., las actualizaciones de versiones menores no deberían tener problemas de compatibilidad. En términos simples,~define la versión mínima y permite actualizar el último número de versión (si no lo entiende, revise nuevamente el ejemplo anterior).
Ejemplo:~1.2

Tenga en cuenta que si ~ actúa sobre el número de versión principal, por ejemplo~1, según lo mencionado anteriormente, Composer podría instalar versiones principales posteriores a la versión 1, pero en realidad~1será tratado como~1.0, por lo que solo se pueden incrementar versiones menores, no la versión principal.

Acento circunflejo ^

^El comportamiento del operador estáSemantic Versioningmuy relacionado con ..., permite actualizar a versiones seguras. Por ejemplo,^1.2.3equivale a>=1.2.3 <2.0.0, porque las versiones anteriores a la 2.0 no deberían tener problemas de compatibilidad. Para versiones anteriores a la 1.0, este método de restricción también tiene en cuenta la seguridad, por ejemplo^0.3será tratado como>=0.3.0 <0.4.0.
Ejemplo:^1.2.3

Estabilidad de versiones

Si no especifica explícitamente la estabilidad de la versión, Composer la establecerá internamente por defecto como-devo-stable. Por ejemplo:

Restricción Restricción interna
1.2.3 =1.2.3.0-stable
>1.2 >1.2.0.0-stable
>=1.2 >=1.2.0.0-dev
>=1.2-stable >=1.2.0.0-stable
<1.3 <1.3.0.0-dev
<=1.3 <=1.3.0.0-stable
1 - 2 >=1.0.0.0-dev <3.0.0.0-dev
~1.3 >=1.3.0.0-dev <2.0.0.0-dev
1.4.* >=1.4.0.0-dev <1.5.0.0-dev
Ejemplo:1.0 - 2.0Si desea especificar que la versión solo sea estable, puede agregar el sufijo-stable。

minimum-stabilityEl elemento de configuración ... define el comportamiento predeterminado de la selección de estabilidad al elegir versiones. El valor predeterminado esstable. Sus valores son los siguientes (ordenados por estabilidad):dev，alpha，beta，RC和stableAdemás de modificar esta configuración para cambiar el comportamiento predeterminado, también podemos usarel indicador de estabilidad(por ejemplo@stable和@dev) para instalar una versión con estabilidad diferente a la de la configuración predeterminada. Por ejemplo:

{
    "require": {
        "monolog/monolog": "1.0.*@beta",
        "acme/foo": "@dev"
    }
}
