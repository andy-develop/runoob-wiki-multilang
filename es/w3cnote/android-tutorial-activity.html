Android 基础入门教程

4.1.1 Activity Primeros pasos

Categoría Tutorial básico de introducción a Android

Introducción de esta sección:

Esta sección comienza explicando Activity (actividad), uno de los cuatro componentes principales de Android. Primero veamos la introducción oficial de Activity: PD: Documentación oficial:Activity

La introducción es la siguiente: Significado aproximado:

Activity es un componente de una aplicación que proporciona un área en la pantalla, permitiendo al usuario realizar algunas operaciones interactivas en ella, como llamar, tomar fotos, enviar correos electrónicos o mostrar un mapa. Activity puede entenderse como una ventana que dibuja la interfaz de usuario, y esta ventana puede llenar toda la pantalla, o puede ser más pequeña que la pantalla o flotar sobre otras ventanas.

De este párrafo anterior, podemos obtener la siguiente información:

1.Activity se utiliza para mostrar la interfaz de usuario; el usuario interactúa a través de Activity para completar operaciones relacionadas2.Una aplicación puede tener múltiples Activities

Bien, la introducción general termina aquí. Si quieres profundizar, puedes continuar consultando la API. ¡Comencemos con el contenido de esta sección~

1. Concepto de Activity y diagrama del ciclo de vida de Activity:

Notas:

1. La premisa para que se llamen onPause() y onStop() es: ¡se ha abierto una nueva Activity! En el primer caso, la Activity anterior aún es visible; en el segundo, la Activity anterior ya no es visible.
2. Además, probado personalmente: AlertDialog y PopWindow no activan los dos métodos de devolución de llamada anteriores~

2. Diferencias entre Activity/ActionBarActivity/AppCompatActivity:

Antes de comenzar a explicar la creación de Activity, hay que hablar de la diferencia entre estos tres: Activity no hace falta mencionarla; los dos últimos fueron propuestos para compatibilidad con versiones antiguas, ambos están en el paquete v7. ActionBarActivity ya está obsoleta; como se deduce del nombre, ActionBar~, y después de 5.0, Google la abandonó; ahora se usa ToolBar... Y cuando creamos una Activity en Android Studio, por defecto hereda: ¡AppCompatActivity! Por supuesto, también puedes escribir solo Activity, pero AppCompatActivity nos proporciona algunas cosas nuevas. Elige una de las dos, Just you like~

3. Proceso de creación de Activity

PS:

Bien, como se dijo antes, puedes heredar de Activity y AppCompatActivity, solo que esta última proporciona algunas cosas nuevas. Además, recuerda: para los cuatro componentes principales de Android, una vez que los defines, los uses o no, debes declarar el componente en AndroidManifest.xml; de lo contrario, el programa saldrá directamente en tiempo de ejecución y lanzará ClassNotFindException...

4. Diferencia entre onCreate() con un parámetro y con dos parámetros:

Creo que los amigos que usan Android Studio, al sobrescribir el método onCreate() de Act, descubrirán que esta cosa tiene dos parámetros:

Pero la forma normal solo tiene un parámetro:

Sí, este es el nuevo método que nos proporciona 5.0. Para usarlo, primero debemos establecer un atributo para nuestra Activity en el archivo de configuración:

android:persistableMode="persistAcrossReboots"

Entonces nuestra Activity tendrá capacidad de persistencia. Generalmente lo usamos junto con otros dos métodos:

public void onSaveInstanceState(Bundle outState, PersistableBundle outPersistentState)
public void onRestoreInstanceState(Bundle savedInstanceState, PersistableBundle persistentState)

Creo que algunos amigos no desconocen estos dos nombres de métodos. El primer método se llamará en las siguientes situaciones:

  1. Pulsar la tecla Home para volver a la página principal, o mantener presionada y elegir ejecutar otro programa
  2. Pulsar el botón de encendido para apagar la pantalla
  3. Iniciar una nueva Activity
  4. Al cambiar entre pantalla horizontal y vertical, seguramente se ejecutará, porque al cambiar se destruye primero la Act y luego se vuelve a crear. Principio importante: cuando el sistema destruye tu activity "sin tu permiso", onSaveInstanceState será llamado por el sistema. Esta es una responsabilidad del sistema, porque debe brindarte una oportunidad para guardar tus datos (puedes guardarlos o no).

Y el segundo método, al igual que onCreate, también puede recuperar los datos guardados por el primero. Generalmente se ejecuta entre onStart() y onResume(). La razón por la que hay dos métodos que pueden obtener los datos guardados es para evitar que, cuando la Act salte sin cerrarse y no pase por onCreate(), aún puedas recuperar los datos guardados~

Volviendo al tema:Volviendo a que esta Activity tiene capacidad de persistencia, el parámetro PersistableBundle agregado hace que estos métodos tengan la capacidad del sistemade reiniciar después de apagarde recuperación de datos. Además, no afecta nuestras otras operaciones de serialización, ¡vaya! Cómo se implementa exactamente, por ahora no lo sé; tal vez se guarde en otro archivo~. Si más adelante conozco el principio, se lo contaré a todos. Además, se requiere versión de API >=21, es decir, solo funciona en versiones 5.0 o superiores~

4. Varias formas de iniciar una Activity

En Android podemos iniciar una nueva Activity de las siguientes dos formas. Nota: aquí se trata de cómo iniciar, no del modo de inicio. Se divide en inicio explícito e inicio implícito.

1. Inicio explícito: iniciar mediante el nombre del paquete, la sintaxis es la siguiente:

① El más común:

startActivity(new Intent(当前Act.this,要启动的Act.class));
② Mediante ComponentName de Intent:
ComponentName cn = new ComponentName("当前Act的全限定类名","启动Act的全限定类名") ;
Intent intent = new Intent() ;
intent.setComponent(cn) ;
startActivity(intent) ;
③Especificar el nombre del paquete al inicializar Intent:
Intent intent = new Intent("android.intent.action.MAIN");
intent.setClassName("当前Act的全限定类名","启动Act的全限定类名");
startActivity(intent);

2. Inicio implícito: se logra mediante Action, Category o data de Intent-filter. Esto se hace a través de Intentintent-filter**. Ese capítulo de Intent lo explicará en detalle. Aquí basta con tener una idea general.

3. Además, también existe una forma de iniciar un APK directamente mediante el nombre del paquete:

Intent intent = getPackageManager().getLaunchIntentForPackage
("apk第一个启动的Activity的全限定类名") ;
if(intent != null) startActivity(intent) ;

5. Problemas de cambio entre pantalla horizontal/vertical y guardado de estado

Antes también se mencionó que cuando la App cambia entre pantalla horizontal y vertical, se destruye la Activity actual y se crea una nueva. Puedes agregar por tu cuenta sentencias de impresión de Log en cada método del ciclo de vida para verificar, o configurar un botón y un TextView; después de hacer clic en el botón, modificar el texto del TextView, y luego cambiar entre horizontal y vertical: descubrirás mágicamente que el texto del TextView vuelve al contenido anterior. Al cambiar entre horizontal y vertical, la Act recorre el siguiente ciclo de vida:
onPause-> onStop-> onDestory-> onCreate->onStart->onResume
Con respecto al cambio entre horizontal y vertical, pueden encontrarse los siguientes problemas:

1. Primero hablemos de cómoprohibir el cambio automático de pantalla entre horizontal y verticalEs muy sencillo: agrega un atributo a la Act en AndroidManifest.xml:android:screenOrientation, con los siguientes valores opcionales:

  • unspecified: valor por defecto; el sistema determina la orientación de la pantalla. La estrategia de decisión depende del dispositivo, por lo que diferentes dispositivos tendrán diferentes orientaciones.
  • landscape: pantalla horizontal (el ancho es mayor que el alto)
  • portrait: pantalla vertical (el alto es mayor que el ancho)
  • user: la orientación preferida actual del usuario
  • behind: igual a la orientación de la Activity que está debajo de esta Activity (en la pila de Activities)
  • sensor: determinada por el sensor físico. Si el usuario rota el dispositivo, la pantalla cambiará entre horizontal y vertical.
  • nosensor: ignora el sensor físico, de modo que no cambiará cuando el usuario rote el dispositivo (excepto con la configuración "unspecified").

2.Cargar diferentes diseños en horizontal y vertical：

1) Preparar dos conjuntos de diseños diferentes; Android cargará automáticamente el diseño correspondiente según la orientación. Crea dos carpetas de diseño:layout-landhorizontal,layout-portvertical

Luego coloca estos dos conjuntos de archivos de diseño en esas dos carpetas, con el mismo nombre de archivo. Android lo determinará automáticamente y cargará el diseño correspondiente.

2) Juzgar por ti mismo en el código, cargar lo que quieras. Generalmente cargamos el archivo de diseño en el método onCreate(). Aquí podemos juzgar el estado de horizontal/vertical. El código clave es el siguiente:

if (this.getResources().getConfiguration().orientation == Configuration.ORIENTATION_LANDSCAPE){  
     setContentView(R.layout.横屏);
}  

else if (this.getResources().getConfiguration().orientation ==Configuration.ORIENTATION_PORTRAIT) {  
    setContentView(R.layout.竖屏);
}

3. Cómo hacer que el emulador cambie entre horizontal y vertical

Si tu emulador es Genymotion, simplemente presiona el botón de cambio en el emulador. En el emulador nativo, puedes usar Ctrl + F11/F12 para cambiar.

4. Problema de guardado de estado:

Esto ya se mencionó antes; se puede lograr mediante el parámetro Bundle savedInstanceState. Tres métodos principales:

onCreate(Bundle savedInstanceState);
onSaveInstanceState(Bundle outState);
onRestoreInstanceState(Bundle savedInstanceState);

Solo sobrescribes el método onSaveInstanceState() y escribes datos en este bundle, por ejemplo:

outState.putInt("num",1);

Así, luego en onCreate o onRestoreInstanceState puedes recuperar los datos almacenados, ¡pero antes de recuperarlos debes verificar si son null!

savedInstanceState.getInt("num");

¡Luego haz lo que quieras~!

startActivity(intent);
