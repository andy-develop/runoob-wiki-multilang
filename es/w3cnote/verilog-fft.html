Categoría Tutorial de Verilog

Diseño de FFT

Descripción del diseño

Para explicar el proceso de transformación de la FFT mediante simulación de manera sencilla, se toma un valor pequeño de 8 puntos de datos.

Si los datos se ingresan en serie, primero se requiere almacenarlos en búfer, por lo que en el diseño el método de entrada de datos es paralelo.

La entrada de datos se divide en parte real e imaginaria, 2 partes en total, por lo que el resultado del cálculo también se divide en parte real e imaginaria.

El diseño adopta una estructura de pipeline y por el momento no se considera el consumo de recursos.

Para simplificar la estructura del diseño, aquí se hace una concesión: la multiplicación se realiza directamente con el signo de multiplicar. Si el diseño FFT se aplica en la práctica, es necesario reemplazar la estructura de multiplicación por un multiplicador con pipeline, o utilizar un IP de multiplicador de alta eficiencia proporcionado oficialmente.

Diseño de la unidad de mariposa

La unidad de mariposa es de operación de punto fijo, por lo que es necesario cuantificar en punto fijo el factor twiddle.

Con la ayuda de MATLAB, el factor twiddle se amplía 8192 veces (desplazamiento a la izquierda de 13 bits); consulte el apéndice.

Para evitar que la multiplicación y la suma en la operación de mariposa aumenten el ancho de bits etapa por etapa, después de completar cada etapa, los datos de salida deben truncarse a un ancho de bits fijo; esto también puede eliminar el efecto del aumento del factor twiddle. El código es el siguiente:

Ejemplo

`timescale 1ns/100ps
/**************** butter unit *************************
Xm(p) ------------------------> Xm+1(p)
           -        ->
             -    -
                -
              -   -
            -        ->
Xm(q) ------------------------> Xm+1(q)
      Wn          -1
*//////////////////////////////////////////////////////
module butterfly
    (
     input                       clk,
     input                       rstn,
     input                       en,
     input signed [23:0]         xp_real, // Xm(p)
     input signed [23:0]         xp_imag,
     input signed [23:0]         xq_real, // Xm(q)
     input signed [23:0]         xq_imag,
     input signed [15:0]         factor_real, // Wnr
     input signed [15:0]         factor_imag,

     output                      valid,
     output signed [23:0]        yp_real, //Xm+1(p)
     output signed [23:0]        yp_imag,
     output signed [23:0]        yq_real, //Xm+1(q)
     output signed [23:0]        yq_imag);

    reg [4:0]                    en_r ;
    always @(posedge clk or negedge rstn) begin
        if (!rstn) begin
            en_r   <= 'b0 ;
        end
        else begin
            en_r   <= {en_r[3:0], en} ;
        end
    end

    //=====================================================//
    //(1.0) Xm(q) mutiply and Xm(p) delay
    reg signed [39:0] xq_wnr_real0;
    reg signed [39:0] xq_wnr_real1;
    reg signed [39:0] xq_wnr_imag0;
    reg signed [39:0] xq_wnr_imag1;
    reg signed [39:0] xp_real_d;
    reg signed [39:0] xp_imag_d;
    always @(posedge clk or negedge rstn) begin
        if (!rstn) begin
            xp_real_d    <= 'b0;
            xp_imag_d    <= 'b0;
            xq_wnr_real0 <= 'b0;
            xq_wnr_real1 <= 'b0;
            xq_wnr_imag0 <= 'b0;
            xq_wnr_imag1 <= 'b0;
        end
        else if (en) begin
            xq_wnr_real0 <= xq_real * factor_real;
            xq_wnr_real1 <= xq_imag * factor_imag;
            xq_wnr_imag0 <= xq_real * factor_imag;
            xq_wnr_imag1 <= xq_imag * factor_real;
            //expanding 8192 times as Wnr
            xp_real_d    <= {{4{xp_real[23]}}, xp_real[22:0], 13'b0};
            xp_imag_d    <= {{4{xp_imag[23]}}, xp_imag[22:0], 13'b0};
        end
    end

    //(1.1) get Xm(q) mutiplied-results and Xm(p) delay again
    reg signed [39:0] xp_real_d1;
    reg signed [39:0] xp_imag_d1;
    reg signed [39:0] xq_wnr_real;
    reg signed [39:0] xq_wnr_imag;
    always @(posedge clk or negedge rstn) begin
        if (!rstn) begin
            xp_real_d1     <= 'b0;
            xp_imag_d1     <= 'b0;
            xq_wnr_real    <= 'b0 ;
            xq_wnr_imag    <= 'b0 ;
        end
        else if (en_r[0]) begin
            xp_real_d1     <= xp_real_d;
            xp_imag_d1     <= xp_imag_d;
            //Establezca el margen de ancho de bits con antelación para evitar el desbordamiento de datos
            xq_wnr_real    <= xq_wnr_real0 - xq_wnr_real1 ;
            xq_wnr_imag    <= xq_wnr_imag0 + xq_wnr_imag1 ;
      end
    end

   //======================================================//
   //(2.0) butter results
    reg signed [39:0] yp_real_r;
    reg signed [39:0] yp_imag_r;
    reg signed [39:0] yq_real_r;
    reg signed [39:0] yq_imag_r;
    always @(posedge clk or negedge rstn) begin
        if (!rstn) begin
            yp_real_r      <= 'b0;
            yp_imag_r      <= 'b0;
            yq_real_r      <= 'b0;
            yq_imag_r      <= 'b0;
        end
        else if (en_r[1]) begin
            yp_real_r      <= xp_real_d1 + xq_wnr_real;
            yp_imag_r      <= xp_imag_d1 + xq_wnr_imag;
            yq_real_r      <= xp_real_d1 - xq_wnr_real;
            yq_imag_r      <= xp_imag_d1 - xq_wnr_imag;
        end
    end

    //(3) discard the low 13bits because of Wnr
    assign yp_real = {yp_real_r[39], yp_real_r[13+23:13]};
    assign yp_imag = {yp_imag_r[39], yp_imag_r[13+23:13]};
    assign yq_real = {yq_real_r[39], yq_real_r[13+23:13]};
    assign yq_imag = {yq_imag_r[39], yq_imag_r[13+23:13]};
    assign valid   = en_r[2];

endmodule

Instanciación de nivel superior

De acuerdo con el diagrama de estructura del algoritmo FFT, instancie las unidades de mariposa para completar la función FFT final.

Se pueden instanciar manualmente 12 veces en orden según la correspondencia de entrada y salida de las unidades de mariposa de cada etapa, o utilizar `generate` para la instanciación; en este caso, es necesario conocer muy bien las características de "grupo" y "etapa" en FFT:

  • (1) El diseño de FFT de 8 puntos requiere 3 etapas de operación, cada etapa tiene 4 unidades de mariposa, y el número de grupos en cada etapa es 4, 2, 1 respectivamente.

  • (2) En cada etapa, la distancia entre los dos puertos de entrada de una unidad de mariposa dentro de un grupo es siempre(m es el índice de la etapa, correspondiente al desplazamiento a la izquierda 1<<m), y la distancia entre los primeros puertos de entrada de dos unidades de mariposa dentro del grupo es 1.

  • (3) La distancia entre los primeros puertos de entrada de la primera unidad de mariposa de grupos adyacentes en cada etapa es(correspondiente al desplazamiento a la izquierda 2<<m).

Entre ellos, las direcciones unidimensional y bidimensional de la señal de matriz xm_real (xm_imag) representan los identificadores de etapa y grupo.

Al determinar la relación de conexión entre los puertos de señal, se utiliza una lógica de decisión aparentemente compleja, e incluso incluye un signo de multiplicación; en realidad, el circuito finalmente generado es exactamente el mismo que el de instanciar manualmente 12 unidades de mariposa en el código. Esto se debe a que las variables en `generate` solo ayudan a generar el circuito real; el cálculo y la determinación de los valores relevantes ya se completan en tiempo de compilación. Estas variables no generan circuitos reales, solo proporcionan un método para una instanciación de módulos más rápida.

Resultados de la simulación

Se puede observar aproximadamente que los resultados de la FFT se pueden generar en pipeline.

Se utiliza la función FFT incorporada en MATLAB para operar sobre los mismos datos; los resultados FFT de los primeros 2 grupos de datos son los siguientes.

Se puede ver que cuando la primera señal de datos de entrada solo tiene válida la parte real, los resultados de la FFT son exactamente iguales.

Pero en la segunda entrada, la parte compleja de los datos también tiene señal; en este momento, los resultados entre ambos comienzan a tener errores, a veces bastante grandes.

Al simular en MATLAB el proceso FFT implementado en Verilog, se descubre que el resultado FFT de este proceso es básicamente consistente con el resultado de la FFT implementada en Verilog.

Se comparan los valores absolutos de los dos resultados FFT con errores, como se muestra en la figura.

Se puede ver que la tendencia de los resultados FFT es aproximadamente la misma, pero en algunos puntos hay errores visibles a simple vista.

Resumen del diseño:

Como se mencionó al diseñar la unidad de mariposa, al cuantificar el factor twiddle, la elección del ancho de bits introduce errores.

Además, el resultado de cada unidad de mariposa se trunca, lo que también introduce errores.

MATLAB no necesita considerar el problema de precisión al calcular la FFT; realiza el cálculo FFT de los datos con su máxima precisión.

Todo lo anterior conduce a diferencias en los resultados entre los dos métodos de cálculo FFT.

Los interesados pueden aumentar el factor twiddle y el ancho de bits de los datos de entrada, y también pueden aumentar el número de puntos FFT; luego, al comparar mediante simulación, el error relativo debería disminuir.

Apéndice: uso de MATLAB

Generación del factor twiddle

La FFT de 8 puntos solo necesita 4 factores twiddle. El factor twiddle se amplifica 8192 veces.

Ejemplo

clear all;close all;clc;
%=======================================================
% Wnr calcuting
%=======================================================
for r = 0:3
    Wnr_factor  = cos(pi/4*r) - j*sin(pi/4*r) ;
    Wnr_integer = floor(Wnr_factor * 2^13) ;
   
    if (real(Wnr_integer)<0)
        Wnr_real    = real(Wnr_integer) + 2^16 ; %Complemento a dos de números negativos
    else
        Wnr_real    = real(Wnr_integer) ;
    end
    if (imag(Wnr_integer)<0)
        Wnr_imag    = imag(Wnr_integer) + 2^16 ;
    else
        Wnr_imag    = imag(Wnr_integer);
    end
   
    Wnr(2*r+1,:)  =  dec2hex(Wnr_real)   %Parte real
    Wnr(2*r+2,:)  =  dec2hex(Wnr_imag)   %Parte imaginaria
end

    En la segunda etapa (m=1) de la estructura de mariposa FFT de 8 puntos, los factores twiddle en principio son W8^0 y W8^2 (W8^2 puede aproximarse a W4^1, pero no puede ser igual a W8^1). Sin embargo, el diseño del código de ejemplo hace que los valores de los factores twiddle sean W(0) y W(1), ¡y este W(1) corresponde a W8^1! Además, el código de verificación de MATLAB también usa W(1+1), lo que provoca una desviación evidente entre el resultado de la operación y el resultado de la función fft estándar.

    En MATLAB, la corrección consiste en cambiar el factor twiddle W(2) de la etapa 2 (cuando m=1) a W(3), y así los resultados de los dos cálculos coinciden.

    De esto se puede ver el correspondiente código HDL:

    .factor_real (factor_real[k[m:0]<(1<<m)? k[m:0] : k[m:0]-(1<<m) ]),
.factor_imag (factor_imag[k[m:0]<(1<<m)? k[m:0] : k[m:0]-(1<<m) ]),

    También debe modificarse; el subíndice de la señal debería ser:

    [k[m:0]<(1<<m)? k[m:0]<<(3-1-m) : (k[m:0]-(1<<m))<<(3-1-m)] ),
