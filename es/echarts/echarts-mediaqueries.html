ECharts Adaptativo

El gráfico de ECharts se muestra en un nodo DOM (contenedor) cuyo alto y ancho especifica el usuario.

A veces queremos poder mostrar bien el contenido del gráfico tanto en PC como en dispositivos móviles, para lograr un diseño responsive. Para resolver este problema, ECharts ha mejorado la configuración de posicionamiento de los componentes y ha implementado una capacidad adaptativa similar aCSS Media Query.

Posicionamiento y diseño de componentes de ECharts

La mayoría de los 'componentes' y 'series' siguen dos métodos de posicionamiento.

Método de posicionamiento left/right/top/bottom/width/height

De estas seis cantidades, cada una puede ser un 'valor absoluto', un 'porcentaje' o una 'descripción de posición'.

  • Valor absoluto

    La unidad es el píxel del navegador (px), usandonumberforma de escritura (sin escribir la unidad). Por ejemplo{left: 23, height: 400}。

  • Porcentaje

    Indica qué porcentaje del alto y ancho del contenedor DOM, usandostringforma de escritura. Por ejemplo{right: '30%', bottom: '40%'}。

  • Descripción de posición

    • Se puede configurarleft: 'center', que indica centrado horizontal.
    • Se puede configurartop: 'middle', que indica centrado vertical.

El concepto de estas seis cantidades es similar al de las seis cantidades en CSS:

  • left: distancia al borde izquierdo del contenedor DOM.
  • right: distancia al borde derecho del contenedor DOM.
  • top: distancia al borde superior del contenedor DOM.
  • bottom: distancia al borde inferior del contenedor DOM.
  • width: ancho.
  • height: alto.

En horizontal, de las tres cantidades left, right, width, solo se necesitan dos con valor, porque cualquiera de las dos puede determinar la posición y el tamaño del componente; por ejemplo, left y right, o right y width, pueden determinar la posición y el tamaño del componente. En vertical, las tres cantidades top, bottom, height son similares a las horizontales, no se entrará en detalles.

Método de posicionamiento center / radius

  • center

    Es un array que representa[x, y], donde,x、ypuede ser un 'valor absoluto' o un 'porcentaje', con el mismo significado mencionado anteriormente.

  • radius

    Es un array que representa[内半径, 外半径], donde, los radios interior y exterior pueden ser un 'valor absoluto' o un 'porcentaje', con el mismo significado mencionado anteriormente.

    Al adaptar el tamaño del contenedor, la configuración de porcentajes es muy útil.

Horizontal y vertical

Los componentes de ECharts de tipo 'apariencia alargada y estrecha' (como legend, visualMap, dataZoom, timeline, etc.) ofrecen en su mayoría la opción de 'diseño horizontal' y 'diseño vertical'. Por ejemplo, en pantallas móviles alargadas y estrechas, puede ser adecuado usar el 'diseño vertical'; en pantallas anchas de PC, puede ser adecuado usar el 'diseño horizontal'.

La configuración del diseño horizontal o vertical generalmente se establece en la opción orient o layout del 'componente' o 'serie', estableciéndola como 'horizontal' o 'vertical'.

Para configurar Media Query en option, se debe seguir el siguiente formato:

option = {
    baseOption: { // 这里是基本的『原子option』。
        title: {...},
        legend: {...},
        series: [{...}, {...}, ...],
        ...
    },
    media: [ // 这里定义了 media query 的逐条规则。
        {
            query: {...},   // 这里写规则。
            option: {       // 这里写此规则满足下的option。
                legend: {...},
                ...
            }
        },
        {
            query: {...},   // 第二个规则。
            option: {       // 第二个规则对应的option。
                legend: {...},
                ...
            }
        },
        {                   // 这条里没有写规则，表示『默认』，
            option: {       // 即所有规则都不满足时，采纳这个option。
                legend: {...},
                ...
            }
        }
    ]
};

En el ejemplo anterior, baseOption y cada option en media son un 'option atómico', es decir, un option ordinario que contiene las definiciones de los componentes y series. Al option completo compuesto por 'option atómico' lo llamamos 'option compuesto'. baseOption siempre se usa; además, cuando se cumple alguna condición de query, el option correspondiente se fusiona usando chart.mergeOption().

query

Cada query es similar a esto:

{
    minWidth: 200,
    maxHeight: 300,
    minAspectRatio: 1.3
}

Ahora se admiten tres propiedades: width, height, aspectRatio (relación de aspecto). Cada propiedad puede llevar el prefijo min o max. Por ejemplo, minWidth: 200 significa 'ancho mayor o igual que 200px'. Escribir dos propiedades juntas significa 'y', por ejemplo: {minWidth: 200, maxHeight: 300} significa 'ancho mayor o igual que 200px, y alto menor o igual que 300px'.

option

Dado que el option en media es un 'option atómico', en teoría se puede escribir cualquier opción de configuración de option. Pero generalmente solo escribimos las relacionadas con el posicionamiento del diseño, por ejemplo, extraer una parte del query option del ejemplo anterior:

media: [
    ...,
    {
        query: {
            maxAspectRatio: 1           // 当长宽比小于1时。
        },
        option: {
            legend: {                   // legend 放在底部中间。
                right: 'center',
                bottom: 0,
                orient: 'horizontal'    // legend 横向布局。
            },
            series: [                   // 两个饼图左右布局。
                {
                    radius: [20, '50%'],
                    center: ['50%', '30%']
                },
                {
                    radius: [30, '50%'],
                    center: ['50%', '70%']
                }
            ]
        }
    },
    {
        query: {
            maxWidth: 500               // 当容器宽度小于 500 时。
        },
        option: {
            legend: {
                right: 10,              // legend 放置在右侧中间。
                top: '15%',
                orient: 'vertical'      // 纵向布局。
            },
            series: [                   // 两个饼图上下布局。
                {
                    radius: [20, '50%'],
                    center: ['50%', '30%']
                },
                {
                    radius: [30, '50%'],
                    center: ['50%', '75%']
                }
            ]
        }
    },
    ...
]

Prioridad cuando se cumplen múltiples query

Nota: puede haber múltiples query que se cumplan al mismo tiempo, y todas se fusionarán con mergeOption; las definidas después se fusionan más tarde (es decir, tienen mayor prioridad).​

query predeterminada

Si algún elemento en media no escribe query, significa 'valor predeterminado', es decir, cuando no se cumple ninguna regla, se adopta este option.

Precauciones cuando el tamaño del contenedor cambia en tiempo real

En muchos casos, no es necesario que el nodo DOM del contenedor cambie de tamaño arbitrariamente al arrastrar, sino que solo se establecen algunos tamaños típicos según los diferentes dispositivos.

Pero si el nodo DOM del contenedor necesita poder cambiar de tamaño arbitrariamente al arrastrar, entonces actualmente al usarlo hay que tener en cuenta esto: si una determinada opción de configuración aparece en un query option, también debe aparecer en los demás query option; de lo contrario, no se puede volver al estado original. (left/right/top/bottom/width/height no están sujetos a esta limitación).

media en un 'option compuesto' no admite merge

Es decir, cuando se llama chart.setOption(rawOption) por segunda (o tercera, cuarta, quinta ...) vez, si rawOption es un option compuesto (es decir, contiene una lista media), entonces la nueva lista rawOption.media no se fusionará con la lista media anterior, sino que simplemente la reemplazará. Por supuesto, rawOption.baseOption todavía se fusionará normalmente con el option anterior. En realidad, hay muy pocos escenarios en los que se necesite usar un 'option compuesto' para llamar a setOption varias veces, y la práctica que recomendamos es que al usar mediaQuery, la primera llamada a setOption use un 'option compuesto', y las llamadas posteriores a setOption usen solo un 'option atómico', es decir, usar setOption únicamente para cambiar baseOption.
