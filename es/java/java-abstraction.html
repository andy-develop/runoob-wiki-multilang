Java Clases Abstractas

En el concepto de la programación orientada a objetos, todos los objetos se describen mediante clases, pero a la inversa, no todas las clases se utilizan para describir objetos. Si una clase no contiene suficiente información para describir un objeto concreto, dicha clase es una clase abstracta.

Además de no poder instanciar objetos, las demás funciones de la clase siguen existiendo. Las variables miembro, los métodos miembro y los constructores mantienen la misma forma de acceso que una clase normal.

Dado que las clases abstractas no pueden instanciar objetos, deben ser heredadas para poder utilizarse. Por esta razón, normalmente se decide si diseñar una clase abstracta en la etapa de diseño.

La clase padre contiene los métodos comunes del conjunto de subclases, pero como la propia clase padre es abstracta, no se pueden utilizar estos métodos.

En Java, una clase abstracta representa una relación de herencia. Una clase solo puede heredar de una clase abstracta, pero puede implementar múltiples interfaces.

Clase abstracta

En el lenguaje Java se utiliza `abstract class` para definir una clase abstracta. Ejemplo:

Código del archivo Employee.java:

/*Nombre de archivo: Employee.java*/ public abstract class Employee { private String name; private String address; private int number; public Employee(String name, String address, int number) { System.out.println("Constructing an Employee"); this.name = name; this.address = address; this.number = number; } public double computePay() { System.out.println("Inside Employee computePay"); return 0.0; } public void mailCheck() { System.out.println("Mailing a check to " + this.name + " " + this.address); } public String toString() { return name + " " + address + " " + number; } public String getName() { return name; } public String getAddress() { return address; } public void setAddress(String newAddress) { address = newAddress; } public int getNumber() { return number; } }

Observa que la clase Employee no tiene nada diferente; aunque es una clase abstracta, todavía tiene 3 variables miembro, 7 métodos miembro y 1 constructor. Ahora si intentas el siguiente ejemplo:

Código del archivo AbstractDemo.java:

/*Nombre de archivo: AbstractDemo.java*/ public class AbstractDemo { public static void main(String [] args) { /*Lo siguiente no está permitido y provocará un error*/ Employee e = new Employee("George W.", "Houston, TX", 43); System.out.println("\n Call mailCheck using Employee reference--"); e.mailCheck(); } }

Cuando intentes compilar la clase AbstractDemo, se producirá el siguiente error:

Employee.java:46: Employee is abstract; cannot be instantiated
      Employee e = new Employee("George W.", "Houston, TX", 43);
                   ^
1 error

Heredar una clase abstracta

Podemos heredar las propiedades de la clase Employee de la siguiente manera:

Código del archivo Salary.java:

/*Nombre de archivo: Salary.java*/ public class Salary extends Employee { private double salary; //Annual salary public Salary(String name, String address, int number, double salary) { super(name, address, number); setSalary(salary); } public void mailCheck() { System.out.println("Within mailCheck of Salary class "); System.out.println("Mailing check to " + getName() + " with salary " + salary); } public double getSalary() { return salary; } public void setSalary(double newSalary) { if(newSalary >= 0.0) { salary = newSalary; } } public double computePay() { System.out.println("Computing salary pay for " + getName()); return salary/52; } }

Aunque no podemos instanciar un objeto de la clase Employee, si instanciamos un objeto de la clase Salary, dicho objeto heredará 7 métodos miembro de la clase Employee y, a través de esos métodos, podrá establecer u obtener las tres variables miembro.

Código del archivo AbstractDemo.java:

/*Nombre de archivo: AbstractDemo.java*/ public class AbstractDemo { public static void main(String [] args) { Salary s = new Salary("Mohd Mohtashim", "Ambehta, UP", 3, 3600.00); Employee e = new Salary("John Adams", "Boston, MA", 2, 2400.00); System.out.println("Call mailCheck using Salary reference --"); s.mailCheck(); System.out.println("\n Call mailCheck using Employee reference--"); e.mailCheck(); } }

El resultado de compilar y ejecutar el programa anterior es el siguiente:

Constructing an Employee
Call mailCheck using  Salary reference --
Within mailCheck of Salary class
Mailing check to Mohd Mohtashim with salary 3600.0

Call mailCheck using Employee reference--

Mailing check to John Adams with salary 2400.

Métodos abstractos

Si deseas diseñar una clase que contenga un método miembro especial cuya implementación concreta sea determinada por sus subclases, entonces puedes declarar dicho método como abstracto en la clase padre.

La palabra clave `Abstract` también se puede utilizar para declarar métodos abstractos. Un método abstracto solo contiene un nombre de método y no tiene cuerpo.

El método abstracto no tiene definición; después del nombre del método va directamente un punto y coma, en lugar de llaves.

public abstract class Employee { private String name; private String address; private int number; public abstract double computePay(); //El resto del código }

Declarar un método abstracto produce los dos resultados siguientes:

  • Si una clase contiene un método abstracto, entonces la clase debe ser abstracta.
  • Cualquier subclase debe sobrescribir el método abstracto de la clase padre, o declararse a sí misma como clase abstracta.

La subclase que herede el método abstracto debe sobrescribirlo. De lo contrario, la subclase también debe declararse como clase abstracta. Finalmente, debe haber una subclase que implemente el método abstracto; de lo contrario, desde la clase padre original hasta la subclase final, ninguna podrá utilizarse para instanciar objetos.

Si la clase Salary hereda de la clase Employee, entonces debe implementar el método `computePay()`:

Código del archivo Salary.java:

/*Nombre de archivo: Salary.java*/ public class Salary extends Employee { private double salary; // Annual salary public double computePay() { System.out.println("Computing salary pay for " + getName()); return salary/52; } //El resto del código }

Reglas resumidas de las clases abstractas

  • 1. Las clases abstractas no pueden ser instanciadas (un error muy común entre principiantes); si se instancian, se producirá un error y la compilación fallará. Solo las subclases no abstractas de una clase abstracta pueden crear objetos.

  • 2. Una clase abstracta no necesariamente contiene métodos abstractos, pero una clase con métodos abstractos debe ser abstracta.

  • 3. Los métodos abstractos en una clase abstracta son solo declaraciones, no contienen cuerpo de método, es decir, no proporcionan la implementación concreta del método ni su funcionalidad específica.

  • 4. Los constructores y los métodos de clase (métodos modificados con `static`) no pueden declararse como métodos abstractos.

  • 5. Las subclases de una clase abstracta deben proporcionar la implementación concreta de los métodos abstractos de la clase abstracta, a menos que la subclase también sea abstracta.

Esto es un problema relacionado con la herencia.

    System.out.println("初始化Animal");

  public void move(){

  }

abstract class Dog extends Animal{
  public Dog(int age){
   // super(age);//去掉会报异常
    System.out.println("初始化Dog");

public class BigDogs extends Dog{
  public BigDogs(){

    Define una clase `Shape` que represente figuras bidimensionales generales. `Shape` tiene métodos abstractos `area` y `perimeter`, que calculan el área y el perímetro de la forma respectivamente. Define algunas clases de formas bidimensionales (como rectángulo, triángulo, círculo, etc.), todas ellas subclases de `Shape`, y calcula el área y el perímetro de estas formas, imprimiendo la información correspondiente.

    Clase de forma:

    public abstract class Shape {
    public abstract double area();
    public abstract double perimeter();
}

    Clase Rectángulo:

    public class Rectangle extends Shape {
    private double length;
    private double width;

    public double getLength() {
        return length;
    }

    public void setLength(double length) {
        this.length = length;
    }

    public double getWidth() {
        return width;
    }

    public void setWidth(double width) {
        this.width = width;
    }

    @Override
    public double area() {
        return getLength() * getWidth();
    }

    @Override
    public double perimeter() {
        return 2 * (getWidth() + getWidth());
    }
}

    Clase Triángulo:

    public class Triangle extends Shape {
    private double a, b, c;

    public double getA() {
        return a;
    }

    public void setA(double a) {
        this.a = a;
    }

    public double getB() {
        return b;
    }

    public void setB(double b) {
        this.b = b;
    }

    public double getC() {
        return c;
    }

    public void setC(double c) {
        this.c = c;
    }

    @Override
    public double area() {
        double p = (getA() + getB() + getC()) / 2;
        return Math.sqrt(p * (p - getA()) * (p - getB()) * (p - getC()));
    }

    @Override
    public double perimeter() {
        return getA() + getB() + getC();
    }
}

    Clase Círculo:

    public class Circle extends Shape {
    private double diameter;

    public double getDiameter() {
        return diameter;
    }

    public void setDiameter(double diameter) {
        this.diameter = diameter;
    }

    @Override
    public double area() {
        return Math.PI * Math.pow(getDiameter() / 2, 2);
    }

    @Override
    public double perimeter() {
        return Math.PI * getDiameter();
    }
}

    public class Test {

        rec.setWidth(5);

        tri.setA(3);
        tri.setB(4);
        tri.setC(5);
        double tri_area = tri.area();
        double tri_perimeter = tri.perimeter();
        System.out.println("三角形的面积："+tri_area+"，周长"+tri_perimeter);

        Circle cir = new Circle();
        cir.setDiameter(10);
        double cir_area = cir.area();
        double cir_perimeter = cir.perimeter();
        System.out.println("圆形的面积："+cir_area+"，周长"+cir_perimeter);
    }
}

    Diferencias entre clases abstractas e interfaces

    1. Diferencias a nivel de sintaxis

    • 1) Una clase abstracta puede proporcionar detalles de implementación de los métodos miembro, mientras que en una interfaz solo pueden existir métodos `public abstract`;
    • 2) Las variables miembro en una clase abstracta pueden ser de varios tipos, mientras que en una interfaz solo pueden ser de tipo `public static final`;
    • 3) Una interfaz no puede contener bloques de código estáticos ni métodos estáticos, mientras que una clase abstracta sí puede tenerlos;
    • 4) Una clase solo puede heredar de una clase abstracta, pero puede implementar múltiples interfaces.

    2. Diferencias a nivel de diseño

    11) Las clases abstractas son una abstracción de una cosa, es decir, una abstracción de una clase, mientras que las interfaces son una abstracción del comportamiento. La clase abstracta abstrae toda la clase en su conjunto, incluyendo atributos y comportamientos, pero la interfaz abstrae solo una parte local (el comportamiento) de la clase. Un ejemplo simple: los aviones y las aves son cosas de diferentes categorías, pero ambas tienen una característica en común: ambas pueden volar. Entonces, al diseñar, se puede diseñar el avión como una clase `Airplane` y el ave como una clase `Bird`, pero no se puedevolaresta característica tampoco se puede diseñar como una clase, porque es solo una característica de comportamiento, no una descripción abstracta de un tipo de cosa. En este momento, se puede diseñar 'volar' como una interfaz `Fly` que contenga el método `fly()`, y luego `Airplane` y `Bird` implementan la interfaz `Fly` según sus propias necesidades. En cuanto a los diferentes tipos de aviones, como cazas o aviones civiles, pueden heredar directamente de `Airplane`; para las aves es similar, los diferentes tipos de aves pueden heredar directamente de la clase `Bird`. De aquí se puede ver que la herencia es una relación de 'es/no es', mientras que la implementación de una interfaz es una relación de 'tiene/no tiene'. Si una clase hereda de una clase abstracta, la subclase debe ser del tipo de la clase abstracta; en cambio, la implementación de una interfaz es una cuestión de tener o no tener, como si un ave puede volar (o si tiene la característica de volar); si puede volar, entonces puede implementar la interfaz; si no puede volar, no la implementa.

    2）A nivel de diseño, son diferentes: la clase abstracta, como clase padre de muchas subclases, es un diseño basado en plantillas. La interfaz es una especificación de comportamiento, un diseño radial. ¿Qué es el diseño basado en plantillas? El ejemplo más simple: todos han usado plantillas en PowerPoint. Si se diseñan el PPT B y el PPT C usando la plantilla A, la parte común de PPT B y PPT C es la plantilla A. Si su parte común necesita cambios, solo basta con modificar la plantilla A, sin necesidad de volver a modificar PPT B y PPT C. En cuanto al diseño radial, por ejemplo, si un tipo de ascensor está equipado con cierto tipo de alarma, una vez que haya que actualizar la alarma, deben actualizarse todas. Es decir, para una clase abstracta, si se necesita agregar un nuevo método, se puede agregar directamente una implementación concreta en la clase abstracta, y las subclases no tienen que cambiar; pero para una interfaz no es posible: si la interfaz cambia, todas las clases que la implementan deben modificarse en consecuencia.

    A continuación, veamos el ejemplo más difundido en Internet: el ejemplo de la puerta y la alarma: las puertas tienenopen() 和 close()dos acciones; en este momento podemos definir este concepto abstracto mediante una clase abstracta y una interfaz:

    abstract class Door {
    public abstract void open();
    public abstract void close();
}

    O bien:

    interface Door {
    public abstract void open();
    public abstract void close();
}

    Pero ahora, si necesitamos que la puerta tenga la función de alarma, ¿cómo deberíamos implementarlo? A continuación se presentan dos ideas:

    1) Poner estas tres funciones en la clase abstracta; pero de este modo todas las subclases que hereden de esta clase abstracta tendrán la función de alarma, aunque algunas puertas no necesariamente la tengan;

    2) Poner estas tres funciones en la interfaz; la clase que necesite la función de alarma tendrá que implementar open( ) y close( ) de esta interfaz, y quizás esa clase ni siquiera tenga las funciones open( ) y close( ), como por ejemplo una alarma contra incendios.

    De aquí se puede ver que open(), close() y alarm() de Door pertenecen en realidad a comportamientos de dos categorías diferentes: open() y close() son características de comportamiento inherentes a la propia puerta, mientras que alarm() es un comportamiento adicional extendido. Por lo tanto, la mejor solución es diseñar la alarma por separado como una interfaz, que contenga el comportamiento alarm(), y diseñar Door como una clase abstracta separada, que contenga los comportamientos open y close. Luego diseñar una puerta con alarma que herede de la clase Door e implemente la interfaz Alarm.

    interface Alram {
    void alarm();
}
 
abstract class Door {
    void open();
    void close();
}
 
class AlarmDoor extends Door implements Alarm {
    void oepn() {
      //....
    }
    void close() {
      //....
    }
    void alarm() {
      //....
    }
}

    ¿Por qué se necesitan las clases abstractas?

    Los métodos abstractos y las clases abstractas parecen redundantes. Para un método abstracto, si no sabemos cómo implementarlo, ¿no bastaría con definir un cuerpo de método vacío? Y la clase abstracta no permite crear objetos, lo que parece solo añadir una restricción innecesaria.

    La introducción de métodos abstractos y clases abstractas es una herramienta sintáctica que ofrece Java; para ciertas clases y métodos, guía a los usuarios a usarlos correctamente y reduce su uso indebido.

    Al usar un método abstracto en lugar de un cuerpo de método vacío, la subclase sabe que debe implementar ese método y no puede ignorarlo.

    Al usar una clase abstracta, cuando el usuario de la clase crea un objeto, sabe que debe usar una subclase concreta y no puede usar por error una clase padre incompleta.

    Ya sea al escribir programas o al hacer cualquier otra cosa en la vida diaria, todos podemos cometer errores. Reducir errores no puede depender solo de la excelente calidad de las personas; también se necesitan mecanismos que hagan que una persona común pueda hacer las cosas correctamente con facilidad y difícilmente hacerlas mal. La clase abstracta es precisamente uno de esos mecanismos que Java proporciona.
