Maven POM

POM (Project Object Model, Modelo de Objetos de Proyecto) es el archivo de configuración central de Maven, en formato XML, con el nombre predeterminadopom.xml。

El POM es la unidad básica de trabajo del proyecto Maven. Es un archivo XML que contiene la información básica del proyecto, se utiliza para describir cómo se construye el proyecto, declarar dependencias del proyecto, etc.

Al ejecutar tareas u objetivos, Maven busca el POM en el directorio actual, obtiene la información de configuración necesaria y luego ejecuta el objetivo.

En el POM se pueden especificar las siguientes configuraciones:

  • Dependencias del proyecto
  • Plugins
  • Objetivos de ejecución
  • Perfiles de compilación del proyecto
  • Versión del proyecto
  • Lista de desarrolladores del proyecto
  • Información de listas de correo relacionadas

Antes de crear el POM, primero necesitamos describir el grupo del proyecto (groupId), el identificador único del proyecto.

<project> <!--Versión del modelo--> <modelVersion>4.0.0</modelVersion> <!--Identificador único de la empresa u organización, y la ruta generada durante la configuración también se genera a partir de esto. Por ejemplo, com.companyname.project-group. Maven colocará el paquete jar de este proyecto en la ruta local: /com/companyname/project-group--> <groupId>com.companyname.project-group</groupId> <!--Identificador único del proyecto. Un groupId puede tener múltiples proyectos, y se distinguen por el artifactId.--> <artifactId>project</artifactId> <!--Número de versión--> <version>1.0</version> </project>

Todos los archivos POM requieren el elemento project y tres campos obligatorios: groupId, artifactId y version.

Nodo Descripción
project Etiqueta raíz del proyecto.
modelVersion La versión del modelo debe establecerse en 4.0.
groupId Es el identificador del grupo del proyecto. Suele ser único dentro de una organización o proyecto. Por ejemplo, una organización bancaria com.companyname.project-group tiene todos los proyectos relacionados con la banca.
artifactId Es el identificador del proyecto. Suele ser el nombre del proyecto. Por ejemplo, banco de consumo. groupId y artifactId juntos definen la ubicación del artefacto en el repositorio.
version

Es el número de versión del proyecto. En el repositorio de artefactos, se utiliza para distinguir diferentes versiones. Por ejemplo:

com.company.bank:consumer-banking:1.0
com.company.bank:consumer-banking:1.1

Estructura básica del archivo POM:

Ejemplo

<project>
    <!-- 1. Información básica-->
    <modelVersion>4.0.0</modelVersion>
    <groupId>com.example</groupId>
    <artifactId>my-app</artifactId>
    <version>1.0.0</version>
    <packaging>jar</packaging>

    <!-- 2. Metainformación-->
    <name>My Application</name>
    <description>A demo project</description>
    <url>https://example.com</url>

    <!-- 3. Gestión de dependencias-->
    <dependencies>...</dependencies>

    <!-- 4. Configuración de compilación-->
    <build>...</build>

    <!-- 5. Configuración del entorno-->
    <properties>...</properties>
    <repositories>...</repositories>
</project>

Gestión de dependencias

En el archivo POM se pueden definir las dependencias del proyecto:

<dependencies>
    <dependency>
        <groupId>junit</groupId>
        <artifactId>junit</artifactId>
        <version>4.12</version>
        <scope>test</scope>
    </dependency>
</dependencies>
ElementoDescripción
groupIdIdentificador de la organización de la dependencia
artifactIdNombre del proyecto de la dependencia
versionVersión de la dependencia
scopeAlcance de la dependencia (compile/test/provided/runtime）
optionalSi es dependencia opcional (por defectofalse）

Gestión de plugins

En el archivo POM también se pueden definir plugins para el proceso de compilación:

<build>
    <plugins>
        <plugin>
            <groupId>org.apache.maven.plugins</groupId>
            <artifactId>maven-compiler-plugin</artifactId>
            <version>3.8.1</version>
            <configuration>
                <source>1.8</source>
                <target>1.8</target>
            </configuration>
        </plugin>
    </plugins>
</build>

Plugins comunes:

  • maven-compiler-plugin: especifica la versión de Java

  • maven-surefire-plugin: controla la ejecución de pruebas

  • maven-jar-plugin: personaliza el paquete JAR

Otros elementos comunes

properties: define algunas variables de propiedades en el proyecto.

Se utiliza para definir variables y evitar repeticiones:

<properties>
    <java.version>11</java.version>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
</properties>

Referenciar en las dependencias:

<version>${java.version}</version>

repositories: Configuración de repositorio.

Especificar repositorio remoto:

<repositories>
    <repository>
        <id>aliyun</id>
        <url>https://maven.aliyun.com/repository/public</url>
    </repository>
</repositories>

dependencyManagement: se utiliza para gestionar las versiones de las dependencias, especialmente en proyectos multimódulo.

<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.springframework</groupId>
            <artifactId>spring-core</artifactId>
            <version>5.3.9</version>
        </dependency>
    </dependencies>
</dependencyManagement>

profiles: se utiliza para definir diferentes configuraciones de compilación, permitiendo compilar según distintos entornos.

<profiles>
    <profile>
        <id>development</id>
        <properties>
            <environment>dev</environment>
        </properties>
    </profile>
    <profile>
        <id>production</id>
        <properties>
            <environment>prod</environment>
        </properties>
    </profile>
</profiles>

Herencia y agregación

Herencia:Mediante el elemento parent, un archivo POM puede heredar la configuración de otro archivo POM:

<parent>
    <groupId>com.example</groupId>
    <artifactId>parent-project</artifactId>
    <version>1.0-SNAPSHOT</version>
</parent>

Agregación:Mediante el elemento modules, un archivo POM puede gestionar varios submódulos:

<modules>
    <module>module1</module>
    <module>module2</module>
</modules>

POM padre (Super POM)

El POM padre (Super POM) es el POM predeterminado de Maven. Todos los POM heredan de un POM padre (esté o no definido explícitamente). El POM padre contiene algunos ajustes predeterminados que pueden heredarse. Por lo tanto, cuando Maven detecta que necesita descargar dependencias del POM, va al repositorio predeterminado configurado en el Super POM, http://repo1.maven.org/maven2, para descargarlas.

Maven utiliza el POM efectivo (Super POM más la configuración propia del proyecto) para ejecutar los objetivos correspondientes. Esto ayuda a los desarrolladores a realizar la menor configuración posible en pom.xml; por supuesto, estas configuraciones pueden sobrescribirse.

Utilice el siguiente comando para ver la configuración predeterminada del Super POM:

mvn help:effective-pom

A continuación creamos el directorio MVN/project, y en ese directorio creamos pom.xml con el siguiente contenido:

<project xmlns = "http://maven.apache.org/POM/4.0.0" xmlns:xsi = "http://www.w3.org/2001/XMLSchema-instance" xsi:schemaLocation = "http://maven.apache.org/POM/4.0.0 http://maven.apache.org/xsd/maven-4.0.0.xsd"> <!--Versión del modelo--> <modelVersion>4.0.0</modelVersion> <!--Identificador único de la empresa u organización, y la ruta generada durante la configuración también se genera a partir de esto. Por ejemplo, com.companyname.project-group. Maven colocará el paquete jar de este proyecto en la ruta local: /com/companyname/project-group--> <groupId>com.companyname.project-group</groupId> <!--Identificador único del proyecto.
