Ciclo de vida de construcción de Maven

El ciclo de vida de construcción de Maven define un proceso de construcción y publicación de un proyecto, e incluye tres ciclos de vida estándar:

  • clean: limpiar el proyecto
  • default (o build): flujo de construcción principal
  • site: generar la documentación del proyecto

Cada ciclo de vida se compone de múltiples fases (phase), y se ejecutan en orden.

1. Ciclo de vida clean

El ciclo de vida clean se encarga de limpiar los archivos y directorios temporales del proyecto (principalmente target/), e incluye las siguientes fases principales:

FaseDescripciónObjetivos de plugin vinculados automáticamente
pre-cleanTrabajo preparatorio antes de la limpiezaSin vinculación predeterminada
cleanEliminartarget/Directoriomaven-clean-plugin:clean
post-cleanTrabajo final después de la limpiezaSin vinculación predeterminada

Comandos comunes:

mvn clean      # 执行clean阶段（包含pre-clean和clean）

2. Ciclo de vida default

El ciclo de vida default es el ciclo de vida más importante de Maven; incluye todos los pasos principales de construcción y despliegue del proyecto.

Un ciclo de vida de construcción (build) típico de Maven se compone de una secuencia de las siguientes fases:

Fase Procesamiento Descripción
Validar (validate) Validar el proyecto Validar que el proyecto sea correcto y que toda la información necesaria esté disponible.
Compilar (compile) Realizar la compilación La compilación del código fuente se completa en esta fase.
Probar (Test) Probar Ejecutar las pruebas utilizando un marco de pruebas unitarias adecuado (por ejemplo, JUnit).
Empaquetar (package) Empaquetar Empaquetar el código compilado en un formato distribuible, por ejemplo JAR o WAR.
Verificar (verify) Verificar Verificar los resultados de las pruebas de integración para garantizar que la calidad cumpla los estándares.
Instalar (install) Instalar Instalar el proyecto empaquetado en el repositorio local para que otros proyectos puedan utilizarlo.
Desplegar (deploy) Desplegar Copiar el paquete final del proyecto al repositorio remoto para compartirlo con otros desarrolladores y proyectos.

Para completar el ciclo de vida default, estas fases (incluyendo otras fases del ciclo de vida no enumeradas anteriormente) se ejecutarán en orden.

Dependencias de las fases:

Comandos comunes:

mvn compile     # 编译主代码
mvn test        # 运行测试
mvn package     # 打包（生成target/*.jar）
mvn install     # 安装到本地仓库（~/.m2/repository）
mvn deploy      # 部署到远程仓库（需配置distributionManagement）

3. Ciclo de vida site

El ciclo de vida site se utiliza para generar la documentación del sitio del proyecto:

FaseDescripciónObjetivos de plugin vinculados automáticamente
pre-sitePreparación antes de generar el sitioSin vinculación predeterminada
siteGenerar la documentación del sitio del proyectomaven-site-plugin:site
post-siteTrabajo final después de generar el sitioSin vinculación predeterminada
site-deployDesplegar el sitio en el servidormaven-site-plugin:deploy

Comandos comunes:

mvn site        # 生成站点（输出在target/site/）
mvn site-deploy # 部署站点（需配置site URL）

Resumen del ciclo de vida

Maven tiene los siguientes tres ciclos de vida estándar:

1. Ciclo de vida Clean:

  • clean: Elimina los archivos de salida de compilación en el directorio de destino. Esto generalmente se ejecuta antes de la construcción para garantizar que el proyecto comience desde un estado limpio.

2. Ciclo de vida Default (también conocido como ciclo de vida Build):

  • validate: Verifica la corrección del proyecto, por ejemplo, comprueba si la versión del proyecto es correcta.
  • compile: Compila el código fuente del proyecto.
  • test: Ejecuta las pruebas unitarias del proyecto.
  • package: Empaqueta el código compilado en un formato distribuible, por ejemplo JAR o WAR.
  • verify: Realiza comprobaciones adicionales en el proyecto para garantizar la calidad.
  • install: Instala el resultado de la construcción del proyecto en el repositorio local de Maven para que otros proyectos puedan utilizarlo.
  • deploy: Copia el resultado de la construcción del proyecto al repositorio remoto para que otros desarrolladores o equipos puedan utilizarlo.

3. Ciclo de vida Site:

  • site: Genera la documentación del proyecto y la información del sitio.
  • deploy-site: Publica la información del sitio generada en un servidor remoto para compartir la documentación del proyecto.

Las fases de construcción están compuestas por objetivos de plugin.

Un objetivo de plugin representa una tarea específica (más detallada que una fase de construcción), lo que ayuda a la construcción y gestión del proyecto. Estos objetivos pueden estar vinculados a múltiples fases o no tener vinculación. Los objetivos que no están vinculados a ninguna fase de construcción pueden ejecutarse mediante una invocación directa fuera del ciclo de vida de construcción. El orden de ejecución de estos objetivos depende del orden en que se invoquen los objetivos y las fases de construcción.

Por ejemplo, considere el siguiente comando:

clean y pakage son fases de construcción, dependency:copy-dependencies es el objetivo.

mvn clean dependency:copy-dependencies package

Aquí, la fase clean se ejecutará primero, luego se ejecutará el objetivo dependency:copy-dependencies y, finalmente, se ejecutará la fase package.

1. Ciclo de vida Clean

Cuando ejecutamos el comando mvn post-clean, Maven invoca el ciclo de vida clean, que incluye las siguientes fases:

  • pre-clean: realizar algún trabajo que debe completarse antes de clean
  • clean: eliminar todos los archivos generados en la última construcción
  • post-clean: realizar algún trabajo que debe completarse inmediatamente después de clean

El clean en mvn clean es el clean mencionado anteriormente. En un ciclo de vida, cuando se ejecuta una fase, todas las fases anteriores a ella también se ejecutan. Es decir, si se ejecuta mvn clean, se ejecutarán las siguientes dos fases del ciclo de vida:

pre-clean, clean

Si ejecutamos mvn post-clean, se ejecutarán las siguientes tres fases del ciclo de vida:

pre-clean, clean, post-clean

Podemos modificar el comportamiento de esta parte definiendo objetivos en cualquier fase del ciclo de vida clean anterior.

En el siguiente ejemplo, agregamos el objetivo maven-antrun-plugin:run a las fases pre-clean, clean y post-clean. De esta manera, podemos mostrar mensajes de texto en las distintas fases del ciclo de vida clean.

Hemos creado un archivo pom.xml en el directorio C:\MVN\project.

<project xmlns="http://maven.apache.org/POM/4.0.0" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 http://maven.apache.org/xsd/maven-4.0.0.xsd"> <modelVersion>4.0.0</modelVersion> <groupId>com.companyname.projectgroup</groupId> <artifactId>project</artifactId> <version>1.0</version> <build> <plugins> <plugin> <groupId>org.apache.maven.plugins</groupId> <artifactId>maven-antrun-plugin</artifactId> <version>1.1</version> <executions> <execution> <id>id.pre-clean</id> <phase>pre-clean</phase> <goals> <goal>run</goal> </goals> <configuration> <tasks> <echo>pre-clean phase</echo> </tasks> </configuration> </execution> <execution> <id>id.clean</id> <phase>clean</phase> <goals> <goal>run</goal> </goals> <configuration> <tasks> <echo>clean phase</echo> </tasks> </configuration> </execution> <execution> <id>id.post-clean</id> <phase>post-clean</phase> <goals> <goal>run</goal> </goals> <configuration> <tasks> <echo>post-clean phase</echo> </tasks> </configuration> </execution> </executions> </plugin> </plugins> </build> </project>

Ahora abra la consola de comandos, navegue hasta el directorio donde se encuentra pom.xml y ejecute el siguiente comando mvn.

C:\MVN\project>mvn post-clean

2. Ciclo de vida Default (Build)

Este es el ciclo de vida principal de Maven, que se utiliza para construir aplicaciones e incluye las siguientes 23 fases:

Fases del ciclo de vida Descripción
validate (validación) Validar que el proyecto sea correcto y que toda la información necesaria esté disponible para completar el proceso de construcción del proyecto.
initialize (inicialización) Inicializar el estado de la construcción, por ejemplo, establecer valores de propiedades.
generate-sources (generar código fuente) Generar cualquier código fuente que se incluya en la fase de compilación.
process-sources (procesar código fuente) Procesar el código fuente, por ejemplo, filtrar cualquier valor.
generate-resources (generar archivos de recursos) Generar los archivos de recursos que se incluirán en el paquete del proyecto.
process-resources (procesar archivos de recursos) Copiar y procesar los recursos al directorio de destino, para preparar la fase de empaquetado.
compile (compilar) Compilar el código fuente del proyecto.
process-classes (procesar archivos de clase) Procesar los archivos generados por la compilación, por ejemplo, realizar mejoras de optimización de bytecode en los archivos class de Java.
generate-test-sources (generar código fuente de pruebas) Generar cualquier código fuente de prueba que se incluya en la fase de compilación.
process-test-sources (procesar código fuente de pruebas) Procesar el código fuente de pruebas, por ejemplo, filtrar cualquier valor.
generate-test-resources (generar archivos de recursos de prueba) Crear archivos de recursos para las pruebas.
process-test-resources (procesar archivos de recursos de prueba) Copiar y procesar los recursos de prueba en el directorio de destino.
test-compile (compilar el código fuente de prueba) Compilar el código fuente de prueba en el directorio de destino de prueba.
process-test-classes (procesar archivos de clases de prueba) Procesar los archivos generados por la compilación del código fuente de prueba.
test (prueba) Ejecutar las pruebas utilizando un marco de pruebas unitarias adecuado (JUnit es uno de ellos).
prepare-package (preparar el empaquetado) Antes del empaquetado real, realizar las operaciones necesarias para preparar el empaquetado.
package (empaquetar) Empaquetar el código compilado en archivos de formato distribuible, como archivos JAR, WAR o EAR.
pre-integration-test (antes de la prueba de integración) Realizar las acciones necesarias antes de ejecutar las pruebas de integración. Por ejemplo, configurar el entorno necesario.
integration-test (prueba de integración) Procesar y desplegar el proyecto en un entorno donde se puedan ejecutar las pruebas de integración.
post-integration-test (después de la prueba de integración) Realizar las acciones necesarias después de completar las pruebas de integración. Por ejemplo, limpiar el entorno de pruebas de integración.
verify (verificar) Ejecutar cualquier comprobación para verificar que el paquete del proyecto es válido y cumple con los estándares de calidad.
install (instalar) Instalar el paquete del proyecto en el repositorio local, de modo que pueda utilizarse como dependencia de otros proyectos locales.
deploy (desplegar) Copiar el paquete final del proyecto al repositorio remoto para compartirlo con otros desarrolladores y proyectos.

Hay algunos conceptos importantes relacionados con el ciclo de vida de Maven que deben explicarse:

Cuando una fase se invoca mediante un comando de Maven, por ejemplo mvn compile, solo se ejecutan todas las fases anteriores a esa fase, incluida la propia fase.

Los diferentes objetivos de Maven se vinculan a diferentes fases del ciclo de vida de Maven según el tipo de empaquetado (JAR / WAR / EAR).

En el siguiente ejemplo, agregamos el objetivo maven-antrun-plugin:run a algunas fases del ciclo de vida de Build. De esta manera, podemos mostrar la información textual del ciclo de vida.

Invocación desde la línea de comandos

En el entorno de desarrollo, use el siguiente comando para construir e instalar el proyecto en el repositorio local.

mvn install

Este comando ejecuta las fases del ciclo de vida default (validate, compile, package, etc.) en orden antes de ejecutar la fase install; solo necesitamos invocar la última fase, que aquí es install.

En el entorno de construcción, use la siguiente invocación para realizar una compilación limpia y desplegar el proyecto en el repositorio compartido.

mvn clean deploy

Esta línea de comandos también se puede utilizar en el caso de múltiples módulos, es decir, proyectos que contienen varios subproyectos. Maven ejecutará el comando clean en cada subproyecto y luego ejecutará el comando deploy.

3. Ciclo de vida Site

El plugin Maven Site se usa generalmente para crear nuevos documentos de informes, desplegar sitios, etc.

  • pre-site: realizar algunos trabajos que deben completarse antes de generar la documentación del sitio.
  • site: generar la documentación del sitio del proyecto.
  • post-site: realizar algunos trabajos que deben completarse después de generar la documentación del sitio y prepararse para el despliegue.
  • site-deploy: desplegar la documentación del sitio generada en un servidor específico.

Las fases que se usan con frecuencia aquí son la fase site y la fase site-deploy, para generar y publicar el sitio de Maven. Esta es una función bastante potente de Maven; a los gerentes les gusta mucho, ya que los documentos y los datos estadísticos se generan automáticamente y se ven muy bien. En el siguiente ejemplo, agregamos el objetivo maven-antrun-plugin:run a todas las fases del ciclo de vida de Site. De esta manera, podemos mostrar toda la información textual del ciclo de vida.
