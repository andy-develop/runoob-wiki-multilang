Análisis del ejemplo - Función showHint()

Cuando el usuario escribe caracteres en el cuadro de entrada anterior, se ejecuta la función "showHint()". Esta función se activa mediante el evento "onkeyup":

function showHint(str) { var xmlhttp; if (str.length==0) { document.getElementById("txtHint").innerHTML=""; return; } if (window.XMLHttpRequest) { //Código ejecutado en navegadores IE7+, Firefox, Chrome, Opera, Safari xmlhttp=new XMLHttpRequest(); } else { //Código ejecutado en navegadores IE6, IE5 xmlhttp=new ActiveXObject("Microsoft.XMLHTTP"); } xmlhttp.onreadystatechange=function() { if (xmlhttp.readyState==4 && xmlhttp.status==200) { document.getElementById("txtHint").innerHTML=xmlhttp.responseText; } } xmlhttp.open("GET","/try/ajax/gethint.php?q="+str,true); xmlhttp.send(); }

Análisis del código fuente:

Si el cuadro de entrada está vacíostr.length==0, entonces la función limpiatxtHintel contenido del marcador de posición y sale de la función.

Si el cuadro de entrada no está vacío,showHint()la función realiza las siguientes tareas:

  • CrearXMLHttpRequestobjeto
  • ejecutar la función cuando la respuesta del servidor esté lista
  • enviar la solicitud al archivo en el servidor
  • Tenga en cuenta que agregamos un parámetro q (con el contenido del cuadro de entrada) a la URL.

'get the q parameter from URL

if (strlen($q) > 0)
{
  $hint="";
  for($i=0; $i<count($a); $i++)
  {
    if (strtolower($q)==strtolower(substr($a[$i],0,strlen($q))))
    {
      if ($hint=="")
      {
        $hint=$a[$i];
      }
      else
      {
        $hint=$hint." , ".$a[$i];
      }
    }
  }
}

// Set output to "no suggestion" if no hint were found
// or to the correct values
if ($hint == "")
{
  $response="no suggestion";
}
else
{
  $response=$hint;
}

//output the response
echo $response;
?>

    Valores y explicación de xmlhttp.readyState:

    0: Solicitud no inicializada (open() aún no ha sido llamada).

    1: Solicitud establecida, pero aún no enviada (send() aún no ha sido llamada).

    2: Solicitud enviada, procesándose (normalmente ahora se pueden obtener los encabezados de contenido de la respuesta).

    3: Solicitud en procesamiento; normalmente ya hay algunos datos disponibles en la respuesta, pero el servidor aún no ha terminado de generar la respuesta.

    4: Respuesta completada; puede obtener y usar la respuesta del servidor.

    Valores y explicación de xmlhttp.status:

    100: El cliente debe continuar haciendo la solicitud.

    101: El cliente solicita al servidor que cambie la versión del protocolo HTTP según la solicitud.

    200: Transacción exitosa.

    201: Indica que se conoce la URL del nuevo archivo.

    202: Aceptada y procesada, pero el procesamiento no está completo.

    203: Información devuelta incierta o incompleta.

    204: Solicitud recibida, pero la información devuelta está vacía.

    205: El servidor completó la solicitud; el agente de usuario debe restablecer el archivo que ha sido navegado actualmente.

    206: El servidor ha completado parte de la solicitud GET del usuario.

    300: El recurso solicitado está disponible en múltiples ubicaciones.

    301: Se eliminan los datos de la solicitud.

    302: Los datos solicitados se encuentran en otra dirección.

    303: Se sugiere al cliente acceder a otra URL o método de acceso.

    304: El cliente ya ejecutó GET, pero el archivo no ha cambiado.

    305: El recurso solicitado debe obtenerse de la dirección especificada por el servidor.

    306: Código utilizado en versiones anteriores de HTTP, ya no se usa en la versión actual.

    307: Declara que el recurso solicitado se ha eliminado temporalmente.

    400: Solicitud incorrecta, como error de sintaxis.

    401: Falló la autorización de la solicitud.

    402: Respuesta de encabezado ChargeTo válida reservada.

    403: Solicitud no permitida.

    404: No se encontró archivo, consulta o URL.

    405: El método definido por el usuario en el campo Request-Line no está permitido.

    406: Según el Accept enviado por el usuario, el recurso solicitado no es accesible.

    407: Similar a 401, el usuario debe primero autorizarse en el servidor proxy.

    408: El cliente no completó la solicitud dentro del tiempo especificado por el usuario.

    409: Para el estado actual del recurso, la solicitud no puede completarse.

    410: El recurso ya no existe en el servidor y no hay más direcciones de referencia.

    411: El servidor rechaza la solicitud de propiedad Content-Length definida por el usuario.

    412: Uno o más campos de encabezado de solicitud son incorrectos en la solicitud actual.

    413: El recurso solicitado es mayor que el tamaño permitido por el servidor.

    414: La URL del recurso solicitado es más larga que la longitud permitida por el servidor.

    415: El recurso solicitado no admite el formato del elemento de solicitud.

    416: La solicitud contiene el campo de encabezado Range, no hay un valor de range dentro del rango del recurso solicitado actualmente, y la solicitud tampoco contiene el campo de encabezado If-Range.

    417: El servidor no cumple con el valor esperado especificado por el campo de encabezado Expect; si es un servidor proxy, puede que el siguiente servidor no pueda satisfacer la solicitud.

    En resumen

    500: El servidor genera un error interno.

    501: El servidor no admite la función solicitada.

    502: El servidor no está disponible temporalmente, a veces para prevenir una sobrecarga del sistema.

    503: El servidor está sobrecargado o en mantenimiento temporal.

    504: Puerta de enlace sobrecargada, el servidor usa otra puerta de enlace o servicio para responder al usuario, el tiempo de espera configurado es demasiado largo.

    505: El servidor no admite o rechaza la versión de HTTP especificada en el encabezado de solicitud.

    1xx: Clase de respuesta informativa, indica que se ha recibido la solicitud y se continúa procesando.

    2xx: Clase de respuesta de procesamiento exitoso, indica que la acción fue recibida, comprendida y aceptada correctamente.

    3xx: Clase de respuesta de redirección, para completar la acción especificada se debe aceptar un procesamiento adicional.

    4xx: Error de cliente, la solicitud del cliente contiene errores de sintaxis o no puede ejecutarse correctamente.

    5xx: Error de servidor, el servidor no puede ejecutar correctamente una solicitud válida.

    xmlhttp.readyState==4 && xmlhttp.status==200La explicación: la solicitud se completó y se devolvió con éxito.
