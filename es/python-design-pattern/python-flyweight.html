Python 享元模式

El patrón Flyweight es un patrón de diseño estructural que minimiza el uso de memoria y mejora el rendimiento mediante el uso compartido de objetos. En pocas palabras, es la idea de "compartir metadatos".

Imagina que vas a la biblioteca a tomar prestado un libro: si cada persona comprara su propio ejemplar, la biblioteca tendría que almacenar miles de copias del mismo libro. Pero en realidad, la biblioteca solo necesita almacenar un ejemplar de "Introducción a Python", y todos los que quieran leerlo pueden tomar prestado ese mismo ejemplar. El patrón Flyweight es como esa "biblioteca": gestiona los objetos que se pueden compartir.

核心思想

El patrón Flyweight divide el estado de un objeto en dos tipos:

  • Estado interno (Intrinsic State): la parte inmutable y compartible
  • Estado externo (Extrinsic State): la parte variable y no compartible

Al compartir el estado interno, se evita crear muchos objetos similares, ahorrando así recursos del sistema.

为什么需要享元模式

问题场景

Supongamos que estamos desarrollando un procesador de texto y necesitamos renderizar los caracteres de un documento. Si creamos un objeto independiente para cada carácter:

实例

# Implementación deficiente: cada carácter es un objeto independiente
class Character:
    def __init__(self, char, font, size, color):
        self.char = char      # Carácter
        self.font = font      # Fuente
        self.size = size      # Tamaño de fuente
        self.color = color    # Color
   
    def render(self, position):
        print(f"Renderizando el carácter '{self.char}' en la posición {position}")

# Ejemplo de uso
char_a = Character('A', '宋体', 12, '黑色')
char_b = Character('B', '宋体', 12, '黑色')
char_a_another = Character('A', '宋体', 12, '黑色')  # Se crea repetidamente el mismo 'A'

Problemas de esta implementación:

  • Desperdicio de memoria: los mismos caracteres se crean repetidamente
  • Bajo rendimiento: gran costo de creación y destrucción de objetos
  • Difícil de mantener: la cantidad de objetos crece explosivamente

解决方案

Usando el patrón Flyweight, podemos:

  • Compartir los mismos objetos de caracteres
  • Almacenar solo una copia del estado interno (el carácter en sí)
  • El estado externo (posición) se pasa al renderizar

享元模式的实现

基本结构

Implementemos el patrón Flyweight con el ejemplo del procesador de texto:

实例

from typing import Dict

# Clase Flyweight: almacena el estado interno
class CharacterFlyweight:
    def __init__(self, char: str, font: str, size: int, color: str):
        self.char = char      # Estado interno: contenido del carácter
        self.font = font      # Estado interno: fuente
        self.size = size      # Estado interno: tamaño de fuente
        self.color = color    # Estado interno: color
   
    def render(self, position: tuple):
        """Renderiza el carácter; position es el estado externo"""
        x, y = position
        print(f"Renderizando en ({x}, {y}): carácter '{self.char}' "
              f"[fuente:{self.font}, tamaño:{self.size}, color:{self.color}]")

# Fábrica Flyweight: gestiona los objetos compartidos
class CharacterFactory:
    _characters: Dict[str, CharacterFlyweight] = {}
   
    @classmethod
    def get_character(cls, char: str, font: str, size: int, color: str) -> CharacterFlyweight:
        # Clave única que identifica el objeto a crear
        key = f"{char}_{font}_{size}_{color}"
       
        # Si el objeto no existe, se crea y se almacena en caché
        if key not in cls._characters:
            cls._characters[key] = CharacterFlyweight(char, font, size, color)
            print(f"Creando nuevo objeto de carácter: {key}")
        else:
            print(f"Reutilizando objeto de carácter existente: {key}")
       
        return cls._characters[key]

# Clase cliente: usa objetos Flyweight
class TextDocument:
    def __init__(self):
        self.characters = []  # Almacena el carácter y la información de posición
   
    def add_character(self, char: str, font: str, size: int, color: str, position: tuple):
        # Obtiene el objeto Flyweight de la fábrica
        character = CharacterFactory.get_character(char, font, size, color)
        # Almacena el objeto de carácter y el estado externo (posición)
        self.characters.append((character, position))
   
    def render(self):
        print("\n"=== Comenzando a renderizar el documento ===")
        for character, position in self.characters:
            character.render(position)
        print("=== Renderizado del documento completado ==="\n")

享元模式的核心组件

1. Flyweight（享元接口或抽象类）

Define la interfaz de los objetos Flyweight, que generalmente incluye métodos para operar con el estado externo.

2. ConcreteFlyweight（具体享元类）

Implementa la interfaz Flyweight y almacena el estado interno. El estado interno debe ser inmutable.

3. FlyweightFactory（享元工厂）

Crea y gestiona los objetos Flyweight, asegurando que se compartan correctamente.

4. Client（客户端）

Mantiene el estado externo y solicita objetos Flyweight a la fábrica cuando es necesario.

更复杂的示例：游戏开发中的应用

Veamos un ejemplo real en el desarrollo de juegos: un sistema de renderizado de árboles.

实例

from typing import Dict, List
from dataclasses import dataclass

@dataclass
class TreeType:
    """Clase Flyweight: tipo de árbol (estado interno)"""
    name: str          # Nombre de la especie de árbol
    texture: str       # Archivo de textura
    color: str         # Color base
   
    def render(self, x: int, y: int, height: int):
        """Renderiza el árbol; la posición y la altura son estado externo"""
        print(f"Renderizando árbol {self.name} en ({x}, {y}), altura {height} metros "
              f"[textura:{self.texture}, color:{self.color}]")

class TreeFactory:
    """Fábrica Flyweight: gestiona los tipos de árbol"""
    _tree_types: Dict[str, TreeType] = {}
   
    @classmethod
    def get_tree_type(cls, name: str, texture: str, color: str) -> TreeType:
        key = f"{name}_{texture}_{color}"
        if key not in cls._tree_types:
            cls._tree_types[key] = TreeType(name, texture, color)
            print(f"Creando nuevo tipo de árbol: {name}")
        return cls._tree_types[key]
   
    @classmethod
    def list_tree_types(cls):
        print(f"\n"Actualmente hay {len(cls._tree_types)} tipos de árbol:")
        for tree_type in cls._tree_types.values():
            print(f"  - {tree_type.name}")

class Tree:
    """Objeto árbol: contiene la referencia Flyweight y el estado externo"""
    def __init__(self, x: int, y: int, height: int, tree_type: TreeType):
        self.x = x              # Estado externo: coordenada X
        self.y = y              # Estado externo: coordenada Y
        self.height = height    # Estado externo: altura
        self.tree_type = tree_type  # Referencia al objeto Flyweight
   
    def render(self):
        self.tree_type.render(self.x, self.y, self.height)

class Forest:
    """Bosque: clase cliente"""
    def __init__(self):
        self.trees: List[Tree] = []
   
    def plant_tree(self, x: int, y: int, height: int,
                   name: str, texture: str, color: str):
        tree_type = TreeFactory.get_tree_type(name, texture, color)
        tree = Tree(x, y, height, tree_type)
        self.trees.append(tree)
   
    def render(self):
        print("\n"=== Comenzando a renderizar el bosque ===")
        for tree in self.trees:
            tree.render()
        print("=== Renderizado del bosque completado ===")

# Ejemplo de uso
forest = Forest()

# Plantar árboles: los árboles del mismo tipo comparten el objeto Flyweight
forest.plant_tree(10, 20, 15, "Pino", "pine_texture.png", "Verde oscuro")
forest.plant_tree(30, 40, 12, "Pino", "pine_texture.png", "Verde oscuro")  # Se reutiliza el tipo Pino
forest.plant_tree(50, 60, 18, "Roble", "oak_texture.png", "Verde claro")
forest.plant_tree(70, 80, 20, "Pino", "pine_texture.png", "Verde oscuro")  # Se reutiliza de nuevo
forest.plant_tree(90, 100, 16, "Arce", "maple_texture.png", "Rojo")

# Renderizar bosque
forest.render()

# Ver estadísticas de tipos de árbol
TreeFactory.list_tree_types()

享元模式的优缺点

优点

  1. Reducción significativa del uso de memoria: al compartir objetos similares, se reduce notablemente la ocupación de memoria
  2. Mejora del rendimiento: reduce la sobrecarga de creación de objetos y recolección de basura
  3. Reutilización de código: la lógica de los objetos idénticos solo necesita implementarse una vez
  4. Fácil de ampliar: añadir nuevos tipos Flyweight no afecta al código existente

缺点

  1. Mayor complejidad: hay que distinguir entre estado interno y estado externo
  2. Problemas de concurrencia: los objetos compartidos requieren un tratamiento adicional en entornos multiproceso
  3. Posible introducción de errores: si se modifica por error el estado interno, afectará a todos los usuarios
  4. No aplicable a todos los escenarios: solo es efectivo cuando los objetos son realmente compartibles

适用场景

适合使用享元模式的场景

  1. Gran cantidad de objetos similares: cuando el sistema necesita crear una gran cantidad de objetos similares
  2. Aplicaciones sensibles a la memoria: entornos con memoria limitada como dispositivos móviles, sistemas embebidos, etc.
  3. Sistemas de caché: cuando se necesita almacenar en caché y reutilizar objetos
  4. Desarrollo de juegos: renderizar una gran cantidad de objetos de juego del mismo tipo
  5. Procesamiento de documentos: procesadores de texto, hojas de cálculo, etc.

不适合使用的场景

  1. Los objetos difieren mucho entre sí: si cada objeto tiene un estado único
  2. Estado externo complejo: si la gestión del estado externo es más compleja que la creación de objetos
  3. Requisitos de rendimiento bajos: en escenarios con memoria suficiente y requisitos de rendimiento bajos

总结

El patrón Flyweight es una poderosa técnica de optimización que reduce el consumo de recursos mediante la compartición de objetos. Puntos clave:

  1. Distinguir estados: distinguir claramente entre estado interno (compartible) y estado externo (no compartible)
  2. Usar una fábrica: gestionar la creación y compartición de objetos Flyweight mediante una clase de fábrica
  3. Sopesar pros y contras: encontrar un equilibrio entre el ahorro de memoria y la complejidad del código
  4. Escenarios aplicables: principalmente para escenarios con una gran cantidad de objetos similares
