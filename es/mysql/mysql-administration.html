MySQL Administración

Iniciar y cerrar el servidor MySQL

En el sistema Windows

Iniciar el servidor MySQL:

1、Mediante la herramienta de administración "Servicios":Abra el cuadro de diálogo "Ejecutar" (Win + R), escribaservices.msc, busque el servicio "MySQL", haga clic derecho y seleccione "Iniciar".

2. Mediante el símbolo del sistema:Abra el símbolo del sistema (como administrador) y escriba el siguiente comando:

net start mysql

Cerrar el servidor MySQL:

1、Mediante la herramienta de administración "Servicios":De igual manera, abra el cuadro de diálogo "Ejecutar", escriba services.msc, busque el servicio "MySQL", haga clic derecho y seleccione "Detener".

2、Mediante el símbolo del sistema:Abra el símbolo del sistema (como administrador) y escriba el siguiente comando:

net stop mysql

En el sistema Linux

1. Iniciar el servicio de MySQL:

Use elsystemdcomando (aplicable a la mayoría de las distribuciones modernas de Linux, como Ubuntu, CentOS, etc.):

sudo systemctl start mysql

Use elservicecomando (en algunas distribuciones más antiguas):

sudo service mysql start

2. Cerrar el servicio de MySQL:

Use systemd:

sudo systemctl stop mysql

Use el comando service:

sudo service mysql stop

3. Reiniciar el servicio de MySQL:

Use systemd: 
sudo systemctl restart mysql

Use el comando service:

sudo service mysql restart

4. Verificar el estado del servicio de MySQL:

Use el comando systemd:

sudo systemctl status mysql

Use el comando service:

sudo service mysql status

En el sistema Mac OS

Iniciar el servicio de MySQL:

Mediante la línea de comandos:

sudo /usr/local/mysql/support-files/mysql.server start

Cerrar el servicio de MySQL:

Mediante la línea de comandos:

sudo /usr/local/mysql/support-files/mysql.server stop

Reiniciar el servicio de MySQL:

Mediante la línea de comandos:

sudo /usr/local/mysql/support-files/mysql.server restart

Verificar el estado del servicio de MySQL:

Mediante la línea de comandos:

sudo /usr/local/mysql/support-files/mysql.server status

En los comandos anteriores, mysql puede variar según la ruta de instalación o la versión.

En Mac OS, la ruta de instalación de MySQL suele ser /usr/local/mysql/, por lo que para iniciar y cerrar el servicio de MySQL se debe utilizar el script mysql.server ubicado en esta ruta.

Configuración de usuarios de MySQL

En MySQL, la configuración de usuarios incluye operaciones como crear usuarios, establecer privilegios y administrar usuarios. A continuación se presentan algunas operaciones comunes de configuración de usuarios de MySQL, incluyendo crear usuarios, establecer privilegios, ver y eliminar usuarios, etc.

Crear usuario

Para crear un nuevo usuario, puede utilizar el siguiente comando SQL:

CREATE USER 'username'@'host' IDENTIFIED BY 'password';
  • username: nombre de usuario.
  • host: especifica desde qué hosts puede conectarse el usuario. Por ejemplo,localhostsolo permite la conexión local,%permite la conexión desde cualquier host.
  • password: la contraseña del usuario.

Ejemplo

CREATE USER 'john'@'localhost' IDENTIFIED BY 'password123';

Otorgar privilegios

Después de crear el usuario, debe otorgarle privilegios de acceso, use elGRANTcomando para otorgar privilegios:

GRANT privileges ON database_name.* TO 'username'@'host';

  • privileges: los privilegios necesarios, comoALL PRIVILEGES、SELECT、INSERT、UPDATE、DELETEetc.
  • database_name.*: indica otorgar privilegios sobre una base de datos o tabla específica.database_name.*indica otorgar privilegios sobre todas las tablas de una base de datos,database_name.table_nameindica otorgar privilegios sobre una tabla específica.
  • TO 'username'@'host': especifica el usuario y el host a los que se otorgan los privilegios.

Ejemplo

GRANT ALL PRIVILEGES ON test_db.* TO 'john'@'localhost';

Actualizar privilegios

Después de otorgar o revocar privilegios, es necesario actualizar los privilegios para que los cambios surtan efecto:

FLUSH PRIVILEGES;

Ver privilegios de usuario

Para ver los privilegios de un usuario específico, puede utilizar el siguiente comando:

SHOW GRANTS FOR 'username'@'host';

Ejemplo

SHOW GRANTS FOR 'john'@'localhost';

Revocar privilegios

Para revocar los privilegios de un usuario, utilice el comando REVOKE:

REVOKE privileges ON database_name.* FROM 'username'@'host';

Ejemplo

REVOKE ALL PRIVILEGES ON test_db.* FROM 'john'@'localhost';

Eliminar usuario

Si necesita eliminar un usuario, puede utilizar el siguiente comando:

DROP USER 'username'@'host';

Ejemplo

DROP USER 'john'@'localhost';

Cambiar la contraseña de usuario

Para cambiar la contraseña de un usuario, puede utilizar el comando ALTER USER:

ALTER USER 'username'@'host' IDENTIFIED BY 'new_password';

Ejemplo

ALTER USER 'john'@'localhost' IDENTIFIED BY 'newpassword456';

Cambiar el host del usuario

Para cambiar el host del usuario (es decir, desde qué hosts se permite la conexión), puede eliminar el usuario y luego crear uno nuevo.

Ejemplo

-- Eliminar el usuario antiguo
DROP USER 'john'@'localhost';

-- Recrear el usuario y especificar el nuevo host
CREATE USER 'john'@'%' IDENTIFIED BY 'password123';

Especificar privilegios al crear usuario

Al crear un usuario, también se pueden otorgar privilegios al mismo tiempo (en MySQL 8.0.16 y versiones posteriores):

Ejemplo

CREATE USER 'john'@'localhost' IDENTIFIED BY 'password123' WITH GRANT OPTION;
GRANT ALL PRIVILEGES ON test_db.* TO 'john'@'localhost';

Configuración del archivo /etc/my.cnf

El archivo /etc/my.cnf es el archivo de configuración de MySQL, utilizado para configurar varios parámetros y opciones del servidor MySQL.

En general, no es necesario modificar este archivo de configuración. La configuración predeterminada del archivo es la siguiente:

[mysqld]
datadir=/var/lib/mysql
socket=/var/lib/mysql/mysql.sock

[mysql.server]
user=mysql
basedir=/var/lib

[safe_mysqld]
err-log=/var/log/mysqld.log
pid-file=/var/run/mysqld/mysqld.pid

En el archivo de configuración, puede especificar el directorio donde se almacenan los diferentes archivos de registro de errores. Generalmente no es necesario modificar estas configuraciones.

El archivo /etc/my.cnf puede variar según el sistema y la versión de MySQL, pero generalmente incluye las siguientes secciones:

1. Configuración básica

  • basedir: directorio de instalación básico del servidor MySQL.
  • datadir: ubicación donde se almacenan los archivos de datos de MySQL.
  • socket: ruta del archivo de socket Unix del servidor MySQL.
  • pid-file: ruta del archivo que almacena el ID de proceso del servidor MySQL en ejecución.
  • port: número de puerto en el que escucha el servidor MySQL, por defecto es 3306.

2. Opciones del servidor

  • bind-address: especifica la dirección IP en la que escucha el servidor MySQL; puede ser una dirección IP o un nombre de host.
  • server-id: en la configuración de replicación, establece un identificador único para cada servidor MySQL.
  • default-storage-engine: motor de almacenamiento predeterminado, por ejemplo InnoDB o MyISAM.
  • max_connections: número máximo de conexiones que el servidor puede mantener simultáneamente.
  • thread_cache_size: tamaño de la caché de subprocesos, utilizado para mejorar la velocidad de inicio de nuevas conexiones.
  • query_cache_size: tamaño de la caché de consultas, utilizado para mejorar la eficiencia de consultas idénticas.
  • default-character-set: conjunto de caracteres predeterminado.
  • collation-server: regla de ordenamiento (collation) predeterminada del servidor.

3. Ajuste de rendimiento

  • innodb_buffer_pool_size: tamaño del grupo de búferes del motor de almacenamiento InnoDB; este es uno de los parámetros más importantes en el ajuste de rendimiento de InnoDB.
  • key_buffer_size: tamaño del búfer de claves del motor de almacenamiento MyISAM.
  • table_open_cache: cantidad de caché de tablas que se pueden abrir simultáneamente.
  • thread_concurrency: número de subprocesos que se permiten ejecutar simultáneamente.

4. Configuración de seguridad

  • skip-networking: prohíbe que el servidor MySQL escuche conexiones de red; solo permite conexiones locales.
  • skip-grant-tables: inicia el servidor MySQL sin necesidad de contraseña; generalmente se usa para recuperar la contraseña de root olvidada, pero esto es un riesgo de seguridad.
  • auth_native_password=1: habilita la autenticación de contraseña nativa de MySQL 5.7 y versiones posteriores.

5. Configuración de registros (logs)

  • log_error: ruta del archivo de registro de errores.
  • general_log: registra todas las conexiones y consultas de los clientes.
  • slow_query_log: registra las consultas lentas cuyo tiempo de ejecución supera un umbral específico.
  • log_queries_not_using_indexes: registra las consultas que no utilizan índices.

6. Configuración de replicación

  • master_host 和 master_user: dirección del servidor maestro y usuario de replicación.
  • master_password: contraseña del usuario de replicación.
  • master_log_file 和 master_log_pos: archivo de registro y posición utilizados para la replicación.

Comandos para administrar MySQL

A continuación se enumeran los comandos de uso común en el proceso de trabajo con la base de datos MySQL:

  • USE Nombre de la base de datos :
    Seleccione la base de datos MySQL sobre la que se va a operar. Después de usar este comando, todos los comandos MySQL se aplicarán únicamente a esa base de datos.

    mysql> use RUNOOB;
Database changed

  • SHOW DATABASES:
    Muestra la lista de bases de datos del sistema de gestión de bases de datos MySQL.

    mysql> SHOW DATABASES;
+--------------------+
| Database           |
+--------------------+
| information_schema |
| RUNOOB             |
| cdcol              |
| mysql              |
| onethink           |
| performance_schema |
| phpmyadmin         |
| test               |
| wecenter           |

+--------------------+

  • SHOW TABLES:
    Muestra todas las tablas de la base de datos especificada. Antes de usar este comando, se debe usar el comando `use` para seleccionar la base de datos sobre la que se va a operar.

    mysql> use RUNOOB;
Database changed
mysql> SHOW TABLES;
+------------------+
| Tables_in_runoob |
+------------------+
| employee_tbl     |
| runoob_tbl       |
| tcount_tbl       |
+------------------+
3 rows in set (0.00 sec)

  • SHOW COLUMNS FROM Tabla de datos:
    Muestra los atributos de la tabla, el tipo de atributo, la información de la clave primaria, si es NULL, el valor predeterminado y otra información.

    mysql> SHOW COLUMNS FROM runoob_tbl;
+-----------------+--------------+------+-----+---------+-------+

    mysql> SHOW INDEX FROM runoob_tbl;
+------------+------------+----------+--------------+-------------+-----------+-------------+----------+--------+------+------------+---------+---------------+

  • SHOW TABLE STATUS [FROM db_name] [LIKE 'pattern'] \G:
    Este comando muestra el rendimiento y las estadísticas del sistema de gestión de bases de datos MySQL.

    mysql> SHOW TABLE STATUS  FROM RUNOOB;   # 显示数据库 RUNOOB 中所有表的信息

mysql> SHOW TABLE STATUS from RUNOOB LIKE 'runoob%';     # 表名以runoob开头的表的信息

    grant select(id, se, rank) on testdb.apache_log to dba@localhost;

    grant execute on procedure testdb.pr_add to 'dba'@'localhost'
grant execute on function testdb.fn_add to 'dba'@'localhost'

    Ver los permisos del usuario actual (uno mismo):

    show grants;

    Ver los permisos de otros usuarios de MySQL:

    show grants for dba@localhost;

    VII. Revocar los permisos que ya se han otorgado a los usuarios de MySQL.

    La sintaxis de `revoke` es similar a la de `grant`; solo hay que cambiar la palabra clave `to` por `from`:

    grant all on *.* to dba@localhost;
revoke all on *.* from dba@localhost;

    VIII. Consideraciones sobre los permisos de usuario en MySQL con `grant` y `revoke`

    1. Después de otorgar o revocar permisos de usuario con `grant` o `revoke`, dichos permisos solo tendrán efecto cuando el usuario se vuelva a conectar a la base de datos MySQL.

    2. Si se desea que el usuario autorizado también pueda otorgar estos permisos a otros usuarios, se necesita la opción grant option 
    grant select on testdb.* to dba@localhost with grant option;

    Esta característica generalmente no se utiliza. En la práctica, los permisos de la base de datos deberían ser administrados de forma unificada por el DBA.

    Motor de almacenamiento InnoDB

    InnoDB es el motor preferido para bases de datos transaccionales. Admite tablas seguras para transacciones (ACID), bloqueo a nivel de fila y claves foráneas. Desde MySQL 5.5.5, InnoDB es el motor de almacenamiento predeterminado. Sus principales características son:

    1. InnoDB proporciona a MySQL un motor de almacenamiento transaccional seguro (compatible con ACID) con capacidades de confirmación (commit), reversión (rollback) y recuperación ante fallos. InnoDB bloquea a nivel de fila y también ofrece una lectura no bloqueante similar a Oracle en las sentencias SELECT. Estas funcionalidades aumentan el rendimiento y el despliegue multiusuario. En las consultas SQL, se pueden mezclar libremente tablas de tipo InnoDB con otros tipos de tablas de MySQL, incluso en la misma consulta.
    2. InnoDB está diseñado para obtener el máximo rendimiento al manejar grandes volúmenes de datos. Su eficiencia de CPU puede no tener comparación con la de cualquier otro motor de bases de datos relacionales basado en disco.
    3. El motor de almacenamiento InnoDB está completamente integrado con el servidor MySQL. InnoDB mantiene su propio grupo de búferes para almacenar en caché datos e índices en la memoria principal. InnoDB guarda sus tablas e índices en un espacio de tabla lógico, que puede contener varios archivos (o particiones de disco crudas). Esto es diferente de las tablas MyISAM, por ejemplo, en las que cada tabla se almacena en un archivo separado. Las tablas InnoDB pueden tener cualquier tamaño, incluso en sistemas operativos donde el tamaño de archivo está limitado a 2GB.
    4. InnoDB admite la restricción de integridad de claves foráneas (FOREIGN KEY). Al almacenar los datos de las tablas, cada tabla se ordena según la clave primaria. Si no se especifica una clave primaria explícita en la definición de la tabla, InnoDB generará un ROWID de 6B para cada fila y lo utilizará como clave primaria.
    5. InnoDB se utiliza en muchos sitios de bases de datos a gran escala que requieren alto rendimiento. InnoDB no crea directorios. Al usar InnoDB, MySQL creará en el directorio de datos de MySQL un archivo de datos de expansión automática llamado `ibdata1` de 10MB, así como dos archivos de registro de 5MB llamados `ib_logfile()` y `ib_logfile1`.

    Motor de almacenamiento MyISAM

    MyISAM es un motor de almacenamiento basado en ISAM y se extiende sobre él. Es uno de los motores de almacenamiento más utilizados en entornos web, de almacenamiento de datos y otras aplicaciones. MyISAM ofrece una alta velocidad de inserción y consulta, pero no admite transacciones. En versiones anteriores a MySQL 5.5.5, MyISAM era el motor de almacenamiento predeterminado. Sus principales características son:

    1. Los archivos grandes (longitud de archivo de hasta 63 bits) se admiten en sistemas de archivos y sistemas operativos que soportan archivos grandes.
    2. Cuando se mezclan operaciones de eliminación, actualización e inserción, las filas de tamaño dinámico generan menos fragmentación. Esto se logra automáticamente fusionando bloques adyacentes eliminados y, si el siguiente bloque también se elimina, expandiéndose al siguiente bloque.
    3. El número máximo de índices por tabla MyISAM es 64, lo que también se puede cambiar mediante compilación. Para longitudes de clave superiores a 250B, se utilizará una clave de más de 1024B.
    4. Las columnas BLOB y TEXT se pueden indexar.
    5. Se permiten valores NULL en las columnas indexadas. Este valor ocupa de 0 a 1 byte por cada clave.
    6. Todos los valores de claves numéricas se almacenan con el byte alto primero para permitir una mayor compresión del índice.
    7. Manejo interno de una columna AUTO_INCREMENT por tabla. MyISAM actualiza automáticamente esta columna para las operaciones INSERT y UPDATE. Hace que la columna AUTO_INCREMENT sea más rápida (al menos 10%). Los valores en la parte superior de la secuencia no se pueden reutilizar después de ser eliminados.
    8. Se pueden colocar los archivos de datos y de índices en directorios diferentes.
    9. Cada columna de caracteres puede tener un conjunto de caracteres diferente.
    10. Las tablas con VARCHAR pueden tener registros de longitud fija o dinámica.
    11. Las columnas VARCHAR y CHAR pueden tener hasta 64KB.

    Usar el motor MyISAM para crear una base de datos producirá 3 archivos. Los nombres de los archivos comienzan con el nombre de la tabla; las extensiones indican el tipo de archivo: el archivo frm almacena la definición de la tabla, la extensión del archivo de datos es .MYD (MYData), y la extensión del archivo de índice es .MYI (MYIndex).

    Motor de almacenamiento MEMORY.

    El motor de almacenamiento MEMORY almacena los datos de la tabla en memoria, proporcionando acceso rápido para consultas y referencias a datos de otras tablas. Las principales características de MEMORY son:

    1. Cada tabla MEMORY puede tener hasta 32 índices por tabla, 16 columnas por índice y una longitud máxima de clave de 500B.
    2. El motor de almacenamiento MEMORY implementa índices HASH y BTREE.
    3. Se pueden tener claves no únicas en una tabla MEMORY.
    4. MEMORY no admite columnas BLOB o TEXT.
    5. Las tablas MEMORY utilizan un formato de longitud de registro fija.
    6. MEMORY admite columnas AUTO_INCREMENT e índices en columnas que contienen valores NULL.
    7. El contenido de las tablas MEMORY se almacena en memoria; la memoria es compartida entre las tablas MEMORY y las tablas internas que el servidor crea en el espacio libre durante el procesamiento de consultas.
    8. Las tablas MEMORY se comparten entre todos los clientes (como cualquier otra tabla no TEMPORARY).
    9. Cuando ya no se necesite el contenido de una tabla MEMORY, para liberar la memoria utilizada por la tabla MEMORY, se debe ejecutar DELETE FROM o TRUNCATE TABLE, o eliminar toda la tabla (usando DROP TABLE).

    Reporta el siguiente error: ERROR 1364 (HY000): Field 'ssl_cipher' doesn't have a default value

    Causa del error:

    Ciertos campos en la tabla de usuarios de MySQL no pueden estar vacíos y no tienen un valor predeterminado. En realidad, es un error de operación; al agregar usuarios en MySQL no se debe insertar directamente en la tabla user de esta manera.

    Solución:

    Método correcto para agregar un usuario:

    GRANT USAGE ON *.* TO 'user01'@'localhost' IDENTIFIED BY '123456' WITH GRANT OPTION;

    Usuario: user01, contraseña: 123456. De esta manera se agrega un nuevo usuario sin que aparezca el error anterior.
