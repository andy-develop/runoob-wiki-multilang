Comandos de barra diagonal / de Claude Code

Los comandos de barra diagonal (slash)/son la entrada de control rápido de las sesiones interactivas de Claude Code;al escribirinstrucciones que comiencen con /,/se pueden invocar rápidamente funciones, gestionar sesiones y personalizar flujos de trabajo.

Ver todos los comandos disponibles:

/help

/helpSe listarán todos los comandos integrados, los comandos personalizados del proyecto actual (Skills / Commands) y los comandos expuestos por los servidores MCP conectados.

Tipos de comandos:

Tipo Forma de activación Origen Ubicación de almacenamiento Escenarios de uso
Comandos integrados /command Se instalan junto con Claude Code Implementación interna Operaciones del sistema como gestión de sesiones, configuración e integración
Skills integrados /skill-name Incluidos con Claude Code Implementación interna Flujos de trabajo de IA predefinidos como revisión de código, depuración y procesamiento por lotes
Skills personalizados del proyecto Recomendado /skill-name El usuario crea un directorio + SKILL.md .claude/skills/<名称>/SKILL.md Flujos de trabajo reutilizables compartidos por el equipo, incluidos en git; admiten la activación automática por Claude

Prioridad de comandos (cuando hay nombres duplicados): nivel empresarial > nivel personal > nivel de proyecto > integrado

Skills vs Commands: ambos se activan/con /, pero Skills (.claude/skills/) son el nuevo formato: admiten la organización de múltiples archivos, la activación automática por Claude y un control de frontmatter más completo; Commands (.claude/commands/) son el formato antiguo y siguen siendo totalmente compatibles; en proyectos nuevos se recomienda usar Skills directamente.

2. Skills integradosNEW

Los Skills integrados son flujos de trabajo de IA preconfigurados incluidos con Claude Code; a diferencia de los comandos integrados, cargan un prompt detallado y Claude los ejecuta mediante razonamiento, produciendo resultados de análisis y operación más ricos. De la misma manera,/se activan.

Diferencia: comandos integrados vs. Skills integrados
Los comandos integrados (como/clear、/compact) ejecutan lógica fija, no implican razonamiento de IA y son extremadamente rápidos.
Los Skills integrados (como/debug、/simplify) cargan el prompt y Claude los ejecuta mediante razonamiento; los resultados son más ricos y son adecuados para tareas de análisis complejas.
Comando Descripción de la función Casos de uso
/simplify Simplificar el código o texto especificado, mejorar la legibilidad y eliminar la complejidad innecesaria Refactorizar funciones extensas, simplificar código sobre-ingenierizado
/debug Realizar un análisis sistemático de causa raíz de los mensajes de error o comportamientos anómalos, y proporcionar ideas de solución Localizar errores difíciles de reproducir
/batch Ejecutar la misma tarea en paralelo sobre múltiples archivos u objetivos (por ejemplo, renombrado por lotes, agregar anotaciones de tipo por lotes) Cambios de código repetitivos a gran escala
/loop Ejecutar repetidamente una operación en un bucle hasta que se cumpla la condición de salida (por ejemplo, reintentar las pruebas hasta que pasen) Automatizar el bucle de corrección de CI
/claude-api Generar rápidamente código de ejemplo para llamar a la API de Anthropic, con soporte para especificar el modelo y el tipo de tarea Crear prototipos de integración con la API de Claude

4. Skills personalizados (nuevo formato recomendado)

Los Skills son el formato de nueva generación para comandos personalizados, que reemplaza a la versión anterior.claude/commands/. Ambos formatos funcionan correctamente, pero en proyectos nuevos se recomienda usar Skills directamente.

Comparación entre Skills y Commands

Característica Skills (recomendado) Commands (formato antiguo)
Ruta de almacenamiento .claude/skills/<名称>/SKILL.md .claude/commands/<名称>.md
Forma de activación /名称Activación manual, o activación automática por Claude según la descripción /名称(solo activación manual)
Soporte multiarchivo Admite plantillas, ejemplos y scripts auxiliares adjuntos Archivo único
Activación automática por Claude Claude decide inteligentemente si invocarlo según la description
Estándar Agent Skills Cumple con estándares abiertos; se puede compartir entre herramientas

Pasos para crear un Skill

Paso 1: crear la estructura de directorios

Los Skills personalizados se dividen en dos tipos, con diferentes ubicaciones de almacenamiento:

  • Skill de proyecto: solo es efectivo en el proyecto actual, compartido por el equipo → directorio:.claude/skills/<名称>/
  • Skill personal: común a todos los proyectos, para uso propio → directorio:~/.claude/skills/<名称>/
# 创建项目级 Skill（团队共享，纳入 git）
mkdir -p .claude/skills/optimize

# 创建个人级 Skill（跨项目通用，本地私有）
mkdir -p ~/.claude/skills/fix-bug

Paso 2: escribir SKILL.md

Crear un nuevoSKILL.mdarchivo: escribir la configuración en el frontmatter YAML y el prompt en el cuerpo de Markdown de abajo.nameEl campo define el nombre del comando de activación.

Ejemplo: crear un Skill de optimización del rendimiento de código

---
name: optimize
description: 分析代码性能瓶颈，给出优化建议。当用户提到性能问题时自动触发。
allowed-tools: Read, Grep, Glob
argument-hint: [目标文件或目录]
model: claude-sonnet-4-6
---

分析以下代码的性能瓶颈，给出具体的优化建议，优先考虑时间复杂度和内存占用：
$ARGUMENTS

Para usarlo, ingresa:

/optimize src/utils/data-processor.ts

Organización de espacios de nombres en subdirectorios

Se puede.claude/skills/organizar en subdirectorios según la función; el nombre del directorio es el nombre del comando:

.claude/skills/
├── optimize/            → /optimize
│   ├── SKILL.md
│   └── examples/        # 可选：示例文件辅助 Claude 理解
├── debug/               → /debug
│   ├── SKILL.md
│   └── scripts/         # 可选：辅助脚本
└── commit/              → /commit
    └── SKILL.md

5. Comandos de barra diagonal personalizados (formato antiguo, compatible)

Si hayprompts que se reutilizan(por ejemplo, requisitos fijos de revisión de código o plantillas de instrucciones repetitivas), puedes convertirlos en comandos personalizados e invocarlos con un solo clic.

Ubicación de almacenamiento de los archivos de comandos:

Alcance Ruta de almacenamiento Forma de compartir Casos de uso
Nivel de proyecto .claude/commands/<命令名>.md Incluido en git, compartido por el equipo Flujos de trabajo exclusivos del proyecto (como generación de código para un framework específico)
Nivel personal ~/.claude/commands/<命令名>.md Privado local Hábitos generales de desarrollo (como la revisión del estilo de código personal)

Sintaxis de parámetros:

Sintaxis Descripción Ejemplo de archivo de comando Ejemplo de invocación
$ARGUMENTS Capturar todo el contenido después del nombre del comando 分析并修复：$ARGUMENTS /fix 登录接口返回 500，见 logs/error.log
$1 $2 Parámetros posicionales separados por espacios 修复 Issue #$1，优先级 $2 /fix-issue 42 high
!`cmd` Ejecutar comandos Shell e incrustar la salida en el Prompt !`git diff HEAD` Expandir automáticamente al resultado de la ejecución del comando
@文件路径 Inyectar el contenido de un archivo en el Prompt 审查 @src/utils/helpers.ts Leer automáticamente el contenido del archivo

Principio fundamental

Los comandos personalizados son esencialmentearchivos de texto Markdown—el nombre del archivo es el nombre del comando, el contenido del archivo es el prompt que se ejecutará; admite pasar parámetros y llamar comandos Bash.

Pasos para crear comandos personalizados

Paso 1: Crear el directorio de almacenamiento de comandos

Hay dos tipos de comandos personalizados, con ubicaciones de almacenamiento diferentes:

  • Comandos de proyecto: solo efectivos en el proyecto actual, compartidos por el equipo → Directorio:.claude/commands/
  • Comandos personales: comunes a todos los proyectos, de uso personal → Directorio:~/.claude/commands/

Tomando como ejemplo la creación de un comando de proyecto, primero cree el directorio:

# 在项目根目录执行
mkdir -p .claude/commands

Paso 2: Escribir el archivo de comando Markdown

Cree un.mdarchivo; el nombre del archivo es el nombre del comando (por ejemplooptimize.md→ comando/optimize), y escriba el prompt en el contenido del archivo.

Ejemplo: Crear un comando de optimización de rendimiento de código

# 写入提示词到文件
echo "分析这段代码的性能瓶颈，给出具体的优化建议，优先考虑时间复杂度和内存占用：" > .claude/commands/optimize.md

Ahora, en la sesión, escriba/optimize, luego pegue el código, ¡y Claude hará el análisis de rendimiento según lo que pidió!

Truco avanzado: añadir parámetros a los comandos

Los comandos pueden llevar parámetros, usando$ARGUMENTS(captura todos los parámetros) o$1 $2(toma parámetros por posición).

Ejemplo: Comando de corrección de bugs con parámetros

Cree el archivo de comando.claude/commands/fix-issue.md：

修复 Issue #$ARGUMENTS，要求：
1. 符合项目编码规范
2. 附上测试用例
3. 说明修复思路

Uso del comando:

/fix-issue 123  # $ARGUMENTS 会被替换成 "123"

6. Referencia de campos de Frontmatter

Tanto en los archivos de comando personalizados (commands/*.md) como en Skills (skills/*/SKILL.md) se puede agregar YAML Frontmatter en la parte superior para una configuración precisa:

---
name: commit                          # Skills 中必填；命令文件中可选（默认取文件名）
allowed-tools: Bash(git add:*), Bash(git commit:*), Read, Edit
argument-hint: [commit-message]
description: 检查代码质量后提交
model: claude-haiku-4-5-20251001
context: fork
agent: general-purpose
disable-model-invocation: false
user-invocable: true
hooks:
  PreToolUse:
    - matcher: "Bash"
      hooks:
        - type: command
          command: "./scripts/validate.sh"
          once: true
---

Descripción de los campos

Campo Tipo Obligatorio Descripción
name string Obligatorio para Skills Define el nombre del comando de activación (/name); los archivos de comando usan por defecto el nombre del archivo
allowed-tools string 否 Herramientas que el comando puede utilizar; las herramientas coincidentes no requieren confirmación manual cada vez
argument-hint string 否 在 /helpSugerencia de formato de parámetros mostrada en la lista, como[message]
description string 否 Descripción de la función del comando, mostrada en la/help 和 /skillslista; en Skills también se usa para que Claude determine si debe activarse automáticamente
model string 否 Forzar la especificación del modelo; en tareas simples se puede usar Haiku para reducir costos
context enum 否 fork: ejecutar como subagente independiente;inline: ejecutar en la sesión actual
agent string 否 context: forkcuando se especifica el tipo de agente
disable-model-invocation bool 否 为 truecuando se prohíbe la invocación programática de este comando a través de la herramienta Skill
user-invocable NEW bool 否 为 falsecuando solo se permite la activación automática por Claude, y el usuario no puede hacerlo manualmente/调用
hooks object 否 Hooks de ciclo de vida durante la ejecución del comando

7. Comandos de plugins y MCP

Además de escribirlos tú mismo, también puedes obtener más comandos de extensión a través deplugins和 servidores MCP.

Formato de nomenclatura:

/mcp__<服务器名>__<命令名> [参数]

Ejemplos de comandos MCP de uso común

Servidor MCP Ejemplo de comando Función
GitHub /mcp__github__list_prs Listar los PR del repositorio actual
GitHub /mcp__github__create_issue "Bug标题" high Crear Issue
PostgreSQL /mcp__postgres__query "SELECT * FROM users LIMIT 10" Ejecutar consulta SQL
Slack /mcp__slack__send_message "#dev" "部署完成" Enviar mensaje de Slack
Jira /mcp__jira__create_issue "修复登录Bug" high Crear ticket de Jira
Figma /mcp__figma__get_component "Button" Obtener información de componentes de Figma

Ver todos los comandos MCP disponibles:/help(Los comandos MCP se muestran en un grupo separado al final de la lista de ayuda)

1. Comandos de plugins

Después de instalar un plugin de Claude Code, se agregan automáticamente comandos exclusivos del plugin, normalmente con el formato:

/plugin-name:command-name  # 避免命令名冲突

Por ejemplo, después de instalar el plugin de Git, podría haber un/git:commitcomando para generar mensajes de commit estandarizados con un solo clic.

2. Comandos MCP

Los servidores MCP (Protocolo de Contexto del Modelo) pueden convertir las funciones de herramientas externas (como GitHub, Jira) en comandos de barra, formato:

/mcp__<服务器名>__<功能名> [参数]

Ejemplo:

/mcp__github__list_prs  # 列出 GitHub 仓库的 PR
/mcp__jira__create_issue "登录按钮失效" high  # 在 Jira 创建高优先级问题

<!-- .claude/commands/security-scan.md -->

以安全工程师视角审查代码库：

高危：SQL 注入、XSS、命令注入、硬编码密钥
中危：不安全的反序列化、过时依赖、敏感信息写入日志、CORS 配置过宽

输出格式：漏洞位置 + 危险级别 + 修复建议代码示例

Refactorización de código:

<!-- .claude/commands/refactor.md -->
---
allowed-tools: Read, Edit, Glob
argument-hint: [目标文件或目录]
description: 代码质量重构
---

对 $ARGUMENTS 进行重构，遵循原则：
- 可读性：变量/函数命名语义化，消除魔法数字
- DRY 原则：提取重复逻辑为复用函数
- 单一职责：拆分超过 50 行的函数
- 错误处理：完善异常捕获和错误边界
- TypeScript：消除 `any` 类型，补全类型注解

重构前先输出变更计划，确认后再执行。

Verificación de enlaces de documentación:

<!-- .claude/commands/check-links.md -->
---
allowed-tools: Read, Bash, WebFetch
argument-hint: [文档文件路径]
description: 检查文档中的链接是否全部有效
model: claude-haiku-4-5-20251001
---

读取 $ARGUMENTS 文件，提取所有超链接（http/https），逐一请求并检查响应状态码。

输出格式：
- 有效链接（200）
- 重定向链接（3xx）及目标地址

最后输出汇总：共 N 个链接，M 个失效。
