Claude Code Flujo de trabajo de Git

Claude Code se integra profundamente con las funciones de Git, lo que permite realizar casi todas las operaciones de Git mediante lenguaje natural, incluida la creación de commits, la gestión de ramas, el manejo de conflictos de fusión y el uso de Git Worktree para flujos de trabajo paralelos. Este capítulo detalla cómo utilizar Git de manera eficiente en Claude Code.

Operaciones básicas de Git

1. Ver los cambios

Puedes obtener el estado de Git simplemente preguntando en lenguaje natural:

我改了哪些文件？
这次的改动有哪些内容？
最近 10 次提交都改了什么？
检查一下当前的 git 状态

Claude ejecutará automáticamente los comandos de Git correspondientes y mostrará los resultados.

2. Hacer commit del código

Commit simple:

提交这次的改动
把这次的修改提交

Commit con descripción:

把这次的修改提交，commit 信息说明修复了登录验证的 bug

Claude generará automáticamente mensajes de commit que cumplen con las convenciones según el contenido real de los cambios.

3. Gestión de ramas

新建一个 feature/user-profile 分支
切换到 develop 分支
把 main 分支的最新改动合并进来
查看所有分支
删除已合并的分支

Manejo de conflictos de fusión

1. Resolver automáticamente conflictos simples

帮我解决合并冲突
这个文件有冲突，帮我看看哪个版本是正确的

Claude analizará el contenido del conflicto y elegirá la versión adecuada o propondrá una solución según el contexto del proyecto.

2. Intervención manual para resolver conflictos complejos

Cuando el conflicto es demasiado complejo, Claude te explicará las ventajas y desventajas de cada opción:

这个冲突涉及架构设计，你来决定保留哪个方案：
A. 保留我们的实现...
B. 保留引入的优化...

Claude Code muestra los cambios y solicita tu confirmación antes de realizar cualquier modificación de archivos. Para operaciones de alto riesgo como los conflictos de fusión, se deben revisar cuidadosamente cada modificación.

Flujo de trabajo paralelo con Git Worktree

Git Worktree te permite trabajar en diferentes ramas al mismo tiempo en distintos directorios, sin necesidad de cambiar de rama ni clonar el repositorio. Es una de las formas más potentes de trabajo paralelo en Claude Code.

1. Crear un Worktree con Claude

Especificar un worktree al iniciar Claude:

claude --worktree feature-auth

Esto automáticamente:

  • 在 .claude/worktrees/feature-auth/Creará un nuevo directorio
  • Basado enorigin/HEAD(la rama predeterminada remota), creará una nueva rama
  • Iniciará una sesión independiente de Claude en el nuevo directorio

Abrir varios worktrees a la vez:

claude --worktree bugfix-123
claude --worktree

Cuando no se especifica un nombre, Claude generará automáticamente nombres interesantes (comobright-running-fox）。

2. Propiedades del Worktree

Propiedad 值
Ubicación <repo>/.claude/worktrees/<name>
Nomenclatura de ramas worktree-<name>
Rama base Remotoorigin/HEADRama a la que apunta

3. Ciclo de vida del Worktree

Escenario Comportamiento
No se han realizado cambios El Worktree y la rama se eliminan automáticamente
Existen cambios o commits Claude te pide que elijas entre conservar o eliminar
Worktree huérfano debido a un fallo de Claude Después de superarcleanupPeriodDayslos días configurados, se elimina automáticamente

4. Copiar archivos .gitignore al Worktree

Crear en el directorio raíz del proyecto.worktreeincludeun archivo que especifica qué archivos gitignore deben copiarse al worktree:

.env
.env.local
config/secrets.json

Solo los archivos que coinciden con un patrón且ignorado por gitignore se copiarán.

5. Gestión manual del Worktree

Si necesitas más control, puedes gestionarlo manualmente:

# 创建 worktree 并指定分支
git worktree add ../project-feature-a -b feature-a

# 使用已有分支创建 worktree
git worktree add ../project-bugfix bugfix-123

# 在 worktree 中启动 Claude
cd ../project-feature-a && claude

# 完成后清理
git worktree list
git worktree remove ../project-feature-a

Se recomienda.claude/worktrees/añadir a.gitignore, para evitar que el contenido del worktree aparezca como archivos sin seguimiento en el repositorio principal.

Aislamiento de Worktree para subagentes

Los subagentes pueden utilizar la función de aislamiento de worktree para lograr un trabajo paralelo completamente independiente:

Opción 1: Dejar que Claude lo maneje automáticamente

让子代理使用 worktree 来并行处理这些任务

Opción 2: Especificar en la configuración del subagente

Ejemplo

---
name: experimental-refactor
description: Probar un enfoque de refactorización en un worktree aislado
isolation: worktree    # Ejecutar en un worktree temporal
tools: Read, Write, Edit, Bash
---

Puedes modificar libremente en el entorno aislado sin afectar la rama principal.
Al finalizar, resume los cambios y si el plan ha sido exitoso.

Características del Worktree de subagentes

  • Cada subagente obtiene automáticamente un worktree independiente
  • El worktree se limpia automáticamente al completar la tarea
  • Los cambios no afectan al repositorio principal
  • Ideal para tareas exploratorias y comparación de enfoques

Flujo de trabajo de Pull Request

1. Pasos para crear un PR

Paso 1: Pedir a Claude que resuma los cambios

总结一下我对认证模块做的改动

Paso 2: Generar el PR

创建一个 PR

Paso 3: Completar la descripción del PR

在 PR 描述中补充更多关于安全改进的内容

2. Asociación de sesiones de PR

Usargh pr createAl crear un PR, la sesión de Claude se asocia automáticamente a ese PR:

  • Una vez que la sesión está vinculada al PR, se puede reanudar la conversación desde el PR
  • Usarclaude --from-pr <number>para restaurar la sesión asociada

3. Usar GitHub CLI

Claude sabe cómo usar laghherramienta CLI. Si no está instalada,ghClaude puede leer y escribir en la API de GitHub, pero con funcionalidad limitada.

# Claude 可以执行的操作
gh pr create --title "Fix login bug"
gh pr view --comments
gh pr diff
gh issue create --title "Bug report"

Gestión de sesiones e integración con Git

1. Restaurar sesiones anteriores

Comando Función
claude --continue Continuar la conversación más reciente del directorio actual
claude --resume Abrir el selector de sesiones o restaurar por nombre
claude --from-pr 123 Restaurar la sesión asociada a un PR específico

2. Funciones de Git del selector de sesiones

Atajo de teclado Función
B Filtrar las sesiones de la rama git actual

3. Visualización de metadatos de sesión

El selector de sesiones muestra la siguiente información:

  • Nombre de la sesión o prompt inicial
  • Tiempo transcurrido desde la última actividad
  • Número de mensajes
  • Rama de Git (si existe)

4. Sesiones de rama

Usar/branch、/rewind 或 --fork-sessionLas sesiones creadas se agrupan bajo la sesión raíz para facilitar su gestión.

Modo de planificación y análisis seguro

El modo de planificación (Plan Mode) utiliza operaciones de solo lectura para analizar el código de forma segura, sin ejecutar ninguna operación de escritura.

Iniciar el modo de planificación

claude --permission-mode plan

O ejecutar una consulta puntual en la sesión:

claude --permission-mode plan -p "分析认证系统并提出改进建议"

Configurar el modo predeterminado en settings.json

Ejemplo

{
  "permissions": {
    "defaultMode": "plan"
  }
}

Ejemplos de flujos de trabajo típicos

Flujo de trabajo 1: Desarrollo paralelo de múltiples tareas

# 场景：同时开发三个功能，但不想切换分支

> 启动三个 worktree，分别处理登录重构、支付集成和性能优化
> 在每个 worktree 中独立工作，完成后合并到主分支

Flujo de trabajo 2: Proceso de corrección de errores

# 第一步：描述问题
> 用户反馈：用户登出后刷新页面仍然显示已登录

# 第二步：创建修复分支
> 创建一个 bugfix/session-cookie 分支来修复这个问题

# 第三步：分析与修复
> 先分析可能的原因，在 bugfix 分支中修复

# 第四步：提交并创建 PR
> 提交修复并创建一个 PR

Flujo de trabajo 3: Revisión de código

# 审查特定文件
> 帮我审查 src/payment/processor.ts，重点关注错误处理

# 审查 git 改动
> 审查我这次的所有改动，看看有没有明显的问题

# 在独立分支中审查
> 创建一个 worktree 来审查这个重构方案

Flujo de trabajo 4: Desarrollo y validación de funciones

# 主会话：实现新功能
> 实现用户资料编辑功能

# 子代理：并行运行测试
> 在子代理中运行所有测试，只返回失败的测试和根因

# 子代理：检查代码规范
> 使用子代理审查代码是否符合项目规范

# 完成后：创建 PR
> 创建一个 PR 并添加详细的描述

Sistemas de control de versiones distintos de Git

Para usuarios de SVN, Perforce o Mercurial, Claude Code admite extensión mediante hooks:

Configurar hooks personalizados

在 .claude/settings.jsonse configura en:

Ejemplo

{
  "hooks": {
    "WorktreeCreate": "./scripts/create-worktree.sh",
    "WorktreeRemove": "./scripts/remove-worktree.sh"
  }
}

Estos hooks reemplazan el comportamiento predeterminado de git. Al usar scripts de hook, copie el archivo de configuración local dentro del script, en lugar de usar.worktreeinclude。

Mejores prácticas del equipo interno de Anthropic

  • Múltiples worktrees: ejecutar 3-5 worktrees de git simultáneamente, cada uno con una sesión independiente, es una práctica recomendada reconocida por el equipo para mejorar la eficiencia
  • Planificar tareas complejas primero: usarplanmodo para que un Claude escriba el plan y otro actúe como asesor para revisarlo
  • Actualizar CLAUDE.md después de errores: después de cada corrección, añade "actualiza tu CLAUDE.md, no vuelvas a cometer el mismo error"
  • Entrar específicamente al modo de planificación para la fase de verificación: asegurar que el proceso de verificación sea seguro y controlable

Preguntas frecuentes

P: ¿Cuál es la diferencia entre Worktree y rama?

Worktree es un directorio independiente donde puedes trabajar en diferentes directorios al mismo tiempo; la rama es un historial de confirmaciones diferente dentro del mismo directorio. Worktree es más adecuado para escenarios donde necesitas manejar múltiples tareas complejas simultáneamente.

P: ¿Los worktrees creados por Claude afectan al repositorio principal?

No. Los worktrees tienen directorios independientes, su contenido no afecta los cambios no confirmados del repositorio principal.

P: ¿Cómo hago que Claude trabaje en una rama específica?

Cambia de rama primero y luego inicia Claude, o usaclaude --worktree <name>crear rama automáticamente.

P: ¿Demasiados worktrees ocupan demasiado espacio?

Git Worktree comparte el historial del repositorio, el nuevo directorio solo contiene las diferencias de la rama, por lo que ocupa muy poco espacio.

P: ¿Cuándo se limpian los worktrees de los subagentes?

Cuando se completan normalmente, Claude te pedirá que elijas conservarlos o eliminarlos. Los worktrees huérfanos por fallos se eliminarán automáticamente después decleanupPeriodDayslos días configurados.
