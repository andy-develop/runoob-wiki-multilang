Gestión del contexto de Claude Code

Guía de uso de CLAUDE.md

CLAUDE.mdEs el archivo de configuración más importante en Claude Code, utilizado para transmitir instrucciones persistentes a nivel de proyecto a Claude. Cada vez que se inicia una sesión de Claude Code, este lee y carga automáticamente el contenido de este archivo, integrándolo en cada conversación como contexto a nivel de sistema.

En términos sencillos,CLAUDE.mdes un manual de trabajo que le escribes a Claude en el proyecto: le indicas qué es este proyecto, qué normas seguir y qué precauciones hay, para que cada vez pueda trabajar de acuerdo con los requisitos del proyecto, en lugar de tener que volver a explicarlo en cada conversación.

La función de CLAUDE.md

SinCLAUDE.mdCLAUDE.md, Claude entiende tu proyecto desde cero cada vez; tienes que repetirle: qué gestor de paquetes usar, cuál es el estilo de código, cómo ejecutar las pruebas, qué archivos no tocar... ConCLAUDE.mdCLAUDE.md, esta información solo se escribe una vez y Claude la cumplirá cada vez.

En concreto,CLAUDE.mdCLAUDE.md puede ayudarte a lograr lo siguiente:

  • Unificar el comportamiento del equipo: envía el archivo a git y todos los miembros del equipo seguirán las mismas normas al usar Claude Code.
  • Reducir la comunicación repetitiva: las convenciones del proyecto, las reglas de arquitectura y los asuntos prohibidos se escriben una sola vez y tienen efecto permanente.
  • Reducir la probabilidad de errores: indícale claramente a Claude qué operaciones son arriesgadas para evitar que tome decisiones incorrectas.
  • Acelerar la comprensión de la IA: ayuda a Claude a localizar rápidamente archivos clave y comprender la estructura del proyecto, reduciendo exploraciones innecesarias de archivos.

Ubicación del archivo

Claude Code cargará CLAUDE.md desde varias ubicacionesCLAUDE.md: los archivos en diferentes ubicaciones tienen distintos alcances:

Ubicación Ruta Alcance ¿Enviar a git?
Directorio raíz del proyecto {项目根目录}/CLAUDE.md Todas las sesiones del proyecto actual ✅ Recomendado enviar, compartido por el equipo
Local del proyecto {项目根目录}/.claude/CLAUDE.md Todas las sesiones del proyecto actual ❌ Añadir a .gitignore, solo uso personal
Subdirectorio {任意子目录}/CLAUDE.md Se carga automáticamente cuando Claude abre archivos en ese directorio ✅ Adecuado para repositorios multimódulo
Nivel global de usuario ~/.claude/CLAUDE.md Todos los proyectos del usuario actual ❌ Configuración personal, no se envía

Cuando existen múltiples ubicacionesCLAUDE.mdcon CLAUDE.md, Claude Code lascargará y fusionará todas. La prioridad, de mayor a menor, es:

项目本地 → 项目根目录 → 子目录 → 全局用户级

La del directorio raíz del proyectoCLAUDE.mdSe recomienda enviarla a git para que todo el equipo comparta el mismo conjunto de normas de trabajo con IA.

Las preferencias personales (como no gustar los puntos y comas) se colocan en.claude/CLAUDE.mdCLAUDE.md local y se añaden a.gitignore.gitignore, sin afectar a los demás.

Crear CLAUDE.md rápidamente

La forma más sencilla es dejar que Claude Code genere automáticamente la versión inicial. Después de iniciar Claude Code en el directorio del proyecto, ejecuta:

/init

Claude Code analizará la estructura de tu proyecto, el estilo de código y los archivos de configuración existentes (comopackage.json、pyproject.toml、.eslintrcpackage.json, etc.) y generará automáticamente un CLAUDE.md acorde con la situación real del proyecto,CLAUDE.mdy luego puedes complementarlo y ajustarlo sobre esa base.

También puedes crearlo manualmente en el directorio del proyecto:

touch CLAUDE.md

Estructura del contenido del archivo

CLAUDE.mdCLAUDE.md es un archivo Markdown normal, sin requisitos de formato obligatorios, pero una buena estructura ayuda a Claude a encontrar información clave más rápido. A continuación se muestra la estructura de contenido recomendada:

# 项目名称

一句话说明这个项目是什么，方便 Claude 快速定位项目性质。

## 技术栈
- 语言：Python 3.11
- 框架：FastAPI 0.110
- 数据库：PostgreSQL 15 + SQLAlchemy ORM
- 测试：pytest

## 常用命令

### 开发
```bash
uv run uvicorn main:app --reload   # 启动开发服务器
```


3. Normas de codificación

Informa a Claude sobre el estilo de código y las convenciones del proyecto, asegurando que el código generado sea coherente con la base de código existente:

## 编码规范

### 通用
- 文件名使用 kebab-case（如 `user-profile.ts`），类名使用 PascalCase
- 优先使用具名导出（named export），避免默认导出（default export）
- 异步函数一律使用 async/await，禁止使用 .then() 链式调用

### 组件规范
- 组件文件与其测试文件放在同一目录（如 `Button.tsx` 和 `Button.test.tsx`）
- Props 类型使用 interface 定义，命名格式为 `${组件名}Props`
- 不要将业务逻辑写在组件中，提取为自定义 Hook 或 Service

### 错误处理
- API 路由使用统一的错误响应格式：`{ error: string, code: string }`
- 客户端错误通过 Error Boundary 捕获，不要在每个组件里单独 try/catch

4. Restricciones de arquitectura y asuntos prohibidos

Esta es la parte clave para evitar que Claude tome decisiones "inteligentes pero incorrectas". Las situaciones especiales que tú conoces pero Claude desconoce deben escribirse explícitamente:

## 架构约束

- 所有数据库查询必须通过 `src/lib/db/queries/` 中的函数执行，不要在路由或组件中直接写 SQL
- 状态管理使用 Zustand，不要引入 Redux 或其他状态管理库
- 样式使用 Tailwind CSS utility class，不要新增 CSS 文件或使用 CSS Modules

## 注意事项（重要）

- `legacy/` 目录下的代码是遗留代码，**禁止修改**，只能读取
- `.env.local` 和 `.env.production` 包含真实密钥，**禁止输出文件内容**
- `prisma/migrations/` 中已有的迁移文件**禁止修改**，数据库变更只能新增迁移
- 修改 `src/middleware.ts` 前必须先告知我，该文件影响所有路由的认证逻辑

Sugerencias para el mantenimiento de CLAUDE.md

1. Mantener la concisión

CLAUDE.mdEl contenido de CLAUDE.md ocupa la ventana de contexto en cada sesión. Un contenido excesivo comprimirá el espacio de contexto realmente disponible para Claude, reduciendo la eficiencia. Se recomienda seguir los siguientes principios:

  • Escribe cada regla solo una vez; no repitas el mismo significado
  • No incluyas información de fondo no relacionada con el código (como presentaciones de la empresa o planificación de productos)
  • La información que puede transmitirse mediante el propio código (como la configuración de eslint que ya define el estilo de código) no necesita declararse enCLAUDE.mdCLAUDE.md repetidamente.
  • Se recomienda mantener el total en menos de 500 caracteres; si supera los 1000, es necesario considerar simplificarlo.

2. Actualización continua

Con la evolución del proyecto,CLAUDE.mdCLAUDE.md también debe actualizarse. Las siguientes situaciones deberían provocar una actualización:

  • Cambio de gestor de paquetes o herramienta de compilación
  • Adición o eliminación de bibliotecas de dependencias importantes
  • Adopción de nuevas convenciones de codificación
  • Descubrir que Claude comete repetidamente el mismo tipo de error (indica que es necesario añadir una aclaración enCLAUDE.mdCLAUDE.md)
  • Algún archivo o módulo se vuelve no modificable al azar (añádalo a las notas de precaución)

3. Usar lenguaje imperativo

Cuanto más claras sean las instrucciones, mayor será la probabilidad de que Claude las cumpla. Evita descripciones vagas y usa órdenes directas:

❌ Descripción vaga ✅ Instrucción clara
El código debería estar bastante ordenado Las funciones no superan las 50 líneas; si lo superan, deben dividirse
Intenta escribir pruebas Cada función nueva debe tener su prueba unitaria correspondiente
Presta atención a la seguridad La entrada del usuario debe procesarse con la funciónsanitize()antes de poder pasarse a las consultas de base de datos.
El directorio legacy no es muy importante Prohibido modificarlegacy/cualquier archivo en el directorio
Es mejor usar pnpm Para la gestión de dependencias usa solo pnpm; prohibido usar npm o yarn

# MyApp — Panel de administración de comercio electrónico

Basado en Next.js 14 App Router + Prisma +Sistema de gestión de comercio electrónico con PostgreSQL.

## Stack tecnológico
-Frontend: Next.js 14（App Router）、TypeScript、Tailwind CSS、shadcn/ui
-Backend: Next.js API Routes、Prisma ORM
-Base de datos: PostgreSQL15
-Autenticación: NextAuth.js v5
-Gestión de paquetes: pnpm

## Comandos comunes

```bash
pnpm dev # Iniciar servidor de desarrollo (puerto3000）
pnpm build &&pnpm start # Compilar e iniciar servidor de producción
pnpm test # Ejecutar todas las pruebas
pnpm test:e2e # Ejecutar pruebas de extremo a extremo (requiere iniciar dev server primero)
pnpm db:migrate # Ejecutar migraciones de base de datos
pnpm db:studio # Abrir Prisma Studio (herramienta de visualización de base de datos)
pnpm lint &&pnpm typecheck # Revisión de código y verificación de tipos
```

## Estructura del proyecto

- `src/app/` — Páginas del App Router y rutas de API
- `src/app/(dashboard)/` — Páginas de administración que requieren inicio de sesión
- `src/app/api/` — Rutas de API (estilo RESTful)
- `src/components/` — Componentes reutilizables
- `src/lib/` — Funciones de utilidad, cliente de base de datos, configuración de autenticación
- `prisma/schema.prisma` — Definición del Schema de la base de datos

## Estándares de codificación

-Usar solo exportaciones nombradas (namedexport), prohibidodefault export(excepto Next.jsarchivos de página)
-Los componentes de servidor son async por defecto; los componentes de cliente agregan ` en la parte superior del archivo"use client"`
-Formato de respuesta unificado para rutas de API: éxito `{ data: T }`, error `{ error: string, code: string }`
-Las consultas de base de datos se encapsulan en `src/lib/db/` directorio; no usar el cliente `prisma` directamente en otros lugares

## Precauciones

- `prisma/migrations/Archivos existentes en `**Prohibido modificar**, los cambios de base de datos solo se pueden realizar ejecutando `pnpm db:migrate` para nuevas migraciones
- `.env.local` contiene claves reales,**prohibido leer o mostrar el contenido del archivo**
- `src/lib/auth.ts` es el archivo principal de autenticación,**debes informarme antes de modificarlo**
-Al modificar `prisma/schema.prisma`, se debe ejecutar `pnpm db:migrate` y enviar los archivos de migración

Preguntas frecuentes

P: ¿Qué hacer si Claude no sigue las reglas en CLAUDE.md?

Primero verifica si la redacción de la regla es lo suficientemente clara (consulta la sugerencia anterior sobre "usar lenguaje imperativo"). Si la redacción ya es clara pero aún así no la sigue, puedes enfatizarla nuevamente en la conversación específica, o colocar la regla en una posición más adelantada del archivo: Claude presta más atención al contenido de la primera mitad del archivo.

P: ¿Es mejor que CLAUDE.md sea más largo?

No. Demasiado contenido tiene dos efectos secundarios: primero, ocupa la ventana de contexto, reduciendo el espacio de Claude para procesar tareas reales; segundo, las reglas importantes se pierden entre mucho texto y son menos propensas a cumplirse. Se recomienda revisar periódicamente y eliminar las entradas que ya no sean aplicables o tengan poco valor.

P: ¿Cuándo se carga el CLAUDE.md de un subdirectorio?

Cuando Claude abre o edita un archivo en ese subdirectorio, elCLAUDE.mdCLAUDE.md de ese subdirectorio se carga automáticamente. No necesitas decirle manualmente a Claude que lo lea; todo el proceso es automático.

P: ¿Se puede hacer referencia a otro CLAUDE.md dentro de un CLAUDE.md?

No se puede hacer referencia directa, pero puedes usar la sintaxis@文件路径para hacer referencia al contenido de cualquier archivo Markdown. Si hay estándares compartidos entre módulos, se recomienda extraerlos a un documento independiente y luego en cadaCLAUDE.mduno usar@para referenciarlo.
