Sintaxis básica de Dart

Cada lenguaje de programación tiene su propio conjunto de reglas básicas, y Dart no es una excepción.

Este capítulo presenta la estructura básica de un programa Dart, la sintaxis de comentarios, la diferencia entre sentencias y expresiones, y las reglas de nomenclatura de identificadores.

Estructura del programa y la función main()

La extensión de los archivos Dart es.dartCada programa Dart debe tener un punto de entrada: la función main().

El programa comienza a ejecutarse desde la primera línea de la función main() y termina en la llave de la última línea.

Ejemplo

La estructura de un programa Dart mínimo:

// Punto de entrada: la función main() es el punto de partida de un programa Dart
void main() {
  // Escribe tu código aquí
  print('¡Bienvenido al tutorial de RUNOOB Dart!');
}

Desglosemos cada parte de este código:

Elemento de códigoDescripción
voidTipo de retorno; void indica que la función no devuelve ningún valor
mainNombre de la función; este es el nombre de la función de entrada definido por Dart y no se puede cambiar
()Lista de parámetros; main() puede no recibir parámetros, o puede recibir argumentos de línea de comandos
{ }Cuerpo de la función; el código entre llaves es lo que ejecuta la función
print()Función incorporada, se utiliza para mostrar texto en la consola
;Terminador de sentencia; en Dart, cada sentencia debe terminar con un punto y coma

Dart exige estrictamente que cada sentencia termine con un punto y coma (;). Olvidar el punto y coma es el error de sintaxis más común entre los principiantes. Afortunadamente, el complemento Dart de VS Code avisa automáticamente dónde falta el punto y coma.

La función main() con argumentos de línea de comandos

La función main() puede recibir una lista de cadenas como argumentos de línea de comandos:

Ejemplo

// List<String> args recibe la lista de argumentos pasados desde la línea de comandos
void main(List<String> args) {
  // Muestra el número de argumentos
  print('Número de argumentos: ${args.length}');

  // Itera e imprime cada argumento
  for (var i = 0; i &lt; args.length; i++) {
    print('Argumento $i: ${args[i]}');
  }
}

Sintaxis de comentarios

Los comentarios son explicaciones del código; el compilador ignora su contenido.

Un buen comentario permite que otros (incluido tu yo de meses después) comprendan más rápido la intención del código.

Dart admite tres tipos de comentarios:

TipoSintaxisCaso de uso
Comentario de una línea// contenido del comentarioExplicación breve de la función de una línea de código
Comentario de varias líneas/* contenido del comentario */Explicación detallada en varias líneas
Comentario de documentación/// comentario de documentaciónGenera documentación de API para funciones y clases

Ejemplo

/// Este es un comentario de documentación que describe la funcionalidad del programa
/// Los comentarios de documentación pueden generar documentación HTML con el comando [dart doc]
void main() {
  // Comentario de una línea: muestra un mensaje de bienvenida
  print('¡Bienvenido a aprender Dart!'); // Comentario en línea: esto también es válido

  /*
* Comentario de varias líneas: adecuado para explicaciones largas
* Segunda línea del comentario
* Tercera línea del comentario
   */
  print('Tutorial RUNOOB - Sintaxis básica de Dart');
}

El principio de los comentarios es "explicar el porqué, no el qué". El código ya muestra qué hace; los comentarios deben explicar por qué se escribió así, o complementar información de contexto que el código no puede expresar.

Sentencias y expresiones

En Dart, el código se compone de sentencias (Statement) y expresiones (Expression).

Comprender la diferencia entre ambos te ayuda a organizar mejor la lógica del código.

Expresión (Expression)

Una expresión es un fragmento de código que puede evaluarse y produce un valor.

Ejemplo

void main() {
  // Cada una de las siguientes líneas es una expresión; todas producen un valor
  42;              // Expresión literal, valor 42
  3 + 5;           // Expresión aritmética, valor 8
  'Hello'.length;  // Expresión de acceso a propiedad, valor 5
  (10 > 5);        // Expresión relacional, valor true
}

Sentencia (Statement)

Una sentencia es una instrucción que ejecuta una acción; no produce un valor.

Ejemplo

void main() {
  // Sentencia de declaración de variable: declara una variable y le asigna un valor
  var name = 'RUNOOB';

  // Sentencia de llamada a función: llama a print() para ejecutar una acción de salida
  print(name);

  // Sentencia de control de flujo: decide qué código ejecutar según una condición
  if (name.length > 3) {
    print('La longitud del nombre es mayor que 3');
  }
}
RUNOOB
名称长度大于 3

En resumen:Las expresiones producen valores; las sentencias ejecutan acciones.

Puedes usar expresiones donde se necesita un valor, pero no puedes usar sentencias.

Un error común es tratar todo el código como "sentencias". En realidad, muchas construcciones en Dart (como las llamadas a funciones y la asignación de variables) son en sí mismas expresiones, lo que significa que se pueden anidar. Esta es una característica común de Dart y otros lenguajes de la familia C.

Reglas de nomenclatura de identificadores

Un identificador (Identifier) es el nombre que das a elementos de código como variables, funciones, clases, etc.

Dart tiene algunas reglas y convenciones para los identificadores:

Reglas de nomenclatura (obligatorias)

Los identificadores solo pueden estar compuestos por letras, números, guiones bajos (_) y el símbolo de dólar ($).

Los identificadores no pueden comenzar con un número.

Los identificadores no pueden ser palabras clave reservadas de Dart (como class, if, var, etc.).

Convenciones de nomenclatura (recomendadas)

Elemento de códigoEstilo de nomenclaturaEjemplo
Nombre de claseUpperCamelCaseStudentInfo、HttpClient
Tipo enumeradoUpperCamelCaseColor、Status
Nombre de librería, nombre de archivoMinúsculas con guiones bajos (lowercase_with_underscores)my_utils、user_service
Nombre de variablelowerCamelCaseuserName、maxCount
Nombre de funciónlowerCamelCasegetUserInfo()、calculateTotal()
Nombre de constantelowerCamelCasepiValue、defaultPort
Miembros privadosPrefijo de guion bajo_internalState、_privateMethod()

Ejemplo

Aplicación práctica de los distintos estilos de nomenclatura:

// Nombre de clase: UpperCamelCase
class UserAccount {
  // Miembros públicos: lowerCamelCase
  String userName;

  // Miembros privados: prefijo de guion bajo (solo accesibles dentro de este archivo)
  String _password;

  // Constructor
  UserAccount(this.userName, this._password);

  // Métodos públicos: lowerCamelCase
  bool verifyPassword(String input) {
    return input == _password;
  }

  // Métodos privados: prefijo de guion bajo
  void _encryptPassword() {
    // Lógica de cifrado...
  }
}

// Función de entrada: minúsculas
void main() {
  // Nombre de variable: lowerCamelCase
  var userAccount = UserAccount('runoob', '123456');

  // Constante: lowerCamelCase (estilo Dart)
  const maxLoginAttempts = 3;

  print('Nombre de usuario: ${userAccount.userName}');
  print('Número máximo de intentos de inicio de sesión: $maxLoginAttempts');
}
用户名: runoob
最大登录尝试次数: 3

En las convenciones de nomenclatura de Dart, las constantes usan lowerCamelCase, en lugar del estilo común en otros lenguajes de MAYÚSCULAS con guiones bajos (UPPER_CASE). Este es un estilo distintivo de la comunidad de Dart, tenlo en cuenta.
