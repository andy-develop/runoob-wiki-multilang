Programación CGI en Python

Qué es CGI

CGI es mantenido actualmente por NCSA, que define CGI de la siguiente manera:

CGI (Common Gateway Interface), Interfaz de Pasarela Común, es un programa que se ejecuta en un servidor, como un servidor HTTP, y proporciona una interfaz con páginas HTML del cliente.

Nota:

A partir de Python 3.11, el módulo cgi está oficialmente marcado como "obsoleto" (Deprecated) y se elimina a partir de Python 3.13.

Se recomienda migrar aFlask、Django 或 FastAPIy otros marcos web modernos.

Navegación web

Para comprender mejor cómo funciona CGI, podemos partir del proceso de hacer clic en un enlace o URL en una página web:

  • 1. Usa tu navegador para acceder a la URL y conectarte al servidor web HTTP.
  • 2. El servidor web recibe la información de la solicitud, analiza la URL y verifica si el archivo solicitado existe en el servidor. Si existe, devuelve el contenido del archivo; de lo contrario, devuelve un mensaje de error.
  • 3. El navegador recibe la información del servidor y muestra el archivo recibido o el mensaje de error.

Los programas CGI pueden ser scripts de Python, scripts de PERL, scripts de SHELL, programas en C o C++, etc.

Diagrama de arquitectura CGI

Soporte y configuración del servidor web

Antes de realizar programación CGI, asegúrate de que tu servidor web sea compatible con CGI y de que ya esté configurado el manejador de CGI.

Configuración de soporte CGI en Apache:

Establece el directorio CGI:

ScriptAlias /cgi-bin/ /var/www/cgi-bin/

Todos los programas CGI que ejecuta el servidor HTTP se guardan en un directorio preconfigurado. Este directorio se denomina directorio CGI y, por convención, se llama /var/www/cgi-bin.

La extensión de los archivos CGI es.cgi, Python también puede usar la extensión.pyla extensión.

Por defecto, el directorio cgi-bin configurado en el servidor Linux es /var/www.

Si deseas especificar otro directorio para ejecutar scripts CGI, puedes modificar el archivo de configuración httpd.conf, como se muestra a continuación:

<Directory "/var/www/cgi-bin">
   AllowOverride None
   Options +ExecCGI
   Order allow,deny
   Allow from all
</Directory>

Agrega la extensión .py en AddHandler para poder acceder a los archivos de scripts de Python que terminan en .py:

AddHandler cgi-script .cgi .pl .py

Primer programa CGI

Creamos el primer programa CGI con Python, con el nombre de archivo hello.py, ubicado en el directorio /var/www/cgi-bin, con el siguiente contenido:

#!/usr/bin/python
# -*- coding: UTF-8 -*-

print "Content-type:text/html"

Cabeceras HTTP

" Content-type:text/html" en el contenido del archivo hello.py es parte de la cabecera HTTP. Se envía al navegador para indicarle el tipo de contenido del archivo.

El formato de la cabecera HTTP es el siguiente:

HTTP 字段名: 字段内容

Por ejemplo:

Content-type: text/html

La siguiente tabla describe la información que se usa frecuentemente en las cabeceras HTTP en programas CGI:

头Descripción
Content-type: Información MIME de la solicitud correspondiente a la entidad. Por ejemplo: Content-type:text/html
Expires: Date Fecha y hora de caducidad de la respuesta
Location: URL Se utiliza para redirigir al receptor a una ubicación distinta de la URL solicitada para completar la solicitud o identificar un nuevo recurso
Last-modified: DateHora de última modificación del recurso solicitado
Content-length: NLongitud del contenido de la solicitud
Set-Cookie: String Configurar cookies HTTP

Variables de entorno CGI

Todos los programas CGI reciben las siguientes variables de entorno, que desempeñan un papel importante en los programas CGI:

Nombre de la variableDescripción
CONTENT_TYPEEl valor de esta variable de entorno indica el tipo MIME de la información transmitida. Actualmente, la variable de entorno CONTENT_TYPE suele ser: application/x-www-form-urlencoded, lo que significa que los datos provienen de un formulario HTML.
CONTENT_LENGTHSi la transferencia de información entre el servidor y el programa CGI es mediante POST, esta variable de entorno es el número de bytes de datos válidos que se pueden leer desde la entrada estándar STDIN. Esta variable de entorno debe usarse al leer los datos de entrada.
HTTP_COOKIEContenido de las cookies en el cliente.
HTTP_USER_AGENTProporciona información del navegador del cliente que incluye el número de versión u otros datos propietarios.
PATH_INFOEl valor de esta variable de entorno representa otra información de ruta que sigue inmediatamente al nombre del programa CGI. A menudo aparece como parámetro del programa CGI.
QUERY_STRINGSi la transferencia de información entre el servidor y el programa CGI es mediante GET, el valor de esta variable de entorno es la información transmitida. Esta información va después del nombre del programa CGI, separada por un signo de interrogación '?'.
REMOTE_ADDREl valor de esta variable de entorno es la dirección IP del cliente que envía la solicitud, por ejemplo, 192.168.1.67 de arriba. Este valor siempre está presente. Además, es el único identificador que el cliente web debe proporcionar al servidor web, y se puede usar en programas CGI para distinguir diferentes clientes web.
REMOTE_HOSTEl valor de esta variable de entorno contiene el nombre de host del cliente que envía la solicitud CGI. Si no se admite la consulta deseada, no es necesario definir esta variable de entorno.
REQUEST_METHODProporciona el método con el que se invoca el script. Para scripts que usan el protocolo HTTP/1.0, solo GET y POST tienen significado.
SCRIPT_FILENAMERuta completa del script CGI
SCRIPT_NAMENombre del script CGI
SERVER_NAMEEste es el nombre de host, alias o dirección IP de tu servidor web.
SERVER_SOFTWAREEl valor de esta variable de entorno contiene el nombre y el número de versión del servidor HTTP que invoca el programa CGI. Por ejemplo, el valor anterior es Apache/2.2.14(Unix).

Métodos GET y POST

El navegador cliente transmite información al servidor mediante dos métodos: el método GET y el método POST.

Transmisión de datos usando el método GET

El método GET envía la información del usuario codificada al servidor. Los datos se incluyen en la URL de la página solicitada, separados por un signo "?", como se muestra a continuación:

http://www.test.com/cgi-bin/hello.py?key1=value1&key2=value2
Algunos comentarios adicionales sobre las solicitudes GET:
  • Las solicitudes GET se pueden almacenar en caché
  • Las solicitudes GET permanecen en el historial del navegador
  • Las solicitudes GET se pueden guardar como marcadores
  • Las solicitudes GET no deben usarse al manejar datos sensibles
  • Las solicitudes GET tienen limitación de longitud
  • Las solicitudes GET solo deben usarse para recuperar datos

Uso de cookies en CGI

Una gran desventaja del protocolo http es que no verifica la identidad del usuario, lo que causa grandes inconvenientes a los programadores. La aparición de la función de cookie compensa esta deficiencia.

La cookie consiste en que, mientras el cliente accede al script, se escriben datos de registro en el disco duro del cliente a través del navegador de este. Cuando el cliente vuelva a acceder al script, se recuperan los datos, logrando así la función de identificación. La cookie se usa comúnmente en la verificación de identidad.

　

Sintaxis de cookies

El envío de la cookie http se realiza a través de la cabecera http, que precede a la transferencia del archivo. La sintaxis de la cabecera Set-Cookie es la siguiente:

Set-cookie:name=name;expires=date;path=path;domain=domain;secure
  • name=name:Se debe configurar el valor de la cookie (el nombre no puede usar ";y ",carácter), cuando haya múltiples valores de name, use ";" para separar, por ejemplo:name1=name1;name2=name2;name3=name3。
  • expires=date:Período de validez de la cookie, formato: expires="Wdy,DD-Mon-YYYY HH:MM:SS"
  • path=path: Establecer la ruta compatible con la cookie. Si path es una ruta, la cookie es válida para todos los archivos y subdirectorios de ese directorio, por ejemplo: path="/cgi-bin/". Si path es un archivo, la cookie solo es válida para ese archivo, por ejemplo: path="/cgi-bin/cookie.cgi".
  • domain=domain:Dominio donde la cookie es válida, por ejemplo: domain="www.runoob.com"
  • secure:Si se proporciona este indicador, significa que la cookie solo puede transmitirse a través de un servidor https con protocolo SSL.
  • La recepción de la cookie se logra mediante la variable de entorno HTTP_COOKIE. El programa CGI puede obtener la información de la cookie consultando esta variable.

Configuración de cookies

La configuración de Cookie es muy simple; la cookie se envía por separado en la cabecera http. El siguiente ejemplo establece name y expires en la cookie:

#!/usr/bin/python
# -*- coding: UTF-8 -*-
# 
print 'Content-Type: text/html'
print 'Set-Cookie: name="菜鸟教程";expires=Wed, 28 Aug 2016 18:30:00 GMT'
print
print """
<html>
    <head>
        <meta charset="utf-8">
        <title>菜鸟教程(runoob.com)</title>
    </head>
    <body>
        <h1>Cookie set OK!</h1>
    </body>
</html>
"""

Recuperación de información de cookies

La página de recuperación de información de Cookie es muy simple. La información de Cookie se almacena en la variable de entorno HTTP_COOKIE del CGI, con el siguiente formato de almacenamiento:

key1=value1;key2=value2;key3=value3....

El siguiente es un programa CGI simple para recuperar información de cookie:

#!/usr/bin/python
# -*- coding: UTF-8 -*-

# 导入模块
import os
import Cookie

print "Content-type: text/html"
print

print """
<html>
<head>
<meta charset="utf-8">
<title>菜鸟教程(runoob.com)</title>
</head>
<body>
<h1>读取cookie信息</h1>
"""

if 'HTTP_COOKIE' in os.environ:
    cookie_string=os.environ.get('HTTP_COOKIE')
    c=Cookie.SimpleCookie()
    c.load(cookie_string)

    try:
        data=c['name'].value
        print "cookie data: "+data+"<br>"
    except KeyError:
        print "cookie 没有设置或者已过期<br>"
print """
</body>
</html>

"""

# 获取文件名
fileitem = form['filename']

# 检测文件是否上传
if fileitem.filename:
   # 设置文件路径 
   fn = os.path.basename(fileitem.filename)
   open('/tmp/' + fn, 'wb').write(fileitem.file.read())

   message = '文件 "' + fn + '" 上传成功'
   
else:
   message = '文件没有上传'
   
print """\
Content-Type: text/html\n
<html>

Diálogo de descarga de archivos

Primero creamos el archivo foo.txt en el directorio actual, para que el programa lo descargue.

La descarga de archivos se implementa configurando la cabecera HTTP. El código de la funcionalidad es el siguiente:

#!/usr/bin/python
# -*- coding: UTF-8 -*-

# HTTP 头部
print "Content-Disposition: attachment; filename=\"foo.txt\"";
print
# 打开文件
fo = open("foo.txt", "rb")

str = fo.read();
print str

# 关闭文件
fo.close()
