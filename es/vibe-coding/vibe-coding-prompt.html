Ingeniería de Prompts

El Prompt es el único canal de comunicación entre tú y la IA. Con el mismo requisito, un Prompt diferente puede hacer que la calidad del resultado varíe hasta 10 veces.

Los cinco elementos de un buen Prompt:

ElementoPregunta centralQué ocurre si falta
Objetivo¿Qué hay que hacer?La IA adivina tu intención y puede desviarse
Restricciones¿Qué limitaciones existen?La IA usa un stack tecnológico que no conoces y el código no se puede integrar
Entrada¿Qué datos recibe?La IA asume un formato de entrada y falla en la ejecución real
Salida¿Qué resultado produce?La IA da el código pero no da el modo de uso; no sabes cómo ejecutarlo
Criterios de aceptación¿Qué se considera aceptable?La IA termina, pero no sabes si está realmente terminado

Elemento 1: Objetivo — di claramente qué quieres hacer

Redacción incorrecta

帮我写一个表单

Problema: ¿qué formulario? ¿Inicio de sesión? ¿Registro? ¿Búsqueda? ¿Cuántos campos?

Buena redacción

帮我写一个用户注册表单，包含以下字段：
用户名、邮箱、密码、确认密码

Mejor redacción

帮我写一个用户注册表单，包含以下字段：
- 用户名（文本框，3-20 个字符）
- 邮箱（文本框，需验证格式）
- 密码（密码框，至少 6 位，包含数字和字母）
- 确认密码（密码框，需与密码一致）

Consejos clave:Divide el «qué hacer» en partes concretas. La IA comprende mucho mejor lo concreto que los conceptos vagos.

Elemento 2: Restricciones — delimita el alcance

Las restricciones le dicen a la IA qué no puede hacer y qué debe usar. Sin restricciones, la IA improvisa, lo que hace que el código no se pueda integrar en tu proyecto.

Tipos comunes de restricciones

技术栈约束：
- 使用 React 18 + TypeScript
- 不引入第三方 UI 库（自己写 CSS）
- 使用 Vite 作为构建工具

代码风格约束：
- 使用函数组件和 Hooks，不用 Class 组件
- 每个文件不超过 150 行
- 所有 props 都要有 TypeScript 类型定义

输出约束：
- 所有代码放在一个文件里
- 给出完整的 import 语句
- 关键逻辑加上注释

Cuantas más restricciones escribas, más controlable será el resultado de la IA. Pero no escribas demasiadas de una vez: primero escribe 3-5 restricciones principales y añade más según los resultados.

Elemento 3: Entrada — define el formato de los datos

Dile a la IA cómo son los datos de entrada; así podrá escribir un código más preciso.

Redacción incorrecta

写一个函数处理用户数据

Buena redacción

写一个函数 formatUser(user)，接收一个用户对象：
{
  name: string,       // 用户名，例如 "张三"
  age: number,        // 年龄，例如 25
  email: string,      // 邮箱，例如 "zhangsan@example.com"
  createdAt: string   // 注册时间，ISO 格式，例如 "2026-06-28T10:00:00Z"
}
返回格式化的用户信息字符串。

Consejos clave:Añade un valor de ejemplo para cada campo. La IA entiende mucho mejor los ejemplos que las descripciones abstractas de tipos.

Elemento 4: Salida — especifica la forma del resultado

Dile a la IA la forma de salida que esperas: ¿código? ¿explicación? ¿sugerencia de modificación?

Formas de salida comunes

Forma de salidaEscenario de usoEjemplo de Prompt
Código completoFunciones nuevas, archivos nuevosDame el código completo, incluyendo todos los imports
Modificación de códigoModificar código existenteSolo genera las partes modificadas, en formato diff
ExplicaciónEntender el códigoExplica línea por línea qué hace este código
Sugerencia de solucionesDecisiones de arquitecturaOfrece dos opciones de implementación y compara sus ventajas e inconvenientes
Solución de erroresDepuraciónAnaliza la causa de este error y proporciona los pasos para corregirlo

Elemento 5: Criterios de aceptación — define en qué consiste "terminado"

Los criterios de aceptación son el elemento que más fácilmente se pasa por alto, pero determinan si puedes juzgar que la tarea está completa.

Ejemplo de buenos criterios de aceptación

验收标准：
- 用户名少于 3 个字符时，显示红色提示"用户名至少 3 个字符"
- 密码少于 6 位时，显示红色提示"密码至少 6 位"
- 两次密码不一致时，显示红色提示"两次密码不一致"
- 所有字段为空时点击提交，每个字段下方显示对应的错误提示
- 所有字段正确填写后点击提交，控制台打印表单数据，不发送请求

Consejos clave:Los criterios de aceptación deben ser específicos hasta el punto de «qué se introduce, qué se ve», usando«cuando..., debería...»como estructura de frase.

Plantilla de Prompt

Esta es la plantilla de Prompt que se usará más adelante en este curso; puedes aplicarla directamente:

## 目标
[一句话描述要做什么]

## 约束
- [技术栈限制]
- [代码风格要求]
- [输出格式要求]

## 输入
[输入数据的结构和示例]

## 输出
[期望的输出形式]

## 验收标准
- [具体可验证的标准 1]
- [具体可验证的标准 2]
- [具体可验证的标准 3]

Errores comunes de Prompt y sus correcciones

ErrorProblemaCorrección
Ayúdame a crear una tienda en líneaDemasiado vago; la IA no sabe por dónde empezarAyúdame a crear la página de listado de productos de la tienda: muestra la imagen del producto, el nombre y el precio, con 3 productos por fila
Impleméntalo de la mejor maneraLa IA no sabe qué es «lo mejor» para tiOptimiza el rendimiento del renderizado con React.memo y useCallback
Este código tiene problemas, ayúdame a corregirloNo se dice dónde está el problemaDespués de hacer clic en el botón de eliminar, la lista no se actualiza y la consola muestra el error «id is undefined». Ayúdame a corregirlo
Añade una funciónNo se dice en qué archivo ni en qué posición añadirlaAñade un menú desplegable de avatar de usuario en el lado derecho de la barra de navegación de src/components/Header.tsx

Práctica: el mismo requisito, comparación de tres Prompts

Requisito: crear unalista «Tareas de hoy».

Versión A: Prompt de una sola frase

帮我做一个待办列表

Resultado de la IA: puede ser una página HTML simple, puede usar React, puede usar Vue; no sabes qué obtendrás.

Versión B: Prompt con restricciones añadidas

帮我做一个待办列表，用 HTML + CSS + 原生 JavaScript，
可以添加和删除任务。

Resultado de la IA: una lista de tareas funcional, pero el estilo puede ser muy básico y puede que no maneje entradas vacías.

Versión C: Prompt completo de cinco elementos

## 目标
做一个"今日待办"列表组件。

## 约束
- 使用 HTML + CSS + 原生 JavaScript，单文件
- 不使用任何第三方库
- 移动端友好的响应式布局

## 输入
- 用户在输入框中输入待办事项文字
- 用户点击"添加"按钮或按 Enter 键

## 输出
- 一个完整的 HTML 文件，可以直接在浏览器打开
- 输入框在顶部，已添加的待办事项在下方列表显示
- 每个待办事项右侧有删除按钮
- 底部显示"共 X 项，已完成 Y 项"

## 验收标准
- 输入空内容点击添加时，显示提示"请输入待办事项"
- 添加成功后，输入框清空
- 点击待办事项文字，切换完成/未完成状态（加删除线）
- 点击删除按钮，该项消失
- 统计数据实时更新
- 刷新页面后数据保留（使用 localStorage）

Resultado de la IA: una lista de tareas completa, con persistencia de datos, estadísticas y manejo de errores.

Al comparar los resultados de las tres versiones, te darás cuenta de forma intuitiva: el límite de calidad del Prompt es el límite de calidad del resultado de la IA.

Práctica de desarrollo iterativo

El flujo de trabajo central de Vibe Coding no consiste en dar un Prompt y obtener un código perfecto de una vez, sinodar Prompt → verificar → retroalimentar → volver a verificarel ciclo.

Las cinco etapas del desarrollo iterativo

Proyecto práctico: crear un "Diccionario de términos de programación"

Este proyecto consiste en crear un diccionario de términos de programación con función de búsqueda, que incluya el nombre del término, la explicación y la categoría.

Sigue las cinco iteraciones de abajo y pon en práctica cada una de ellas.

Primera ronda: haz que funcione

Prompt：

做一个编程术语词典网页，要求：
- 使用 HTML + CSS + 原生 JavaScript，单文件
- 显示一个术语列表，每条术语包含名称和简短解释
- 预置 10 个常见编程术语（HTML、CSS、JavaScript、API、变量、函数、循环、数组、对象、Git）
- 顶部有一个搜索框，输入关键词可以过滤术语
- 深色背景，卡片式布局

Guarda el código generado por la IA comodict.htmly ábrelo en el navegador.

  • Verificación: ¿Se abre la página? ¿Se muestran los 10 términos? ¿El cuadro de búsqueda puede filtrar?

  • Retroalimentación: Si la búsqueda no funciona, describe a la IA el problema concreto.

El objetivo de la primera ronda no es la perfección, sino que funcione. Una versión que funciona pero no es perfecta es 100 veces mejor que una versión perfecta en tu imaginación pero que aún no has escrito.

Segunda ronda: haz que sea utilizable

Prompt：

在上一轮的代码基础上，做以下改进：
1. 每个术语卡片加上分类标签（如"前端"、"JavaScript"、"通用"等）
2. 搜索时同时匹配术语名称和分类标签
3. 搜索结果为空时，显示"没有找到相关术语"而不是空白
4. 添加一个"随机学习"按钮，点击后随机展示一个术语
5. 术语列表按字母顺序排列

Verificación: ¿Se muestran las etiquetas de categoría? ¿La búsqueda puede coincidir con las categorías? ¿Hay un aviso cuando no hay resultados? ¿El botón aleatorio funciona?

Retroalimentación: Revisa punto por punto y comunica a la IA los elementos que no se cumplen.

Tercera ronda: corrige los Bugs

En esta ronda debes buscar Bugs activamente.

Prueba los siguientes escenarios:

Ingrese caracteres especiales en el cuadro de búsqueda (como<、>、/）。

Ingrese espacios en el cuadro de búsqueda (espacios al inicio y al final).

Haga clic rápida y consecutivamente en el botón aleatorio.

Ingrese letras mayúsculas en el cuadro de búsqueda (los datos originales pueden estar en minúsculas).

Elimine todos los términos (si se admite la función de eliminación).

Por cada error (bug) encontrado, descríbalo a la IA de forma estructurada:

当我在搜索框中输入大写 "HTML" 时，没有匹配到任何结果。
预期：不区分大小写，输入 "html" 和 "HTML" 都能匹配到。
实际：只有输入小写 "html" 才能匹配。
请修复这个大小写敏感的问题。

Cuarta ronda: pule los detalles

Prompt：

在上一轮代码基础上，优化以下细节：
1. 搜索时添加防抖（输入停止 300ms 后再搜索，避免频繁过滤）
2. 卡片 hover 时有一个微小的上浮动画
3. 搜索结果高亮匹配的关键词（用黄色背景标记）
4. 添加一个"已学 X 个"的计数器，点击术语卡片上的"已学"按钮 +1
5. 已学过的术语显示一个勾的标记
6. 用 localStorage 保存已学记录

Verificar: ¿Son fluidas las animaciones? ¿El resaltado es correcto? ¿Los registros aprendidos siguen ahí después de actualizar?

Quinta ronda: añade pruebas y documentación

Prompt：

在上一轮代码基础上：
1. 在代码顶部用注释写出功能说明和用法
2. 为搜索过滤函数写注释，说明它的输入、输出和逻辑
3. 如果代码中有复杂的逻辑，拆分成更小的函数，每个函数只做一件事
4. 在文件中添加数据来源说明（术语数据来自哪里）

Hábitos clave durante el proceso iterativo

Cambia solo una cosa a la vez

Si la IA cambia muchas cosas a la vez pero usted solo quiere cambiar una, dígalo claramente:

只修改搜索框的大小写问题，不要改动其他任何代码。

Ejecuta una verificación inmediatamente después de cada iteración

No acumule varios cambios para verificarlos juntos: ejecute una vez después de cada ronda de cambios para asegurarse de que no se introduzcan nuevos problemas.

Conserva una versión de cada ronda

Use Git para confirmar (commit) los resultados de cada ronda:

git add dict.html && git commit -m "第一轮：基本功能能跑"
git add dict.html && git commit -m "第二轮：添加分类和随机功能"
git add dict.html && git commit -m "第三轮：修复大小写和特殊字符 bug"
git add dict.html && git commit -m "第四轮：添加动画和已学记录"
git add dict.html && git commit -m "第五轮：添加注释和文档"

Así puede volver a cualquier versión en cualquier momento y comparar los cambios de cada ronda.

Git es la red de seguridad del Vibe Coding. Cuando pida a la IA que haga cambios importantes, primero haga commit de la versión actual y, si se rompe, revierta.
