React Props

En React, los Props (propiedades) son el mecanismo para pasar datos del componente padre al componente hijo. Los Props son de solo lectura; los componentes hijos no pueden modificarlos directamente, sino que el componente padre debe administrarlos y actualizarlos.

La principal diferencia entre state y props es quepropslos props son inmutables, mientras que state puede cambiar según la interacción con el usuario. Es por eso que algunos componentes contenedores necesitan definir state para actualizar y modificar datos. Y los componentes hijos solo pueden transferir datos a través de props.

Usando Props

Sintaxis para pasar Props:

<ComponentName propName={propValue} />

El siguiente ejemplo demuestra cómo usar props en un componente:

Ejemplo de React

function HelloMessage(props) { return <h1>Hello {props.name}!</h1>; } const element = <HelloMessage name="Runoob"/>; const root = ReactDOM.createRoot(document.getElementById("root")); root.render( element );

Props predeterminados

Puedes establecer valores predeterminados para props mediante la propiedad defaultProps de la clase del componente. Ejemplo:

Ejemplo de React

class HelloMessage extends React.Component { render() { return ( <h1>Hello, {this.props.name}</h1> ); } } HelloMessage.defaultProps = { name: 'Runoob' }; const element = <HelloMessage/>; const root = ReactDOM.createRoot(document.getElementById("root")); root.render( element );

Múltiples Props

Puedes pasar múltiples atributos al componente hijo.

Ejemplo

const UserCard = (props) => {
  return (
    <div>
      <h2>{props.name}</h2>
      <p>Age: {props.age}</p>
      <p>Location: {props.location}</p>
    </div>
  );
};

const App = () => {
  return (
    <UserCard name="Alice" age={25} location="New York" />
  );
};

ReactDOM.render(<App />, document.getElementById('root'));

Validación de propTypes

propTypes es una herramienta proporcionada por React para realizar la verificación de tipos de los props de un componente.

Puedes usar la librería prop-types para verificar los tipos de los props del componente.

En React, propTypes se define como una propiedad estática del componente. Primero, necesitas instalar el paquete prop-types:

npm install prop-types

Luego, importa prop-types en el archivo de tu componente y define la propiedad propTypes. A continuación se muestra un ejemplo:

Ejemplo

import PropTypes from 'prop-types';

const Greeting = (props) => {
  return <h1>Hello, {props.name}!</h1>;
};

Greeting.propTypes = {
  name: PropTypes.string.isRequired
};

const App = () => {
  return (
    <div>
      <Greeting name="Alice" />
      {/* <Greeting /> // Esta línea provocará una advertencia en la consola, porque name es obligatorio */}
    </div>
  );
};

ReactDOM.render(<App />, document.getElementById('root'));

Pasar funciones de devolución de llamada como Props

Puedes pasar funciones como props al componente hijo, y este puede invocar esas funciones para comunicarse con el componente padre.

Ejemplo

class ParentComponent extends React.Component {
  constructor(props) {
    super(props);
    this.state = { message: '' };
  }

  handleMessage = (msg) => {
    this.setState({ message: msg });
  };

  render() {
    return (
      <div>
        <ChildComponent onMessage={this.handleMessage} />
        <p>Message from Child: {this.state.message}</p>
      </div>
    );
  }
}

const ChildComponent = (props) => {
  const sendMessage = () => {
    props.onMessage('Hello from Child!');
  };

  return (
    <div>
      <button onClick={sendMessage}>Send Message</button>
    </div>
  );
};

ReactDOM.render(<ParentComponent />, document.getElementById('root'));

Desestructurando Props

En los componentes de función, puedes simplificar el código desestructurando props.

Ejemplo

const Greeting = ({ name }) => {
  return <h1>Hello, {name}!</h1>;
};

const App = () => {
  return <Greeting name="Alice" />;
};

ReactDOM.render(<App />, document.getElementById('root'));

Resumen

  • Pasar y usar Props: el componente padre pasa datos al componente hijo, el componente hijo recibe mediantepropslos props.
  • Props predeterminados:usadefaultPropspara establecer los valores predeterminados de los atributos del componente.
  • Validación de PropTypes:usaprop-typesla librería para verificar los tipos de props.
  • Pasar funciones de devolución de llamada: el componente padre puede pasar funciones como props al componente hijo, para lograr la comunicación entre componentes.
  • Desestructurar Props: desestructura props en componentes de función para simplificar el código.

State y Props

El siguiente ejemplo demuestra cómo combinar state y props en una aplicación. Podemos establecer state en el componente padre y pasarlo al componente hijo mediante props. En la función render, configuramos name y site para obtener los datos pasados por el componente padre.

Ejemplo de React

class WebSite extends React.Component { constructor() { super(); this.state = { name: "Runoob", site: "https://www.runoob.com" } } render() { return ( <div> <Name name={this.state.name} /> <Link site={this.state.site} /> </div> ); } } class Name extends React.Component { render() { return ( <h1>{this.props.name}</h1> ); } } class Link extends React.Component { render() { return ( <a href={this.props.site}> {this.props.site} </a> ); } } const root = ReactDOM.createRoot(document.getElementById("root")); root.render( <WebSite /> );

Por supuesto, podemos presentarte másPropTypesvalidadores y cómo usarlos. A continuación se muestran algunosPropTypesDescripción de los validadores:

Tipos de datos básicos

  • PropTypes.string: cadena
  • PropTypes.number: número
  • PropTypes.boolean: booleano
  • PropTypes.object: objeto
  • PropTypes.array: array
  • PropTypes.func: función
  • PropTypes.symbol：Symbol

Tipos especiales

  • PropTypes.node: cualquier contenido que se pueda renderizar: números, cadenas, elementos o arrays (incluidos estos tipos)
  • PropTypes.element: elemento de React
  • PropTypes.instanceOf(Class): instancia de una clase

Tipos combinados

  • PropTypes.oneOf(['option1', 'option2']): tipo de enumeración; el valor debe ser una de las opciones proporcionadas
  • PropTypes.oneOfType([PropTypes.string, PropTypes.number]): uno de varios tipos
  • PropTypes.arrayOf(PropTypes.number): array compuesto por un tipo determinado
  • PropTypes.objectOf(PropTypes.number): objeto compuesto por un tipo determinado
  • PropTypes.shape({ key: PropTypes.string, value: PropTypes.number }): objeto con una forma específica

Otros

  • PropTypes.any: cualquier tipo
  • PropTypes.exact({ key: PropTypes.string }): objeto con claves específicas y sin claves adicionales

A continuación se muestran algunos ejemplos de código que demuestran cómo usar diferentesPropTypesvalidadores:

Ejemplo

import React from 'react';
import ReactDOM from 'react-dom/client';
import PropTypes from 'prop-types';

class MyComponent extends React.Component {
  static propTypes = {
    title: PropTypes.string.isRequired, // Debe ser una cadena y es obligatorio
    age: PropTypes.number,              // Número opcional
    isAdmin: PropTypes.bool,            // Booleano opcional
    user: PropTypes.shape({             // Debe ser un objeto con una forma específica
      name: PropTypes.string,
      email: PropTypes.string
    }),
    items: PropTypes.arrayOf(PropTypes.string), // Debe ser un array de cadenas
    callback: PropTypes.func,           // Función opcional
    children: PropTypes.node,           // Contenido renderizable opcional
    options: PropTypes.oneOf(['option1', 'option2']), // Debe ser uno de los valores específicos
  };

  render() {
    return (
      <div>
        <h1>{this.props.title}</h1>
        {this.props.age && <p>Age: {this.props.age}</p>}
        {this.props.isAdmin && <p>Admin</p>}
        {this.props.user && (
          <div>
            <p>Name: {this.props.user.name}</p>
            <p>Email: {this.props.user.email}</p>
          </div>
        )}
        {this.props.items && (
          <ul>
            {this.props.items.map((item, index) => (
              <li key={index}>{item}</li>
            ))}
          </ul>
        )}
        {this.props.callback && (
          <button onClick={this.props.callback}>Click me</button>
        )}
        {this.props.children}
        {this.props.options && <p>Option: {this.props.options}</p>}
      </div>
    );
  }
}

const root = ReactDOM.createRoot(document.getElementById("root"));
root.render(
  <MyComponent
    title="Hello, World!"
    age={30}
    isAdmin={true}
    user={{ name: "John Doe", email: "john@example.com" }}
    items={['Item 1', 'Item 2', 'Item 3']}
    callback={() => alert('Button clicked!')}
    options="option1"
  >
    <p>This is a child element</p>
  </MyComponent>
);

    Para complementar lo que dijo el compañero anterior. En muchos casos, el componente hijo necesita todos los props del componente padre, y escribir los parámetros uno por uno es muy tedioso. Por ejemplo:

    <Name name={this.props.name} url={this.props.url}  .../>

    Entonces, ¿cómo podemos asignar directamente las propiedades del padre a los props del componente hijo? Basta con escribirlo de la siguiente manera:

    <Name props={this.props}/>

    De esta manera se vuelve muy conciso, es decir, tanto el componente hijo como el componente padre tienen props con la misma estructura de datos.

    En muchos casos, al depurar la página, los nombres de los parámetros que se ven en el componente padre y en el componente hijo son diferentes, pero representan el mismo valor. Quien escribió este código quizás recuerde que el parámetro fue transformado, pero otras personas que lo lean quedarán confundidas, lo que es ineficiente. Por lo tanto, generalmente recomendamos mantener los nombres sin cambios al referenciar los parámetros del componente padre, para facilitar el mantenimiento futuro.

    En el JSX del valor de retorno de la función render del componente BodyChild, el value de <p> es el valor de la variable getname obtenida desde el componente padre, y onChange obtiene la función changeUsername. Por lo tanto, si el valor en el cuadro de texto cambia, el evento de cambio de valor activa la función changeUsername. Esta función obtiene el valor del evento, es decir, el valor modificado en nuestro cuadro de texto, y lo asigna a la variable state.username del componente padre. Y cuando esta variable del componente padre cambia, el state cambia en consecuencia; en ese momento, render se vuelve a ejecutar, por lo que veremos el valor modificado.
