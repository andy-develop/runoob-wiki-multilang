Estado de componentes (State) en React

Los componentes pueden tener estado (state), que es la parte privada de los datos del componente y se puede utilizar para gestionar datos dinámicos.

El estado solo aplica a componentes de clase, o puede usarse en componentes de función cuando se utilizan los Hooks de React.

React trata los componentes como máquinas de estado (State Machines). Mediante la interacción con el usuario, se logran diferentes estados y luego se renderiza la interfaz de usuario, manteniendo la interfaz coherente con los datos.

En React, solo hay que actualizar el estado del componente y luego volver a renderizar la interfaz de usuario según el nuevo estado (no manipular el DOM).

El siguiente ejemplo crea una clase ES6 que extiende React.Component, y usa this.state en el método render() para modificar la hora actual.

Agrega un constructor de clase para inicializar el estado this.state. Los componentes de clase siempre deben llamar al constructor base con props.

Gestión de estado en componentes de clase

Crear un componente de clase con estado:

Archivo Counter.js

import React, { Component } from 'react';

class Counter extends Component {
  constructor(props) {
    super(props);
    this.state = { count: 0 };
  }

  increment = () => {
    this.setState({ count: this.state.count + 1 });
  }

  render() {
    return (
      <div>
        <p>Count: {this.state.count}</p>
        <button onClick={this.increment}>Increment</button>
      </div>
    );
  }
}

export default Counter;

Renderizar este componente en src/index.js:

Ejemplo

import React from 'react';
import ReactDOM from 'react-dom';
import './index.css';
import Counter from './Counter';

const root = ReactDOM.createRoot(document.getElementById("root"));
// Renderizar el componente Counter
root.render(<Counter />);

Gestión de estado en componentes de función (usando Hooks)

Usando los Hooks de React, se puede usar estado en componentes de función. El Hook más común es useState.

Crear un componente de función con estado:

Archivo Counter.js

import React, { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>Increment</button>
    </div>
  );
}

export default Counter;

Renderizar este componente en src/index.js:

Ejemplo

import React from 'react';
import ReactDOM from 'react-dom';
import './index.css';
import Counter from './Counter';

const root = ReactDOM.createRoot(document.getElementById("root"));
// Renderizar el componente Counter
root.render(<Counter />);

A continuación, haremos que Clock configure su propio temporizador y se actualice cada segundo.

Agregar métodos de ciclo de vida a la clase

En aplicaciones con muchos componentes, es muy importante liberar los recursos ocupados por los componentes cuando se destruyen.

Cada vez que el componente Clock se carga por primera vez en el DOM, queremos generar un temporizador. Esto se llama en Reactmontaje。

De manera similar, cuando el DOM generado por Clock sea eliminado, también querremos limpiar el temporizador. Esto se llama en Reactdesmontaje。

Podemos declarar métodos especiales en la clase del componente para ejecutar código cuando el componente se monta o desmonta:

Ejemplo de React

class Clock extends React.Component { constructor(props) { super(props); this.state = {date: new Date()}; } componentDidMount() { this.timerID = setInterval( () => this.tick(), 1000 ); } componentWillUnmount() { clearInterval(this.timerID); } tick() { this.setState({ date: new Date() }); } render() { return ( <div> <h1>Hello, world!</h1> <h2>Ahora es{this.state.date.toLocaleTimeString()}.</h2> </div> ); } } const root = ReactDOM.createRoot(document.getElementById("root")); root.render( <Clock /> );

Pruébalo »

Análisis del ejemplo:

componentDidMount() 与 componentWillUnmount()Los métodos se denominan hooks del ciclo de vida.

Se ejecuta después de que la salida del componente se renderice en el DOM.componentDidMount()En este hook, podemos configurar un temporizador.

this.timerID es el ID del temporizador. PodemoscomponentWillUnmount()limpiar el temporizador en el hook.

Orden de ejecución del código:

  1. 当 <Clock />se pasa aReactDOM.render()Cuando React llamaClockal constructor del componente. Dado queClocknecesita mostrar la hora actual, se inicializa con un objeto que contiene la hora actual.this.state. Actualizaremos este estado más tarde.

  2. Luego React llama alClockmétodo del componenterender()render. Así React sabe qué se debe mostrar en la pantalla y luego actualiza el DOM para que coincida conClockla salida de renderizado.

  3. 当 ClockCuando su salida se inserta en el DOM, React llama alcomponentDidMount()hook de ciclo de vida. Dentro de este,Clockel componente pide al navegador configurar un temporizador que llame una vez por segundo atick()。

  4. El navegador llama cada segundo atick()método. Dentro de este,Clockel componente, mediante un objeto con la hora actual, llama asetState()para programar la actualización de la interfaz. Al llamar asetState(), React sabe que el estado ha cambiado y vuelve a llamar alrender()método para determinar qué mostrar en pantalla. Esta vez,render()en el métodothis.state.dateserá diferente, por lo que la salida renderizada contendrá la hora actualizada y el DOM se actualizará en consecuencia.

  5. Una vez queClockel componente es eliminado del DOM, React llama alcomponentWillUnmount()este hook, y el temporizador se limpiará.

Los datos fluyen de arriba hacia abajo

Ni el componente padre ni el hijo pueden saber si un componente tiene estado o no, y no deberían preocuparse de si un componente se define como una función o como una clase.

Por eso el estado a menudo se denomina local o encapsulado. Ningún otro componente, excepto el que lo posee y lo establece, puede acceder a él.

En el siguiente ejemplo, el componente FormattedDate recibirá el valor date en sus props, y no sabrá si proviene del estado de Clock, de las props de Clock, o si se ingresó manualmente:

Ejemplo de React

function FormattedDate(props) { return <h2>Ahora es{props.date.toLocaleTimeString()}.</h2>; } class Clock extends React.Component { constructor(props) { super(props); this.state = {date: new Date()}; } componentDidMount() { this.timerID = setInterval( () => this.tick(), 1000 ); } componentWillUnmount() { clearInterval(this.timerID); } tick() { this.setState({ date: new Date() }); } render() { return ( <div> <h1>Hello, world!</h1> <FormattedDate date={this.state.date} /> </div> ); } } const root = ReactDOM.createRoot(document.getElementById("root")); root.render( <Clock /> );

Pruébalo »

Esto a menudo se denomina flujo de datos de arriba hacia abajo o unidireccional. Cualquier estado siempre pertenece a algún componente específico, y cualquier dato o interfaz derivado de ese estado solo puede afectar a los componentes que están más abajo en el árbol.

Si imaginas un árbol de componentes como una cascada de props, el estado de cada componente es como una fuente de agua adicional que se conecta en un punto arbitrario, pero también fluye hacia abajo.

Para demostrar que todos los componentes están realmente aislados, podemos crear un componente App que renderice tres Clock:

Ejemplo de React

function FormattedDate(props) { return <h2>Ahora es{props.date.toLocaleTimeString()}.</h2>; } class Clock extends React.Component { constructor(props) { super(props); this.state = {date: new Date()}; } componentDidMount() { this.timerID = setInterval( () => this.tick(), 1000 ); } componentWillUnmount() { clearInterval(this.timerID); } tick() { this.setState({ date: new Date() }); } render() { return ( <div> <h1>Hello, world!</h1> <FormattedDate date={this.state.date} /> </div> ); } } function App() { return ( <div> <Clock /> <Clock /> <Clock /> </div> ); } const root = ReactDOM.createRoot(document.getElementById("root")); root.render(<App />);

Pruébalo »

En el ejemplo anterior, cada componente Clock crea su propio temporizador y se actualiza de forma independiente.

En una aplicación React, si un componente tiene estado o no se considera un detalle de implementación del componente que puede cambiar con el tiempo.

Podemos usar componentes sin estado dentro de componentes con estado, y también usar componentes con estado dentro de componentes sin estado.

    Sobre la forma de llamar a tick() en setInterval al montar: ()=>this.tick():

    1、()=>this.tick()

    ()=>this.tick()Es una forma de declarar funciones en ES6, llamada expresión de función flecha. La introducción de las funciones flecha tiene dos propósitos: funciones más cortas y no vincular this.

    var f = ([参数]) => 表达式（单一）
// 等价于以下写法
var f = function([参数]){
   return 表达式;
}

    La sintaxis básica de la función flecha es la siguiente:

    (参数1, 参数2, …, 参数N) => { 函数声明 }
(参数1, 参数2, …, 参数N) => 表达式（单一）
//相当于：(参数1, 参数2, …, 参数N) =>{ return 表达式; }

// 当只有一个参数时，圆括号是可选的：
(单一参数) => {函数声明}
单一参数 => {函数声明}

// 没有参数的函数应该写成一对圆括号。
() => {函数声明}

    Según los conceptos anteriores, intenta cambiar la forma de llamar a tick() en setInterval a la forma de declaración normal:

    this.timerID = setInterval(function(){
    return this.tick();
  },1000
);

    Pero se produce un error: tick() no es un método.

    2、this.tick()

    En this.tick(), this se refiere a la función, no a la clase de componente Clock que queremos. Por lo tanto, debemos encontrar una manera de que this se refiera correctamente. Aquí usamos la táctica de "asediar a Wei para rescatar a Zhao".

    let that = this;
this.timerID = setInterval(function () {
  return that.tick();
},1000);

    Fuera de la función de cierre, primero se usa that para referenciar el valor de this en el método de montaje componentDidMount() del componente Clock; luego, dentro de setInterval, la función de cierre usa that. Como that no encuentra una declaración, según la cadena de alcance heredará that del nivel superior (la capa anterior), que es el this de la clase de componente Clock que referenciamos.

    Hasta aquí, hemos sustituido equivalentemente () => this.tick() por la forma que nos resulta familiar.

    ch4o5 (compañero)Al convertir el uso de la función flecha a la escritura normal en el ejemplo, se reporta el error:tick() no es un métodoLa razón es que setInterval es un método de window. Al usar this dentro del cierre, este también apunta a window. window no tiene el método tick(), por lo que se produce el error.

    this.timerID = setInterval(function(){   //setInterval是window的方法
    return this.tick();                  //this指的是window
  },1000
);

    Por lo tanto, hay que cambiar la referencia: definir una variable fuera de setInterval, let that/_this = this, para poder usar _this.tick() correctamente.

    componentDidMount(){
    let _this = this;
    this.timerID = setInterval(function(){
      _this.tick();
    }, 1000);
}
