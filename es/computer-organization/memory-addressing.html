Direcciones de memoria y direccionamiento

Cuando declaras una variable en un programa, ¿cómo la "encuentra" la computadora? ¿Por qué un sistema de 32 bits solo puede instalar 4 GB de memoria RAM?

Esta lección desvela el misterio de las direcciones de memoria y te ayuda a entender el espacio de direccionamiento: la limitación fundamental que determina cuánta memoria puede usar una computadora.

Analogía cotidiana: los buzones de un edificio de apartamentos

Imagina un edificio de apartamentos: cada hogar tiene un buzón independiente, y cada buzón tiene un número de vivienda único.

Cuando el cartero entrega una carta, solo necesita saber el número de vivienda (la dirección) para poder poner la carta con precisión en el buzón correspondiente. La forma en que la CPU accede a la memoria es casi idéntica a cómo el cartero entrega la carta:

  • Cada celda de memoria (1 byte)= un buzón
  • Dirección de memoria= el número de vivienda del buzón (numerado desde 0)
  • Ancho del bus de direcciones= cuántos dígitos puede tener como máximo el número de vivienda (determina cuántos números se pueden asignar como máximo)

Si el número de vivienda solo tiene 2 dígitos (00~99), el edificio solo puede tener como máximo 100 buzones. De manera similar, si el bus de direcciones tiene solo 32 bits de ancho, la CPU solo puede distinguir como máximo 2^32 celdas de memoria diferentes.

La naturaleza de las direcciones de memoria

La dirección es un número de identificación

Desde la perspectiva del hardware, la memoria es una gran fila de celdas físicas que pueden almacenar 0 y 1. Cada celda almacena 1 byte (8 bits), y cada celda tiene un número de identificación único. Este número esla dirección de memoria。

La CPU lee y escribe la memoria a través de un sistema de tres buses:

  1. La CPU coloca la dirección objetivo en elbus de direcciones— "quiero encontrar el buzón número 103"
  2. La CPU envía la señal de "leer" o "escribir" en elbus de control— "por favor dame lo que hay dentro" o "por favor pon esto dentro"
  3. La memoria coloca los datos en elbus de datospara lectura, o toma los datos del bus de datos para escritura

¿Por qué cada dirección corresponde a 1 byte?

Esta es una decisión de diseño. Algunas computadoras antiguas usaban "direccionamiento por palabra" (cada dirección correspondía a 2 o 4 bytes), pero las computadoras modernas casi todas usandireccionamiento por byte— cada dirección corresponde a 1 byte.

La ventaja de hacerlo así es que resulta muy natural al manejar caracteres (en ASCII cada carácter ocupa 1 byte), sin necesidad de lógica adicional de alineación y división.

内存地址：  0      1      2      3      4      5      6      7
         +------+------+------+------+------+------+------+------+
内容：    | 0x48 | 0x65 | 0x6C | 0x6C | 0x6F | 0x00 | 0xFF | ... |
         +------+------+------+------+------+------+------+------+
           'H'    'e'    'l'    'l'    'o'    '\0'

一个 32 位整数 0x12345678 在内存中的存储（小端序）：
地址：    0      1      2      3
         +------+------+------+------+
内容：    | 0x78 | 0x56 | 0x34 | 0x12 |
         +------+------+------+------+
          低字节在低地址——这就是「小端序」(Little Endian)

¿Por qué un sistema de 32 bits solo puede usar como máximo 4 GB de memoria?

Causa directa: el ancho del bus de direcciones

Una dirección de 32 bits es un número binario compuesto por 32 ceros o unos.

Los distintos valores que pueden representar 32 bits binarios son:

2^32 = 2 × 2 × 2 × ... (32 veces) =4,294,967,296

es decir, aproximadamente4GB（GigaBytes）。

Si cada dirección corresponde a 1 byte, entonces el espacio de direcciones de 32 bits puede direccionar en total 4,294,967,296 bytes = 4 GB.

Cálculo derivado

1 KB  = 2^10 字节 = 1,024 字节
1 MB  = 2^20 字节 = 1,048,576 字节
1 GB  = 2^30 字节 = 1,073,741,824 字节

2^32  = 2^2 × 2^30
      = 4 × 1 GB
      = 4 GB

Por lo tanto,32 bits = 4 GB, esto no es una coincidencia, sino una relación matemática estricta entre el número de bits de dirección y el espacio direccionable.

Analogía: el número de dígitos de un número de teléfono

Supongamos que los números de teléfono de una ciudad tienen 8 dígitos (00000000 ~ 99999999). ¿Cuántos números de teléfono diferentes puede tener esa ciudad como máximo?

10^8 = 100 millones. Si la población supera los 100 millones, 8 dígitos no serán suficientes: hay que actualizar a 9 dígitos.

Con la misma lógica: una dirección de 32 bits "marcada" hasta el límite también es 4 GB. Cuando la necesidad de memoria supera los 4 GB, un sistema de 32 bits no puede hacer nada: esta es la razón por la que la industria migró colectivamente a 64 bits.

¿Qué significa 64 bits?

El límite teórico del espacio de direcciones de 64 bits es:

2^64 = 18 446 744 073 709 551 616 bytes ≈16 EB（ExaBytes）

¿Qué tan grande es este número?

  • 1 EB = mil millones de GB
  • 16 EB son aproximadamente cientos de veces el volumen de tráfico de datos de un día de Internet a nivel mundial en 2025
  • Si cada byte fuera un grano de arena, 16 EB de arena podrían llenar aproximadamente 2000 piscinas estándar

Actualmente ninguna placa base de consumo soporta una memoria tan grande. Los CPU modernos de 64 bits generalmente solo implementan 48 bits de líneas de dirección física (direccionable 256 TB), y Windows 10 Home lo limita a 128 GB, pero para el presente y el futuro previsible, esto ya es "suficiente".

El verdadero significado de 64 bits no es cuánta memoria se puede instalar, sino que:El software y los sistemas operativos ya no tienen que buscar soluciones alternativas por la insuficiencia del espacio de direcciones.(por ejemplo, la PAE de la era de 32 bits: extensión de dirección física).

def address_space_to_str(bytes_val):
    """
Convertir el número de bytes a un formato legible por humanos
Soporta: B, KB, MB, GB, TB, PB, EB
    """
    if bytes_val == 0:
        return "0 B"

    units = ['B', 'KB', 'MB', 'GB', 'TB', 'PB', 'EB']
    unit_idx = 0
    value = float(bytes_val)

    # Aumentar la unidad gradualmente, manteniendo el valor en un rango razonable
    while value >= 1024 and unit_idx < len(units) - 1:
        value /= 1024
        unit_idx += 1

    if unit_idx == 0:
        return f"{int(value):,} {units[unit_idx]}"
    elif value >= 100:
        return f"{value:,.0f} {units[unit_idx]}"
    elif value >= 10:
        return f"{value:,.1f} {units[unit_idx]}"
    else:
        return f"{value:,.2f} {units[unit_idx]}"

PAE: el plan de "prolongar la vida" de los sistemas de 32 bits

"Antes de que los 64 bits se generalizaran, ante el límite de 4GB, Intel diseñó una solución alternativa:""PAE (Extensión de Dirección Física)"。

"PAE extiende las líneas de dirección física de 32 a 36 bits, permitiendo que una CPU de 32 bits pueda direccionar hasta 2^36 = 64 GB de memoria física."

"Pero aquí hay una limitación clave:""El espacio de direcciones virtuales de cada proceso sigue siendo de 32 bits (4GB)"". Un solo programa todavía puede usar como máximo 4GB de memoria. La ventaja de PAE es que permite al servidor ejecutar más programas al mismo tiempo, cada uno usando sus propios 4GB."

"PAE es solo una solución de transición; la solución real es migrar completamente a 64 bits."

Dirección virtual vs. dirección física

"Lo que llamamos 'dirección' anteriormente se refiere principalmente a""dirección física""—la numeración real a nivel de hardware en los módulos de memoria."

"Pero en los sistemas operativos modernos, la dirección que ve tu programa no es la dirección física, sino la""dirección virtual"。

¿Por qué se necesitan direcciones virtuales?

  1. "Aislamiento y protección"": el programa A no puede leer ni escribir la memoria del programa B (de lo contrario, un programa que se bloquee podría dañar todo el sistema)."
  2. "Simplificación de la programación"": cada programa cree que tiene todo el espacio de direcciones para sí mismo (por ejemplo, de 0 a 4GB), sin preocuparse de qué direcciones utilizan otros programas."
  3. "Gestión flexible de la memoria"": el sistema operativo puede escribir temporalmente en el disco duro la memoria poco utilizada (intercambio/paginación) y volver a leerla cuando sea necesario."

"Dentro de la CPU hay una unidad de hardware llamada""MMU (Unidad de Gestión de Memoria)"", que se encarga de traducir en tiempo real la dirección virtual a dirección física."

程序看到的虚拟地址 → [MMU 翻译] → 物理地址 → [地址总线] → 内存条

程序写:  *(0x08048000) = 42
         ↓
MMU 查表: 虚拟页 0x08048 → 物理页 0x1A3F0
         ↓
物理地址: 0x1A3F0000 的内存单元被写入 42

"La dirección virtual es la piedra angular de la estabilidad de los sistemas operativos modernos. Sin las direcciones virtuales y la MMU, un programa que lea o escriba fuera de los límites podría provocar una pantalla azul en todo el sistema—una pesadilla que ocurría a diario en la era del DOS."
