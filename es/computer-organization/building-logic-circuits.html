De las puertas lógicas al sumador

Construcción de circuitos de puertas lógicas

En la lección anterior conocimos cuatro puertas lógicas básicas. En esta lección, las conectaremos para construir circuitos que resuelvan problemas reales.

Una puerta lógica individual es como un tornillo: por sí sola tiene una función limitada. Pero al combinarlas, se pueden construir funciones de cualquier complejidad.

Analogía cotidiana: construir un castillo con bloques LEGO

Imagina que tienes bloques LEGO de cuatro colores:

  • Bloque verde = puerta AND: solo conduce cuando ambos extremos están conectados
  • Bloque naranja = puerta OR: conduce si cualquier extremo está conectado
  • Bloque rojo = puerta NOT: lo encendido se apaga, lo apagado se enciende
  • Bloque morado = puerta XOR: conduce cuando los dos extremos tienen estados diferentes

¿Qué puedes construir con estos bloques?

Un votador: tres personas votan y la mayoría gana. Este es un circuito lógico combinacional típico: se puede implementar conectando puertas AND/OR.

Una cerradura de contraseña: hay que pulsar a la vez varias teclas correctas para abrir. Es esencialmente una cascada de puertas AND — cada tecla corresponde a una entrada, y solo cuando todas las entradas son 1 la salida es 1.

Una alarma: cualquier sensor que se active hace sonar la alarma. Es esencialmente una aplicación de la puerta OR — basta con que un sensor emita 1 para que la alarma suene.

Lógica combinacional vs. lógica secuencial

Antes de profundizar en la construcción de circuitos, distinguimos dos conceptos importantes:

TipoCaracterísticaLa salida depende de¿Tiene memoria?Ejemplos
Lógica combinacionalLa salida está determinada solo por la entrada actualValores de entrada actualesNoSumadores, votadores por mayoría, decodificadores
Lógica secuencialLa salida está determinada por la entrada actual + el estado previoEntrada actual + valores almacenados previamente有Contadores, registros, máquinas de estado

Esta lección se centra en la lógica combinacional.La lógica secuencial se tratará en detalle en la lección 9.

Una forma sencilla de distinguirlas: la lógica combinacional es «lo que ingresas, eso devuelvo» (como una función matemática); la lógica secuencial es «todavía recuerdo lo que ingresaste antes» (como la memoria humana).

Metodología de construcción de circuitos: método de tres pasos

Para construir cualquier circuito lógico combinacional con puertas lógicas, hay un proceso general de tres pasos:

  1. Elaborar la tabla de verdad: enumera todas las combinaciones de entrada y escribe la salida esperada en cada caso.
  2. Escribir la expresión lógica: para cada fila donde la salida sea 1, escribe el «término producto» correspondiente (combinación AND de las entradas) y luego conecta todos los términos producto con OR. Esto se llama forma «suma de productos» (Sum of Products).
  3. Dibujar el diagrama del circuito / escribir código: traduce la expresión lógica a conexiones de circuito con puertas.

A continuación practicamos este método con tres ejemplos de dificultad creciente.

Caso 1: cerradura de contraseña de dos entradas

Requisito: diseñar un circuito simple de verificación de contraseña. Hay dos entradas A y B; solo cuando A=1 y B=1 la salida es 1 (desbloqueada), en los demás casos la salida es 0 (bloqueada).

Este requisito es en realidad una puerta AND. Pero podemos usarlo para demostrar el método de tres pasos:

Paso 1: tabla de verdad

ABSalida esperada Y
000 (bloqueado)
010 (bloqueado)
100 (bloqueado)
111 (desbloqueado)

Paso 2: expresión lógica

Solo la última fila tiene salida 1. El término producto correspondiente es: A AND B.

Por lo tanto: Y = A AND B

Paso 3: implementación del circuito

Solo se necesita una puerta AND, con A y B como entradas y Y como salida.

¿Demasiado simple? Veamos un ejemplo con mayor aplicación práctica.

Caso 2: votador por mayoría (caso central)

Requisito: tres personas (A, B, C) votan sobre una propuesta (1 = a favor, 0 = en contra). Cuando al menos dos votan a favor, la propuesta se aprueba (salida 1).

Este es un votador por mayoría clásico de tres entradas y un caso imprescindible en los libros de circuitos digitales.

Paso 1: elaborar la tabla de verdad

Con tres entradas hay 23= 8 combinaciones:

ABCNúmero de votos a favor¿Se aprueba? YDescripción
00000Nadie a favor
00110Solo C a favor
01010Solo B a favor
01121B y C a favor
10010Solo A a favor

11021A y B a favor

Paso 2: escribir la expresión lógica

Localiza las filas con salida 1 (filas 4, 6, 7, 8) y escribe un término producto para cada una:

  • Fila 4: NOT(A) AND B AND C
  • Fila 6: A AND NOT(B) AND C
  • Fila 7: A AND B AND NOT(C)
  • Fila 8: A AND B AND C

Conecta con OR: Y = (NOT(A) AND B AND C) OR (A AND NOT(B) AND C) OR (A AND B AND NOT(C)) OR (A AND B AND C)

Esta expresión, aunque parece un poco larga, es muy clara a nivel lógico:Y es 1 si y solo si cualquiera de dos o tres entradas es 1。

Paso 3: dibujar el diagrama del circuito con SVG

Las tres puertas AND detectan respectivamente si los pares «AB», «BC» y «AC» son 11, y luego la puerta OR resume el resultado.

# Votador por mayoría de tres entradas (demo runoob)
# Requisito: tres personas votan, se aprueba (salida 1) solo si al menos dos votan a favor (1)

# ----- Reutilizar las puertas lógicas básicas de la lección 6 -----
def AND(a, b):
    return 1 if a == 1 and b == 1 else 0

def OR(a, b):
    return 1 if a == 1 or b == 1 else 0

def NOT(a):
    return 1 if a == 0 else 0


# ----- Método 1: forma estándar de suma de productos (SOP) -----
def majority_voter_sop(a, b, c):
    """
Implementación del votador por mayoría mediante «suma de productos».
Se deduce directamente de la tabla de verdad: localiza todas las filas con salida 1,
escribe un término producto para cada fila y luego conéctalos con OR.
    """
    term1 = AND(AND(NOT(a), b), c)       # ~A·B·C
    term2 = AND(AND(a, NOT(b)), c)       # A·~B·C
    term3 = AND(AND(a, b), NOT(c))       # A·B·~C
    term4 = AND(AND(a, b), c)            # A·B·C
    return OR(OR(term1, term2), OR(term3, term4))


# ----- Método 2: forma simplificada optimizada -----
def majority_voter_optimized(a, b, c):
    """
Implementación optimizada del votador por mayoría: Y = AB + BC + AC.
Esta forma requiere menos puertas, pero es lógicamente equivalente al método 1.

¿Por qué son equivalentes?
Al expandir la forma SOP del método 1, se puede simplificar usando la ley de absorción del álgebra de Boole:
    ~A·B·C + A·~B·C + A·B·~C + A·B·C
    = (~A·B·C + A·B·C) + (A·~B·C + A·B·C) + (A·B·~C + A·B·C)
    = B·C·(~A+A) + A·C·(~B+B) + A·B·(~C+C)
    = B·C + A·C + A·B
    """
    return OR(OR(AND(a, b), AND(b, c)), AND(a, c))

Caso 3: comparador de un bit

Requisito: Comparar dos números binarios de 1 bit A y B. Produce tres señales: A > B, A = B, A < B

Este es un circuito fundamental muy importante: los comparadores de múltiples bits y las evaluaciones de condiciones en la CPU se derivan todos de aquí.

Paso 1: Tabla de verdad

ABA > BA = BA < B
00010
01001
10100
11010

Paso 2: Expresión lógica

Observa la tabla de verdad:

  • A > B es 1 si y solo si: A=1 AND B=0. Por lo tanto: Greater = A AND NOT(B)
  • A = B es 1 si y solo si: A y B son iguales. Por lo tanto: Equal = NOT(A XOR B), o bien Equal = (A AND B) OR (NOT(A) AND NOT(B))
  • A < B es 1 si y solo si: A=0 AND B=1. Por lo tanto: Less = NOT(A) AND B

Observa que la detección de A = B está estrechamente relacionada con la puerta XOR. La salida XOR igual a 1 significa «diferente»; aplicarle NOT produce «igual».

Paso 3: Implementación en código

Ejemplo

# Comparador de 1 bit (demostración de runoob)
# Compara dos números binarios de 1 bit A y B

def AND(a, b):
    return 1 if a == 1 and b == 1 else 0

def OR(a, b):
    return 1 if a == 1 or b == 1 else 0

def NOT(a):
    return 1 if a == 0 else 0


def one_bit_comparator(a, b):
    """
Comparador de 1 bit: compara A y B.
Devuelve la tupla de tres elementos (Greater, Equal, Less)
    """
    greater = AND(a, NOT(b))   # A > B: A=1 y B=0
    less = AND(NOT(a), b)      # A < B: A=0 y B=1
    # A = B: no es ni greater ni less
    # Equivalente a NOT(A XOR B); aquí se usa otra implementación
    equal = AND(NOT(greater), NOT(less))
    return (greater, equal, less)

def AND(a, b):
    return 1 if a == 1 and b == 1 else 0

def NOT(a):
    return 1 if a == 0 else 0


def decoder_2to4(a1, a0):
    """
Devuelve la lista [Y0, Y1, Y2, Y3],
donde exactamente uno es 1 y los demás son 0.
# Imprime la tabla de verdad
    """
    Y0 = AND(NOT(a1), NOT(a0))  # 00 → Y0

    Y2 = AND(a1, NOT(a0))       # 10 → Y2
    Y3 = AND(a1, a0)            # 11 → Y3
    return [Y0, Y1, Y2, Y3]

Puertas universales: la particularidad de NAND y NOR

Puertas universales: lo especial de NAND y NOR

Puerta NAND = AND + NOT

, es decir, primero se realiza AND y luego se niega. NAND y NOR se denominan «puertas universales» (Universal Gates) porque cada una por sí sola puede implementar todas las funciones booleanas.¿Por qué los chips prefieren NAND/NOR? Porque en el proceso CMOS:

La puerta NAND solo necesita 4 transistores, mientras que la AND necesita 6 (AND = NAND + NOT)

  • La velocidad de conmutación de la puerta NAND es más rápida
  • Por lo tanto, en los chips reales, la función AND se implementa internamente con NAND + NOT.
  • A continuación, demostremos la «universalidad» de la puerta NAND:

def NAND(a, b):
    Y = 0 si y solo si a=1 y b=1"""

    return 0 if a == 1 and b == 1 else 1


# Implementar AND con NAND: AND(A,B) = NOT(NAND(A,B)) = NAND(NAND(A,B), NAND(A,B))
def NOT_from_NAND(a):
    return NAND(a, a)


# Implementar OR con NAND: OR(A,B) = NAND(NOT(A), NOT(B))

    nand_ab = NAND(a, b)
    return NAND(nand_ab, nand_ab)

    return NAND(NOT_from_NAND(a), NOT_from_NAND(b))
