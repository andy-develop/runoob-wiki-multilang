JavaScript Cierres

Las variables en JavaScript pueden ser locales o globales.

Los cierres se pueden usar para variables privadas.

Variables Globales

Una función puede acceder a las variables definidas dentro de la función, por ejemplo:

Ejemplo

function myFunction() { var a = 4; return a * a; }

Pruébalo »

Una función también puede acceder a variables definidas fuera de la función, por ejemplo:

Ejemplo

var a = 4; function myFunction() { return a * a; }

Pruébalo »

En el último ejemplo,aes unaglobalvariable.

En una página web, las variables globales pertenecen al objeto window.

Las variables globales se pueden usar en todos los scripts de la página.

En el primer ejemplo,aes unalocalvariable.

Las variables locales solo se pueden usar dentro de la función donde se definen. No están disponibles para otras funciones o código de script.

Las variables globales y locales, incluso si tienen el mismo nombre, son dos variables diferentes. Modificar una no afecta el valor de la otra.

Si al declarar una variable no se usa lavarpalabra clave, entonces es una variable global, incluso si se define dentro de una función.

Ciclo de Vida de las Variables

El ámbito de las variables globales es global, es decir, en todo el programa JavaScript, las variables globales están en todas partes.

Las variables declaradas dentro de una función solo funcionan dentro de la función. Estas variables son locales y su ámbito es local; los parámetros de la función también son locales y solo funcionan dentro de la función.

El Problema del Contador

Imagina que quieres contar algunos valores y que el contador esté disponible en todas las funciones.

Puedes usar una variable global, y la función incrementa el contador:

Ejemplo

var counter = 0; function add() { return counter += 1; } add(); add(); add(); //El contador ahora es 3

Pruébalo »

El valor del contador cambia cuando se ejecuta la función add().

Pero aquí está el problema: cualquier script en la página puede cambiar el contador, incluso sin llamar a la función add().

Si declaro el contador dentro de la función, no se puede modificar el valor del contador sin llamar a la función:

Ejemplo

function add() { var counter = 0; return counter += 1; } add(); add(); add(); //La intención era mostrar 3, pero contra lo esperado, ¡siempre muestra 1!

Pruébalo »

El código anterior no mostrará el resultado correcto; cada vez que llamo a la función add(), el contador se establece en 1.

Las funciones anidadas en JavaScript pueden resolver este problema.

Funciones Anidadas en JavaScript

Todas las funciones pueden acceder a variables globales.

De hecho, en JavaScript, todas las funciones pueden acceder al ámbito de su nivel superior.

JavaScript admite funciones anidadas. Las funciones anidadas pueden acceder a las variables de la función del nivel superior.

En este ejemplo, la función anidadaplus()puede acceder a la variablecounterde la función padre:

Ejemplo

function add() { var counter = 0; function plus() {counter += 1;} plus(); return counter; }

Pruébalo »

Si pudiéramos acceder desde fuera a laplus()función, podríamos resolver el problema del contador.

También necesitamos asegurarnos de quecounter = 0solo se ejecute una vez.

Necesitamos cierres.

Cierres en JavaScript

¿Recuerdas la función de auto-invocación? ¿Qué hace esta función?

Ejemplo

var add = (function () { var counter = 0; return function () {return counter += 1;} })(); add(); add(); add(); //El contador es 3

Pruébalo »

Análisis del Ejemplo

La variableaddadd recibe el valor de retorno de la función de auto-invocación.

La función de auto-invocación se ejecuta solo una vez. Establece el contador en 0 y devuelve la expresión de función.

La variable add se puede usar como una función. La parte genial es que puede acceder al contador del ámbito superior de la función.

Esto se llama cierre enJavaScript.Hace posible que las funciones tengan variables privadas.

El contador está protegido por el ámbito de la función anónima y solo se puede modificar mediante el método add.

El cierre es un mecanismo para proteger variables privadas. Crea un ámbito privado cuando la función se ejecuta, protegiendo así las variables privadas internas de interferencias externas.

De forma intuitiva, un cierre es como un entorno de pila que no se destruye.

    Supongo que mucha gente se siente confundida con este problema del contador al final; a mí también me pasó.

    Después de verificar con código, descubrí que el truco está en:

    var add = (function () {
    var counter = 0;
    return function () {return counter += 1;}
})();

    Nota: ¿por qué el código anterior no escribe directamente function add(){...} sino que asigna la función a la variable add?

    Solemos asumir que cada vez que se llama a add() se vuelve a ejecutar todo el bloque de código de add(), pero no es así.

    Observa el return en el método add: no devuelve valores numéricos como 1, 2, 3, sino que devuelve un método, y ese método se asigna a la variable add.

    Entonces, después de que la función se ejecuta una vez, lo que finalmente se asigna a add es el código return counter += 1.

    Por lo tanto, cada llamada posterior a add() en realidad está llamando a return counter += 1.

    Combinando esto con lo dicho antes en el artículo, el cierre mantiene las variables locales del método padre y no se destruye cuando el método padre se destruye, por lo que este counter proviene en realidad de la variable creada durante la primera ejecución de la función.

    Después de ver la discusión de todos arriba, también daré algunas opiniones propias.

    Sobre la primera controversia, si la existencia y el uso de la clausura son razonables y necesarios, creo que la respuesta es '¡SÍ!'.

    Mi opinión personal es: usar la clausura como método de implementación para acceder a las propiedades privadas de un objeto es más acorde con la lógica de pensamiento de la programación orientada a objetos y con la tendencia de desarrollo de la programación moderna.

    Por ejemplo: si establecemos el valor de 'count' en el objeto contador como propiedad pública, ciertamente podemos resolver el mismo problema sin usar el método de la clausura. Pero si miramos un poco más a largo plazo, la función contador puede ser solo una pequeña funcionalidad dentro de todo el código. Además de esta funcionalidad, habrá módulos de funcionalidad similares, como la función para calcular el promedio, la función de estadística mixta, etc. Entonces, ¿debemos hacer que todas las propiedades clave de las demás funciones sean propiedades globales para que Window pueda llamarlas directamente?

    Si todas se establecen como propiedades globales, ¿acaso el código no está degenerando? El encapsulamiento de los objetos es cada vez menos perfecto, acercándose más a la filosofía de programación orientada a procesos. Al mismo tiempo, causará mayores inconvenientes para futuras modificaciones y actualizaciones.

    Sobre el pensamiento de programación orientada a objetos: ¿qué es? ¿Cuáles son sus beneficios? Creo que no necesito profundizar más aquí.

    Una buena programación orientada a objetos consiste en lograr un encapsulamiento completo y proporcionar interfaces para acceder a los datos internos.

    Si en el futuro queremos modificar la funcionalidad del contador, solo necesitamos modificar sus propiedades internas. No hay que considerar ajustes a las variables globales, porque la implementación concreta a nivel global se realiza mediante funciones de clausura.

    Finalmente, describamos con un ejemplo la función de clausura:

    Vas a un restaurante a comer. El área del salón equivale a la región global (public), y la función de clausura equivale al camarero. Si quieres pedir platos, solo tienes que buscar al camarero.

    Si no hay camarero, ¿cómo sabes qué platos prepara la cocina? Además, la cocina es un lugar prohibido para los no autorizados (la cocina equivale al interior de la función; desde el exterior no puedes acceder, ni siquiera te dejan entrar).

    Entonces la cocina solo podría sacar todos los platos que deberían estar solo en la cocina para mostrártelos. (Convertir la propiedad count interna en una propiedad global). Entonces el restaurante seguramente estará hecho un desastre y no será digno de un gran salón.

    Pero si hay un camarero, puedes conocer los platos de la cocina a través del camarero y completar el pedido. El camarero (función de clausura) permite que el exterior acceda directamente a las propiedades internas de una función.

    La clausura esla interfaz para acceder a propiedades privadas.. Como programador que siempre ha estado aprendiendo C++, al ver esto inmediatamente me llené de lágrimas.

    Bueno, pero al ver el debate que estalló aquí, me gustaría señalar algo:La clausura es necesaria para implementar la programación orientada a objetos.。

    En realidad, el 11.º piso no entendió en absoluto la clausura, e incluso no entendió el significado de la orientación a objetos. El elemento básico de la orientación a objetos esencapsulamiento: quizás necesitamos variables 'private', es decir, propiedades que no se pueden cambiar directamente, sino solo mediante métodos. En cuanto a la supuesta afirmación de que 'se puede sustituir la clausura por objetos', el verdadero significado de la clausura debería aplicarse en los constructores de objetos.

    Por ejemplo, queremos que un objeto tenga una propiedad que solo permita aumentar y no disminuir, y que cada vez solo se pueda añadir un número par con la función add. Aquí la clausura demuestra su utilidad. Se puede decir que este ejemplo resuelve de manera bastante unificada todos los problemas planteados anteriormente.

    function NumPro(val){
    var counter=val;
    this.add=function(num){
        if(num%2==0) counter+=num;
    }
    this.num=function(){
        return counter;
    }
}
//alert(counter);      //报错
alert(NumPro.counter); //输出undefined(显而易见的)
var a=new NumPro(0);
alert(a.counter);      //输出undefined(不在this中)
alert(a.num());        //输出0
a.add(2);
alert(a.num());        //输出2
a.add(1);
alert(a.num());        //输出2(仅允许偶数)
a.add(10);
alert(a.num());        //输出12
var b=new NumPro(-2);
alert(b.num());        //输出-2

    Obviamente, la clausura no se debe solamente a que 'las variables en el ámbito no se destruyen': si se intenta mostrar la variable directamente, se produce un error, y tampoco se puede acceder a la propiedad mediante el nombre de la función; los valores mostrados en dos objetos no tienen ninguna relación entre sí. Al mismo tiempo, puede limitar la operación directa sobre las propiedades: las variables que no están en 'this' no se pueden acceder desde el exterior.

    Por lo tanto, la clausura está diseñada intencionalmente, no es un bug. De hecho, si se ha tenido contacto con Java u otros lenguajes orientados a objetos, se sentirá una profunda impresión: la orientación a objetos de Javascript a menudo es sorprendente (ni siquiera tiene Class). Pero esto no significa que no pueda implementar el efecto 'private' de otros lenguajes. Visto así, la clausura aquí simplemente cambia 'this.counter = num' por 'var counter = num'.

    Por supuesto, la clausura no es exactamente solo esto; por ejemplo, en el artículo, devolver una función(nombre)es el método ingenioso. Sin embargo, la clausura significa que las variables privadas dentro de una función no se destruyen inmediatamente y pueden ser accedidas por funciones anidadas. Esto es suficiente.

    Además, los experimentos demuestran que una función no solo puede acceder a las variables privadas de la función de nivel superior: también puede acceder a las variables de la función padre de la función padre, e incluso de niveles superiores (pero no se recomienda hacerlo... esto parece que solo suele reducir la legibilidad del código). Sin embargo, si se usa:

    NumPro.prototype.numEx=function(){
    return counter;
}

    Si 'counter' está definido dentro de la función NumPro, esta función reportará un error después de usarse (su función prototipo obviamente no contiene la variable 'counter', e incluso si la contuviera, no está claro cómo manejarla).
