Plantillas de Django

El sistema de plantillas de Django (Template System) es un componente central que se utiliza para separar la lógica de negocio (Python) de la capa de presentación (HTML), y permite a los desarrolladores generar páginas HTML dinámicamente mediante etiquetas y variables simples.

En el capítulo anterior utilizamosdjango.http.HttpResponse()para generar"Hello World！", esta forma mezcla los datos con las vistas y no se ajusta al pensamiento MVT de Django.

En este capítulo presentaremos en detalle la aplicación de las plantillas de Django. Una plantilla es un texto que se utiliza para separar la forma de presentación del documento de su contenido.

FunciónSintaxis/EjemploCaso de uso
Renderizado de variables{{ variable }}Mostrar datos dinámicamente
Control lógico{% if %}, {% for %}Renderizado condicional/bucles
Herencia de plantillas{% extends %}, {% block %}Evitar estructuras HTML repetidas
Archivos estáticos{% static 'path' %}Cargar CSS/JS/imágenes
Filtros personalizados@register.filterAmpliar las funciones de las plantillas

Filtros

Sintaxis de plantillas:
{{ 变量名 | 过滤器：可选参数 }}

Los filtros de plantilla pueden modificar la variable antes de que se muestre. Los filtros usan el carácter de tubería (pipe), como se muestra a continuación:

{{ name|lower }}

La variable {{ name }} se procesa con el filtro lower, que convierte el texto de mayúsculas a minúsculas.

Los filtros de tubería pueden ser *encadenados*, es decir, la salida de una tubería de filtro puede ser la entrada de la siguiente:

{{ my_list|first|upper }}

El ejemplo anterior toma el primer elemento y lo convierte a mayúsculas.

Algunos filtros tienen parámetros. Los parámetros del filtro siguen a los dos puntos y siempre se incluyen entre comillas dobles. Por ejemplo:

{{ bio|truncatewords:"30" }}

Esto mostrará las primeras 30 palabras de la variable bio.

Otros filtros:

  • addslashes: añade una barra invertida antes de cualquier barra invertida, comilla simple o comilla doble.
  • date: formatea un objeto date o datetime según el parámetro de cadena de formato especificado. Ejemplo:
    {{ pub_date|date:"F j, Y" }}
  • length: devuelve la longitud de la variable.

default

default proporciona un valor predeterminado a la variable.

Si el valor booleano de la variable pasada por views es false, se usa el valor predeterminado especificado.

Los siguientes valores son false:

0  0.0  False  0j  ""  []  ()  set()  {}  None

safe

Marca la cadena como segura, no requiere escape.

Solo se puede usar safe si se garantiza que los datos enviados desde views.py son absolutamente seguros.

Tiene el mismo efecto que mark_safe en el backend views.py.

Django automáticamente escapa la sintaxis de etiquetas pasada desde views.py a los archivos HTML, invalidando su significado. Añadir el filtro safe le indica a Django que esos datos son seguros y no deben escaparse, permitiendo que su significado sea efectivo.

Etiquetas if/else

La sintaxis básica es la siguiente:

{% if condition %}
     ... display
{% endif %}

O:

{% if condition1 %}
   ... display 1
{% elif condition2 %}
   ... display 2
{% else %}
   ... display 3
{% endif %}

Determina si se muestra según la condición. if/else admite anidamiento.

La etiqueta {% if %} acepta las palabras clave and, or o not para evaluar múltiples variables, o para negar la variable (not), por ejemplo:

{% if athlete_list and coach_list %}
     athletes 和 coaches 变量都是可用的。
{% endif %}

def runoob(request):
    views_num = 88
    return render(request, "runoob.html", {"num": views_num})

Etiqueta for

{% for %} nos permite iterar sobre una secuencia.

De manera similar al caso de la sentencia for de Python, la sintaxis del bucle es for X in Y, donde Y es la secuencia a iterar y X es el nombre de la variable utilizada en cada bucle concreto.

En cada bucle, el sistema de plantillas renderiza{% for %} 和 {% endfor %}todo el contenido entre.

Por ejemplo, dada una lista de atletas con la variable athlete_list, podemos usar el siguiente código para mostrar la lista: 
<ul>
{% for athlete in athlete_list %}
    <li>{{ athlete.name }}</li>
{% endfor %}
</ul>

    return render(request, "runoob.html", {"views_list": views_list})

Código del archivo HelloWorld/templates/runoob.html:

Dentro de la etiqueta {% for %} se puede obtener el número de iteración mediante la variable {{forloop}}.
  • forloop.counter: obtiene el número de iteración en orden, comenzando desde 1
  • forloop.counter0: obtiene el número de iteración en orden, comenzando desde 0
  • forloop.revcounter: obtiene el número de iteración en orden inverso, con el último número 1
  • forloop.revcounter0: obtiene el número de iteración en orden inverso, con el último número 0
  • forloop.first (normalmente se usa con la etiqueta if): devuelve True para el primer dato y False para los demás.
  • forloop.last (generalmente se usa con la etiqueta if): el último dato devuelve True, los demás devuelven False.

csrf_token

csrf_token se usa en formularios form; su función es la protección contra falsificación de solicitudes entre sitios.

Si no se usa{% csrf_token %}la etiqueta, al usar el formulario form, si se intenta redirigir la página se producirá un error 403 de permisos.

Si se usa{% csrf_token %}la etiqueta, al enviar datos con el formulario form, se realizará correctamente.

Análisis:

Primero, se envía una solicitud al servidor para obtener la página de inicio de sesión; en este momento, el middleware csrf genera automáticamente una etiqueta input oculta. El valor del atributo value en esa etiqueta es una cadena aleatoria. El usuario obtiene la página de inicio de sesión y también obtiene esta etiqueta input oculta.

Luego, cuando el usuario necesita usar el formulario form para enviar datos, esta etiqueta input se envía junto con ellos al middleware csrf. La razón es que al enviar datos con el formulario form se incluyen todas las etiquetas input. Cuando el middleware csrf recibe los datos, comprueba si esa cadena aleatoria es la misma que le envió al usuario la primera vez. Si lo es, el envío de datos es exitoso; si no, devuelve un error 403 de permisos.

Herencia de plantillas

Las plantillas pueden reutilizarse mediante la herencia para reducir contenido redundante.

Por lo general, el encabezado y el pie de página de una página web son iguales; podemos lograr la reutilización mediante la herencia de plantillas.

La plantilla padre se utiliza para colocar contenido reutilizable; la plantilla hija hereda el contenido de la plantilla padre y coloca su propio contenido.

Plantilla padre

Etiqueta block...endblock:Es el área reservada en la plantilla padre; esta área se deja para que la plantilla hija complete contenido diferente. Los nombres de las distintas áreas reservadas no pueden ser iguales.

{% block 名称 %} 
预留给子模板的区域，可以设置设置默认内容
{% endblock 名称 %}

Plantilla hija

La plantilla hija usa la etiqueta extends para heredar de la plantilla padre:

{% extends "父模板路径"%}

Si la plantilla hija no establece el contenido del área reservada de la plantilla padre, se utiliza el contenido predeterminado definido en la plantilla padre; por supuesto, también se puede dejar vacío.

La plantilla hija establece el contenido del área reservada de la plantilla padre:

{ % block 名称 % }
内容 
{% endblock 名称 %}

A continuación, primero creamos el archivo base.html en el directorio templates del proyecto anterior; el código es el siguiente:

Código del archivo HelloWorld/templates/base.html:

<!DOCTYPE html> <html> <head> <meta charset="utf-8"> <title>Tutorial para novatos (runoob.com)</title> </head> <body> <h1>Hello World!</h1> <p>Tutorial para novatos Django Test.</p> {% block mainbody %} <p>original</p> {% endblock %} </body> </html>

En el código anterior, la etiqueta block llamada mainbody es la parte que puede ser reemplazada por los herederos (plantillas hijas).

Todas las etiquetas {% block %} le indican al motor de plantillas que las plantillas hijas pueden sobrescribir estas partes.

runoob.html hereda de base.html y reemplaza bloques específicos. El código modificado de runoob.html es el siguiente:

Código del archivo HelloWorld/templates/runoob.html:

{%extends "base.html" %} {% block mainbody %} <p>heredóbase.htmlarchivo</p> {% endblock %}

La primera línea de código indica que runoob.html hereda el archivo base.html. Puede verse que aquí las etiquetas block con el mismo nombre se utilizan para reemplazar los bloques correspondientes de base.html.
