Servlet Introducción

¿Qué es Servlet?

Java Servlet es un programa que se ejecuta en un servidor web o en un servidor de aplicaciones. Actúa como una capa intermedia entre las solicitudes de los navegadores web u otros clientes HTTP y la base de datos o las aplicaciones en el servidor HTTP.

Con Servlet, puede recopilar las entradas del usuario desde formularios de páginas web, presentar registros de una base de datos u otras fuentes, y también crear páginas web dinámicamente.

Java Servlet normalmente puede lograr el mismo efecto que los programas implementados con CGI (Common Gateway Interface, Interfaz de puerta de enlace común). Sin embargo, en comparación con CGI, Servlet tiene las siguientes ventajas:

  • El rendimiento es notablemente mejor.
  • Servlet se ejecuta dentro del espacio de direcciones del servidor web. De esta manera, no es necesario crear un proceso separado para manejar cada solicitud del cliente.
  • Servlet es independiente de la plataforma porque está escrito en Java.
  • El administrador de seguridad de Java en el servidor impone una serie de restricciones para proteger los recursos de la computadora del servidor. Por lo tanto, Servlet es confiable.
  • Toda la funcionalidad de la biblioteca de clases de Java está disponible para Servlet. Puede interactuar con applets, bases de datos u otro software mediante los mecanismos de sockets y RMI.

Tareas de Servlet

Servlet realiza las siguientes tareas principales:

  • Leer los datos explícitos enviados por el cliente (navegador). Esto incluye formularios HTML en páginas web, o también puede ser formularios de applets o programas de cliente HTTP personalizados.
  • Leer los datos implícitos de la solicitud HTTP enviados por el cliente (navegador). Esto incluye cookies, tipos de medios y formatos de compresión que el navegador puede entender, etc.
  • Procesar los datos y generar resultados. Este proceso puede requerir acceder a una base de datos, ejecutar llamadas RMI o CORBA, invocar servicios web, o simplemente calcular la respuesta correspondiente.
  • Enviar datos explícitos (es decir, documentos) al cliente (navegador). El formato de este documento puede ser variado, incluidos archivos de texto (HTML o XML), archivos binarios (imágenes GIF), Excel, etc.
  • Enviar respuestas HTTP implícitas al cliente (navegador). Esto incluye informar al navegador u otros clientes del tipo de documento que se devuelve (por ejemplo, HTML), configurar cookies y parámetros de caché, y otras tareas similares.

Paquetes de Servlet

Java Servlet es una clase de Java que se ejecuta en un servidor web con un intérprete que admite las especificaciones de Java Servlet.

Servlet puede usarjavax.servlet 和 javax.servlet.httpel paquete para crearse, que es una parte estándar de Java Enterprise Edition, una versión extendida de la biblioteca de clases de Java que admite grandes proyectos de desarrollo.

Estas clases implementan las especificaciones de Java Servlet y JSP. Al momento de escribir este tutorial, las versiones correspondientes de ambos son Java Servlet 2.5 y JSP 2.1 respectivamente.

Java Servlet se crea y compila como cualquier otra clase de Java. Después de instalar los paquetes de Servlet y agregarlos a la ruta de clase (Classpath) en su computadora, puede compilar Servlet con el compilador de Java del JDK o cualquier otro compilador.

¿Qué sigue?

A continuación, este tutorial lo guiará paso a paso para configurar su entorno de Servlet, a fin de comenzar a usar Servlet más adelante. Por lo tanto, abróchese el cinturón y ¡comience con nosotros el viaje de aprendizaje de Servlet! Estamos seguros de que disfrutará mucho este tutorial.

    Hay tres formas de crear Servlet.

    1. Implementar la interfaz Servlet

    Debido a que se implementa la interfaz Servlet, necesitamos implementar los métodos de la interfaz.

    A continuación también explicamos el proceso de ejecución de Servlet, es decir, el ciclo de vida de Servlet.

    //Servlet的生命周期:从Servlet被创建到Servlet被销毁的过程
//一次创建，到处服务
//一个Servlet只会有一个对象，服务所有的请求
/*
 * 1.实例化（使用构造方法创建对象）
 * 2.初始化  执行init方法
 * 3.服务     执行service方法
 * 4.销毁    执行destroy方法
 */
public class ServletDemo1 implements Servlet {

    //public ServletDemo1(){}

     //生命周期方法:当Servlet第一次被创建对象时执行该方法,该方法在整个生命周期中只执行一次
    public void init(ServletConfig arg0) throws ServletException {
                System.out.println("=======init=========");
        }

    //生命周期方法:对客户端响应的方法,该方法会被执行多次，每次请求该servlet都会执行该方法
    public void service(ServletRequest arg0, ServletResponse arg1)
            throws ServletException, IOException {
        System.out.println("hehe");

    }

    //生命周期方法:当Servlet被销毁时执行该方法
    public void destroy() {
        System.out.println("******destroy**********");
    }
//当停止tomcat时也就销毁的servlet。
    public ServletConfig getServletConfig() {

        return null;
    }

    public String getServletInfo() {

        return null;
    }
}

    2. Heredar de la clase GenericServlet

    Implementa los métodos de la interfaz Servlet excepto service, aunque este método lo usamos muy raramente.

    public class ServletDemo2 extends GenericServlet {

    @Override
    public void service(ServletRequest arg0, ServletResponse arg1)
            throws ServletException, IOException {
        System.out.println("heihei");

    }
}

    3. Heredar de la clase HttpServlet 

    public class ServletDemo3 extends HttpServlet {

    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {
        System.out.println("haha");
    }

    @Override
    protected void doPost(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {
        System.out.println("ee");
        doGet(req,resp);
    }

}

    Sobre la relación entre HttpServlet, GenericServlet y Servlet

    Para una clase Servlet, el método que más usamos en el día a día es heredar de la clase HttpServlet, que proporciona métodos relacionados con HTTP. HttpServlet extiende la clase GenericServlet, y la clase GenericServlet a su vez implementa las interfaces Servlet y ServletConfig.

    Servlet

    La clase Servlet proporciona cinco métodos, de los cuales tres son métodos del ciclo de vida y dos son métodos ordinarios. No entraré en detalles sobre los métodos de la clase Servlet; principalmente complementaré las ideas de implementación de las otras dos clases.

    GenericServlet

    GenericServlet es una clase abstracta que implementa la interfaz Servlet y proporciona implementaciones predeterminadas para init(), destroy() y service(). En GenericServlet, se realizan principalmente las siguientes tareas:

    • Asignar el ServletConfig en init() a una variable a nivel de clase, que puede obtenerse mediante getServletConfig();
    • Proporcionar implementaciones predeterminadas para todos los métodos de Servlet;
    • Poder llamar directamente a los métodos de ServletConfig;

    La estructura básica es la siguiente:

    abstract class GenericServlet implements Servlet,ServletConfig{
 
   //GenericServlet通过将ServletConfig赋给类级变量
   private trServletConfig servletConfig;
 
   public void init(ServletConfig servletConfig) throws ServletException {

      this.servletConfig=servletConfig;

      /*自定义init()的原因是：如果子类要初始化必须覆盖父类的init() 而使它无效 这样
       this.servletConfig=servletConfig不起作用 这样就会导致空指针异常 这样如果子类要初始化，
       可以直接覆盖不带参数的init()方法 */
      this.init();
   }
   
   //自定义的init()方法，可以由子类覆盖  
   //init()不是生命周期方法
   public void init(){
  
   }
 
   //实现service()空方法，并且声明为抽象方法，强制子类必须实现service()方法 
   public abstract void service(ServletRequest request,ServletResponse response) 
     throws ServletException,java.io.IOException{
   }
 
   //实现空的destroy方法
   public void destroy(){ }
}

    Lo anterior es la idea general de implementación de GenericServlet. Se puede ver que si heredamos esta clase, debemos sobrescribir el método service() para manejar las solicitudes.

    HttpServlet

    HttpServlet también es una clase abstracta. Hereda y encapsula aún más GenericServlet, lo que hace que su uso sea más simple y conveniente. Dado que extiende el contenido de HTTP, también necesita usar HttpServletRequest y HttpServletResponse, que son respectivamente subclases de ServletRequest y ServletResponse. El código es el siguiente:

    abstract class HttpServlet extends GenericServlet{
 
   //HttpServlet中的service()
   protected void service(HttpServletRequest httpServletRequest,
                       HttpServletResponse httpServletResponse){
        //该方法通过httpServletRequest.getMethod()判断请求类型调用doGet() doPost()
   }
 
   //必须实现父类的service()方法
   public void service(ServletRequest servletRequest,ServletResponse servletResponse){
      HttpServletRequest request;
      HttpServletResponse response;
      try{
         request=(HttpServletRequest)servletRequest;
         response=(HttpServletResponse)servletResponse;
      }catch(ClassCastException){
         throw new ServletException("non-http request or response");
      }
      //调用service()方法
      this.service(request,response);
   }
}

    Podemos ver que en HttpServlet se realizan operaciones predeterminadas para todos los métodos del Servlet original, sin necesidad de destruir, inicializar o llamar a service() explícitamente. En HttpServlet, se define un nuevo método service() personalizado, que determina el tipo de solicitud mediante el método getMethod(), y así llama a doGet() o doPost() para manejar las solicitudes GET y POST. El usuario solo necesita heredar HttpServlet y luego sobrescribir el método doPost() o doGet() para manejar las solicitudes.

    Generalmente usamos la herencia de HttpServlet para definir un servlet.
