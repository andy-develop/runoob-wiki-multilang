Servlet Solicitud HTTP del cliente

Cuando el navegador solicita una página web, envía información específica al servidor web; esta información no puede leerse directamente porque se transmite como parte de las cabeceras de la solicitud HTTP. Puede consultarel protocolo HTTPpara obtener más información relacionada.

A continuación se muestra la información importante de cabeceras proveniente del navegador, que puede utilizar con frecuencia en la programación web:

CabeceraDescripción
AcceptEsta cabecera especifica los tipos MIME que el navegador u otros clientes pueden manejar. Los valoresimage/png 或 image/jpegson los dos valores posibles más comunes.
Accept-CharsetEsta cabecera especifica el conjunto de caracteres que el navegador puede utilizar para mostrar información. Por ejemplo, ISO-8859-1.
Accept-EncodingEsta cabecera especifica los tipos de codificación que el navegador sabe cómo manejar. Los valoresgzip 或 compressson los dos valores posibles más comunes.
Accept-LanguageEsta cabecera especifica el idioma preferido del cliente; en este caso, el Servlet generará resultados en varios idiomas. Por ejemplo, en, en-us, ru, etc.
AuthorizationEsta cabecera se utiliza para que el cliente se identifique al acceder a páginas web protegidas por contraseña.
ConnectionEsta cabecera indica si el cliente puede manejar conexiones HTTP persistentes. Las conexiones persistentes permiten al cliente u otros navegadores recuperar múltiples archivos mediante una sola solicitud. El valorKeep-Alivesignifica que se utiliza una conexión persistente.
Content-LengthEsta cabecera solo se aplica a solicitudes POST y proporciona el tamaño de los datos POST (en bytes).
CookieEsta cabecera devuelve al servidor las cookies que fueron enviadas previamente al navegador.
HostEsta cabecera especifica el host y el puerto de la URL original.
If-Modified-SinceEsta cabecera indica que el cliente desea la página solo si ha sido modificada después de la fecha especificada. Si no hay un nuevo resultado disponible, el servidor enviará un código 304, indicandoNot Modifiedla cabecera.
If-Unmodified-SinceEsta cabecera es lo opuesto a If-Modified-Since; especifica que la operación tendrá éxito solo si el documento es anterior a la fecha especificada.
RefererEsta cabecera indica la URL de la página web referente. Por ejemplo, si usted está en la página 1 y hace clic en un enlace a la página 2, cuando el navegador solicite la página 2, la URL de la página 1 se incluirá en la cabecera Referer.
User-AgentEsta cabecera identifica al navegador u otro cliente que realiza la solicitud, y puede devolver contenido diferente a diferentes tipos de navegadores.

Métodos para leer cabeceras HTTP

Los siguientes métodos se pueden utilizar en programas Servlet para leer cabeceras HTTP. Estos métodos están disponibles a través delHttpServletRequestobjeto.

N.ºMétodo y descripción
1Cookie[] getCookies()
Devuelve una matriz que contiene todos los objetos Cookie que el cliente envió con la solicitud.
2Enumeration getAttributeNames()
Devuelve una enumeración que contiene los nombres de los atributos disponibles para la solicitud.
3Enumeration getHeaderNames()
Devuelve una enumeración que contiene todos los nombres de cabeceras incluidos en la solicitud.
4Enumeration getParameterNames()
Devuelve una enumeración de objetos String que contiene los nombres de los parámetros incluidos en la solicitud.
5HttpSession getSession()
Devuelve la sesión actual asociada con la solicitud, o si la solicitud no tiene sesión, crea una.
6HttpSession getSession(boolean create)
Devuelve el HttpSession actual asociado con la solicitud, o si no hay una sesión actual y create es verdadero, devuelve una nueva sesión.
7Locale getLocale()
Basado en la cabecera Accept-Language, devuelve la configuración regional preferida para el contenido aceptado por el cliente.
8Object getAttribute(String name)
Devuelve el valor del atributo nombrado como un objeto, o null si no existe un atributo con el nombre dado.
9ServletInputStream getInputStream()
Utiliza ServletInputStream para recuperar el cuerpo de la solicitud como datos binarios.
10String getAuthType()
Devuelve el nombre del esquema de autenticación utilizado para proteger el Servlet, por ejemplo, "BASIC" o "SSL", o null si el JSP no está protegido.
11String getCharacterEncoding()
Devuelve el nombre de la codificación de caracteres utilizada en el cuerpo de la solicitud.
12String getContentType()
Devuelve el tipo MIME del cuerpo de la solicitud, o null si se desconoce el tipo.
13String getContextPath()
Devuelve la parte del URI de la solicitud que indica el contexto de la solicitud.
14String getHeader(String name)
Devuelve el valor de la cabecera de solicitud especificada como una cadena.
15String getMethod()
Devuelve el nombre del método HTTP de la solicitud, por ejemplo, GET, POST o PUT.
16String getParameter(String name)
Devuelve el valor de un parámetro de solicitud como una cadena, o null si el parámetro no existe.
17String getPathInfo()
Cuando se realiza la solicitud, devuelve cualquier información de ruta adicional asociada con la URL enviada por el cliente.
18String getProtocol()
Devuelve el nombre y la versión del protocolo de la solicitud.
19String getQueryString()
Devuelve la cadena de consulta contenida en la URL de la solicitud después de la ruta.
20String getRemoteAddr()
Devuelve la dirección de Protocolo de Internet (IP) del cliente que envió la solicitud.
21String getRemoteHost()
Devuelve el nombre completamente calificado del cliente que envió la solicitud.
22String getRemoteUser()
Si el usuario ha sido autenticado, devuelve el usuario conectado que realizó la solicitud, o si el usuario no ha sido autenticado, devuelve null.
23String getRequestURI()
Devuelve la parte de la URL de la solicitud, desde el nombre del protocolo hasta la cadena de consulta en la primera línea de la solicitud HTTP.
24String getRequestedSessionId()
Devuelve el ID de sesión especificado por el cliente.
25String getServletPath()
Devuelve la parte de la URL de la solicitud que invocó al JSP.
26String[] getParameterValues(String name)
Devuelve una matriz de objetos String que contiene todos los valores del parámetro de solicitud dado, o null si el parámetro no existe.
27boolean isSecure()
Devuelve un valor booleano que indica si la solicitud utiliza un canal seguro, como HTTPS.
28int getContentLength()
Devuelve la longitud del cuerpo de la solicitud en bytes y proporciona el flujo de entrada, o devuelve -1 si se desconoce la longitud.
29int getIntHeader(String name)
Devuelve el valor de la cabecera de solicitud especificada como un valor int.
30int getServerPort()
Devuelve el número de puerto en el que se recibió esta solicitud.
31int getParameterMap()
Encapsula los parámetros en un tipo Map.

Ejemplo de solicitud con cabeceras HTTP

El siguiente ejemplo utiliza el métodogetHeaderNames()de HttpServletRequest para leer la información de las cabeceras HTTP. Este método devuelve una enumeración que contiene la información de las cabeceras asociadas con la solicitud HTTP actual.

Una vez que tenemos una enumeración, podemos recorrerla de la manera estándar, utilizando el métodohasMoreElements()para determinar cuándo detenernos, y utilizando el métodonextElement()para obtener el nombre de cada parámetro.

//导入必需的 java 库
import java.io.IOException;
import java.io.PrintWriter;
import java.util.Enumeration;

import javax.servlet.ServletException;
import javax.servlet.annotation.WebServlet;
import javax.servlet.http.HttpServlet;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;

@WebServlet("/DisplayHeader")

//扩展 HttpServlet 类
public class DisplayHeader extends HttpServlet {

    // 处理 GET 方法请求的方法
    public void doGet(HttpServletRequest request, HttpServletResponse response) throws ServletException, IOException
    {
        // 设置响应内容类型
        response.setContentType("text/html;charset=UTF-8");

        PrintWriter out = response.getWriter();
        String title = "HTTP Header 请求实例 - 菜鸟教程实例";
        String docType =
            "<!DOCTYPE html> \n";
            out.println(docType +
            "<html>\n" +
            "<head><meta charset=\"utf-8\"><title>" + title + "</title></head>\n"+
            "<body bgcolor=\"#f0f0f0\">\n" +
            "<h1 align=\"center\">" + title + "</h1>\n" +
            "<table width=\"100%\" border=\"1\" align=\"center\">\n" +
            "<tr bgcolor=\"#949494\">\n" +
            "<th>Header 名称</th><th>Header 值</th>\n"+
            "</tr>\n");

        Enumeration headerNames = request.getHeaderNames();

        while(headerNames.hasMoreElements()) {
            String paramName = (String)headerNames.nextElement();
            out.print("<tr><td>" + paramName + "</td>\n");
            String paramValue = request.getHeader(paramName);
            out.println("<td> " + paramValue + "</td></tr>\n");
        }
        out.println("</table>\n</body></html>");
    }
    // 处理 POST 方法请求的方法
    public void doPost(HttpServletRequest request, HttpServletResponse response) throws ServletException, IOException {
        doGet(request, response);
    }
}

El ejemplo de prueba anterior se encuentra en el proyecto TomcatTest, y la configuración correspondiente de web.xml es:

<?xml version="1.0" encoding="UTF-8"?>  
<web-app>  
  <servlet>  
    <!-- 类名 -->  
    <servlet-name>DisplayHeader</servlet-name>  
    <!-- 所在的包 -->  
    <servlet-class>com.runoob.test.DisplayHeader</servlet-class>  
  </servlet>  
  <servlet-mapping>  
    <servlet-name>DisplayHeader</servlet-name>  
    <!-- 访问的网址 -->  
    <url-pattern>/TomcatTest/DisplayHeader</url-pattern>  
  </servlet-mapping>  
</web-app>
