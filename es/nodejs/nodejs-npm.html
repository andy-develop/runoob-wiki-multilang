Introducción al uso de NPM

NPM (Node Package Manager) es una herramienta de gestión de paquetes de JavaScript y también es el gestor de paquetes predeterminado de Node.js.

NPM permite a los desarrolladores descargar, instalar, compartir y gestionar fácilmente las bibliotecas de dependencias y herramientas de un proyecto.

NPM es la herramienta de gestión de paquetes integrada en Node.js, por lo que normalmente solo necesitas instalar Node.js y NPM se instalará automáticamente en el sistema.

Funciones principales:

  • Gestión de paquetes: NPM puede ayudarte a instalar y gestionar varias bibliotecas de terceros (paquetes) necesarias para el proyecto. Por ejemplo, puedes instalar, actualizar o eliminar dependencias mediante comandos simples.

  • Gestión de versiones: NPM admite control de versiones, lo que te permite fijar una versión específica de una dependencia o elegir la versión más reciente según tus necesidades.

  • Publicación de paquetes: NPM permite a los desarrolladores publicar sus propias bibliotecas en el repositorio de NPM, y otros desarrolladores pueden descargarlas y usarlas a través de NPM.

  • Herramienta de línea de comandos: NPM proporciona una potente herramienta de línea de comandos que se puede usar para instalar paquetes, ejecutar scripts, inicializar proyectos, entre otras operaciones.

Debido a que las versiones nuevas de Node.js ya integran NPM, podemos probar directamente ingresandonpm -vpara comprobar si la instalación fue exitosa. Si aparece el indicador de versión, significa que la instalación fue exitosa:

$ npm -v
2.3.0

Si tienes instalada una versión antigua de npm, puedes actualizarla fácilmente con el comando npm, de la siguiente manera:

$ sudo npm install npm -g
/usr/local/bin/npm -> /usr/local/lib/node_modules/npm/bin/npm-cli.js
npm@2.14.2 /usr/local/lib/node_modules/npm

Si es un sistema Windows, usa el siguiente comando:

npm install npm -g

Usar el comando npm para instalar módulos

El formato de sintaxis para instalar módulos de Node.js con npm es el siguiente:

$ npm install <Module Name>

En el siguiente ejemplo, usamos el comando npm para instalar el módulo de framework web de uso común de Node.jsexpress:

$ npm install express

Después de la instalación, el paquete express se coloca en el directorio node_modules dentro del directorio del proyecto, por lo que en el código solo necesitas usarrequire('express')de esa manera, sin necesidad de especificar la ruta del paquete de terceros.

var express = require('express');

Instalación global e instalación local

La instalación de paquetes npm se divide en instalación local (local) e instalación global (global). Desde el comando que escribes, la diferencia es solo si se incluye o no el parámetro-gparámetro.

Instalación local:Instala el paquete en el directorio node_modules y guarda la información en dependencies de package.json.

npm install express          # 本地安装

Instalación global:Se usa para instalar herramientas de línea de comandos o paquetes que se necesitan en varios proyectos.

npm install express -g   # 全局安装

Si aparece el siguiente error:

npm err! Error: connect ECONNREFUSED 127.0.0.1:8087

La solución es:

$ npm config set proxy null

Instalación local

  • Alcance: De manera predeterminada, npm instalará el paquete en el directorio del proyecto actualnode_modulesen la carpeta. Esto significa que cada proyecto que use este paquete tendrá su propia copia del mismo.

  • Uso: La instalación local se usa generalmente para dependencias del proyecto. Cada proyecto puede tener su propia versión de dependencia, lo que ayuda a garantizar la estabilidad y reproducibilidad del proyecto.

  • Comando de instalación: Ejecutar en el directorio del proyectonpm install <package-name>instalará el paquete en el directorionode_modulesdentro de la carpeta, y en elpackage.jsonarchivo se agregará la dependencia.

  • Gestión de versiones: Mediante elpackage.json 和 package-lock.jsonarchivo se gestionan las versiones de dependencias, asegurando la consistencia del proyecto en diferentes entornos.

Instalación global

  • Alcance: La instalación global instalará el paquete en un directorio a nivel de sistema, generalmente/usr/local/bin(en sistemas tipo Unix) o%AppData%\npm(en Windows).

  • Uso: La instalación global se usa para herramientas o utilidades de línea de comandos que no necesitan instalarse repetidamente en cada proyecto. Por ejemplo, instalar una herramienta globalcreate-react-appse puede usar para crear nuevos proyectos React.

  • Comando de instalación: Usa el-gindicador para instalar el paquete globalmente, por ejemplonpm install -g <package-name>。

  • Gestión de versiones: La versión de los paquetes instalados globalmente la gestiona npm, pero no se refleja en elpackage.jsondel proyecto. Esto significa que los paquetes instalados globalmente pueden compartirse entre diferentes proyectos, pero también pueden causar problemas debido a conflictos de versiones.

Número de versión

Al usar NPM para descargar y publicar código, siempre se manejan números de versión. NPM utiliza números de versión semánticos para gestionar el código. Aquí hay una breve introducción.

El número de versión sigue el control de versiones semántico (SemVer), con el formato MAJOR.MINOR.PATCH, y pueden agregarse marcas adicionales.

  • MAJOR (versión principal): Se incrementa cuando realizas cambios incompatibles en la API. Por ejemplo:2.0.0。
  • MINOR (versión secundaria): Se incrementa cuando agregas nuevas funciones pero mantienes la compatibilidad hacia atrás. Por ejemplo:1.1.0。
  • PATCH (versión de parche): Se incrementa cuando corriges errores sin agregar nuevas funciones. Por ejemplo:1.0.1。

Marcas adicionales

  • Versión de prelanzamiento: como1.0.0-alpha 或 1.0.0-beta.1, significa que esta versión todavía está en pruebas.
  • Metadatos de compilación: como1.0.0+build.1, proporciona información sobre la compilación.

Ejemplo de instalación

  • Instalar una versión específica:npm install package-name@1.2.3
  • Instalar la última versión principal:npm install package-name@^1.2.3(Instala la1.x.xúltima versión de)

Usar el espejo NPM de Taobao

Debido a que usar directamente el espejo oficial de npm en China es muy lento, para resolver este problema podemos usar el espejo proporcionado por Taobao (cnpm o mediante la configuración de NPM) para acelerar la descarga e instalación de paquetes.

El espejo NPM de Taobao es un espejo completo de npmjs.org; puedes usarlo en lugar de la versión oficial (solo lectura). Actualmente la frecuencia de sincronización es de una vez cada 10 minutos para intentar mantenerse sincronizado con el servicio oficial.

Puedes usar la herramienta de línea de comandos cnpm (con soporte de compresión gzip) personalizada por Taobao en lugar del npm predeterminado:

$ npm install -g cnpm --registry=https://registry.npmmirror.com

A continuación, podemos usar cnpm para reemplazar a npm en la instalación y gestión de paquetes:

$ cnpm install [name]

Explicación y uso de package.json

package.json es un archivo central en un proyecto Node.js; contiene metadatos del proyecto, dependencias, scripts y otra información.

El archivo package.json se usa para describir los metadatos y las dependencias del proyecto; generalmente se encuentra en el directorio raíz del proyecto y es el archivo de configuración del proyecto.

El archivo package.json es un archivo en formato JSON y contiene los siguientes campos básicos:

  • name: el nombre del proyecto, debe ser único, normalmente se usan letras minúsculas y guiones.
  • version: el número de versión del proyecto, que sigue el control de versiones semántico (Semantic Versioning).
  • description: una breve descripción del proyecto.
  • main: el archivo de entrada del proyecto, normalmente el archivo de inicio de la aplicación.
  • scripts: define una serie de scripts de línea de comandos que se pueden ejecutar en el proyecto para realizar tareas específicas.
  • dependencies: lista todos los paquetes de dependencias necesarios para ejecutar el proyecto y sus versiones.
  • devDependencies: lista los paquetes de dependencias necesarios solo durante el desarrollo y sus versiones.
  • peerDependencies: lista los paquetes que el proyecto espera que sus dependencias también tengan como dependencia.
  • optionalDependencies: lista los paquetes de dependencias opcionales.
  • engines: especifica las versiones de Node.js compatibles con el proyecto.
  • repository: información del repositorio de código del proyecto, como la URL del repositorio de GitHub.
  • keywords: las palabras clave del proyecto, que ayudan a encontrar el proyecto en la búsqueda de npm.
  • author: información del autor del proyecto.
  • license: información de la licencia del proyecto.

Método de uso:

  1. Inicializar el proyecto: en el directorio del proyecto, ejecutarnpm initel comando; npm te guiará para crear unpackage.jsonarchivo, o generará automáticamente uno con valores predeterminadospackage.json。

  2. Instalar dependencias: usarnpm install <package-name>el comando para instalar dependencias; npm agregará automáticamente las dependencias apackage.jsondel archivodependencies 或 devDependenciesen él, y crearápackage-lock.jsonun archivo para fijar las versiones de las dependencias.

  3. Gestionar scripts: en elscriptscampo, definir comandos, por ejemplo"start": "node app.js", luego se puede usarnpm startel comando para ejecutar estos scripts.

  4. Control de versiones: usarnpm versionel comando para gestionar el número de versión del proyecto; npm actualizará automáticamentepackage.jsonel número de versión en él y generará una nueva etiqueta de Git.

  5. Publicar el paquete: cuando el proyecto esté listo para publicarse en npm, se puede usarnpm publishel comando; npm leerápackage.jsonla información en él para publicar el paquete.

  6. Gestión de dependencias：package.json 和 package-lock.jsonEl archivo, trabajando en conjunto, garantiza que las versiones de dependencias del proyecto sean consistentes en diferentes entornos.

Beneficios de usar package.json

  • Gestión de dependencias: gestionar de forma centralizada las dependencias del proyecto y sus versiones.
  • Automatización de tareas: mediantescriptsel campo se pueden ejecutar tareas comunes de manera conveniente.
  • Control de versiones: garantizar la consistencia de las versiones del proyecto y sus dependencias, lo que facilita la colaboración del equipo.
  • Describir el proyecto: proporcionar metadatos del proyecto, lo que facilita su publicación e intercambio.

Gestión de dependencias

dependencies: almacenar las dependencias necesarias para ejecutar el proyecto.

"dependencies": {
  "express": "^4.17.1"
}

Se usa al instalar dependencias:

npm install express

devDependencies: almacenar las dependencias necesarias durante el desarrollo del proyecto.

"devDependencies": {
  "nodemon": "^2.0.20"
}

Se usa al instalar dependencias:

npm install nodemon --save-dev

Campo scripts

El campo scripts se usa para definir comandos que se pueden ejecutar con npm run <script>. Los scripts comunes incluyen:

"scripts": {
  "start": "node app.js",
  "test": "jest",
  "build": "webpack --mode production",
  "dev": "nodemon app.js"
}

Ejemplo de ejecución de scripts:

npm run dev   # 执行 "nodemon app.js"
npm start     # 等同于 "node app.js"，可以直接用 npm start 运行

Explicación de los símbolos en el número de versión

  • ^(caret): indica instalar la última versión compatible con la versión principal actual. Por ejemplo,^4.17.1se instalará4.x.xla última versión dentro de él.
  • ~(tilde): indica instalar la última versión compatible con la versión secundaria actual. Por ejemplo,~4.17.1se instalará4.17.xla última versión dentro de él.

npm init

Ver las dependencias del proyecto:

npm list --depth=0

Actualizar dependencias:

npm update package-name

  • usarpackage-lock.jsonpara fijar las versiones de las dependencias, asegurando la consistencia del proyecto en diferentes entornos.
  • Actualizar las dependencias periódicamente para aprovechar las últimas funciones y correcciones de seguridad.
