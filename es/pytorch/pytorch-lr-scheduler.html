Scheduler de tasa de aprendizaje de PyTorch

La tasa de aprendizaje (Learning Rate) es uno de los hiperparámetros más importantes en el entrenamiento de redes neuronales. Si es demasiado grande, el entrenamiento oscila o incluso diverge; si es demasiado pequeña, la convergencia es muy lenta y es fácil caer en óptimos locales.

Scheduler de tasa de aprendizaje (LR Scheduler)Al ajustar dinámicamente la tasa de aprendizaje durante el entrenamiento, se equilibra la convergencia rápida de las etapas iniciales con el ajuste fino de las etapas finales.

4.1 LinearLR: Programación lineal

Cambia la tasa de aprendizaje linealmente dentro de un número determinado de épocas (útil para precalentamiento lineal o decaimiento lineal).

Ejemplo

optimizer = optim.Adam(model.parameters(), lr=0.01)

warmup_scheduler = optim.lr_scheduler.LinearLR(

# Cambio de LR: 0.001 -> 0.003 -> 0.005 -> 0.007 -> 0.009 -> 0.01

4.3 SequentialLR: Programación combinada

Concatenar varios programadoresen ordenes la práctica estándar para implementar la estrategia combinada de "precalentamiento + decaimiento".

Ejemplo

optimizer = optim.Adam(model.parameters(), lr=0.01)

# Fase uno: precalentamiento (primeras 5 épocas, LR aumenta linealmente de 0.001 a 0.01)
warmup = optim.lr_scheduler.LinearLR(
    optimizer, start_factor=0.1, end_factor=1.0, total_iters=5
)

# Fase dos: decaimiento por coseno (restantes 95 épocas)
cosine = optim.lr_scheduler.CosineAnnealingLR(
    optimizer, T_max=95, eta_min=1e-6
)

# Combinación: primero se ejecuta el warmup, después de la época 5 se cambia a cosine
scheduler = optim.lr_scheduler.SequentialLR(
    optimizer,
    schedulers=[warmup, cosine],
    milestones=[5]          # Cambio en la época 5
)

# Se usa exactamente igual que un programador normal
for epoch in range(100):
    train(...)
    scheduler.step()

Escenarios de aplicación:Estándar en el entrenamiento de Transformers (precalentamiento + decaimiento por coseno); el preentrenamiento de BERT, GPT y ViT utiliza esta estrategia.

5. Scheduler cíclico

5.1 CyclicLR: Tasa de aprendizaje cíclica

La tasa de aprendizajebase_lr 和 max_lrentrecicla periódicamente, lo que puede ayudar al modelo a explorar un espacio de parámetros más amplio y salir de puntos de silla.

Ejemplo

optimizer = optim.SGD(model.parameters(), lr=0.01)
scheduler = optim.lr_scheduler.CyclicLR(
    optimizer,
    base_lr=0.001,          # Límite inferior de la tasa de aprendizaje
    max_lr=0.01,            # Límite superior de la tasa de aprendizaje
    step_size_up=2000,      # Número de pasos de iteración desde base_lr hasta max_lr
    step_size_down=2000,    # Número de pasos de iteración desde max_lr hasta base_lr (por defecto igual a step_size_up)
    mode='triangular',      # Ciclo triangular (amplitud constante)
    # mode='triangular2' # Cada ciclo reduce la amplitud a la mitad
    # mode='exp_range' # Amplitud con decaimiento exponencial
)

# CyclicLR se llama por step (batch), no por epoch
for epoch in range(num_epochs):
    for inputs, labels in train_loader:
        optimizer.zero_grad()
        loss = criterion(model(inputs), labels)
        loss.backward()
        optimizer.step()
        scheduler.step()    # Se llama después de cada batch

modeVariación de amplitudCaracterística

triangular2Se reduce a la mitad cada cicloPrimero explora, luego converge

5.2 OneCycleLR: Estrategia de un solo ciclo

Uno de los programadores con mejor rendimiento, la política 1-Cycle propuesta por fastai. Todo el entrenamiento tiene un solo ciclo: la tasa de aprendizaje primero sube y luego baja, y el momento (momentum) varía en sentido inverso.

El entrenamiento es más rápido; normalmente solo se necesitan1/5~1/10de las épocas del entrenamiento tradicional para alcanzar la misma precisión.

Ejemplo

optimizer = optim.SGD(model.parameters(), lr=0.01, momentum=0.9)

steps_per_epoch = len(train_loader)

scheduler = optim.lr_scheduler.OneCycleLR(
    optimizer,
    max_lr=0.1,                              # Punto máximo de la tasa de aprendizaje
    steps_per_epoch=steps_per_epoch,         # Número de pasos por epoch
    epochs=10,                               # Número total de épocas
    pct_start=0.3,                           # El 30% inicial se usa para el precalentamiento ascendente
    anneal_strategy='cos',                   # Estrategia de decaimiento ('cos' o 'linear')
    div_factor=25,                           # lr inicial = max_lr / div_factor
    final_div_factor=1e4                     # lr final = max_lr / final_div_factor
)

# lr inicial = 0.1 / 25 = 0.004
# lr máximo = 0.1 (en el 30%)
# lr final = 0.1 / 10000 = 0.00001

# También se llama por batch
for epoch in range(10):
    for inputs, labels in train_loader:
        optimizer.zero_grad()
        loss = criterion(model(inputs), labels)
        loss.backward()
        optimizer.step()
        scheduler.step()    # Se llama después de cada batch

Escenarios de aplicación:Es la primera opción cuando los recursos computacionales son limitados y se necesita validar ideas rápidamente;max_lrSe recomienda usar la herramienta LR Finder para determinar el valor óptimo.

6. Scheduler personalizado

6.1 LambdaLR: Personalización funcional

Se personaliza completamente la estrategia de programación pasando una función Lambda (recibe el número de epoch y devuelve un multiplicador de la tasa de aprendizaje).

Ejemplo

optimizer = optim.Adam(model.parameters(), lr=0.01)

# Ejemplo 1: estrategia clásica de precalentamiento de Transformer
# lr ∝ min(step^-0.5, step × warmup_steps^-1.5)
def transformer_lr(epoch, warmup_epochs=10, d_model=512):
    if epoch == 0:
        return 1e-7 / 0.01          # Evitar división por cero
    step = epoch + 1
    warmup = warmup_epochs
    return (d_model ** -0.5) * min(step ** -0.5, step * warmup ** -1.5) / 0.01

scheduler = optim.lr_scheduler.LambdaLR(optimizer, lr_lambda=transformer_lr)


# Ejemplo 2: decaimiento polinómico (lr disminuye de forma lineal/polinómica desde el valor inicial hasta 0)
def polynomial_decay(epoch, total_epochs=100, power=1.0):
    return max((1 - epoch / total_epochs) ** power, 0.0)

scheduler = optim.lr_scheduler.LambdaLR(optimizer, lr_lambda=polynomial_decay)


# Ejemplo 3: tasa de aprendizaje por grupos (diferentes estrategias para diferentes grupos de parámetros)
optimizer = optim.Adam([
    {'params': model.backbone.parameters(), 'lr': 1e-4},
    {'params': model.head.parameters(),     'lr': 1e-3},
])

# Una función lambda para cada grupo de parámetros
scheduler = optim.lr_scheduler.LambdaLR(
    optimizer,
    lr_lambda=[
        lambda epoch: 0.95 ** epoch,    # backbone: decaimiento lento
        lambda epoch: 0.85 ** epoch,    # head: decaimiento rápido
    ]
)

6.2 Heredar de LRScheduler

Cuando se necesita una lógica más compleja, heredeLRScheduler(PyTorch >= 2.0, en versiones anteriores era_LRScheduler) para implementar una personalización completa:

Ejemplo

from torch.optim.lr_scheduler import LRScheduler
import math

class WarmupCosineScheduler(LRScheduler):
    """
Programador combinado de precalentamiento + decaimiento por coseno (versión implementada manualmente)
- Precalentamiento lineal durante las primeras warmup_epochs épocas
- Después, decaimiento por coseno hasta min_lr
    """
    def __init__(self, optimizer, warmup_epochs, total_epochs,
                 min_lr=1e-6, last_epoch=-1):
        self.warmup_epochs = warmup_epochs
        self.total_epochs  = total_epochs
        self.min_lr        = min_lr
        super().__init__(optimizer, last_epoch)

    def get_lr(self):
        epoch = self.last_epoch

        # Fase de precalentamiento: aumento lineal
        if epoch < self.warmup_epochs:
            warmup_factor = (epoch + 1) / self.warmup_epochs
            return [base_lr * warmup_factor for base_lr in self.base_lrs]

        # Fase de decaimiento por coseno
        progress = (epoch - self.warmup_epochs) / (
            self.total_epochs - self.warmup_epochs
        )
        cosine_factor = 0.5 * (1 + math.cos(math.pi * progress))
        return [
            self.min_lr + (base_lr - self.min_lr) * cosine_factor
            for base_lr in self.base_lrs
        ]


optimizer = optim.Adam(model.parameters(), lr=0.01)
scheduler = WarmupCosineScheduler(
    optimizer,
    warmup_epochs=10,
    total_epochs=100,
    min_lr=1e-6
)

7. Comparación visual de schedulers

El siguiente código puede dibujar las curvas de cambio de LR de cada programador para una comparación visual directa:

Ejemplo

import torch
import torch.optim as optim
import matplotlib.pyplot as plt

def simulate_lr(scheduler_fn, epochs=100, steps_per_epoch=None):
    """Simula y registra los cambios de la tasa de aprendizaje del programador"""
    model     = torch.nn.Linear(1, 1)
    optimizer = optim.SGD(model.parameters(), lr=0.1)
    scheduler = scheduler_fn(optimizer)
    lrs = []

    if steps_per_epoch:
        # Programador que se llama por step
        for _ in range(epochs):
            for _ in range(steps_per_epoch):
                optimizer.step()
                scheduler.step()
                lrs.append(optimizer.param_groups[0]['lr'])
    else:
        # Programador que se llama por epoch
        for _ in range(epochs):
            optimizer.step()
            scheduler.step()
            lrs.append(optimizer.param_groups[0]['lr'])
    return lrs

schedulers = {
    'StepLR(step=30, gamma=0.1)':
        lambda opt: optim.lr_scheduler.StepLR(opt, 30, 0.1),
    'CosineAnnealingLR':
        lambda opt: optim.lr_scheduler.CosineAnnealingLR(opt, T_max=100),
    'ExponentialLR(gamma=0.95)':
        lambda opt: optim.lr_scheduler.ExponentialLR(opt, 0.95),
    'CosineWarmRestarts(T0=25)':
        lambda opt: optim.lr_scheduler.CosineAnnealingWarmRestarts(opt, T_0=25),
}

plt.figure(figsize=(12, 5))
for name, fn in schedulers.items():
    plt.plot(simulate_lr(fn), label=name)

plt.xlabel('Epoch')
plt.ylabel('Learning Rate')
plt.title('PyTorch LR Scheduler Comparison')
plt.legend()
plt.grid(True, alpha=0.3)
plt.tight_layout()
plt.savefig('lr_schedulers.png', dpi=150)
plt.show()

import torch.nn as nn
import torch.optim as optim
from torch.optim.lr_scheduler import SequentialLR, LinearLR, CosineAnnealingLR

# Hiperparámetros
EPOCHS       = 100
WARMUP_EPOCHS = 5
BASE_LR      = 1e-3
MIN_LR       = 1e-6
SAVE_PATH    = 'best_model.pth'

device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')

# Modelo / optimizador / programador
model     = MyModel().to(device)
optimizer = optim.AdamW(model.parameters(), lr=BASE_LR, weight_decay=1e-4)
criterion = nn.CrossEntropyLoss(label_smoothing=0.1)

# Precalentamiento 5 épocas + decaimiento por coseno 95 épocas
warmup_sched = LinearLR(optimizer, start_factor=0.1, total_iters=WARMUP_EPOCHS)
cosine_sched = CosineAnnealingLR(optimizer, T_max=EPOCHS - WARMUP_EPOCHS, eta_min=MIN_LR)
scheduler    = SequentialLR(optimizer, [warmup_sched, cosine_sched], milestones=[WARMUP_EPOCHS])

# Restaurar punto de control
start_epoch = 0
best_acc    = 0.0

try:
    ckpt = torch.load(SAVE_PATH, map_location=device)
    model.load_state_dict(ckpt['model'])
    optimizer.load_state_dict(ckpt['optimizer'])
    scheduler.load_state_dict(ckpt['scheduler'])
    start_epoch = ckpt['epoch'] + 1
    best_acc    = ckpt['best_acc']
    print(f"Restaurado desde Epoch {start_epoch}, mejor precisión {best_acc:.4f}")
except FileNotFoundError:
    print("Entrenar desde cero")

# Bucle de entrenamiento
history = {'train_loss': [], 'val_acc': [], 'lr': []}

for epoch in range(start_epoch, EPOCHS):
    # Entrenamiento
    model.train()
    total_loss = 0.0
    for inputs, labels in train_loader:
        inputs, labels = inputs.to(device), labels.to(device)
        optimizer.zero_grad()
        loss = criterion(model(inputs), labels)
        loss.backward()
        torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)  # Recorte de gradientes
        optimizer.step()
        total_loss += loss.item()

    # Validación
    model.eval()
    correct = 0
    with torch.no_grad():
        for inputs, labels in val_loader:
            inputs, labels = inputs.to(device), labels.to(device)
            correct += (model(inputs).argmax(1) == labels).sum().item()

    avg_loss = total_loss / len(train_loader)
    val_acc  = correct / len(val_loader.dataset)
    cur_lr   = scheduler.get_last_lr()[0]

    # Registrar e imprimir
    history['train_loss'].append(avg_loss)
    history['val_acc'].append(val_acc)
    history['lr'].append(cur_lr)
    print(f"Epoch {epoch+1:3d}/{EPOCHS} | "
          f"Loss: {avg_loss:.4f} | Acc: {val_acc:.4f} | LR: {cur_lr:.2e}")

    # Actualizar el programador
    scheduler.step()

    # Guardar el mejor modelo
    if val_acc > best_acc:
        best_acc = val_acc
        torch.save({
            'epoch':      epoch,
            'model':      model.state_dict(),
            'optimizer':  optimizer.state_dict(),
            'scheduler':  scheduler.state_dict(),
            'best_acc':   best_acc,
        }, SAVE_PATH)
        print(f" Guardando el mejor modelo, Acc: {best_acc:.4f}")

print(f"\nEntrenamiento completado, mejor precisión de validación: {best_acc:.4f}")

9. Guía para elegir un scheduler

Recomendaciones por tipo de tarea

EscenarioProgramador recomendadoMotivo
Experimentación rápida / validación de prototiposReduceLROnPlateauNo requiere ajuste de hiperparámetros, decaimiento adaptativo
Clasificación de imágenes (épocas fijas)CosineAnnealingLRDecaimiento suave, buena calidad de convergencia
Transformer / BERTLinearLR + CosineAnnealingLREl precalentamiento es indispensable
Recursos limitados, entrenamiento rápidoOneCycleLRAlcanza la misma precisión en 1/5 del tiempo
Ajuste fino de modelos grandes (fine-tuning)LinearLR(precalentamiento) +ConstantLRajuste fino estable con tasa de aprendizaje baja
Número de épocas inciertoReduceLROnPlateauRespuesta automática, no depende de un ritmo fijo
Detección de objetos (YOLO/Faster-RCNN)MultiStepLR / OneCycleLRTiene puntos de decaimiento claros o busca velocidad
Se desea escapar de óptimos localesCosineAnnealingWarmRestartsReinicio periódico para explorar el espacio de parámetros

Combinaciones de configuración comunes

Ejemplo

# Combinación 1: Warmup + decaimiento por coseno (estándar en Transformers)
SequentialLR([LinearLR(5 epochs), CosineAnnealingLR(95 epochs)])

# Combinación 2: monitoreo del conjunto de validación + decaimiento automático (opción general preferida)
ReduceLROnPlateau(mode='min', patience=5, factor=0.5)

# Combinación 3: OneCycleLR (opción preferida para entrenamiento rápido)
OneCycleLR(max_lr=0.1, total_steps=total_steps, pct_start=0.3)

# Combinación 4: decaimiento por escalones tradicional (clásico en visión por computadora)
MultiStepLR(milestones=[30, 60, 90], gamma=0.1)
