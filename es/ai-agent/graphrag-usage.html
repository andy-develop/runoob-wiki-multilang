Tutorial de introducción a GraphRAG

GraphRAG es un sistema de generación aumentada por recuperación (RAG) estructurado y jerárquico de código abierto de Microsoft Research. A diferencia del RAG tradicional, que utiliza recuperación vectorial sobre texto plano, GraphRAG primero usa un modelo grande para extraer entidades y relaciones de los documentos originales, construir un grafo de conocimiento y, a continuación, realizar la recuperación y las preguntas y respuestas basándose en la estructura del grafo.

Este tutorial está dirigido a lectores sin conocimientos previos, te lleva desde la instalación para que completes todo el proceso dedocumento → grafo de conocimiento → consulta y respuestadel flujo completo, el modelo usaqwen-plus, y el Embedding usa el de Tongyi de Alibaba Cloudtext-embedding-v4。

¿Qué es GraphRAG?

Para entender GraphRAG, primero hay que entender en qué es mejor que el RAG tradicional.

Limitaciones del RAG tradicional

El flujo de trabajo del RAG tradicional (Baseline RAG) es: dividir el documento en fragmentos pequeños → generar vectores → cuando llega una pregunta, usar la similitud vectorial para recuperar los fragmentos más relevantes → enviarlos al modelo para generar una respuesta.

Este enfoque funciona bien para problemas de "recuperación exacta", pero tiene un rendimiento deficiente en dos tipos de escenarios:

  • Razonamiento de relaciones entre documentos: cuando la respuesta requiere conectar información dispersa en diferentes documentos, la similitud vectorial no puede expresar esa "relación". Por ejemplo: "¿Qué relación hay entre el CEO de la empresa A y el fundador de la empresa B?"
  • Problemas de resumen global: cuando la pregunta pide un resumen macro de todo el corpus, unos pocos fragmentos de texto no pueden cubrir el panorama completo. Por ejemplo: "¿Cuáles son los riesgos más importantes en estos documentos financieros?"

Cómo resuelve GraphRAG estos dos problemas

La idea central de GraphRAG es:No recuperar directamente fragmentos de texto, sino construir primero un grafo de conocimiento y luego recuperar basándose en la estructura del grafo.。

Todo el proceso se divide en dos fases:

FaseQué haceQué genera
Indexación (Index)Usa el LLM para leer documentos, extraer entidades (personas, lugares, organizaciones, etc.) y relaciones, y construir un grafo de conocimiento; luego aplica el algoritmo de Leiden para realizar una agrupación jerárquica del grafo y generar resúmenes para cada comunidad.Grafo de conocimiento + Resúmenes de comunidades + Índice vectorial
Consulta (Query)Cuando el usuario pregunta, se elige una estrategia de recuperación según el tipo de pregunta, y se inyectan los datos del grafo, los resúmenes de las comunidades y los fragmentos de texto originales en el contexto del LLM para generar una respuesta.Respuesta estructurada con fuentes de evidencia

La fase de indexación de GraphRAG requiere llamar a muchas API de LLM, realizando extracción de entidades y resúmenes para cada fragmento de texto.El consumo de tokens es mucho mayor que en el RAG tradicional. Se recomienda, en el primer uso, probar el flujo con documentos pequeños (menos de unos miles de caracteres) y, una vez confirmado que funciona correctamente, procesar corpus a gran escala.

Comparación de cuatro modos de consulta

Modo de consultaEstrategia de recuperaciónTipo de preguntas adecuadasConsumo de recursos
Global SearchMap-Reduce recorre todos los resúmenes de las comunidadesPreguntas globales y de resumen, como "¿Cuál es el tema central de estos documentos?"Alto (múltiples llamadas LLM concurrentes)
Local SearchParte de las entidades relevantes y expande nodos vecinos y textos asociadosPreguntas sobre entidades específicas, como "la red de relaciones principal de cierta persona"中
DRIFT SearchLocal Search + preguntas iterativas guiadas por la información de la comunidadPreguntas relacionadas con entidades que requieren un contexto amplio, equilibrando profundidad y amplitudMedio-alto
Basic SearchSimilitud vectorial estándar (igual que el RAG tradicional)Recuperación exacta simple, para comparar resultados低

Instalación

GraphRAG se publica en PyPI; se recomienda instalarlo en un entorno virtual de Python para no contaminar el entorno del sistema.

Crear el directorio del proyecto e inicializar el entorno virtual

mkdir graphrag_demo
cd graphrag_demo
python -m venv .venv
También se puede usarel comando uvpara especificar la versión de Python:
uv venv --python 3.12

Activar el entorno virtual

macOS / Linux：

source .venv/bin/activate

Windows：

.venv\Scripts\activate

Instalar GraphRAG

pip install graphrag

Después de la instalación, verifica:

graphrag --help

Mostrará algo degraphraginformación de comandos; la salida será similar a:

GraphRAG instalará automáticamente dependencias como LiteLLM, LanceDB, pandas, numpy, etc. La primera instalación tarda bastante (generalmente de 1 a 3 minutos); por favor, ten paciencia.

Inicializar el espacio de trabajo

Ejecutargraphrag initcomando, GraphRAG generará los archivos de configuración y la estructura de directorios en el directorio actual.

graphrag init

Nos pedirá que configuremos el modelo; podemos pulsar Enter para aceptar los valores predeterminados y modificarlos más tarde:

Specify the default chat model to use [gpt-4.1]: 
Specify the default embedding model to use [text-embedding-3-large]:

Durante la inicialización se te pedirá que ingreses el modelo de Chat y el modelo de Embedding predeterminados; puedes omitirlos temporalmente pulsando Enter; más adelante los modificaremos manualmente.settings.yaml。

Una vez completada la inicialización, la estructura de directorios es la siguiente:

graphrag_demo/
├── .env                  # 存放 API Key 环境变量
├── settings.yaml         # 核心配置文件
├── input/                # 存放待处理的文本文件
├── output/               # 索引产物输出目录（自动生成）
└── prompts/              # Prompt 模板目录（自动生成）

Después de cada actualización de una versión menor de GraphRAG, se recomienda volver a ejecutargraphrag init --forcepara refrescar el formato de configuración; de lo contrario, puede haber errores de ejecución debido a cambios en la estructura de configuración. Ten en cuenta que este comando sobrescribirá los existentessettings.yamly prompts; se recomienda hacer una copia de seguridad primero.

Iniciar la indexación

Una vez completada la configuración, ejecute el comando de indexación; GraphRAG leerá automáticamenteinput/todos los archivos en el directorio, invocará a qwen-plus para realizar extracción de entidades, reconocimiento de relaciones, generación de resúmenes y, finalmente, construirá un grafo de conocimiento completo.

graphrag index

Una vez completada la indexación,output/en el directorio se generarán una serie de archivos Parquet:

ArchivoContenido
entities.parquetTodas las entidades extraídas (nombre, tipo, descripción, vector)
relationships.parquetRelaciones entre entidades (entidad origen, entidad destino, descripción de la relación, peso)
communities.parquetComunidades generadas por el agrupamiento de Leiden (estructura jerárquica)
community_reports.parquetInforme resumido de cada comunidad (datos principales de Global Search)
text_units.parquetBloques de texto originales (fuente de referencia de Local Search)
lancedb/Base de datos vectorial, que almacena los vectores de varias entidades y bloques de texto

Referencia de tiempo de indexación:Para un documento chino de unos pocos miles de caracteres (aproximadamente 10~20 bloques de texto), usar qwen-plus tarda alrededor de 3~10 minutos; para colecciones de documentos grandes de más de 100 000 caracteres, puede llevar varias horas. Se recomienda primero probar el flujo con un documento pequeño y luego procesar datos a gran escala.

Ejecutar consultas

Una vez completada la indexación, se puede consultar el grafo de conocimiento. GraphRAG ofrece dos formas: CLI y Python API.

Consulta mediante CLI

Búsqueda global (adecuada para preguntas de carácter macro):

graphrag query "文档中涉及的主要组织和人物有哪些？它们之间有什么关系？"

Búsqueda local (adecuada para preguntas sobre entidades específicas), agregue--method local：

graphrag query "SpaceX 公司的主要业务和合作伙伴有哪些？" --method local

Búsqueda DRIFT (equilibra profundidad y amplitud):

graphrag query "埃隆·马斯克的职业背景和主要贡献是什么？" --method drift

Búsqueda vectorial básica (para comparar con RAG tradicional):

graphrag query "Starship 星舰的设计目标和能力是什么？" --method basic

Consulta mediante la API de Python

Llamar a la consulta de GraphRAG en el código es adecuado para integrarlo en aplicaciones.

Ejemplo

# Ruta del archivo: query_demo.py
# Consulta usando la Python API de GraphRAG

import asyncio
from graphrag.api import GraphRagConfig, search

async def run_query():
    # Cargar el archivo de configuración (lee settings.yaml desde el directorio actual)
    config = GraphRagConfig.from_yaml("settings.yaml")

    # ── Ejemplo de búsqueda global ─────────────────
    print("=" * 60)
    print("【Global Search】Pregunta global")
    print("=" * 60)

    global_result = await search(
        config=config,
        query="¿Cómo es la red de relaciones entre las principales empresas y personajes mencionados en el documento?",
        method="global",            # Usar Global Search
    )
    print(global_result.response)
    print()

    # ── Ejemplo de búsqueda local ─────────────────
    print("=" * 60)
    print("【Local Search】Pregunta sobre una entidad específica")
    print("=" * 60)

    local_result = await search(
        config=config,
        query="¿Cuál es el antecedente del equipo fundador de SpaceX y sus principales productos?",
        method="local",             # Usar Local Search
    )
    print(local_result.response)
    print()

    # Ver la información de fuentes recuperada (opcional)
    if hasattr(local_result, "context_data"):
        entities = local_result.context_data.get("entities", [])
        print(f"Se recuperaron {len(entities)} entidades relevantes:")

if __name__ == "__main__":
    asyncio.run(run_query())

Ajuste automático de prompts

Los desarrolladores oficiales de GraphRAG recomiendan encarecidamente ejecutar el ajuste automático de Prompt antes de procesar sus propios datos.

El ajuste automático hará que el LLM lea parte de tus documentos y luego genere un Prompt de extracción de entidades personalizado para el dominio de tus datos, lo que mejora la calidad de la construcción del grafo de conocimiento.

graphrag prompt-tune --config settings.yaml --root . --language Chinese

Una vez completado el ajuste,prompts/los archivos Prompt en el directorio se actualizarán automáticamente. Si tus documentos están en chino, agregue--language Chineseel parámetro puede hacer que el Prompt generado también esté en chino, mejorando la precisión de la extracción de entidades en chino.

El ajuste de Prompt en sí mismo también consume Tokens del LLM (aproximadamente equivalente a hacer una indexación rápida de una pequeña cantidad de documentos). Se recomienda reajustar cada vez que se cambie el conjunto de datos, en lugar de usar siempre el Prompt predeterminado.

Preguntas frecuentes

¿Qué hago si la indexación falla a mitad de camino?

GraphRAG guarda en caché los resultados de cada llamada al LLM. Después de un fallo, simplemente vuelva a ejecutargraphrag index, los bloques de texto ya procesados con éxito se leerán desde la caché y no se consumirán Tokens repetidamente.

Si desea reiniciar desde cierto paso, use--resumeel parámetro:

graphrag index --resume

¿Cómo manejo los errores de análisis JSON?

La fase de extracción de entidades exige que el modelo devuelva estrictamente formato JSON. Si apareceJSONDecodeError, puede probar los siguientes métodos:

  • 在 call_argsAñadir enresponse_format: {type: json_object}(requiere que el modelo admita este parámetro)
  • 将 temperatureEstablecer en 0
  • 将 max_gleaningsEstablecer en 0 (reducir las preguntas de seguimiento, disminuir la probabilidad de errores)
  • Ejecutegraphrag prompt-tuneReajuste el Prompt para que el modelo esté más familiarizado con el formato de salida

¿Cómo elegir entre Global Search y Local Search?

Tipo de preguntaModo recomendadoEjemplo
Resumen, carácter globalGlobal Search"¿Cuál es el tema central de este lote de documentos?" "La visión completa de toda la red de relaciones entre personajes"
Para entidades específicasLocal Search"¿La trayectoria profesional de Musk?" "Las principales características técnicas del cohete Falcon 9"
Se necesita equilibrar profundidad y amplitudDRIFT Search"Análisis de las conexiones entre un personaje y el ecosistema circundante"
Búsqueda simple y precisaBasic Search"¿En qué año se fundó SpaceX?"

¿Cómo controlar un consumo de tokens demasiado alto?

  • 将 chunking.sizeAumente apropiadamente (menos bloques de texto = menos llamadas al LLM)
  • 将 extract_graph.max_gleaningsEstablecer en 0 o 1
  • 在 entity_typesEn, conserve solo los tipos de entidades más relevantes para el negocio
  • Use un modelo más económico en la fase de indexación, y en la fase de consulta puede cambiarlo a un modelo más potente según sea necesario

GraphRAG ofrece una estrategia de "configuración de modelo asimétrica": encompletion_modelsdefina múltiples modelos; use un modelo de bajo costo en la fase de indexación y un modelo más capaz para consultas clave en la fase de consulta, encontrando un equilibrio entre costo y calidad.

¿Cómo manejar documentos en chino?

Al manejar documentos en chino, hay que tener en cuenta los siguientes puntos:

  • Asegúrese de queinput.encoding: utf-8(por defecto ya es UTF-8)
  • Reduzcachunking.size(los caracteres chinos tienen alta densidad de información; con 600~1000 Tokens es suficiente)
  • Ejecutegraphrag prompt-tune --language ChineseGenere un Prompt en chino
  • entity_typesPuede agregar apropiadamente tipos específicos del chino, comogovernment_agency(instituciones gubernamentales),policy(políticas)
