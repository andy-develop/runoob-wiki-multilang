Implementación de modelos locales

Mucha gente piensa que la IA solo se puede usar en la nube: al usar ChatGPT, los datos se envían a los servidores de OpenAI; al usar Claude, las solicitudes se envían al centro de datos de Anthropic.

En realidad,Los modelos de IA pueden ejecutarse completamente en tu propia computadora.。

Imagina: puedes usar IA sin conexión, los datos confidenciales no salen de tu computadora, no necesitas pagar por cada llamada y puedes personalizarla como quieras.

Este es el valor de la implementación de modelos locales.

Este módulo te llevará desde cero para ejecutar tu primer modelo de IA local en tu propia computadora.

¿Por qué necesitas IA local?

La IA en la nube es muy conveniente, pero la IA local tiene ventajas irremplazables.

Protección de la privacidad de los datos

Esta es la razón principal por la que muchos eligen la implementación local.

Si lo que manejas son contratos, historiales médicos, datos financieros o documentos internos, enviar estos datos a servidores de terceros es arriesgado.

Cuando se ejecuta localmente,todos los datos se procesan en tu propia computadora y no salen de tu dispositivo.。

Uso en entornos sin red

En aviones, trenes o lugares con conexión inestable, la IA en la nube no se puede usar.

Una vez descargado el modelo local, está disponible para siempre sin necesidad de conexión de red.

Control de costos

La IA en la nube se cobra por número de llamadas o por token; si se usa mucho, puede ser un gasto considerable.

El modelo local se descarga una sola vez y luego se puede usar libremente sin pagos adicionales.

Posibilidad de personalización

Los modelos en la nube no se pueden modificar; solo puedes usar las funciones que ofrecen.

Los modelos locales se pueden ajustar (fine-tune), cuantizar, modificar las plantillas de prompts y personalizar completamente según tus necesidades.

Comparación de estas ventajas:

CaracterísticaIA en la nubeIA local

Dependencia de redDebe estar en líneaSin necesidad de red
Costo de usoCobro por usoDescarga única, uso ilimitado

No es que la IA en la nube sea mala, sino quecada una tiene sus escenarios de aplicación.Para charlas cotidianas usa la nube, para datos confidenciales usa local; para tareas simples usa la nube, para personalización especial usa local.

Evaluación de requisitos de hardware

Si el modelo local puede ejecutarse y qué tan rápido lo hace depende principalmente de la configuración de tu hardware.

Inferencia en CPU vs inferencia en GPU

Hay dos formas de ejecutar modelos: inferencia en CPU e inferencia en GPU.

La inferencia en CPU usa el procesador principal de la computadora para ejecutar el modelo; la ventaja es una buena compatibilidad, casi todas las computadoras pueden hacerlo; la desventaja es que es lento, y con los modelos grandes puede requerir una larga espera.

La inferencia en GPU usa la tarjeta gráfica; la ventaja principal esla fuerte capacidad de cómputo paralelo, que hace que el modelo corra decenas de veces más rápido.。

Para tarjetas NVIDIA, necesitas instalar el kit de herramientas CUDA; para tarjetas AMD, puedes usar ROCm; para tarjetas Intel, puedes usar OpenVINO.

Relación entre la memoria de video (VRAM) y el tamaño del modelo

La memoria de video (VRAM) determina el tamaño del modelo que puedes ejecutar.

Cuantos más parámetros tiene el modelo, mayor es la VRAM necesaria. Pero con la cuantización, se puede ejecutar un modelo más grande con menos VRAM.

Ventajas de la serie M de Mac

Apple Silicon (chips de las series M1, M2, M3) tiene ventajas únicas en IA local.

El framework Metal y la arquitectura de memoria unificada de Apple hacen que las Mac ejecuten modelos locales con alta eficiencia.

La memoria unificada significa quela CPU y la GPU comparten memoria,y cuando la VRAM no es suficiente, se puede tomar prestada memoria automáticamente.

Una MacBook Pro con 16GB de memoria unificada puede ejecutar modelos cuantizados de 7B y 13B con fluidez.

No te dejes intimidar por el término "gran modelo". La tecnología de cuantización actual ya permite ejecutar un modelo 7B fluidamente en una computadora normal, y la capacidad de un modelo 7B es suficiente para la mayoría de las tareas cotidianas.

Ollama: la herramienta de IA local más sencilla

  • Sitio web oficial de Ollama:https://ollama.com/
  • Lista de modelos compatibles con Ollama:https://ollama.com/search
  • Tutorial de Ollama:https://www.runoob.com/ollama/ollama-tutorial.html

Ollama es actualmente la herramienta de modelos locales más popular; en una frase:instala modelos como si instalaras una app, y usa la IA como si usaras la línea de comandos.。

Instalación y configuración

Ollama es compatible con macOS, Linux y Windows; el proceso de instalación es muy sencillo.

Dirección de descarga del paquete de instalación:https://ollama.com/download

Instalación con un solo comando:

curl -fsSL https://ollama.com/install.sh | sh

Los usuarios de macOS pueden descargar directamente el paquete de instalación o instalarlo con Homebrew:

# macOS 使用 Homebrew 安装
brew install ollama

# 或者下载安装包：https://ollama.com/download

Los usuarios de Windows pueden descargar el paquete de instalación directamente desde el sitio web oficial y ejecutarlo.

Después de la instalación, inicie el servicio de Ollama:

ollama serve

Una vez que vea que el servicio se inició correctamente, ya puede empezar a usarlo.

Descargar modelos

La biblioteca de modelos de Ollama es muy completa, e incluye modelos populares como Llama, Qwen, Gemma, Mistral, etc.

Para descargar un modelo solo necesita un comando:

Ejemplo

# Descargar Llama 3 (parámetros 8B)
ollama pull llama3

# Descargar Qwen (Tongyi Qianwen, amigable con el chino)
ollama pull qwen

# Descargar Gemma (creado por Google)
ollama pull gemma

# Descargar Mistral
ollama pull mistral

También se puede usarollama run + nombre del modelocomando; si no existe el modelo especificado, se descargará automáticamente:

ollama run qwen

Ejecute el modelo qwen; si no está disponible, se descargará.

Cada modelo tiene diferentes versiones, como 8B, 70B, o diferentes versiones cuantizadas.

Puede usarollama listpara ver los modelos ya descargados:

ollama list

La salida es similar a:

NAME              ID              SIZE      MODIFIED
qwen3.5:latest    6488c96fa5fa    6.6 GB    3 months ago

Llamadas a la API

Ollama incluye una API HTTP; puede llamarla con código, no solo desde la línea de comandos.

De forma predeterminada, Ollama está enhttp://localhost:11434y ofrece el servicio API.

Usar Python para llamar a la API de Ollama:

Ejemplo

# Ruta del archivo: /Users/runoob/ollama_test.py
# Llamar a la API de Ollama con Python

import requests
import json

# Dirección de la API de Ollama
OLLAMA_URL = "http://localhost:11434/api/generate"


def ask_ollama(prompt: str, model: str = "llama3") -> str:
    """
Enviar una solicitud a Ollama y obtener la respuesta del modelo

    Args:
prompt: el mensaje (prompt) ingresado por el usuario
model: el nombre del modelo utilizado, por defecto llama3

    Returns:
El texto de respuesta del modelo
    """
    # Construir los datos de la solicitud
    payload = {
        "model": model,      # Modelo utilizado
        "prompt": prompt,    # Entrada del usuario
        "stream": False      # No usar salida en streaming, devolver todo de una vez
    }

    try:
        # Enviar solicitud POST
        response = requests.post(OLLAMA_URL, json=payload)
        response.raise_for_status()  # Verificar si la solicitud fue exitosa

        # Analizar el JSON devuelto
        result = response.json()
        return result.get("response", "")

    except requests.exceptions.ConnectionError:
        return "Error: no se puede conectar al servicio de Ollama, asegúrese de que Ollama esté iniciado"
    except requests.exceptions.RequestException as e:
        return f"Error de solicitud: {str(e)}"


# Probemos
if __name__ == "__main__":
    # Pregunta de prueba 1
    question1 = "Presenta el tutorial de RUNOOB en una frase"
    answer1 = ask_ollama(question1)
    print(f"Pregunta: {question1}")
    print(f"Respuesta: {answer1}")
    print("-" * 50)

    # Pregunta de prueba 2
    question2 = "Escribe una función en Python que calcule la secuencia de Fibonacci"
    answer2 = ask_ollama(question2)
    print(f"Pregunta: {question2}")
    print(f"Respuesta: {answer2}")

def chat_with_runoob():

Usar la biblioteca Python de Ollama para conversaciones de múltiples turnos
    """

    messages = [
        {
            "role": "system",
            "content": "Eres un asistente de programación amigable llamado RunoobBot. Tus respuestas deben ser concisas, prácticas y con muchos ejemplos de código."
        }

    print("RunoobBot iniciado. Escribe 'quit' para salir.")
    print("-" * 50)

        # Obtener la entrada del usuario

        if user_input.lower() in ["quit", "exit", quit]:
            print("¡Adiós!")
            break

        # Agregar el mensaje del usuario al historial
        messages.append({

        })

        print(f"RunoobBot：{assistant_message}")

        # Agregar la respuesta del asistente al historial
        messages.append({
            "role": "assistant",
            "content": assistant_message
        })


if __name__ == "__main__":
    chat_with_runoob()

Servicio de API local

LM Studio también puede ofrecer un servicio API, compatible con el formato de API de OpenAI.

Esto significa que el código que escriba para OpenAI solo necesita cambiar la dirección de la API y la clave (Key) para usar modelos locales.

Ejemplo

# Ruta del archivo: /Users/runoob/lmstudio_openai.py
# LM Studio compatible con el formato de API de OpenAI

from openai import OpenAI

# Conectar al servidor local de LM Studio
# Nota: primero debe iniciar el servidor en LM Studio
client = OpenAI(
    base_url="http://localhost:1234/v1",
    api_key="lm-studio"  # LM Studio solo necesita este marcador de posición
)


def ask_local_model(prompt: str, system_prompt: str = "Eres un asistente útil.") -> str:
    """
Llamar al modelo local de LM Studio a través de la interfaz compatible con OpenAI
    """
    response = client.chat.completions.create(
        model="local-model",  # Este campo será ignorado por LM Studio
        messages=[
            {"role": "system", "content": system_prompt},
            {"role": "user", "content": prompt}
        ],
        temperature=0.7,
    )
    return response.choices[0].message.content


# Prueba
if __name__ == "__main__":
    question = "Presenta las características del tutorial de RUNOOB"
    answer = ask_local_model(
        prompt=question,
        system_prompt="Eres el servicio de atención al cliente exclusivo de Runoob, respondes profesionalmente preguntas sobre el aprendizaje de programación."
    )

    print(f"Respuesta: {answer}")

Introducción a la cuantización de modelos

La cuantización es una tecnología clave para hacer que los modelos grandes funcionen en computadoras comunes:Ejecutar modelos más grandes con menos memoria de video, manteniendo la mayor parte de la capacidad。

¿Qué es la cuantización?

En pocas palabras, la cuantización consiste en reducir la precisión de los parámetros del modelo.

Los modelos nativos suelen almacenar cada parámetro usando números de punto flotante de 16 bits (FP16) o de 32 bits (FP32).

Después de la cuantización, almacenamos con enteros de 8 bits (INT8) e incluso enteros de 4 bits (INT4).

La precisión se reduce, pero el tamaño y los requisitos de memoria de video también se reducen considerablemente.

Por ejemplo:

PrecisiónTamaño del modelo 7BTamaño del modelo 13BRequisitos de memoria de videoPérdida de calidad
FP1613 GB26 GB高无
Q8_07 GB13 GB中Muy pequeña
Q5_K_M5 GB9 GB低Aceptable
Q4_K_M4 GB7 GBMuy bajoLeve
Q3_K_M3 GB5 GBExtremadamente bajoNotable

La experiencia es: con la cuantización Q8 apenas se nota una pérdida de calidad, y la cuantización Q4 es suficiente para la mayoría de las tareas.

Explicación detallada del formato GGUF

GGUF es actualmente el formato de modelo cuantizado más popular.

El predecesor de GGUF es GGML, desarrollado por el proyecto llama.cpp.

Las ventajas de este formato:

  • Primero,Buena compatibilidad multiplataforma—Funciona en Windows, macOS y Linux, y puede ejecutarse tanto en CPU como en GPU.

  • Segundo,Admite múltiples niveles de cuantización—Desde FP16 hasta Q3, elige según tus necesidades.

  • Tercero,Velocidad de inferencia rápida—Se ha optimizado ampliamente para CPU y GPU.

Ahora la mayoría de las herramientas de modelos locales (Ollama, LM Studio, llama.cpp) admiten el formato GGUF.

Diferencias entre cuantización Q4/Q8

Q4 y Q8 son los dos niveles de cuantización más utilizados.

  • La cuantización Q8 es de 8 bits; cada parámetro se almacena con un entero de 8 bits. La ventaja de Q8 espérdida de calidad mínima, casi idéntica al modelo original; la desventaja es que el tamaño aún no es lo suficientemente pequeño.

  • La cuantización Q4 es de 4 bits; cada parámetro se almacena con un entero de 4 bits. La ventaja de Q4 estamaño pequeño y alta velocidad; la desventaja es que la calidad disminuye notablemente en tareas complejas.

Cómo elegir:

EscenarioNivel de cuantización recomendadoRazón
Memoria de video muy limitada (menos de 8 GB)Q4_K_MQue funcione es lo primero
Conversación diaria, tareas simplesQ4_K_MMejor relación calidad-precio
Escritura, programación, análisisQ5_K_M o Q6_KEquilibrio entre calidad y velocidad
Buscando la mejor calidadQ8_0Cerca de la calidad original

Esquemas de cuantización AWQ/GPTQ

Además del método de cuantización de GGUF, existen otros dos esquemas comunes: AWQ y GPTQ.

AWQ (Activation-aware Weight Quantization) se caracteriza porconservar los pesos que más influyen en el resultado, lo que reduce la pérdida de calidad tras la cuantización.

GPTQ (Gradient-based Post-Training Quantization) se caracteriza porutilizar información de gradientes para optimizar la cuantización, adecuado para escenarios con GPU.

Estos dos esquemas se utilizan principalmente en tarjetas gráficas NVIDIA con soporte CUDA.

Comparación sencilla:

Esquema de cuantizaciónHardware compatibleVelocidadCalidadHerramienta recomendada
GGUFCPU + varios GPU快好Ollama、LM Studio
AWQNVIDIA GPUMuy rápidaMuy buenavLLM、Text Generation WebUI
GPTQNVIDIA GPUMuy rápidaMuy buenaAutoGPTQ、ExLlama

Para principiantes, no te preocupes por estos detalles técnicos: simplemente usa la versión Q4_K_M recomendada en Ollama o LM Studio; es el punto de equilibrio óptimo, ampliamente validado.

Los modelos no son mejores cuanto más grandes, ni cuanto más nuevos—que se adapten a tu hardware y a tu tareason los mejores. Se recomienda descargar algunos modelos 7B para probar y, una vez que te familiarices, actualizar.

Práctica: construir una base de conocimiento local completamente offline

Uno de los casos de uso más prácticos de los modelos locales es crear tu propia base de conocimiento privada:alimentar el modelo con documentos locales para que responda preguntas basadas en esos documentos.。

Todo el sistema funciona completamente fuera de línea; los datos no salen de tu computadora.

Solución técnica

Usamos la tecnología RAG (Generación Aumentada por Recuperación):

1. Dividir los documentos en fragmentos pequeños

2. Usar un modelo de incrustación para convertir cada fragmento en un vector

3. Almacenar los vectores en una base de datos vectorial

4. Al hacer una pregunta, convertir también la pregunta en vector

5. Encontrar los fragmentos de documento más relevantes en la base de datos vectorial

6. Enviar los documentos relevantes junto con la pregunta al modelo local grande

7. El modelo grande responde basándose en el contenido de los documentos

Este proceso suena complejo, pero con herramientas existentes es muy sencillo.

Implementación con Ollama + LangChain

Usamos Python para implementar una versión sencilla:

Ejemplo

# Ruta del archivo: /Users/runoob/local_knowledge_base.py
# Sistema RAG de base de conocimiento local completamente fuera de línea

# Primero instala las dependencias:
# pip install langchain langchain-ollama chromadb pypdf

from langchain_ollama import OllamaLLM, OllamaEmbeddings
from langchain_community.document_loaders import PyPDFLoader, TextLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_community.vectorstores import Chroma
from langchain.chains import RetrievalQA
import os


class LocalKnowledgeBase:
    """Clase de base de conocimiento local, implementa funcionalidad RAG completamente fuera de línea"""

    def __init__(self, model_name: str = "llama3", persist_dir: str = "./chroma_db"):
        """
Inicializar la base de conocimiento

        Args:
model_name: nombre del modelo Ollama a usar
persist_dir: directorio de persistencia de la base de datos vectorial
        """
        self.model_name = model_name
        self.persist_dir = persist_dir

        # 1. Inicializar el LLM (modelo local)
        self.llm = OllamaLLM(model=model_name)

        # 2. Inicializar el modelo de incrustación (incrustación local)
        # Usa nomic-embed-text, este modelo funciona bien tanto en chino como en inglés
        self.embeddings = OllamaEmbeddings(model="nomic-embed-text")

        # 3. Marcador de posición de la base de datos vectorial
        self.vector_store = None
        self.qa_chain = None

    def load_documents(self, document_paths: list):
        """
Cargar documentos y construir la base de datos vectorial

        Args:
document_paths: lista de rutas de documentos
        """
        documents = []

        for path in document_paths:
            if not os.path.exists(path):
                print(f"Advertencia: el archivo {path} no existe, se omite")
                continue

            # Seleccionar el cargador según la extensión del archivo
            if path.lower().endswith(".pdf"):
                loader = PyPDFLoader(path)
            elif path.lower().endswith(".txt"):
                loader = TextLoader(path, encoding="utf-8")
            else:
                print(f"Advertencia: tipo de archivo no compatible {path}, se omite")
                continue

            documents.extend(loader.load())
            print(f"Cargado: {path}")

        if not documents:
            print("No se cargó ningún documento correctamente")
            return

        print(f"Se cargaron en total {len(documents)} fragmentos de documentos")

        # 4. Dividir el documento
        text_splitter = RecursiveCharacterTextSplitter(
            chunk_size=500,      # Cada bloque 500 caracteres
            chunk_overlap=100    # Superposición de 100 caracteres entre bloques
        )
        split_docs = text_splitter.split_documents(documents)
        print(fDividido en {len(split_docs)} fragmentos)

        # 5. Construir la base de datos vectorial
        print(Construyendo la base de datos vectorial...)
        self.vector_store = Chroma.from_documents(
            documents=split_docs,
            embedding=self.embeddings,
            persist_directory=self.persist_dir
        )
        print(¡Base de datos vectorial construida!)

        # 6. Construir la cadena de preguntas y respuestas
        self._build_qa_chain()

    def _build_qa_chain(self):
        """Construir la cadena de preguntas y respuestas RAG"""
        if not self.vector_store:
            print(¡Por favor, cargue primero el documento!)
            return

        # Construir el recuperador
        retriever = self.vector_store.as_retriever(
            search_type="similarity",
            search_kwargs={"k": 3}  # Devolver los 3 fragmentos más relevantes
        )

        # Construir la cadena RAG
        self.qa_chain = RetrievalQA.from_chain_type(
            llm=self.llm,
            chain_type="stuff",
            retriever=retriever,
            return_source_documents=True
        )

    def load_existing_db(self):
        """Cargar la base de datos vectorial existente"""
        if os.path.exists(self.persist_dir):
            self.vector_store = Chroma(
                persist_directory=self.persist_dir,
                embedding_function=self.embeddings
            )
            self._build_qa_chain()
            print(Se ha cargado la base de datos vectorial existente)
            return True
        else:
            print(No se encontró ninguna base de datos vectorial existente)
            return False

    def ask(self, question: str) -> dict:
        """
Hacer preguntas a la base de conocimiento

        Args:
question: pregunta

        Returns:
Diccionario que contiene la respuesta y las fuentes de referencia
        """
        if not self.qa_chain:
            return {"error": ¡Cargue primero el documento o la base de datos existente!}

        # Construir una plantilla de prompt para fomentar respuestas en chino
        result = self.qa_chain.invoke({
            "query": f"""Por favor, responda las siguientes preguntas en chino. Si la respuesta está en el contexto, indíquelo claramente.
Si no hay respuesta en el contexto, diga honestamente "no se puede responder según la información proporcionada".

Pregunta: {question}
"""
        })

        return {
            "question": question,
            "answer": result["result"],
            "sources": [doc.page_content for doc in result["source_documents"]]
        }


# ============================================
# Ejemplo de uso
# ============================================

if __name__ == "__main__":
    # 1. Crear una instancia de la base de conocimiento
    kb = LocalKnowledgeBase(model_name="qwen")  # Usar Qwen, mejor para chino

    # 2. Intentar cargar la base de datos existente; de lo contrario, cargar el documento
    if not kb.load_existing_db():
        # Preparar algunos documentos, por ejemplo, guardar algunos tutoriales de RUNOOB como txt
        sample_docs = [
            "/Users/runoob/documents/runoob_python_tutorial.txt",
            "/Users/runoob/documents/company_handbook.pdf",
        ]
        kb.load_documents(sample_docs)

    # 3. Preguntas y respuestas interactivas
    print("=" * 50)
    print(¡La base de conocimiento local de Runoob se ha iniciado!)
    print(Ingrese su pregunta, o escriba 'quit' para salir)
    print("=" * 50)

    while True:
        user_input = input("\nSu pregunta:)

        if user_input.lower() in ["quit", "exit", Salir]:
            print(¡Adiós!)
            break

        if not user_input.strip():
            continue

        # Preguntar
        result = kb.ask(user_input)

        if "error" in result:
            print(fError: {result['error']})
            continue

        print(f"\nRespuesta: {result['answer']})
        print("\nFuentes de referencia:)
        for i, source in enumerate(result["sources"], 1):
            print(f"\n[{i}] {source[:200]}...")

Antes de usar este sistema, es necesario descargar el modelo de incrustación:

Ejemplo

# Descargar el modelo de incrustación
ollama pull nomic-embed-text

# Descargar el modelo principal (si aún no se ha descargado)
ollama pull qwen

Así tendrás un sistema de base de conocimiento privado que se ejecuta completamente en local.

Puedes poner tus notas, documentos y libros electrónicos y dejar que la IA te ayude a buscar y responder preguntas.

Todos los datos de este sistema están en tu equipo: los documentos en tu disco duro, la base de datos vectorial en tu directorio y el modelo en tu computadora; no tienes que preocuparte por fugas de datos.

Consejos para optimizar el rendimiento

El modelo local ya está funcionando, pero ¿cómo hacer que vaya más rápido? Aquí tienes algunos consejos prácticos.

Elegir el nivel de cuantización adecuado

Esta es la optimización más sencilla y eficaz: cuanto menor sea el nivel de cuantización, mayor será la velocidad.

Si Q4 funciona, no uses Q8; si Q8 funciona, no uses FP16.

Ajustar el tamaño de la ventana de contexto

Cuanto mayor sea la ventana de contexto, más cálculo se requiere.

Si no necesitas un contexto muy largo, puedes configurarlo en el Modelfile de Ollama:

Ejemplo

# Crear un modelo personalizado, limitar la ventana de contexto
# Crear un nuevo archivo Modelfile

echo "FROM llama3
PARAMETER num_ctx 2048" > Modelfile

# Crear el modelo personalizado
ollama create llama3-fast -f Modelfile

# Ejecutar
ollama run llama3-fast

Reducir el contexto de los 8192 predeterminados a 2048 hará que sea bastante más rápido.

Usar aceleración por GPU

Si tienes una tarjeta gráfica NVIDIA o Apple Silicon en tu Mac, asegúrate de que Ollama esté usando la GPU en lugar de la CPU.

Ollama detecta y usa la GPU automáticamente, pero a veces conviene comprobarlo.

En el registro de inicio de Ollama, deberías ver información similar a "Metal GPU activated" o "CUDA activated".

Usar parámetros de muestreo más rápidos

Algunos parámetros de muestreo afectan la velocidad:

Ejemplo

# Crear un Modelfile optimizado para la velocidad
# Archivo: Modelfile.fast

echo "FROM llama3
PARAMETER temperature 0.7
PARAMETER top_k 20
PARAMETER top_p 0.9
PARAMETER num_predict 256" > Modelfile.fast

# Crear y ejecutar
ollama create llama3-optimized -f Modelfile.fast
ollama run llama3-optimized

Descripción de parámetros:

ParámetroFunciónSugerencia de optimización
temperatureControlar la aleatoriedadCon moderación es suficiente, no afecta la velocidad
top_kLimitar el número de palabras candidatasPonerlo más pequeño (20-40) puede acelerar
top_pUmbral de probabilidad acumulativaEl valor predeterminado de 0.9 está bien
num_predictNúmero máximo de tokens generadosLimitarlo según sea necesario
num_ctxTamaño de la ventana de contextoCon que sea suficiente, cuanto más pequeño, más rápido

Desactivar funciones innecesarias

Si usas llamadas a la API y no necesitas salida en streaming, puedes establecer stream en false.

Aunque esto no hará que la inferencia sea más rápida, reducirá la sobrecarga de transferencia de red.

La optimización del rendimiento es un arte de equilibrio: velocidad, calidad y memoria de video; no se pueden tener las tres a la vez. Según tus necesidades, solo tienes que encontrar el punto de equilibrio adecuado para ti.
