Implementación de ingeniería de IA

Has ejecutado un modelo en tu computadora portátil que genera respuestas rápida y correctamente, pero cuando lo pones en un servidor y cien usuarios lo llaman al mismo tiempo, la situación cambia:Algunos usuarios esperan diez segundos para recibir una respuesta, algunas solicitudes simplemente superan el tiempo de espera y arrojan errores, la memoria de la GPU se llena en un momento, y el importe de la factura sube de forma que te duele.

Este es el problema que debe resolver el despliegue de IA:Convertir un modelo que funciona en un servicio útil.。

El cuello de botella de los servicios web tradicionales suele estar en la CPU y la base de datos.

El cuello de botella de los servicios de IA se encuentra principalmente en la GPU: si hay suficiente memoria de video, si el cálculo es rápido, y cómo se ponen en cola las solicitudes concurrentes.

Los desafíos centrales del despliegue de IA se pueden resumir en tres palabras: latencia, rendimiento (throughput) y costo.

MétricaSignificadoExperiencia del usuario
Latencia (Latency)Tiempo desde que el usuario envía la solicitud hasta que recibe la primera palabra¿Es rápido?
Rendimiento (Throughput)Cuántas solicitudes puede procesar por segundoSi puede atender a muchas personas al mismo tiempo
Costo (Cost)Costo de GPUs/servidores para ejecutar el servicio¿Es caro?

Un buen despliegue de IA consiste en encontrar el equilibrio entre estos tres: latencia suficientemente baja, rendimiento suficientemente alto y costo controlable.

Marco de servicio de modelos

Para envolver un modelo entrenado como un servicio API, se necesita un marco especializado. Esta sección presenta tres opciones principales: vLLM, TGI y Ollama.

vLLM: Inferencia de alto rendimiento impulsada por PagedAttention

vLLM es un motor de inferencia desarrollado por el equipo de UC Berkeley, y su mayor característica es la velocidad.

La innovación principal de vLLM esPagedAttention—una técnica para gestionar eficientemente la memoria de video, inspirada en la paginación de memoria virtual de los sistemas operativos.

En los marcos de inferencia tradicionales, la caché KV (cache de claves y valores) de cada solicitud necesita ocupar un espacio contiguo de memoria de video.

Cuando las solicitudes tienen longitudes diferentes, la memoria de video se fragmenta y la utilización es baja.

PagedAttention divide la memoria de video en páginas de tamaño fijo; la caché KV de cada solicitud puede almacenarse de forma dispersa en diferentes páginas, y las posiciones se registran mediante una tabla de páginas.

De esta manera, la utilización de la memoria de video mejora significativamente y se pueden atender más solicitudes al mismo tiempo.

Ejemplo

# Instalar vLLM
pip install vllm

# Iniciar un servicio API compatible con OpenAI usando vLLM
# --model especifica el modelo, --host y --port especifican la dirección de escucha
# --tensor-parallel-size para usar varias GPUs en inferencia paralela

    --model Qwen/Qwen2.5-7B-Instruct \
    --host 0.0.0.0 \
    --port 8000 \
    --tensor-parallel-size 1 \
    --gpu-memory-utilization 0.9 \

Su característica es un ecosistema completo, con integración profunda con Hugging Face Hub, y soporte para optimizaciones como Flash Attention y procesamiento por lotes dinámico.

        "model": model,
        "messages": messages,
        "stream": True,

            "num_ctx": 8192,

                break

Técnicas de optimización de inferencia

El mismo modelo, ejecutado de diferentes maneras, puede tener diferencias de varias veces en velocidad y costo.

Esta sección presenta técnicas de optimización de inferencia comunes en entornos de producción.

Procesamiento por lotes continuo (Continuous Batching)

El procesamiento por lotes tradicional es estático: se acumula un lote de solicitudes, se procesan juntas, y solo después de completarlas todas se procesa el siguiente lote.

El problema es: algunas solicitudes son muy cortas (por ejemplo, generar solo 10 caracteres), y otras muy largas (generar 500 caracteres).

Las solicitudes cortas deben esperar a que las largas terminen para liberar recursos juntas, y la utilización de la GPU no aumenta.

Procesamiento por lotes continuoes dinámico: cuando una solicitud se completa, inmediatamente se agrega una nueva solicitud de la cola, sin esperar a que todo el lote termine.

Así la GPU trabaja casi siempre a plena carga, y el throughput aumenta significativamente.

Tanto vLLM como TGI incluyen procesamiento por lotes continuo integrado; no necesitas implementarlo manualmente, solo activarlo.

Muestreo especulativo (Speculative Decoding)

Un modelo grande, para generar un carácter, necesita ejecutar una propagación hacia adelante completa, lo cual es lento.

La idea del muestreo especulativo es:usar un modelo pequeño para "adivinar" los siguientes caracteres, y luego hacer que el modelo grande los verifique de una sola vez.。

El modelo pequeño adivina rápido; aunque no siempre acierta, la parte acertada puede emitirse en lote.

La parte incorrecta se descarta y se vuelve a adivinar.

De esta manera, la velocidad general puede mejorar de 2 a 3 veces, y la calidad de salida no cambia.

Ejemplo

# Habilitar muestreo especulativo en vLLM
# --speculative-model especifica el modelo pequeño (modelo borrador)
# --num-speculative-tokens especifica cuántos caracteres adivinar cada vez
python -m vllm.entrypoints.openai.api_server \
    --model Qwen/Qwen2.5-7B-Instruct \
    --speculative-model Qwen/Qwen2.5-0.5B-Instruct \
    --num-speculative-tokens 5 \
    --host 0.0.0.0 \
    --port 8000

Inferencia cuantizada: AWQ y GPTQ

La cuantización de modelos consiste en comprimir los pesos del modelo desde números de punto flotante de 16 bits (FP16) a enteros de 8 o 4 bits.

La ocupación de memoria de video se reduce a la mitad o incluso menos, y la velocidad de inferencia puede ser aún mayor.

Los dos esquemas de cuantización más utilizados son AWQ y GPTQ.

Esquema de cuantizaciónCaracterísticasPérdida de precisiónVelocidad de inferencia
AWQCuantización de pesos sensible a activacionesMínima快
GPTQCuantización optimizada por capas小快
GGUFAdecuada para ejecución localAceptable快

# Ruta del archivo: awq_inference.py
from transformers import AutoModelForCausalLM, AutoTokenizer
import torch

# Cargar modelo cuantizado AWQ
model_name = "TheBloke/Qwen2.5-7B-Instruct-AWQ"

# Nota: para ejecutarlo realmente se necesita instalar la librería autoawq
# pip install autoawq

tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    torch_dtype=torch.float16,
    device_map="auto",
    trust_remote_code=True,
)

# Inferencia
messages = [
    {"role": "system", "content": "Eres un asistente de IA servicial."},
    {"role": "user", "content": "Presenta runoob"}
]

text = tokenizer.apply_chat_template(
    messages,
    tokenize=False,
    add_generation_prompt=True
)

inputs = tokenizer([text], return_tensors="pt").to(model.device)

with torch.no_grad():
    outputs = model.generate(
        **inputs,
        max_new_tokens=500,
        temperature=0.7,
    )

response = tokenizer.decode(
    outputs[0][inputs.input_ids.shape[1]:],
    skip_special_tokens=True
)
print(response)

Destilación de modelos

La destilación consiste en usar un modelo grande (maestro) para entrenar un modelo pequeño (estudiante), de modo que el modelo pequeño aprenda las capacidades del modelo grande.

El modelo pequeño es más rápido y más económico; aunque su rendimiento es ligeramente inferior, es suficiente en muchos escenarios.

Por ejemplo, usando Qwen2.5-72B como maestro para entrenar un estudiante Qwen2.5-7B, el resultado puede acercarse al 72B, pero con la velocidad y el costo de un 7B.

Los beneficios de la destilación suelen ser:El tamaño del modelo se reduce a 1/10, la velocidad de inferencia mejora de 5 a 10 veces, y el rendimiento se conserva en más del 90%.。

Diseño de servicios API

Envolver el modelo es solo el primer paso; una API en producción necesita muchas más funciones: autenticación, limitación de velocidad, respuestas en streaming y manejo de errores.

FastAPI es una excelente opción para esto.

Encapsulación de servicios LLM con FastAPI

Vamos a escribir un servicio API completo que incluya autenticación, limitación de velocidad y respuestas en streaming.

Ejemplo

# Ruta del archivo: llm_api_server.py
from fastapi import FastAPI, Depends, HTTPException, status
from fastapi.security import HTTPBearer, HTTPAuthorizationCredentials
from fastapi.responses import StreamingResponse
from pydantic import BaseModel, Field
from typing import List, Optional, AsyncGenerator
from enum import Enum
import time
import asyncio
import uuid
from datetime import datetime, timedelta
from collections import defaultdict

# ============================================
# 1. Inicialización de la aplicación y configuración
# ============================================

app = FastAPI(title="RUNOOB LLM API", version="1.0.0")

# Autenticación simple por API Key (en producción se recomienda un esquema más robusto)
VALID_API_KEYS = {
    "sk-runoob-123456": {"user": "demo_user", "quota": 1000},
    "sk-runoob-789012": {"user": "pro_user", "quota": 10000},
}

# Limitador de velocidad simple (implementación en memoria, en producción se recomienda Redis)
class RateLimiter:
    def __init__(self):
        self.requests = defaultdict(list)  # key -> [timestamp, ...]

    async def is_allowed(self, key: str, max_requests: int, window_seconds: int) -> bool:
        """Comprueba si se ha superado el límite de velocidad"""
        now = time.time()
        # Limpiar registros expirados
        self.requests[key] = [t for t in self.requests[key] if now - t < window_seconds]
        # Comprobar si se superó el límite
        if len(self.requests[key]) >= max_requests:
            return False
        # Registrar esta solicitud
        self.requests[key].append(now)
        return True

rate_limiter = RateLimiter()

# ============================================
# 2. Modelo de datos
# ============================================

class Role(str, Enum):
    SYSTEM = "system"
    USER = "user"
    ASSISTANT = "assistant"

class Message(BaseModel):
    role: Role = Field(..., description="Rol del mensaje")
    content: str = Field(..., description="Contenido del mensaje")

class ChatCompletionRequest(BaseModel):
    model: str = Field(..., description="Nombre del modelo")
    messages: List[Message] = Field(..., description="Lista de mensajes de la conversación")
    temperature: Optional[float] = Field(default=0.7, ge=0, le=2, description="Temperatura de muestreo")
    top_p: Optional[float] = Field(default=0.9, ge=0, le=1, description="Muestreo Top-P")
    max_tokens: Optional[int] = Field(default=500, ge=1, le=4096, description="Número máximo de tokens a generar")
    stream: Optional[bool] = Field(default=False, description="Si se debe emitir en streaming")

class ChatCompletionResponse(BaseModel):
    id: str
    object: str = "chat.completion"
    created: int
    model: str
    choices: List[dict]
    usage: dict

# ============================================
# 3. Dependencia de autenticación
# ============================================

security = HTTPBearer()

async def get_current_user(credentials: HTTPAuthorizationCredentials = Depends(security)):
    """Verifica la API Key y devuelve la información del usuario"""
    api_key = credentials.credentials
    if api_key not in VALID_API_KEYS:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Invalid API Key"
        )
    return VALID_API_KEYS[api_key]

# ============================================
# 4. Simulación de generación del LLM (en proyectos reales, reemplazar por una llamada a un modelo real)
# ============================================

async def mock_llm_generate(messages: List[Message], max_tokens: int) -> str:
    """Simula el proceso de generación del LLM"""
    # Esto es solo una simulación; en un proyecto real deberías llamar al modelo real
    response_text = (
        "¡Hola! Soy el asistente de IA de RUNOOB."\n\n"
        "RUNOOB ofrece una gran variedad de tutoriales de programación, incluyendo Python, Java, C++, desarrollo frontend, etc."\n"
        "¡Puedes visitar https://www.runoob.com para aprender más contenido!"\n\n"
        "¿En qué puedo ayudarte?"
    )
    # Simular latencia de generación
    await asyncio.sleep(0.5)
    return response_text

async def mock_llm_generate_stream(messages: List[Message], max_tokens: int) -> AsyncGenerator[str, None]:
    """Simula la generación en streaming del LLM"""
    response_text = await mock_llm_generate(messages, max_tokens)
    # Salida carácter por carácter para simular el efecto de streaming
    for char in response_text:
        yield char
        await asyncio.sleep(0.03)  # Retraso de 30 ms por carácter

# ============================================
# 5. Endpoints de la API
# ============================================

@app.post("/v1/chat/completions")
async def chat_completions(
    request: ChatCompletionRequest,
    user: dict = Depends(get_current_user)
):
    """Interfaz de chat completion, compatible con el formato de OpenAI"""

    # Verificación de límite de velocidad: máximo 60 solicitudes por minuto por usuario
    user_key = user["user"]
    if not await rate_limiter.is_allowed(user_key, max_requests=60, window_seconds=60):
        raise HTTPException(
            status_code=status.HTTP_429_TOO_MANY_REQUESTS,
            detail="Rate limit exceeded"
        )

    # Generar ID de solicitud
    request_id = f"chatcmpl-{uuid.uuid4().hex[:24]}"
    created = int(datetime.now().timestamp())

    if request.stream:
        # Respuesta en streaming
        async def stream_generator():
            async for token in mock_llm_generate_stream(request.messages, request.max_tokens):
                # Construir chunk en formato SSE
                chunk = {
                    "id": request_id,
                    "object": "chat.completion.chunk",
                    "created": created,
                    "model": request.model,
                    "choices": [{
                        "index": 0,
                        "delta": {"content": token},
                        "finish_reason": None
                    }]
                }
                yield f"data: {__import__('json').dumps(chunk)}\n\n"
            # Enviar marcador de finalización
            yield "data: [DONE]\n\n"

        return StreamingResponse(
            stream_generator(),
            media_type="text/event-stream",
            headers={"Cache-Control": "no-cache"}
        )

    else:
        # Respuesta no streaming
        response_text = await mock_llm_generate(request.messages, request.max_tokens)

        return ChatCompletionResponse(
            id=request_id,
            created=created,
            model=request.model,
            choices=[{
                "index": 0,
                "message": {
                    "role": "assistant",
                    "content": response_text
                },
                "finish_reason": "stop"

Ejemplo

# Ruta del archivo: redis_rate_limiter.py
import redis.asyncio as redis
import time

class RedisRateLimiter:
    """Limitador de velocidad distribuido basado en Redis"""

    def __init__(self, redis_url: str = "redis://localhost:6379"):
        self.redis = redis.from_url(redis_url)

    async def is_allowed(
        self,
        key: str,
        max_requests: int,
        window_seconds: int
    ) -> bool:
        """
Algoritmo de limitación de velocidad por ventana deslizante
key: clave de limitación (por ejemplo, user_id o api_key)
max_requests: número máximo de solicitudes en la ventana
window_seconds: tamaño de la ventana (segundos)
        """
        now = time.time()
        window_start = now - window_seconds

        # Claves de Redis
        redis_key = f"rate_limit:{key}"

        # Usar operación atómica con pipeline
        async with self.redis.pipeline() as pipe:
            # 1. Eliminar registros fuera de la ventana
            pipe.zremrangebyscore(redis_key, 0, window_start)
            # 2. Contar las solicitudes dentro de la ventana actual
            pipe.zcard(redis_key)
            # 3. Agregar la solicitud actual
            pipe.zadd(redis_key, {str(now): now})
            # 4. Establecer tiempo de expiración
            pipe.expire(redis_key, window_seconds)
            # Ejecutar
            _, current_count, _, _ = await pipe.execute()

        return current_count < max_requests

    async def close(self):
        await self.redis.close()


# Ejemplo de uso

Balanceo de carga y escalado

Cuando hay cada vez más usuarios y un solo servidor no da abasto, necesitas añadir máquinas y distribuir el tráfico entre varias.

Esto es lo que resuelven el balanceo de carga y el escalado automático.

Diseño de servicios sin estado

Primero, recuerda:El servicio de IA debe ser sin estado (stateless)。

Sin estado significa que las solicitudes no comparten memoria; cualquier servidor puede procesar cualquier solicitud.

Así el escalado es simple: solo añade máquinas, sin preocuparte por la sincronización de datos.

El estado de la sesión (por ejemplo, el historial de la conversación) puede almacenarse en el cliente (para que el usuario lo envíe cada vez) o en Redis.

Pruebas A/B de modelos de IA

Has lanzado una nueva versión del modelo, ¿cómo saber si es mejor que la anterior? Con pruebas A/B.

El núcleo de las pruebas A/B es:Dividir el tráfico en varios grupos, cada grupo usa un modelo diferente y comparar las métricas.。

Estrategia de división de tráfico

Hay varias formas comunes de dividir el tráfico:

Ejemplo

# Ruta del archivo: ab_test_router.py
import hashlib
import random
from typing import Dict, List, Tuple
from dataclasses import dataclass

@dataclass
class Variant:
    """Una variante de las pruebas A/B"""
    name: str           # Nombre de la variante
    model_name: str     # Nombre del modelo
    weight: int         # Peso del tráfico
    config: dict        # Otra configuración


class ABTestRouter:
    """Enrutador de tráfico para pruebas A/B"""

    def __init__(self, test_name: str, variants: List[Variant]):
        self.test_name = test_name
        self.variants = variants
        # Calcular el peso total
        total_weight = sum(v.weight for v in variants)
        # Construir rangos segmentados
        self.ranges: List[Tuple[int, int, Variant]] = []
        current = 0
        for v in variants:
            self.ranges.append((current, current + v.weight, v))
            current += v.weight
        self.total_weight = total_weight

    def get_variant_by_user(self, user_id: str) -> Variant:
        """
División estable basada en el ID de usuario
El mismo usuario siempre se asigna al mismo grupo para evitar experiencias inconsistentes.
        """
        # Calcular la puntuación del usuario con hash
        hash_input = f"{self.test_name}-{user_id}".encode()
        hash_value = hashlib.md5(hash_input).hexdigest()
        # Convertir a un número de 0-999
        score = int(hash_value[:4], 16) % 1000
        # Buscar la variante correspondiente
        for start, end, variant in self.ranges:
            if start <= score < end:
                return variant
        return self.variants[-1]

    def get_variant_random(self) -> Variant:
        """División aleatoria (adecuada para escenarios que no requieren adherencia)"""
        score = random.randint(0, self.total_weight - 1)
        for start, end, variant in self.ranges:
            if start <= score < end:
                return variant
        return self.variants[-1]

Determinación de la significancia estadística

Una vez obtenidos los datos, no se puede decir que el grupo B es mejor solo porque A tiene 52% y B tiene 55%.

Hay que realizar una prueba de significancia estadística para confirmar que la diferencia no se debe a fluctuaciones aleatorias.

Ejemplo

# Ruta del archivo: ab_test_analysis.py
import math
from typing import Tuple

def calculate_z_test(
    control_conv: float,
    treatment_conv: float,
    control_total: int,
    treatment_total: int
) -> Tuple[float, float]:
    """
Calcular el p-value de la prueba Z
control_conv: tasa de conversión del grupo de control
treatment_conv: tasa de conversión del grupo de tratamiento
control_total: tamaño de muestra del grupo de control
treatment_total: tamaño de muestra del grupo de tratamiento
    """
    # Tasa de conversión combinada
    p_pool = (control_conv * control_total + treatment_conv * treatment_total) / (control_total + treatment_total)
    # Error estándar
    se_pool = math.sqrt(p_pool * (1 - p_pool) * (1 / control_total + 1 / treatment_total))
    # Estadístico Z
    z_score = (treatment_conv - control_conv) / se_pool
    # Calcular el p-value (prueba de dos colas)
    p_value = 2 * (1 - normal_cdf(abs(z_score)))
    return z_score, p_value

def normal_cdf(x: float) -> float:
    """Función de distribución acumulada de la normal estándar (aproximación)"""
    return (1.0 + math.erf(x / math.sqrt(2.0))) / 2.0

def analyze_ab_test(
    control_conversions: int,
    control_total: int,
    treatment_conversions: int,
    treatment_total: int,
    alpha: float = 0.05
):
    """Analizar los resultados de la prueba A/B"""
    control_conv = control_conversions / control_total
    treatment_conv = treatment_conversions / treatment_total

    z_score, p_value = calculate_z_test(
        control_conv, treatment_conv,
        control_total, treatment_total
    )

    relative_lift = (treatment_conv - control_conv) / control_conv

    print("Análisis de resultados de la prueba A/B")
    print("=" * 50)
    print(f"Grupo de control: {control_conversions}/{control_total} ({control_conv:.2%})")
    print(f"Grupo de tratamiento: {treatment_conversions}/{treatment_total} ({treatment_conv:.2%})")
    print(f"Mejora relativa: {relative_lift:+.2%}")
    print("-" * 50)
    print(f"Estadístico Z: {z_score:.4f}")
    print(f"p-value: {p_value:.4f}")
    print("-" * 50)

    if p_value < alpha:
        print(f"&#x2705; Resultado estadísticamente significativo (p < {alpha})")
        if relative_lift > 0:
            print(" ¡El grupo de tratamiento se desempeñó mejor!")
        else:
            print(" ¡El grupo de control se desempeñó mejor!")
    else:
        print(f"&#x274c; Resultado no significativo (p >= {alpha})")
        print(" No se puede determinar qué versión es mejor, se necesitan más datos")

Monitoreo específico de IA: detección de deriva (drift)

Los modelos de IA no solo se "rompen", también se "desvían": con el tiempo, la distribución de los datos cambia y el rendimiento del modelo disminuye.

Ejemplo

# Ruta del archivo: drift_detection.py
import numpy as np
from scipy import stats
from dataclasses import dataclass
from typing import List, Tuple
import json

@dataclass
class DistributionStats:
    """Información de estadísticas de distribución"""
    mean: float
    std: float
    min: float
    max: float
    percentiles: dict


class DataDriftDetector:
    """Detector de deriva de datos"""

    def __init__(self, baseline_data: np.ndarray):
        """Inicializar con datos de referencia"""
        self.baseline_stats = self._compute_stats(baseline_data)
        self.baseline_data = baseline_data

    def _compute_stats(self, data: np.ndarray) -> DistributionStats:
        """Calcular estadísticas de los datos"""
        return DistributionStats(
            mean=float(np.mean(data)),
            std=float(np.std(data)),
            min=float(np.min(data)),
            max=float(np.max(data)),
            percentiles={
                "p10": float(np.percentile(data, 10)),
                "p25": float(np.percentile(data, 25)),
                "p50": float(np.percentile(data, 50)),
                "p75": float(np.percentile(data, 75)),
                "p90": float(np.percentile(data, 90))
            }
        )

    def detect(self, new_data: np.ndarray, threshold: float = 0.05) -> dict:
        """
Detectar deriva
Devuelve: si hay deriva, valor p, estadísticas
        """
        # Prueba KS: comparar si dos distribuciones son iguales
        ks_statistic, ks_pvalue = stats.ks_2samp(self.baseline_data, new_data)

        # Calcular estadísticas de los nuevos datos
        new_stats = self._compute_stats(new_data)

        # Calcular la diferencia de medias (porcentaje)
        mean_diff_pct = abs((new_stats.mean - self.baseline_stats.mean) / self.baseline_stats.mean * 100)

        # Determinar si hay deriva
        is_drift = ks_pvalue < threshold

        return {
            "is_drift": is_drift,
            "ks_statistic": float(ks_statistic),
            "ks_pvalue": float(ks_pvalue),
            "mean_diff_percent": float(mean_diff_pct),
            "baseline_stats": self.baseline_stats,
            "new_stats": new_stats,
            "threshold": threshold
        }

Estrategias de optimización de costos

Las GPU son caras; optimizar costos no es "tacañería", es "capacidad de ingeniería".

Caché de solicitudes: caché semántica

El caché tradicional es de coincidencia exacta: si la pregunta es exactamente la misma, devuelve directamente la respuesta anterior.

El caché semántico va más allá: preguntas similares también pueden reutilizar respuestas anteriores o resultados intermedios.

Ejemplo

# Ruta del archivo: semantic_cache.py
import numpy as np
from typing import Optional, Tuple
import time

class SemanticCache:
    """Implementación simple de caché semántica"""

    def __init__(self, threshold: float = 0.9):
        self.threshold = threshold
        self.queries = []  # Almacenar los vectores de las preguntas
        self.answers = []  # Almacenar las respuestas correspondientes
        self.timestamps = []  # Almacenar el tiempo

    def _simulate_embedding(self, text: str) -> np.ndarray:
        """
Simula embeddings; en proyectos reales se usan OpenAI Embeddings, Sentence-Transformers, etc.
        """
        # Simulación simple con hash; en proyectos reales se usa un modelo de embedding real
        np.random.seed(hash(text) % (2**32))
        return np.random.randn(128)  # Vector de 128 dimensiones

    def _cosine_similarity(self, a: np.ndarray, b: np.ndarray) -> float:
        """Calcular la similitud del coseno"""
        return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

    def get(self, query: str) -> Optional[str]:
        """Consultar el caché; si se encuentra una pregunta similar, devolver la respuesta"""
        query_vec = self._simulate_embedding(query)

        for i, (q_vec, answer, ts) in enumerate(zip(self.queries, self.answers, self.timestamps)):
            # Limpieza por expiración (más de 1 hora)
            if time.time() - ts > 3600:
                continue

            similarity = self._cosine_similarity(query_vec, q_vec)
            if similarity >= self.threshold:
                return answer

        return None

    def put(self, query: str, answer: str):
        """Guardar en el caché"""
        query_vec = self._simulate_embedding(query)
        self.queries.append(query_vec)
        self.answers.append(answer)
        self.timestamps.append(time.time())

        # Control de capacidad simple: máximo 1000 entradas
        if len(self.queries) > 1000:
            self.queries = self.queries[-1000:]
            self.answers = self.answers[-1000:]
            self.timestamps = self.timestamps[-1000:]


# Ejemplo de uso
def main():
    cache = SemanticCache(threshold=0.9)

    # Primera solicitud
    query1 = "¿Cómo leer un archivo CSV con Python?"
    print(f"Consulta 1: {query1}")
    answer1 = cache.get(query1)
    if answer1:
        print(f"Acierto de caché: {answer1}")
    else:
        print("Fallo de caché, llamando al modelo...")
        answer1 = "Se puede usar pandas.read_csv('file.csv') para leer un archivo CSV."
        cache.put(query1, answer1)
        print(f"Guardado en caché: {answer1}")

    print()

    # Segunda vez: pregunta similar
    query2 = "¿Cómo se lee un CSV con Python?"
    print(f"Consulta 2: {query2}")
    answer2 = cache.get(query2)
    if answer2:
        print(f"Acierto de caché: {answer2}")
    else:
        print("Fallo de caché, llamando al modelo...")

    print()

    # Tercera vez: pregunta completamente diferente
    query3 = "¿Qué es el aprendizaje automático?"
    print(f"Consulta 3: {query3}")
    answer3 = cache.get(query3)
    if answer3:
        print(f"Acierto de caché: {answer3}")
    else:
        print("Fallo de caché, llamando al modelo...")


if __name__ == "__main__":
    main()

Enrutamiento de modelos: modelo pequeño como respaldo

No todas las solicitudes necesitan un modelo grande. Para preguntas simples se usa un modelo pequeño; para preguntas complejas, un modelo grande.

Ejemplo

# Ruta del archivo: model_router.py
from typing import List, Dict, Any
from dataclasses import dataclass

@dataclass
class ModelConfig:
    name: str
    cost_per_1k_tokens: float
    max_tokens: int
    capabilities: List[str]  # Lista de capacidades


class SmartModelRouter:
    """Enrutador inteligente de modelos"""

    def __init__(self):
        self.models = {
            "small": ModelConfig(
                name="Qwen2.5-0.5B-Instruct",
                cost_per_1k_tokens=0.001,
                max_tokens=4096,
                capabilities=["chat", "simple_qa", "summarization"]
            ),
            "medium": ModelConfig(
                name="Qwen2.5-7B-Instruct",
                cost_per_1k_tokens=0.01,
                max_tokens=8192,
                capabilities=["chat", "qa", "coding", "reasoning"]
            ),
            "large": ModelConfig(
                name="Qwen2.5-72B-Instruct",
                cost_per_1k_tokens=0.1,
                max_tokens=32768,
                capabilities=["complex_qa", "advanced_coding", "deep_reasoning"]
            )
        }

    def _classify_query(self, query: str) -> str:
        """
Clasificación simple de preguntas (en un proyecto real se puede usar un clasificador)
Devuelve: small/medium/large
        """
        query_lower = query.lower()

        # Palabras clave para preguntas simples
        simple_keywords = [
            "Hola", "hello", "Gracias", "hi", "Adiós",
            "El clima de hoy", "Qué hora es", "Fecha",
            "Ayuda con traducción", "translate",
            "Breve introducción", "Qué es"
        ]

        # Palabras clave para preguntas complejas
        complex_keywords = [
            "Código", "Escribe un", "Implementa", "code", "python",
            "Analiza", "Explica por qué", "Deducir", "Demostrar",
            "Comparar", "Contrastar", "Diferencia",
            "Detallado", "Profundo", "Complejo"
        ]

        # Comprobar si es una pregunta simple
        for keyword in simple_keywords:
            if keyword in query_lower:
                return "small"

        # Comprobar si es una pregunta compleja
        for keyword in complex_keywords:
            if keyword in query_lower:
                return "large"

        # Por defecto, usar el modelo mediano
        return "medium"

    def route(self, query: str, user_tier: str = "free") -> str:
        """
Decisión de enrutamiento
        """
        # Primero clasificar la pregunta
        category = self._classify_query(query)

        # Los usuarios de pago pueden usar un modelo mejor
        if user_tier == "pro":
            upgrade_map = {
                "small": "small",
                "medium": "medium",
                "large": "large"
            }
            category = upgrade_map[category]
        elif user_tier == "enterprise":
            upgrade_map = {
                "small": "medium",
                "medium": "large",
                "large": "large"
            }
            category = upgrade_map.get(category, category)

        # Devolver el nombre del modelo
        return self.models[category].name

    def get_cost_estimate(self, model_name: str, input_tokens: int, output_tokens: int) -> float:
        """Estimar el costo"""
        for model in self.models.values():
            if model.name == model_name:
                return (input_tokens + output_tokens) * model.cost_per_1k_tokens / 1000
        return 0.0

Manejo de fallos y degradación

En producción no existe "no tener fallos", solo existe "cómo responder con elegancia cuando hay fallos".

Estrategias de degradación

Ejemplo

# Ruta del archivo: fallback_handler.py
import time
from typing import Optional
from dataclasses import dataclass
from enum import Enum

class ServiceStatus(Enum):
    HEALTHY = "healthy"
    DEGRADED = "degraded"
    FAILED = "failed"

@dataclass
class FallbackResponse:
    content: str
    is_fallback: bool
    fallback_reason: Optional[str] = None


class FallbackHandler:
    """Manejador de degradación"""

    def __init__(self):
        self.error_count = 0
        self.last_error_time = 0
        self.circuit_open = False
        self.circuit_open_time = 0

        # Configuración del interruptor de circuito
        self.error_threshold = 5  # Abrir el interruptor tras 5 errores consecutivos
        self.circuit_timeout = 30  # Intentar recuperar 30 segundos después de abrir el interruptor

    def _call_primary_service(self, query: str) -> str:
        """Simular la llamada al servicio principal"""
        # Aquí se reemplaza por una llamada real al modelo
        return "Esta es la respuesta del servicio principal"

    def _call_fallback_service(self, query: str) -> str:
        """Simular llamada al servicio de degradación (más rápido pero de menor calidad)"""
        # Puede ser un modelo más pequeño, respuestas en caché o incluso plantillas predefinidas
        return "Lo sentimos, el servicio está temporalmente ocupado. Esta es una respuesta simplificada."

    def _call_static_fallback(self, query: str) -> str:
        """Respuesta de degradación estática (última línea de defensa)"""
        return (
            "Lo sentimos mucho, nuestro servicio está experimentando algunos problemas actualmente.\n"
            "Por favor, inténtelo de nuevo más tarde. Para problemas urgentes, contacte con support@runoob.com."
        )

    def process_request(self, query: str) -> FallbackResponse:
        """Procesar la solicitud, con lógica de degradación completa"""

        # 1. Comprobar si el cortacircuitos está abierto
        if self.circuit_open:
            if time.time() - self.circuit_open_time > self.circuit_timeout:
                # Tiempo agotado, probar estado semiabierto, permitir que pasen pocas solicitudes
                print("Cortacircuitos semiabierto, intentando recuperar...")
                self.circuit_open = False
            else:
                # Degradación directa
                print("Cortacircuitos abierto, degradación directa")
                return FallbackResponse(
                    content=self._call_fallback_service(query),
                    is_fallback=True,
                    fallback_reason="circuit_open"
                )

        # 2. Intentar con el servicio principal
        try:
            result = self._call_primary_service(query)
            # Éxito: restablecer el contador de errores
            self.error_count = 0
            return FallbackResponse(
                content=result,
                is_fallback=False
            )

        except Exception as e:
            print(f"Error en la llamada al servicio principal: {e}")
            self.error_count += 1
            self.last_error_time = time.time()

            # 3. Comprobar si es necesario activar el cortacircuitos
            if self.error_count >= self.error_threshold:
                print("Demasiados errores, abrir el cortacircuitos")
                self.circuit_open = True
                self.circuit_open_time = time.time()

            # 4. Intentar con el servicio de degradación
            try:
                print("Intentando llamar al servicio de degradación")
                result = self._call_fallback_service(query)
                return FallbackResponse(
                    content=result,
                    is_fallback=True,
                    fallback_reason="primary_failed"
                )
            except Exception as e2:
                print(f"El servicio de degradación también falló: {e2}")

                # 5. Respuesta estática final
                return FallbackResponse(
                    content=self._call_static_fallback(query),
                    is_fallback=True,
                    fallback_reason="all_failed"
                )


# Ejemplo de uso
def main():
    handler = FallbackHandler()

    print("Ejemplo de manejo de degradación")
    print("="*50)

    # Solicitud normal
    print("Solicitud normal:")
    resp = handler.process_request("Hola")
    print(f" Respuesta: {resp.content}")
    print(f" ¿Está degradada? {resp.is_fallback}")
    print()

    # Simular error (en proyectos reales, se lanzaría una excepción de verdad)
    # Aquí simplemente demostramos la lógica
    print("Resumen de la estrategia de degradación:")
    print(" 1. Priorizar el servicio principal")
    print(" 2. Si el servicio principal falla → usar modelo pequeño/caché")
    print(" 3. Fallos consecutivos → cortar el circuito, evitar avalanchas")
    print(" 4. Durante el corte del circuito → devolver rápidamente respuesta degradada")
    print(" 5. Última línea de defensa → respuesta estática")

Lanzamiento canario y reversión

No publiques la nueva versión toda de golpe; primero asígnale el 1% del tráfico, si no hay problemas, luego 5%, 10%, 100%.

Si hay problemas, debes poder hacer rollback rápidamente; no esperes a que los usuarios se quejen durante mucho tiempo antes de cambiar la configuración apresuradamente.
