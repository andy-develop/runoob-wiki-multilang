Introducción a TCP/IP

TCP/IP Tutorial


TCP/IP es el protocolo de comunicación de Internet.

El protocolo de comunicación TCP/IP es una descripción de las reglas que las computadoras deben cumplir; solo si cumplen estas reglas, las computadoras pueden comunicarse entre sí.

¡Comienza a aprender TCP/IP!

Protocolo TCP:https://www.runoob.com/np/tcp-protocol.html

Su navegador y servidor utilizan el protocolo TCP/IP.

El navegador y el servidor utilizan el protocolo TCP/IP para conectarse a Internet.

El navegador usa el protocolo TCP/IP para acceder al servidor, y el servidor usa el protocolo TCP/IP para enviar HTML al navegador.

Su correo electrónico utiliza el protocolo TCP/IP.

Su correo electrónico también se envía y recibe mediante el protocolo TCP/IP.

Las direcciones de Internet son protocolo TCP/IP.

Una dirección de Internet, como "42.120.45.233", es un protocolo TCP/IP.

    Interconexión de redes y el modelo OSI de siete capas:

    Capa física, capa de enlace de datos, capa de red, capa de transporte, capa de sesión, capa de presentación, capa de aplicación.

    ==========================================

    Capa física

    Función: define algunas características eléctricas, mecánicas, de proceso y especificaciones, como el concentrador (hub);

    PDU (Unidad de Datos de Protocolo): bit/bit

    Dispositivo: concentrador (HUB);

    Nota: no existe el concepto de direccionamiento;

    ==========================================

    Capa de enlace de datos

    Función: define cómo formatear los datos y admite la detección de errores;

    Protocolos típicos: Ethernet, Frame Relay (VPN de nivel antiguo)

    PDU: frame (trama); Dispositivo: conmutador Ethernet;

    Nota: el conmutador reenvía datos mediante direcciones MAC, control lógico de enlace;

    ===========================================

    Capa de red

    Función: define un direccionamiento lógico, selecciona la mejor ruta de transmisión y enruta paquetes de datos;

    Protocolos típicos: IP, IPX, ICMP, ARP (IP->MAC), IARP;

    PDU: packet/paquete de datos;

    Dispositivo: enrutador

    Nota: implementa el direccionamiento

    ============================================

    Capa de transporte:

    Función: proporciona transmisión confiable y de mejor esfuerzo;

    Protocolos típicos: TCP, UDP, SPX, port (65535 puertos), EIGRP, OSPF,

    PDU: fragment (segmento);

    Sin dispositivo típico;

    Nota: responsable de la transmisión de red y el establecimiento de sesiones;

    =============================================

    Capa de sesión:

    Función: controla las sesiones, establece, administra y termina las sesiones de aplicaciones;

    Protocolos típicos: NFS, SQL, ASP, PHP, JSP, RSVP (Protocolo de Reserva de Recursos), Windows,

    Nota: responsable del establecimiento de sesiones;

    ==============================================

    Capa de presentación:

    Función: formatear datos;

    Protocolos típicos: ASCII, JPEG, PNG, MP3, WAV, AVI,

    Nota: puede proporcionar servicios de cifrado;

    ===============================================

    Capa de aplicación:

    Función: controlar las aplicaciones;

    Protocolos típicos: telnet, ssh, http, ftp, smtp, rip, BGP, (continuará)

    Nota: proporciona servicios de red a las aplicaciones;

    ================================================

    P: ¿Cuándo hay PDU?

    R: Solo cuando necesitas comunicarte con otros.

    Primero hablemos de estos protocolos. Ya existían antes de que Internet se generalizara; con el tiempo, a medida que los datos se fueron enriqueciendo, los tipos de protocolos también se fueron acumulando.

    Para nosotros, el mundo de la red es colorido y variado; para Internet, no es más que datos.De acuerdo con las reglas correspondientesvan de un lado a otro. (Estas reglas son los protocolos). Es como cuando conduces al trabajo por la mañana y respetas las normas de tránsito; luego llegas sano y salvo a la empresa: eso equivale a completar un envío de información. ¡Basta de rodeos, vamos al tema!

    El modelo OSI mencionado anteriormente es una teoría casi perfecta; ten en cuenta que este modelo solo aparece en los libros de texto. Este modelo se propuso después de que el protocolo TCP/IP ya estaba maduro, y puede entenderse como una versión mejorada. Pero no llegó a popularizarse, principalmente por las siguientes razones:

    1. Apareció demasiado tarde.

    2. Incluyó demasiadas consideraciones políticas y no se abordó únicamente desde el punto de vista técnico.

    3. ………… También olvidé algunos puntos; en fin, no se popularizó.

    Por lo tanto, la transmisión de datos en red está dominada por TCP/IP.

    El protocolo TCP/IP es un conjunto de muchos protocolos. El protocolo TCP/IP se divide en cuatro capas (es decir, una transmisión de datos pasa principalmente por los siguientes 4 pasos), de arriba a abajo: capa de aplicación, capa de transporte, Internet (capa de red), capa física.

    Supongamos que envías un mensaje a tu amigo; los datos comienzan a transmitirse. En ese momento, los datos deben seguir el protocolo TCP/IP. Tu computadora realizará las siguientes acciones, que no puedes ver.

    1. La capa de aplicación primero convierte el formato de tu mensaje; ya sea texto, imagen o video para adultos, y lo cifra, entre otras operaciones, luego lo entrega a la capa de transporte. (En este momento, la unidad de datos (unidad) es información).

    2. La capa de transporte divide los datos en segmentos, para facilitar la transmisión, y les añade algunas marcas, como el número de puerto de la aplicación actual, y se los entrega a Internet (capa de red). (En este momento, la unidad de datos (unidad) es el flujo de datos).

    3. La capa de Internet comienza a agrupar los datos; la cabecera del grupo contiene la IP de la dirección de destino y cierta información relacionada, y se entrega a la capa física. (En este momento, la unidad de datos (unidad) es el paquete).

    4. La capa física convierte los datos en un flujo de bits, comienza a buscar la dirección física real del host para realizar operaciones de verificación; si la verificación pasa, comienza a correr hacia el destino con "¡Ziu, ziu, ziu!". (En este momento, la unidad de datos (unidad) es el bit).

    Una vez que llega al destino, el dispositivo receptor realiza las operaciones anteriores en orden inverso y finalmente lo presenta.

    Personalmente creo que ya es bastante fácil de entender.Todas estas cosas son conocimientos teóricos, pertenecen a la infraestructura; los predecesores ya nos han allanado el camino.
