Conceptos principales de Codex
Extensión de Codex para IDE

Aplicación de escritorio Codex

Actualmente, Codex tiene tres formas principales de uso:

Forma Público adecuado Nivel de recomendación
Versión web Experiencia ligera ⭐⭐
Versión CLI (línea de comandos) Desarrolladores avanzados ⭐⭐⭐⭐
Aplicación de escritorio La mayoría de las personas ⭐⭐⭐⭐⭐

La App de Codex es el cliente de escritorio recomendado oficialmente, que ofrece funciones completas y una experiencia fluida de proyectos múltiples en paralelo.

Descarga e instalación

La App de Codex es compatible con macOS (Apple Silicon) y Windows.

Dirección de descarga:https://chatgpt.com/codex

PlataformaMétodo de descarga
macOSDescarga desde el sitio oficial o Homebrew
WindowsDescargar el instalador desde el sitio oficial

Primer uso

Una vez completada la instalación, sigue estos pasos:

1. Abre la App de Codex

2. Inicia sesión con una cuenta de ChatGPT o una API Key de OpenAI

Si inicias sesión con una API Key, algunas funciones en la nube pueden no estar disponibles.

3. Después de iniciar sesión correctamente, la interfaz es la siguiente:

Cuando empezamos a usarlo, podemos centrarnos en los chats y proyectos. El chat funciona igual que la versión web de ChatGPT: solo hay que conversar.

Podemos entender un proyecto (Project) como una combinación de: el chat de ChatGPT + el directorio del proyecto en el IDE + la memoria a largo plazo del agente de IA.

Un proyecto (Project) se vincula a una carpeta de tu ordenador. Codex solo trabajará dentro de este directorio.

Aquí elijo "Agregar nuevo proyecto" y añado codex-runoob-test:

Una vez dentro, el nombre del proyecto se puede ver tanto a la izquierda como a la derecha. Se pueden seleccionar varios proyectos en la lista:

4. Envía el primer Prompt para empezar a usarlo

Tres modos de ejecución

Cada proyecto puede elegir entre tres modos de ejecución:

ModoDescripciónEscenario aplicable
LocalTrabajar en el directorio del proyecto localDesarrollo diario, ver resultados directamente
WorktreeTrabajar en un worktree de Git independienteAislamiento de cambios, desarrollo en paralelo
CloudEjecutar en un entorno aislado en la nubeDelegación remota, procesamiento en paralelo

Selección de modo

Al crear un nuevo proyecto, elige el modo debajo del campo de entrada:

  • Local: trabajar directamente en el directorio actual, los cambios son visibles de inmediato
  • Worktree: crear una rama independiente, después de completarlo se puede fusionar en Local
  • Cloud: la tarea se ejecuta en la nube, los resultados se presentan mediante PR o informes

El modo Worktree usa la tecnología Git worktree, que permite trabajar en diferentes ramas al mismo tiempo.

Modo Review

El modo Review te permite ver y aprobar los cambios realizados por Codex.

Funciones del panel de revisión

FunciónDescripción
Vista de diffMuestra la comparación detallada de todos los cambios de archivos
Comentarios en líneaAñade comentarios en líneas de código específicas
Operaciones de chunk (bloque)Acepta o rechaza por bloque de código
Confirmación completa (commit)Crea un commit de Git o envía los cambios (push)

Cambiar la vista de revisión

El panel de revisión admite dos vistas:

  • Todos los cambios: Muestra el estado de Git del proyecto, incluidos los cambios que no son de Codex.
  • Cambios de Last turn: Solo muestra los cambios de la ronda más reciente de Codex.

Operaciones de revisión

# Operaciones con atajos de teclado
Cmd + Option + B    # Alternar panel de revisión
Cmd + Shift + P     # Abrir menú de comandos

# Flujo de revisión
1. Ver los cambios de archivos
2. Haz clic en el bloque de código para aceptar/Rechazar
3. Añade comentarios o explicaciones
4. Confirmar o enviar (push)

Automations (Automatizaciones)

Automations te permite programar tareas para que Codex las ejecute periódicamente en segundo plano.

Requisitos previos

  • La aplicación Codex está en ejecución
  • El proyecto seleccionado está disponible en el disco

Crear automatizaciones

  1. Abre el panel Automations en la barra lateral
  2. Haz clic en "New Automation"
  3. Configura la frecuencia de activación y la descripción de la tarea
  4. Establece el modo sandbox

Ejemplos de automatización

TareaDescripción
Creación automática de habilidadesEscanea archivos de sesión y actualiza las habilidades para hacerlas más efectivas
Resumen diarioAnaliza los commits recientes y genera un resumen de cambios
Monitoreo de errores (bugs)Revisa errores de telemetría e intenta corregirlos automáticamente

Los resultados de las tareas de automatización se añaden a la bandeja de entrada de Triage y se archivan automáticamente cuando no hay resultados.

Gestión de Worktrees

La aplicación Codex incluye soporte integrado para Git worktree.

Ventajas de Worktree

  • Procesa varias tareas en paralelo sin interferencias
  • Mantiene la rama principal limpia
  • Concéntrate en el trabajo en primer plano mientras las tareas se ejecutan en segundo plano

Proceso de Handoff

Handoff permite cambiar entre Local y Worktree:

  1. Completa la tarea en Worktree
  2. Crea un commit y un PR (pull request)
  3. Selecciona Handoff a Local para continuar probando

Worktree solo hereda los archivos del repositorio Git; los archivos en .gitignore no se mueven con el proyecto.

Preguntas frecuentes

Q: ¿Cómo se sincronizan la App con CLI/IDE?

Cuando usas la App y la extensión del IDE en el mismo proyecto, sincronizan automáticamente Auto Context y el proyecto activo.

Q: ¿Cómo encontrar proyectos archivados?

En Settings, revisa Archived Threads y selecciona Unarchive para restaurarlos.

Q: ¿El código de Worktree es diferente del local?

Worktree solo hereda los archivos del repositorio Git. Se necesitan scripts de configuración para instalar dependencias y compilar.

Q: ¿Las diferencias de versión entre App y CLI causan diferencias de funcionalidad?

Verifica la versión: para CLI usa `codex --version`, para la App usa el menú About.
