How AI works

AI Tools Panorama

Since 2023, the number of AI tools has grown exponentially.

There are AI writing assistants for writing articles, AI painting tools for drawing, AI programming assistants for coding, and even dedicated AI tools for making PPTs and editing videos.

Faced with hundreds of AI tools, many people's first reaction is: Where do I start? Which one suits me?

This chapter will establish a cognitive framework for AI tools—understanding what categories exist, what representative tools are in each category, what their pros and cons are, and what scenarios each should be used in.

You don’t need to try every new tool that comes out. Just find 3–5 that work for you and use them well—that’s enough.

Tools serve people. Don’t use tools for the sake of using tools. Be clear about what problem you want to solve, then find a tool that can solve that problem.

Text generation tools

The most mature and widely applied category of AI tools. Writing emails, writing reports, writing code, translating, summarizing, brainstorming—all of these can be done with text generation tools.

Recommendations for choosing a text generation tool.

If you are using AI for the first time, we recommend starting withChatGPT 或 Claudestart—they represent the highest level of current text generation.

If you mainly handle Chinese content, domestic tools may be more convenient—they usually have better understanding and generation of Chinese.

If you need to process ultra-long documents (e.g., reading a book, a several-hundred-page report), Claude or Kimi are good choices.

Suggestion: first choose 1-2 mainstream tools, become proficient, then consider trying others. Depth of usage is more important than breadth.

Usage example of the code assistant.

Take Cursor as an example, it is a code editor specifically designed for AI.

In Cursor, you can collaborate with AI like this:

Scenario 1:Ask AI to generate a runoob tutorial page.

You just need to input:

创建一个简单的 Python 入门教程网页，包含标题、代码示例、说明

AI will directly generate a complete HTML file for you.

Scenario 2:Ask AI to explain code.

Select a piece of code you don't understand, press Cmd+K (Mac) or Ctrl+K (Windows).

Then input:

解释这段代码在做什么

AI will analyze the code logic line by line and explain each step of the execution process.

Scenario 3:Ask AI to fix bugs.

Select the code that reports errors.

Then input:

这段代码报错了，帮我看看问题在哪，修复它

AI will locate the cause of the error and provide a runnable fix.

Scenario 4:Refactor code.

Select the code that needs optimization.

Then input:

这段代码太乱了，帮我重构得更清晰，加上注释

AI will optimize the code structure, split responsibilities, and automatically add necessary comments to improve readability and maintainability.

GitHub Copilot is more like a super autocomplete — you write a comment, it writes code for you; you write halfway, it completes it for you.

Example

# Assuming you have Copilot installed in VS Code
# You write a comment like this:

def calculate_runoob_score(student_data):
    """Calculate the student's runoob comprehensive score
Input is a dictionary containing homework, exams, and attendance.
Output is the total score from 0-100.
    """
    # At this point, Copilot might auto-complete the entire function:

    # Copilot auto-completed content (example):
    homework_weight = 0.3
    exam_weight = 0.5
    attendance_weight = 0.2

    homework_score = student_data.get("homework", 0)
    exam_score = student_data.get("exam", 0)
    attendance_score = student_data.get("attendance", 0)

    total = (homework_score * homework_weight +
             exam_score * exam_weight +
             attendance_score * attendance_weight)

    return min(max(total, 0), 100)

# You just need to check whether it's correct, rather than writing from scratch.

Suggestions for Choosing a Code Assistant

If you are a student or just entering the field,GitHub Copilot（https://github.com/copilot）It is a must-install — it can help you quickly get past the threshold of not knowing how to write.

If you want to experience smarter AI programming, tryCursor/Qoder/Trae— Use it to write a project once, and you'll know what programming in the AI era feels like.

Note: AI-written code may have bugs and may be insecure. You are the programmer; you are responsible for the code. Treat AI as an assistant, not an authority.

Use cases for search-enhanced AI

When should you use search-enhanced AI instead of a traditional search engine?

When you need to synthesize information: For example, "What are the important advances in AI in 2024?" — AI will synthesize information from various sources into a summary for you, rather than throwing dozens of articles at you.

When you need answers rather than links: For example, "How to send an email with Python" — AI will directly give you complete code examples and steps, instead of making you dig through a dozen blog posts.

When you need fact-checking: For example, "What are a certain company's financial report figures?" — AI will look up the latest official data, rather than giving you outdated information.

Tip: Even search-enhanced AI can make mistakes. Please cross-verify important information and don't rely on just one source.

Whisper usage example

Whisper is OpenAI's open-source speech recognition model, excellent for converting speech to text.

Example

# Install Whisper (Python and ffmpeg need to be installed first)
pip install openai-whisper

# Simplest usage: transcribe an audio file to text
whisper runoob_podcast.mp3 --model base

# Specify Chinese model
whisper runoob_interview.wav --model small --language Chinese

# Output as subtitle file formats (SRT, VTT)
whisper runoob_lecture.m4a --model medium --language Chinese --output_format srt

# Whisper will output:
# [00:00:00.000 --> 00:00:05.000] Welcome to the runoob tutorial
# [00:00:05.000 --> 00:00:10.000] Today we'll learn about using AI tools

Note: AI audio tools may be misused. Please comply with laws and regulations. Do not clone others' voices without permission, and do not use AI-generated content for fraud.

Basic principles for selecting tools

面对这么多工具，怎么选？这里有几个原则可以帮你做决策。

Principle 1: Clarify the problem first, then find the tools.

不要看到别人说某款工具好就去试。先想清楚：你要解决什么问题？

是想写代码更快？那选代码助手。是想做设计图？那选图像生成工具。是想提高写作效率？那选文本生成工具。

工具是手段，不是目的。

Principle Two: Master one first, then expand.

很多人犯的错是：每款工具都试一下，每款都用不深。

更好的做法是：选一款主流工具，花一两周时间把它用熟，搞清楚它的边界——什么场景它能搞定，什么场景它搞不定。

等你把一款用精通了，再试其他的，你会发现很多设计思路是相通的。

Principle 3: Look at "frequency of use," not "degree of novelty."

一款每天都能用的工具，比一款一年用一次但很酷炫的工具有价值得多。

比如：代码助手你每天写代码都能用，它的价值就很高；视频生成工具你可能半年才用一次，那就不用急着买最贵的套餐。

Principle 4: Consider costs, not just money.

工具的成本不只是订阅费，还有学习成本、迁移成本、数据安全成本。

有些免费工具需要你花很多时间折腾，那你的时间也是成本。有些工具把你的数据存在云端，那数据安全也是成本。

成本类型说明怎么权衡
金钱成本订阅费、按次付费等看它帮你省的时间值不值这个钱
Learning costTime needed to learn to use itPrioritize simplicity and ease of use, unless it brings huge benefits
Migration costData and habit migration when switching toolsPrioritize tools with export features and open ecosystems
Data securityWhere data is stored and who can see itPrioritize local deployment or privacy-friendly tools for sensitive data

A simple criterion: If a tool saves you 2 hours a week, then paying $20 a month for it is usually worth it—your time is more valuable than that.
