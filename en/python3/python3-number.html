Python3 Numbers (Number)

The Python numeric data type is used to store numeric values.

Data types are not allowed to be changed, which means that if you change the value of a numeric data type, memory space will be reallocated.

In the following example, a Number object is created when a variable is assigned:

var1 = 1
var2 = 10

You can also use the del statement to delete references to some number objects.

The syntax of the del statement is:

del var1[,var2[,var3[....,varN]]]

You can delete references to a single or multiple objects using the del statement, for example:

del var
del var_a, var_b

Python supports three different numeric types:

  • Integer (int)- Usually called an integer or whole number, it is a positive or negative integer without a decimal point. Python3 integers have no size limit and can be used as a Long type, so Python3 does not have the Long type of Python2. Boolean (bool) is a subtype of integer.

  • Float (float)- Float consists of an integer part and a fractional part. Float can also be expressed in scientific notation (2.5e2 = 2.5 x 102 = 250）

  • Complex (complex)- A complex number consists of a real part and an imaginary part. It can be expressed as a + bj, or complex(a,b). The real part a and imaginary part b of a complex number are both floating-point types.

We can use hexadecimal and octal to represent integers:

Python Number Type Conversion

Sometimes, we need to convert the built-in types of data. For data type conversion, you only need to use the data type as the function name.

  • int(x)Convert x to an integer.

  • float(x)Convert x to a float.

  • complex(x)Convert x to a complex number, with the real part x and the imaginary part 0.

  • complex(x, y)Convert x and y to a complex number, with the real part x and the imaginary part y. x and y are numeric expressions.

The following example converts float variable a to an integer:

>>> a = 1.0
>>> int(a)
1

Python Number Operations

The Python interpreter can act as a simple calculator. You can enter an expression in the interpreter, and it will output the value of the expression.

The syntax of expressions is straightforward:+, -, * 和 /, just like in other languages (such as Pascal or C). For example:

>>> 2 + 2
4
>>> 50 - 5*6
20
>>> (50 - 5*6) / 4
5.0
>>> 8 / 5  # 总是返回一个浮点数
1.6

Note:The results of floating-point operations may be different on different machines.

In integer division, division/always returns a float. If you only want an integer result, discarding the possible fractional part, you can use the operator// ：

>>> 17 / 3  # 整数除法返回浮点型
5.666666666666667
>>>
>>> 17 // 3  # 整数除法返回向下取整后的结果
5
>>> 17 % 3  # ％操作符返回除法的余数
2
>>> 5 * 3 + 2 
17

Note://The result is not necessarily an integer type; it depends on the data types of the denominator and numerator.

>>> 7//2
3
>>> 7.0//2
3.0
>>> 7//2.0
3.0
>>>

The equal sign=is used to assign values to variables. After assignment, except for the next prompt, the interpreter will not display any result.

>>> width = 20
>>> height = 5*9
>>> width * height
900

Python can use**operator for exponentiation:

>>> 5 ** 2  # 5 的平方
25
>>> 2 ** 7  # 2的7次方
128

Variables must be "defined" (i.e., assigned a value) before use, otherwise an error will occur:

>>> n   # 尝试访问一个未定义的变量
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
NameError: name 'n' is not defined

When different types of numbers are mixed in operations, integers will be converted to floats:

>>> 3 * 3.75 / 1.5
7.5
>>> 7.0 / 2
3.5

In interactive mode, the result of the last printed expression is assigned to the variable_ . For example:

>>> tax = 12.5 / 100
>>> price = 100.50
>>> price * tax
12.5625
>>> price + _
113.0625
>>> round(_, 2)
113.06

Here,_ the variable should be treated as a read-only variable by the user.

    “4 round down, 6 round up, 5 rounds to even; odd advances, even does not” — I think this is not because of the representation of floating-point numbers in computers. The representation of computer floating-point numbers is a standard rule defined by IEEE. If it exists in Python, there is no reason it shouldn't exist in other languages. In fact, this rounding method is more accurate in scientific computing than the previous “round half up” method. National standards have also stipulated using “round half to even” to replace “round half up”.

    From a statistical point of view, if a large amount of data blindly uses round-half-up, the statistical results will be biased larger. Round-half-to-even can minimize rounding errors.

    Round-half-to-even is a relatively precise and scientific method of retaining digits, and is a numerical rounding rule.

    Its specific requirements are as follows (taking retaining two decimal places as an example):

    • (1) If the digit after the digit to be retained is 4 or less, discard it. For example, 5.214 rounded to two decimal places is 5.21.
    • (2) If the digit after the digit to be retained is 6 or greater, round it up. For example, 5.216 rounded to two decimal places is 5.22.
    • (3) If rounding to the integer part or to one decimal place, the decision of odd-advance-even-round-down is made according to the retained digit:
      >>> round(5.215,2)#实际并没有进位
5.21
>>> round(5.225,2)
5.22
>>>
>>> round(1.5)#此处进位
2
>>> round(1.5)==round(2.5)#偶数舍去
True
>>> round(1.15,1)
1.1
>>> round(1.25,1)
1.2
>>> round(1.151,1)
1.2
>>> round(1.251,1)
1.3
    • (4) If the digit after the retained digit is 5, and there are digits following that digit, round up. For example, 5.2152 rounded to two decimal places is 5.22, 5.2252 rounded to two decimal places is 5.23, and 5.22500001 rounded to two decimal places is 5.23.
    From a statistical point of view, round-half-to-even is more scientific than round-half-up. In a large number of operations, it makes the mean of errors after rounding tend to zero, rather than rounding up on every 5 as round-half-up does, which biases results toward larger numbers, causing errors to accumulate and thus produce systematic error. Round-half-to-even minimizes the impact of rounding error on measurement results.

    Some pitfalls about Python integer comparison:

    or==compares whether the contents of two objects are equal; by default it calls the object'sis。

    ==method.__eq__()This compares whether the ids of two objects are equal, that is, whether they are the same object and whether they point to the same memory address.

    isWe can understand the results shown for the first few comparisons, but in the last one, when a/b both refer to the integer object 257, the result of using `is` for comparison is False.

    >>> a = 4
>>> b = 4
>>> a == b
True
>>> a is b
True
>>> a = 256
>>> b = 256
>>> a == b
True
>>> a is b
True
>>> a = 257
>>> b = 257
>>> a == b
True
>>> a is b
False

    This is because Python, for performance considerations, has made internal optimizations. For integer objects, it caches some frequently used integer objects and stores them in a

    linked list.small_intsDuring the entire lifetime of Python, wherever these integer objects need to be referenced, no new integer object is created again. The range is

    Now look at the following example:[-5,256]。

    This is because Python programs are composed of code blocks, and a code block is executed as the smallest basic unit of a program. A module file, a function body, a class, or a single line of code in an interactive command is called a code block.

    >>> a = 259
>>> def foo () :
...     b = 259
...     c = 259
...     print(a is b)
...     print(b is c)
...
>>> foo()
False
True

    The above program has two parts of code blocks: one is the code block where the name a resides, and the other is the code block where the names b/c reside. Another optimization in Python is that if two integer objects created in the same code block have equal values, then the two objects reference the same integer object. Therefore, for performance reasons, for any immutable object, as long as objects with equal values are in the same code block, they will not be created repeatedly; instead, they directly reference the existing object. Not only integer objects, but string objects also follow the same principle.

    Actually, the precise rounding rule is for binary floating-point numbers:

    >>> round(1.5,0) # 1.5d -> 0x3FF8000000000000 -> 1.5, 按照5后为0处理，奇进偶不进
2.0
>>> round(2.5,0) # 2.5 -> 0x4004000000000000 -> 2.5,  按照5后为0处理，奇进偶不进
2.0
>>> round(1.15,1) #1.15 ->0x3FF2666666666666 -> 1.14999999999999991118215802999 按照4处理，退位
1.1
>>> round(1.25,1) # 1.25 ->0x3FF4000000000000 ->1.25 同2.5退位
1.2
>>>

    It can be considered that rounding first calculates the difference from the integer; if the differences are equal, then "round half to even" occurs. Note that 1.15, due to the base issue, has different distances to 1.1 and 1.2, so it is not the decimal round result.

    >>> abs(1.25-1.2)==abs(1.25-1.2)
True
>>> abs(1.15-1.2)==abs(1.15-1.1)
False

    Regarding the discussion of the _ variable in the article and the notes section, I did some personal testing and made a brief summary:

    The system automatically assigns the result of the previous expression to the variable _, which is, for the user, a''read-only variable''. Users can manually create a new _ variable. Once a new _ variable appears, the system will preferentially reference this new variable. The value of the new variable will not update automatically, while the read-only variable _ will keep updating, but it will not be referenced unless the user deletes the self-created _ variable.

    >>> t=1
>>> p=2
>>> t+p
3
>>> _+1  # 系统将上一表达式结果 3 赋值给变量 _ ，3+1=4
4
>>> _+1  # 系统将上一表达式结果 4 赋值给变量 _ ，4+1=5
5
>>> _=10  # 系统将上一表达式结果 5 赋值给变量 _ ，同时用户手动创建变量 _=10
>>> _+1   # 优先引用用户变量（10），10+1=11,同时系统将11这个值赋给只读变量 _
11
>>> _+1   # 优先引用用户变量（10），10+1=11,同时系统将11这个值赋给只读变量 _
11
>>> del _ # 删除用户变量（10）
>>> _+1  # 此时只有只读变量 _ ，值为11，11+1=12
12

    Regarding the two variables mentioned above having the same name, I haven't looked at the source code, so I can only guess: the two variables are different at the underlying level, but the identifier is not transparent to the user, so only _ is visible for both.

    randrange() 和 uniform()are functions in Python used to generate random numbers; they both belong to therandommodule, but they differ in the type and range of the random numbers generated.

    Choose the appropriate function according to your needs:

    • When generating random integers, userandrange()。

    • When generating random floating-point numbers, useuniform()。

    The following are their differences and connections:

    Difference

    1. The module they belong to

    • Both belong to therandommodule; before use, you need to import the module:import random

    2. Type of random numbers generated

    • randrange()generatesrandom integers。

    • uniform()generatesrandom floating-point numbers。

    3. Range of random numbers generated

    • randrange()The range is[start, stop), that is, includesstartbut does not includestop. You can use thestepparameter to specify the step, controlling the interval between random numbers.

    • uniform()The range is[a, b], that is, includesa 和 b. The generated random floating-point numbers area 和 buniformly distributed between.

    Similarities

    1. Both belong to therandommodule

    • Both are used to generate random numbers, and both depend on therandommodule.

    2. Range control

    • Both allow specifying the range of random numbers to be generated.

    3. Randomness

    • The generated random numbers are all pseudo-random numbers; when based on the same random seed (seed), the results are reproducible.

    Example Comparison

    Generate a random number between 1 and 10

    Generate a random number between 1 and 10 using randrange():

    import random
num = random.randrange(1, 11)  # 生成 1 到 10 之间的随机整数
print(num)

    Generate a random number between 1 and 10 using uniform():

    import random
num = random.uniform(1.0, 10.0)  # 生成 1.0 到 10.0 之间的随机浮点数
print(num)

    Range[start, stop)(left-closed, right-open)[a, b](closed interval)
