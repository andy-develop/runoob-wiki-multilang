Claude Code Slash / Commands

Slash/Commands are Claude Code interactive session'sshortcut control entry, by entering/instructions starting with /, you can quickly call functions, manage sessions, and customize workflows.

View all available commands:

/help

/helpIt will list all built-in commands, custom commands of the current project (Skills / Commands), and commands exposed by connected MCP servers.

Command types:

Type Trigger Method Source Storage Location Applicable Scenarios
Built-in Commands /command Installed with Claude Code Internal implementation System operations such as session management, configuration, integration
Built-in Skills /skill-name Bundled with Claude Code Internal implementation Pre-built AI workflows such as code review, debugging, batch processing
Project Custom Skills Recommended /skill-name User creates directory + SKILL.md .claude/skills/<名称>/SKILL.md Team-shared reusable workflows, included in git; supports automatic triggering by Claude
Project Custom Commands Legacy format /command User-created.mdFile .claude/commands/ Team-shared repetitive workflows, included in git
Personal Custom Skills /skill-name User creates directory + SKILL.md ~/.claude/skills/<名称>/SKILL.md Personal workflows common across projects
Personal Custom Commands /command User-created.mdFile ~/.claude/commands/ Personal workflows common across projects (legacy format)
MCP Commands /mcp__服务器__命令 Automatically exposed by MCP server Provided by MCP server Call external tools such as GitHub, Slack, databases
!Shell Commands !bash命令 Direct execution — Bypass AI processing and directly run terminal commands

Command priority (when names are the same): Enterprise-level > Personal-level > Project-level > Built-in

Skills vs Commands: Both use/trigger, but Skills (.claude/skills/) is a new-generation format, supporting multi-file organization, automatic Claude triggering, and richer frontmatter control; Commands (.claude/commands/) is the legacy format, still fully compatible; for new projects, it is recommended to use Skills directly.

II. Built-in SkillsNEW

Built-in Skills are preset AI workflows bundled with Claude Code. Unlike built-in commands, they load detailed prompts and are then executed by Claude through reasoning, producing richer analysis and operation results. They are also triggered with/trigger.

Difference: Built-in commands vs Built-in Skills
Built-in commands (e.g.,/clear、/compact) execute fixed logic without AI reasoning and are extremely fast.
Built-in Skills (e.g.,/debug、/simplify) load prompts and are executed by Claude through reasoning, producing richer results; they are suitable for complex analysis tasks.
Command Description Use case
/simplify Simplify specified code or text to improve readability and eliminate unnecessary complexity. Refactor lengthy functions, simplify over-engineered code.
/debug Perform systematic root-cause analysis on error messages or abnormal behavior, and provide fix ideas. Locate hard-to-reproduce bugs.
/batch Execute the same task on multiple files or targets in parallel (e.g., batch rename, batch add type annotations). Large-scale repetitive code changes.
/loop Repeatedly execute an operation in a loop until an exit condition is met (e.g., keep retrying tests until they pass). Automated CI fix loop.
/claude-api Quickly generate example code for calling the Anthropic API, with support for specifying model and task type. Build Claude API integration prototypes.

IV. Custom Skills (New Recommended Format)

Skills are the next-generation format for custom commands, replacing the old version.claude/commands/. Both formats work normally, but it is recommended to use Skills directly for new projects.

Skills vs Commands Comparison

Feature Skills (recommended) Commands (old format)
Storage path .claude/skills/<名称>/SKILL.md .claude/commands/<名称>.md
Trigger method /名称Manually triggered, or automatically triggered by Claude based on description. /名称(manually triggered only)
Multi-file support Supports attached templates, examples, and helper scripts. Single file
Claude auto-trigger Claude intelligently decides whether to invoke based on the description.
Agent Skills standard Complies with open standards and can be shared across tools.

Steps to Create a Skill

Step 1: Create the directory structure

Custom Skills come in two types, with different storage locations:

  • Project Skill: Effective only in the current project, shared by the team → directory:.claude/skills/<名称>/
  • Personal Skill: Common to all projects, for personal use → directory:~/.claude/skills/<名称>/
# 创建项目级 Skill（团队共享，纳入 git）
mkdir -p .claude/skills/optimize

# 创建个人级 Skill（跨项目通用，本地私有）
mkdir -p ~/.claude/skills/fix-bug

Step 2: Write SKILL.md

Create a newSKILL.mdfile, write configuration in YAML frontmatter, and write the prompt in the Markdown body below.nameThe field defines the trigger command name.

Example: Create a code performance optimization Skill

---
name: optimize
description: 分析代码性能瓶颈，给出优化建议。当用户提到性能问题时自动触发。
allowed-tools: Read, Grep, Glob
argument-hint: [目标文件或目录]
model: claude-sonnet-4-6
---

分析以下代码的性能瓶颈，给出具体的优化建议，优先考虑时间复杂度和内存占用：
$ARGUMENTS

When using, enter:

/optimize src/utils/data-processor.ts

Subdirectory Namespace Organization

You can.claude/skills/under it, use subdirectories to manage by function. The directory name is the command name:

.claude/skills/
├── optimize/            → /optimize
│   ├── SKILL.md
│   └── examples/        # 可选：示例文件辅助 Claude 理解
├── debug/               → /debug
│   ├── SKILL.md
│   └── scripts/         # 可选：辅助脚本
└── commit/              → /commit
    └── SKILL.md

V. Custom Slash Commands (Legacy Format, Compatible)

If you havereusable prompts(e.g., fixed code review requirements, repeated instruction templates), you can turn them into custom commands and invoke with one click.

Command file storage location:

Scope Storage path Sharing method Use case
Project-level .claude/commands/<命令名>.md Include in git, shared by team Project-specific workflows (e.g., code generation for specific frameworks)
Personal level ~/.claude/commands/<命令名>.md Local private General development habits (e.g., personal code style checking)

Parameter syntax:

Syntax Description Command file example Call example
$ARGUMENTS Capture everything after the command name 分析并修复：$ARGUMENTS /fix 登录接口返回 500，见 logs/error.log
$1 $2 Positional parameters split by spaces 修复 Issue #$1，优先级 $2 /fix-issue 42 high
!`cmd` Execute shell command and embed output into Prompt !`git diff HEAD` Automatically expand to command execution result
@文件路径 Inject file content into Prompt 审查 @src/utils/helpers.ts Automatically read file content

Core Principles

Custom commands are essentiallyMarkdown text filesThe filename is the command name, the file content is the prompt to execute, supports passing parameters and calling Bash commands.

Steps to Create Custom Commands

Step 1: Create a command storage directory

Custom commands come in two types, stored in different locations:

  • Project commands: Only effective in the current project, shared by the team → Directory:.claude/commands/
  • Personal commands: Common to all projects, for personal use → Directory:~/.claude/commands/

Take creating a project command as an example, first create the directory:

# 在项目根目录执行
mkdir -p .claude/commands

Step 2: Write the Markdown command file

Create a new.mdfile, the filename is the command name (e.g.,optimize.md→ command/optimize), and write the prompt in the file content.

Example: Create a code performance optimization command

# 写入提示词到文件
echo "分析这段代码的性能瓶颈，给出具体的优化建议，优先考虑时间复杂度和内存占用：" > .claude/commands/optimize.md

Now, enter in the session/optimize, then paste the code, and Claude will perform performance analysis as you requested!

Advanced Tips: Adding Parameters to Commands

Commands can have parameters, using$ARGUMENTS(capture all parameters) or$1 $2(retrieve parameters by position).

Example: Bug fix command with parameters

Create command file.claude/commands/fix-issue.md：

修复 Issue #$ARGUMENTS，要求：
1. 符合项目编码规范
2. 附上测试用例
3. 说明修复思路

Use the command:

/fix-issue 123  # $ARGUMENTS 会被替换成 "123"

VI. Frontmatter Field Reference

Custom command files (commands/*.md) and Skills (skills/*/SKILL.md) can have YAML Frontmatter added at the top for fine-grained configuration:

---
name: commit                          # Skills 中必填；命令文件中可选（默认取文件名）
allowed-tools: Bash(git add:*), Bash(git commit:*), Read, Edit
argument-hint: [commit-message]
description: 检查代码质量后提交
model: claude-haiku-4-5-20251001
context: fork
agent: general-purpose
disable-model-invocation: false
user-invocable: true
hooks:
  PreToolUse:
    - matcher: "Bash"
      hooks:
        - type: command
          command: "./scripts/validate.sh"
          once: true
---

Field Descriptions

Field Type Required Description
name string Required for Skills Define triggering command name (/name); for command files, the filename is used by default
allowed-tools string 否 Tools that the command can use; matched tools do not require manual confirmation each time
argument-hint string 否 在 /helpParameter format hint displayed in the list, e.g.,[message]
description string 否 Command function description, displayed in the/help 和 /skillslist; for Skills, also used to let Claude determine whether to auto-trigger
model string 否 Force a specific model; for simple tasks using Haiku can reduce cost
context enum 否 fork: Run as an independent subagent;inline: Run within the current session
agent string 否 context: forkWhen specifying the agent type
disable-model-invocation bool 否 为 trueWhen ..., programmatic invocation of this command via the Skill tool is prohibited
user-invocable NEW bool 否 为 falseWhen ..., only allow Claude to auto-trigger; users cannot trigger manually/调用
hooks object 否 Lifecycle hooks during command execution

allowed-toolsWriting Examples

Syntax Meaning
Read Allow reading any file
Read(src/*) Only allow readingsrc/directory
Bash(git *:*) Allow all git subcommands
Bash(npm test:*) Only allow runningnpm test
Read, Grep, Glob Combine multiple tools

Hook Trigger Timing

Timing Description Typical use cases
PreToolUse Before tool calls Run lint before commit, backup before writing files
PostToolUse After tool calls Auto-format after modifications, generate changelog

1. Plugin Commands

After installing a Claude Code plugin, plugin-specific commands are automatically added, usually in the format:

/plugin-name:command-name  # 避免命令名冲突

For example, after installing the Git plugin, there may be a/git:commitcommand that generates standardized commit messages with one click.

2. MCP Commands

MCP (Model Context Protocol) servers can turn the capabilities of external tools (such as GitHub, Jira) into slash commands, in the format:

/mcp__<服务器名>__<功能名> [参数]

Example:

/mcp__github__list_prs  # 列出 GitHub 仓库的 PR
/mcp__jira__create_issue "登录按钮失效" high  # 在 Jira 创建高优先级问题

- 重定向链接（3xx）及目标地址
- 失效链接（4xx/5xx）及建议替代链接

最后输出汇总：共 N 个链接，M 个失效。
