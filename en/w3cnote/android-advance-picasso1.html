Getting Started with Picasso

Adding to Dependencies

First, you need to add the dependency. Currently we will use the latest version.2.5.2There are two well-known ways to add the dependency.

Gradle

compile 'com.squareup.picasso:picasso:2.5.2'

Maven

<dependency>  
    <groupId>com.squareup.picasso</groupId>
    <artifactId>picasso</artifactId>
    <version>2.5.2</version>
</dependency>

Basic Image Loading

Picasso uses chain-style programming. It requires at least three parameters to complete a basic image request.

  • with(Context context)- ManyAndrod APIwill call it; no difference here.
  • load(String imageUrl)- This refers to which image should be loaded. In most cases, we use a String representing a URL image.
  • into(ImageView targetImageView)- The target ImageView to display.

Let's take a simple example.

ImageView targetImageView = (ImageView) findViewById(R.id.imageView);  
String internetUrl = "http://i.imgur.com/DvpvklR.png";

Picasso  
    .with(context)
    .load(internetUrl)
    .into(targetImageView);

At this point, as long as the image at the URL is fine, you will see the image you want in a moment. If the image does not exist, Picasso will return to the error callback. I'll explain how to request the error callback later. With just three simple lines you have completed an image request, but this is only the tip of the iceberg.

Advanced Picasso

Beyond simple usage, we will find that the load method is an overloaded method. In fact, besides the basic String type loading, we can also try loading the images we want from various sources.

Resource loading

int resourceId = R.mipmap.ic_launcher;

Picasso  
    .with(context)
    .load(resourceId)
    .into(imageViewResource);

File loading

File file = new File(Environment.getExternalStoragePublicDirectory(Environment.DIRECTORY_PICTURES), "Running.jpg");

Picasso  
    .with(context)
    .load(file)
    .into(imageViewFile);

Uri loading

Uri uri = resourceIdToUri(context, R.mipmap.future_studio_launcher);

Picasso  
    .with(context)
    .load(uri)
    .into(imageViewUri);

public static final String ANDROID_RESOURCE = "android.resource://";  
public static final String FOREWARD_SLASH = "/";

private static Uri resourceIdToUri(Context context, int resourceId) {  
    return Uri.parse(ANDROID_RESOURCE + context.getPackageName() + FOREWARD_SLASH + resourceId);
}

public class ImageListAdapter extends ArrayAdapter {  
    private Context context;
    private LayoutInflater inflater;

    private String[] imageUrls;

    public ImageListAdapter(Context context, String[] imageUrls) {
        super(context, R.layout.listview_item_image, imageUrls);

        this.context = context;
        this.imageUrls = imageUrls;

        inflater = LayoutInflater.from(context);
    }

    @Override
    public View getView(int position, View convertView, ViewGroup parent) {
        if (null == convertView) {
            convertView = inflater.inflate(R.layout.listview_item_image, parent, false);
        }

        Picasso
            .with(context)
            .load(imageUrls[position])
            .fit() // 稍后解释
            .into((ImageView) convertView);

        return convertView;
    }
}

The important part is ingetView()this method. Of course, you will find that using Picasso hasn't changed much. Devoting this article to explain this may not seem worth it, but behind the scenes Picasso automatically cancels image requests while scrolling, clears images, and loads the correct image toImageView。

The Power of Picasso: Cache

When you scroll up and down repeatedly, you will see images display much faster than before. I think you must have guessed that these images come from the cache and no longer need to be loaded from the network. Picasso mainly loads images from three sources:Memory -> Disk -> NetworkIn the end, whatever you need to do, Picasso has already done it for you! You can even change the cache size; we will explain this later.

Handling null/empty values in lists

When using Picasso, we might encounter two problems:IllegalArgumentException: Path must not be emptySecond, incomplete image mapping. To ensure the program runs normally, we will provide two ways to solve the problem.

Cancelling Picasso image requests

If you don't intend to load, you need to cancel this request usingcancelRequest()This ensures that this ImageView has no request callback. If the user scrolls very fast, ListView and ImageView reuse may occur. Cancelling requests can avoid incorrect image display.

Using placeholders

Another way is to use placeholders; simply put, use a default image.

Code example

@Override
public View getView(int position, View convertView, ViewGroup parent) {  
    if (null == convertView) {
        convertView = inflater.inflate(R.layout.listview_item_image, parent, false);
    }

    ImageView imageView = (ImageView) convertView;

    if (TextUtils.isEmpty(imageUrls[position])) {
        // option 1: 取消Picasso的图片请求
        Picasso
                .with(context)
                .cancelRequest(imageView);

        imageView.setImageDrawable(null);

        // option 2: 使用占位符
        /*
        Picasso
                .with(context)
                .load(R.drawable.floorplan)
                .into(imageView);
        */
    }
    else {
        Picasso
                .with(context)
                .load(imageUrls[position])
                .fit() // will explain later
                .into(imageView);
    }

    return convertView;
}

placeholder(), error(), fade in/out

.placeholder() placeholder

We almost forgot to consider a problem: an empty ImageView is a very unfriendly experience. If you use Picasso to load images from the network, different network environments may prevent the image from loading immediately. This is when our placeholder comes into play..placeholder()It will pre-load an image (of course, a local one) until the network image is loaded successfully.

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .placeholder(R.mipmap.ic_launcher)
    .into(imageViewPlaceholder);

.error() error placeholder

Suppose the image link we loaded has become invalid. We can choose an appropriate action through Picasso's error callback, but that would be too complicated. In most cases, you just need to callerror()is enough.

Picasso  
    .with(context)
    .load("http://futurestud.io/non_existing_image.png")
    .placeholder(R.mipmap.ic_launcher) 
    .error(R.mipmap.future_studio_launcher) 
    .into(imageViewError);

Using noFade()

If you want to display the image directly without the fade effect, you can use noFade().

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .placeholder(R.mipmap.ic_launcher) 
    .error(R.mipmap.future_studio_launcher) 
    .noFade()
    .into(imageViewFade);

Using noPlaceholder()

Let's consider the following situation: you load an image into an ImageView, and after some time, you want to load another image into the same ImageView. With the default settings, when you call Picasso again, the ImageView will load the previously set placeholder image. If this ImageView is important in your UI, rapidly changing the ImageView's image within a few seconds may look inappropriate. A better solution is to call.noPlaceholder()this method. The ImageView will keep displaying the first image until the second image is loaded. This will be very user-friendly.

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .placeholder(R.mipmap.ic_launcher) 
    .into(imageViewnoPlaceholder, new Callback() {
        @Override
        public void onSuccess() {
            Picasso
                .with(context)
               .load(UsageExampleListViewAdapter.eatFoodyImages[1])
               .noPlaceholder() 
               .into(imageViewNoPlaceholder);
        }
        @Override
        public void onError() {
        }
    });

Image scaling, resizing

Resizing with resize(x, y)

Generally speaking, if the images on your server exactly match the size you need, this will be a good balance of bandwidth, memory consumption, and image quality, but things don't always go as desired. If the resulting image is a size that cannot meet your needs, you can useresize(horizontalSize, verticalSize)to change the size of the image.

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .resize(600, 200) 
    .into(imageViewResize);

Using scaleDown()

If we callresize(x,y)method, Picasso will generally recalculate to change the loading quality of the image, for example when a small image is displayed as a large image. However, if our original image is larger than the new resized image specs, we can call onlyScaleDown() to display it directly without recalculating.

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .resize(6000, 2000)
    .onlyScaleDown() //如果它大于6000x2000像素，将仅对图像进行调整大小。
    .into(imageViewResizeScaleDown);

Avoiding image scaling and stretching

When we manipulate images, the aspect ratio between the original and the target can cause distortion. To prevent this, Picasso provides two solutions: callcenterCrop() or centerInside()。 centerCrop()centerCrop() uses a cropping technique to scale the image to fill the ImageView bounds, then crops off the excess parts. Using this method will fill the ImageView very well, but the image may not be fully displayed.

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .resize(600, 200) // resizes the image to these dimensions (in pixel)
    .centerCrop() 
    .into(imageViewResizeCenterCrop);

CenterInside()

centerInside() is also a cropping technique. When scaling, the image's width and height are both equal to or smaller than the set ImageView bounds. The image will be fully displayed, but it may not completely fill the ImageView.

Picasso
    .with(this)
    .load(eatFoodyImages[0])
    .resize(600, 200)
    .centerInside()
    .into(imageView);

fit()

The features introduced earlier can basically solve your scaling needs. There is also another feature that will be very useful: fit().

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .fit()
    // call .centerInside() or .centerCrop() to avoid a stretched image
    .into(imageViewFit);

fit() will measure the ImageView's width and height, and internally use resize() to reduce the image size to fit the ImageView. There are two things you must know about fit(): First, calling fit() delays the image request because Picasso needs to wait until the ImageView's size has been measured. Second, only one ImageView can be used as the target of fit (we will look at other targets later). The advantage is that the image uses the lowest resolution and is not affected by image quality. Lower resolution means it takes up less cache.
