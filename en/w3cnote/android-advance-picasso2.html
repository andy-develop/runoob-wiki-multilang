Image request ordering

Priority: HIGH, MEDIUM, LOW

Suppose there is a scenario where image loading needs to be displayed with priority, then you will usepriority(). This method requires one of three parameters:HIGH,MEDIUM,LOW, by default, all requests are MEDIUM.

//HIGH
Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .fit()
    .priority(Picasso.Priority.HIGH)
    .into(imageViewHero);

//LOW
Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[2])
    .fit()
    .priority(Picasso.Priority.LOW)
    .into(imageViewLowPrioRight);

注: Usepriority()It does not guarantee the display order of images; it is only the priority of requests.

tag() grouping requests

You have already learned about the request priority of images. Perhaps that is not enough. Suppose we need to cancel, pause, and resume multiple image requests at the same time; then you will usetag()

tag()You can use any Java object as a parameter, because based on these we can build image groups. The image group has the following options:

  • Pause requests pauseTag()
  • Resume requests resumeTag()
  • Cancel requests cancelTag()

Maybe you still cannot understand what this is all about. Let us look at a small example.

Example: pauseTag() and resumeTag()

Suppose we have an email app, the content is mainly used forListViewdisplay.

Now, let us imagine a scenario: the user wants to find a certain piece of information and will swipe quickly. ListView would normally quickly recycle and reuse each container. However, Picasso will attempt to make a request for each item and then immediately cancel it, because the user is swiping quickly.

To reduce more requests, we can wait until the ListView has finished scrolling before loading images. The user will not notice any difference, but this has already reduced the number of requests.

Implementation is very easy. First, add a tag to your Picasso request.

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .tag("Profile ListView") // can be any Java object
    .into(imageViewWithTag);

//接着，实现一个  `AbsListView.OnScrollListener` 和重写  `onScrollStateChanged()`

@Override
public void onScrollStateChanged(AbsListView view, int scrollState) {
final Picasso picasso = Picasso.with(context);

if (scrollState == SCROLL_STATE_IDLE || scrollState == SCROLL_STATE_TOUCH_SCROLL) {
      picasso.resumeTag(context);
} else {
      picasso.pauseTag(context);
}
}

//最后一步
listView.setOnScrollListener(onScrollListener);

When the ListView is in a very fast scrolling state, it pauses all requests; when scrolling normally or stopped, it resumes requests.

Official website sample code

Note: This article mainly uses String as the tag. Maybe you want to use a different object, perhaps you would think ofContext or Activity, Fragment, but the official documentation issued a warningIf the user leavesActivity, the garbage collector may not be able to destroy the Activity object because of Picasso, resulting in a memory leak.

Callbacks, RemoteView and Notifications

Differences between fetch(), get() and Target

fetch()： fetch()Asynchronously loads the image on a background thread, but does not display it inImageView, nor returns a Bitmap. This method only saves it to the disk and memory caches. It can be used to load the current image later.

get()： get()Synchronously loads the image and returns aBitmapobject.Targets：The into option, besides passing an ImageView object, can also accept a Target, which is a callback.

Using Target as a callback mechanism

So far,.into()we have been passing in ImageView objects. Of course, this method also has overloads. Let us directly look at an example, and you may immediately understand.

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .into(target);

//下面是重点
private Target target = new Target() {  
    @Override
    public void onBitmapLoaded(Bitmap bitmap, Picasso.LoadedFrom from){
        // 图片加载成功
    }
    @Override
    public void onBitmapFailed(Drawable errorDrawable) {
        // 图片加载失败
    }
    @Override
    public void onPrepareLoad(Drawable placeHolderDrawable) {
        //图片加载中
    }
};

Note:It is not recommended to use an anonymous implementation here. The garbage collector may recycle your target, and you will not get the Bitmap.

Image rotation and transformation

Rotation

Picasso has built-in rotation functionality. Let us look directly at the code, because it is not difficult to understand.

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .rotate(90f)
    .into(imageViewSimpleRotate);

In addition to rotating around the center by default, sometimes we may need to rotate around other pivot points. We can callrotate(float degrees, float pivotX, float pivotY)。

Picasso  
    .with(context)
    .load(R.drawable.floorplan)
    .rotate(45f, 200f, 100f)
    .into(imageViewComplexRotate);

Transformation

Rotation is only a small part of image processing techniques. Picasso also providesTransformationfor image processing. You only need to implementTransformationa main method of the interfacetransform(android.graphics.Bitmap source), this method takes a Bitmap as input and returns the transformed one. After implementing this interface, you only need to call it in Picassotransform(Transformation transformation)and the image transformation is complete. With all that said, let us look at two examples.

Blur image

First, we need to implementTransformationthe interface, by usingRenderScript. But this article does not intend to introduceRenderScript, but we should understand that it can be used to blur images.

public class BlurTransformation implements Transformation {

    RenderScript rs;

    public BlurTransformation(Context context) {
        super();
        rs = Renderscript.create(context);
    }

    @Override
    public Bitmap transform(Bitmap bitmap) {
        // 创建一个位图，
        Bitmap blurredBitmap = bitmap.copy(Bitmap.Config.ARGB_8888, true);

        // 分配内存
        Allocation input = Allocation.createFromBitmap(rs, blurredBitmap, Allocation.MipmapControl.MIPMAP_FULL, Allocation.USAGE_SHARED);
        Allocation output = Allocation.createTyped(rs, input.getType());

        // 加载一个特定的脚本
        ScriptIntrinsicBlur script = ScriptIntrinsicBlur.create(rs, Element.U8_4(rs));
        script.setInput(input);

        // 设置模糊半径
        script.setRadius(10);

        // 启动ScriptIntrinisicBlur
        script.forEach(output);

        // 输出
        output.copyTo(blurredBitmap);

        bitmap.recycle();
        return blurredBitmap;
    }

    @Override
    public String key() {
        return "blur";
    }
}

After the definition is complete, the call in Picasso becomes very simple.

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .transform(new BlurTransformation(context))
    .into(imageViewTransformationBlur);

Blur and grayscale scalingNot only that, Picasso'stransformmethod also providestransform(List<? extends Transformation> transformations), which means we can apply a series of transformations to the image. Here, we will implement another grayscale scaling.

public class GrayscaleTransformation implements Transformation {

    private final Picasso picasso;

    public GrayscaleTransformation(Picasso picasso) {
        this.picasso = picasso;
    }

    @Override
    public Bitmap transform(Bitmap source) {
        Bitmap result = createBitmap(source.getWidth(), source.getHeight(), source.getConfig());
        Bitmap noise;
        try {
            noise = picasso.load(R.drawable.noise).get();
        } catch (IOException e) {
            throw new RuntimeException("Failed to apply transformation! Missing resource.");
        }

        BitmapShader shader = new BitmapShader(noise, REPEAT, REPEAT);

        ColorMatrix colorMatrix = new ColorMatrix();
        colorMatrix.setSaturation(0);
        ColorMatrixColorFilter filter = new ColorMatrixColorFilter(colorMatrix);

        Paint paint = new Paint(ANTI_ALIAS_FLAG);
        paint.setColorFilter(filter);

        Canvas canvas = new Canvas(result);
        canvas.drawBitmap(source, 0, 0, paint);

        paint.setColorFilter(null);
        paint.setShader(shader);
        paint.setXfermode(new PorterDuffXfermode(PorterDuff.Mode.MULTIPLY));

        canvas.drawRect(0, 0, canvas.getWidth(), canvas.getHeight(), paint);

        source.recycle();
        noise.recycle();

        return result;
    }

    @Override
    public String key() {
        return "grayscaleTransformation()";
    }
}

After completion, it is time to reference it in Picasso. This time we only need to create a List collection.

List<Transformation> transformations = new ArrayList<>();

transformations.add(new GrayscaleTransformation(Picasso.with(context)));  
transformations.add(new BlurTransformation(context));

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .transform(transformations)
    .into(imageViewTransformationsMultiple);

Image caching

Picasso's default cache configuration.

LRU memory cache: 15% of available RAM Disk cache: 2% of storage space, up to 50MB, but no less than 5MB Three download threads for disk and network access

We can change the cache size, but that is beyond the scope of this blog. Returning to the topic of image caching, Picasso first tries to load the image from the memory cache; if it is not there, it then retrieves the disk cache; if it is not on the disk either, then it will initiate a network request (memory -> disk -> network request). In addition, all requested images are stored in both caches (until they must be deleted to free up space). If you think this caching strategy cannot satisfy you, we can look atMemoryPolicy

Memory policy

First, Picasso will preferentially fetch the requested image from memory. If you want to skip this step, you can usememoryPolicy(MemoryPolicy policy, MemoryPolicy... additional)。 MemoryPolicyis a simple enum with two valuesNO_CACHE和NO_STORE。

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[1])
    .memoryPolicy(MemoryPolicy.NO_CACHE)
    .into(imageViewFromDisk);

If you want to know what NO_STORE is used for: it means that the requested image is not cached in memory. Let us take a look at the example below.

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[1])
    .memoryPolicy(MemoryPolicy.NO_CACHE, MemoryPolicy.NO_STORE)
    .into(imageViewFromDisk);

This makes the requested image not cached in memory, and Picasso will not look for it in memory either. The benefit of doing this is that it can speed up memory reclamation, because the existing API cannot clear the memory cache.

Network policy

If you want to skip the disk cache, you can call.networkPolicy(NetworkPolicy policy, NetworkPolicy... additional) 与 NetworkPolicy.NO_CACHEas a parameter.

Picasso  
    .with(context)
    .load(UsageExampleListViewAdapter.eatFoodyImages[2])
    .networkPolicy(NetworkPolicy.NO_CACHE)
    .into(imageViewFromNetwork);

Finally, a third option is also providedNetworkPolicy：OFFLINE. If this is used as a parameter, then Picasso will only look for the image from the cache; even if there is a network, it will not send a request.

Cache indicator, logging, statistics

Cache indicator

As competent developers, sometimes we need to analyze where images come from. The simplest way is to enable the cache indicator, just use.setIndicatorsEnabled(true) 。

Picasso  
    .with(context)
    .setIndicatorsEnabled(true);

After that, all images will have a small indicator in the upper-left corner.

  • Green (image from memory)
  • Blue (image from disk)
  • Red (image from network)

Sometimes we may need more information; we can enable logging,.setLoggingEnabled(true)。

Picasso

Using Picasso.Builder to customize Picasso

Picasso has direct methods to modify instances of PicassoPicasso.Builder类. You can use it to customize Picasso.

Locally customizing Picasso

Before diving into customizing Picasso, we need to briefly review how to obtain a standard Picasso instance.

Picasso picasso = Picasso.with(Context);

This method returns a standard Picasso. If you need to create a custom instance, one way is to createPicasso.Builderan object to make adjustments.

// 创建 Picasso.Builder 对象
Picasso.Builder picassoBuilder = new Picasso.Builder(context);
// TODO
Picasso picasso = picassoBuilder.build()

Next, we can use the custom Picasso to load images.

picasso  
    .load(UsageExampleListViewAdapter.eatFoodyImages[0])
    .into(imageView1)

Globally using a custom Picasso

The methods for creating and modifying a Picasso instance remain unchanged.

// 创建 Picasso.Builder 对象
Picasso.Builder picassoBuilder = new Picasso.Builder(context);

//TODO
Picasso picasso = picassoBuilder.build();

To make this Picasso global, just callPicasso.setSingletonInstance(picasso);, usually, this should be initialized when the App starts.

try {  
    Picasso.setSingletonInstance(picasso);
} catch (IllegalStateException ignored) {
}

Once you have a custom global Picasso, all subsequentPicasso.with(Context context)calls will return the custom Picasso.

Now that we've learned how to customize Picasso, we still don't understand what customizing Picasso can do?

Customizing Picasso: Changing the downloader

Picasso uses the best available caching and network components by default. If you want to replace the default downloader, you canPicasso.Buildercalldownloader(Downloader downloader), for example, our OkHttp.

Picasso.Builder picassoBuilder = new Picasso.Builder(context);

//更改下载器。
picassoBuilder.downloader(new OkHttpDownloader(new OkHttpClient()));

Picasso picasso = picassoBuilder.build();

However, there is one thing to note: if the images you load are fetched from your own server, and the server uses HTTPS, and a signature is required, then OkHttp may fail to load the images due to SSL issues. In this case, you can choose to use UnsafeOkHttpClient to avoid this problem.

picassoBuilder.downloader(  
    new OkHttpDownloader(
        UnsafeOkHttpClient.getUnsafeOkHttpClient()
    )
);

Custom request handling

Still about customizing Picasso, let's look at a piece of code first.

Picasso.Builder picassoBuilder = new Picasso.Builder(context);

picassoBuilder.addRequestHandler(new EatFoodyRequestHandler());

Picasso picasso = picassoBuilder.build();

The only thing that might be confusing isEatFoodyRequestHandler, which is aRequestHandlercustom (request handler) class that we inherit from, so let's see whatRequestHandler。

RequestHandler implementation

This is an abstract class with two methods to implement.

boolean canHandleRequest(Request data) Result load(Request request, int networkPolicy)

The first method lets Picasso know whether this request handler can handle the current request. If it can, the request will be passed to theload()method.

Let's take a look at how this class is implemented as a whole.

public class EatFoodyRequestHandler extends RequestHandler {  
    private static final String EAT_FOODY_RECIPE_SCHEME = "eatfoody";
    @Override
    public boolean canHandleRequest(Request data) {
        return EAT_FOODY_RECIPE_SCHEME.equals(data.uri.getScheme());
    }

    @Override
    public Result load(Request request, int networkPolicy) throws IOException {
        //获取请求的host
       String imageKey = request.uri.getHost(); 
       Bitmap bitmap;
       if (imageKey.contentEquals("cupcake")) {
           bitmap = BitmapFactory.decodeResource(getResources(), R.drawable.cupcake);
       }else if (imageKey.contentEquals("full_cake")) {
           bitmap = BitmapFactory.decodeResource(getResources(), R.drawable.full_cake);
       }else {
           bitmap = BitmapFactory.decodeResource(getResources(), R.mipmap.ic_launcher);
       }
       return new Result(bitmap, Picasso.LoadedFrom.DISK);
    }
}

The code does not look easy to understand. First,canHandleRequestin the method, we check whether the URI's scheme equalseatfoody. If not, Picasso will fall back to the standard download process. If so, it will enter theloadmethod, and in theloadmethod, we check the URI'shostpart, and then return the corresponding bitmap based on the check.

//这会按照标准的流程加载图片
picasso  
    .load("http://i.imgur.com/DvpvklR.png")
    .into(imageView1);

//他会进入 load 方法中的逻辑判断去加载 `R.drawable.full_cake`
picasso  
    .load("eatfoody://cupcake")
    .into(imageView2)
