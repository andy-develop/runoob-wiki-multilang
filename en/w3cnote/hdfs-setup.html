4.0 HDFS Configuration and Usage

Category Hadoop Tutorial

The three Hadoop modes mentioned earlier:Standalone mode、Pseudo-distributed mode和Cluster mode。

Standalone mode: Hadoop only exists as a library, and can execute MapReduce tasks on a single computer. It is only used by developers to set up learning and experimental environments.

Pseudo-distributed mode: In this mode, Hadoop runs as daemon processes on a single machine, generally used by developers to set up learning and experimental environments.

Cluster mode: This mode is Hadoop's production environment mode, that is to say, this is the mode Hadoop is truly used in, providing production-grade services.

HDFS Configuration and Startup

HDFS is similar to a database in that it is started as daemon processes. To use HDFS, you need an HDFS client to connect to the HDFS server over the network (socket) to use the file system.

在Hadoop Runtime EnvironmentIn the chapter, we have already configured the basic Hadoop environment, with the container named hadoop_single. If you closed that container last time or shut down the computer causing the container to close, please start and enter the container.

After entering the container, let's confirm whether Hadoop exists:

hadoop version

If the result shows the Hadoop version number, it means Hadoop exists.

Next, we will proceed to the formal steps.

Create a new hadoop user

Create a new user named hadoop:

adduser hadoop

Install a small utility for modifying user passwords and permission management:

yum install -y passwd sudo

Set the hadoop user password:

passwd hadoop

Next, enter the password twice. Be sure to remember it!

Change the owner of the hadoop installation directory to the hadoop user:

chown -R hadoop /usr/local/hadoop

Then use a text editor to modify the /etc/sudoers file, in

root    ALL=(ALL)       ALL

add a line after that

hadoop  ALL=(ALL)       ALL

Then exit the container.

Shut down and commit the container hadoop_single to the image hadoop_proto:

docker stop hadoop_single
docker commit hadoop_single hadoop_proto

Create a new container hdfs_single:

docker run -d --name=hdfs_single --privileged hadoop_proto /usr/sbin/init

In this way, the new user is created.

Start HDFS

Now enter the container you just created:

docker exec -it hdfs_single su hadoop

You should now be the hadoop user:

whoami

It should display "hadoop"

Generate an SSH key:

ssh-keygen -t rsa

Here you can keep pressing Enter until generation finishes.

Then add the generated key to the trusted list:

ssh-copy-id hadoop@172.17.0.2

Check the container's IP address:

ip addr | grep 172

Thus we know the container's IP address is 172.17.0.2; your IP may be different.

Before starting HDFS, we do some simple configuration. All Hadoop configuration files are stored in the etc/hadoop subdirectory under the installation directory, so we can enter this directory:

cd $HADOOP_HOME/etc/hadoop

Here we modify two files: core-site.xml and hdfs-site.xml

In core-site.xml, we add the following properties under the <configuration> tag:

<property>
    <name>fs.defaultFS</name>
    <value>hdfs://<你的IP>:9000</value>
</property>

In hdfs-site.xml, add properties under the <configuration> tag:

<property>
    <name>dfs.replication</name>
    <value>1</value>
</property>

Format the file structure:

hdfs namenode -format

Then start HDFS:

start-dfs.sh

Startup is divided into three steps: start NameNode, DataNode, and Secondary NameNode respectively.

We can run jps to view Java processes:

At this point, the HDFS daemon processes have been established. Since HDFS itself has an HTTP panel, we can visit http://your-container-IP:9870/ via a browser to view the HDFS panel and detailed information:

If this page appears, it means HDFS has been configured and started successfully.

Note:If you are not using a Linux system with a desktop environment and have no browser, you can skip this step. If you are using Windows but not using Docker Desktop, this step will be difficult to accomplish.

Using HDFS

HDFS Shell

Go back to the hdfs_single container. The following commands will be used to operate HDFS:

# 显示根目录 / 下的文件和子目录，绝对路径
hadoop fs -ls /
# 新建文件夹，绝对路径
hadoop fs -mkdir /hello
# 上传文件
hadoop fs -put hello.txt /hello/
# 下载文件
hadoop fs -get /hello/hello.txt
# 输出文件内容
hadoop fs -cat /hello/hello.txt

The most basic HDFS commands are as described above. In addition, there are many other operations supported by traditional file systems.

HDFS API

HDFS is already supported by many backend platforms. Currently, the official distribution includes C/C++ and Java programming interfaces. In addition, the package managers of node.js and Python also support importing HDFS clients.

The following is a list of dependencies for the package managers:

Maven：

    <dependency>
        <groupId>org.apache.hadoop</groupId>
        <artifactId>hadoop-client</artifactId>
        <version>3.1.4</version>
    </dependency>

Gradle：

providedCompile group: 'org.apache.hadoop', name: 'hadoop-hdfs-client', version: '3.1.4'

NPM：

npm i webhdfs

pip：

pip install hdfs

Here is an example of connecting to HDFS with Java (don't forget to modify the IP address):

Example

package com.runoob;
import java.io.IOException;
import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.fs.*;
public class Application {
    public static void main(String[] args) {
        try {
            // Configure the connection address
            Configuration conf = new Configuration();
            conf.set("fs.defaultFS", "hdfs://172.17.0.2:9000");
            FileSystem fs = FileSystem.get(conf);
            // Open the file and read the output
            Path hello = new Path("/hello/hello.txt");
            FSDataInputStream ins = fs.open(hello);
            int ch = ins.read();
            while (ch != -1) {
                System.out.print((char)ch);
                ch = ins.read();
            }
            System.out.println();
        } catch (IOException ioe) {
            ioe.printStackTrace();
        }
    }
}
