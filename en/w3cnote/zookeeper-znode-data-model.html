5.0 ZooKeeper Data Model znode Structure Detailed

Category Zookeeper Tutorial

Data Model

In zookeeper, it can be said that all stored data in zookeeper consists of znodes. Nodes are also called znodes, and data is stored in key/value form.

The overall structure is similar to the Linux file system pattern, stored in a tree structure. The root path starts with/at the beginning.

Enter the bin directory of the zookeeper installation, open the command line terminal via sh zkCli.sh, and execute the "ls /" command to display:
$ ls /
$ ls /zookeeper
$ ls /zookeeper/quota

We can intuitively see that the stored data currently has two nodes, runoob and zookeeper, under the root directory, and under the zookeeper node there is a node called quota.

The runoob node was created in our previous chapter, and its value was set to 0 through the Java client. Now we execute in the command line terminalget /runoobto display the attributes of this node.

$ get /runoob

The 0 displayed in the first line is the value of this node.

Znode Status Attributes

cZxidThe transaction ID when the node was created
ctimeThe time when the node was created
mZxidThe transaction ID when the node was last modified
mtimeThe time when the node was last modified
pZxidIndicates the transaction ID of the last modification to the child node list of this node. Adding or deleting child nodes affects the child node list, but modifying the data content of a child node does not affect this ID.(Note: only changes to the child node list will change pzxid; changes to child node content do not affect pzxid)
cversionChild node version number; the version number increases by 1 each time the child node is modified
dataversionData version number; the version number increases by 1 each time the data is modified
aclversionPermission version number; the version number increases by 1 each time the permission is modified
ephemeralOwnerThe session ID of the session that created this ephemeral node.（**If the node is a persistent node, then this attribute value is 0)**
dataLengthThe data length of this node
numChildrenThe number of child nodes this node has(Only counts the number of direct child nodes)

With the above status attribute values understood, we will/runoobmake a modification to the node, execute the commandset /runoob 1, as shown in the figure below:

$ set /runoob 1

Comparing the above results, it can be seen that mZxid, mtime, and dataVersion have all changed.

在 /runoobUnder the node, we add another child node, execute:

$ create -e  /runoob/child  0
$ get /runoob

It can be seen that/runoobthe pZxid, cversion, and numChildren of the node have all changed accordingly.
