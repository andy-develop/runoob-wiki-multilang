Java class.forname Detailed Explanation

Category Programming Technology

For most people, the first time they seeclass.forName(String className)this code should be when usingJDBCthe method to connect to the database.

Example

import com.mysql.jdbc.Driver; import java.sql.*; public class JdbcDemo { public static void main(String[] args) throws SQLException, ClassNotFoundException { String url = "jdbc:mysql://127.0.0.1:3306/mydb"; String username = "root"; String password = "redhat"; Class.forName("com.mysql.jdbc.Driver"); Connection connection = DriverManager.getConnection(url, username, password); String sql = "SELECT * FROM msg"; PreparedStatement prepareStatement = connection.prepareStatement(sql); ResultSet resultSet = prepareStatement.executeQuery(); resultSet.next(); String address = resultSet.getString("address"); System.out.println(address); } }

Class.forNameAfter passing in com.mysql.jdbc.Driver, you know that the database I am connecting to is MySQL. Why is this? Let's look at the source code:

@CallerSensitive public static Class<?> forName(String className) throws ClassNotFoundException { Class<?> caller = Reflection.getCallerClass(); return forName0(className, true, ClassLoader.getClassLoader(caller), caller); }

We find that it calls the forName0 method. Let's continue tracing and take another look:

private static native Class<?> forName0(String name, boolean initialize, ClassLoader loader, Class<?> caller) throws ClassNotFoundException;

It is a native method, so the source code ends here. Let's take a look at the description in the official documentation:https://docs.oracle.com/javase/7/docs/api/java/lang/Class.html#forName(java.lang.String)

Returns the Class object associated with the class or interface with the given string name, using the given class loader. Given the fully qualified name for a class or interface (in the same format returned by getName) this method attempts to locate, load, and link the class or interface. The specified class loader is used to load the class or interface. If the parameter loader is null, the class is loaded through the bootstrap class loader. The class is initialized only if the initialize parameter is true and if it has not been initialized earlier.

A rough translation is: Returns a Class object for a given class or interface. If no classloader is given, the root class loader will be used. If the initialize parameter is passed as true, then the given class will be initialized if it has not been initialized before. In the first step of JDBC, the parameter we pass in is com.mysql.jdbc.Driver. That is to say, this class will be initialized. Let's look at the contents of this class:

public class Driver extends NonRegisteringDriver implements java.sql.Driver { static { try { java.sql.DriverManager.registerDriver(new Driver()); } catch (SQLException E) { throw new RuntimeException("Can't register driver!"); } } public Driver() throws SQLException { // Required for Class.forName().newInstance() } }

We find that this class is also super simple. It has a constructor and a static code block. We know that when a class is initialized, the contents of the static code block will be executed. That is to say, weClass.forNameand directly writingDriverManager.registerDriver(new Driver)The two are functionally equivalent. Let's switch to this style and try again:

public class JdbcDemo { public static void main(String[] args) throws SQLException, ClassNotFoundException { String url = "jdbc:mysql://127.0.0.1:3306/mydb"; String username = "root"; String password = "redhat"; //Class.forName("com.mysql.jdbc.Driver"); DriverManager.registerDriver(new Driver()); Connection connection = DriverManager.getConnection(url, username, password); String sql = "SELECT * FROM msg"; PreparedStatement prepareStatement = connection.prepareStatement(sql); ResultSet resultSet = prepareStatement.executeQuery(); resultSet.next(); String address = resultSet.getString("address"); System.out.println(address); } }

We find that the code still executes normally.

Let's summarize: Class.forNameThe purpose of the method is to initialize the given class. And in the MySQL Driver class we provided, it registers the driver in the static code block through JDBC's DriverManager. We can also directly use JDBC's driver manager to register the MySQL driver, thereby replacing the use ofClass.forName。

    Understanding Class.forName()

    The concept of the Class class

    Class is also a Java class. It stores the meta information (metadata) of the corresponding Java class, which is used to describe the structure of the class, such as describing what members a class has, what methods it has, etc. It is generally used in reflection.

    Detailed explanation:Java source code (.java file) is converted into Java bytecode (.class file) after being compiled by the Java compiler. The class loader is responsible for reading the Java bytecode and converting it into an instance of the java.lang.Class class (a Class object). That is to say, in Java, every Java class has a corresponding Class object to represent the type information of this Java class.

    The concept of class loading

    When using a class (for example, creating an instance of a class with new), it checks whether this class has been loaded into memory. If not, the loading operation is performed.

    Read the class file data corresponding to the class, parse this data, and construct an instance of the Class class corresponding to this class. At this point, the JVM can use the class, such as instantiating the class or calling static methods of the class.

    Java also provides an interface for manually loading classes, and the class.forName() method is one of them. (After all is said and done, it is actually generating the Class of this class.)

    The concept of class loader

    As the name suggests, a class loader is used to load Java classes into the Java virtual machine. Generally speaking, the way the Java virtual machine uses Java classes is as follows: Java source code (.java file) is converted into Java bytecode (.class file) after being compiled by the Java compiler. The class loader is responsible for reading the Java bytecode and converting it into an instance of the java.lang.Class class. Each such instance is used to represent a Java class. Through the newInstance() method of this instance, an object of this class can be created. Basically all class loaders are instances of the java.lang.ClassLoader class.

    The concept of class initialization

    After the class is loaded, the JVM has obtained a Class instance that describes the class structure. However, the class initialization operation must be performed before the class can be used normally. The class initialization operation is to execute the static statements of the class once, including the declaration of static variables and static code blocks.

    The Class.forName() method

    The meaning of this method is: load the class specified by the parameter and initialize it.

    Application in connecting to a database with JDBC

    At this point, without further explanation, readers will understand why it is necessary to executeClass.forName('驱动类名')The method is: load the class file of the driver class into memory, form a Class instance describing the structure of this driver class, and initialize this driver class, so that the JVM can use it. This is the meaning of the Class.forName() method.

    Friends with database development experience will notice that some do not call the newInstance() method when we load the database driver package. That is, some JDBC database connection code uses Class.forName(xxx.xx.xx); while others use Class.forName(xxx.xx.xx).newInstance(). Why are there these two approaches?

    As mentioned earlier,Class.forName("");The role is to require the JVM to find and load the specified class. If the class has a static initializer, the JVM will necessarily execute the static code segment of the class. In the JDBC specification, this Driver class is explicitly required to register itself with DriverManager. That is, the code of the Driver class of any JDBC Driver must be similar to the following:

    public class MyJDBCDriver implements Driver { 
    static { 
        DriverManager.registerDriver(new MyJDBCDriver()); 
    } 
}

    Since the registration has already been performed in the static initializer, when using JDBC we only need toClass.forName(XXX.XXX);That is all that is needed.

    The difference between Class.forName() and xxx.class

    All classes are dynamically loaded into the JVM when they are first used. When the program creates the first reference to a static member of the class, the class is loaded. This also proves that the constructor is also a static method of the class, even though there is no static keyword before the constructor. Therefore, creating an object of the class using the new operator is also regarded as a reference to a static member of the class.

    Therefore, a Java program is not completely loaded before it starts running; its various parts are loaded only when needed.

    The class loader first checks whether the Class object of this class has been loaded. If it has not been loaded, the default class loader will look up the .class file based on the class name. When the bytecode of this class is loaded, it undergoes verification to ensure that it has not been corrupted.

    Class objects are loaded only when needed. Static initialization is performed when the class is loaded.

    ForClass.forName()this method is a static member of the Class class. Class objects are just like other objects, we can obtain and manipulate their references. forName() is a method for obtaining a reference to a Class object. It takes a String containing the text name of the target class as an input parameter and returns a reference to a Class object. When the forName() method finds that a certain class has not been loaded, it will actively load this class. During the loading process, the static clause of the class will be executed.

    Java also provides another way to generate a reference to a Class object, namely using a class literal. For example: xxx.class. However, when this form is used to create a reference to a Class object, the Class object is not automatically initialized. Initialization is deferred until a static method or a non-constant static field is first referenced.

    public class Initable {  
    static final int staticFinal = 47;  
    static final int staticFianl2 = ClassInitialization.rand.nextInt(1000);  
    static {  
        System.out.println("Initializing Initable");  
    }

    From the creation of the reference to initable, it can be seen that merely using .class syntax to obtain a reference to a class does not cause initialization. If a static final value is a "compile-time constant", like Initable.staticFinal, then this value can be read without initializing the Initable class. But if a field is merely set to static and final, that is not enough to ensure this behavior. For example, access to Initable.staticFianl2 will force initialization of the type, because it is not a compile-time constant.
