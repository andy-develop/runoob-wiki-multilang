Perl Special Variables

The Perl language defines some special variables, usually prefixed with $, @, or %, for example: $_.

Many special variables have a long English name; the OS error variable $! can be written as $OS_ERROR.

If you want to use special variables with English names, you need to add the following at the top of the program:use English;This allows you to use descriptive English special variable names.

The most commonly used special variable is $_, which contains the default input and pattern matching content. Example:

Example

#!/usr/bin/perl foreach ('Google','Runoob','Taobao') { print $_; print "\n"; }

Running the above program produces the output:

Google
Runoob
Taobao

In the following example, we do not use $_ to output content:

Example

#!/usr/bin/perl foreach ('Google','Runoob','Taobao') { print; print "\n"; }

Running the above program produces the output:

Google
Runoob
Taobao

In the example, it first outputs "Google", then outputs "Runoob", and finally outputs "Taobao".

In an iteration loop, the current loop's string is placed in $_, then output via print. Additionally, print uses $_ by default when no output variable is specified.

The following are places where Perl assumes $_ is used even if it is not explicitly written:

  • Various unary functions, including functions like ord() and int(), as well as all file test operators ("-f", "-d") except "-t"; "-t" operates on STDIN by default.
  • Various list functions, such as print() and unlink().
  • Pattern matching operations "m//", "s///", and "tr///" when the "=~" operator is not used.
  • The default iteration variable for a "foreach" loop when no other variable is given.
  • The implicit iteration variable for the grep() and map() functions.
  • When "while" has only a single condition and that condition tests the result of a "<>" operation, $_ is the default location for storing the input record. This only happens in a "while" test condition. (Mnemonic: the underscore can be omitted in certain operations.)

Special Variable Types

According to the usage characteristics of special variables, they can be divided into the following categories:

  • Global scalar special variables.

  • Global array special variables.

  • Global hash special variables.

  • Global special file handles.

  • Global special constants.

  • Regular expression special variables.

  • File handle special variables.

Global Array Special Variables

@ARGV The list of command-line arguments passed to the script.
@INC The list of directories to search when importing modules.
@F The array input of the command line.

Global Hash Special Variables

%INC

 The hash %INC contains all files included with do or require statements. The key is the filename, and the value is the path to the file.

%ENV

 Contains the current environment variables.

%SIG

 The signal list and how they are handled.

Global Special File Handles

ARGV

 A special file handle that iterates over all filenames in the array variable @ARGV.

STDERR

 Standard error output handle.

STDIN

 Standard input handle.

STDOUT

 Standard output handle.

DATA

 The special file handle references any content after the __END__ marker in the file, including the script content. Or it references all content after the __DATA__ marker in a file; __DATA__ exists as long as you read data in the same package.

_ (underscore)

 A special file handle used to cache file information (fstat, stat, and lstat).

Global Special Constants

__END__

 The logical end of the script; the following text is ignored.

__FILE__

 The current filename.

__LINE__

 The current line number.

__PACKAGE__

 The current package name; the default package name is main.

    Perl Reading .ini Style Configuration Files with Config::IniFiles

    If a Perl script has too many parameters to configure, using command-line arguments is not appropriate. We can use a configuration file to configure these parameters, and the Config::IniFiles module provides us with parsing for.inistyle configuration files. Importantly, other languages, such as Python, also have.inipackages for parsing style configuration files, so using this method facilitates program portability.

    Config::IniFiles

    First, let's look at the .ini style configuration file format:

    [section]          #参数模块
Parameter=Value    #该模块某参数的值。配置文件使用'#'或者';'注释

    Usage:

    use Config::IniFiles; #加载模块
my $cfg = new Config::IniFiles( -file => "/path/configfile.ini" ); #读取配置文件
my $value = $cfg->val('Section', 'Parameter'); #读取参数

    A more convenient way to read:

    my %ini
tie %ini, 'Config::IniFiles', ( -file => "/path/configfile.ini" );
#该方法把参数读进了二维哈希（引用的引用），即$ini{Section}{Parameter}

    For detailed usage, please refer to:http://search.cpan.org/~wadg/Config-IniFiles-2.38/IniFiles.pm
