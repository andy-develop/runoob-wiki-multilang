Java Multithreading Programming

Java provides built-in support for multithreading programming. A thread refers to a single sequential control flow within a process. A process can have multiple threads running concurrently, and each thread executes different tasks in parallel.

Multithreading is a special form of multitasking, but multithreading uses smaller resource overhead.

Here is another term related to threads - process: A process includes memory space allocated by the operating system and contains one or more threads. A thread cannot exist independently; it must be part of a process. A process keeps running until all non-daemon threads have finished running.

Multithreading enables programmers to write highly efficient programs to make full use of the CPU.

The Lifecycle of a Thread

A thread is a dynamic execution process, and it also has a process from creation to death.

The following diagram shows the complete lifecycle of a thread.

  • New state:

    Usingnewthe keyword andThreadAfter a class or its subclass creates a thread object, the thread object is in the new state. It remains in this state until the programstart()this thread.

  • Ready state:

    After the thread object calls the start() method, the thread enters the ready state. A thread in the ready state is in the ready queue and waits for scheduling by the thread scheduler in the JVM.

  • Running state:

    If a thread in the ready state obtains CPU resources, it can executerun(), at this point the thread is in the running state. A thread in the running state is the most complex; it can change to the blocked state, ready state, and dead state.

  • Blocked state:

    If a thread executes methods such as sleep, suspend, and so on, after losing the occupied resources, the thread transitions from the running state to the blocked state. When the sleep time expires or device resources are obtained, it can re-enter the ready state. It can be divided into three types:

    • Waiting blocked: A thread in the running state executes the wait() method, causing the thread to enter the waiting blocked state.

    • Synchronous blocked: The thread fails to acquire the synchronized lock (because the lock is occupied by another thread).

    • Other blocking: When an I/O request is issued by calling the thread's sleep() or join(), the thread enters the blocked state. When the sleep() state times out, join() waits for the thread to terminate or times out, or when I/O processing completes, the thread transitions back to the ready state.

  • Dead state:

    When a running thread completes its task or other termination conditions occur, the thread switches to the terminated state.

Thread Priority

Every Java thread has a priority, which helps the operating system determine the order in which threads are scheduled.

The priority of a Java thread is an integer whose value ranges from 1 (Thread.MIN_PRIORITY) to 10 (Thread.MAX_PRIORITY).

By default, every thread is assigned a priority of NORM_PRIORITY (5).

Threads with higher priority are more important to the program and should be allocated processor resources before lower-priority threads. However, thread priority does not guarantee the order of thread execution and is highly platform-dependent.

Creating a Thread

Java provides three ways to create threads:

  • By implementing the Runnable interface;
  • By extending the Thread class itself;
  • By creating threads through Callable and Future.

Creating a Thread by Implementing the Runnable Interface

To create a thread, the simplest way is to create a class that implements the Runnable interface.

To implement Runnable, a class only needs to implement one method call, run(), declared as follows:

public void run()

You can override this method. It is important to understand that run() can call other methods, use other classes, and declare variables, just like the main thread.

After creating a class that implements the Runnable interface, you can instantiate a thread object within the class.

Thread defines several constructors. The following is the one we often use:

Thread(Runnable threadOb,String threadName);

Here, threadOb is an instance of a class that implements the Runnable interface, and threadName specifies the name of the new thread.

After the new thread is created, it will run only when you call its start() method.

void start();

The following is an example of creating a thread and starting it:

Example

class RunnableDemo implements Runnable { private Thread t; private String threadName; RunnableDemo( String name) { threadName = name; System.out.println("Creating " + threadName ); } public void run() { System.out.println("Running " + threadName ); try { for(int i = 4; i > 0; i--) { System.out.println("Thread: " + threadName + ", " + i); //Make the thread sleep for a while Thread.sleep(50); } }catch (InterruptedException e) { System.out.println("Thread " + threadName + " interrupted."); } System.out.println("Thread " + threadName + " exiting."); } public void start () { System.out.println("Starting " + threadName ); if (t == null) { t = new Thread (this, threadName); t.start (); } } } public class TestThread { public static void main(String args[]) { RunnableDemo R1 = new RunnableDemo( "Thread-1"); R1.start(); RunnableDemo R2 = new RunnableDemo( "Thread-2"); R2.start(); } }

Creating a Thread via Callable and Future

  • 1. Create an implementation class of the Callable interface and implement the call() method. The call() method will serve as the thread execution body and has a return value.

  • 2. Create an instance of the Callable implementation class, and use the FutureTask class to wrap the Callable object. The FutureTask object encapsulates the return value of the call() method of that Callable object.

  • 3. Use the FutureTask object as the target of a Thread object to create and start a new thread.

  • 4. Call the FutureTask object's get() method to obtain the return value after the child thread finishes execution.

Example

public class CallableThreadTest implements Callable<Integer> { public static void main(String[] args) { CallableThreadTest ctt = new CallableThreadTest(); FutureTask<Integer> ft = new FutureTask<>(ctt); for(int i = 0;i < 100;i++) { System.out.println(Thread.currentThread().getName()+"The value of loop variable i"+i); if(i==20) { new Thread(ft,"Threads with return values").start(); } } try { System.out.println("Return value of the child thread:"+ft.get()); } catch (InterruptedException e) { e.printStackTrace(); } catch (ExecutionException e) { e.printStackTrace(); } } @Override public Integer call() throws Exception { int i = 0; for(;i<100;i++) { System.out.println(Thread.currentThread().getName()+" "+i); } return i; } }

Comparison of the Three Ways to Create Threads

  • 1. When creating multithreading by implementing the Runnable or Callable interfaces, the thread class only implements the Runnable or Callable interface and can still inherit other classes.

  • 2. When creating multithreading by inheriting the Thread class, the code is simple. If you need to access the current thread, you don't need to use Thread.currentThread(); you can directly use this to obtain the current thread.

Several Key Concepts of Threads

In multithreaded programming, you need to understand the following concepts:

  • Thread synchronization
  • Inter-thread communication
  • Thread deadlock
  • Thread control: suspension, stop, and resume

Usage of Multithreading

The key to effectively using multithreading is understanding that programs execute concurrently rather than serially. For example, if a program has two subsystems that need to execute concurrently, multithreaded programming is needed at that point.

By using multithreading, you can write very efficient programs. However, please note that if you create too many threads, the execution efficiency of the program actually decreases rather than increases.

Remember, context-switching overhead is also important. If you create too many threads, the CPU will spend more time switching contexts than executing the program!

    Thread Pool

    1. A thread pool is actually a container that holds multiple threads. The threads in it can be reused, avoiding the operation of frequently creating thread objects and consuming excessive resources by repeatedly creating threads. (What it is)

    2. So why do we need a thread pool? Can't we just create threads manually each time they are used?

    In Java, if a new thread is created every time a request arrives, the overhead is quite large. In actual use, the time spent creating and destroying threads and the system resources consumed are considerable, and may even be much more than the time and resources spent processing actual user requests. In addition to the overhead of creating and destroying threads, active threads also consume system resources. If too many threads are created in a JVM, the system may suffer from resource insufficiency due to excessive memory consumption or "excessive switching." To prevent resource insufficiency, some measures need to be taken to limit the number of requests processed at any given moment, reduce the number of times threads are created and destroyed as much as possible, especially for threads whose creation and destruction are relatively resource-intensive, and try to use existing objects for service. (Why)

    Thread pools are mainly used to solve the problem of thread lifecycle overhead and resource insufficiency. By reusing threads for multiple tasks, the overhead of thread creation is spread across multiple tasks, and since the threads already exist when requests arrive, the delay caused by thread creation is eliminated. This allows requests to be served immediately, making the application more responsive. In addition, by properly adjusting the number of threads in the pool, resource insufficiency can be prevented. (What it is used for)

    3. Thread pools are created through a thread pool factory, then methods in the thread pool are called to obtain threads, and then threads are used to execute task methods.

    • Executors: Thread pool factory class
    • public static ExecutorServicenewFixedThreadPool(int nThreads): Returns a thread pool object
    • ExecutorService: Thread pool class
    • Future<?> submit(Runnable task): Obtain a thread object from the thread pool and execute it
    • Future interface: Used to record the result produced after a thread task completes. Creation and use of thread pools

    4. Here are two methods for creating threads using a thread pool

    1) Using the Runnable interface to create a thread pool

    Steps for using thread objects in a thread pool:

    • 1. Create a thread pool object
    • 2. Create a subclass object of the Runnable interface
    • 3. Submit the subclass object of the Runnable interface
    • 4. Shut down the thread pool

    Differences between processes and threads

    Process

    An execution instance of an application, with independent memory space and system resources

    Thread

    The basic unit of CPU scheduling and dispatching, the smallest unit that performs operations in a process, and can complete an independent sequential control flow

    Relationship between processes and threads

    (1) A thread can belong to only one process, while a process can have multiple threads, but at least one thread. A thread is the smallest execution and scheduling unit recognizable by the operating system.

    (2) Resources are allocated to processes, and all threads of the same process share all the resources of that process. Multiple threads in the same process share the code segment (code and constants), data segment (global variables and static variables), and extended segment (heap storage). However, each thread has its own stack segment, also called the runtime segment, which is used to store all local variables and temporary variables.

    (3) The processor is allocated to threads, that is, what actually runs on the processor is threads.

    (4) During execution, threads need cooperative synchronization. Threads from different processes must use message communication to achieve synchronization.

    Difference between run() and start() in Java Thread

    Java threads are implemented through the java.lang.Thread class. When the VM starts, there is a thread defined by the main method. New threads can be created by creating instances of Thread. Each thread completes its operations through the method run() corresponding to a specific Thread object, and the method run() is called the thread body. A thread is started by calling the start() method of the Thread class.

    In Java, threads usually have five states: new, ready, running, blocked, and dead.

    • The first is the new state. When a thread object is generated and the start method of the object has not been called, the thread is in the new state.
    • The second is the ready state. After the start method of the thread object is called, the thread enters the ready state, but at this time the thread scheduler has not yet set the thread as the current thread, so it is in the ready state. After the thread runs and returns from waiting or sleeping, it also enters the ready state.
    • The third is the running state. The thread scheduler sets the ready thread as the current thread. At this point, the thread enters the running state and begins executing the code in the run function.
    • The fourth is the blocked state. While the thread is running, it is paused, usually to wait for some event to occur (such as a resource becoming ready) before continuing. Methods such as sleep, suspend, and wait can cause thread blocking.
    • The fifth is the dead state. If a thread's run method finishes executing or the stop method is called, the thread becomes dead. For a dead thread, the start method can no longer be used to make it ready.

    There are two methods to implement and start a thread

    • 1. Write a class that inherits from the Thread class and override the run method. Use the start method to start the thread
    • 2. Write a class that implements the Runnable interface and implement the run method. Use the new Thread(Runnable target).start() method to start it.

    Multithreading principle:It's equivalent to playing a game console. There is only one console (CPU), but many people want to play. So, start is queuing! When the CPU selects you, it's your turn, and you run(). When the CPU's time slice has been executed, this thread continues to queue and waits for the next run().

    After calling start(), the thread will be placed in the waiting queue and wait for CPU scheduling. It does not necessarily start executing immediately; it just puts the thread into a runnable state. Then through the JVM, the Thread will call the run() method to execute the thread body of this thread. Calling start first and then run is so troublesome; why not directly call run? It is to realize the advantages of multithreading. Without start, it won't work.

    • 1.start() The method to start a thread truly realizes multithreaded execution. At this time, there is no need to wait for the run method body to finish executing; you can directly continue executing the following code. By calling the start() method of the Thread class to start a thread, the thread is in the ready state at this time, not running. Then the run() method is called through this Thread class to complete its running operation. Here, the run() method is called the thread body; it contains the content to be executed by this thread. When the run method finishes executing, this thread terminates. Then the CPU schedules other threads.
    • 2.run()Calling the method as an ordinary method. The program still executes sequentially. You must wait until the run method body has finished executing before continuing to execute the following code. In the program, there is only the main thread—this one thread—and its program execution path is still only one, so the purpose of writing threads is not achieved.

    Remember:Multithreading is time-sharing use of the CPU, making all threads execute together from a macro perspective, also called concurrency.

    Thread state diagram:

    Threads include the following 5 states:

    1. New state (New):After a thread object is created, it enters the new state. For example, Thread thread = new Thread().

    2. Ready state (Runnable):Also known as the "executable state". After a thread object is created, other threads call the object's start() method to start the thread. For example, thread.start(). A thread in the ready state may be scheduled and executed by the CPU at any time.

    3. Running state (Running):The thread obtains CPU permission to execute. It should be noted that a thread can only enter the running state from the ready state.

    4. Blocked state (Blocked):The blocked state is when a thread gives up the right to use the CPU for some reason and temporarily stops running. Only when the thread enters the ready state does it have a chance to move to the running state. There are three types of blocking situations:

    • (01) Waiting blocking -- By calling the thread's wait() method, the thread waits for the completion of some work.
    • (02) Synchronous blocking -- When the thread fails to acquire the synchronized lock (because the lock is occupied by another thread), it enters the synchronous blocked state.
    • (03) Other blocking -- When calling the thread's sleep() or join(), or when an I/O request is issued, the thread enters the blocked state. When the sleep() state times out, join() waits for the thread to terminate or timeout, or when I/O processing is completed, the thread transitions back to the ready state.

    5. Dead state (Dead):When the thread finishes execution or exits the run() method due to an exception, the thread ends its life cycle.

    Thread safety issues

    Causes:Multiple threads compete for the same resource (accessing the same data). You can refer to the classic producer-consumer problem.

    Solution:

    Inside the run method: synchronized code block synchronized {}

    Public synchronized 返回值类型 方法名（）{} 自动释放对象锁

    Use Lock lock

    The Lock lock needs to be manually released by the programmer (in the finally code block).

    Lock lock=new ReentranttLock()    // Reentrant（可重用的）

    The Lock implementation provides a broader range of locking operations than can be obtained using synchronized methods and statements, and it appeared after JDK 1.5.

    Methods in the Lock interface:

    void lock()   // 获取锁 
void unlock() // 释放锁

    Implementation classes of the Lock interface:

    java.util.concurrent.locks.ReentrantLock implements Lock

    Usage steps:

    • 1. Create a ReentrantLock object at the member position.
    • 2. Before code that may have thread safety issues, call the lock method in the Lock interface to acquire the lock object.
    • 3. After code that may have thread safety issues, call the unlock method in the Lock interface to release the lock object.
    public class RunnableImpl implements Runnable{
    //定义一个共享的票源
    private int ticket = 100;
    //1.在成员位置创建一个ReentrantLock对象
    Lock l = new ReentrantLock();
    //设置线程任务:卖票
    @Override
    public void run() {
        //使用死循环,让卖票重复的执行
        while(true){
            //2.在可能出现线程安全问题的代码前,调用Lock接口中的方法lock获取锁对象
            l.lock();
            //判断票是否大于0
            if(ticket>0){
                //为了提高线程安全问题出现的几率,让程序睡眠10毫秒
                try {
                    //可能会产生异常的代码
                    Thread.sleep(10);
                    //进行卖票 ticket--
                    System.out.println(Thread.currentThread().getName()+"正在卖第"+ticket+"张票!");
                    ticket--;
                } catch (InterruptedException e) {
                    //异常的处理逻辑
                    e.printStackTrace();
                }finally {
                    //一定会执行的代码,一般用于资源释放(资源回收)
                    //3.在可能出现线程安全问题的代码后,调用Lock接口中的方法unlock释放锁对象
                    l.unlock();//无论程序是否有异常,都让锁对象释放掉,节约内存,提高程序的效率
                }
            }
        }
    }
}

    Use CompletableFuture to solve the callback problem.

    import java.util.concurrent.CompletableFuture;
import java.util.concurrent.CountDownLatch;

public class CompletableFutureDemo {
    public static void main(String[] args) throws InterruptedException {
        long l = System.currentTimeMillis();
        CompletableFuture<Integer> completableFuture = CompletableFuture.supplyAsync(() -> {
            System.out.println("执行耗时操作...");
            timeConsumingOperation();
            return 100;
        });
        completableFuture.whenComplete((result, e) -> {
            System.out.println("结果：" + result);
        });
        System.out.println("主线程运算耗时:" + (System.currentTimeMillis() - l) + " ms");
        new CountDownLatch(1).await();
    }

    static void timeConsumingOperation() {
        try {
            Thread.sleep(3000);
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}

    Console output:

    执行耗时操作...
主线程运算耗时:74 ms
结果：100

    It can be found that the time-consuming operation does not occupy the time slice of the main thread, achieving the effect of asynchronous calls. We also do not need to introduce any third-party dependencies; this all depends on the emergence of java.util.concurrent.CompletableFuture. CompletableFuture provides nearly 50 methods, greatly facilitating Java multithreading operations and the writing style of asynchronous calls.

    Regarding Java multithreading, here is a supplement about the thread methods of the Object class.

    notify(): Notifies a thread waiting on the object to return from wait(), and the prerequisite for returning is that the thread has acquired the object's lock.

    notifyAll(): Notifies all threads waiting on that object.

    wait(): The thread that calls this method enters the WAITING state. It only returns when it waits for another thread's notification or is interrupted. Note that

    After calling the wait() method, it will release the object's lock.

    wait(long): Wait with a timeout for a period of time. The parameter here is milliseconds, i.e., wait up to n milliseconds. If there is no notification, it returns on timeout.

    wait(long, int): For finer-grained control of the timeout time, it can reach milliseconds.
