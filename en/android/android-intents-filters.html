Android Intent and Filter

An Android intent is an abstract description of an operation to be performed. It can start an activity via startActivity, send a broadcast to any broadcast receiver component interested in it via broadcastIntent, and communicate with a background service via startService(Intent) or bindService(Intent, ServiceConnection, int).

The intent itself (an Intent object) is a passive data structure that holds an abstract description of the operation to be performed.

For example, you have an activity that needs to open an email client and send an email through an Android device. For this purpose, your activity needs to send an ACTION_SEND with an appropriate selector to the Android intent handler. The specified selector provides a suitable interface for the user to decide how to send his email data.

Intent email = new Intent(Intent.ACTION_SEND, Uri.parse("mailto:"));
email.putExtra(Intent.EXTRA_EMAIL, recipients);
email.putExtra(Intent.EXTRA_SUBJECT, subject.getText().toString());
email.putExtra(Intent.EXTRA_TEXT, body.getText().toString());
startActivity(Intent.createChooser(email, "Choose an email client from..."));

The above syntax calls the startActivity method to open the email activity, and the code execution result looks like this:

For example, you have an activity that needs to open a URL in a browser on an Android device. For this purpose, your activity sends an ACTION_WEB_SEARCH intent to the Android intent handler to open the given URL in the browser. The intent handler parses a series of activities and selects the one that best matches your intent; in this example, it is the web browser activity. The intent handler passes your web address to the web browser and opens the web browser activity.

String q = "https://www.runoob.com";
Intent intent = new Intent(Intent.ACTION_WEB_SEARCH );
intent.putExtra(SearchManager.QUERY, q);
startActivity(intent);

The above example will search for "www.runoob.com" on the Android search engine and present the keyword results in an activity.

For each component - activity, service, and broadcast receiver - there are independent mechanisms for delivering intents.

No. Method and Description
1 Context.startActivity(): The intent is passed to this method to start a new activity or have an existing activity do something new.
2 Context.startService(): The intent is passed to this method to initialize a service or pass new information to an already running service.
3 Context.sendBroadcast(): The intent is passed to this method, and the information will be delivered to all broadcast receivers interested in it.

Intent Object

An Intent object is a bundle of information. The intent received by a component is akin to the information received by the Android system.

An Intent object includes the following components, depending on what is to be communicated or performed.

Action

This is a mandatory part of the intent object, expressed as a string. In a broadcast intent, the action will be reported once it occurs. The action largely determines how the other parts of the intent are organized. The Intent class defines a set of action constants corresponding to different intents. Here is aAndroid Intent standard actionslist.

The action in an intent object can be set via the setAction() method and read via the getAction() method.

Data

Add data specifications to the intent filter. This specification can be just a data type (such as a MIME type attribute), a URI, or both a data type and a URI. The URI is specified by attributes of different parts.

These attributes specifying the URI format are optional, but they are also independent of each other -

  • If the intent filter does not specify a scheme, all other URI attributes will be ignored.
  • If no host is specified for the filter, the port attribute and all path attributes will be ignored.

The setData() method can only specify data as a URI, setType() can only specify data as a MIME type, and setDataAndType() can specify both a URI and a MIME type. The URI is read via getData(), and the type is read via getType().

The following are some examples of action/data pairs -

No. Action/Data Pair and Description
1 ACTION_VIEW content://contacts/people/1: Displays the information of the user with ID 1.
2 ACTION_DIAL content://contacts/people/1: Displays the phone dialer and fills in the data of user 1.
3 ACTION_VIEW tel:123: Displays the phone dialer and fills in the given number.
4 ACTION_DIAL tel:123: Displays the phone dialer and fills in the given number.
5 ACTION_EDIT content://contacts/people/1: Edits the information of the user with ID 1.
6 ACTION_VIEW content://contacts/people/: Displays the list of users for viewing.
7 ACTION_SET_WALLPAPER: Displays the wallpaper picker settings.
8 ACTION_SYNC: Synchronizes data. The default value is: android.intent.action.SYNC
9 ACTION_SYSTEM_TUTORIAL: Starts a platform-defined tutorial (default tutorial or startup tutorial)
10 ACTION_TIMEZONE_CHANGED: Notifies when the time zone has changed.
11 ACTION_UNINSTALL_PACKAGE: Runs the default uninstaller.

Category

Categories are optional parts of an intent, a string containing additional information about the type of component that should handle the intent. The addCategory() method adds a category to the intent object, the removeCategory() method removes a previously added category, and getCategories() retrieves all categories set on the intent object. Here is theAndroid Intent standard categorieslist.

Refer to the intent filters in the following section to understand how we use categories to select the appropriate activity for a corresponding intent.

Extras

These are additional pieces of information in key-value pairs passed to the component that will handle the intent. They are set via the putExtras() method and read via the getExtras() method. Here is theAndroid Intent standard extraslist.

Flags

These flags are optional parts of an intent, indicating how the Android system should launch an activity and how to handle it after it is launched.

No. Flags and Descriptions
1 FLAG_ACTIVITY_CLEAR_TASK: If set in the intent and passed via Context.startActivity, this flag will cause all existing tasks associated with the activity to be cleared before the activity is started. The activity becomes the root of an empty task, and all old activities are finished. This flag can be used in combination with FLAG_ACTIVITY_NEW_TASK.
2 FLAG_ACTIVITY_CLEAR_TOP: If this flag is set, the activity will be launched in the currently running task. This does not launch a new instance of the activity; all activities above it are closed, and this intent is passed as a new intent to the existing (currently at the top) activity.
3 FLAG_ACTIVITY_NEW_TASK: This flag is generally used to give the activity "launcher" style behavior: to provide the user with data that can run independently and to launch a complete and independent activity.

Component Name

The component name object is an optional field representing an activity, service, or broadcast receiver class. If set, the intent object is passed to an instance of the designed class; otherwise, Android uses other information in the intent to locate a suitable target. The component name is set via setComponent(), setClass(), or setClassName(), and retrieved via getComponent().

Types of Intents

Android supports two types of intents.

Explicit Intent

Explicit intents are used to connect the internal world of an application. Suppose you need to connect one activity to another; we can use an explicit intent. The following figure shows connecting the first activity to the second activity by clicking a button.

These intents specify the target component by name, typically used for messaging within an application—for example, an activity launching a subordinate activity or a sibling activity. For example:

// 通过指定类名的显式意图
Intent i = new Intent(FirstActivity.this, SecondAcitivity.class);

// 启动目标活动
startActivity(i);

Implicit Intent

These intents do not name a target, and the component name field is empty. Implicit intents are often used to activate components of other applications. For example:

Intent read1=new Intent();
read1.setAction(android.content.Intent.ACTION_VIEW);
read1.setData(ContactsContract.Contacts.CONTENT_URI);
startActivity(read1);

The above code will produce the following result:

When the target component receives the intent, it can use the getExtras() method to obtain the additional data sent by the source component. For example:

// 在代码中的合适位置获取包对象
Bundle extras = getIntent().getExtras();

// 通过键解压数据
String value1 = extras.getString("Key1");
String value2 = extras.getString("Key2");

Intent Filter

You have seen how to use intents to invoke another activity. The Android operating system uses filters to specify which activities, services, and broadcast receivers handle intents, based on the action, category, and data pattern specified by the intent. Use the <intent-filter> element in the manifest file to list the corresponding actions, categories, and data types in activities, services, and broadcast receivers.

The following example shows a portion of the AndroidManifest.xml file, specifying that an activity com.runoob.intentfilter.CustomActivity can be invoked through the set action, category, and data:

<activity android:name=".CustomActivity"
   android:label="@string/app_name">

   <intent-filter>
      <action android:name="android.intent.action.VIEW" />
      <action android:name="com.example.MyApplication.LAUNCH" />
      <category android:name="android.intent.category.DEFAULT" />
      <data android:scheme="http" />
   </intent-filter>

</activity>

When an activity is defined by the above filter, other activities can invoke it in the following ways. Use android.intent.action.VIEW, use the action com.runoob.intentfilter.LAUNCH, and provide the category android.intent.category.DEFAULT.

The <data> element specifies the data type expected by the activity to be invoked. In the above example, the data expected by the custom activity begins with "http://".

There are cases where an intent will be delivered to multiple activities or services through the filter, and the user will be asked which component to launch. If no target component is found, an exception will occur.

Before invoking an activity, Android performs a series of checks:

  • The filter <intent-filter> must list one or more actions and cannot be empty; the filter must contain at least oneelement, otherwise it will block all intents. If multiple actions are mentioned, Android tries to match one of the mentioned actions before invoking the activity.
  • A filter <intent-filter> may list zero, one, or multiple categories. If no categories are mentioned, Android passes this test. If multiple categories are mentioned, the intent passes the category test only if each category of the intent object matches one of the categories in the filter.
  • EachAn element can specify a URI and a data type (MIME type). There are separate attributes for each part of the URI: scheme, host, port, and path. An intent contains a URI and a type, and it passes the data type test only if its type matches one of the types listed in the filter.
