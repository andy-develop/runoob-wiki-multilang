Redis Introduction

Redis (Remote Dictionary Server) is an open-source in-memory database that complies with the BSD License. It provides a high-performance key-value storage system, commonly used in application scenarios such as caching, message queues, and session storage.

  • Extremely high performance:Redis is renowned for its extremely high performance, capable of supporting hundreds of thousands of read/write operations per second. This makes Redis an ideal choice for handling high-concurrency requests, especially in scenarios requiring fast responses, such as caching, session management, leaderboards, etc.

  • Rich data types:Redis not only supports basic key-value storage, but also provides rich data types, including strings, lists, sets, hashes, sorted sets, etc. These data types give developers flexible data manipulation capabilities, allowing Redis to adapt to various application scenarios.

  • Atomic operations:All operations in Redis are atomic, meaning an operation either executes completely or not at all. This feature is crucial for ensuring data consistency and integrity, especially when handling transactions in high-concurrency environments.

  • Persistence:Redis supports data persistence, allowing in-memory data to be saved to disk so that data can be recovered after a system restart. This provides data security for Redis, ensuring that data is not lost due to system failures.

  • Supports publish/subscribe mode:Redis has built-in publish/subscribe mode (Pub/Sub), allowing clients to communicate through message passing. This enables Redis to serve as a platform for message queues and real-time data transmission.

  • Single-threaded model:Although Redis is single-threaded, it handles concurrent requests through an efficient event-driven model, ensuring high performance and low latency. The single-threaded model also simplifies the complexity of concurrency control.

  • Master-slave replication:Redis supports master-slave replication, allowing data backup or read request offloading through slave nodes, improving data availability and system scalability.

  • Wide range of application scenarios:Redis is widely used in various scenarios, including but not limited to caching systems, session storage, leaderboards, real-time analytics, geospatial data indexing, etc.

  • Community support:Redis has an active developer community that provides extensive documentation, tutorials, and third-party libraries, offering developers strong support and rich resources.

  • Cross-platform compatibility:Redis can run on multiple operating systems, including Linux, macOS, and Windows, allowing it to be flexibly deployed across different technology stacks.

How is Redis different from other key-value stores?

The main difference between Redis and other key-value storage systems lies in its rich data types, high-performance read/write capabilities, atomic operations, persistence mechanisms, and extensive feature set.

The following are some of Redis's unique features:

  • Rich data types:Redis not only supports simple key-value data types, but also provides storage for data structures such as list, set, zset (sorted set), hash, etc. These data types can better meet specific business requirements, making Redis applicable to a wider range of scenarios.

  • High-performance read/write capabilities:Redis can read at a speed of 110,000 times/s and write at a speed of 81,000 times/s. This high performance is mainly attributed to Redis storing data in memory, which significantly improves data access speed.

  • Atomic operations:All operations in Redis are atomic, meaning an operation either executes completely or not at all. This feature is very important for ensuring data consistency and integrity.

  • Persistence mechanism:Redis supports data persistence, allowing in-memory data to be saved to disk so that it can be loaded and used again after a system restart. This provides data security for Redis, ensuring that data is not lost due to system failures.

  • Extensive feature set:Redis also supports advanced features such as publish/subscribe mode, notifications, key expiration, etc. These features enable Redis to be used in complex application scenarios like message queues and real-time data analysis.

  • Master-slave replication and high availability:Redis supports data backup in master-slave mode, providing data backup and master-slave replication capabilities, enhancing data availability and fault tolerance.

  • Supports Lua scripting:Redis supports writing complex operations using Lua scripts, which can be executed on the server side, providing more flexibility and powerful functionality.

  • Single-threaded model:Although Redis is single-threaded, it handles concurrent requests through an efficient event-driven model, ensuring high performance and low latency.

    What is atomicity, and what is an atomic operation?

    For example:

    A wants to transfer 1000 yuan from their account to B's account. The process from when A starts the transfer to when the transfer ends is called a transaction. In this transaction, the following operations need to be performed:

    • 1. Subtract 1000 yuan from A's account. If A's account originally had 3000 yuan, it now becomes 2000 yuan.
    • 2. Add 1000 yuan to B's account. If B's account originally had 2000 yuan, it now becomes 3000 yuan.

    If an unexpected incident occurs after 1000 yuan has been subtracted from A's account, such as a power outage, causing the transfer transaction to terminate unexpectedly, and at that time 1000 yuan has not yet been added to B's account, then we say this operation failed and a rollback must be performed. Rollback means returning to the state before the transaction began, that is, returning to the state where A's account has not yet been reduced by 1000 yuan and B's account is in its original state. At this point, A's account still has 3000 yuan, and B's account still has 2000 yuan.

    We call an operation like this, where either it succeeds together (A's account successfully decreases by 1000 while B's account successfully increases by 1000) or fails together (A's account returns to its original state and B's account also returns to its original state), an atomic operation.

    If a transaction can be viewed as a program, it is either executed completely or not executed at all. This characteristic is called atomicity.
